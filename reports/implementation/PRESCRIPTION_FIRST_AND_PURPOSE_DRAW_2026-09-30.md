# 처방 우선·목적 내 무작위 변경 구현 보고

## 1. 반영한 결정

사용자는 여러 훈련을 먼저 고르는 대신 구체적인 처방 한 개를 받는다.
원하면 숫자 버튼으로 조절하고, `다른 훈련`으로 현재 목적과 조건에 허용된
다른 방법을 바로 확인한다. 목록 선택은 부가 기능이며 첫 단계의 의무가 아니다.

스펙은 `SESSION_METHOD_SELECTION_AND_ADJUSTMENT_CONTRACT.md` v0.74의
§21.55에 반영했다. §21.54의 고정 순서 탐색을 대체하되 기존 처방 전이,
저장, 안전, 근거, 주기 배치의 권한을 확대하지 않는다.

## 2. 이번 코드 변경

- 기본 진입 문구를 `처방 훈련 확인`, `처방 확인·조절`로 변경했다.
- V3 주요 훈련은 기존 검토된 기본 구성 하나를 먼저 보여준다. 추천 이력과
  전체 구성 목록은 접어 두며 필요한 경우 열 수 있다.
- V2의 외부 `처방 확인·조절` 버튼은 목록 위치로 이동할 뿐 아니라 실제
  상세 영역도 연다. 개인 기록 확인과 최종 적용은 기존 절차를 유지한다.
- `다른 훈련`을 누를 때만 추첨한다. 화면 갱신만으로 다시 뽑지 않는다.
- 현재 방법은 즉시 재등장하지 않는다. 아직 보지 않은 방법부터 제시하고,
  풀이 소진되면 다시 섞는다. 두 방법만 있으면 교대로 나오는 것이 정상이다.
- 같은 방법의 조절 수치 여러 개가 추첨 확률을 늘리지 않도록 검토된
  숫자 조절 그룹을 한 방법으로 취급한다.
- V2 추첨은 같은 종목·목적의 방법으로 한정한다. V3는 현재 컨텍스트에 대해
  기존 조정 정책이 허용한 정확한 구성만 사용한다. 새 생리학적 동등성
  판정이나 전체 주기 적격성 모델을 추가한 것은 아니다.
- 기존 검토된 숫자 조절, 최대 20단계 되돌리기, 다시 하기, 초기화를 보존했다.
- 조절 화면은 본운동부터 표시하고 준비·정리 운동은 펼쳐 확인한다.
  전체 시간에는 준비·회복·정리를 계속 포함하며 전체 수행 순서도 유지한다.
- 조절 버튼을 변경 내용 설명보다 앞에 배치했다. 시간 값은 `600초`보다
  읽기 쉬운 `10분` 형식으로 표시한다. 저장되는 수치는 바꾸지 않는다.
- 미리보기·추첨·숫자 조절 자체는 저장하지 않는다. 명시적으로 적용해야 한다.

## 3. 실제 앱에서 확인한 경로

합성 입력: 5000m, 구조화 훈련 경험 있음, 주 3일, 9일, LT 목적,
하루 한 번, 기록 없는 시간·노력 안내. 실제 선수의 건강 자료는 사용하지 않았다.

1. 기존 기본 처방인 20분 연속 구성을 확인한다.
2. `다른 훈련`으로 10분씩 2회, 반복 사이 조깅 1분 구성을 받는다.
3. 운동 시간 줄이기 버튼으로 검토된 8분씩 2회 구성을 확인한다.
4. 되돌리기로 10분씩 2회로 돌아온다.
5. 다른 훈련 요청을 반복해도 목록 선택을 강요하지 않는다.
6. 미리보기 전후 localStorage가 동일한지 확인한다.

이는 해당 LT 파일럿의 실제 UI 연결 증거다. 모든 종목·목적에 같은 공급 폭이
있거나 모든 처방에 개인 페이스가 제공된다는 증거가 아니다.

결함 주입용 첫 간이 탐침은 모든 방법을 본 뒤의 경우를 포함하지 않아
즉시 반복 변조를 잡지 못했다. 소진 후 경계를 추가한 뒤 3/3 차단을 확인했고,
동일 경계를 단위 테스트에도 명시했다. 검증을 처음부터 무결했다고 보고하지 않는다.

전체 앱 스위트, WebKit/iOS 실기기, 외부 독립 검수, CI, 운영 저장·공개 배포
확인은 이번 작업에 포함하지 않았다. 작은 화면·큰 글자에서는 상세 내용에
스크롤이 필요할 수 있으며 모든 훈련을 무조건 한 화면에 넣었다고 주장하지 않는다.

## 5. 남은 실질 범위

1. 목적별 실제 상세 훈련 공급 확대. 현재 임의 숫자 조합으로 새 처방을
   생성하는 엔진이 아니라 수용된 구성의 정확한 참조를 선택한다.
2. 거리·반복·세트·회복·페이스 조절 축은 검토된 전이가 있는 경우만 열린다.
   이번 작업으로 모든 조합에 모든 버튼을 활성화하지 않았다.
3. 기록 기반 페이스 계산이 연결되지 않은 범위에 임의 초를 발명하지 않았다.
   기록 입력과 지원 모델별 개인 페이스 공급은 별도로 확대해야 한다.
4. 전체 주기의 MAIN·회복 배치 품질과 실제 수행의 다음 주기 반영은 이
   추첨 UI만으로 해결되지 않는다. 기존 미완 범위를 완료로 바꾸지 않았다.
5. 새 방법을 추가할 때 목적뿐 아니라 종목·경험·앞뒤 일정·가능 시간과
   해당 구성의 검토 근거를 확인하고 실제 공개 경로를 시험해야 한다.
