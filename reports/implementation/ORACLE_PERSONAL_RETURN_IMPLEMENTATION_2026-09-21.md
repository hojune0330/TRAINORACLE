# Oracle 개인 결과와 재방문 연결 — 2026-09-21

## 범위와 상태

사용자 지시: 남은 승인 작업을 실행하고, root가 통합하며 낮은 모델 작업자들이 명확한 구현 단위를 완료한다. Luna high 작업자 2명과 Luna medium 작업자 1명이 결과 도메인·재방문 저장소·화면/집중 계약 검사를 병렬 수행했고 root가 실제 입력·탭·계정 경계와 화면을 통합했다.

기준은 로컬 `3f7ecb8`, 원격 main은 읽기 전용 조회에서 `5cc89a76f4623bd42decc342c24592a631c8bb2c`였다. 열린 PR 및 `work-order` 라벨 issue 조회 결과는 비어 있었다. 원래 dirty worktree와 다른 계획 통합 작업은 수정하지 않았다.

이 구현은 기존 승인된 설명형 분석·계획 비교의 제품 연결이다. 여섯 새 과학적 진단 모델이나 유료 상품이 완성됐다는 뜻은 아니다.

## 구현된 연결

| 주제 | 개인 결과의 실제 근거 | 다음 동작 |
|---|---|---|
| 현재 수준 | 목표를 제외한 경기 기록. 최근 달성 기록과 같은 거리의 앞선 기록 | 기존 경기 기록 입력 후 선택한 개인 결과로 복귀 |
| 강점·보완점 | 현재 계획에 정확히 연결된 explicit RPE와 예정 RPE 범위의 기존 비교 | 계획에서 해당 훈련 기록, 또는 근거 일지 확인 |
| 훈련 비교 | 기존 월별 거리 중앙값. 세션 조건 동일 여부는 추정하지 않음 | 월별 거리 항목으로 직접 이동 |
| 훈련 구성 | 기존 최근 8주 훈련 목적 집계와 반영/제외 경계 | 기존 훈련 구성 분석 또는 훈련 기록 |
| 우선 훈련 | 기존 계획 반응 평가의 유지/감량 검토 방향 | 현재 계획의 기존 검토·안전 확인 경로. 자동 적용 없음 |
| 훈련 후 변화 | 기존 월별 RPE 비교, 없을 때는 명시적인 거리 요약 | 실제 RPE 일지 또는 월별 거리 분석 |

- 상세에서 `내 기록 / 예시`를 명확하게 전환한다. 개인 데이터가 없을 때 가상 결과를 자기 결과처럼 채우지 않는다.
- 표시 가능한 개인 자료가 있으면 개인 결과를 먼저 보여준다. 자료가 없으면 예시를 먼저 경험할 수 있다.
- 개인 입력 진입은 주제와 계정 범위를 메모리에 보관한다. 성공한 경기 기록/훈련 기록 입력 후 같은 주제에 돌아온다. 안전 검토 메시지가 있으면 자동 재진입하지 않는다. 계정 변경·입력 취소·명시 탭 이동 시 이전 입력 의도를 폐기한다.
- 일반 저장 영수증의 거리·기분·통증 버튼은 저장 날짜와 해당 월별 지표로 연결한다. 기존 분석 탭 위에서 진입해도 올바른 항목으로 다시 열린다.
- 홈의 경기 기록만 있는 사용자도 개인 결과로 진입한다. 여섯 주제는 모든 사용자에게 계속 노출한다.

## 저장과 반복 사용

- 관심 주제는 사용자의 명시적인 저장 선택 후 해당 계정/기기 게스트 범위에만 보관한다.
- 홈에는 저장한 분석의 짧은 재진입만 둔다. 관리와 참여 요일 설정은 분석 화면에서 접어서 제공한다.
- 업데이트는 실제 분석 출력의 유효한 change token이 바뀐 경우에만 표시한다. 첫 기준값, 예시 열기, 날짜만의 이동, 개인 메모 수정은 새 분석으로 세지 않는다.
- 원문·건강 수치·원본 식별자·메모 메타데이터를 재방문 저장소에 복제하지 않는다. fingerprint는 보안 인증이 아닌 로컬 변경 감지용이다.
- 참여는 별도 선택한 요일 설정 후 실제 구조화 일지 저장, 활성 계획 아래의 명시적인 확인, 선택한 휴식 기록만 인정한다. 날짜당 한 번이며 app-open/sample-view는 제외한다. 연속과 누적을 분리하고 휴식으로 누적을 지우지 않는다.
- 기존 포인트·분석 접근 권한·보상·알림·결제는 바꾸지 않았다.

## 글과 배치

UI/UX 스킬의 정보 단계화 기준을 기존 토큰 시스템에 맞춰 적용했다. 상단 주제 선택과 결과 종류는 한 줄에 놓고, 핵심 결과/출처/한 가지 주 동작을 우선한다. 설명과 표는 접혀 있다. 빈 화면의 출처·단위·빈 차트 중복 안내를 제거했다.

월별 상세 수치는 접되 반영/제외·오래된 출처·충돌·빈 달 안내는 밖에 둔다. 본문/캡션은 기존 14.5px/12px 기준이며 글자를 줄여 밀어 넣지 않는다. 좁은 화면과 글자 확대에서 주제 타일은 자연스럽게 한 열로 바뀐다.

## 근거 계약

- `WORK_ORDER_P1_ATHLETE_RECORDS.md`: 달성 기록/목표 분리, 날짜·검증 상태 유지, 날짜만으로 현재 능력 승격 금지.
- `DATA_PROVENANCE_RUNTIME_ADOPTION_DECISION.md` 및 분석·시각화 계약: allowlisted 구조화 값만 사용, 원문 zero-signal, imported/legacy 우회 금지.
- `PLAN_CYCLE_RESPONSE_AND_ADAPTATION_CONTRACT.md`의 승인된 근거 연결 수정: 정확한 계획 링크, explicit RPE, 충돌/중복/변경 수행 제외. 기존 비교 함수 재사용.
- `SESSION_INTENSITY_ASSESSMENT_SPEC.md`: 설명형 수치를 새로운 처방/안전 권한으로 확대하지 않음.

## 실행 확인

새 개인 결과, 관심/요일 저장소, 계정 전환, 예시 무쓰기, 저장 후 복귀와 지표 이동의 집중 계약 검사만 실행했다. 전체 CI/전체 E2E/운영 계정 검사는 반복하지 않았다.

- 개인 결과 wrapper 11개 통과: 목표/잘못된 기록 제외, 실제 linked RPE 2건의 감량 검토 연결, private memo-only 추가/날짜 tick의 불필요한 업데이트 방지 포함.
- 관심 저장소/참여 패널 16개 통과: 동의·계정 분리·손상/미래 날짜·중복·선택 요일 연속 계산·compact 범위.
- 저장 영수증→지표 이동 8개 통과.
- AppShell/홈/참여 통합/개인 결과 표시의 마지막 영향 검사 4파일 28개 통과.
- 기존 예시 차트/탐색 26개, 분석 선택 4개 통과. 문구 변경 후 남아 있던 테스트의 예전 accessible-name 정규식은 새 라벨과 맞췄으며 기존 검증을 삭제하지 않았다.
- 월별 상세 접힘/초기 metric 및 기존 막대 계약의 해당 검사 통과.
- TypeScript 및 production-mode Vite 빌드 통과. 이후 짧은 요약/경고 표시 보정은 해당 wrapper 11개로 확인했다. 기존 폰트 경로·혼합 동적 import·큰 chunk 경고는 남아 있으며 배포 성공 증거로 취급하지 않았다.
- `git diff --check` 오류 없음. Windows의 LF/CRLF 안내는 별개다.

실제 로컬 브라우저에서 가상 경기 기록으로 `예시 → 내 기록 → 입력 → 원래 개인 결과 → 관심 저장 → 홈 재진입`을 확인했다. 375×667, 320×667에서 확인한 개인 결과의 가로 넘침은 없었다. 운영 계정이나 실제 건강 데이터는 사용하지 않았다. 확인용 탭과 임시 viewport를 정리하고 이 작업에서 시작한 로컬 개발 서버만 종료했다.

## 남겨 둔 별도 결정과 공개 상태

새 생리학적 등급·약점 원인·미래 기록 예측·훈련 효과의 인과 판정, 미승인 처방 수치/변형은 도입하지 않았다. 현재 주제별 결과는 위 표의 실제 지원 범위를 따른다. 특히 개인 구간 자동 판독과 조건 일치 세션 쌍 자동 선정은 이번의 월별 설명형 비교와 다르다.

가격, 실제 유료 제공 범위, 환불, 권한 및 결제 개시는 정해지지 않았으므로 가짜 잠금/상품을 만들지 않았다. 원격 push와 운영 배포는 하지 않았다. 로컬 체크포인트 이후 자동으로 실행되는 후속 작업은 없다.
