## 6. 다음 공급 작업을 위한 정확한 출발점

한 개씩 개발 승인을 다시 묻는 작업이 아니다. 다음 담당자는 아래 순서로 **내용 채택안**을 완성한다.

1. [전체 37개 비교표](../review/METHOD_CONFIGURATION_REVIEW_CARDS_V3.md)와 [정확한 원본](../review/METHOD_OWNER_REVIEW_BUNDLE_V3.json)을 함께 읽는다. 생성 카드 원본을 직접 고치지 않는다.
2. 기록 없는 경로와 기존 기록 기반 경로를 분리해 `종목 × 경험 × 목적 × 주기 역할`의 지원 범위를 고정한다. 청소년/성인과 자기 선택/코치 확인 범위도 보존한다.
3. 같은 목적에서 구조가 다른 방법 두 개와 최소 한 가지 유용한 조절을 우선 묶되 고정 짝으로 등록하지 않는다. 반복 수만 다른 것은 조절 범위이지 새 방법이 아니다.
4. 정확한 운동/회복/강도·준비정리·적용 대상·수치별 설명을 원문 근거와 코칭 판단으로 나눠 검토한다. 특히 입문 GLY 직접 근거 부족, LT 참고 페이스, 거리 회복의 미산출 시간은 해결됐다고 표시하지 않는다.
5. 개별 구성 승인과 전체 일정 조합 검토를 분리한다. 날짜·AM/PM·MAIN 수를 그대로 유지하고, 변경하지 않은 세션과 앞뒤 주기를 함께 검토한다. 승인된 구성만으로 임의 모든 조합을 열지 않는다.
6. 완성된 정확한 묶음 ID/버전/내용 지문과 미해결 항목을 오너에게 한 번에 제시한다. [승인 경로](../review/OWNER_TRAINING_ADOPTION_REVIEW_ROUTE_2026-09-07.md)에 따라 실제 최종 답변만 결속한다.
7. 채택된 내용만 registry/결속/설명/전이/과거 버전 보존에 연결하고, 실제 사용자 범위에서 선택·조절·적용·저장·재열기·일지의 동일 처방을 확인한다.

현재 자료에는 강도 적용성, 정확한 운동/회복 근거, 주기 배치, 개인 적용성 등의
미완료 항목이 있다. **현재 막힌 것이 오너의 답변 하나뿐이라고 표현하면 안 된다.**
내용 검토를 마치지 않은 37개를 일괄 승인해 달라고 요구하는 것도 이번 작업의 결론이 아니다.

| compact에서 준비·정리와 회복이 숨음 | 존재하는 지원 구간은 요약에서도 표시 | 컴포넌트 회귀 + 브라우저 |
| V2 시간/권한 조회 예외가 렌더를 중단 | 후보 조회만 격리, 초안과 기존 처방 보존, Apply 재검증 유지 | V2 20/20 및 결함 주입 실패 증명 |
| 반복 1회가 회복 제거 때문에 새 방법으로 계산됨 | 비교용 복사에서만 비활성 회복 정규화 | V2/V3 반복 축소 회귀 |
| 다른 훈련이 A→B→A 무한 반복 | 이미 본 방법 추적, 소진 후 `본 방법 다시 보기` | 브라우저·단위·결함 주입 |
| 중첩 1세트가 다른 세트 회복 두 가지를 하나로 합침 | 전체 중첩 반복 수준에서 명시 회복 구성을 우선 대표로 선택 | V2/V3 A=60초/B=120초 둘 다 보존, 독립 재현 차단 |

전체 수정은 원래 처방 수치·템플릿 허용 목록을 바꾸지 않는다. 화면 의미와 탐색 분류의 수리다.

## 8. 공개 완료 조건과 미실시 항목

- 기존 범위 UI 개선의 배포와 새로운 훈련 공급의 공개를 별도로 판정한다.
- 새 공급의 최소 공개 조건: 한 실제 범위에서 서로 다른 적격 방법 2개 + 유용한 조절 1개 + 저장/재열기/일지 연결.
- 실제 신규 공급의 다른 기기 동기화, 실제 선수 사용성, iOS VoiceOver, Fable UX 검수는 이번 자동 시험으로 대체하지 않는다.
- 실시간 AI 생성, 원문 메모 분석, 새로운 훈련 용량/페이스 공식, 다음 주기 자동 증량, 운영 DB 변경은 수행하지 않았다.
- Git 커밋·CI·배포·공개 확인은 각각 증거가 생긴 뒤 기록한다. 로컬 미리보기를 배포로 부르지 않는다.
