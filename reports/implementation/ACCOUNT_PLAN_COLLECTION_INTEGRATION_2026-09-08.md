## 수정한 검수 발견

1. 이전 작업의 ACK가 늦게 확인되면 더 최신의 서버 계획을 예전 계획으로 표시할 수 있었다.
   영수증은 해당 작업만 정산하고, 이미 본 높은 revision을 유지하도록 수정했으며 회귀 검증했다.
2. 이전 도중 단일 원본이 변경되면 같은 실패 요청에서 빠져나오지 못했다.
   중단 요청을 암호화 보존하고 새 원본을 재확인한 뒤 새 작업으로 이전하도록 수정했다.
3. 기존 단일 문서용 outbox가 새 서비스에서 숨겨져 빈 계정처럼 표시될 수 있었다.
   같은 계정의 이전 대기·충돌 상태를 먼저 검사하고, 원본 보존 및 복구 경로를 구현했다.
4. 과거 이력을 아직 불러오지 않은 상태에서 기존 백업/이력 독자가 빈 목록을 만들 수 있었다.
   전체 이력 확인 전에는 백업을 만들지 않고 조회 실패를 명시하도록 수정했다.

독립 검토에서 발견한 늦은 영수증, 이전 원본 변경, 구 대기본 은폐/다른 기기
선행 이전 문제를 재현하고 수정했다. 최종 화면 변경의 독립 검토에서는 추가
P1/P2가 보고되지 않았다. 외부 운영 검수나 과학적 근거 수용을 의미하지 않는다.

## 이전 대기본 처리

- 권장 경로인 `계획 원본으로 보관`은 미전송 계획을 온라인 과거 이력으로
  저장하되 현재 훈련으로 자동 선택하지 않는다. 정확한 서버 영수증 이후에만
  인계 완료를 기록하며 기존 outbox 원문을 삭제하거나 가짜 ACK를 만들지 않는다.
- 서버 계획 선택 경로는 미전송 원본을 암호화된 기기 보관본으로 남긴다.
  이것은 미전송 원본이 온라인에도 저장됐다는 뜻이 아니며 화면에서 구분한다.
- 같은 계획 ID의 내용이 충돌하면 자동 덮어쓰기하지 않는다. 원본이 다시
  바뀌면 이전 인계 표식을 재사용하지 않는다.
