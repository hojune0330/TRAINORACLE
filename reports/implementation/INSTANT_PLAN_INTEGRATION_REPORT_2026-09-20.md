## 3. 기존 계약을 유지한 구현

### 3.1 입력과 기준 기록

- `instant-plan-entry.ts`: 지원 7종목, 양수 유한 초, 소수점, 실제 달성일과 미래 날짜를 경계에서 재검사한다.
- CURRENT_RECORD만 기존 계정 범위의 선수 기록 저장소에 저장/재사용한다. GOAL_ONLY와 NO_RECORD는 현재 기록이나 처방 앵커가 아니다.
- 이번 PR은 선수 기록의 새로운 서버 동기화 구현이 아니다. 기존 계정 범위 저장소의 의미를 유지한다.
- `instant-plan-intake.ts`: 기존 승인된 방법 선택지만 제안한다. 명시적으로 고른 RPE 방법(`null`)은 미선택(`undefined`)과 구분하여 뒤로 갔다 와도 보존한다.
- 800m 121.5초, 1500m 263.4초, 3000m 655초, 5000m 1111초를 실제 생성·저장 경로에서 확인했다.
- 10km·하프·마라톤 또는 기존 상세 적격성이 없는 입력에 승인되지 않은 페이스를 발명하지 않는다.

### 3.2 추천과 일정

- 표시 정책 `SUPPORT_DURATION_RANGE_FIRST_V1`: 기존 BALANCED를 먼저 보여주는 제품 기본값이다. 과학적 최적 순위나 새 훈련량 정책이 아니다.
- `instant-plan-projection.ts`는 실제 `candidate.sessions`의 날짜·횟수·오전/오후를 투영한다. 없는 세션을 휴식 처방으로 둔갑시키지 않는다.
- 기간 내 세션을 오전 → 오후로 정렬한다. 주요 훈련 횟수는 실제 QUALITY 세션으로 센다.
- 가능일은 '주간'이 아니라 선택한 7/9/10일 계획 기간 내 가능일로 설명한다. 매일 훈련과 매일 고강도는 다르다.
- 375×667에서 9일 일정 전체와 시작 버튼을 첫 화면에 확인했다. 320px 및 실제 글자 200%에서는 정보 보존과 가로 잘림 방지를 우선하고 필요한 세로 스크롤은 허용한다.
- 기본값·근거·기준 기록 확인은 제거하지 않고 펼쳐 볼 수 있게 둔다.

### 3.3 저장·안전·오늘·일지

- 기존 저장과 계정 ACK 결과만 실제 활성화를 결정한다. SAVING/PENDING은 저장 완료가 아니다.
- 클릭 중복은 한 요청으로 막는다. 저장 실패 재시도는 실패한 정확한 후보/시작일을 재사용한다.
- ACCOUNT_PLAN_STALE/EVIDENCE_REQUIRED/REVIEW_REQUIRED는 재확인할 질문·다듬기 경로를 열고, 그 상태에서 무작정 재저장하지 않는다. 대기 중이거나 상태가 불명확한 쓰기는 계속 차단한다.
- 오늘 안내는 기존 안전 검사와 상세 처방 승인/만료/철회 검사를 표시 전에 확인한다. 이 사전 검사는 지시를 감추는 용도이며 사용자 대신 실행을 승인하지 않는다.
- 오늘 상세 훈련 근처에 기존 시작 전 확인을 연결했다. 미래 첫 훈련과 이미 기록이 있는 세션에는 새 START 버튼을 표시하지 않는다. 사용자가 몸 이상을 알렸을 때 정상 실행 안내를 동시에 계속 보여주지 않는다.
- 연결 일지는 계획/세션 지문과 날짜가 맞을 때만 기록 존재로 센다. 일지 저장만으로 progress를 완료로 변경하거나 오후 훈련까지 완료 처리하지 않는다.
- 조정형 계획 V4~V6의 기존 전용 화면은 유지한다. 이번 간편 Today 투영을 모든 구버전 화면에 적용했다고 주장하지 않는다.

## 4. 독립 읽기 검수와 수정

P 작업자에게 I 파일을 읽기 전용으로 검수하도록 요청했다. P가 I 코드를 직접 덮어쓰지 않았고, I가 원본 경로를 대조하여 수정했다. 다음 발견은 가설로 받은 뒤 코드와 테스트에서 확인했다.
