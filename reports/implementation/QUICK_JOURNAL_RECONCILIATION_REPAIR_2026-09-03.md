## 4. 결함 주입 증거

다음 세 결함을 일시적으로 다시 넣자 `P2-1`, `P2-2`, `P2-3`를 포함한 다섯
도메인·UI 테스트가 각각 해당 이유로 실패했다. 테스트 로딩 실패가 아니었다.

1. 후보를 QUICK 작성 깊이로만 제한: 상세 편집 일지 후보 목록이 비어서 실패.

### 4.1 비밀 메모 선작성 경로의 추가 P1

독립 재검수에서 비밀 메모를 먼저 쓴 일지에 파일 값을 보완하면, 저장용 사본의
빈 메모를 삭제 의도로 읽어 암호문이 제거되는 문제가 재현됐다. 메모를 보완
후에 작성하는 테스트만으로는 이 순서를 잡지 못했다.

- 잠금·잠금 해제 두 경우의 신규 테스트를 수정 전 코드에 실행해, 병합 성공과
  동시에 암호문 항목이 사라지는 실패를 각각 확인했다.
- `updateEntryPreservingMemo`는 기존 소유권·버전·식별자·계획 연결 검사를 모두
  거치며, 메모 텍스트와 목적이 바뀌면 거부한다. 통과한 파일 보완은 암호문을
  읽거나 다시 암호화하거나 삭제하지 않는다.
- 일반 `updateEntry`의 명시적인 메모 삭제 동작은 유지한다.
- 독립 재검수에서 두 잠금 상태의 암호문 완전 동일·원문 복원, 메모 변경 우회
  거부, 오래된 버전·객관값·출처·식별자 변경 거부를 확인했다.

- `import-draft.ts`: `D848B1297577FF504EAA5EC7611431E000A953C627760F55A9CFDD88E3BD1C49`
- `journal-update.ts`: `DE3A0A989EF37BDDAE93D568AB135DB829AF107BA05A38724D56B0B8D8FEF0A0`

전체 앱 최초 실행은 예전 안내 문구를 찾는 테스트 한 건과 분석 화면 로딩을
기다리는 테스트 한 건이 실패했다. 전자는 실제 새 안내를 검증하도록 갱신했고,
