# 통증 확인 후 계획안 만들기

## 오너 지시와 적용 범위

통증 때문에 계획 진입에서 이탈하는 문제를 줄이기 위해 체크 후 계획안을
만드는 경로를 추가했다. 계획 만들기와 실제 시작·적용은 분리한다.

- 몸 상태 질문의 이상·불확실 선택지는 더 이상 막힌 길이 아니다.
- 기본 해제된 체크와 `계획안 만들기` 버튼을 제공한다. 체크 전 생성하지 않는다.
- 만들면 실제 날짜·요일의 달력과 날짜별 훈련안을 보여준다.
- `통증·몸 상태 확인 필요`를 첫 화면과 날짜 상세에 유지한다.
- 재활·통증 맞춤 처방이 아니라 일반 구성 미리보기다. 개인 기록 환산을 하지 않는다.
- 과거 통증·D9 상태·일지·현재 계획을 수정하거나 서버에 새 자료를 보내지 않는다.
- 체크는 안전 판정이 아니다. 미리보기는 기존 선택·활성화·일지 링크·메모 내보내기
  경로에 들어가지 못한다. 화면을 닫으면 사라지는 임시 계획안이다.
- `몸 상태 다시 확인하기`는 기존 답을 유지하고 원래 안전·생성·저장 검사를 재실행한다.

## 구현 경계

엔진의 `generateSafetyReviewPreview`는 실제 blocked gate를 그대로 받아
별도 결과를 만든다. passed gate를 지어내거나 D9를 정상으로 변경하지 않는다.
선택 가능한 후보 ID·pair ID·gate·선택 권한·개인 기록·주기 연계는 반환하지 않는다.
기존 `generatePlanCandidates`와 `generatePlanFromDraft`의 차단은 변경하지 않았다.

화면은 기존 달력·날짜 리더를 재사용한다. 긴 안내는 접고 생성 확인은 한 체크와
한 버튼으로 끝난다. 미리보기의 메모 내보내기는 사용하지 않는다.

## 근거와 검수 상태

기능 승인 근거는 2026-10-06 오너 요청이다. 이탈 사례는 오너 전달이며 새로운
사용자 조사나 전환율 효과 검증으로 주장하지 않는다. 통증을 참고 뛰도록 유도하지
않는 안내는 [NHS 러닝 통증 안내](https://www.nhs.uk/live-well/exercise/knee-pain-and-other-running-injuries/)를 참고했다.
이를 모든 부상의 공통 재활 처방이나 의료적 승인 기준으로 사용하지 않는다.

- 최소 경계 검사 5개 통과: 체크 전 차단, 계획안 표시, 실행 결과와 분리, 기존
  저장 불변, 미기록/읽기 실패를 정상으로 바꾸지 않음, 원문 거부, 재진입 체크 초기화.
- 앱 타입 검사 통과. 기존 문구를 사용하는 테스트 선택자는 새 표시로 갱신했다.
- 오너 지시에 따라 전체 회귀·브라우저·페르소나·실계정 검수는 후속으로 남겼다.
- 배포용 빌드·공개 반영은 별도 배포 기록과 이번 작업 최종 보고에서 구분한다.

## 후속 검수

첫 생성·기존 통증 일지·읽기 실패·다음 주기 진입에서 같은 체크 흐름인지,
날짜 상세·뒤로가기·큰 글자에서 안내가 유지되는지 확인한다. 실제 부상별 운동
허용·재활 훈련 자동 생성·체크만으로 활성 계획 적용은 이번에 구현하지 않았다.
