# STRUCTURED_JOURNAL_SYNC_BETA_IMPLEMENTATION_2026-08-27.md

## 목적

TrainOracle의 첫 서버 동기화를 자유 메모가 아닌 구조화 일지 백업으로 제한한다.
로그인만으로 업로드하지 않고, 사용자가 기기 일지를 계정에 연결한 뒤 동기화를
켜고 합칠 개수를 확인하고 다시 확인해야 실행된다.

## 이번 변경

- 동기화 동의를 계정별 저장 공간에서 읽고 쓴다.
- 로그인 계정이 바뀌면 이전 계정의 동의, 미리보기, 결과 메시지를 초기화한다.
- 거리, 시간, RPE 등 구조화 필드만 서버 payload에 포함한다.
- 훈련 메모, 개인 메모, `memoPurpose`는 첫 공개 동기화에서 전송하지 않는다.
- 과거 시험 설정에 메모 공유나 복구 코드가 남아 있어도 실행 경계에서 무시한다.
- 메모가 제거된 서버 일지를 빈 메모 셸로 복원해 다른 기기에서 사라지지 않게 한다.
- 과거 서버 payload에 남은 메모 원문은 로컬에 저장하지 않고 다음 upsert에서 제거한다.
- 구조화 일지 미리보기가 개인 메모 테이블 상태에 의존하지 않게 분리한다.
- 동기화가 끝나면 다음 실행 전에 다시 미리보기를 요구한다.
- 첫 베타의 메모 경계를 최신 동기화 계약 v0.2에 기록했다.

## 유지되는 경계

- 로그인만으로 동기화가 시작되지 않는다.
- 로그인 전 기기 일지는 사용자의 두 번 확인 전까지 어느 계정 소유로도 추정하지 않는다.
- 다른 계정 소유 일지는 읽거나 올리지 않는다.
- 삭제 표식은 본문 없이 ID와 삭제 시각만 다룬다.
- 서버 실패는 로컬 일지 작성과 열람을 막지 않는다.
- 동기화는 D9, RVE, Safety Gate 또는 훈련 계획의 안전 상태를 바꾸지 않는다.

## 공개 순서

1. 코드 PR 병합과 CI 통과
2. 공개 환경에서 `TRAINORACLE_FEATURE_SYNC=true` 설정
3. 배포 후 계정 화면에서 구조화 일지 동기화 베타 노출
4. 공유, 훈련 메모, 개인 메모 암호문은 계속 비공개

이 보고서는 공개 배포 완료나 운영 증거를 주장하지 않는다.
