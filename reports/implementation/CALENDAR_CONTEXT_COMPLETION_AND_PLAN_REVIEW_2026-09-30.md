## 1. 구현한 것

1. 일지·주기 일지의 첫 위치를 최근 실제 기록으로 지정. 미래 기록은 초기 위치에서 제외.
2. 직접 고른 날짜/월과 로딩 중 수동 스크롤을 존중. 새 데이터나 자정이 탐색을 덮어쓰지 않음.
3. `최근 일지`, `가까운 기록`, 리더의 `이전 기록/다음 기록`으로 빈 날짜 연타를 줄임.
4. 원문 Back, 주 탭 왕복, 날짜·주기·스크롤 복원. 리더 종료 시 현재 날짜에 포커스 복원.
5. 후보·인테이크 시작일과 활성/종료 계획의 날짜 규칙을 분리. 조정 계획 공통 패널에도 연결.
6. READY/LOADING/STALE/ERROR를 구분. 로딩 실패를 “일지 없음”으로 바꾸지 않음.
7. 확인된 빈 상태에 작은 주간 예시, 선택 시 분리된 예시 달력. 실제 저장·통계·포인트 변경 없음.
8. OS 및 앱 `달력 움직임 줄이기` 설정. 저장 권한 실패 시에도 현재 탭의 설정은 유지.
9. 날짜별 일지 인덱스로 계획 달력 셀의 전체 이력 반복 검색 제거. 기존 역할색·AM/PM 구분 유지.

계정이 바뀌면 메모리 내 탐색 정보를 지운다. 메모 원문을 위치 저장/history에 넣지 않는다.
기존 처방·안전·계정 귀속·동기화 스키마는 수정하지 않았다. 달력 저장 위치는 브라우저를
재시작할 때까지 보존하는 새 영속 저장 기능이 아니다.
