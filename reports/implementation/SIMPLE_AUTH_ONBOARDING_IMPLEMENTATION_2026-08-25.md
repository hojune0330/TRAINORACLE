# TrainOracle 간편 회원가입 구현 보고서

작성일: 2026-08-25
기준 커밋: `6eed8fdfbdb33325cda0eb2a8dcc97c0d2c46906`
작업 브랜치: `codex/simple-auth-onboarding`

## 1. 이번에 구현한 범위

- 카카오, 구글, 이메일 인증번호의 세 가지 첫 가입 경로를 하나의 모바일 우선 화면으로 구성했다.
- 비밀번호 가입은 만들지 않았다.
- 가입 전에 생년월일과 필수 약관 동의를 확인한다.
- 법적 나이 경계는 브라우저와 서버 모두 한국 서비스 날짜(`Asia/Seoul`)를 사용한다.
- 만 14세 미만이면 외부 인증 요청이나 서버 프로필 생성을 시작하지 않고, 로컬 일지와 훈련계획을 계속 쓸 수 있다고 안내한다.
- OAuth 또는 이메일 인증 뒤에는 서버의 본인 프로필과 현재 약관 버전을 다시 확인해야 계정 설정과 동기화 화면이 열린다.
- 로그인만으로 로컬 일지나 메모가 자동 업로드되지 않는다. 동기화는 기존의 명시적 선택 흐름으로 분리했다.
- 공개 기능 플래그는 켜지 않았다.

## 2. 정책 및 스펙 정합성

- 새 정본 후보 스펙 `ACCOUNT_AUTHENTICATION_AND_IDENTITY_LINKING_SPEC.md`를 추가했다.
- 기존 계열사 SSO 문서는 첫 가입 계약이 아니라 향후 AthleteTime 연동 계약으로 범위를 좁혔다.
- 기존 백엔드 계획과 계정 연동 결정 문서에는 현재 우선순위가 카카오, 구글, 이메일 인증임을 명시했다.
- 공개 전환 게이트와 Supabase 설치 문서를 마이그레이션 `0001`부터 `0028`까지의 현재 범위로 맞췄다.
- 현재 사용자 FAQ의 과거 보호자 가입 설명을 만 14세 미만 로컬 사용 정책으로 바꿨다.

## 3. 데이터 및 안전 경계

- 생년월일은 브라우저의 임시 가입 상태에 최대 15분만 보관하고, 가입 완료 영수증에는 저장하지 않는다.
- 가입 완료 영수증에는 사용자 ID와 동의 문서 버전만 남긴다.
- 서버 마이그레이션은 만 14세 미만 프로필의 생성과 수정을 거부한다.
- 기존에 남아 있을 수 있는 만 14세 미만 프로필도 네트워크 기능 적격 판정에서 제외한다.
- 새 기기에서는 로컬 영수증을 신뢰하지 않고 현재 세션, 본인 프로필, 약관 버전, 삭제 요청 상태를 서버에서 다시 확인한다.
- 계정이 바뀌는 순간 이전 사용자의 준비 완료 상태가 잠시 보이지 않도록 전환 경쟁 조건을 차단했다.

## 4. 실행 검증

### 코드와 계약

- 앱 타입 검사: 통과
- 인증 관련 최종 집중 테스트: `40/40` 통과
- 일반 시간대 전체 앱 테스트: `1563/1563` 통과
- 한국 표준시 전체 앱 테스트: `1562/1563` 통과, 아래 기존 시간 제한 변동 1건
- 구현 계층 테스트: `633/633` 통과
- D9 평가기: `11/11` 통과
- 공개 환경 변수 계약: `9/9` 통과
- 프로덕션 빌드: 통과

한국 표준시 전체 실행에서는 기존 `PlanBeta.pace-prescription` 첫 테스트가 5초 제한을 0.236초 넘겨 시간초과했다. 같은 한국 표준시 설정으로 해당 파일을 단독 실행하면 `6/6` 통과했다. 회원가입 코드와 무관한 기존 병렬 실행 변동이지만, 전체 실행 결과를 완전 통과로 과장하지 않고 후속 테스트 안정화 항목으로 남긴다.

### 전체 브라우저 회귀

- 데스크톱 Chromium: `77` 통과, `24` 조건부 생략
- 모바일 Chromium: `93` 통과, `8` 조건부 생략
- 좁은 터치 화면: `95` 통과, `6` 조건부 생략
- 동작 축소 환경: `75` 통과, `26` 조건부 생략
- 프로젝트 총괄: `4/4 PASS`, 테스트 서버 정리 `PASS`

### 새 화면 실측

- `375x667` 화면에서 카카오, 구글, 이메일, 로컬 계속 사용 선택이 첫 화면에 표시됐다.
- 가입 가능 여부 화면과 이메일 인증 화면에 가로 넘침이 없었다. 측정값은 `innerWidth=375`, `scrollWidth=375`였다.
- 만 14세 미만 경계 입력은 외부 인증을 시작하지 않고 로컬 사용 안내로 전환됐다.
- 성인 입력은 필수 약관 동의 뒤 이메일 입력 화면으로 이동했다.
- 브라우저 콘솔 오류는 없었다. 개발 도구의 기존 버전 안내 경고만 확인됐다.

### 변조 검증

서버의 만 14세 기준 두 곳을 13세로 일부러 바꾸자 마이그레이션 계약 테스트가 `2`건 실패했다. 원래 14세 기준으로 복구한 뒤 `3/3` 통과했고, 파일 SHA-256도 변조 전후 `631A3EC22EF4904B831C03D916815D719E75BBA19CD0B3884E0F202D9785F64D`로 일치했다. 따라서 테스트가 단순히 항상 통과하는 것이 아니라 핵심 연령 경계를 실제로 잠근다는 것을 확인했다.

## 5. 이번에 완료됐다고 주장하지 않는 것

- 카카오 개발자 콘솔의 실제 앱 등록 및 운영 Redirect URI
- Google Cloud의 실제 OAuth 클라이언트 등록
- 운영 Supabase 프로젝트의 `0027`, `0028` 마이그레이션 적용
- 실제 이메일 인증번호 발송과 운영 메일 템플릿
- 실제 카카오, 구글, 이메일의 왕복 로그인 증거
- 두 계정 사이의 운영 데이터 격리 증거
- 개인정보처리방침, 이용약관, 운영자 정보의 공개 URL 확정
- 공개 사이트에서 계정 기능 활성화
- 계정 병합, 휴대전화 인증, 네이버, 토스, Apple, AthleteTime 연동

## 6. 공개 전환 전 남은 순서

1. 운영자 정보와 약관 문서의 최종 공개 URL 및 버전을 확정한다.
2. 시험 Supabase에 `0027`, `0028`을 적용하고 만 14세 경계와 RLS를 다시 검증한다.
3. 카카오와 구글 콘솔에 정확한 도메인 및 Redirect URI를 등록한다.
4. 이메일 인증번호 템플릿과 만료 시간을 운영 환경에서 확인한다.
5. 세 경로를 실제 모바일에서 각각 가입, 로그아웃, 재로그인한다.
6. 서로 다른 두 계정으로 프로필과 동기화 데이터가 섞이지 않는지 검증한다.
7. 위 증거를 공개 전환 게이트에 연결한 뒤 오너의 별도 승인을 받는다.

현재 결과는 코드와 화면이 준비된 상태다. 운영 인증 제공자와 법률 문서가 아직 연결되지 않았으므로 공개 계정 기능은 계속 비활성으로 유지한다.
