# 첫 상세 MAIN 및 수행 결과 기반 다음 주기 구현

- 날짜: 2026-10-01
- 상태: LOCAL_IMPLEMENTED_AND_TESTED / NOT_DEPLOYED
- 범위: 첫 생성의 상세 MAIN, 일반 저장 계획(version 3)의 다음 주기 상세 구성
- 배포·실제 계정 저장·훈련 효과 검증을 완료했다는 보고가 아니다.

## 1. 달라진 동작

### 첫 생성부터 상세 MAIN

기존에는 임시 시간·RPE 범위가 검토된 상세 구성보다 먼저 적용되어, 실제 카탈로그에 훈련이 있어도 넓은 시간 범위만 남는 경우가 있었다.

새 계획의 MAIN은 목적·종목·경험 조건에 맞는 검토된 구성으로 계산한다. 본운동뿐 아니라 준비·회복·정리 시간을 모두 포함한다. 기존 임시 시간 범위에 맞는 구성을 먼저 찾고, 없으면 가능한 가장 짧은 완전한 구성을 실제 총시간과 함께 보여준다. 사용자가 시작하기 전에는 활성 계획이 바뀌지 않는다.

- 같은 방법의 단순 시간 변형을 서로 다른 방법으로 부풀리지 않는다.
- EASY 및 오후 회복 세션의 기존 시간·강도 한도는 유지한다.
- MAIN 수, 하루 세션 수, 훈련 가능일은 늘리지 않는다.
- 경기 기록이나 환경 확인을 자동으로 만들어 넣지 않는다.
- 기존 저장 계획을 읽는 것만으로 새 구성으로 바꾸지 않는다.

### 실제 수행을 다음 주기에 반영

현재 계획과 정확히 연결된 구조화 일지의 직접 입력 RPE를 사용한다. 종목·경험·목적·주기 구조가 호환되는 경우 같은 목적의 순서에 따라 이전 상세 MAIN을 이어간다.

같은 목적에서 유효한 높은 RPE가 서로 다른 수행 2건 이상에서 반복되고 해당 목적의 관찰이 완전하면, 같은 방법의 이미 검토된 더 적은 구성을 제안한다. 가능한 여러 낮은 구성 중 기존 운동량에 가장 가까운 구성을 우선한다. 임의 비율이나 새 수치를 만들지 않는다.

실행 확인 예시:

| 이전 구성 | 다음 구성 | 유지한 부분 |
|---|---|---|
| P-LT-B: 2 × 10분 | P-LT-B-480: 2 × 8분 | 반복 사이 조깅 60초, 준비·정리, 목적 |
| P-VO2-2 | P-VO2-2-5 | 같은 방법, 회복 조건, 총부하 비증가 |

한 번의 높은 RPE, 낮거나 범위 안의 RPE, 누락, 중복, 충돌, 다른 운동으로 바뀐 기록만으로는 훈련을 늘리거나 줄이지 않는다. 비교 가능한 다른 목적의 기록과 섞어 횟수를 채우지 않는다. 적절한 낮은 구성이 없으면 기존 상세 훈련을 유지하고 확인이 필요함을 표시한다.

화면에는 짧은 결과와 접힌 근거를 제공한다. 새 계획을 선택하기 전까지 현재 계획과 원본 일지를 보존한다. 저장 후 새로고침에도 새 상세 구성과 주기 계보가 유지된다.

## 2. 자동 제공 범위의 실제 재계수

100개의 서로 다른 가상 사용자 입력을 사용했다. 이 중 정보가 충분하고 안전 확인을 통과한 생성 프로필 82개, MAIN이 있는 프로필 57개에서 첫 번째 계획안의 MAIN 85개를 별도로 검사했다.

| 목적 | MAIN 수 | 첫 자동 상세 연결 | 남은 조건 |
|---|---:|---:|---|
| LT | 19 | 19 | 없음: 이 표본 기준 |
| VO2 | 15 | 15 | 없음: 이 표본 기준 |
| MIX | 17 | 17 | 없음: 이 표본 기준 |
| GLY | 17 | 6 | 나머지 11개는 경험 조건에 맞는 무확인 구성이 없음 |
| ATP-PC | 17 | 0 | 가속·감속 공간 등 실제 환경 확인 필요 |
| 합계 | 85 | 57 | 28개를 자동 연결 완료로 세지 않음 |

BASE·REC 목적에는 이 표본에서 MAIN이 없으므로 위 분모에 넣지 않았다. 이는 표본의 첫 생성 결과이며 모든 종목·수준의 처방 적합률이나 과학적 효과를 뜻하지 않는다. 조건을 확인한 수동 선택과 첫 자동 생성의 범위도 구분한다.

## 3. 공격적 검수에서 고친 문제

1. 이미 저장된 동일 요청을 다시 확인할 때 일지가 바뀌면 저장 실패로 표시될 수 있었다. 정확한 기존 저장 결과와 원본 이력을 확인한 재시도는 쓰기 없이 성공을 반환하도록 고쳤다.
2. 다음 주기 저장 호출에서 근거 문맥을 생략하면 재확인이 빠질 수 있었다. 모든 새로운 다음 주기 저장에 원래 미리보기의 근거 문맥을 요구한다.
3. 조회 실패와 빈 일지를 구분하는 기존 테스트 문구가 실제 화면과 달랐다. 빈 기록이라고 표시하지 않는 동작은 유지하면서 현재 안내 문구를 검사하도록 맞췄다.
4. 서버 일지 검증 번들에 앞선 변경의 카탈로그 교체 정책이 반영되지 않은 상태를 발견했다. 생성기를 재실행하고 의존성 목록과 서버 검사를 맞췄다. 서버 배포는 별도다.
5. 변경 이력이 있는 version 4/5/6까지 새 상세 계승을 지원하는 것처럼 읽히던 안내를 분리했다.

독립 검수 최초 실행은 18개 중 15개 통과, 제품 결함 2개, 검수 픽스처의 MAIN 개수 가정 오류 1개였다. 마지막 오류는 실제 생성 개수를 확인하고 1개를 누락시키는 시험으로 수정했다. 검수 작성 테스트를 저장소에 보존했으며 수정 후 18개 모두 통과했다. 이를 별도 사람 전문가의 승인이라고 표시하지 않는다.

100명 감사의 최초 실패 26개는 이전의 `모든 MAIN이 임시 RPE·시간 상한을 넘으면 안 됨` 규칙이었다. 승인된 새 스펙에 맞춰 MAIN은 정확한 검토 구성·총시간 선언을 검사하고, EASY 상한은 그대로 검사하게 바꿨다. 실패 기록은 로컬 증거에 남겼으며 조용히 삭제하지 않았다.
