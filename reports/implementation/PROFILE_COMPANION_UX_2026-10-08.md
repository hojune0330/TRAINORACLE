# 러닝 취향 질문과 마리 안내 개선

러닝 취향 V2를 시작, 한 문항 응답, 항목 결과, 선택형 다음 항목으로 정리했다.
새 마리 삽화는 눌러 읽는 짧은 안내에 사용한다. 질문 원문과 ID, 점수 계산,
훈련 처방과 보상 정책은 바꾸지 않았다. 이전 작업에서 남은 긴 LT 설명과
기록 풀이의 앱 내부 움직임 줄이기도 함께 정리했다.

## 화면과 동작

- 첫 제목은 `나는 어떤 달리기를 좋아할까요?`다. 질문 3개로 훈련 방식을 먼저
  살펴보고, 읽을거리와 설정은 보조 행동으로 남겼다.
- 질문에는 현재 순서, 선택한 답, 이전 답 수정이 있다. 원래의 모름, 상황마다
  다름, 경험 없음, 건너뛰기와 작성 중 닫기 및 이어쓰기를 유지했다.
- 일반 첫 응답은 기존처럼 세 번째 답에서 저장한다. 결과의 `내 답 확인·수정`은
  해당 답만 바꾼 뒤 다른 답을 유지하고 결과로 돌아가며 기존 저장 경로를 호출한다.
- 결과 해설과 내 응답 기준을 먼저 표시한다. 숫자 응답이 부족하면 큰 빈 점수
  영역 대신 `점수 없이 답만 정리했어요.`를 표시한다. 점수는 능력·건강 평가가 아니다.
- 다음 항목은 선택 사항이다. 저장 실패나 미확정 응답을 덮고 다음 항목을 열지 않는다.
  개인 답을 URL·브라우저 history에 추가하지 않는다.
- 비회원이 계정 저장소의 초기 LOADING 상태를 전달받아 그림이 숨겨지던 연결을
  고쳤다. 소유 계정이 없을 때만 화면 상태를 READY로 읽으며 계정의 실제 로딩·
  충돌·실패 차단과 서비스 생성 조건은 그대로다. READY가 계정 저장 완료를 뜻하지 않는다.

## 마리 자산과 선택 반응

기존 단발·안경을 유지한 무광 입체 상반신 3종을 생성했다. 모두 256×256 투명
WebP이며 화면에서는 80px로 표시한다.

| 파일 | 역할 | 용량 |
|---|---|---:|
| mari-profile-hello-v4.webp | 시작 안내 | 10,946 B |
| mari-profile-explain-v4.webp | 결과 읽기 안내 | 11,898 B |
| mari-profile-wave-v4.webp | 안내를 누른 뒤 손인사 | 12,748 B |

신규 합계는 35,592 B다. 기존 18개를 보존한 전체 매니페스트는 21개·235,330 B다.
원본과 실제 프롬프트는 `assets/illustrations/profile-companion-20261008/`, 웹 파일은
`app/public/illustrations/`, 바이트·해시는 `docs/handoff/contextual-illustrations.json`에 있다.
서비스 워커 사전 저장 목록은 늘리지 않았다. 개인 기록이나 금융 앱 영상은 생성 입력으로
보내지 않았다.

`ProfileCompanion`은 보이는 버튼 이름, 펼침 상태와 키보드 조작을 갖춘 선택형
도움말이다. 열면 자세가 바뀌고 짧은 팁이 나타난다. Escape는 안내를 먼저 닫고
리더를 유지한다. 이미지 실패 시에도 글과 행동은 남는다. 정답 평가·보상·반복
애니메이션·강제 대기·새 저장은 없다. OS와 앱의 움직임 줄이기를 모두 따른다.

## 긴 훈련 설명 정리

`WorkoutNotation`의 읽기 전용 표시에서 확인된 기존 LT 문구 두 종류만 접는다.
예를 들어 `2 × 10분 · 힘든 정도 6–7/10 (제안) · 반복 사이 60초 조깅`을 먼저
보여주고 원래의 긴 노력 설명은 `강도 안내`에 그대로 남긴다. 알 수 없는 문구,
중단 경고, 미지정 값과 실제 시간·반복·휴식·페이스는 임의로 생략하지 않는다.
표시용 복사본을 저장이나 처방 계산에 전달하지 않는다.

기록 풀이에는 기존 OS 설정에 더해 앱의 움직임 줄이기를 연결했다. 이 작업은
전체 앱의 모든 모션을 재감사했다는 뜻은 아니다.

## 검토와 로컬 확인

별도 읽기 전용 리뷰에서 찾은 단일 답 수정의 재응답 요구, 진행 표시 의미 불일치,
건너뜀의 큰 빈 점수 영역을 수정했다. 질문 첫 포커스 의심은 개발 서버의 변경
감시가 테스트 산출물까지 다시 읽는 상황과 겹쳤다. 소스가 고정된 정적 빌드에서는
첫 질문, 다음 질문, 답 수정 후 결과 포커스가 모두 확인됐다.

- 성향 화면 계약 32개 통과.
- 훈련 표기와 두 조절 편집기 등 관련 5파일 63개 통과.
- 부모 연결·소유 계정 경계, 마리, 기록 풀이, 자산 매니페스트, 시각 기준 관련
  5파일 64개 통과. 합계는 서로 다른 159개이며 전체 저장소 검사 결과가 아니다.
- 캐릭터 클릭 무반응, 수정 답 누락, 원문 강도 설명 누락의 결함 주입에서 각각
  해당 이름의 테스트 실패를 확인하고 원상 복구했다.
- 앱과 E2E 타입 검사 통과, 로컬 빌드 통과. 기존 폰트 경로 및 번들 크기·혼합
  import 경고는 남는다.
- 브라우저 성향 3동선 통과: 375px 선택·결과·단일 답 수정·다음 항목·뒤로가기,
  320px 제목 48px/본문·버튼 28px와 이미지 실패·앱 모션 감소·초안 이어쓰기,
  1440px 건너뜀과 OS 모션 감소. 마지막 두 모바일 동선은 안내 Escape와 실제
  제목 확대를 보강해 다시 통과했다. 반복 실행을 별도 통과 개수로 더하지 않았다.
- 합성 훈련의 도움말 열기·Escape·수치 유지·미적용 변경 취소 1동선 통과.
  초기 연결 거절은 개발 서버 감시 중단 때문이며, 산출물을 감시하지 않는
  루프백 서버에서 재실행했다. 실행하지 못한 첫 시도를 통과로 세지 않았다.
- 타입 검사의 테스트 코드 오류 2개와 기존 부모 테스트의 이전 버튼 이름 3건을
  바로잡은 뒤 재검사했다. 제품을 옛 라벨에 맞춰 되돌리지 않았다.

화면 캡처는 `app/.scratch/profile-companion-browser-final/`, 데스크톱 건너뜀은
`app/.scratch/profile-companion-browser/`, 훈련 도움말은
`app/.scratch/profile-workout-help-verified/`에 있다. 합성 응답만 사용했으며 실제
학생 사용성 시험과 실제 계정 저장 왕복은 이번 확인에 포함하지 않았다.
기존 `prescription-first-draw.spec.ts`의 옛 영어 기대값도 현행 한글 표기로 맞췄으나
그 파일의 긴 전체 계획 시나리오는 재실행하지 않았다.

## 인계

통합 담당은 루트, 성향 화면·훈련 표기·자산은 파일 소유권을 나누어 병렬 처리했다.
공통 기준은 `docs/UX_UI_VISUAL_STANDARD.md` §8.5에 추가했다. 기존 더 많은
미커밋 변경은 보존했다. 이 보고서의 범위는 성향 V2와 명시한 두 후속 정리이며,
레거시 러닝 프로필 전체 재설계나 새 과학적 성향 검사 개발이 아니다.
