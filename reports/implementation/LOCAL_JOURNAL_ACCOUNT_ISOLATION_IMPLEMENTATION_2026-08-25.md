# LOCAL_JOURNAL_ACCOUNT_ISOLATION_IMPLEMENTATION_2026-08-25.md

## 1. 목적

같은 브라우저에서 계정 A가 로그아웃하고 계정 B가 로그인했을 때, 계정 A의 로컬 일지가 계정 B에게 보이거나 업로드되는 경로를 차단한다.

서버 RLS 계정 격리와 별개로, 기존 로컬 일지는 `trainoracle.journal.v1` 한 저장 공간을 모든 사용자가 공유했다. 이 구현은 일지 본문 형식을 바꾸지 않고 일지 ID와 계정 ID만 담는 별도 소유권 장부를 추가한다.

## 2. 확정 동작

| 상황 | 동작 |
|---|---|
| 로그인 전 작성 | `UNBOUND_DEVICE_DATA`로 남고 어떤 계정에도 자동 귀속되지 않음 |
| 계정 로그인 후 새 작성 | 현재 인증 계정의 로컬 일지로 기록 |
| 계정 A에서 계정 B로 전환 | A 소유 일지는 숨기되 삭제하지 않음 |
| 로그인 전 일지 연결 | 계정 화면에서 2단계 확인 후에만 현재 계정 소유로 지정 |
| 동기화 | 현재 계정 소유 일지만 미리보기·병합·업로드 |
| 백업 복원·파일 가져오기 | 로그인 중이어도 새 항목을 자동 귀속하지 않고 기기 데이터로 유지 |
| 소유권 장부 손상 | 계정 소유 여부를 추정하지 않고 일지 읽기·새 계정 저장을 차단 |

## 3. 구현 경계

- 소유권 장부에는 `entryId -> userId`만 저장한다. 일지 내용, 날짜, 통증, 메모는 넣지 않는다.
- 로그인 확인 전에는 계정 소유 일지를 표시하지 않는다.
- 읽기 필터만 적용하지 않는다. 수정, 삭제, 휴지통 복원, 전체 교체, 동기화 복구에서도 다른 계정의 항목을 보존하고 접근을 거부한다.
- 일지 ID가 겹쳐도 다른 계정의 기존 소유권을 덮어쓰지 않는다.
- 삭제된 항목의 소유권은 tombstone과 휴지통 복원을 위해 유지한다.
- 다른 계정의 휴지통과 tombstone은 현재 계정 동기화에 포함하지 않는다.
- `이 기기 데이터 전부 지우기`는 일지 본문과 일반 소유권을 지우되, 서버 부활 방지에 필요한 tombstone의 계정 연결만 최소한으로 남긴다. 삭제 기록까지 지우는 내부 옵션에서는 소유권 장부도 제거한다.

## 4. 사용자 화면

계정 화면에 `이 기기에서 먼저 쓴 일지` 영역을 추가했다.

1. 연결 전 개수와 자동 업로드되지 않았다는 사실을 보여준다.
2. 공용 기기에서는 아직 연결하지 않은 기기 일지가 보일 수 있음을 알린다.
3. 첫 번째 누름은 설명, 두 번째 누름은 확정이다.
4. 확정 후부터 해당 일지는 다른 계정에서 보이지 않고 현재 계정 동기화 대상이 된다.
