# 단계별 입력과 저장 화면 구현 인계

2026년 10월 8일 승인된 단계별 UX 패치를 로컬 작업실에 구현했다. 한 번에 현재 질문만 보여주고, 실제 입력은 최종 확인 뒤 저장한다. 훈련량 계산, 포인트 지급 정책, 계정 기능 공개와 운영 배포는 이 변경에 포함하지 않는다.

## 작업 기준

- 통합 담당은 현재 채팅의 root다. 세 작업자가 계획과 훈련 표시, 기록 양식, 계정 화면을 나누어 작업했고 root가 공통 화면과 저장 완료 연결을 통합했다.
- 작업실은 `TRAINORACLE-home-clarity-20261008`, 시작 HEAD와 갱신한 origin/main은 `42a3b7817e3e33caf543e6af9417d65c2890cbc5`다. 현재 변경은 커밋되지 않은 detached 작업실에 있다.
- 시작 전에 있던 `docs/UX_UI_VISUAL_STANDARD.md`, 승인 계획과 `.scratch` 자료는 보존했다. 다른 작업의 파일을 정리하거나 삭제하지 않았다.
- 시작 시 PR 353은 별도 성능 및 브라우저 검사 작업으로 열려 있었다. 공통 파일 중복을 확인했으며 이 작업에서 병합하지 않았다. PR 349 미니게임은 의존성이 아니다. 공개 전 원격 상태는 다시 확인해야 한다.
- 기준은 [승인 계획](../plans/TASK_FOCUSED_UX_PATCH_PLAN_2026-10-08.md)과 기존 제품 및 화면 표준이다.

## 구현한 동작

| 영역 | 구현과 보존 경계 |
| --- | --- |
| 공통 입력 | `TaskFlowStep`은 현재 질문, 답 요약과 행동만 표현한다. 실제 답과 검증은 각 양식이 소유한다. 제목에 초점을 보내되 입력 키보드를 자동으로 열지 않는다. |
| 뒤로가기 | `useTaskFlowBack`은 기존 `browserNavigation`의 한 층만 사용한다. 저장 중 이동, 열린 확인창 위에 중복 등록, 이전 계정의 늦은 콜백을 방어한다. 새 전역 라우터는 없다. |
| 빠른 기록 | 결과, 시간대, 힘든 정도, 몸 상태를 순서대로 묻는다. 휴식에는 수행 수치를 묻지 않는다. 요약을 먼저 보여주고 글과 운동 추가는 선택 행동으로 둔다. |
| 훈련 후 기록 | 현재 입력 묶음만 연다. 요약은 실제 입력한 행만 표시하고 빈 항목은 작은 추가 버튼으로 모은다. 요약에서 고친 한 항목은 다른 질문을 반복하지 않고 요약으로 돌아온다. |
| 하루 마무리 | 수면, 몸 상태와 기분, 메모를 나누며 메모로 바로 갈 수 있다. 체중과 심박은 선택해서 입력한다. 기존 값과 복구 초안은 요약부터 확인한다. |
| 경기 기록 | 경기 정보와 선택 메모를 분리한다. 직전과 직후 입력은 단계 전환으로 지우지 않는다. 최종 확인에서 페이스나 메모 검증에 실패하면 해당 입력을 연다. |
| 계획 입력 | 분기에 맞지 않는 숫자 진행률을 없애고 이전 답 수정 진입을 남긴다. 브라우저 뒤로가기에서도 종목과 미제출 기록 입력이 유지된다. 새로고침 후 계획 초안 복원은 새로 구현하지 않았다. |
| 훈련 변경 확인 | 단일 훈련 편집과 최종 저장 전에 현재와 변경안의 핵심 수치를 바로 보여준다. 기존 검증된 원본과 변경 자료를 읽으며 시간은 분·초로 표시한다. 양쪽 모두 미확인인 행은 생략하고 0은 보존한다. 최종 화면에서는 양쪽 실제 수행 구성도 함께 확인할 수 있다. |
| 수행 안내 | 역할 기반으로 총시간, 준비, 본운동, 회복, 정리를 표시한다. 압축 보기에도 필수 구간을 유지하고 공식 대신 기존 일반 표기를 사용한다. 기존 중단 안내도 유지한다. |
| 시간의 불확실성 | PACE_TARGET에는 확정된 전체 소요시간 계약이 없다. 기존 본운동과 회복 합계만 읽고 전체 시간 미정 및 준비와 정리 별도를 표시한다. 임의 합산이나 운동량 변경은 없다. |
| 저장 결과 | 확인된 저장은 지속되는 완료 화면에서 기록 보기와 닫기로 이어진다. 계정 대기와 충돌은 저장 성공으로 바꾸지 않는다. 포인트 확인 실패는 조회만 재시도하고 일지를 다시 저장하지 않는다. |
| 빠른 기록의 후속 처리 | 확인된 저장 시 기존 참여와 보상 처리를 연결한다. 완료를 눌러도 같은 기록과 저장 시각에 중복 처리하지 않는다. 뒤로 나가기 전에 기존 작은 저장 알림에서 보상 상태를 볼 수 있다. |
| 반응형 | 44px 조작 영역과 기존 글자 크기를 유지한다. 작성 중 하단 탭을 숨긴다. PC의 계획과 작성 화면만 최대 48rem로 넓히고 일지 원문과 달력 좌표 체계는 바꾸지 않는다. |
| 계정 설정 | 가입이 끝난 계정의 프로필, 온라인 보관, 자료와 백업, 공유와 동의를 목적별로 연다. 자식 폼은 유지하고 접힌 그룹에도 진행 중 또는 알림 여부를 표시한다. 필수 가입 입력은 접지 않는다. |

홈, 오라클, 달력, 파일 가져오기, 꾸미기, 로그인과 설정 목록은 실제 코드에서 기존 조건부 진입과 자유 탐색을 대조했다. 탐색 메뉴를 순서대로 완료하게 만드는 새 절차는 넣지 않았다. 계정 화면 밖의 동기화, 복원과 기기 자료 오류 패널은 계속 직접 보이게 유지했다.

## 중간 검토에서 바로잡은 문제

- 복구한 메모의 용도나 암호화 준비가 부족할 때 오류만 내고 숨긴 입력을 열지 않던 경로를 수정했다.
- 입력을 접은 뒤 저장 대기 중 메모 안전 안내와 통증 안내가 사라지지 않게 했다.
- 새 기록의 요약에서 한 항목을 수정하면 나머지 질문을 다시 돌던 문제와 뒤로가기 정체를 수정했다.
- 저장 후 완료 버튼을 누르지 않으면 빠른 기록의 참여와 보상 후속 처리를 놓칠 수 있던 연결을 수정했다.
- 휴대전화 화면에서 제목과 저장 버튼이 가장자리에 붙던 여백을 수정했다.
- 빈 요약 행을 반복하던 초기 구현을 실제 답과 선택 입력 버튼으로 다시 정리했다.
- 계정 필수 동의를 접는 안은 채택하지 않았다. 작업 중 의미 상태가 없던 세 기존 패널에는 `aria-busy`만 연결했다. 저장, 삭제와 동의 로직은 그대로다.
- 마지막 훈련 비교 표에서 긴 초 단위 숫자를 기존 분·초 표기로 바꿨다. 원본 비교 조건이 기존 유효한 훈련 저장 경로를 막지 않는지 도메인의 원본 검증과 직접 대조했다.

## 다음 작업과 공개 조건

1. 실제 중학생의 화면 설명 과제, 실제 모바일 키보드 및 보조기술 확인, 실제 계정 왕복은 별도다. 합성 테스트를 그 결과로 대체하지 않는다.
2. 최근 운동 수준이나 회당 시간 제한을 새로 수집해 처방에 연결하는 규칙은 별도 훈련 도메인 결정이 필요하다. 이번 UI 작업으로 새 운동량을 정하거나 나이만으로 강도를 변경하지 않았다.
3. 커밋과 공개 요청을 받으면 최신 origin/main과 중복 PR을 다시 대조하고 기존 릴리스 관문을 적용한다. 새 preview 주소나 계정 기능 공개를 이 작업만으로 만들지 않는다.

현재 main 반영, 커밋, 푸시, 병합, CI 실행과 수동 배포는 하지 않았다. 로컬 구현과 검사만으로 운영 배포 완료를 표시하지 않는다.
