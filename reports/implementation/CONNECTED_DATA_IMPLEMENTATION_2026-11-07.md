# 자동연동·일지 화면 구현 기록 — 2026-11-07

기준 소스: b4c7e26a17fa813ea1d4a9d408022501916697b4. 아래는 전체 기획 중 구현된 첫 묶음이다. 전체 제공자 연동 완료 보고가 아니다.

## 변경
- 홈에서 실제 Garmin 상태와 연결 진입, 저장된 수면·안정시 심박의 원래 날짜 이동, 최근 운동 및 추이 진입을 표시한다.
- 건강 지표 표시 여부·순서를 계정별 보기 설정으로 보관한다. 보기 설정에는 건강 수치를 저장하지 않는다.
- 공통 갱신 스케줄러: 단일 요청, 포커스·온라인 복귀, 기본 60초, 이벤트 최소 10초 간격, 일시적 실패 지수 재시도, 첫 수신 대기 간격, 숨김·오프라인 중단.
- AUTO와 REVIEW 모두 수신 목록을 확인한다. 일시적 실패는 마지막 정상 목록을 보존하고 인증 실패는 목록을 비우고 재시도를 중단한다. 배경 갱신은 현재 검토·페이지를 재설정하지 않고 새 기록 알림을 표시한다.
- 서버 저장 시각 변경 및 계정 화면의 주기 갱신에서 읽기 전용 일지를 다시 가져온다. 미전송 초안은 보내지 않는다. 배경 조회만 합치고 명시적 가져오기 검토는 새 조회를 유지한다.
- 수면 0과 없음, 안정시 심박 명칭, 읽기 쉬운 운동 단위, 원본 표 보존, 상세 식별자 로딩·오류·재시도를 보완한다.
- 기존 큐 잠금·인증을 유지하며 최대 10회/작업, 새 작업 시작 전 35초 예산의 순차 순환 배치를 적용한다. 서버·DB·자격증명을 새로 만들지 않았다.

## 검사 근거와 한계
- Edge 인증·큐 검사 9건 통과.
- 브라우저 독립 갱신 스케줄러 검사 4건 통과.
- 첫 집중 실행에서 Garmin 상세 검사 6건 통과.
- 중간 타입 검사 통과 후 추가한 합성 일지 fixture의 필수 syncState 누락을 발견해 전체 EveningEntry 필드를 갖추도록 수정했다. 최종 후보 타입/빌드 결과는 별도 확인한다.
- Vitest forks/threads 작업자 시작이 반복해서 시간 초과됐다. 별도 설치된 Node v24.22.1에서도 같은 시작 실패가 발생했다. 이 결과는 UI 검사 통과가 아니다.
- CUA 응답 및 Playwright Chromium 시작이 시간 초과되어 시각 검수·접근성 완료를 주장하지 않는다.
- 단일 프로세스 합성 DOM 검사와 원격 빌드를 대체 확인 경로로 진행한다. 배포 결과는 별도 영수증으로 확인한다.

## 전체 기획에서 남은 작업
1. 실제 Garmin 계정·Health API 범위와 운동/수면/심박 수신 왕복.
2. 제공자 건강 관측값의 자동 수집·원본 보관·수면 단계·일일 심박 상세. 현재 홈은 이미 저장된 일지 값을 표시한다.
3. Apple HealthKit·Android Health Connect의 실제 변경 피드와 계정 수신. 현재 모바일 후보는 미리보기 브리지 중심이다.
4. COROS 파트너 런타임, 제조사 운동부하 상세, 교차 제공자 중복 대표 선택·되돌리기.
5. 주간 사실 비교·회고, 운영 큐 대기 시간과 저장→표시 p95 계측.
6. 전체 후보 UI 검사, 공개 배포 및 실제 계정 검증.
