## 승인된 전체 방향

새 목표 진입만으로 이전 요구를 대체하지 않는다.

- 개인 기록을 쓰는 기존 처방 경로를 유지한다. 목표 기록을 현재 실력으로 저장하지 않는다.
- 처음에는 추천 처방 하나와 실제 수행 순서를 보여준다. 설명과 조절은 필요할 때 연다.
- 기록을 입력하지 않는 사람도 목표 프로그램을 먼저 둘러볼 수 있어야 한다.
- 10km 목표는 60·50·45·40·30분 모두 포함한다. 30분 목표 선택을 초보자의 수행 적합성으로 해석하지 않는다.
- 새 목표 프로그램은 9.5일 × 3주기, 57반일, 29개 날짜이다. 휴식을 명시하고 하루 훈련은 최대 한 번이다.
- D-day는 날짜를 역산한다. 기간이 부족해도 훈련을 압축하거나 대회일을 몰래 옮기지 않는다.
- 7열 달력에는 짧은 훈련명과 분량, 날짜를 열면 준비·본운동·회복·정리를 보여준다. 모바일 목록도 제공한다.
- 익숙한 사용자와 코치의 조절은 기존 최신 상태 확인·안전·저장 경로를 사용한다.
- 목표별 실제 훈련량과 주기화는 검토된 프로그램 원본에 근거해야 한다. 임의 숫자, 성공 보장, 엘리트 원본의 초보자 일괄 적용을 금지한다.

## 준비했으나 앱 진입점에 연결하지 않은 변경

`goal-program-calendar.ts`는 훈련 수치를 만들지 않는 순수 날짜 계약이다.

- 57반일을 세 개의 19반일 주기로 구분한다.
- 공유 날짜 양쪽에 두 훈련이 들어가면 거절한다.
- 29개 날짜 중 빠진 날짜를 휴식으로 자동 채우지 않는다.
- 대회 날짜 역산, 과거 시작일 거절, 윤년·월/연도 경계를 처리한다.

`GoalProgramEntry.tsx`는 목표 → 오늘/시작일/D-day → 미리보기 요청의 표시 컴포넌트다.
계정·일지 조회나 활성화·저장을 하지 않으며 **현재 앱에 라우팅되어 있지 않다**.
가까운 대회일에 사용자가 오늘 시작 대안을 선택하면 대회 지정과 분리된 요청을 만든다.
이 구성 요소가 존재한다는 이유로 한 달 훈련표가 이미 제공된다고 보고하지 않는다.

## 남은 핵심 작업

1. **목표별 검토 원본 확보**: 5개 목표와 초보 준비 과정의 날짜별 운동·휴식, 준비·정리, 반복·회복, 증량/회복/대회 전 구성을 검수한다. 사용자의 코치 자료에서 출처를 확인하되 개인정보를 앱 자산으로 복사하지 않는다.
2. **미리보기 → 수행 적합성 확인 → 명시 적용 연결**: 기록 미입력·목표만 있음·초보·숙련자/코치 경로를 구별하고, 미리보기만으로 안전 확인·개인 페이스·저장이 활성화되지 않게 한다.
3. **3주기 저장 모델**: 기존 프레임을 28.5일로 늘리지 않는다. 세 개의 검증된 프레임을 감싸는 버전 있는 프로그램 문서/현재 주기 전환/충돌 보존을 별도로 구현한다. 현재 단일 `currentPlanId`를 미래 주기 대기열처럼 오용하지 않는다.
4. **29일 실제 프로그램 달력 연결**: 현재 opt-in 달력은 기존 한 프레임의 표시 개선이다. 29일 데이터 투영은 검토 원본 및 새 저장 계약을 사용해야 한다.
5. **재방문·조절·복원 통합**: 기본 화면 재진입, 탐색 중 초안 보존, 시작하지 않은 오늘 조절, 최신 revision 재확인, 계정 전환과 백업/복원까지 프로그램 단위로 검증한다.
6. 최종 통합 후 변경 위험에 맞는 릴리스 검사, 최신 원격 상태 확인, 커밋/푸시/배포를 따로 보고한다.

현재 `creator-program/registry.ts`는 빈 registry이며 공급 상태는 `BLOCKED_SOURCE`다.
10km goal-paced 단일 세션 원본은 존재하지만 **단일 세션의 계산 가능성과 3주기 프로그램 승인/적합성은 다르다**.
기존 자료로 검수용 프로그램 구성안을 작성할지, 오너가 목표별 원본을 지정할지 질문했으나 이 시점 답변은 없다.

## 시각 확인 범위와 한계

- 합성 1500m 계획을 사용한 로컬 게스트 경로다. 실제 선수 기록이나 계정은 사용하지 않았다. 이는 미구현 10km 29일 프로그램의 화면 증거가 아니다.
- 담당자는 320/375px에서 PNG와 실제 viewport가 각각 320×900/375×900임을 확인했다. `innerWidth = clientWidth = documentScrollWidth`이며 가로 문서 넘침이 없었다.
- 부모가 직접 확인한 대표 이미지: `app/.codex-calendar-visual-qa/review-calendar-375.png`, `review-calendar-1280.png`, `review-reader-320.png`. 7열 달력, 분·초 표시, 날짜 reader의 준비·본운동·정리와 본문 폭을 확인했다.
- 이전 목록 캡처에서 하루마다 반복된 물음표·설명·확대 도구를 발견해 마지막 lightweight 목록으로 다시 수정했다. 이전 `review-list-*.png`를 최종 목록의 통과 증거로 쓰지 않는다.
- 마지막 브라우저 DOM 확인에서 첫 훈련·총시간 → 페이스 안내 → 시작 버튼 → 전체 일정/날짜별 목록 순서를 확인했다. 목록·reader 전환/초점 복귀는 최종 계약 테스트로 확인했다.
- 마지막 목록은 담당자가 CUA의 320×900 viewport-only 이미지로 확인했다. 날짜·슬롯·훈련명·분량 위주이며 반복 도구가 없고, 시작 버튼은 전체 일정 앞에 있었다. 이 이미지는 도구 출력으로만 제공돼 로컬 파일 경로를 확보하지 못했으며 부모가 직접 열어 재확인한 이미지와는 구분한다. 전체 페이지 캡처와 별도 headless 접속은 시간 초과로 종료했으며 추가 재시도하지 않았다.
- 실기기 iOS/Safari, 큰 글씨 전체 조합, 인증 계정 저장, 3주기 프로그램 저장·복원, CI와 배포는 이번 증거에 포함하지 않는다.

`git fetch origin`은 네트워크 이름 확인 오류로 실패했으므로 원격 최신성을 확인했다고 보고하지 않는다.
기존 `.scratch`, `review-captures`, 개인 성향 캐릭터 contact sheet 등 선행 untracked 파일은 보존한다.
실제 계정·개인 선수 기록으로 테스트하지 않았고 서버·안전·구매·계정 저장 정책을 변경하지 않았다.
담당자가 만든 `.codex-vitest-calendar-temp`와 4176 개발 서버 세션은 정리했다. 소유하지 않은 4175 서버는 건드리지 않았다. 검토용 이전 이미지들은 유지하지만 최종 목록 이미지로 잘못 인용하지 않는다.

다음 작업자는 이 보고서의 미완 범위와 실제 코드의 연결 여부를 먼저 확인해야 한다.
