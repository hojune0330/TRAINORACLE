## 1. 결정 요약

계정 로그인과 서버 동기화는 같은 기능으로 취급하지 않는다. 로그인했다고 로컬 데이터를 자동 업로드하지 않으며, 사용자가 데이터 종류를 보고 동기화를 별도로 켜야 한다.

서버 동기화는 다음 세 단계로 연다.

| 단계 | 데이터 | 현재 결정 |
|---|---|---|
| 1 | 구조화된 일지, 삭제 표식, 선택한 암호화 메모 | 기존 계약과 DB 경로를 유지한다. 실제 A/B 계정 검증 전에는 공개하지 않는다. |
| 2 | 선수 기록, 꾸미기 상태 | 새 RLS 스키마와 충돌 확인 화면을 만든 뒤 시험 환경에서 연다. |
| 3 | 선택된 훈련 계획 스냅샷과 수행 진행 | 안전 상태·계획 버전·출처를 함께 보존하는 별도 계약과 시험을 통과한 뒤 연다. |

포인트 잔액은 서버로 옮기는 독립 자산이 아니다. 포인트는 유효한 일지 행동에서 다시 계산하며, 꾸미기 상태에는 사용한 포인트와 소유 항목만 보존한다.

## 2. 데이터별 허용 범위

### 2.1 선수 기록

허용:

- 종목 거리
- 기록 시간
- 기록 목적(PB, SB, 최근 기록, 목표 기록)
- 달성 날짜와 시즌 ID
- 사용자 직접 입력 또는 승인된 출처 코드

금지:

- 메모 원문
- 증상·부상 서술
- 기록을 근거로 D9 위험을 해제하는 처리
- 같은 종목 기록의 무조건 덮어쓰기

같은 ID 또는 같은 경기 사실이 다르면 양쪽을 보존하고 사용자가 확인하기 전에는 개인 페이스 근거로 새 버전을 자동 채택하지 않는다.

### 2.2 꾸미기

허용:

- 소유한 카탈로그 ID
- 사용한 포인트 합계
- 선택한 테마·잉크·아바타
- 즐겨찾기·최근 사용 ID
- 날짜와 고정 슬롯으로 제한된 배치

금지:

- 현금 가치, 양도 가능 잔액 또는 결제 수단으로 해석
- 훈련 거리·속도·강도에 따른 잠금 해제
- 통증이나 휴식을 숨기게 만드는 보상
- 일지 메모나 증상 문구의 복제

계정과 기기 양쪽에 실제 꾸미기 이력이 있으면 자동 병합하지 않는다. 빈 기본 상태만 있는 쪽은 실제 이력으로 보지 않는다.

### 2.3 훈련 계획

허용 후보:

- 사용자가 선택해 저장한 계획의 불변 스냅샷
- 계획 생성 규격 버전과 처방 카탈로그 버전
- 계획의 기록 근거 ID와 페이스 계산 버전
- 일자별 세션 ID 및 구조화된 수행 상태
- 당시 D9/RVE/Safety Gate 결과 코드와 시각

초기 서버 동기화에서 제외:

- 생성 중 후보 전체
- 자유 메모와 증상 서술
- 로컬 적응 계산의 임시 후보
- 자동 활성화 명령
- 서버가 계획 강도·양·빈도를 다시 계산하는 기능

서버 저장 성공은 계획의 안전 승인이나 의료적 허가가 아니다. `D9_ACTIVE`와 `D9_UNKNOWN`은 기존 규칙대로 계획 실행을 막으며, 서버 사본이 이 상태를 지우거나 `CLEARED`로 바꿀 수 없다.

## 3. 충돌과 기기 이전

```yaml
conflict_policy:
  automatic_overwrite: forbidden
  automatic_plan_merge: forbidden
  preserve_both_until_user_choice: required
  source_delete_before_verified_target_write: forbidden
  per_resource_result_and_conflict_handling: required
  raw_text_in_conflict_audit: forbidden
```

로그인 전에 만든 데이터는 다음 원칙으로 계정에 연결한다.

1. 계획, 선수 기록, 꾸미기를 각각 독립적으로 검사한다.
2. 사용자가 첫 버튼에서 대상과 충돌 여부를 확인한다.
3. 두 번째 버튼을 눌렀을 때만 현재 계정으로 옮긴다.
4. 대상 계정에 같은 종류의 실제 데이터가 있으면 양쪽을 그대로 둔다.
5. 쓰기나 원본 제거가 실패하면 해당 종류의 정확한 원래 바이트로 복구한다.

## 4. 출시 게이트

아래 증거 전에는 2단계와 3단계 서버 동기화를 공개하지 않는다.

- 실제 서로 다른 계정 A/B의 RLS 교차 읽기·쓰기 차단
- 서로 다른 브라우저 프로필에서 로컬 화면 격리
- 로그아웃·계정 전환·재로그인 후 이전 계정 데이터 비노출
- 종류별 업로드 동의와 취소
- 네트워크 중단, 부분 성공, 재시도, 삭제 표식 왕복
- 충돌 시 양쪽 보존과 사용자 선택
- 계획 서버 사본이 D9/RVE/Safety Gate를 변경하지 않는 시험

## 5. 이번 결정이 하지 않는 주장

- 선수 기록·꾸미기·훈련 계획 서버 테이블이 구현됐다는 주장이 아니다.
- 실제 Supabase A/B 브라우저 검증이 끝났다는 주장이 아니다.
- 계정 또는 동기화 공개 승인이 아니다.
- 기존 열린 이슈를 닫거나 스펙을 정본으로 승격하지 않는다.
