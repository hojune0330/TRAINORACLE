# 설치 안내 숨김과 훈련 입력 여백 — 2026-10-06

## 승인·기준 상태

- 사용자 승인: 설치 확인 시 안내 숨김, 확인되지 않는 브라우저에는 `이미 추가했어요` 선택 제공.
- 작업 시작 소스: `b2873671380da7469fd49d8bda8404195a37702c`, 원격 main과 일치.
- 기존 공개 배포: Pages `0762b65521aa8c765df1ae82efdca3b25c9e22ae`.
- 캡처 및 공개 DOM: PC 1920px에서도 `.app-shell`은 520px, 계획 입력 컨테이너는 padding 0.

## 변경

- 실제 standalone 실행 또는 `appinstalled` 관찰 시 홈 제안과 더보기 설치 항목을 모두 숨긴다.
- 별도 기기 선호 `trainoracle:install-shortcut:suppression:v1`에 `manual` 또는 `confirmed`만 저장한다. 이 값은 안내 억제 선호이며 현재 설치 사실을 증명하지 않는다.
- 설치 요청 수락만으로 설치 완료나 confirmed 선호를 기록하지 않는다.
- `이미 추가했어요`는 안내만 숨긴다. 설치가 현재 확인되지 않는 브라우저의 더보기에는 작은 `바로가기 안내 다시 보기` 동작을 둔다.
- 복원은 해당 선호 키만 제거한다. 일지·계획·계정 데이터 삭제나 사이트 데이터 전체 초기화를 사용하지 않는다.
- 기존 7일 닫기 동작을 보존한다. 저장이 막히면 현재 화면의 선호만 유지하며 재방문 저장을 보장하지 않는다.
- 서로 다른 브라우저나 별도 저장 환경 사이의 설치 감지를 보장하지 않는다.
- 메뉴/복원 버튼의 React 식별자를 분리하고, 숨김 후 DOM 교체가 끝난 뒤 안전한 대상으로 포커스를 복귀시킨다.
- `.app-flow-stage > .account-plan-runtime:has(> .instant-plan)`에 20px 여백, 380px 이하에 16px 여백을 적용한다. 홈 내장 뷰와 기존 상세 계획·일지 프레임은 제외한다.

## PC 크기 설명·미변경 범위

- 기본 셸은 `workspace` 파라미터가 없는 경우 항상 선택된다. `app=1`이 PC를 모바일로 강제하는 별도 원인은 아니다.
- 520px은 기존 앱 토큰의 의도된 제한이다. 입력의 가장자리 밀착은 별개의 여백 누락이었다.
- `workspace`는 여러 모바일 프레임을 보여주는 갤러리이므로 일반 PC용 반응형 앱의 대안으로 소개하지 않는다.
- PC 폭 확대는 사용자 선호를 별도로 요청했다. 이번 변경은 전체 폭·하단 탭·일지 좌표계·훈련 계산을 바꾸지 않는다.

## 실행 증거

- 관련 3개 파일: InstallShortcut 19개, plan-entry-container 2개, visual-system 10개 — 31/31 통과.
- 결함 주입으로 설치 감지 메뉴 숨김과 실제 여백 누락을 각각 해당 이름의 테스트 실패로 확인하고 원복했다.
- 주입 실행에서 별도의 포커스 문제도 드러났다. DOM 버튼 교체 후 복귀를 수정한 뒤 같은 최종 테스트 31개가 통과했다.
- 작업자 최초 sandbox 검사는 기존 junction의 realpath EPERM으로 0건 실행되었다. 최종 검사는 동일 범위에서 허용된 실행으로 수행했다.
- 타입 검사, 최종 빌드 및 공개 반영 상태는 배포 영수증에 따로 기록한다. 전체 CI·실제 모바일 설치·계정 왕복 성공을 이 결과로 주장하지 않는다.
