# TrainOracle 무료 베타 200명 구현 보고서

작성일: 2026-08-01
대상 브랜치: `codex/beta-200-formal`

## 결론

이번 변경은 기존 로컬 일지를 유지하면서 무료 베타에 필요한 계정·동기화·공유·일지 경험·FAQ의 기반을 추가한다.

서비스 운영자는 제품 규칙과 기능 공개 여부를 직접 결정한다. 외부 전문가 승인을 공개 조건으로 두지 않는다. 대신 문제가 생긴 기능만 즉시 끌 수 있는 스위치를 둔다. 자동 처방과 같이 책임이 큰 기능은 기본값을 꺼 둔다.

코드가 존재하는 것과 공개 가능한 것은 구분한다. 서버 자격 정보와 운영 설정이 없는 기능은 켜지지 않는다.

## 이번 변경에서 실제로 완성한 것

### 일지와 사용 경험

- 첫 화면에 누적 참여일, 연속 기록, 불꽃·식물 상태, 기분·몸 상태·날씨 직접 선택을 배치했다.
- 달력·주간·9일/10일 교대 주기·하루 상세로 지난 일지를 탐색할 수 있다.
- 베타 포인트는 테마·스티커·아바타에만 사용한다. 현금화·양도·훈련 강도 보상은 없다.
- CSV·JSON·TCX·GPX 파일을 기기에서 읽고 미리보기에서 고른 항목만 저장한다. Garmin 자동 연동은 열지 않았다.
- 피로를 신경계·대사계·근육·충격 부하·주관적 피로로 나눠 직접 기록할 수 있다. 통합 참고값은 별도 선택이 있어야 보인다.

### 쉬운 FAQ

- 필수 질문 13개를 중학생도 읽을 수 있는 문장으로 추가했다.
- 첫 200명 베타가 무료라는 점과 나중에 월 구독 또는 광고가 포함된 선택 상품이 생길 수 있다는 점을 함께 알린다.
- `Owner`라는 표현은 사용자 안내에 쓰지 않고 `서비스 운영자`, `사용자`, `선수`, `코치·지원자`, `보호자`로 구분한다.

### 계정과 데이터

- 기존 이메일 인증번호·Google 로그인 공개 게이트를 유지했다.
- 생년월일과 제품 분석 동의를 별도 프로필로 저장한다.
- 로그인 뒤 서버·기기 기록 개수를 미리 본 후 별도 버튼으로 병합한다.
- `나만의 메모`는 브라우저에서 AES-GCM으로 암호화하고 서버에는 암호문만 보낸다. PBKDF2 반복 수는 210,000회이며 복구 코드는 세션 저장소에만 둔다.
- `훈련 메모`는 사용자가 공유를 켠 경우에만 일반 일지 동기화에 포함한다.
- 제품 분석은 별도 동의가 있어야 하며 정해진 이벤트 이름과 시각만 저장한다. 메모·통증·기분·훈련 내용 필드는 없다.
- 계정 삭제 요청 뒤 데이터 접근을 차단하고 30일 안에 서버 계정과 백업을 지우는 서비스 전용 정리 함수를 만들었다.

### 보호자와 코치·지원자

- 초대 원문은 서버에 저장하지 않고 SHA-256 해시만 보낸다.
- 코치·지원자는 항상 `자격 미확인`으로 표시한다.
- 기본 공유 범위는 훈련 기록·훈련 메모·통증·기분·몸 상태이며 `나만의 메모`는 데이터베이스 제약으로도 제외한다.
- 만 14세 미만 계정은 로그인한 보호자가 확인하기 전 동기화와 첫 공유 연결을 사용할 수 없다.
- 코치 초대 수락은 코치 계정으로 실행할 수 있게 선수 본인 확인 조건과 선수 계정 상태 확인 조건을 분리했다.

### 계획 제안과 안전 확인

- 제안은 `DRAFT`로만 생성되고 선수만 검토할 수 있다.
- 경고가 없으면 한 번, 경고가 있으면 서로 다른 두 단계로 확인한다.
- 경고 이유와 보수적인 대안을 표시하고 의료 허가가 아니라는 문구를 유지한다.
- 이전 제안은 삭제하지 않는다.

다음 스위치를 GitHub Pages 빌드까지 연결했다.

### 공격형 점검에서 막은 서버 결함

- 코치·지원자가 계획 제안을 만들 수 없던 권한 조건을 선수 계정 상태 확인과 제안자 확인으로 분리했다.
- 제안자가 다른 사용자의 식별자를 넣어 기록 출처를 위조하지 못하도록 서버가 로그인 사용자를 직접 대조한다.
- 생년월일 프로필이 없을 때 성인으로 간주되던 우회를 없애고 유효한 프로필 없이는 동기화·공유를 열지 않는다.
- 계정 삭제 요청 시각과 제품 분석 만료 시각은 브라우저 값이 아니라 서버 시각으로만 기록한다.
- 삭제 요청 뒤에는 본인뿐 아니라 연결된 코치·지원자의 일지 열람과 계획 검토도 막는다.
- 제품 분석 이벤트는 허용 목록과 별도 동의를 서버 함수에서 다시 확인하며 브라우저의 직접 삽입은 금지한다.

## 아직 공개하면 안 되는 부분

| 기능 | 남은 일 | 현재 조치 |

| 동기화 | 실제 Supabase에서 200명·하루 1,000회 저장·순간 50요청 시험 | 동기화 꺼짐 |
| 보호자 | 법정대리인임을 확인하는 운영 수단과 시즌 갱신·공유 확대 화면 | 공유 꺼짐 |
| 계획 제안 | 서버 제안의 계획 본문과 로컬 활성 계획을 실패 없이 한 번에 전환하는 연결, 코치 작성 화면 | 계획 제안 꺼짐 |
| 제품 분석 | 예약 정리 작업의 시험 환경 실행과 운영 지표 화면 | 제품 분석 꺼짐 |

위 항목은 외부 전문가의 승인을 기다린다는 뜻이 아니다. 서비스 운영자가 실제 서버 설정과 실패 시험 결과를 확인한 뒤 해당 스위치를 열면 된다.

## 데이터베이스 적용 순서

이 문서의 기존 `0001`~`0010` 목록은 더 이상 정본이 아니다. 최신 정본은 `SERVER_OPERATIONS_IMPLEMENTATION_REPORT_2026-08-02.md`의 `데이터베이스 정본 순서`다. 중간 번호를 건너뛰거나 `0018`만 따로 적용하지 않는다.

## 용량 시험의 정확한 의미

자동 테스트는 200명 × 5건 = 1,000건의 병합과 50개 동시 클라이언트 병합이 자료를 잃지 않는지 검사한다. 이것은 브라우저 로직의 용량 시험이다.

실제 Supabase 네트워크·데이터베이스의 부하 시험은 아직 아니다. 운영 프로젝트와 별도의 시험 계정이 준비된 뒤 실행 결과를 남겨야 한다.

## 검증 결과

- 앱 단위·계약 테스트: `87`개 파일, `539/539` 통과
- 실제 브라우저: 데스크톱·모바일·320px·저모션에서 `185`개 통과, 화면 조건에 맞지 않는 `35`개 정상 건너뜀, 실패 `0`
- TypeScript 앱·브라우저 타입 검사와 프로덕션 빌드 통과
- D9 개인정보 경계 평가: `11/11` 통과
- 구현 패키지 테스트: `107/107` 통과
- 추론 하네스 `16`, 상세 처방 카탈로그 `30`, 조언형 추천기 `42`, 의존성 감사 `7`개 검사 통과
- 변경한 TypeScript `83`개 파일에서 금지된 형식 우회 `0`건
- 브라우저 클라이언트 용량 시험: `1,000`건 병합과 동시 `50`건 병합 통과

프로덕션 의존성의 높은 등급 취약점은 `0`건이다. 개발 전용 도구에서 기존 높은 등급 경고 `3`건이 남아 있다. 빌드는 성공하지만 가장 큰 자바스크립트 묶음이 약 `571 kB`라서 후속 코드 분할 대상으로 남긴다.

## 개인정보와 미성년자 기준

개인정보 보호법 제22조의2는 만 14세 미만 아동의 개인정보 처리에 동의가 필요할 때 법정대리인의 동의와 그 확인을 요구한다. 현재 구현은 이를 보수적으로 적용해 보호자 확인 전 동기화와 공유를 닫는다.

참고: [국가법령정보센터 개인정보 보호법 제22조의2](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=02&joNo=0022&lsiSeq=270351&urlMode=lsScJoRltInfoR)

## 공개 순서

1. 이번 PR을 병합해 로컬 일지·FAQ·꾸미기·기기 파일 가져오기를 공개한다.
2. Supabase 마이그레이션과 인증 공급자를 시험 환경에 적용한다.
3. 계정 삭제, 사용자 간 권한 분리, 암호문 전용 저장을 실제 서버에서 확인한다.
4. 계정과 동기화를 먼저 연다.
5. 보호자·시즌 갱신·공유 확대 흐름이 끝난 뒤 공유를 연다.
6. 계획 본문 전환이 원자적으로 연결된 뒤 계획 제안을 연다.
7. 별도 동의와 30일 정리 일정이 확인된 뒤 제품 분석을 연다.
