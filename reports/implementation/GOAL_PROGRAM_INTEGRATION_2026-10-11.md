## 구현

- 훈련 화면의 `10km 한 달 훈련표`로 진입한다. 60·50·45·40·30분 목표, 오늘/시작일/D-day, 경험 선택 뒤 미리보기를 제공한다.
- 사용자 최종 확인대로 **9.5일은 마이크로사이클 하나**, 세 번을 묶은 28.5일이 한 달 기본 프로그램이다. 29개 날짜는 달력 표현이다. UI의 하위 단위는 `1차·2차·3차, 각 9.5일`이다.
- 원본 3프레임, 57반일, 두 번째 PM 시작을 지원한다. 기존 AM/누락 startSlot의 정체성과 이전 저장 문서를 유지한다.
- 달력/목록, 날짜 reader, 원본 기반 정확한 분·초, 짧은 휴식 표시, 주기 시작·대회 날짜 표시를 연결했다. 미리보기는 저장/활성화하지 않는다.
- 실제 계획은 최신 몸 상태를 확인하고 명시적으로 시작한다. 시간 초과 원본에는 전체 시간 확인을 별도로 요구한다.
- 보관/재진입/현재 마이크로사이클 수정/진행 표시/명시 종료/다음 시작/새 프로그램 교체/전용 파일 백업·복원을 구현했다.
- 최신 변경·소유 계정·반환 시점·storage readback을 확인한다. 원본이 불명확하거나 충돌하면 기본값으로 덮어쓰지 않는다.
- 로컬 데이터 삭제에 새 두 저장 키와 계정별 파생 키를 포함했다.
- 앱 PM 스키마와 두 로컬 서버 검증 번들을 일치시켰다. 운영 서버 변경은 하지 않았다.

## 독립 검토에서 확인한 경계

- 코치 PDF는 월별 배치·훈련 다양성의 참고 자료이지 목표별 한 달 증량·테이퍼의 검수 원본이 아니다. 두 번째 원문 PDF는 발견하지 못했고 허용된 이미지 파생본 일부를 확인한 한계를 유지한다. 개인 선수 수치/건강 메모를 코드·문서·테스트에 복사하지 않았다.
- 기본 시간·RPE 레시피는 같은 경험/횟수에서 목표 45분과 50분을 고르더라도 같을 수 있다. 별도 목표 페이스 선택만 기존 10km GOAL 기준을 사용한다. ACTUAL 기록을 만들지 않는다.
- 직접적인 회복 버그: 읽기 실패 후 재시도에서 `missing`이 되어도 진입 화면으로 돌아오지 못하던 상태를 수정했다.
- 미리보기와 저장 성공/적용 실패를 구분하고, 복원된 PAUSED 계획은 몸 상태 재확인 후 연결한다.
- 기본 시간을 넘는 카탈로그 원본의 장시간 확인이 빠진 경로를 보완했다. 단순 목표 페이스 체크로 이 확인을 대신하지 않는다.
- 원본 재투영 실패 시 과거 원본을 정상 일정처럼 보여주던 폴백을 제거했다.
- 공유 날짜에 2회 훈련이 생길 수 있다는 PM 편집 의심은 기존 편집 규칙과 실제 테스트로 검토했다. 존재하지 않는 문제를 이유로 도메인 규칙을 넓히지 않는다.

## 현재 남겨 둔 제품·릴리스 제한

- 새 프로그램은 기기 사용자의 실행 경로가 구현된 상태다. 계정 저장/서버 간 동기화 지원·실계정 왕복은 완료했다고 주장하지 않는다. 계정 모드 시작 제한을 그대로 유지했다.
- 별도 목표별 달성 보장, 자동 대회 전 테이퍼, 코치의 수치 그대로 복제, 무제한 편집 계보/보관은 구현 범위가 아니다.
- 기존 보관 한도는 18이며, 원본을 증명할 수 없는 상태는 보존 후 제한한다. 손상/충돌 원본 삭제나 과거 기록 재작성은 하지 않는다.
- 이 작업에서 커밋·푸시·병합·CI·수동 배포·실기기 Safari/실계정 확인은 아직 수행하지 않았다. 로컬 완료를 출시 완료로 부르지 않는다.
- 기존 `.scratch`, `review-captures`, 캐릭터 contact sheet 등 다른 작업자의 파일은 보존했다. 테스트 브라우저는 임시 컨텍스트만 사용한다.
