## 2. 구현 파일과 유지한 경계

- [실제 값 대조](../../app/src/domain/plan-main-comparison.ts): 후보 이름 대신 실제 값을 비교한다. 반복/회복 합계는 구조에서 다시 계산하며 과거 합계 캐시를 그대로 믿지 않는다.
- [비교 화면](../../app/src/screens/plan-beta/MainWorkComparison.tsx): 공통 수치는 한 번 표시하고, 다르거나 대응 구간이 없으면 A/B를 분리한다. 누락은 0이나 반대편 처방으로 채우지 않는다.
- [기존 후보 화면 연결](../../app/src/screens/plan-beta/PlanCandidates.tsx): `같은 횟수와 RPE` 고정 문구를 제거했다. 동일 RPE 봉투는 수치 일치로만 설명한다.
- [스펙 §12.1](../../specs/reconstruct/TRAINING_SESSION_PRESCRIPTION_CONTRACT.md): 비교 결과는 새 템플릿 수용·활성화·효과 동등성의 근거가 아니다.

출력 비교값에는 개인 기록 ID·앵커 참조·기록일·메모를 복제하지 않는다. 기존 처방의 목표 시간만 읽는다. 거리 기반 처방의 실제 소요시간을 계산된 확정값처럼 제시하지 않는다. 과거 계획, 승인된 네 템플릿, 청소년·자기 선택, 오전·오후, 기존 적응 제한과 D9 경계는 유지했다.

## 3. 독립 검토와 수정

범위를 나눈 읽기 전용 검토를 수행했다. 스포츠과학 심사나 Fable UX 수용 판정이 아니다.

1. 별도 파생 시퀀스 저장은 현재 실행·복원 능력을 더하지 않고 두 원본 사이 불일치만 늘릴 수 있어 제외했다.
2. 수치가 같은 RPE/시간 봉투를 명시적 방법 동일성으로 오인할 여지를 발견해 `sameMainValues`와 `sameMainPrescription`을 분리했다.
3. PACE 대 RPE 비교에서 양쪽 모두 반복 구간이 없는 것처럼 읽히던 상태 문구를 수정했다.
4. 삭제한 문구를 요구하던 기존 브라우저 검사 1개를 실제 실행해 실패를 확인하고 새 문구와 미지정 경계 단언으로 교체했다.

검토자가 함께 언급한 잘못된 PACE 구조(`setCount: 0`)는 이미 null/CONTEXT_MISMATCH 경로였다. 이 부분을 새로 발견·수정한 결함처럼 세지 않는다.

## 5. 아직 완료되지 않은 핵심 작업

1. **실제 서로 다른 두 MAIN 제공:** 현재 활성화된 상세 수치 템플릿 네 개 각각의 종목/목적에 두 번째 채택 방법이 없다. 이번 비교 화면은 이 공백을 숨기지 않는다.
2. **거리형·시간형·복합형 활성화:** 일반 시퀀스 표현은 있으나 새 독립 처방 저장/선택/실행/백업 계약과 정확한 구성 수용은 별도 단계다.
3. **상세 수치 범위 확대:** 10km·하프·마라톤과 초보/발전 단계의 구체적 수치 처방을 완료했다고 보지 않는다.
4. **반복 주기 관찰 확장:** 현재 정확한 일지 링크와 RPE 비교를 넘어, 여러 주기의 실제 구간 수행 비교가 남아 있다. 자동 증량·인과 단정은 하지 않는다.
5. **병합 전 분리 검수와 배포:** PR #314 → #315 순서의 head CI 및 Fable UX·코어/과학적 내용 검수 후 병합한다. 이후 main SHA·배포 receipt·공개 화면을 따로 확인한다.

다음 작업은 두 번째 MAIN의 정확한 구성·대상·회복·근거를 수용 가능한 패킷으로 만드는 것이다. 단순 반복 수 변경이나 현재 템플릿 복제로 이 단계를 대신하지 않는다. 제품 방향 승인과 특정 수치/대상 범위의 채택 증거를 혼동하지 않는다.
