## 1. 화면에서 달라진 것

| 역할 | 표현 | 적용 범위 |
|---|---|---|
| 경기 | 노랑 + 경기 전/경기 결과 또는 경기 일지 | 저장된 경기 일지 |
| 주요 훈련 | 연한 살구색 + 주요 | 계획의 명시적 QUALITY/MAIN |
| 플라이오 | 민트색 + 플라이오 | 전체 계열 선택값이 없고 구성 운동이 플라이오뿐일 때. 혼합이면 원래 색 안에 보조 글자 |
| 기본 운동 | 흰색 + 기본 | 계획 BASE/EASY+BASE, 직접 선택한 base 기록 |
| 회복 운동 | 하늘색 + 회복 | 계획 REC/RECOVERY, 직접 선택한 rest 기록 |
| 휴식 | 중립 회색 + 휴식 | 명시적 REST/OFF/RESTED |
| 미분류 | 중립 바탕 + 점선과 훈련/계열 이름 | 분류 정보가 없는 일지 또는 역할 미확인 |

오전·오후가 서로 다르면 날짜 안에서 독립적으로 칠한다. 오늘은 날짜 원, 선택한
날은 테두리, 계획/주기 범위는 하단 선으로 표시한다. 색상 뜻은 접힌 `달력 색상`에서
확인한다. 사용자 사진의 이름·처방을 복제하지 않고 별도의 합성 기록으로 확인했다.
혼합 기록은 한 면으로 묶는다. 계획 달력의 실제 기록에는 `일지`를 붙여 예정 훈련과 구별한다.

월 변경에는 짧은 등장, 누름에는 작은 즉각 반응, 선택 날짜에는 짧은 강조를 넣었다.
모션 종료를 기다리지 않고 조작할 수 있고 OS 모션 감소에서는 움직임을 제거한다.

## 3. 의미 보존과 제한

주요 역할과 고강도는 같은 개념이 아니다. ATP-PC를 플라이오로 자동 치환하지 않는다.
일지에 LT/VO2/GLY/ATP/MIX가 적혔다는 이유로 실제 MAIN 역할을 새로 만들지 않는다.
제목·메모·통증·체중·연결된 계획을 추측 분류 입력으로 읽지 않는다. 생리학적 강도,
회복 완료, 실제 계획 수행, 저장 성공을 색으로 판정하지 않는다.

현재 계획 스키마에는 독립 플라이오 세션과 저장된 경기 일정의 완전한 경로가 없다.
따라서 계획에 그런 일정을 새로 발명하지 않는다. 노란색은 현재 존재하는 경기 일지,
민트색은 명시된 실제 플라이오 구성에서 확인 가능하다. 향후 승인된 일정 모델이
연결되면 같은 색상 계약을 사용한다. 경기 날짜 저장의 별도 권한을 이번 색상 승인으로
변경하지 않았다.

## 5. 독립 검수

Luna max의 [독립 소스 검토](../review/CALENDAR_ROLE_COLOR_LUNA_REVIEW_2026-09-30.md)에서
P1 혼합 플라이오 중복 표시와 P2 계획 달력의 실제 기록 분류 누락을 받았다. 둘 다 재현 가능한
코드 경로로 확인하고 수정했다.

- P1: 한 일지는 한 면으로 유지한다. 플라이오 포함 문구는 같은 면 안의 보조 글자이며,
  미분류 혼합 기록 전체를 민트색으로 칠하지 않는다. 명시적 전체 계열과 구성 운동을 분리했다.
- P2: 계획 달력의 실제 기록에도 같은 분류 함수를 쓰고 `일지` 표시를 붙였다. 경기 전/후도
  개수로 합쳐 지우지 않는다. 3개 초과는 추가 개수, 접근 가능한 설명에는 전체를 포함한다.
- 혼합 기록 단위 검사와 계획/일지 양쪽 컴포넌트 검사를 추가했다. 동일 혼합 합성 기록으로
  실제 브라우저에서 한 면만 표시되고 예정 MAIN/회복과 구별됨을 다시 확인했다.
- 기존 AM/PM 영문 표시를 고정한 회귀 검사 한 곳은 이번 승인한 오전/오후 한글에 맞춰 갱신했다.

검수자는 테스트나 브라우저를 독립 실행하지 않았으며, 요청한 12개 페르소나·24개 시나리오
전체는 완료하지 못했다. 따라서 그 수의 독립 검증 완료나 독립 최종 APPROVE를 주장하지 않는다.
그의 원본 보고서는 수정하지 않고 보존했다. 수정 후 72개 검사와 80동작은 본 작업자의 실행이다.
앞선 계획의 30개 페르소나 검토와 이번 실제 브라우저 검증도 서로 다른 증거다.
