## 1. 승인과 이번 범위

오너는 상세 훈련 선택 확대와 코어 데이터·규칙 연결 방향을 승인했으며,
코어·스펙 정합성을 먼저 정리하고 개발하라고 지시했다. 이번 구현은 그 첫 단계다.
전체 분류기·D1~D8·9.5일 원장·새 MAIN 활성화를 완료했다고 주장하지 않는다.

| 작업 | 상태 | 달라진 점 |
| --- | --- | --- |
| 코어 지침·스펙 정합성 | 반영 | 현재 구현/배포 구분, 네 상세 승인본, AM/PM 상세 경계, 일지 비교 기준을 정리 |
| 일지-계획 증거 결합 | 구현 | 버전·시작일·세션 내용·날짜·AM/PM 전부 맞는 연결만 비교 |
| 비교 데이터 무결성 | 구현 | 중복은 한 번, 충돌·휴식·건너뜀·변경한 세션은 별도 설명 |
| 실제 사용자의 근거 확인 | 구현 | 훈련별 계획 RPE/직접 기록 RPE와 비교 제외 이유를 펼쳐 확인 |
| 다음 계획 연결 | 기존 경로 보강 | 반복된 높은 RPE에서 기존 감량 후보 확인으로 이동하되 명시적 요청·현재 안전 확인·최종 선택 유지 |
| 상세 훈련 선택 | 표시·적격성 개선 | 선택 전에 거리·반복·회복과 준비/정리를 확인, 경험 범위 밖은 선택 후 실패 대신 미리 설명 |
| 원문 동기화 우회 방지 | 구현 | 과거 동의값이 true여도 구조화 투영만 전송, 로컬 원문과 계획 연결 보존 |
| 새로운 MAIN 두세 가지 | 미완 | 같은 종목의 추가 채택본이 없어 새 수치를 활성화하지 않음 |

## 2. 유지한 경계

- 청소년·성인에게 같은 적격성 기준을 적용한다. 나이·성별 배율을 추가하지 않는다.
- 자가 선택과 모든 가용일의 일 2회 설정을 유지한다.
- 원문·비밀 메모의 내용/존재를 비교·중복 판단에 사용하지 않는다.
- 일지를 많이 썼거나 RPE가 낮다는 이유로 강도·양·빈도를 자동 증가시키지 않는다.
- 상세 페이스 세션의 계획 RPE를 지어내지 않는다. 실제 RPE는 관측으로만 보여준다.
- 비교 결과를 보고 있는 동안 기존 계획·상세 MAIN·기록을 바꾸지 않는다.
- 기존 문서와 이슈를 삭제하거나 정본으로 승격하지 않는다.

## 3. 추가 MAIN 승인 사실 확인

현재 `app/src/domain/detailed-prescription-manifest.json`의 네 승인본과
`detailed-prescription-runtime-authority.ts`의 실제 허용 목록을 재확인했다.
기존 800/1500/3000/5000m 각 한 종류 외에 실행 가능한 추가 승인본은 없다.
기존 `OWNER_DECISION_PERSONALIZED_PRESCRIPTION_ALGORITHM_V2_2026-08-23.json`은
종목별 2~3개 방향을 승인했지만, 추가본은 코칭 적합성과 스포츠과학 전이 검토를
동일 내용 지문에 묶도록 요구한다. AI 검토를 그 사람 검토로 기록하지 않는다.

다음 검토 패킷에서 그대로 유지할 실제 카탈로그 예시는 다음과 같다. 아래는
선수에게 적용할 처방이 아니며, 새 반복 수·페이스·회복 방식을 확정하지 않았다.

| 기존 예시 | 아직 결정해야 할 것 | 주의 |
| --- | --- | --- |

### 4.1 테스트가 실제 결함을 잡는지 확인

- 정확한 계획 ID 검증과 occurrence 중복 제거를 일시적으로 무력화했을 때
  기존 주기 테스트 17개 중 5개가 이름 단위로 실패했다. 동일 기록 중복,
  충돌 입력, 비밀 메모 무접근 중복 검사, 이전 계획 버전/시작일, 바뀐 세션
  내용 검사가 각각 실패했다. 원상복구 후 전체 앱 검사가 통과했다.
- 원문 업로드 우회 분기를 되살린 실험은 동기화 테스트 7개를 실패시켰다.
  provenance/plan link 누락 실험은 21개를 실패시켰다. 복구 후 동기화 관련
  146개 검사가 통과했다. 이 146개는 전체 앱 테스트와 중복되므로 합산하지 않는다.
- 기존 적응 정책 검사가 Windows CRLF 문장을 LF 문자열로만 검사해 정상 문서를
  반려했다. CRLF 전용 회귀 테스트가 수정 전 실패함을 확인한 뒤 줄바꿈만
  정규화했다. 실제 규칙 변경은 계속 거부하며, 테스트의 변조 대상도 존재 확인한다.
- 추가 브라우저 검사의 첫 실행은 완료 상태의 비동기 저장을 기다리기 전에
  비교 기준을 읽어 2건 실패했다. 완료 저장을 직접 확인한 뒤 비교하도록
  테스트를 수정했고, 최종 22개가 모두 통과했다. 제품 결함으로 숨겨 기록하지 않는다.
- 기존 e2e가 과거 `.omo/evidence` 이미지를 덮어쓰던 경로를 실행별
  `testInfo.outputPath`로 바꿨다. 이번 실행이 바꾼 과거 이미지 6개는 원래
  상태로 복구했고 아래 새 증거만 별도로 보존한다.
