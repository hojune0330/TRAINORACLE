## 1. 검수와 구현의 구분

원본 검수는 `reports/review/LUNA_MAX_PRESCRIPTION_LIFECYCLE_REVIEW_2026-10-02.md`에 보존한다.
Luna 최고 추론 독립 작업자 3명이 24개 페르소나 관점으로 검토했고, 부모 검수자는
8개 실제 브라우저 생성 표본을 실행했다. 24개 관점을 24명 브라우저 실행으로 세지 않는다.
이 문서는 그 검수의 권고 1~5를 반영한 구현·재검증 보고서이며, 새 독립 승인서는 아니다.

감량은 기존 검토된 같은 방식의 짧은 구성 규칙만 사용하며 새 알고리즘 권한을 만들지 않았다.

## 3. 통합 검증에서 추가 발견한 결함

현재 전체 작업본의 개발 미리보기에서 6개 브라우저 시나리오 중 5개가 실패했다.
화면 초기화를 StrictMode가 재실행하면, 일지에서 돌아온 날짜를 펼친 직후 달력 초기화가
다시 접는 경로였다. 저장 자료 손실은 아니지만 복귀 위치와 기록 확인 흐름이 깨졌다.

`PlanSchedulePreview`의 초기화는 실제 달력 식별자가 바뀔 때만 수행하도록 수정했다.
StrictMode 전용 회귀 테스트와 실제 취소·빠른 일지·상세 일지 복귀 검증을 추가했다.
수정 뒤 현재 통합 코드에서 6/6 브라우저 시나리오가 통과했다.

200m 반복 목표 30.375초를 정수로 강제하지 않는다.
부분 수행은 선택한 변경 이유를 보존하되 완료로 바꾸지 않는다.

추가 감량 여정은 실제 생성기·검증기로 만든 합성 선행 계획과 정확히 연결된 높은 RPE 일지
2개를 초기 자료로 주입한다. 사용자 자료를 사용하지 않았다. 화면에서 다음 계획 요청 →
안전 확인 → 높은 RPE 2회라는 근거 확인 → 수락 → P-LT-B-480 두 개로 변경된 저장값 →
새로고침 후 보존 → 기존 일지 불변까지 확인했다. 앞선 2개 일지를 이 시나리오에서 직접
입력했다고 주장하지 않는다. 직접 입력 흐름은 별도 부분/완료 여정이 검증한다.

## 5. 빌드와 공개 범위

초기에는 현재 통합 프로덕션 빌드가 2318개 모듈 변환 후 상세 오류 출력 없이 종료했다.
자식 프로세스 종료 코드를 직접 수집해 Windows 코드 3221226505(0xC0000409)를 확인했다.
Node 24.11.1에서 재현됐고, 같은 코드·라이브러리를 Node 24.19.0으로 실행하면 정상 빌드됐다.
라이브러리 삭제·교체나 제품 코드를 우회하지 않았다. 네이티브 내부의 정확한 결함 위치는 미확정이다.

`app/scripts/check-build-runtime.mjs`를 npm prebuild에 연결해 재현된 Windows 24.11.1에서는
조용히 종료되는 대신 검증된 24.19.0 사용 안내로 중단한다. 다른 OS에서 같은 버전이
고장 난다고 추정하지 않는다. 전역 Node 설치·설정은 변경하지 않았다.

현재 전체 작업본 프로덕션 빌드 PASS, `index-D3F7kYvd.js`. 위 9+6개 브라우저 검사는
이 빌드 출력으로 수행했다. 폰트의 빌드 시 경고는 있었으나 출력 fonts 폴더에 실제 파일이
존재한다. 대형 청크 경고는 남았고 성능 최적화 완료를 주장하지 않는다.

빌드 실패 차단 사유는 해소됐다. 다만 운영 계정 설정과 실제 서버 검증을 포함한 공개 배포 판정은 별도다.
이번 작업은 커밋·푸시·병합·Supabase 배포·Pages 배포를 하지 않았다.
실제 iPhone Safari, 로그인 계정 동시 저장, 실제 사용자의 훈련 효과도 검증하지 않았다.
합성 기록과 격리한 테스트 브라우저만 사용했으며 사용자 기존 자료는 수정하지 않았다.

## 6. 최종 독립 리뷰와 개선

추가 Luna 최고 추론 작업자 1명이 9개 관점에서 정적 독립 리뷰했다. 이 작업자는 파일을
수정하거나 브라우저 검사를 실행하지 않았다. 아래 런타임 재검증은 부모 작업자가 수행했다.
독립 리뷰의 발견 자체를 최종 독립 런타임 승인으로 바꾸어 표현하지 않는다.

| 발견 | 개선 | 최종 확인 |
| --- | --- | --- |
| 같은 계획 슬롯에 같은 완료 결과의 중복 일지가 있으면 진행 반영 가능 | 일지 ID와 계획 슬롯 링크가 각각 정확히 1개일 때만 반영. 중복 원문은 삭제하지 않음 | 동일 ID·다른 ID 중복 회귀 검사, 진행 불변·원문 보존 |
| 오래된 통증 동반 높은 RPE가 일반 감량 근거로 들어갈 수 있음 | 통증 신호를 별도로 분류하고 해당 기록으로 수치를 바꾸지 않음. 몸 상태 확인 이유 표시 | 최근 안전 검사 기간 밖의 통증 자료로 다음 주기 생성·수락 후 기존 상세 구성 유지, 두 화면 크기에서 확인 |
| 실제 수행 여부·오전/오후가 없는 과거 RPE의 감량 권한이 불명확 | 설명용 RPE 비교와 수치 변경 자격 분리. 명시적 완료·일치 슬롯·통증 없음 응답 및 출처가 있어야 감량 근거로 사용 | 누락 수행·슬롯·출처의 단위 반례 및 실제 화면의 미확인 수행 경로 확인 |

기존 간편 일지에 있는 응답을 사용하며 새 필수 질문 화면은 추가하지 않았다.
과거 미기록을 자동 보충하지 않고, 일부 수행을 완료로 승격하지 않으며, 통증이 없었다거나
회복됐다고 추정하지 않는다. 검토된 감량 구성 밖으로 증량·새 처방 권한을 확대하지 않았다.
해당 경계는 계획-일지 연결 계약의 오너 승인 부록에도 반영했다.

최종 판정: 이번 수정 범위의 로컬 구현·집중 검사·모바일 브라우저 여정은 통과했다.
실제 계정 간 동시 저장, iPhone Safari, 전체 카탈로그의 모든 조합, 생리학적 효과 검증은
이번 결과로 승인하지 않는다. 공개 배포와 운영 검증도 수행하지 않았다.
