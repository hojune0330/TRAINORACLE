## 문제

기존 `기기 데이터 확인하기` 흐름은 훈련 계획을 브라우저 안의 익명 키에서 계정별 키로 옮겼지만, 온라인 서버에는 저장하지 않았다. 그런데 화면은 `기기 훈련 계획을 연결했어요`라고 표시했다. 따라서 사용자는 온라인 저장이 끝난 것으로 이해할 수 있었고, 실제 서버 계획 컬렉션은 0건인 상태가 가능했다.

## 수정

1. 기기 계획을 계정 계획 패킷으로 검증한다. V1은 기존 파서로 의미가 같은 V2로 정규화하고, V2는 과거 계획으로만 보관한다.
2. 유효한 적응 컨텍스트가 있으면 같은 패킷에 보존하고, 유효하지 않으면 새 정보를 추정하지 않는다.
3. 계획을 현재 계획으로 자동 활성화하지 않고 온라인 계정 보관함의 이력으로 저장한다.
4. 서버가 `ACCOUNT` 영수증을 반환한 뒤에만 익명 기기 키를 계정별 기기 키로 이동한다.
5. 전송 대기, 충돌, 거절, 용량 초과, 검증 실패 때는 기기 원본을 그대로 보존한다.
6. 과거 흐름에서 이미 계정별 기기 키로 이동된 계획도 다시 찾아 온라인에 보관할 수 있다.
7. 서버에 동일한 계획과 진행 상태가 이미 있으면 중복 쓰기 없이 온라인 보관 완료로 처리한다.
8. UI는 온라인 계획 보관과 기기 내부 계정 구분을 서로 다른 문장으로 설명한다.
9. V2 계획은 현재 계획으로 지정하거나 진행률을 갱신할 수 없고, `SELECT`·`PROGRESS` 요청을 `REVIEW_REQUIRED`로 거절한다.

## 안전 경계

- 온라인 보관은 계획 실행 승인이나 안전 해제가 아니다.
- 보관된 계획을 다시 사용하려면 계획 화면에서 현재 상태를 확인하고 선택해야 한다.
- 서버 확인 전에는 로컬 원본을 삭제하거나 이동하지 않는다.
- 진행 상태가 다른 동일 계획은 자동 병합하지 않고 충돌로 남긴다.
- 선수 메모 원문이나 증상 문장을 계획 패킷에 새로 추가하지 않는다.

## 공개 검증

### 1차 공개 검증과 후속 수정

- 검증 대상: GitHub Actions run `34410120226`, main `a08567409a9069fcf3657f736629d212a7cf1bd1`
- 공개 앱은 과거 연결 흐름이 계정별 기기 공간으로 옮겨 둔 계획 1개를 정확히 감지했다.
- 첫 온라인 보관 요청은 완료되지 않았고, 화면은 실패를 알리면서 계정별 기기 원본을 그대로 보존했다.
- 같은 시각 서버 함수의 인증된 조회 요청은 HTTP 200으로 도착했지만, 새 계획 컬렉션 쓰기는 시작되지 않았다.
- 원인은 이전 단일 문서 저장 방식에서 새 계획 컬렉션으로의 전환이 필요한 상태를 기기 계획 가져오기 흐름이 처리하지 않은 데 있었다.
- 후속 수정은 기존 서버 문서를 먼저 새 컬렉션으로 전환하고, 그 전환이 서버에서 확인된 경우에만 기기 계획을 추가한다. 전환이 확인되지 않으면 기기 원본을 이동하지 않는다.
- 수정 코드를 제거한 회귀 실행은 `migrate -> store` 순서 검증에서 실제로 실패했고, 복원 후 통과했다.

이 기록은 실패와 보존을 확인한 중간 증거다. 후속 코드가 병합·배포되고 실제 계정에서 저장+완료될 때까지 문서 상태를 완료로 바꾸지 않는다.

후속 서버 재계수에서 새 컬렉션뿐 아니라 이전 방식의 서버 계획 문서도 0건임을 확인했다. 따라서 `migrationRequired` 선처리는 이전 문서가 존재하는 계정을 위한 예방적 호환 수리이며, 이번 실제 실패의 직접 원인으로 확정하지 않는다. 첫 공개 실패는 새 컬렉션을 쓰기 전 클라이언트 단계에서 발생했다. 다음 공개 진단에서는 뭉뚱그린 실패 문구 대신 저장 결과를 충돌·용량·거절·재검토·형식·사용 불가·기타 실패로 구분하며, 정확한 결과를 확인한 뒤 다음 수리를 결정한다.

정확한 공개 오류는 `invalid`였고 같은 요청 시각에 계획 컬렉션 함수 호출이 관찰되지 않았다. 코드 대조 결과, V1은 로컬에서 V2로 읽히지만 계정 패킷은 V3 이상만 허용하여 서버 호출 전에 탈락할 수 있었다. 이를 해결하기 위해 V2를 실행 불가 과거 계획으로만 수용했다. 실제 V1 원문을 사용한 회귀 테스트는 V2 정규화, `SAVE_HISTORY` 전송, 서버 확인 뒤에도 계정별 기기 원문 바이트가 그대로 남는 것을 검증한다. 이 진단은 공개 재시험에서 서버 영수증과 재조회가 확인될 때 최종 확정한다.

코드 병합과 GitHub Pages 배포 뒤 실제 계정에서 다음을 확인해야 완료로 전환한다.

1. 계정 화면에서 온라인 보관 버튼이 표시된다.
2. 클릭 후 온라인 보관 완료 문구가 표시된다.
3. 서버 계획 컬렉션의 인덱스·스냅샷·영수증이 실제로 생성된다.
4. 새로고침 후 계획 보관함에서 해당 계획을 확인할 수 있다.
5. 기기 원본 또는 계정별 기기 사본이 손실되지 않는다.
