## 1. 첫 계획의 상세 훈련

LT, VO2, MIX 등의 검토된 구성은 첫 생성에서 바로 계산한다. 임시 시간 범위 때문에 완전한 MAIN 구성이 사라지던 경로는 앞선 구현에서 수정했다.

이번에는 ATP-PC의 가속·감속 공간 등 실제 장소 조건을 첫 생성 화면에서 확인하고 상세 처방에 연결한다. 확인 전에는 체크를 자동으로 채우지 않는다. 날짜·대상·구성이 바뀌면 이전 확인을 재사용하지 않는다. 날짜를 바꿨다가 원래 날짜로 돌아와도 새로 확인한다.

거리형 훈련에 개인 페이스 근거가 없으면 구간 시간을 직접 정하는 기존 편집기를 연결한다. 사용자가 정한 시간은 개인 기록으로 계산한 추천 페이스라고 표시하지 않는다. 입문 경험에 맞는 해당계 구성이 아직 없는 경우 경험을 숙련으로 바꾸거나 신규 수치를 발명하지 않는다. 제공하지 못하는 범위를 짧게 안내하고 다른 목적을 명시적으로 선택할 수 있게 한다.

긴 훈련 설명은 접혀 있다. 먼저 날짜·반복 표기·총시간과 필요한 확인만 표시한다. 작성 중인 확인과 수동 편집이 있으면 미확정 변경을 숨긴 채 계획을 저장하지 않는다.

## 2. 실제 수행을 다음 계획으로 연결

일반 계획은 같은 목적의 정확히 연결된 수행 결과를 사용한다. 높은 RPE가 여러 번 반복된 경우 기존 검토 목록에 있는 같은 방법의 낮은 구성만 제안한다. 예: `2 x 10min, r60s Jog`에서 `2 x 8min, r60s Jog`. 강도·양·횟수를 자동으로 늘리지 않는다.

이번 비교는 구조화된 실제 운동·회복 구간까지 읽는다. 운동 거리가 다르거나 시간형 본운동·회복시간이 달라졌다면 원래 처방 그대로의 RPE 관찰에서 제외한다. 동일 거리에서 달린 시간이 달라진 것은 페이스 차이로 남긴다. 일부만 적었다고 나머지를 0이나 실패로 만들지 않는다.

두 형식의 수행 기록이 동시에 있거나 계산 연결이 위조되면 비교 불가로 남긴다. 아주 작은 숫자 변경도 근거 지문에 반영한다. 표시용 반올림 때문에 서로 다른 원본을 같은 기록으로 취급하지 않는다. 메모·운동 이름 등 자유 텍스트는 읽지 않는다.

다음 계획의 접힌 설명에서 이전 훈련과 다음 훈련의 실제 표기를 나란히 보여준다. 사용자가 새 계획을 시작하기 전에는 기존 계획과 일지를 그대로 보존한다.

## 3. 수정한 계획의 계승

수정 계획 version 4/5/6은 버전별 저장 검증과 당시 근거를 통과한 실제 AFTER 구성을 다음 주기로 이어간다. 원래 템플릿으로 되돌리거나 version 3으로 강제 변환하지 않는다.

수정된 MAIN에는 채택된 RPE 목표가 없는 경우가 있다. 이 경우 원래 템플릿의 RPE를 빌려 감소를 계산하지 않고 정확한 상세 구성을 유지한다. 현재 검토 범위에서 같은 구성을 새 날짜에 재발행할 수 없다면 적용하지 않는다. 이는 모든 수정 훈련의 자동 수치 적응을 허용한 것이 아니다.

## 4. 저장과 서버

- 미리보기 이후 일지·계획·계정이 바뀌면 새 적용을 거부한다.
- 계정 저장에서는 확인된 전체 일지 버전을 미리보기와 저장 요청에 묶고 기존 원자적 일지 보호 저장 경로를 사용한다.
- 다른 기기에서 추가·수정·삭제한 일지와 오래된 다음 주기 요청을 섞지 않는다.
- 이미 성공한 동일 요청의 응답 재확인은 새 쓰기 없이 기존 영수증으로 처리한다.
- 개인 메모, 인증정보, 실제 선수 자료는 이 작업의 테스트 자료로 사용하지 않는다.

운영 DB의 달력 보호 함수는 적용 후 본문·실행 권한을 읽기 전용으로 확인했다. 기존 다른 작업과 마이그레이션 번호가 겹쳐 저장소 파일은 `0043_catalog_replacement_calendar_guard.sql`로 정리했다. 운영 SQL을 두 번 실행한 것은 아니다. 영수증의 `0041`은 최초 실행 당시 파일명이며 현재 파일명은 별도 필드에 기록했다.
