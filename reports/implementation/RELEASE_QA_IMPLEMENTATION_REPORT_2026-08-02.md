# TrainOracle Task 17 반복·브라우저 공개 준비 검증

## 기준

- 검증 시작 main: `2a350cbadf613e2dcbf759ad8dc9c3becec74157`
- 범위: 반복 단위 검사, 320px, 키보드, 오프라인 로컬 일지, 전체 브라우저 회귀
- 운영 Supabase 적용, 기능 플래그 변경, 사용자 데이터 전송은 하지 않았다.

## 발견하고 고친 문제

서버 운영 마이그레이션 계약 검사가 줄바꿈을 Linux의 `LF`로만 가정했다. 같은 파일을 Windows가 `CRLF`로 체크아웃하면 실제 SQL 내용이 같아도 698/699로 실패했다.

파일을 읽는 테스트 경계에서 `CRLF`를 `LF`로 정규화했다. SQL과 제품 동작은 바꾸지 않았다. 수정 전 Windows 전체 검사에서 해당 1건이 실패했고, 수정 후 집중 검사 `43/43`과 전체 검사가 통과했다.

## 새 브라우저 계약

1. 앱 셸을 한 번 연 뒤 네트워크를 끊고 새로고침해도 로컬 일지가 열린다.
2. 오프라인에서 `3.2km`, `18분`, `RPE 5` 훈련을 저장하면 화면 영수증과 로컬 기록이 남는다.
3. 위 흐름은 데스크톱과 320px에서 모두 동작한다.
4. 320px에서 키보드 `Tab`만으로 하단 탭 5개를 순서대로 이동하고 `Enter`로 FAQ를 연다.
5. FAQ를 연 뒤 가로 넘침이 생기지 않는다.

## 실행 결과

| 검사 | 결과 |
|---|---|
| 전체 앱 단위 검사 1회 | `699/699` |
| 전체 앱 단위 검사 2회 | `699/699` |
| 전체 앱 단위 검사 3회 | `699/699` |
| 서버 운영 Windows 집중 검사 | `43/43` |
| 새 오프라인·키보드 집중 브라우저 | `3` 통과, `1` 조건부 제외, 실패 `0` |
| 전체 브라우저 | `192` 통과, `44` 조건부 제외, 실패 `0` |
| 앱 타입 검사 | 통과 |
| 브라우저 타입 검사 | 통과 |
| 프로덕션 빌드 | 통과 |
| diff 공백 검사 | 통과 |

조건부 제외는 프로젝트별 화면 조건 때문이다. 예를 들어 320px 키보드 검사는 `touch-narrow`에서만 실행하며, 기본 공개 빌드에서 꺼진 실험 피로도 입력은 실행하지 않는다.

## 안전 경계

- 계정, 동기화, 공유, 계획 제안, 제품 분석, 실험 피로도는 계속 꺼져 있다.
- 오프라인 시나리오는 서비스 워커의 정적 앱 셸과 브라우저 로컬 저장만 사용한다.
- 개인 메모나 일지 원문을 네트워크 분석 이벤트로 보내지 않는다.
- 기존 개발 도구용 PostCSS high advisory 1건은 이 변경에서 의존성을 바꾸지 않았으며 이슈 `#146`에 보존한다.
