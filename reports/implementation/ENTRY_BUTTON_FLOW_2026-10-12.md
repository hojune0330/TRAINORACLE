## 구현한 화면 계약

| 화면 | 이번 변경 | 보존한 경계 |
| --- | --- | --- |
| 홈 | 중복 제목·빈 분석 설명 제거, 일지 날짜/종류/보관 범위 요약, 실제 결과 전체를 누르는 버튼, 꾸미기·예시·훈련법 직접 진입 | 실제 수치/기간/출처, 안전·저장 오류, 원문 개인정보, 기존 다음 훈련 |
| 일지 | 실제 달력부터 표시, 월간/기록 묶음 짧은 선택, 예시는 별도 선택 | 날짜·월·원문 복귀, 기록 없는 날 쓰기, 예시를 실제 기록으로 저장하지 않음 |
| 기록 | 빠르게 기록/자세히 기록/하루 마무리/경기 기록 네 종류를 직접 선택 | 대상 날짜, 입력/임시 저장, 선택만으로 저장하지 않음, 홈 빠른 기록은 선택기 우회 |
| 훈련 | 현재 질문 하나에 집중, 10km 월간 훈련표는 첫 사용자에게 직접 제시하고 기존 일정·복원 상태가 있으면 뒤에 배치 | 저장 직후·복원 대기/실패도 기존 상태로 판정, 신규 저장 조회 없음, 명시적 적용과 초안 이탈 확인 |
| 오라클 | 분석 항목을 직접 선택하고 선택된 내용만 표시, 중복 과제 제목 제거, 버튼의 긴 보조 설명은 접근성 설명으로 유지 | 실제 결과와 기간·출처·제외, 파일 분석 준비 상태, 선택·복귀 문맥 |
| 러닝 취향 | 질문 3개로 한 항목 알아보기/질문 없이 읽을거리의 두 진입 | 강제 설문 없음, 부분 점수·미응답·임시 응답과 보관 상태, 기존 캐릭터 |
| 가져오기/더보기 | 파일 바로 선택 또는 파일 준비 버튼, 선택한 출처 안내만 표시; 중복 메뉴 제목 제거 | 파일 형식/크기·기기/계정 저장 범위, 명시적 저장, 실패와 재시도 |

입력 선택을 요구하는 것과 선택 기능·동의·저장을 강요하는 것은 다르다. 새 공통 플로우 엔진,
색상 체계, 계정 공개, DB/API, 훈련 계산·용량·주기·안전 기준을 추가하거나 변경하지 않았다.
달력과 비교·원문·실제 결과는 한 화면에서 비교할 역할을 유지한다.

## 간소화의 부작용 방어

- 기존 `useCalendarSnapshot`을 사용해 READY 빈 상태와 LOADING/STALE/ERROR를 분리했다.
  확인되지 않은 읽기를 첫 일지·완료·분석 결과로 제시하지 않는다. 직접 쓰기 행동은 유지한다.
- 계정 보관 표시는 기존 소유자별 확인 원본과 `syncState`, 저장 시각, 날짜, 종류가 일치할 때만
  사용한다. 과거 확인본·기기 보관·대기·실패·충돌을 같은 성공 배지로 표시하지 않는다.
- 최근 날짜는 연도가 다르면 연도도 보인다. 여러 기록은 하루당 하나의 행 안에 종류/개수를 남긴다.
- 하루 마무리만 있거나 분석 가능한 거리가 없으면 빈 분석 설명을 생략하되 목적지는 유지한다.
- 드릴다운 버튼의 부가 설명만 화면 읽기용으로 남겼다. 선택 결과의 설명·경고·수치에는
  숨김 규칙을 적용하지 않는다. `파일 분석 · 준비 중`과 44px 조작 영역은 보인다.
- 계정·데이터가 없는 예시는 opt-in이다. 예시/부분 결과를 개인 분석이나 완성 점수로 바꾸지 않는다.
- 9.5일 마이크로사이클, 세 주기, RP/RPE·원표기·시간·반복·회복을 바꾸지 않았다.
  주기별 증량·회복 수치의 오너 승인 대기와 계정 공개 관문은 별도 유지한다.
- 미래 날짜 통증 경고의 기존 안전 정책은 이 UI 패치에서 변경하지 않았다.

## 로컬 검증 증거

고정 Node 24.19.0, 기존 설치 의존성을 사용했다. Windows 공유 node_modules의 sandbox EPERM은
권한 범위를 로컬 검사로 제한한 실행으로 해결했다. 패키지 설치·외부 계정 호출은 하지 않았다.
아래는 서로 겹치는 검사 묶음이며 합산한 전체 고유 테스트 수가 아니다.

| 검사 묶음 | 결과 |
| --- | --- |
| 최종 초기 화면/실제 Home/일지 복귀/오라클 접근성 6개 파일 | 62 통과 |
| 최종 달력 복귀/가져오기/재진입/하루 마무리/기존 모션 5개 파일 | 55 통과 |
| KST 날짜·저장 상태·실제 달력·오라클 접근성 6개 파일 | 59 통과 |
| 계획 진입/클라우드 복원/조정된 계획/계정 합성/더보기·오라클 복귀 6개 파일 | 38 통과, 기존 skip 1 |
| 성향 질문/읽을거리와 읽기 상태 4개 파일 | 68 통과 (성향 41 포함) |
| 앞선 가져오기·기록·모션·계획 입력·오라클 탐색·AppShell 선택 복귀 7개 파일 | 140 통과 |
| 프로젝트 TypeScript 및 E2E TypeScript | 각각 exit 0 |
| 로컬 합성 Chromium | 15 캡처, 실행 경로 page error 0, 320/375/1280px 및 200% 글씨 |

계획 검사에서 기존 비활성 1건은 `keeps the current intake step when another tab stores unrelated data`다.
이를 통과로 세거나 새로 비활성화하지 않았다. 전체 E2E·릴리스 빌드·CI·배포·실계정 검사는 실행하지 않았다.

실제 브라우저에서는 하단 탭, 파일 준비/닫기 포커스, 종목→기준→기록의 값 유지,
일지 달력, 분석 선택 후 기록→뒤로 복귀, 성향 질문 없이 읽기, 하루 마무리+저장 계획 조합을 확인했다.
화면별 캡처와 JSON은 `app/.codex-calendar-visual-qa/entry-clarity-20261012/`에 로컬 보관했다.
재현 스크립트는 `app/e2e/entry-clarity.browser.mjs`이며 loopback 4176 외 요청을 차단하고 새 브라우저 문맥만 쓴다.
실제 계정·개인 일지·인증 정보는 검증 자료에 사용하지 않았다.

### 결함 주입

다음 임시 결함에서 각각 의도한 이름의 검사가 실패했고, 주입을 정확히 되돌린 정상 코드는 후속 검사로 확인했다.

1. 파일 준비를 기본 펼침으로 바꿈: 직접 파일 선택 경로 검사 실패.
2. 성향의 읽을거리 선택을 결과로 바꿈: 직접 읽기 및 미완성 답 복귀 검사 2건 실패.
3. 저장 확인의 `savedAt` 대조 제거: 같은 ID의 새 수정본을 옛 성공으로 승격하는 반례 실패.
4. Home 읽기 상태를 READY로 고정: STALE에서 오늘 완료로 표시하는 반례 실패.
5. 기록 선택기의 READY 조건 제거: 손상·읽기 실패·부분 읽기·LOADING 반례 4건 실패.
6. 계획 입구 배치의 `stored === null` 조건 제거: 저장 직후 일정 우선 순서 검사 실패.

### 독립 리뷰와 검사 도중 수정

Sol이 훈련표 버튼이 기존 일정보다 먼저 오는 문제를 확인해 현재 상태 기반 순서로 수정했다.
Luna는 홈/일지의 직접 진입·문구·표시 계약을 담당했다. 별도 독립 읽기 리뷰는 파일 선택/저장 분리와
포커스 복귀에서 새 P1/P2 결함을 찾지 못했다. 실제 학생 조사를 했다는 뜻은 아니다.

통합 중 JSX/타입 오류와 이전 UI의 버튼 이름·접힘 단계를 전제한 검사 실패를 수정했다.
실제 동작 단언을 삭제하지 않고 직접 경로·날짜·진행 상태로 갱신했다. 이전 실패 JSON은 중간 증거로 남긴다.
최종 `final-entry-tests.json`, `final-flow-tests.json`, `kst-tests.json`, `plan-navigation-tests.json`을 완료 판단에 사용한다.
처음 브라우저 확인에 넣었던 `oracleV2=1`은 성향 바로가기였으므로 일반 앱 진입에서 제거했다.
홈을 잠깐 거쳐 성향으로 이동한 현상을 앱의 새 결함으로 수정하지 않았다.
