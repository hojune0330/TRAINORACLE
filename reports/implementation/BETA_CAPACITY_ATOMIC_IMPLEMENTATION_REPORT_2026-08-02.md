# 무료 베타 200석 서버 제한 구현 보고

작성일: 2026-08-02

## 결과

`0016_atomic_beta_capacity.sql`이 무료 베타 좌석을 서버에서 원자적으로 배정한다.

- `PUBLIC_BETA` 한 행을 `for update`로 잠근 뒤 현재 좌석 수를 센다.
- 200석이 찼으면 `BETA_FULL`을 반환하고 좌석과 프로필을 만들지 않는다.
- 같은 사용자의 재시도는 기존 좌석을 재사용한다.
- 좌석과 프로필 생성은 같은 데이터베이스 트랜잭션 안에서 처리된다.
- 브라우저의 프로필 직접 추가·수정 권한과 좌석표 직접 쓰기 권한을 제거했다.
- 최신 보호자 권한 만료·철회 규칙은 `athlete_support_access_allowed()`를 통해 그대로 유지한다.
- 계정이 30일 보존 절차 뒤 실제 삭제될 때 좌석도 함께 회수된다.

200석이 찬 사용자는 서버 계정 기능만 열리지 않는다. 기존 기기 일지는 계속 사용할 수 있다.

- 변경 전 기준 테스트: `30/30`
- 새 좌석·서비스 집중 테스트: `27/27`
- 전체 앱 단위 테스트: `621/621`
- 브라우저 회귀: `189` 통과, `39` 화면 조건부 건너뜀, 실패 `0`
- 앱·브라우저 TypeScript 검사와 프로덕션 빌드: 통과
- 좌석 상한, 잠금, 중복 방지, 직접 쓰기 권한을 훼손한 변조: 모두 거부

## 공개 경계

마이그레이션은 저장소에만 추가한다. 실제 Supabase 적용과 계정 기능 공개는 별도 운영 단계이며, 그 전까지 계정 공개 스위치는 계속 꺼져 있다. 이 좌석은 인증 공급자에 생성된 미완성 로그인 식별자가 아니라, 서버 데이터와 동기화를 사용할 수 있도록 승인된 `beta_enrollments`를 센다.
