# ACCOUNT_JOURNAL_RECORD_INTEGRATION_2026-09-08.md

## 현재 판정

계정 중심 저장 전환은 **개발 중이며 배포 완료가 아니다**. 이번 변경은 기존
초안 기반을 실제 일지 작성·수정·읽기·삭제·복원에 연결하는 통합 작업이다.
기능 기본값은 OFF로 유지했다. 실제 사용자의 저장 경로나 운영 데이터는
이번 로컬 구현·합성 시험으로 전환하지 않았다.

제품 방향과 구현·배포 진행 승인은 이미 받았다. 아래 미완성 항목을
오너의 추가 승인 대기라고 표현하지 않는다.

## 구현한 범위

- 훈련 후, 하루 마무리, 경기, 빠른 기록 네 폼을 계정 저장 서비스에 연결.
- 폼별 고정 ID와 중복 클릭 방어. 계정 저장 확인/전송 대기/충돌을 구분.
- 기존 일지 스키마를 공유하는 FINALIZED JOURNAL 검증기. 알 수 없는 필드나
  파서의 조용한 값 변경을 거절하고 서버 검증기를 재현 가능하게 생성.
- 본인 계정의 암호화 버퍼와 서버 revision을 사용한 저장·재시도·조회.
- 일반 화면·분석에는 비밀 원문을 제외하고, 본인의 일지 열람에는 복원.
- 0034의 수정본·휴지통·삭제·복원·만료 조회 제한 및 cleanup RPC.
- 일지 수정 이력과 계정 휴지통 화면, 명시적 기존 일지 이전. 기기 원본은 보존.
- 초안 패널의 800ms 전송, 내부 화면 이동 보호, 통신 재연결 재시도.
- 전용 IndexedDB/계정 복구 브라우저 검사와 공유 검증기 재생성 검사를 CI에 연결.

이전 기반 보고서의 3064개 테스트 등은 해당 시점의 결과로 보존한다.
이 보고서의 범위와 합쳐 운영 검증이나 전체 기능 완료로 재해석하지 않는다.

## 통합 검수에서 발견한 문제

| 문제 | 처리 또는 남은 작업 |
|---|---|
| 계정으로 옮긴 일지를 삭제하면 보존한 로컬 사본이 다시 보일 수 있음 | 계정에서 다룬 ID와 로컬 대체 사본을 구분; 삭제 표식 조회와 함께 보완 |
| 구형 비밀 금고가 최신 계정 원문을 덮어 반환할 수 있음 | 계정 원문 확보 시 구형 금고 복원을 적용하지 않음 |
| ACK 일지가 synced여서 수정 버튼에서 제외 | 현재 계정의 정책 판단에만 local 사본 사용; 원본 ACK 상태는 유지 |
| 비동기 삭제 중 중복 클릭·Escape·실패 처리 | 진행 중 재진입·닫기 방어, 실패 안내와 재시도 가능 상태 |
| 계정 A의 비밀 이력이 B 또는 A-B-A 전환 뒤 나타날 수 있음 | 화면 상태 제거와 요청 세대 검사 |
| 서버 저장 코드가 기존 편집 불변 조건을 우회 | 본문 ID·종류·날짜·가져온 수치·출처·계획 연결 검사 |
| 구형 동기화/가져오기/백업 복원이 별도 저장소에 쓰고 성공할 수 있음 | 클라이언트 구형 writer 차단; 새 가져오기/복원 통합과 서버 차단은 잔여 |

접근 실패를 확인한 것은 아니므로 인증 불가나 승인 부족이라고 단정하지 않는다.
