## 1. 승인과 범위

오너의 수동 배포 요청에 따라 전체 훈련 계산·계획·일지 연결과 그 선행 작업을 함께 게시한다.
최초 기준 소스는 main `3e659d4`이며 이전 공개 배포는 gh-pages `b1a67ef`다.

- 달력의 최근 기록 위치, 훈련 역할별 색상, 빈 기록 예시와 모션.
- 처방 우선 표기, 같은 목적의 다른 훈련 제안과 117개 계산 카탈로그.
- 실제 구간·반복 기록과 원래 계획 비교, 서버 저장 형식 호환.
- 관련 스펙, 근거 검토, 합성 검수 자료.

117개는 거리·시간 등의 변형을 포함한 구성 수이며 독립 훈련법 117종이 아니다.
자동 개인 페이스가 없는 구성은 직접 확인한 값이 필요하다. 강도·양·횟수를 자동으로 늘리지 않는다.

## 2. 배포 순서

1. 승인된 소스와 선행 작업을 커밋하고 main에 정상 후속 커밋으로 보존한다.
2. 기존 `account-plan-collection`, `account-journal` 두 함수의 저장 검증기를 먼저 배포한다.
3. 기존 공개 웹 설정을 그대로 유지해 웹을 빌드하고 gh-pages에 정상 후속 커밋으로 게시한다.
4. 공개 영수증, HTML과 진입 파일 해시 및 서버 인증 거절 상태를 확인한다.

새 SQL, 신규 계정, 비밀값 변경, COROS 기능 활성화, 운영 선수 자료 조회·삭제는 포함하지 않는다.
기존 서버 인증과 저장 암호화도 바꾸지 않는다. 이전 계획에 새 처방을 소급해 덮어쓰지 않는다.

배포 직전 생성 검증기 재현과 저장 계약 검사를 실행한다. GitHub 전체 CI나 실제 사용자 계정
저장 성공을 이 로컬 결과와 동일시하지 않는다. 공개 배포 확인은 아래에 별도로 기록한다.

## 4. 사용자 시험 순서

1. 공개 웹을 새로고침하고 계획에서 새 계획을 만든다. 기존 계획은 먼저 보관하거나 그대로 둔다.
2. 상세 훈련의 거리·반복·세트·목표 초·회복을 확인하고 같은 목적의 다른 훈련을 열어 본다.
3. 미정 목표 초가 있으면 입력하고, 더 긴 구성은 표시된 전체 시간을 확인한 뒤 적용한다.
4. 계획을 저장하고 화면을 다시 열어 같은 수치인지 확인한다.
5. 연결된 일지에서 실제로 한 구간만 입력하고 계획과 실제 비교를 확인한다.

실제로 하지 않은 운동을 운영 기록으로 입력할 필요는 없다. 시험 자료를 저장했다면 실제 기록과
구분하고, 온라인 저장은 로그인 계정의 저장 완료 표시와 다시 열기 결과로 판단한다.
