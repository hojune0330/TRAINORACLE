```yaml
runtime_base: 4fd519d3
integration_base: 68286fa5
production_deployment: NOT_RUN
authenticated_account_round_trip: NOT_RUN
actual_student_usability_study: NOT_RUN
```

오너 지시: 모든 탭에 누적된 불필요한 설명과 빈 상자를 과감하게 없애고,
필요한 기능은 이름이 명확한 탐색으로 연결한다. 앞선
[초기 화면 버튼 진입 구현](ENTRY_BUTTON_FLOW_2026-10-12.md)의 후속 변경이다.
기존 문서의 계획 진행 미리보기·상시 준비 중 항목·별도 하루 상태 입력 배치는
이번 승인과 [공통 UI 기준 §0](../../docs/UX_UI_VISUAL_STANDARD.md)에 따라 대체한다.

## 구현 범위

| 화면 | 제거하거나 줄인 것 | 유지한 경로 |
| --- | --- | --- |
| 홈 | 중복 오늘 제목·완료 문장, 계획 완료 체크를 분석처럼 보여주던 패널, 반복 상태 입력·빈 분석 설명 | 운동 기록, 컨디션·메모, 실제 다음 훈련·기록, 오라클, 가져오기·최고기록, 꾸미기 |

| 훈련 | 중복 요약·상세 앞의 설명, 빈 연결 일지 안내, 이미 달력에서 보이는 주기별 재집계, 행동을 감싼 불필요한 펼침 | 목표·기록 입력, 날짜·처방, 직접 수정·표기 읽기, 주기 시작·마치기·재생성 |
| 오라클 | 계획 체크 수를 결과로 표시, 사용할 수 없는 파일 분석 선택, 중복 제목과 가져오기 펼침 | 실제 수치·출처·예시, 분석 항목 직접 선택, 훈련표·원문·컨디션 기록 |
| 러닝 취향 | 비어 있는 보관함, 설정의 중복 매니저 안내, 읽을거리 주제 앞의 펼침 | 질문·점수·캐릭터·읽을거리, 모든 취향 항목 직접 선택, 응답·추가 정보 관리 |
| 더보기·파일 가져오기 | 반복 메뉴 설명·중복 화면 제목·가져오기 단계 설명 | 이름 있는 목적지 버튼, 파일 바로 선택, 필요할 때 출처별 준비 안내 |

`하루 마무리` 표시명은 `컨디션·메모`로 맞췄다. 내부 `evening` 종류, 기존 값,
백업 형식은 그대로다. 새 기록은 몸 상태·기분 / 수면 / 메모 쓰기 / 체중·심박 중
원하는 입력으로 들어간다. 기존 기록 수정과 복구된 초안은 확인 화면에서 이어간다.
선택만으로 실제 일지를 저장하거나 모든 선택 항목을 완료시키지 않는다.

## 제거하면 안 되는 정보와 데이터

- 훈련량·페이스 계산, RP/RPE·원표기·반복·회복·9.5일 × 3의 계약은 변경하지 않았다.
- 실제 날짜·기간·단위·처방·출처·제외·예시 구분과 통증·저장 실패·재시도는 유지했다.
- 계획 완료 체크는 훈련표에 그대로 남는다. 원본 데이터나 기능을 삭제하지 않고
  홈·오라클의 분석 대용 표시만 없앴다.
- 정상 저장 위치는 확인 가능한 때만 완결된 문구로 보인다. 소유자 불명·다른 계정은
  배지를 만들지 않고, 계정 대기·거절·실패·충돌을 성공으로 바꾸지 않는다.
- 예전 별도 상태 입력의 데이터는 삭제·자동 병합하지 않는다. 회복 화면에 실제 값이
  있을 때만 `이전에 남긴 상태`로 읽을 수 있다. 현재 계정 저장 키와 scope generation을
  확인하며 읽기 실패는 빈 상태가 아니라 실패·다시 불러오기로 처리한다.
- 글씨 축소나 전역 CSS 숨김으로 줄이지 않았다. 새 선택 버튼은 기존 디자인 토큰과
  44px 터치 영역을 사용한다. 원문·달력·장식 좌표와 구매·포인트는 수정하지 않았다.
- 실제 계정·개인 일지를 검사 자료로 쓰지 않았다. DB·인증·서버·운영 설정은 변경하지 않았다.

## 분담과 독립 검토

통합 담당 root, 훈련 담당 Sol, 일지·유틸리티 및 오라클 담당 Luna가 파일을 나눠 작업했다.
UI 담당자가 다른 영역을 읽기 전용으로 교차 검토했다.

1. Sol이 과거 상태 읽기 실패를 빈 화면과 구분하지 못하는 문제를 찾았다. 실패 안내와
   다시 불러오기를 복구했고 저장 데이터는 건드리지 않았다.
2. Luna가 간소화 도중 설정의 특정 러닝 취향을 바로 선택하는 경로가 빠진 것을 찾았다.
   모든 기존 취향 항목의 직접 선택을 복구하고 작성 중 응답 보호를 유지했다.
3. 통합 검사는 삭제된 설명·이전 제목을 전제한 테스트를 실제 직접 경로에 맞췄다.
   저장·계정 분리·충돌·값 유지 검증을 삭제하여 통과시키지 않았다.

## 로컬 검증

`lean-ci`에 따라 UI·탐색 변경과 영향을 받는 저장 경계의 검사만 실행했다.
Node 24.19.0 및 이미 설치된 의존성을 사용했다. 패키지 설치는 하지 않았다.
이전 의존성 junction에는 최신 main이 요구하는 `shaders/js`가 없어, 현재 작업실의
링크만 해당 버전이 설치된 형제 작업실로 연결했다. 실제 패키지 파일은 보존했다.

경로로 수정하고 위 두 파일을 다시 실행했다. 원래의 UNAVAILABLE→MISSING 구분,
출처·수치·초안 재개·계정 변경·충돌 검증은 유지했다. 단독 재검사 증거는
`declutter-navigation-final.json`, `oracle-profile-v2-contract.json`이다.

전체 E2E, 전체 빌드, hosted CI, 릴리스 관문, 실계정 왕복, 실제 학생 사용성 조사는
이번 실행 범위가 아니다. 테스트에서 합성 계정 경계를 확인한 것을 실계정 확인으로 보고하지 않는다.

## 소스 통합·배포 경계

진행 중 원격 main의 새 문서 전용 2개 커밋을 확인하고 `68286fa5`로 fast-forward했다.
`docs/phase2`만 바뀌었고 이번 런타임 변경과 겹치지 않았다. 다른 작업자의 미추적
캡처·scratch·캐릭터 contact sheet는 보존하고 커밋에서 제외한다.
소스 커밋은 저장소의 main 직접 작업 규칙을 따르되 `[skip ci]`를 사용해 자동 운영 게시를
유발하지 않는다. 정식 앱·gh-pages·배포 영수증·계정 공개 설정은 수정하지 않는다.

배포가 승인되면 최신 main과 계정 보류·자산 보존 설정을 다시 확인하고 별도의 릴리스
관문 및 보존형 수동 게시 절차를 따른다. 이 문서는 배포 완료나 전 화면 무결점 보증이 아니다.
