# 트레인오라클 페이스 도구 차용·UX 구현 계획

- 날짜: 2026-10-05
- 계획 버전: `0.2.0` — §1~14 보존, §15~24 실행 세부안 추가.
- 상태: `OWNER_APPROVED_IMPLEMENTATION_IN_PROGRESS`
- 준비 감사·계산·화면·연결의 집중 검사: `COMPLETED`; 정본 승격·서버 변경 없음. 실제 계정 왕복·운영 통합은 미완료이며, 실행 기록은 검수 보고서로 구분한다.
- 요청 범위: AthleteTime의 계산 구조를 차용하되, 결함을 검증하고 TrainOracle의 기존 제품 흐름에 맞게 다시 설계한다.
- 이 문서는 구현 준비안이다. 새로운 훈련 구성·생리학적 공식·예측의 처방 적용 승인을 만들지 않는다.
- 감사 원문: [AthleteTime 페이스 계산기 차용 감사](../review/ATHLETETIME_PACE_CALCULATOR_PORT_AUDIT_2026-10-05.md).
- 실행 분해: [개발 작업지시서](TRAINORACLE_PACE_TOOLS_IMPLEMENTATION_WORK_ORDER_2026-10-05.md).
- 읽는 순서: 제품 범위 §1~3 → 화면 §15~17 → 계산 §18 → 연결·보존 §19~20 → 실행 §21~24.

## 1. 제품 결정

**오라클 안에 `페이스 계산`을 둔다. 별도 분석 엔진을 복사하지 않고 기존 기록·페이스 코어를 쓴다.**

사용자가 원하는 답은 다음 순서다.

1. 내 기록으로 200m·400m·1km를 몇 초에 달리는가?
2. 이 숫자는 어느 기록을 기준으로 계산했는가?
3. 실제 반복 훈련에 이 숫자를 쓸 수 있는가?
4. 트랙이나 경기 중간에 누적 몇 분이어야 하는가?
5. 다른 기준으로 바꾸면 계획의 어느 부분이 바뀌는가?

첫 질문에 답하기 전에 모든 도구와 설명을 보여주지 않는다. 단순 산술 결과를 적합한 훈련이나 최대 능력으로 포장하지도 않는다.

기본 이름은 `페이스 계산`이다. `훈련 페이스 분석`은 계산기 전체의 정식 이름으로 사용하지 않는다. 오라클 브랜드 아래에 두되 버튼은 구체적인 행동 이름을 쓴다.

## 3. 배치와 진입점

### 3.1 주 진입점

`오라클 → 페이스 계산`.

`Trends` 요약 화면의 기록 관련 도구 가까이에 작은 아이콘+이름 행으로 배치한다. 하단 메인 탭을 늘리거나 홈 최상단에 새 홍보 블록을 만들지 않는다. 러닝 프로필·최고기록 풀이를 대체하지 않는다.

모바일에서는 독립된 전체 화면 도구로 연다. 기본 하단 내비게이션은 기존 앱의 오버레이 규칙을 따른다. 긴 입력과 작은 팝업을 겹치지 않는다.

데스크톱 `DesktopWorkspace`에서도 실제 진입 콜백을 연결한다. 모바일 `AppShell`에만 연결해 PC에서 기능이 사라지게 만들지 않는다.

### 3.2 맥락 진입점

| 출발 위치 | 행동 이름 | 열릴 때 채우는 것 | 돌아갈 위치 |
|---|---|---|---|
| 오라클 | 페이스 계산 | 선택된 기록 또는 기본 빈 입력 | 오라클의 같은 구역·스크롤 |
| 경기 기록 저장 완료 | 이 기록으로 페이스 계산 | 방금 저장한 기록·종목·버전 | 기록 상세/저장 완료 |
| 훈련 상세 | 기준 바꾸기 | 선택 구간·목적·현재 기준 | 같은 훈련·같은 구간 |
| 계획 변경 미리보기 | 계산 근거 | 그 제안의 고정 스냅샷 | 같은 변경 미리보기 |
| 용어 도움말 | RP 계산 보기 | 설명 중인 종목·기록이 있을 때만 | 도움말을 연 원래 위치 |

계산만 보고 돌아갈 수 있어야 한다. 기록 등록이나 계획 생성으로 밀어 넣지 않는다.

## 4. 화면 구조와 정보량

### 4.1 첫 화면

```text
<  페이스 계산                         ?

기준  800m 최근 경기 · 2:01.5       변경

200m          400m           1km
30.4초        1:00.8         2:32/km

구간 더 보기                         >
구간표                               >
트랙 도구                            >
페이스 표                            >

[적용 가능한 훈련에서 연 경우에만]
변경 확인
```

위 숫자는 경기 평균 속도 환산 예시다. 반복 횟수·회복이나 전력질주 능력은 계산하지 않는다. 400m는 반올림 후 60.8초, km는 151.875초/km를 초 단위로 표시한 값이다.

핵심 구간은 3개 내외로 시작한다. 중거리 맥락에서는 200m·400m·현재 훈련 구간을, 장거리 맥락에서는 400m·1km·현재 훈련 구간을 우선한다. 같은 구간이 중복되면 하나만 보여준다. 실제 계산 정밀도는 유지한다.

카드 안에 다시 카드·설명 목록을 쌓지 않는다. 숫자와 단위, 기준 기록 한 줄이 중심이다. 메인 결과 위에 길게 소개하는 문장은 넣지 않는다.

### 4.2 도구 이동

첫 화면에서 5개 탭을 압축해 작은 글자로 만들지 않는다. 추가 도구는 이름 있는 행으로 들어간다. 도구 내부에 비교 모드가 필요하면 짧은 세그먼트를 쓴다.

- 구간표: `200m / 400m / 1km / 직접` 중 종목에 맞는 기본값.
- 트랙: `한 바퀴 / 경기 400m`; 별도 메뉴에 `장애물 3000m`.
- 페이스 표: 시간 범위·간격을 제한한 숫자 표. 현재 기준 행을 표시한다.

상단 뒤로가기는 직전 도구로 돌아간다. 시스템 뒤로가기도 같은 순서를 따른다. 도움말을 닫았다고 홈으로 이동하지 않는다.

### 4.3 입력 경험

기록이 있는 사람은 한 번 골라 결과를 본다. 같은 종목을 앞에서 이미 선택했다면 다시 묻지 않는다.

기록이 없는 사람은 `종목 선택 → 시간 입력 → 결과`다. 시간 입력의 시·분·초를 각각 별도 페이지로 만들지 않는다. 필요한 두 필드를 한 화면에서 입력하고, 유효해지는 즉시 결과가 계산되게 한다.

입력 중에는 자동 스크롤·포커스 이동을 하지 않는다. 다음 화면으로 넘어가는 명시 행동 뒤에만 결과 영역에 자연스럽게 맞춘다. 숫자 키보드가 닫히기 전에 결과로 강제로 이동하지 않는다.

샘플은 `예시`를 누른 경우에만 채운다. 9:30이나 하프 1:45가 자신의 기록처럼 미리 저장돼 있으면 안 된다.

## 5. 기준 기록과 숫자의 의미

### 5.1 저장 기록 사용

현재 `derivePaceRecordOptions`를 사용한다. 최근 실제 경기, 최근 12개월 최고, 입력된 개인 최고, 목표를 분리한다. 동일 기록에 여러 의미가 있으면 카드 하나에 표식을 합친다.

같은 날 서로 다른 실제 기록의 최신 순서를 모르거나 날짜가 없으면 자동으로 임의 선택하지 않는다. 오래된 기록·날짜 미입력은 한 줄로 확인하게 한다. 최근 12개월을 생리학적 유효성 보증으로 설명하지 않는다.

조회 가능한 기록과 처방에 적용할 수 있는 기록은 다르다. 저장된 기록의 확인 상태·현재성·계정 소유권을 기존 적격성 모듈로 검사한다. 읽기용 계산에서 본 값을 곧바로 적격 처방 근거로 올리지 않는다.

### 5.2 직접 입력

직접 입력에는 `경기 기록 / 목표 시간`의 의미 선택을 둔다. 기본 계산 초안은 계정 경기 이력이 아니다. 사용자가 실제 기록으로 저장하려면 기존 기록 등록 화면으로 넘기며 필요한 날짜·출처·확인을 받는다.

훈련 구간에 적용하는 경로는 저장된 적격 기록 또는 기존 직접 입력 계약을 따른다. 계산기가 임시 `recordId`를 만들어 실제 경기 근거처럼 붙이지 않는다.

### 5.3 세 종류의 계산 분리

| 종류 | 표시 | 처방 처리 |
|---|---|---|
| 실제 기록 평균 속도 환산 | `800m 최근 경기 2:01.5 기준` | 선언된 종목·목적·구성에만 연결 |
| 목표 평균 속도 환산 | `800m 목표 2:00 기준` | 현재 실력과 분리; 기존 목표 적용 조건 검사 |
| 다른 종목 예상 | `공식 예상 · Riegel 1.06` | 기존 비교 전용. 자동 처방 적용 불가 |

페이스 표에서 5km 속도를 그대로 10km까지 곱한 숫자는 `같은 평균 속도일 때`의 값이다. 10km 예상 경기력이나 PB가 아니다.

Zone 2·LT·VO2max·해당계 능력을 경기 평균 페이스만으로 측정했다고 표시하지 않는다. 기존 승인된 5km 기준 LT 참고 모델은 계약 범위를 유지하며 `측정한 개인 역치 아님`을 상세에서 설명한다.

## 6. 계산 계약

### 6.1 공통 환산·입력

- 7종목 기록: 800·1500·3000·5000·10000·21097.5·42195m.
- 하프 21097m 레거시 읽기 호환을 유지하고 계산은 21097.5m로 통일한다.
- 직접 환산: `기준 초 × 구간 거리 / 기준 거리`.
- 시·분은 정수; 분은 0~59. 초는 유한한 소수, 0 이상 60 미만. 전체 시간은 양수.
- 필드가 비어 있는 상태와 0을 구분한다. 소수 입력 중 `1.`을 조용히 다른 기록으로 확정하지 않는다.
- 기존 기록 저장의 최대 시간 등 기술 한계를 유지한다. 별도 계산기가 더 넓게 받더라도 실제 기록 저장·처방으로 넘어갈 때 재검증한다.
- 0 거리·음수·NaN·Infinity·잘못된 레인은 거부한다. 입력 실패는 해당 필드 옆에 짧게 표시한다.
- 60m 미만 경기 평균 환산을 허용하기 위해 기존 제한을 풀지 않는다.

기존 7종목 밖의 직접 거리 계산은 필요 시 `같은 속도 계산`의 읽기 전용 보조 함수로 분리한다. 이것은 종목 등록이나 처방 기준 확장이 아니다. 100~400m 전문선수 계획을 이번 기능으로 몰래 열지 않는다.

### 6.2 포맷터

숫자를 먼저 반올림하고 분·초로 나눈다. 소수 초 보존과 표시 정밀도를 구분한다.

- 800m 2:01.5 → 200m 내부 30.375초, 기본 30.4초.
- 10km 40:00 → 400m 96초, 1km 4:00/km.
- 59.999초 → 초 단위 표시에서는 1:00; 0.1초 표기에서는 1:00.0.
- km 페이스는 초 단위. 초 입력값을 먼저 정수로 버리지 않는다.
- 반복의 예상 총 시간은 표시된 구간 값을 다시 곱하지 않고 원본 계산값을 사용한다.

### 6.3 구간표

기본은 균등한 거리 분할이다. 마지막 부분 거리도 포함한다. 1500m를 400m로 볼 때 `400 + 400 + 400 + 300m`처럼 정확히 표시한다.

모든 모드에서 거리 합계는 전체 거리, 내부 시간 합계는 목표 시간과 일치해야 한다. 개별 표시 반올림과 합계가 어긋나면 총 목표는 원본값을 사용하고, 누적 표시와 마지막 구간을 일관되게 조정한다. 숨겨진 손실을 만들지 않는다.

가속 분할을 넣는다면 구간 길이를 반영한 가중치를 정규화한다. 감사 스크립트의 ±1% 예시는 수학적 수리 검증이지 채택된 경기 전략이 아니다. 사용자에게 일반 최적 전략이라고 권하지 않는다.

직접 편집한 구간표는 경기 구간 목표다. 자동으로 인터벌 반복·회복·일지 수행 랩이 되지 않는다.

행 수가 큰 입력은 기술적 상한과 가상화/페이지 나누기를 사용한다. 무제한 행 생성으로 화면을 멈추게 하지 않는다. 상한은 선수 능력 제한처럼 표현하지 않는다.

### 6.4 트랙 레인

표준 규격·측정선·단위·버전을 한 곳에서 관리한다. 상수 표와 별도 계산식의 이중 원본을 만들지 않는다.

- `같은 출발선에서 한 바퀴`: 외곽 레인은 길이가 늘어난다. 사용자가 기준으로 정한 레인의 시간 또는 페이스에서 비교한다.
- `경기 400m`: 레인별 출발선이 조정된 경기 거리다. 외곽 레인이라는 이유로 더 긴 거리를 뛰는 목표를 만들지 않는다.
- 실제 트랙이 표준 도형이 아니거나 레인 폭·측정선이 다르면 표준 계산을 실제 측정값처럼 주장하지 않는다.
- 원전이 확인되지 않은 규격은 `확인 필요` 상태로 두고 해당 자동 계산을 활성화하지 않는다.

장애물 3000m의 안쪽/바깥쪽 물웅덩이 계산은 별도 시설 규격 참조를 가진다. 단순 안쪽/바깥쪽 선택만으로 모든 경기장의 바퀴 길이를 확정하지 않는다. 장애물 종목 결과를 평지 3000m 기록으로 저장하지 않는다.

## 7. 훈련 계획·일지 연결

### 7.1 적용 가능 여부

훈련이 요구하는 기준 종목과 구간 목적을 기존 템플릿 선언에서 읽는다. 200m라는 거리만 보고 800m RP를 지정하지 않는다. 언덕·최대 가속·근력·플라이오에는 평지 경기 평균을 자동 적용하지 않는다.

계산 결과는 기존 상세 훈련을 대체하지 않는다. 반복·세트·구간·회복은 현재 처방에서 읽고, 바뀌는 페이스만 비교한다.

예: `200m × 6 · 32초 → 31.6초 · 회복 90초 유지`. 이 표시는 해당 구성에 그 기록을 사용할 수 있을 때만 제공한다. 계산기가 6회·90초를 새로 만들어내지 않는다.

### 7.2 새 기준 연결과 기존 링크 갱신

`refreshExistingPaceInputs`는 기존 링크 갱신 함수다. 새 모델이나 새 구간 기준을 선택하는 일을 이 함수에 억지로 넣지 않는다.

- 새 기준 선택: 기존 카탈로그 편집·`createSegmentRecordReference`·적격성 경로.
- 기존 기준 갱신: `preparePacePlanUpdate`의 미리보기·원자적 변경 경로.
- 실제 적용: 기존 활성 계획 편집·계정 저장·저널 보호 계약.

화면 동작은 `계산 → 변경 확인 → 적용`이다. 계산 자동 갱신과 계획 자동 갱신을 같은 것으로 만들지 않는다.

### 7.3 보존·충돌

지난 날짜, 시작·완료·부분 수행·일지 연결된 슬롯, 수동 고정 구간은 기존 규칙대로 보호한다. 페이스 변경을 이유로 반복·거리·회복·주간 빈도를 늘리지 않는다.

적용 직전에 계획 버전·기준 기록 버전·계정·일지 상태를 재확인한다. 다른 기기의 변경이면 새 미리보기를 만든다. 두 번 클릭은 하나의 요청으로 처리한다.

서버 저장 성공 전에는 `적용 완료`를 표시하지 않는다. 실패하면 기존 계획과 계산 초안을 보존한다. 계정 저장이 비활성화된 오라클 프리뷰에서는 그 상태를 가상의 성공으로 덮지 않는다.

일지는 당시 처방·기준 기록의 스냅샷을 유지한다. 미래 PB 편집이 과거 일지의 목표 시간을 재계산하지 않는다. 다음 주기의 기준 선택과 훈련량 적응도 서로 구분한다.

## 9. 디자인·반응성·접근성

기존 `UX_UI_VISUAL_STANDARD`의 토큰·폰트·버튼·간격·모션을 따른다. 검은 글자·종이 배경·절제된 상태색을 유지한다. 별도 네온 레인 팔레트, 그림자, 좌측 색띠, 거대한 상단 소개, 작은 영문 탭은 가져오지 않는다.

- 표시 숫자는 고정 폭 또는 tabular 숫자로 안정되게 배치한다.
- 아이콘은 기존 Lucide를 사용하고 모호한 아이콘에는 이름/툴팁을 제공한다.
- 터치 영역 44px을 유지한다. 글자를 키워야 할 때 스크롤을 허용하며 잘라내지 않는다.
- 기준 변경은 150~220ms 정도의 결과 강조, 도구 이동은 기존 화면 전환 모션을 사용한다.
- 숫자 입력마다 큰 애니메이션·진동·자동 화면 이동을 반복하지 않는다.
- 움직임 줄이기에서는 즉시 갱신하며 의미·위치가 유지된다.
- 화면낭독기는 입력 확정/안정된 계산 결과를 요약해 알린다. 매 타자마다 전체 표를 읽지 않는다.
- 키보드 닫기·뒤로가기·선택 복귀와 320/375px·데스크톱·200% 글자 확대를 검증한다.

중요한 입력 오류, 목표/예측 표식, 오래된 기준, 저장 실패는 물음표 안에 숨기지 않는다. 공식 유도·시설 상세·모델 한계는 상세에 둔다.

| S3 | 입력·표시·구간 산술 | 미착수 | PC-01~06, 원시 함수 검증, 단일 결과 스냅샷 |
| S4 | 오라클 계산 화면·모바일/PC 복귀 | 미착수 | 출발별 진입, 도구 전환·도움말 복원 |
| S5 | 기존 훈련 편집/페이스 변경 연결 | 미착수 | 적용 적격성·미리보기·저장·과거 보존 |
| S6 | 트랙·레인·구간표·페이스 표 | 미착수 | 합계 보존, 시설 원전 확인, 모드 의미 명확 |
| S7 | 집중 검수·리뷰·배포 | 미착수 | 변경 범위의 계약·UI 테스트, 공개 화면·계정 증거 분리 |

S3/S4는 원본 결함 수정과 읽기 계산에 집중한다. S5의 계정 적용이 외부 상태 때문에 불가능하더라도 계산 기능 검증과 안전한 읽기 공개를 분리할 수 있다. 이때 적용 가능하다고 표시하지 않는다.

SC는 S6의 시설 원전 확인이 안 되면 `조건부 대기`로 별도 보고한다. 단순 원문 접근 실패를 숫자로 덮거나 전체 이식을 완료했다고 합산하지 않는다.

검증은 변경된 함수·흐름에 집중한다. 앱 전체 기능을 반복 점검하거나 배포를 기다리는 동안 불필요한 대규모 CI를 여러 번 실행하지 않는다. 필수 검사와 실제 실패는 생략하거나 통과로 표기하지 않는다.

## 14. 완료 기준

사용자가 기록을 고르거나 입력하고 → 구간 시간과 기준을 이해하고 → 필요한 구간표/트랙 도구를 열고 → 원래 훈련으로 돌아오고 → 적용 가능한 변경만 확인·저장하며 → 과거 일지와 다음 계획의 근거를 혼동하지 않아야 완료다.

**숫자만 나오는 것, 원본 화면을 복사한 것, 미리보기 배포만 된 것은 전체 완료가 아니다.** 읽기 계산, 트랙 규격 검증, 실제 계획 연결, 로그인 저장을 각각 보고한다.

현재 준비 작업은 S1과 본 구현 계획까지다. 실제 앱·스펙·서버는 이 문서 작성으로 변경하지 않았다.

## 15. 상세화 결정과 우선순위

이하 내용은 기존 범위를 축소하지 않는 구현 세부안이다. 초기안에서 선택지가 남은 항목은 아래 권장안으로 구체화한다. 문서 작성 자체가 런타임 채택이나 과학적 근거 추가를 뜻하지 않는다.

### 15.1 세 가지 이용 모드

| 모드 | 무엇을 하는가 | 저장/변경 | 첫 화면의 주 행동 |
|---|---|---|---|
| 계산만 보기 | 기록·목표에서 구간 시간을 계산 | 계획·경기 이력 쓰기 없음 | 기준 바꾸기 / 구간표 |
| 이 훈련의 기준 바꾸기 | 선택 구간의 기준을 바꾼 미리보기 | 현재 화면에서 선택한 적용 대상만 명시 변경 | 이 훈련에 적용 |
| 남은 훈련 갱신 | 이미 연결된 해당 종목 기준을 일괄 갱신 | 표시된 적격 미수행 슬롯을 원자적으로 변경 | 남은 훈련 N개에 적용 |

계산만 보기 화면에 일괄 적용 버튼을 두지 않는다. 개별 모드에서 같은 목적의 다른 훈련까지 자동 선택하지 않는다. 일괄 모드는 기존 기준 링크 갱신이며, 링크가 없던 모든 훈련에 새 기준을 배정하는 기능이 아니다.

### 15.2 클릭 최소화

- 기록이 선택돼 있는 맥락에서는 종목·기록을 다시 묻지 않고 결과를 바로 연다.
- 선택한 기록이 없는 경우에만 종목 → 시간 순서를 쓴다.
- 완성된 입력의 산술 결과는 자동 갱신한다. 매번 `계산하기`를 누르게 하지 않는다.
- 적용 모드에서는 유효한 선택 뒤 변경 미리보기를 자동 준비한다. 핵심 전후 차이와 적용 대상이 이미 보이면 추가 확인 팝업 없이 명시 적용 버튼 한 번으로 요청한다.
- §4의 `변경 확인`은 미리보기가 아직 별도 화면에 있을 때의 진입명이다. 자동 미리보기가 같은 화면에 준비된 경우 `이 훈련에 적용` 또는 `남은 훈련 N개에 적용`으로 대체한다. 계산 선택 자체는 여전히 저장이 아니다.
- 목표 기준·오늘 미시작 확인·기존 더 긴 훈련 확인처럼 이미 필요한 조건은 생략하지 않는다. 동일 조건을 두 화면에서 반복 질문하지 않는다.
- 변경 상세, 제외 사유, 전체 표는 펼치기나 추가 화면으로 옮긴다. 현재 적용 범위·목표 표식·실패 상태는 바로 보인다.

### 15.3 개발 우선순위

P0는 구간 계산·입력 정확성·원점 복귀·새/기존 기준 연결이다. P1은 구간표·평지 트랙·레인·페이스 표이며 전체 프로젝트 완료 범위에 포함한다. P2인 새 생리학적 모델·별도 즐겨찾기 저장·소셜 공유는 이번 완료 범위가 아니다.

SC도 차용 대상에서 지우지 않는다. 시설 규격 근거 확인을 별도 완료 조건으로 가진 조건부 작업이다. 확인되면 계산 전용으로 제공하고, 미확인 상태를 전체 완료로 합산하지 않는다.

위 ID는 화면 역할이다. 9개 페이지를 차례로 다 방문하는 가입 절차가 아니다. 입력과 결과는 같은 작업 화면을 공유할 수 있으며 추가 도구는 선택적으로 연다.

### 16.1 종목과 기준 선택

화면 이름은 `페이스 계산`, 질문은 `어느 종목 기록인가요?`다. 표시명은 `800m / 1500m / 3000m / 5km / 10km / 하프 / 마라톤`이다. 이력 없는 사용자에게 임의의 경기 기록이나 목표 시간을 채우지 않는다.

훈련에서 열면 선언된 기준 종목을 먼저 사용한다. 기준 종목이 고정된 훈련에 다른 종목 선택지를 보여주고 나중에 실패시키지 않는다. 계산만 보기로 전환한 경우 다른 종목을 둘러볼 수 있지만 적용 모드는 해제한다.

기준 목록은 해당 종목의 의미별 선택지를 먼저 보여준다. 전체 경기 이력은 `다른 기록`으로 연다. 현재 선택을 목록 맨 위에서 유지하며 PB가 빠르다는 이유로 덮지 않는다.

사용자가 가지고 있는 기록은 단순 계산에 사용할 수 있지만, 확인 상태·날짜·현재성이 처방에 적합하지 않으면 적용 불가를 짧게 표시한다. 원본을 확인된 공식 기록으로 재분류하지 않는다.

### 16.2 시간 입력

800~10km의 기본은 분·초 두 필드다. `시간 포함`을 열거나 긴 종목 맥락에서 시 필드를 표시한다. 시 값이 0이 아니면 필드를 계속 표시하며, 접는 동작으로 값을 숨기거나 조용히 0으로 바꾸지 않는다. 이전 입력의 보이지 않는 시 값이 새 계산에 섞이면 안 된다. 긴 종목이어도 50분 등 입력은 그대로 허용한다.

`2:01.5` 또는 `1:20:00` 형태의 명시적인 시계 문자열 붙여넣기는 보조 기능으로 지원할 수 있다. 지원한다면 하나의 결정적 시간 파서를 쓰고 자유 문장·일지 메모에서 시간을 추출하지 않는다. V1 필수 입력은 구조화된 시·분·초다.

초 필드의 소수 입력과 키보드 `완료`를 지원한다. 음수나 60 이상을 다른 분 값으로 자동 보정하지 않는다. 빈 필드를 0으로 취급하는 것은 다른 유효 필드가 존재하는 계산 단계에서만 하며, 입력 원문은 빈 상태로 보존한다.

### 16.3 결과 숫자와 단위

첫 결과의 기준은 `800m 최근 경기 · 2:01.5`처럼 한 줄로 표시한다. 길면 기준 종류와 날짜를 두 줄로 나눈다. 작게 축소하거나 말줄임으로 목표 표식을 없애지 않는다.

짧은 구간은 `200m / 30.4초`, 긴 구간은 `1km / 4:00/km`처럼 단위를 바로 붙인다. `400m / 1:36`을 쓸 때는 구간 시간 열임이 분명해야 한다. `평균 속도 기준`을 짧게 두고 상세 설명은 물음표에서 제공한다.

계산만 보는 결과에는 세트·휴식·반복을 새로 만들지 않는다. 훈련 맥락에서만 기존 구성과 함께 `400m × 5 · 96초씩 · r60초`처럼 읽으며, 방법을 여는 기능은 기존 훈련 상세로 연결한다.

### 16.4 큰 화면과 작은 화면

모바일은 한 열 작업 화면이다. 결과 숫자는 기본 3열이고 320px·큰 글자에서 2열 또는 한 열로 바꾼다. 내용이 넘치면 세로 스크롤을 허용하며 정보를 자르지 않는다.

데스크톱의 실제 서비스는 `AppShell`을 넓은 화면에서도 동작시키는 경로를 확인한다. `DesktopWorkspace`는 여러 휴대폰 프레임을 나열한 쇼케이스이므로 이것만 통과하고 PC 서비스가 된 것으로 보고하지 않는다. 쇼케이스도 같은 계산 컴포넌트를 사용하되 별도 전역 상태나 숫자를 만들지 않는다.

상세 숫자·표는 넓은 화면에서 가용 폭을 활용한다. 인위적으로 휴대폰 폭에만 가두거나 정보 없는 대형 여백을 만들지 않는다. 기존 컴포넌트와 토큰을 우선한다.

## 17. 실제 여정과 버튼 순서

| 여정 | 순서 | 피해야 할 불필요한 행동 |
|---|---|---|
| 기록 없는 첫 방문 | 오라클 → 페이스 계산 → 종목 → 시간 → 자동 결과 | 로그인 강요, 날짜 먼저 묻기, 필드마다 다음 버튼 |
| 저장 기록 있음 | 오라클 → 페이스 계산 → 해당 종목 기록 선택/맥락 결과 | 이미 고른 종목 다시 선택 |
| 선택한 훈련 변경 | 훈련 상세 → 기준 바꾸기 → 기준 선택 → 전후 비교 → 이 훈련에 적용 | 새 훈련 유형·세트·휴식 재질문 |
| 새 경기 기록 등록 | 기록 저장 → 바뀔 기존 링크가 있을 때만 변경 보기 → 일괄 미리보기 → 적용 | 기록 저장을 계획 변경으로 간주 |
| 목표 탐색 | 결과 → 목표로 계산 → 시간 조정 → 목표 표식 결과 | 실제 PB를 수정하거나 자동 저장 |
| 트랙에서 확인 | 결과 → 트랙 도구 → 레인/모드 → 결과 | 도구를 바꿀 때 원본 기록 재입력 |
| 설명 읽기 | 결과/구간표 → 계산 근거 → 뒤로 | 홈으로 돌아가기, 숫자 초기화 |

숫자를 몇 번 바꿨다는 이유로 브라우저 뒤로가기를 수십 번 누르게 만들지 않는다. 반면 도구·상세로 들어간 사용자의 직전 페이지는 건너뛰지 않는다.

### 17.1 기록 수정과 목표 실험 구분

저장된 실제 기록은 결과 화면에서 읽기 전용이다. `목표로 계산`은 별도의 임시 목표 초안을 만들고 `목표`를 표시한다. 이때 원본 PB·경기 기록은 바뀌지 않는다.

`기록 수정`은 기존 경기 기록 편집기로 간다. 수정 완료 후 원본 버전이 달라지므로 계산·계획 미리보기의 기준을 다시 확인한다. 화면의 +/-로 저장된 PB를 조용히 고치는 UX는 만들지 않는다.

직접 구간 초를 조절하는 경우 기존 수동 입력 레인을 쓴다. 수동으로 바뀐 숫자를 다시 `800m 최근 경기에서 계산됨`이라고 표시하지 않는다.

### 17.2 모션

종목/기준 선택 후에는 기존 전환 방향으로 다음 콘텐츠를 보여준다. 결과 숫자만 달라지면 짧은 배경/밑줄 강조만 사용한다. 결과 영역의 높이는 바뀌지 않도록 한다.

도구 진입·돌아오기에는 방향성 있는 기존 전환을 사용한다. 입력 중 화면 이동, 자동 키보드 재열기, 숫자의 과도한 카운트업은 하지 않는다. 결과를 이해하기 전에 모션이 입력을 막으면 안 된다.

줄인 모션에서도 선택·결과·복귀가 동일하게 동작해야 한다. 숫자 색만 바꾸어 기준 변경을 알리지 않는다.

## 18. 산술·표시의 상세 규칙

### 18.1 단일 입력 스냅샷

입력 원문, 검증된 숫자, 계산 결과, 표시 문자열을 별도 의미로 취급한다. 계산 결과만 독립된 mutable state로 보관해 입력과 어긋나게 만들지 않는다.

유효 스냅샷은 기준 종류·종목·정밀 초·기록 ID/버전(저장 기록일 때)·계산 모델·평가일/시간대·대상 구간·반올림 정책을 함께 가진다. 모든 결과와 구간표는 같은 스냅샷을 읽는다.

입력이 비어 있거나 `1.`처럼 미완성인 동안 현재 결과와 적용 버튼을 해제한다. 원래 선택과 입력 원문은 유지한다. 오류를 이유로 사용자의 값을 지우거나 과거 결과를 현재 것처럼 남기지 않는다.

기록이 외부에서 수정·삭제되면 선택 결과를 `기준 다시 확인` 상태로 바꾼다. 새 기준 선택 전에는 현재 처방 적용을 금지한다. 이미 저장된 과거 스냅샷은 재계산하지 않는다.

### 18.2 구간표의 반올림

내부 누적 시각을 `C_i`, 표시 단위를 `u`초, 공통 반올림 함수를 `R_u`라고 한다.

```text
표시 누적 시간_i = R_u(C_i)
표시 구간 시간_i = R_u(C_i) - R_u(C_(i-1))
마지막 누적 시간 = R_u(목표 총 시간)
```

이 규칙으로 표시 구간의 합과 마지막 누적 표시가 일치하게 한다. 누적 값은 반올림된 이전 구간을 반복 더해 계산하지 않는다. 표의 구간 시간은 누적 값의 차이라 독립적으로 반올림한 구간 값과 최대 표시 단위 수준의 차이가 생길 수 있으며, 그 이유는 상세에서 설명한다.

이것은 표시 보정이지 실제 목표 초나 회복을 바꾸는 권한이 아니다. 훈련 처방의 원본 구간 초는 정밀 계산값으로 보존한다. 극단적으로 짧아 표시가 0이 되는 값은 `표시 단위 미만`으로 처리하며 유효한 0초 처방을 생성하지 않는다.

### 18.3 가속 구간표와 사용자 조정

구간 길이가 `d_i`, 총 거리 `D`, 양수 상대 시간 가중치가 `w_i`, 목표 시간이 `T`일 때:

```text
구간 초_i = T * (d_i * w_i) / sum(d_j * w_j)
```

입력 변화는 총합을 보존하며 모든 구간이 양수여야 한다. 균등 분할은 모든 가중치가 같다. 원본 계산기의 특정 ±1%를 자동 추천값으로 복사하지 않는다.

초기 화면은 균등만 자동 생성한다. `분할 조정`을 열면 앞/뒤 구간의 목표를 바꿀 수 있다. 조정량·단위·재분배 범위는 화면에 나타내고, `원래 분할`로 되돌릴 수 있게 한다. 총 목표 자체를 바꾸려면 별도의 총 시간 입력을 사용한다.

직접 고정한 구간이 있으면 남은 양수 시간만 미고정 구간에 배분한다. 고정 구간 합계가 목표보다 크거나 남은 구간에 양수 시간이 없으면 조정 불가를 표시한다. 임의로 고정값을 줄이지 않는다.

사용자 조정은 계산기 내 경기 구간 배분이다. 생리학적 동등성이나 최적 레이스 전략을 보증하지 않으며, 활성 훈련 계획의 구간 구조에 자동 이식하지 않는다.

### 18.4 페이스 표의 기본 범위

현재 계산의 km 페이스를 기준으로 가까운 5행을 먼저 보여주는 표시 규칙을 제안한다. 예를 들어 4:00/km이면 3:50·3:55·4:00·4:05·4:10/km다. 행 간격 5초는 탐색용 UI 간격이지 훈련 증감 추천량이 아니다.

다른 간격·이전/다음 범위·직접 행 추가를 지원한다. 존재하지 않는 음수/0 페이스 행은 만들지 않는다. 거리 열은 현재 맥락을 우선하고 `다른 거리`로 추가한다. 모든 비교값은 같은 평균 속도 환산이다.

최초 모바일 표는 거리 2~3개와 기준 열 정도로 제한한다. 많은 열을 선택한 사용자는 가로 표 탐색을 사용할 수 있지만 기본 화면 전체를 가로로 밀게 하지 않는다. 표 열의 단위를 항상 표시한다.

## 19. 상태·복귀·임시 보관 계약

### 19.1 상태 목록

| 상태 | 보여줄 것 | 허용 행동 |
|---|---|---|
| EMPTY | 종목·시간 입력 | 입력 / 명시 예시 |
| INCOMPLETE | 입력 원문, 짧은 안내 | 계속 입력; 현재 결과 적용 불가 |
| INVALID | 필드별 이유 | 값 수정; 이전 결과를 현재로 사용 금지 |
| READY | 기준·결과·도구 | 비교·도구 이동 |
| REFERENCE_CHANGED | 기준 다시 확인 | 새 기준 선택; 현재 적용 금지 |
| PREVIEW_READY | 전후 차이·적용 범위 | 명시 적용 / 취소 |
| APPLYING | 변경 요청 중 | 중복 요청 잠금, 기존 결과 유지 |
| SAVE_UNCONFIRMED | 저장 결과 확인 중 | 기존 요청의 결과 조회, 새 요청 금지 |
| CONFLICT | 기준/계획이 달라짐 | 새 미리보기; 기존 초안 보존 |
| FAILED | 실제 실패 이유 | 같은 초안으로 재시도 / 취소 |
| APPLIED | 서버 확인된 결과 | 원래 훈련 복귀 / 허용된 되돌리기 |

계산은 동기 산술이므로 가짜 로딩 스피너나 기다림 시간을 넣지 않는다. 네트워크 상태는 실제 계획 저장·계정 읽기에만 표시한다.

### 19.2 이력 이동

앱 오버레이의 기존 owner/version 검증을 확장하고 화면 ID와 임시 컨텍스트 ID만 이력에 넣는다. 기록 원문·개인 숫자·로그인 정보는 주소나 이력 마커에 싣지 않는다.

- 새 계산 도구 진입은 1개의 이력을 추가한다.
- 초기 종목 선택 → 입력은 의미 있는 다음 화면이다. 입력 중 자동 결과 갱신은 같은 화면이므로 이력을 추가하지 않는다.
- 기준 선택·구간표·트랙·페이스 표·근거는 직전 화면으로 복귀할 수 있는 이력을 추가한다.
- 숫자 변경·필터·동일 도구 모드 전환은 새 이력을 쌓지 않는다.
- 선택 완료는 결과로 복귀하면서 상위 초안을 갱신한다. 동일 선택을 두 번 소비하거나 뒤로가기로 저장을 재실행하지 않는다.
- 미리보기 취소·단순 뒤로가기는 쓰기를 수행하지 않는다.

기존 `openOverlay`는 정해진 종류의 단계 변경 외에는 `replaceState`를 사용한다. `pace-calculator` 종류만 추가하고 끝내면 도구 복귀가 건너뛰어질 수 있다. 추가 도구의 의미 있는 단계 전환을 명시적으로 분류하고 회귀 테스트를 쓴다.

복귀 시 출발 탭·훈련 주소(day/slot)·편집 중 구간·스크롤·포커스를 복원한다. 복원 대상이 삭제됐으면 현재 존재하는 상위 목록으로 돌아가며, 관계없는 홈으로 강제 이동하지 않는다.

### 19.3 초안 보존

도구 왕복 초안은 상위 컨트롤러 메모리에 보관한다. 숫자를 자동으로 전역 localStorage에 쓰지 않는다. 같은 방문 안에서는 내부 도구를 오가도 입력을 유지한다. 새로고침 후 임시 계산의 복원은 V1 필수 보장 범위가 아니다.

계산 화면을 열기 전에 기존 일지/계획 편집의 미저장 보호를 통과해야 한다. 계산기 초안이 단순 임시 산술인 경우 모든 뒤로가기마다 버리기 확인을 요구하지 않는다. 실제 저장 요청이나 기록 등록 초안이 생겼다면 기존 보호 경로를 사용한다.

계정 변경·로그아웃·컨텍스트 교체 시 이전 기록과 pending callback을 무효화한다. 이미 시작한 요청의 반환은 원래 계정/요청에만 반영한다. 다른 계정 화면에 결과·성공 알림이 나타나면 결함이다.

## 20. 적용 세부 계약과 확인해야 할 코드 차이

### 20.1 개별·일괄 대상

개별 모드는 선택한 세션의 선택된 구간/기존 편집 초안을 수정한다. 혼합 세션에서 10km RP와 1500m RP를 하나의 기준으로 덮지 않는다. 개별 적용을 일괄 갱신 함수에 넣어 다른 날까지 바꾸지 않는다.

일괄 모드는 같은 종목의 기존 연결을 가진 적격 남은 슬롯만 대상으로 한다. 날짜·AM/PM·수동 고정·보호 일지·기존 템플릿·현재 안전 조건을 검사한다. 오늘은 미시작 확인과 보호 자료 부재를 만족할 때만 가능하다.

적용 개수는 세션/구간 중 무엇을 센 것인지 고정한다. 주 CTA는 `남은 훈련 3개에 적용`처럼 세션 수를 사용하고, 상세에 변경 구간 수를 표시한다. 오후 구간 1개 변경을 하루 전체 변경처럼 표시하지 않는다.

### 20.2 같은 숫자, 다른 근거

| 상황 | 의미 | 처리 |
|---|---|---|
| 같은 기록·같은 버전·같은 모델·같은 값 | 변경 없음 | 적용 요청하지 않음 |
| 동일 기록이 최근 경기와 PB 둘 다 해당 | 선택 표식 차이 | 중복 카드 없음; 표식만으로 계획을 다시 저장하지 않음 |
| 실제 → 목표, 표시 초 동일 | 기준 의미 변경 | `목표 기준으로 바뀜` 표시, 명시 적용 가능 여부 검사 |
| 다른 실제 기록/새 버전, 표시 초 동일 | 개인 근거 변경 | 명시 기준 변경은 새 근거 스냅샷으로 확인; 숫자 증량 없음 |
| 정밀 초 변경, 반올림 표시 동일 | 계산 원본 변경 | 상세 정밀 차이와 근거 변경 표시; 과거 값 보존 |

현재 `paceTargetsChanged`는 숫자와 실제/목표 구분을 중심으로 검사한다. 새 기록 자동 저장 알림의 `NO_PACE_CHANGE` 동작과, 사용자가 명시적으로 다른 기준을 고른 동작을 구분해야 한다. 모든 기록 저장을 근거 변경 적용으로 바꾸지 않는다. 명시 선택을 조용히 버리지도 않는다.

이 차이는 구현 시 기존 함수/계약 테스트를 대조해 최소 범위로 보완한다. 표의 처리안은 새 과학 모델 승인이 아니라 명시 선택과 스냅샷 정합성을 위한 계획이다.

### 20.3 저장 결과 불명

타임아웃은 저장 실패의 증명이 아니다. 기존 원자적 요청 식별자/영수증 경로로 동일 요청의 결과를 확인한다. 확인 전에는 성공·실패를 단정하거나 새 요청 ID로 다시 적용하지 않는다.

확인 후 성공이면 서버의 현재 버전과 적용 결과를 받아 원래 훈련으로 돌아간다. 확인된 실패이면 초안을 보존해 재시도한다. 충돌이면 새 차이를 보여주고 이전 승인으로 새 값을 적용하지 않는다.

되돌리기는 마지막 변경의 원래 스냅샷을 사용한다. 이후 기록·진행이 생긴 슬롯을 보호하고, 현재 PB로 과거 계획을 재구성하지 않는다.

### 20.4 신규 스키마·서버 변경의 원칙

계산만 보기와 트랙 도구에는 새 DB나 Edge Function이 필요하지 않다. 기존 계획 적용은 기존 저장 경로를 우선 사용한다.

현재 엄격 스키마에 새 표식이나 스냅샷 정보를 넣을 자리가 없다면, UI 임시 메타데이터와 저장 필수 메타데이터를 먼저 구분한다. 저장 필수 확장은 S2에 호환·버전·내보내기·서버 검증 범위를 기록하고 구현한다. 임시 화면 값 때문에 별도 영구 저장소를 만들지 않는다.

## 21. 작업 단위·파일 경계·병행 가능 범위

세부 작업은 동반 작업지시서의 W1~W8을 따른다. 해당 지시서는 인력 발주가 아니라 후속 구현용 분해다. 이번 계획 요청으로 새 작업자를 실행하지 않는다.

W1은 S2의 경계 계약과 스키마 맵을 먼저 정한다. W2 산술과 W3 화면 준비는 그 인터페이스가 정해진 뒤 독립 파일에서 병행 가능하다. W4 내비게이션과 W5 계획 연결은 실제 화면·콜백이 준비된 뒤 통합한다. W6 추가 도구, W7 공격적 검수, W8 공개 확인 순서로 마친다.

초기 단계와 세부 작업의 대응은 `S2 = W1`, `S3 = W2`, `S4 = W3 + W4`, `S5 = W5`, `S6 = W6`, `S7 = W7 + W8`이다. S1은 이미 완료한 원본 감사이며 새 구현 증거로 중복 집계하지 않는다. W2의 종료는 순수 계산 검수이고, 해당 계산을 쓰는 화면 여정은 W3/W4/W6와 W7에서 완료한다.

`AppShell`의 이력, 기존 계획 적용 함수, 공통 기록 타입은 한 통합 담당만 수정한다. 화면 담당이 별도 적용 함수를 복제하거나, 트랙 담당이 기록 타입을 늘리지 않는다.

공유 파일의 동시 작업이 확인되면 변경 내용을 읽고 소유 범위를 나눈다. 관련 없는 변경·초안·에셋을 되돌리지 않는다. 임의 새 브랜치·전체 리베이스·정리 삭제는 이 지시서의 일부가 아니다.

## 22. 검수의 범위와 증거

### 22.1 단계별 검수

| 관문 | 필요한 증거 | 충분하지 않은 증거 |

| UI | 입력 변경·도구 왕복·포커스·모바일/PC 화면 | CSS 계약 검사만 통과 |
