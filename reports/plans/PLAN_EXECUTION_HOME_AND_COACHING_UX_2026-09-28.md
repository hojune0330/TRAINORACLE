## 1. 최종 설계 방향

**메인 탭인 홈에 `훈련 코칭`을 상설 배치한다. 홈은 지금 할 일과 읽을 이유를 보여주고, 상세 화면은 실제 수행 차이·다음 일정·근거를 설명한다.**

새로운 여섯 번째 하단 탭을 만드는 안이 아니다. 첨부된 홈 화면을 기준으로 현재의 큰 분석 소개와 메뉴 여섯 개를 상단에 그대로 둔 채 코칭을 덧붙이지 않는다. 기존 정보의 위치와 우선순위를 조정한다.

- 홈: 지금 중요한 코칭 한 건, 다음 훈련/기록의 빠른 진입, 읽을거리 일부.
- 훈련 코칭 상세: 계획과 실제 차이, 설명, 교정안, 코칭 이력.
- 분석 탭: 기간별 수치·비교·구성·누적 데이터. 계산 결과는 재사용하고 별도 분석기를 만들지 않는다.
- 계획 탭: 전체 달력과 개별 세션 실행. 교정 전후 일정은 같은 달력 렌더러를 사용한다.
- 일지: 사실을 입력하고 당시 원본과 비교하는 곳. 교정 검토 때문에 기록 저장이 지연되거나 취소되지 않는다.

훈련하는 날/쉬는 날이라는 구분으로 홈 전체를 바꾸지 않는다. 같은 위치에 같은 종류의 정보를 두고 그 안의 실제 상태만 갱신한다. 오늘 뛴 것이 없어도 기존 기록의 해설과 일반 훈련 콘텐츠를 읽을 수 있다.

이 문서는 [전체 구현 계획](PLAN_EXECUTION_REVIEW_AND_REPLAN_IMPLEMENTATION_PLAN_2026-09-28.md)의 F 작업을 구체화한다. [비교·재설계 계약](../../specs/reconstruct/PLAN_EXECUTION_DEVIATION_AND_REPLAN_CONTRACT.md)의 A~E 코어·정책·계정 관문을 생략하지 않는다.

## 2. 현재 화면의 문제와 근거

사용자가 제공한 스크린샷은 UI 관찰 자료다. 이 검토에서 새 브라우저 시험이나 실제 사용자의 과제 수행 시험은 하지 않았다. 아래 코드 위치는 inspected head에서 읽었다.

| 근거 종류 | 확인한 내용 | 개선 결정 |
|---|---|---|
| 스크린샷 + [TrainingHome.tsx](../../app/src/screens/home/TrainingHome.tsx) L69-82 | 큰 분석 CTA와 6개 토픽이 다음 훈련보다 먼저 표시 | 사용자가 지금 처리할 행동을 상단에, 일반 탐색은 아래로 |

| 설계 위험 | 예시·일반 정보가 개인 처방처럼 보임 | 근거 종류와 날짜를 제목 가까이에 표시. 예시로부터 실제 계획 적용 금지 |

새 설계로 위험을 다루었다는 뜻이지, 현재 UI의 수정 완료나 실화면 PASS 판정은 아니다.

## 3. 홈 정보 순서

공통 순서는 아래와 같다. 큰 글자·안전/저장 문제 등으로 첫 화면을 넘으면 세로 스크롤을 허용한다. 무스크롤을 맞추려고 핵심 숫자나 접근성을 삭제하지 않는다.

1. 현재의 작은 브랜드/계정/더보기 헤더.
2. 즉시 필요한 안전·저장 상태. 해당 없으면 공간을 차지하지 않음.
3. **훈련 코칭과 다음 행동:** 중요한 한 건만 강조. 상단의 넓은 주요 버튼도 하나.
4. **기록:** `운동 기록하기` 또는 `오늘 기록 보기` + 작은 `기록 더 남기기`. 기록 완료를 모든 훈련 완료로 표현하지 않음.
5. **내 기록으로 읽는 훈련:** 실제 근거가 있는 최신 코칭 요약 최대 두 건과 `지난 코칭`.
6. **훈련 알아보기:** 일반 콘텐츠 최대 두 건과 `훈련 배우기`. 개인 코칭과 분리.
7. 기존 분석·일지·꾸미기 등 탐색의 짧은 진입. 기존 여섯 분석 항목은 분석 화면에서 모두 접근 가능하게 유지.

`훈련 코칭`이 다음 세션에 관한 내용이면 같은 세션의 큰 `다음 훈련` 카드를 바로 아래에 중복하지 않는다. 하나의 영역 안에서 현재 일정과 확인 행동을 보여준다. 다른 기간의 회고 글이라면 다음 훈련이 더 먼저이며 회고는 읽을거리 위치에 둔다.

상단 제목은 큰 질문형 광고 문장보다 `훈련과 기록`처럼 짧은 제목을 기본으로 한다. 브랜드·로그인 표시·고정 하단 탭은 유지한다. 기존 기록/계획 없이 들어온 사람에게 `내 분석 결과`를 가지고 있는 것처럼 말하지 않는다.

### 홈에서 없애거나 옮길 것

- 큰 분석 CTA와 동일 목적의 대형 소개를 코칭 위에 중복하지 않는다.
- 6개 분석 타일은 홈 첫 화면에서 아래 탐색/기존 분석 화면으로 옮긴다. 기능 자체를 삭제하지 않는다.
- `기록 없음`·`미사용`을 모든 모듈에 반복하지 않는다. 판단에 중요한 누락은 해당 코칭 안에서 숨기지 않는다.
- 원문 지문·스키마·상태 코드·검수 과정·내부 처리 명칭을 기본 화면에 쓰지 않는다.
- 알림 개수를 줄이기 위해 의미가 다른 미해결 문제를 삭제하지 않는다. 상단 한 건과 `다른 확인 사항 N건`의 목록으로 나눈다.

## 4. 상단 행동 결정표

상단 배치는 순수한 `HomeCoachingViewModel`로 계산한다. 이는 새로 구현할 결과 모델이며 기존에 존재한다고 간주하지 않는다. 안전·저장 상태는 별도 축이며, 이 표의 조언이 이를 무효화하지 않는다.

| 실제 상태 | 상단 내용 | 주 행동 | 다음 행동/금지 |
|---|---|---|---|
| 새 방문, 계획·기록 없음 | 기록 후 받을 수 있는 설명의 짧은 예고 | `운동 기록하기` | `코칭 예시 보기`, `계획 만들기`는 보조. 로그인 선요구 없음 |
| 계획만 있음, 수행 기록 없음 | 정확한 다음 세션과 기존 처방의 목적 한 줄 | `훈련 보기` | `이 훈련을 하는 이유`. 수행 차이가 있다고 꾸미지 않음 |
| 계획 없는 기록 사용자 | 근거 있는 기록 요약/최근 기록 | 오늘 기록 전 `운동 기록하기`, 기록 후 `오늘 기록 보기` | 계획 비교를 강요하지 않고 `계획 만들기`는 선택 |
| 변경 기록의 핵심 정보 미확인 | 확인된 차이 + 필요한 질문 하나 | `실제로 한 훈련 확인` | 긴 일지 재작성 요구 없음 |
| 다음 훈련 영향 검토 필요 | 관련 날짜/슬롯 + 짧은 이유 | `다음 훈련 확인` | 기존 일정은 `검토 전 일정`으로 구별. 없는 교정안을 있다고 하지 않음 |
| 검토된 새 안 준비 | 바뀌는 범위와 이유 한 줄 | `변경안 보기` | 홈에서 즉시 적용하지 않음 |
| 근거 있는 유지 결론 | `다음 일정은 그대로 진행해요` + 이유 | `훈련 보기` | 완료율이나 RPE 하나만으로 유지 결론 생성 금지 |
| 교정안 서버 적용 성공 | `변경된 일정` + 다음 세션 | `훈련 보기` | `왜 바뀌었나요?`와 지난 코칭 보존 |
| 다음 훈련 없음/계획 종료 | 최근 코칭·기록 요약 | `최근 기록 보기` 또는 `다음 계획 만들기` | 없는 다음 훈련이나 미수행을 발명하지 않음 |
| 저장 대기/오프라인/출처 오류 | 자료 상태 + 가능한 읽기 행동 | 해결 가능한 `저장 상태 확인` 등 | 빈 기록/미수행/개인 분석으로 대체 금지 |
| 기존 안전 확인 우선 상태 | 기존 안전 문구와 확인 행동 | 기존 안전 확인 경로 | 새 코칭이 교정 수락·훈련 실행 권한을 부여하지 않음 |

읽을거리 탐색은 비차단 상태에서 계속 가능하다. 아직 확인 안 된 교정안이나 오래된 처방을 현재 승인된 훈련처럼 보이게 해서는 안 된다.

### 여러 상태가 동시에 있을 때

1. 안전과 저장 문제는 삭제하거나 하나로 오해되게 합치지 않는다. 같은 원인의 중복 안내만 묶는다.
2. 코칭 순위는 안전 경로와 분리해 가장 가까운 미수행 세션에 영향을 주는 검토를 우선한다. 영향 규칙 없는 항목을 긴급 처방으로 승격하지 않는다.
3. 같은 세션/계획 revision의 관련 기록은 하나의 검토 묶음으로 표현하고 서로 다른 미해결 사항은 목록에 남긴다.
4. 영향 정책·대상 날짜·안정적 id 등 명시된 순서로 정렬한다. 매 방문 무작위나 조회수순으로 바뀌지 않는다.
5. 새 데이터가 와도 읽는 중 스크롤·포커스를 빼앗지 않는다. `새 기록이 도착했어요`를 통해 명시적으로 새 결과를 연다. 적용 버튼은 즉시 만료 처리한다.

## 5. 화면 구조 예시

다음은 합성 사례의 텍스트 와이어프레임이다. 실제 앱 캡처나 훈련 수치 채택이 아니다.

```text
훈련 코칭
달라진 훈련, 다음 일정을 확인해요
어제 예정된 반복 훈련 대신 자전거를 기록했어요.

[ 다음 훈련 확인                          > ]

기록

기록 더 남기기

내 기록으로 읽는 훈련              지난 코칭 >
회복 시간을 바꾼 날, 어떤 점이 달랐나요?    >

훈련 알아보기
반복 사이에는 왜 쉬나요?                   >
```

### B. 교정 검토가 필요하지 않은 홈

```text
TRAINORACLE                         계정  더보기

다음 훈련
화요일 오후 · 저장한 훈련명
저장한 정확한 운동 구성 · 반복 사이 회복
[ 훈련 보기                              > ]
이 훈련을 하는 이유

기록                                     >

내 기록으로 읽는 훈련              지난 코칭 >

```

비교가 없으면 그냥 원래 계획을 보여준다. 코칭 검토가 실제로 있었다면 그 날짜와 짧은 결론을 추가한다. 자료가 없다는 이유로 `문제없음`을 만들지 않는다.

### C. 처음 온 사람

```text
TRAINORACLE                         로그인  더보기

훈련과 기록
오늘 한 운동을 남겨요
[ 운동 기록하기                          > ]
계획 만들기

이런 코칭을 볼 수 있어요                  예시
```

예시는 항상 `예시` 표시와 합성 데이터 출처를 유지한다. 실제 기록이 있는 사람에게 예시를 첫 과제로 반복하지 않는다. 저장 읽기 실패 때문에 잘못 방문자 모드로 전환하지 않는다.

## 6. 코칭 읽기 화면

모바일은 전체 화면으로 읽고 PC는 기존 본문 너비를 유지한다. 긴 내용을 작은 팝업·중첩 서랍에 넣지 않는다. 읽는 재미는 메뉴 개수나 긴 서문이 아니라 **내 기록의 구체적인 사실이 다음 판단으로 이어지는 내용**에서 만든다.

1. **결론:** 지금 무엇을 확인/유지/변경할지 한 줄. 기준 일자와 개인 기록/일반 정보/예시 표시.
2. **계획과 실제:** 동일 범위의 숫자·구간을 나란히. 없는 값은 미기록, 충돌값은 확인 필요.
3. **무엇이 달라졌나요:** 사실과 검토된 해석 분리. 두세 문장 기본, 추가 설명은 펼침.
4. **다음에는 어떻게 하나요:** 유지되는 부분, 바뀔 부분, 변경하지 않는 이유까지.
5. **왜 이렇게 판단했나요:** 사용 필드, 규칙·검토 버전, 기전/코칭 자료, 모르는 부분. 기본 접힘.
6. **관련 글/지난 기록:** 읽기를 마친 뒤 선택. 새 처방처럼 자동 연결하지 않음.

기존 상세 처방의 `방법 / 이유·근거 / 주기·기록`과 충돌하지 않게, 정확한 방법은 기존 세션 상세를 연다. 두 번째 처방 포맷터나 별도 숫자를 만들지 않는다.

### 글과 시각 자료

- 계획/실제의 운동·회복 순서를 짧은 나란한 도식으로 표시한다. 순서도는 시간 비례 그림처럼 보이지 않게 한다.
- 일정 비교는 기존 달력 renderer에 전후 diff를 전달한다. 실제 년월·요일·오전/오후를 유지한다.
- 날짜를 누르면 해당 세션과 변경 이유를 크게 본다. 글자 범례만으로 일정을 설명하지 않는다.
- 불명확한 값에 막대 길이·회복률·기여율 퍼센트를 그리지 않는다.
- 기본/전문 보기 모두 결론·변경 숫자·회복·적용을 본다. 전문 보기만 근거를 더 자세히 펼친다.
- 차트에 표/텍스트 대안을 제공한다. 중학생이 핵심을 읽을 수 있는 한국어를 쓰고 전문 용어는 기존 용어집으로 연결한다.

## 7. 읽기·검토·적용의 상태 분리

| 상태 축 | 예 | 의미와 제한 |
|---|---|---|
| 읽기 | NEW / OPENED | 화면을 열었는지. 끝까지 이해했다는 증거 아님 |
| 검토 | NEEDS_INPUT / READY / DEFERRED / RESOLVED / STALE | 비교·제안 상태. 글을 열었다고 해결되지 않음 |
| 계획 적용 | NOT_REQUESTED / PENDING / APPLIED / FAILED | 계정 서버 적용 여부. APPLIED는 정확한 revision 영수증 필요 |

세 상태는 별도다. `읽음`은 계획 변경 동의가 아니다. `변경안 보기`는 적용이 아니다. `나중에`는 문제 해결이나 기록 삭제가 아니다.

- 같은 근거 digest/규칙 버전의 알림을 매 방문 다시 NEW로 만들지 않는다.
- `나중에`를 선택하면 비차단 큰 안내는 접고 관련 다음 훈련에 확인 경로를 남긴다. 새로운 안전 상태는 기존 계약대로 처리한다.
- 자료 수정·삭제·늦은 동기화·계획 revision·권한 변경 시 제안은 STALE이다. 과거 코칭은 `당시 기록 기준`으로만 읽는다.
- 실제 적용 후에도 과거 설명과 원래 계획 링크를 보존한다. 저장 성공을 글 읽기 애니메이션으로 대체하지 않는다.
- `지난 코칭`은 내 계정 범위의 목록이다. 해결 여부·기준 날짜를 표시하고 공개 프로필/친구에게 자동 노출하지 않는다.

### 이력과 읽기 상태의 보관 범위

- 코칭 결과는 source refs/revisions, 비교 결과, 채택된 설명/규칙 버전, 적용 영수증 참조로 재현한다. 매 방문 최신 설명을 과거 기록에 새로 끼워 넣지 않는다.
- 읽기 상태는 reportId/evidence digest와 열람·미루기 상태 등 최소 정보만 가진다. 상세 건강값·메모·완독 시간 추적을 추가하지 않는다.
- 로그인 사용자는 기존 계정 저장/권한/삭제/보존 정책을 재사용한다. 새로운 전체 원문 복사본이나 별도 개인정보 보관소를 만들지 않는다.
- 원본 삭제·동의 철회·계정 범위 변경 시 연결된 코칭의 열람/캐시도 같은 정책에 맞춰 무효화한다. 이력 보존을 이유로 지운 원본을 우회 열람시키지 않는다.
- 로그아웃 사용자는 기존 허용 범위의 기록/예시를 이용한다. 읽기 이력을 동기화하기 위해 가입을 강요하거나 로그인 시 기기 기록을 자동 계정 편입하지 않는다.
- 정확한 저장 adapter, 읽음 상태의 다기기 병합, 원본 삭제 전파는 전체 계획 E에서 정하고 검수한다. 이 부분을 단순 CSS/상태 훅 작업으로 생략하지 않는다.

## 8. 읽을거리 공급과 개인화의 정직성

| 콘텐츠 | 선택/생성 근거 | 기본 표식 | 허용 행동 |
|---|---|---|---|
| 수행 후 코칭 | 정확한 개인 계획·적격 수행 기록·채택 규칙 | `내 기록 · 기준 날짜` | 비교·검토된 제안 보기 |
| 계획 해설 | 저장된 구성·배치·검토된 설명 | `현재 계획` | 방법/이유 읽기 |
| 기간 회고 | 자료 조회가 정상 완료된 적격 집계·버전 | `내 기록 · 기간` | 수치/구성 비교. 효과 원인이나 능력 부족 단정 금지 |
| 일반 훈련 설명 | 승인된 용어·훈련 콘텐츠와 출처 | `훈련 알아보기` | 읽기. 계획 적용 버튼 없음 |
| 체험 예시 | 고정 합성 자료 | `예시` | 결과 체험. 실제 계획/일지 자동 삽입 없음 |

별도의 글 생성 AI를 추가하지 않는다. 구조화 사실·검토된 설명을 조립한다. 원문 메모/비밀 메모 내용이나 존재를 콘텐츠 선택·코칭 제목·분석에 사용하지 않는다.

콘텐츠 양을 위해 매일 같은 결론을 새 날짜로 발행하지 않는다. 근거가 바뀌거나 새 검토 결과가 있을 때 개인 코칭을 갱신한다. 개인 코칭이 없을 때는 일반 글을 구별해 제공할 수 있다.

일반 글에서 기존 계획/기록 기능으로 이동할 수는 있지만, 읽은 사실을 훈련 동의나 적격성으로 사용하지 않는다. 완독·조회·더 많은 운동을 보상이나 훈련량 증가에 연결하는 기능은 이번 범위에 추가하지 않는다.

## 9. UI 규격과 상호작용

- [현재 UX·UI 기준](../../docs/UX_UI_VISUAL_STANDARD.md)을 우선한다. Pretendard·기존 토큰·hairline·lucide를 재사용하고 새 테마/외부 UI 라이브러리는 도입하지 않는다.
- 페이지 구획은 여백·헤딩·구분선으로 나눈다. 떠 있는 큰 카드, 카드 중첩, 그림자, 왼쪽 색띠, 신규 둥근 배지를 남발하지 않는다.
- 큰 틸 액센트 버튼은 홈 한 화면에 하나. 보조 행동은 텍스트/아이콘과 충분한 터치 영역으로 구분한다. 안전/실패 의미색은 숨기지 않는다.
- 제목/본문/캡션 토큰과 최소 44px 타깃을 유지한다. 글자를 줄여 첫 화면에 억지로 넣지 않는다.
- 행 전체가 글 열기라면 그 안에 별도 도움말/적용 버튼을 중첩하지 않는다. 추가 행동은 형제 요소로 둔다.
- 펼침/다음 질문에는 기존 200~350ms 토큰 범위의 짧은 전환만 사용한다. 자동 슬라이드·캐러셀·무한 맥박/회전은 금지한다.
- 명시적 클릭 뒤에만 해당 제목/질문으로 포커스를 준다. 배경 동기화·홈 진입·새 코칭 도착 때문에 읽는 위치를 끌어내리지 않는다.
- reduced motion에서는 즉시 전환한다. 애니메이션 종료가 저장/적용 조건이 되지 않는다.
- 스와이프에 이전/다음 버튼과 키보드 대안을 둔다. 작은 도움말은 기존 TermHelp, 긴 내용은 전체 화면 reader.
- 적용 버튼은 상세 변경안에서만 강조한다. 연속 클릭/복귀/새로고침으로 중복 적용하거나 손가락 위치에 버튼이 바뀌어 오작동하면 안 된다.
- 하단 탭·안전영역을 고려한다. 기본 글자 375×667에서 큰 주요 행동에 접근하도록 설계하되 실제 합격은 렌더링 후 판정한다. 320px·200%에서는 정상 세로 스크롤을 허용한다.

## 10. 탐색·계정·성능 계약

기존 [AppShell.tsx](../../app/src/AppShell.tsx)의 origin/owner/history와 draft-safe navigation을 확장한다. 코칭용 독립 history stack은 만들지 않는다.

- 홈→코칭→용어집→뒤로는 같은 코칭 문단/확장 상태로, 다시 뒤로는 원래 홈 위치로 복귀한다.
- 일지/달력 진입이면 같은 기록/날짜/슬롯으로 복귀한다. 무조건 홈으로 보내지 않는다.
- URL/history에 개인 수치·이유·안전 정보·메모를 넣지 않는다. opaque id로 조회해도 id 자체를 권한으로 취급하지 않는다.
- 계정 전환·권한 회수·기록 삭제·직접 주소·새로고침에서 원본과 권한을 확인한다. 상세가 없다고 가짜 예시로 대체하지 않는다.
- 비교 중 뒤로 가면 미리보기는 저장되지 않는다. 적용 성공 뒤 뒤로간다고 실제 적용을 취소하지 않는다.
- 홈은 요약/참조만 읽고 전체 원본·논문·이력을 전부 내려받지 않는다.
- 캐시 키는 account/athlete scope, plan revision, evidence digest, policy version, 표시 버전을 포함한다. 계정/권한 변경 시 캐시와 화면을 정리한다.
- 오래된 캐시는 `이전 기록 기준`이며 적용 권한이 없다. 비공개 데이터를 공개 service-worker 캐시로 옮기지 않는다.
- 로딩/실패/재시도 중에도 미해결 상태를 없애지 않는다. 기존 `loadEntries()` 배열만으로 읽기 완전성을 판정하지 않고 COMPLETE/PARTIAL/UNAVAILABLE/CONFLICT 상태를 전달한다.
- 계정 전환 뒤 도착한 pending apply 응답이 새 계정 화면을 갱신하지 않는다. 적용 진실은 서버 영수증과 기존 원자적 저장 경로가 소유한다.

| 처음 온 중학생 | 기록·계획·예시를 설명 없이 찾는가? 예시를 자기 결과로 착각하는가? |
| 기록만 쓰는 일반 러너 | 코칭/계획을 강요받지 않고 간편 기록을 끝내는가? |
| 일2회 선수 | 어느 날짜·오전/오후의 차이이고 어느 다음 세션에 영향이 있는가? |
| 읽으러 온 사용자 | 새 기록 없이 지난 코칭/일반 글을 찾는가? |
| 여러 날 운동 변경 | 중요한 건을 처리하면서 다른 미해결 사항도 찾는가? |
| 이미 글을 읽은 사람 | 반복 알림 없이 아직 미적용이라는 점을 아는가? |
| 한 손·큰 글자 | 읽기와 실제 변경을 혼동하지 않고 버튼에 접근하는가? |
| 스크린리더·키보드 | 계획/실제 비교, 행 이름, 포커스 복귀가 명확한가? |
| 느린 통신·오프라인 | 저장 완료/대기/코칭 준비/실패를 구분하고 입력을 보존하는가? |
| 다른 계정으로 전환 | 이전 사용자의 설명·수치·제안이 남지 않는가? |

합격 기준:

- 홈→코칭 상세는 1탭. 질문이 없는 교정안은 상세→전후 확인→명시적 적용으로 끝난다. 탭 목표 때문에 필요한 확인을 생략하지 않는다.
- `읽음`, `나중에`, `적용됨`의 차이를 문장으로 구별할 수 있다.
- 여섯 분석 항목·일지 꾸미기·훈련 배우기를 기존 탭/탐색에서 여전히 찾을 수 있다.
- 새 방문/계획만 있음/기록 있음/변경 검토/적용 후/자료 오류를 서로 다른 fixture로 캡처한다.
- 320×568, 375×667, 넓은 PC, 200% 글자 확대, reduced motion에서 가로 넘침·가려진 버튼·과도한 점프가 없다.
- 뒤로/앞으로/용어집/새로고침/동기화 중 이동을 무작위 순서로 시도하되 seed와 경로를 기록해 재현한다.
- 계정·안전·저장·내용 변경을 주입하면 오래된 결과를 적용하지 못하는 테스트가 실제 결함을 잡는지 확인한다.
- 전후 캡처, 접근성/탐색/상태 검사, 계정 적용 실행을 각각 증거로 남긴다. 예쁜 화면만으로 완료하지 않는다.

새 외부 행동 분석 서비스는 도입하지 않는다. 초기 평가는 합성 시나리오·로컬 검수이며 실사용 관찰은 기존 동의/수집 정책 범위의 최소 이벤트만 사용한다. 기록 내용·개인 건강값을 행동 로그에 넣지 않는다.

## 14. 구현 순서와 종료 경계

1. 전체 계획 A/B/C에서 비교·근거·검토 결과 shape와 권한을 고정한다.
2. 상태별 fixture를 작성하고 홈 정보 순서를 적용한다. 실제 결과 없는 가짜 교정 카드는 노출하지 않는다.
3. 공통 코칭 reader와 일지/달력/홈의 진입·복귀를 연결한다.
4. 전체 계획 D/E의 교정안·계정 수락이 준비되면 전후 달력과 적용을 연결한다.
5. 읽음/미해결/이력/갱신, 개인/일반/예시 콘텐츠 구분을 완성한다.
6. 변경 영역 검사 후 최종 통합 검수에서 UI·코어·저장·공개 동선을 함께 확인한다.

초안의 완료 경계는 홈 배치까지 포함한 구현계획이었다. 2026-09-29에는 홈/reader/일지 비교 코드와 4개 로컬 브라우저 시나리오까지 진행했다. 코칭 설명만으로 전체 계획의 교정·저장 단계를 완료로 표시하지 않는다.

현재 구현은 개인 비교 최근 2개와 추가 10개씩 열기, 일반 안내 2편, 원래 화면으로 복귀, 기존 여섯 분석 항목 유지다. 새 방문자에게 가짜 개인 교정 결과를 표시하지 않는다. 읽음/미해결 영속 상태, 교정 전후 달력, 실제 계정 수락은 남아 있다. 자세한 근거는 [구현 보고서](../implementation/PLAN_EXECUTION_COACHING_IMPLEMENTATION_2026-09-29.md)를 본다.
