## 1. 목표와 범위

선수가 훈련을 열면 무엇을 얼마나, 어느 정도로, 어떻게 쉬며 할지 바로 이해하고, 원하면 순서와 이유를 더 읽고, 같은 내용을 메모로 가져갈 수 있게 한다. 훈련 설명과 훈련 메모는 별도의 중복 콘텐츠가 아니라 같은 처방의 서로 다른 표시 방식이다.

- 포함: 첫 계획 결과, 홈의 훈련 진입, 날짜별 훈련, 달력 상세, 현재 계획 수정, 변경 전후 비교, 일지의 당시 처방, 수행 평가, 다음 계획 미리보기, 복사와 이미지 저장 및 공유.
- 제외: 새 훈련 종류, 처방 숫자 및 계산식 변경, 새로운 자동 증량, 코치 비교 엔진, 미니게임, 새로운 계정 저장 체계, 캐릭터 및 이미지 신규 제작.
- 기능은 삭제하지 않는다. 화면 역할에 맞게 위치와 강조를 바꾸고 이름 있는 경로를 유지한다.
- 중학생이 설명 없이 사용할 수 있는지를 사용성 목표로 삼되, 합성 검수로 실제 선수의 이해도를 입증했다고 표현하지 않는다.

## 2. 확정할 화면 구조

### 2.1 하루 훈련 읽기

위에서 아래로 다음 순서를 유지한다.

1. 날짜 이동과 오전/오후 선택. 선택한 세션 하나의 상세를 표시하고 다른 세션의 존재와 상태는 선택부에 남긴다.
2. 훈련 이름, 필요한 상태, `간단히 / 자세히` 선택.
3. 선택한 대분류의 두 하위 보기와 현재 표현 방식 `쉬운 말` 또는 `훈련 표기`. 표현 선택은 이름 있는 메뉴로 열며 꾸미기와 분리한다.
4. 메모 형태의 처방 본문. 본운동을 가장 먼저 알아보게 하고 반복·목표·회복의 역할을 분리한다.
5. 해당 화면의 주 행동. 일지 작성이 허용된 미기록 세션은 `이 훈련 일지 쓰기`, 연결된 기록이 있으면 `쓴 일지 보기`. 기존 적격성·안전 정책이 우선한다.
6. `페이스 확인`, `훈련 조절`, `메모 가져가기` 등 실제 가능한 보조 행동. 이미 제공되는 기능을 임의로 제거하지 않는다.

꾸미기·공유·이미지 저장은 기본 읽기 화면의 처방과 주 행동 사이에 두지 않는다. 기본 배경은 기존 중립 단색과 타이포 위계를 사용하고 노트 줄, 장식 그림, 반복 구분선을 깔지 않는다. 마리 등 기존 장식은 메모 꾸미기 안에 유지한다.

### 2.2 깊이와 표현은 독립적으로 선택

| 대분류 | 하위 보기 | 표시 내용 | 생략하지 않는 내용 |
|---|---|---|---|
| 간단히 | 핵심만 | 본운동·목표·반복·세트·회복을 압축한 행, 준비·정리의 짧은 요약 | 모든 필수 수행 수치, 회복 방식과 위치, 마지막 반복의 예외, 현재 경고 |
| 간단히 | 기본 | 본운동·목표·반복 사이·세트 사이를 각각 분리한 행, 준비·정리 요약 | 핵심만과 같은 처방 정보 |
| 자세히 | 방법 | 준비 → 본운동 → 정리의 실제 수행 순서와 구간별 목표 | 혼합 구간, 반복 범위, 회복 위치, 수행 제한 |
| 자세히 | 설명까지 | 방법과 동일한 처방 뒤에 목적·회복 이유·관찰할 점, 긴 출처는 펼침 | 검토된 설명의 적용 범위와 한계 |

- 최초 기본값은 `간단히 > 기본 > 쉬운 말`이다. 이전 선택이 있으면 같은 계정의 앱 세션 안에서 복원한다.
- 하위 보기 두 개만 해당 대분류 아래에 표시한다. 네 가지 보기와 두 표현 방식을 동시에 여섯 개의 큰 선택지로 나열하지 않는다.
- `핵심만`은 목표 행 병합만 하는 현재 방식에서 벗어나 반복되는 설명과 배치를 압축한다. 복잡한 혼합 훈련이 길어지는 것은 허용하며 숫자를 자르거나 구간을 누락해 짧게 만들지 않는다.
- 쉬운 말은 `200m마다 30.4초`, `반복 사이 2분 30초 걷기`처럼 단위와 행위를 명시한다. 훈련 표기는 같은 값으로 `@ 30.4s/200m`, `r150s Walk` 등을 사용한다.
- 반복 구조는 구조화된 구간에서 묶는다. 동일한 가속 달리기 네 번을 네 개의 긴 문장으로 펼치지 않는다. 서로 다른 목표·회복이 섞이면 억지로 하나의 반복으로 묶지 않는다.
- 운동 시간, 회복 시간, 준비·회복·정리를 포함한 총시간을 서로 바꾸어 표현하지 않는다. 시간형 훈련의 예상 거리를 필수 거리로 만들지 않는다.

## 3. 연결 화면별 역할

| 화면 | 먼저 보일 정보 | 주 행동과 상세 경로 | 넣지 않을 것 |
|---|---|---|---|
| 첫 계획 결과 | 기간·횟수·첫 훈련의 핵심 처방·필요한 상태 | 기존 계획 선택/적용, 날짜별 확인 | 모든 날짜의 메모 편집 도구 |
| 홈의 오늘/다음 훈련 | 실제 날짜·시간대·훈련 이름·핵심 목표 | 해당 날짜 상세로 이동 | 메모 저장 및 꾸미기 툴바 |
| 날짜별 훈련/달력 상세 | 선택 세션의 공통 리더 | 일지 또는 연결 기록, 페이스·수정·메모 경로 | 오전·오후 전체 상세의 연속 나열 |
| 변경 전후 검토 | 바뀐 필드의 이전 값 → 이후 값, 변경 날짜·제외 사유 | 명시적 적용, 필요할 때 전체 방법 | 양쪽에 복사·저장·공유를 각각 반복 |
| 일지/수행 평가 | 당시 목표 / 실제 기록 / 확인 가능한 차이 | 일지 수정 또는 적격한 다음 단계 | 과거 처방을 현재 PB로 다시 계산 |
| 다음 계획 | 새 계획의 날짜와 상태·변경 요약·대표 처방 | 기존 제안 검토/적용 | 이전 주기의 날짜·일차를 새 제목 아래 그대로 사용 |
| 메모 가져가기 | 선택 날짜·슬롯·보기·표현의 출력 미리보기 | 텍스트 복사, 이미지 저장, 공유 | 계정 저장 성공으로 오인할 `저장` 단독 표기 |

변경 비교는 모바일에서도 필드마다 이전 값과 이후 값을 함께 보여준다. 비교할 두 계획을 번갈아 넘겨 외워야 하는 구조로 만들지 않는다. 바뀌지 않은 준비·정리는 `전체 방법` 안에서 확인할 수 있게 한다.

적용 대상 호출부: `PlanCandidateOverview`, `PlanSchedulePreview`, `PlanDayReader`, `DetailedPrescriptionView`, `AdjustedPrescriptionV3`, `AdjustedJournalOriginalPlan`, `JournalOriginalPlan`, `OriginalTrainingMethod`, `ExecutionReview`, `HomeCoachingSummary`, 단일/다중 변경 검토 및 다음 계획 흐름. 상위 소비자인 `ActivePlan`, `PlanCandidates`, `GoalTrainingProgramFlow`, `DatedPlanPanel`, `RecommendationCalendar`, `JournalMonthCalendar`와 독립 메모 fixture도 함께 추적한다. 기존 V3/V4 호환 경로를 한쪽만 갱신하지 않는다.

## 4. 날짜와 처방 상태 계약

날짜·상태는 상위 제목에서 추측하지 않고 콘텐츠 모델에 전달한다. 과거 처방에 기본 `PREVIEW`가 붙는 구조를 없앤다. 날짜가 없는 합법적인 후보는 명시적인 미지정 상태로 표현하며 임의로 오늘 날짜를 채우지 않는다.

| 상황 | 날짜의 원본 | 상태 표현 | 보호 규칙 |
|---|---|---|---|
| 적용 전 후보 | 후보의 시작일과 실제 일정 | 계획안 | 적용 전임을 화면과 출력에서 구분 |
| 활성 계획 | 선택 계획의 날짜와 슬롯 | 계획한 훈련 | 실제 수행으로 표시하지 않음 |
| 과거 일지의 처방 | 연결된 당시 처방 스냅샷 | 당시 계획 | 현재 기록·카탈로그로 재계산하지 않음 |
| 변경 비교 | 현재 계획 날짜와 변경안 날짜 각각 | 현재 / 변경 후 | 이동된 날짜와 슬롯도 변경 필드로 표시 |
| 다음 주기 후보 | 새 주기의 날짜·일차 | 다음 계획안 | 이전 주기 날짜를 복사하지 않음 |
| 날짜 미지정 | 명시적 미지정 | 날짜 미지정 | 저장 이미지에도 누락 사실을 그대로 표시 |

- 날짜가 확인된 모든 호출에서 화면·복사·PNG의 날짜와 오전/오후가 일치해야 한다.
- 원본 연결 불명, 읽기 실패, 저장 대기·실패·충돌, 안전 확인 필요는 별도의 상태다. 단순한 계획안이나 기록 없음으로 대체하지 않는다.
- 표시 컨텍스트는 권한을 부여하지 않는다. `ACTIVE` 같은 표시값을 넘겨도 적용·수행 연결·내보내기 정책 검사를 우회할 수 없어야 한다.
- 통증 확인 뒤 읽기 전용 미리보기의 기존 제한을 유지한다. 내보내기 UI를 옮기면서 그 제한을 해제하지 않는다.
- 정상 상태 문구는 화면 맥락에서 한 번만 표시한다. 독립 이미지에는 날짜와 계획/당시 계획 구분을 반드시 포함한다.

## 5. 기준과 이유를 한 곳에서 설명

### 5.1 기준 표시

- 체감 강도 처방에 `기준: 체감 강도 기준 · 경기 기록 환산 아님`을 반복하지 않는다. 본문의 힘든 정도와 필요한 도움말로 설명한다.
- 실제 기록 환산, 목표 기록, 직접 지정, 예상값의 구분은 숫자 근처의 짧은 표시로 남긴다. 오래된 기록·출처 불명·적용 제한은 숨기지 않는다.
- 사용한 원본 기록, 달성일, 공식, 버전, 선택 사유는 `페이스 기준`에서 확인한다. 페이스 도구와 기준 변경 기능도 이 경로에서 발견 가능해야 한다.
- 계획 결과·날짜 상세·일지 당시 처방·메모 출력이 같은 표시 정책을 사용한다. 문자열을 각 화면에서 별도로 제거하지 않는다.

### 5.2 이유와 설명

- 저장된 검토 설명을 우선하고, 없으면 검증된 카탈로그 설명, 그마저 없으면 공통 목적 설명으로 구분한다. 공통 설명을 개인 분석이나 검토된 조정 이유로 표현하지 않는다.
- 설명이 실제로 없는 경우와 원본 조회·버전 검증에 실패한 경우를 구분한다. 후자는 공통 설명으로 덮지 않고 확인하지 못한 상태와 가능한 재시도 경로를 남긴다.
- 메모의 `설명까지`와 별도 `방법과 근거`가 같은 긴 본문을 이중으로 만들지 않는다. 하나의 설명 모델과 출처를 사용한다.
- 읽기 화면의 이유 진입은 같은 설명 영역을 열도록 한다. 메모 출력 역시 같은 모델을 사용하되 외부 공개 가능한 출처만 포함한다.
- 당시 처방은 저장된 설명 버전과 근거를 따른다. 지금 카탈로그의 최신 설명으로 과거 의미를 조용히 바꾸지 않는다.
- 늦은 수행이나 높은 RPE를 근거로 특정 생리학적 능력 부족을 새로 단정하지 않는다. 실제 수행이 없으면 차이를 계산하지 않는다.

## 6. 메모 내보내기와 꾸미기

- `메모 가져가기`는 기존 시트/확장 패턴 중 현재 앱의 접근 가능한 구성요소를 재사용한다. 별도 전체 화면 편집기를 새로 만들지 않는다.
- 읽던 보기·표현으로 미리보기를 시작한다. 내보내기에서 바꾼 보기와 꾸미기는 출력 초안에만 반영하고, 닫으면 원래 읽기 설정과 위치로 복귀한다.
- 버튼 이름은 `텍스트 복사`, `이미지 저장`, `공유`로 구분한다. 이미지 생성 성공과 실제 기기 저장 완료를 혼동하는 성공 문구를 쓰지 않는다.
- 꾸미기는 출력 미리보기 아래 `꾸미기`에 모은다. 스티커·종이색·이미지 테마가 실제 처방 수치나 일지 원본에 영향을 주지 않는다.
- 핵심·기본 출력에도 필수 반복·세트·목표·회복·준비·정리·현재 주의 정보가 남는다. 긴 혼합 훈련과 설명은 기존 안전한 출력 한도 안에서 내용에 맞게 이미지 높이를 늘리고 글자를 작게 눌러 넣거나 자르지 않는다. 한도를 초과하면 텍스트 복사 경로를 제공한다. 새로운 다중 이미지 편집기는 이번 범위에 넣지 않는다.
- 이미지에는 해당 처방과 공개 가능한 근거만 담는다. 일지 원문·비밀 글·통증 부위·계정 정보는 포함하지 않는다. 썸네일/캔버스 등 다른 출력 경로에도 같은 필터를 적용한다.
- 생성 실패·공유 취소·클립보드 불가를 구분한다. 취소는 저장 성공이 아니다. 중복 클릭과 진행 중 계정/날짜 전환에서는 기존 취소·소유권 검사를 유지한다.

## 7. 구현 구조와 설정 수명

새 처방 엔진이나 범용 UI 프레임워크를 만들지 않는다. 기존 모델·포맷터·컴포넌트를 다음 책임으로 정리한다.

| 기존 위치 | 맡길 책임 |
|---|---|
| `workout-memo.ts` 및 처방 어댑터 | 구조화된 처방·날짜·슬롯·상태·출처·설명 연결. 숫자 계산의 원본은 기존 엔진 |
| `workout-memo-presentation.ts`, `workout-notation.ts` | 깊이·쉬운 말/훈련 표기·반복 묶기·시간 포맷. 문자열 역파싱 금지 |
| `WorkoutMemoSheet` | 행동 버튼 없는 공통 읽기/출력 표면. 출력용 장식은 명시적인 옵션 |
| `WorkoutMemoTool` | 내보내기 초안·꾸미기·복사/PNG/공유. 기본 리더에 도구 전체를 삽입하지 않음 |
| 각 화면 컨테이너 | 날짜/상태 제공, 일지·적용·수정 등 해당 화면의 주 행동 |
| 기존 계정 범위 UI 상태 계층 | 읽기 깊이·표현 유지, 날짜/스크롤/포커스 복귀와 분리 |

- 깊이·표현은 날짜 이동, 오전/오후 전환, 상세 닫기·재진입 중 유지한다. 앱 재실행·다른 기기 동기화는 이번 범위에 포함하지 않는다.
- 계정 전환·로그아웃에서는 이전 계정의 선택이나 내보내기 초안이 새 사용자에게 넘어가지 않는다. 선택 기억에 일지 원문이나 처방 데이터를 복제해 보관하지 않는다.
- 컴포넌트의 날짜별 `key`를 무조건 지워 설정 문제를 해결하지 않는다. 기존 날짜 전환 애니메이션·포커스 계약을 유지하고 설정 상태를 적절한 상위 계층으로 옮긴다.
- 혼합 훈련의 구간별 페이스 기준을 하나로 덮지 않는다. 새 보기 선택이 처방·계획·완료 상태를 저장하거나 변경하지 않는다.
- 불완전한 구형 처방에는 짧은 미정 상태와 실제 필요한 주의를 보여준다. 총시간을 본운동 시간으로 가정하거나 없는 회복을 발명하지 않는다.

## 8. 반응형과 접근성 인수 기준

- 320px·360px·넓은 화면, 200% 글자 확대에서 숫자·단위·날짜·선택·주 행동이 잘리지 않는다. 가로 페이지 넘침을 만들지 않는다.
- 짧은 단일 훈련은 정상 글자 크기에서 핵심과 다음 행동이 한눈에 들어오게 한다. 긴 훈련·확대에서는 자연스러운 세로 스크롤을 허용하며 고정 높이로 내용을 숨기지 않는다.
- 터치 영역 44px 이상, 기존 대비와 포커스 토큰, Lucide 아이콘을 유지한다. 선택은 색 외에 명칭·선택 상태로도 구분한다.
- 날짜 이동·시트 열고 닫기·보기 전환 후 키보드 초점이 유실되지 않는다. 내보내기에서 돌아오면 열었던 버튼과 읽던 위치를 복원한다.
- 숫자 입력 중 자동 정렬하지 않는다. 기존 명시적 날짜 이동 정렬은 사용자가 스크롤/터치하면 중단되고 reduced-motion에서도 동일한 기능을 제공한다.
- 결과 안내는 날짜와 선택 세션 등 바뀐 부분만 짧게 읽는다. 전체 처방과 도구 목록을 매번 화면낭독기로 반복하지 않는다.
- 꾸미기와 메모를 쓰지 않아도 훈련 확인 → 일지 작성 → 기록 확인 → 적격한 다음 계획 흐름이 완결돼야 한다.

## 9. 단계별 작업과 통합 순서

| 단계 | 작업 | 완료 조건 |
|---|---|---|
| 0 | 최신 기준과 호출부 목록 확정, 기존 실패를 제품/검사/환경으로 분류 | 현재 변경과 담당 파일 확인, 9개 발견 사항을 회귀 항목에 연결 |
| 1 | 날짜·슬롯·상태 명시, 과거/변경/다음 주기 어댑터 정리 | 과거가 PREVIEW로 나오지 않고 내보내기까지 날짜·상태 일치 |
| 2 | 순수 읽기 표면과 내보내기 행동 분리, 화면별 주 행동 배치 | 일지·적용 버튼이 메모 도구에 밀리지 않고 기능 진입 경로 유지 |
| 3 | 네 깊이·두 표현, 반복 묶기, 계정 범위 읽기 설정 | 핵심/기본/방법/설명의 차이가 실제이며 날짜 이동 후 유지 |
| 4 | 기준·설명 정책 공통화, 복사·PNG 일치, 구형 처방 처리 | 중복 기준·설명 제거, 출처·상태·필수 수치 보존 |
| 5 | 영향받은 계약·여정·반응형 검사 복구, 최종 diff 검토 | 필요한 검사가 실행됐고 실패를 숨기지 않음 |
| 6 | 승인된 통합/배포 절차와 공개 화면 점검 | 배포 revision과 공개 변경 흐름 확인. 실계정·선수 사용 증거는 별도 보고 |

단계 1의 컨텍스트와 단계 2의 컴포넌트 경계는 한 통합 담당자가 결정한다. 독립 작업을 나눌 때는 포맷터/계약 검사, 화면 적용, 내보내기·반응형 검사로 소유권을 나누고 같은 공통 파일을 동시에 고치지 않는다. 작업자 수나 모델 변경 자체를 완료 조건으로 삼지 않는다.

| R13 | 이미지 실패, 공유 취소, 복사 불가, 중복 클릭 | 초안 보존, 정확한 상태, 성공 오표시 없음 |

자동 검수는 기존 유지되는 명령과 프로젝트 필수 관문을 사용한다. CSS 클래스에만 의존하던 검사는 사용자 역할·라벨·날짜·실제 수치 중심으로 고치되, 의미 있는 수치·회복·연결 검증을 삭제하지 않는다. 안전·저장·출력 경계에는 잘못된 컨텍스트나 거부 상태에서 실제로 닫히는 대조 검사를 둔다.

합성 여정은 처음 쓰는 중학생, 훈련 표기에 익숙한 선수, 오전/오후 사용자, 과거 기록 확인 사용자, 계획 수정 사용자, 확대/키보드 사용자 관점으로 R01~R16을 묶는다. 실제 사람 수로 보고하지 않는다. 실제 선수와의 무설명 사용에서는 '할 훈련과 회복을 말할 수 있는가', '저장을 일지 저장으로 오해하는가', '날짜를 바꾸고 돌아올 수 있는가'를 관찰하며 소요 시간과 멈칫한 위치를 기록한다. 이 실사용 확인은 자동 검수와 구분한다.

## 11. 완료와 배포 판정

- 기능 완료: 관련 화면에 남은 중복 훈련 설명·상태 기본값 오류·보기 설정 초기화가 없고, 모든 기존 기능에 이름 있는 접근 경로가 있다.
- 내용 완료: 네 보기와 두 표현에서 같은 처방을 읽고, 날짜·구간·회복·근거·과거 스냅샷이 보존된다. 설명이 부족한 구형 자료는 부족함을 정직하게 표시한다.
- 검수 완료: 변경된 공통 모델의 계약 검사와 영향받은 홈/달력/기록/다음 주기 여정, 반응형 검사가 실행돼 통과한다. 조기 중단으로 미실행된 검사를 통과로 세지 않는다.
- 통합 완료: 최신 관련 변경과 충돌을 해결하고 프로젝트의 현재 필수 관문을 만족한다. 다른 작업자의 변경과 생성 자료를 무단으로 포함하지 않는다.
- 공개 완료: 승인된 배포 경로에서 실제 revision과 공개 핵심 흐름을 확인한다. 푸시·빌드·공개 배포를 같은 완료로 합치지 않는다.
- 실사용 확인: 로그인 계정 저장 왕복, 실제 iPhone 공유, 선수 무설명 사용 중 미실행 항목을 별도로 남긴다. 자동 검사만으로 사용 피로가 해소됐다고 확정하지 않는다.
