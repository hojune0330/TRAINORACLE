# TrainOracle 탐색·훈련 분석·반복 사용 최종 계획

작성일: 2026-09-20
문서 상태: 최종 UX 실행 계획. 구현·배포 완료를 의미하지 않는다.
확인한 소스 기준: `83211de5943365cdcfb7798c01548fb91d62661e`
로컬 브랜치: `main` (PR·원격 상태는 이번 계획 작업에서 조회하지 않음)
현재 지시: 모든 사용자가 작은 클릭으로 기능과 결과를 경험하고, 개인 분석·추가 기록·지속 참여로 자연스럽게 이어지도록 최종 계획을 확정한다.

이 문서는 [앞선 UX 검토](../review/TRAINORACLE_ANALYSIS_CORE_UX_REVIEW_2026-09-20.md)의 탐색·홈·재방문 설계를 갱신한다. 이전 시안의 사용자 유형 선택 버튼은 기능을 둘러보게 만드는 효과를 설명한 참고이며, 실제 제품에 `첫 방문 / 자주 기록 / 오랜만에 방문`을 고객용 메뉴로 복제하지 않는다.

훈련·안전·개인정보·보상 계약은 유지한다. 본 계획은 새로운 생리학적 지표, 처방 수치, 출석 보상 금액, 계정 권한, 외부 원문 전송을 승인하지 않는다. 기존 계획 생성 재설계 문서와 다른 작업자의 변경을 덮어쓰지 않는다.

## 1. 최종 결정

**누구나 모든 주제를 둘러볼 수 있게 한다. 클릭 하나마다 결과 하나를 먼저 제공하고, 그 결과를 내 기록으로 확인하고 싶게 만든다.**

핵심 제품 약속은 그대로다: 내 훈련의 현재 수준과 보완할 점을 알고, 다음에 할 훈련을 정한다.

앞선 제안에서 달라지는 점:

1. 사용자 유형별로 기능을 나누거나 감추지 않는다. 공통 탐색 입구는 누구에게나 동일하게 제공한다.
2. 개인화는 첫 추천, 페이지 안의 결과, 이어서 할 행동에 적용한다. 주요 메뉴 위치는 예측 가능하게 유지한다.
3. 데이터가 없어도 체험은 완결된다. 단순 빈 화면·회색 잠금·준비 중 안내만으로 페이지를 끝내지 않는다.
4. 모든 페이지 방문을 의무로 만들지 않는다. 어느 주제에서 시작해도 하나의 답을 얻을 수 있고, 관심이 생기면 다음으로 이어간다.
5. 기록은 결과를 보기 위한 막연한 숙제가 아니라, 사용자가 선택한 질문에 답하기 위한 투자로 제시한다.
6. 반복 사용의 보상은 더 많이 클릭했다는 사실보다 새로 이해한 것, 실제로 확인한 변화, 다음 훈련에 적용한 내용이다.

사용 경험의 기본 순서는 `궁금한 주제 선택 → 즉시 결과·예시 확인 → 내 기록으로 확인하고 싶음 → 필요한 입력 → 개인 결과 → 우선 훈련 → 수행·휴식 기록 → 변화 확인`이다. 이 순서는 강제 온보딩이 아니며 중간 진입·건너뛰기·복귀를 허용한다.

## 2. 누구나 열어볼 수 있는 여섯 가지 주제

홈에는 한 개의 추천 결과와, 여섯 개의 짧은 탐색 입구를 둔다. 모바일은 읽을 수 있는 2열 구성이 기본이며 글자 확대 시 1열로 전환한다. 모든 상세 내용을 홈에 펼치지 않는다.

| 주제 | 클릭 전에 생기는 질문 | 클릭 직후 제공할 내용 | 자연스러운 다음 행동 |
|---|---|---|---|
| 현재 수준 | 현재 기록을 어떻게 봐야 할까? | 종목·거리·날짜에 맞춘 수행 기록의 해석 또는 명시적인 결과 예시 | 내 종목·최근 기록으로 보기 |
| 강점·보완점 | 잘하는 점과 먼저 고칠 점은? | 근거가 있는 잘한 점과 우선 보완점. 근거가 없으면 평가 예시와 필요한 자료 | 해당 근거 보기 또는 필요한 항목 추가 |
| 훈련 비교 | 지난번과 무엇이 달라졌을까? | 비교 가능한 구간·강도·수행 차이를 보여주는 간단한 비교 | 내 훈련 두 개로 비교 |
| 훈련 구성 | 어떤 종류의 훈련에 치우쳤을까? | 실제로 기록한 종류별 횟수·시간·거리. 구성과 신체 능력은 구분 | 내 기록 보기 또는 관련 훈련 설명 |
| 우선 훈련 | 지금 무엇부터 해야 할까? | 검토된 기준에 따른 훈련 선택 이유와 구성, 또는 명시적인 구성 예시 | 내 조건 확인 후 계획에 적용 |
| 훈련 후 변화 | 이 훈련을 하고 무엇이 달라졌을까? | 같은 기준의 전후 비교 또는 재평가 예시. 아직 후속 자료가 없으면 비교할 항목 | 다음 비교 항목 저장·후속 기록 연결 |

주제 이름은 고정하고 카드 안의 짧은 예고만 자료에 맞게 바꾼다. 사주·운세·궁합·MBTI식 유형·`오늘의 흐름` 같은 추상적인 이름은 사용하지 않는다. 근거 없는 백분위·등급·단일 체력 점수로 `현재 수준`을 채우지 않는다.

`훈련 배우기`와 `일지 꾸미기`는 홈에서 계속 접근 가능하게 둔다. 여섯 분석 주제와 경쟁하는 큰 카드로 늘리지 않고 짧은 별도 진입으로 유지한다. 하단은 `홈 / 일지 / 기록하기 / 계획 / 분석`을 유지한다.

## 3. 클릭 한 번의 완성 기준

각 주제 페이지는 다음 계약을 따른다.

1. 첫 화면에서 제목이 약속한 질문에 답한다. 답 대신 로그인·긴 설문·기능 소개만 제시하지 않는다.
2. 핵심 결과 한 문장과 이를 설명하는 시각 자료 하나 또는 짧은 비교를 제공한다.
3. 실제 결과인지 예시인지, 어느 기간·자료인지 즉시 구별할 수 있다.
4. 이어지는 행동은 가장 관련 있는 하나를 주 행동으로, 필요할 때만 다른 주제 하나를 보조 행동으로 둔다.
5. `다음`·`자세히`보다 `내 기록으로 비교`·`이 훈련을 고른 이유`처럼 얻는 내용을 버튼에 적는다.
6. 같은 답을 여러 페이지로 잘게 찢지 않는다. 다음 화면은 새로운 질문이나 깊이를 제공할 때만 만든다.
7. 실제 계산이 없는데 분석 중 애니메이션을 연출하지 않는다. 짧은 전환과 피드백은 사용하되 모션 감소 설정을 지킨다.

핵심은 미끼를 계속 미루는 것이 아니라, 방금 생긴 궁금증을 먼저 충족시키는 것이다. 자세히 읽고 싶어진 뒤 설명이 펼쳐지게 하며, 언제든 그만 보거나 다른 주제로 갈 수 있다.

## 4. 자료가 없는 사용자도 경험을 끝낼 수 있게 한다

### 예시 체험

- 각 주제마다 완결된 예시 결과를 준비한다. 그래프 조각이나 흐린 미리보기만 보여주지 않는다.
- 페이지 제목 근처에 `예시 기록`을 계속 표시한다. 예시 화면에서 사용자를 지칭하는 `당신의 약점` 같은 문구를 쓰지 않는다.
- 필요할 때 `초반이 빠른 기록 / 페이스를 일정하게 유지한 기록`처럼 실제 수행 차이를 보여주는 소수의 예시를 선택할 수 있게 한다. 임의의 성격 유형을 부여하지 않는다.
- 예시에서 `내 기록으로 보기`를 선택하면, 바로 전에 본 질문을 해결하는 데 필요한 입력만 요청한다.
- 예시 숫자는 개인 차트·일지·계획·출석·보상·분석 자료 수에 절대 합산하지 않는다. 예시 체험이 운동 수행으로 저장되지 않는다.
- 로그인·기기 연결을 둘러보기의 조건으로 삼지 않는다. 실제 저장·연동이 필요해지는 지점에서는 기존 권한·보관 정책을 정확하게 따른다.

### 실제 기능의 준비 여부도 구분

예시가 존재한다고 내 기록 분석도 구현됐다고 표시하지 않는다. 주제마다 `내 자료로 분석 가능 / 예시 체험만 가능 / 설명 콘텐츠`를 구분한다.

개인 분석이 아직 없는 주제는 `결과 예시`와 `내 기록 분석은 준비 중`을 함께 표시하되, 실제로 읽고 조작할 수 있는 예시를 제공한다. 지원하지 않는 기능을 위해 개인자료 입력·연동을 요구하지 않는다. `준비 중`만 있는 빈 페이지를 여섯 개 만드는 것은 본 계획의 완료가 아니다.

## 5. 개인 데이터 상태에 따른 동작

| 상태 | 기본 표시 | 이어지는 행동 | 금지할 오해 |
|---|---|---|---|
| 자료 없음 | 명확히 표시한 완결된 예시 | 지원되는 경우 내 기록으로 전환 | 예시가 내 평가인 것처럼 보이기 |
| 자료 일부 | 확인 가능한 내 결과, 나머지는 확인할 항목 | 선택한 질문에 필요한 최소 항목만 추가 | 빈칸을 샘플·0·추정 점수로 채우기 |
| 분석에 적합한 자료 | 실제 결론·근거·기간·출처 | 우선 훈련 또는 비교 상세 | 자료 수만으로 정확도가 보장된다는 주장 |
| 오래된 자료 | 당시 날짜와 과거 결과 | 최근 운동 반영 또는 예시 둘러보기 | 과거 평가를 현재 몸 상태로 표시 |
| 비교 조건 부적합 | 각각의 실제 기록과 비교가 어려운 이유 | 가능한 비교 또는 다른 주제 | 서로 다른 조건을 억지로 개선·악화 판정 |
| 오류·전송 대기 | 실제 처리 상태와 마지막 정상 결과가 있다면 그 결과 | 재시도·보존된 초안·예시 체험 | 오류를 자료 없음이나 분석 완료로 처리 |

내 결과와 예시 모드는 페이지 단위로 분명히 구분한다. 내 결과 안에 가상 수치를 섞지 않는다. 이전 화면·선택한 주제·입력값은 뒤로가기와 복귀 때 유지한다. 학습 경로나 예시 열람은 저장 동의·계획 확정·공유를 자동 실행하는 권한이 아니다.

## 6. 입력의 깊이는 관심이 생긴 뒤 늘린다

- 첫 탐색은 입력 없이 가능하다.
- 첫 개인화에서는 현재 선택한 질문에 필요한 자료만 받는다. 예: 수행 기록 해석에 종목·기록·날짜가 필요하다면 그 자료부터 받는다.
- 빠른 운동 기록은 기존 짧은 경로를 유지한다. 추가 비교를 선택했을 때만 구간·조건 등 필요한 항목을 안내한다.
- `더 입력하면 정확해져요` 대신 `구간 기록을 넣으면 후반 페이스를 볼 수 있어요`처럼 실제 기능상의 이득을 설명한다.
- 이미 받은 답변은 재사용한다. 사실 질문에 추천 답변을 붙이지 않는다. 자동 완성된 사실은 사용자가 확인할 수 있어야 한다.
- 필드가 많을 때는 필요한 그룹 단위로 받는다. 체류시간을 늘리려고 모든 필드를 한 화면씩 쪼개지 않는다.
- 처방에 필요한 현재 몸 상태·적격성 확인은 결과를 빨리 보여주기 위해 생략하지 않는다. 답변을 건너뛰면 안전에 영향을 받지 않는 체험·열람만 계속 제공한다.

## 7. 계속 돌아오고 싶은 이유를 만든다

| 계기 | 즉시 얻는 보상 | 다음에 기대할 수 있는 것 |
|---|---|---|
| 첫 탐색 | 어떤 결과를 받을 수 있는지 실제로 이해 | 같은 질문을 내 기록으로 확인 |
| 첫 기록 | 내 운동이 읽기 쉬운 한 장으로 정리됨 | 조건이 맞는 기록과 비교 |
| 비교 가능한 기록 추가 | 지난번과 다른 부분을 직접 확인 | 보완할 훈련의 근거 |
| 우선 훈련 선택 | 왜 해야 하는지와 어떻게 할지 명확해짐 | 수행 후 확인할 항목 |
| 훈련 후 기록 | 계획과 실제 수행의 차이 확인 | 동일 조건에서의 변화 확인 |
| 쉬는 날 방문 | 계획 확인·일정 조정·검토된 짧은 훈련 설명 | 다음 운동을 준비한 상태 |
| 한동안 쉬었다 복귀 | 이전 관심 주제와 지난 결과를 즉시 재개 | 최근 운동을 반영한 현재 분석 |

기록이 늘었는데 모든 결과가 같은 수준에 머물러서는 안 된다. 다만 깊어지는 조건은 임의의 `출석 3일`·`기록 5개`가 아니라 각 분석에 실제로 필요한 자료와 비교 적격성이다.

새 자료나 새로 계산할 근거가 없으면 매일 새로운 개인 분석을 발명하지 않는다. 그날의 볼거리는 관심을 표시한 다른 주제, 아직 읽지 않은 검토된 설명, 다음 계획 준비로 전환한다. 가능한 내용이 끝났다면 끝났다고 알린다. 무한 피드를 추가하지 않는다.

관심 주제를 `다음에 볼 항목`으로 보관할 수 있게 하고 재방문 시 이어준다. 이미 읽은 예시는 매번 새 발견으로 표시하지 않는다. 개인 분석의 `업데이트됨` 표시는 실제 자료·평가 결과 변경과 연결한다.

## 8. 연속 참여: 동기는 주되 운동량과 분리

연속 참여를 원하는 사용자에게 선택형으로 제공한다. 본체는 분석과 훈련이지 출석 도장이 아니다.

- 사용자에게 맞는 참여 요일을 선택할 수 있게 한다. 매일 참여를 원하면 그 선택도 지원한다.
- 훈련 기록, 휴식 기록, 다음 훈련 확인 같은 의미 있는 행동을 참여로 인정할 수 있다. 앱을 열기만 하거나 같은 버튼을 반복 누르는 것을 가치 있는 참여로 간주하지 않는다.
- `연속 참여`와 `누적 참여`를 구분한다. 쉬었다고 이전 성취·일지·분석을 삭제하거나 접근권을 회수하지 않는다.
- 쉬는 날 참여를 위해 운동을 더 하게 만들지 않는다. 안전 안내·휴식·검토가 필요한 상황이 연속 참여보다 항상 우선한다.
- 핵심 분석은 출석으로 잠그지 않는다. 가짜 마감, 벌점, 보상 상실 경고, 무작위 보상으로 반복 접속을 압박하지 않는다.
- 기본 보상은 이해·준비·실제 변화의 확인이다. 소규모 성취 표시는 가능하지만 출석을 신체 능력 점수로 표시하지 않는다.
- 포인트·꾸미기 지급은 기존 계약을 유지한다. 이 문서를 근거로 새로운 지급량이나 분석 권한을 만들지 않는다.
- 알림은 별도 선택과 설정을 따른다. 사용자가 고른 시간·목적에만 연결하고, 미접속 자체를 불안하게 만드는 문구는 사용하지 않는다.

연속 참여와 훈련 수행 완료는 별도 상태로 저장한다. 날짜 경계·중복 인정·휴식·누적 성취 처리 기준은 이 기능 구현 시 명시하되, 현재 보상 체계를 조용히 변경하지 않는다.

## 9. 신뢰와 과학성

결과의 강도는 관찰과 판정의 범위에 맞춘다. 명료함을 포기하지 않되, 모르는 원인을 아는 것처럼 말하지 않는다.

- 단일 수행의 관찰, 반복되는 수행 특성, 원인 가설, 훈련 추천을 분리한다.
- 훈련 목적 빈도를 신체 능력 분포로 바꾸지 않는다. 근거 없는 레이더 차트·정밀 점수·개인 신뢰도 퍼센트를 만들지 않는다.
- 후반 감속을 관찰했다고 심폐·근력·회복 부족을 바로 확정하지 않는다.
- 우선 훈련은 검토된 추천 기준, 현재 적격한 입력, 안전 확인을 거쳐 제시한다. 기존 허용 종목·템플릿을 확대하지 않는다.
- 미래 성과를 보장하지 않는다. 다음 훈련 뒤 어떤 조건에서 무엇을 다시 확인할지 제시한다.
- 결과를 바꿀 수 있는 중요한 제한은 바로 옆에 짧게 표시한다. 긴 방법론만 접는다.
- 원문 메모·비밀 글을 체험 개인화나 외부 모델 입력으로 전환하지 않는다. 이벤트 수집에도 원문·증상·훈련 원자료를 넣지 않는다.

현행 UI 규칙의 서술형 분석 범위와 새 평가형 기능의 경계는 구현 시 함께 정리해야 한다. 이번 UX 계획만으로 초안 수식·예측 모델·처방 규칙이 자동 채택되지는 않는다. 안전을 이유로 평가·처방 본체를 영구히 빼는 것이 아니라, 기준과 보호 장치를 갖춘 분석 과제부터 완성한다.

## 10. 화면·기술 연결 범위

| 영역 | 작업 | 유지할 것 |
|---|---|---|
| 홈 | 모두에게 열린 여섯 주제, 추천 결과 하나, 관심 주제 재개 | 빠른 기록 접근, 기존 하단 탭, 안전 안내 |
| 분석 | 주제별 결과, 예시/내 결과 분리, 자료 상태별 다음 행동 | 출처·기간·미기록 처리·접근 가능한 표 |
| 기록 저장 후 | 저장 완료와 새로 확인 가능한 점, 해당 기록으로 이동 | 저장 상태 사실성, 추가 작성·수정 |
| 일지 상세 | 선택한 훈련의 분석·다음 훈련으로 이어지는 출구 | 하루 묶음·펼치기·꾸미기 |
| 계획 | 선택한 분석 과제를 유지한 처방, 다음 평가 항목 연결 | 현재 안전 게이트·적격성·원래 계획과 실제 수행 구분 |
| 반복 참여 | 관심 주제 이어보기, 실제 업데이트 표시, 선택형 참여 기록 | 운동 완료와 분리, 기존 보상·알림 권한 |

구현에는 주제 ID, 결과 모드, 데이터 적격 상태, 원본 기록 ID, 기간, 진입 원점, 다음 행동을 전달하는 공통 경로가 필요하다. 날짜·지표가 있는 버튼이 일반 분석 탭 첫 화면으로만 이동해서는 안 된다.

공통 주제 정의에는 실제 지원 상태와 예시 자료를 함께 관리한다. 예시 자료는 별도 읽기 전용 자료로 두고 개인 집계·개인 저장 함수에 전달하지 않는다. 화면 상태가 바뀌어도 이 구분이 유지되어야 한다.

색·폰트·여백은 기존 제품 기준을 따른다. 검색 도구의 일반적인 다색·대형 블록·다른 폰트 추천은 채택하지 않는다. 작은 클릭은 작은 글자나 좁은 터치 영역을 뜻하지 않는다. 44px 접근 영역, 읽기 좋은 본문, 하단 여백, 글자 확대, 뒤로가기 복원을 지킨다.

## 11. 구현 순서와 병렬 작업

### 1차 — 누구나 체험할 수 있는 입구와 결과

- 공통 주제 목록·지원 상태·예시/실제 모드 계약을 먼저 정의한다.
- 홈의 여섯 입구와 각 주제의 완결된 예시를 만든다.
- 현재 계산 가능한 내 자료 결과를 같은 경로에 연결한다.
- 사용자 유형별 메뉴 잠금, 빈 화면 막다른 길, 강제 가입 없이 탐색을 끝낼 수 있게 한다.

### 2차 — 체험에서 개인 분석과 훈련까지

- 선택한 질문에 필요한 입력, 답변 재사용, 기록 저장 후 관련 분석 진입을 연결한다.
- 검토된 평가 과제 하나를 `수행 비교 → 보완점 → 우선 훈련 → 실제 기록 → 재평가`까지 완성한다.
- 아직 판정기가 없는 주제는 지원 상태를 정직하게 유지한다. 문구만 바꿔 완료로 처리하지 않는다.

### 3차 — 다음 방문을 이어주는 기능

- 관심 주제 재개, 실제 변경점 표시, 다음 비교 항목을 연결한다.
- 본체가 작동한 다음 선택형 연속·누적 참여를 붙인다.
- 기존 꾸미기·학습을 관련 상황에 연결하되 포인트 시스템을 확장하지 않는다.

병렬 분업: A는 탐색·결과 화면, B는 예시 콘텐츠와 지원 상태 정의, C는 평가·추천 기준과 기존 적격 분석 연결을 맡긴다. 공통 상태 계약을 먼저 합의하고 동일 파일 동시 수정을 피한다. 간단한 문구·문서·정적 UI 작업은 낮은 비용의 모델에, 과학적 판단·안전·자료 경계는 별도 신중한 검토에 배정한다. 코드가 합쳐진 뒤 필요한 연결 경로만 확인한다.

## 12. 완료 기준과 최소 확인

기능 완료 기준:

1. 자료 없는 사용자도 여섯 주제를 모두 열고 각각 약속한 결과의 예시를 볼 수 있다.
2. 실제 결과와 예시를 혼동하지 않으며, 예시가 개인 기록·분석·계획·보상에 섞이지 않는다.
3. 각 주제의 첫 화면에 답이 있고, 관련 없는 질문지나 또 다른 예고만 반복되지 않는다.
4. 지원되는 개인 분석은 해당 질문의 입력·결과·다음 행동까지 이어진다. 지원하지 않는 기능은 개인자료를 요구하지 않는다.
5. 자주 기록하는 사람의 기존 빠른 작성 경로가 길어지지 않는다.
6. 복귀 사용자는 이전 결과의 날짜와 마지막 관심 주제를 확인하고 바로 이어간다.
7. 참여 기록 때문에 휴식을 포기하거나 추가 운동을 해야 할 이유가 없다.
8. 기존 안전·저장·접근성·뒤로가기 동작을 깨지 않는다.

후속 구현 검증은 변경된 범위에 한정한다: 여섯 주제의 목적지 연결, 예시/실제 격리, 자료 없음·일부·유효·오래됨·오류의 대표 상태, 저장 후 해당 기록 이동, 선택/초안 복원, 375px와 글자 확대 시 잘림 여부. 처방을 연결한 부분에만 해당 안전·적격성 검사를 적용한다. 불필요한 전체 회귀·반복 시연은 요청하지 않는다.

제품 효과는 아직 가설이다. 확인할 지표는 첫 결과 도달, 체험 후 자발적인 내 기록 전환, 결과 이해, 우선 훈련 선택, 후속 비교 재방문이다. 클릭 수·체류시간만으로 성공을 판단하지 않는다. 입력 이탈, 예시를 내 결과로 오인한 비율, 빠른 기록 시간, 알림 해제·휴식일 압박도 함께 본다. 실제 운영 근거 없이 목표 전환율·보장 효과를 만들지 않는다. 측정 추가는 기존 동의·개인정보 정책 범위에서 별도 적용한다.

## 13. 인수인계와 이번 작업의 종료 상태

- 완료: 공통 탐색 중심 최종 계획, 데이터 상태별 행동, 예시와 개인 결과 분리, 반복 참여 방식, 과학성 경계, 구현 순서와 최소 완료 기준.
- 이번 변경: 이 최종 계획 추가와 앞선 검토 문서의 후속 계획 링크. 앱 소스·시안·보상·도메인 계약은 변경하지 않았다.
- 확인: 현재 로컬 HEAD·변경 목록, 상위 제품/시각 기준, 앞선 검토 문서를 확인했다. 두 독립 관점에서 탐색 보상과 신뢰·피로 경계를 검토했다. 실제 사용자 연구나 전환율 실험은 아니다.
- 실행하지 않음: 앱 테스트·새 브라우저 검수·커밋·푸시·배포·PR/CI 재검사·운영 자료 조회. 외부 상태를 현재라고 주장하지 않는다.
- 기존 변경 보존: 다른 작업의 이미지와 계획 문서를 수정·정리하지 않는다.
- 다음 실행 작업: 주제 목록과 `예시/실제 결과/지원 상태` 공통 계약을 만든 뒤 1차 홈·체험 화면을 구현한다. 병행하여 첫 평가·추천 과제의 기존 기준과 미채택 범위를 확인한다.
- 계획 단계의 추가 선택 요청은 없다. 구현에서 신규 도메인 기준·권한이 필요하면 그 범위만 따로 명시한다.

이번 요청은 최종 계획 작성으로 종료한다. 구현이나 모니터링이 백그라운드에서 계속되는 것은 아니다.
