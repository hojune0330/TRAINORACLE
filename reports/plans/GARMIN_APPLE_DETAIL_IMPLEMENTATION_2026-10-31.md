# Garmin · Apple 데이터 상세 역설계와 구현 명세

- 작성: 2026-10-31 KST
- 기준 코드: `f6d19aef9cb0635aee77a42c93e97ea8ddc41a36` (PR #375 포함)
- 상태: **구현 준비 명세 + 기존 파일 관측 상세의 로컬 구현 후보**
- 오너 요청: 제공자 화면에서 확인하던 필수 세부 항목과 조작을 TrainOracle에서도 잃지 않도록 역설계.
- 이 문서의 API 후보는 실제 수신 검증이나 운영 활성화 증거가 아니다. 구현 결과는 마지막 절의 증거를 따른다.

## 1. 준비 상태 판정

**전체 상세 화면 동등성은 아직 충족하지 못한다.** 기존 자료는 연결·가져오기·선택 저장·일지 복귀에 집중돼 있었다.
현재 main의 RecordUI, ImportedRecords, 원본 시간 의미 표시는 재사용한다.
현재 FileObservationV1은 날짜·시작 시각·시간대·종목·거리·시간·명시적 랩만 담는다.
TCX Trackpoint의 심박·고도·케이던스 등은 파서에서 수집하지 않으며, GPX 좌표는 거리 계산 이후 보관되지 않는다.

따라서 완료 기준은 화면 수가 아니라 **필드별 수신 → 검증 → 보존 → 재조회 → 표시 → 조작 → 실제 원본 대조**다.
각 제공자에게 보이는 화면과 제3자 API로 받을 수 있는 필드는 별도 열로 관리한다.

## 2. 역설계 근거와 관찰 한계

### 직접 확인한 공식 동작

- [Garmin 활동 차트](https://support.garmin.com/en-PH/?faq=V0T9hu0HIa8uj2gi0ea9aA):
  활동 선택 → Charts, 확대, 특정 시점 수치, 지표 겹쳐 보기. 순간 페이스와 랩 평균 페이스의 계산 의미가 다름.
  10월 31일 공식 페이지 본문을 브라우저에서 확인했다. 실기기 앱을 조작한 증거는 아니다.
- [Apple 달리기 지표](https://support.apple.com/ko-kr/guide/watch/apd1f24d4d35/27/watchos/27):
  수치·달리기 자세·구간·스플릿·고도·파워 묶음. 공식 페이지 선택 버전은 watchOS 27.
- [Apple 심박 영역](https://support.apple.com/ko-kr/guide/watch/apd897dccddf/27/watchos/27):
  Fitness 세션 → 운동 → 심박수 영역 더 보기. 사용자별 영역과 수동 편집이 가능하므로 임의의 공통 영역을 Apple 값으로 표시하지 않는다.
- 위 Apple 페이지의 [공식 이미지](https://ipcdn-web.apple.com/assets/v2/web/dde97bd8-0518-4809-a2c4-d46709e3a3a0)를 440×488 원본으로 관찰:
  주 수치와 보조 라벨 분리, 현재 영역 이름·색·포인터 병행, 현재 값과 평균·머문 시간의 명확한 구분.
  이미지의 픽셀 크기는 확인했지만 앱 내부 폰트·반경·애니메이션 수치는 측정하지 않았다.

상세 출처와 제공 범위는 [Garmin 조사](../research/GARMIN_DETAIL_PARITY_2026-10-31.md),
[Apple 조사](../research/APPLE_DETAIL_PARITY_2026-10-31.md)를 참조한다.
공개 설명서·정적 이미지에 근거한 화면/동작 역설계다. 네이티브 바이너리 디컴파일, 비공개 API 추출, 실제 개인 운동 수신은 수행하지 않았다.

### 차용 기준

- Garmin: 풍부한 활동 상세, 원본 랩, 축·지표 선택, 시점 비교, 단위·계산 의미.
- Apple: 요약에서 지표 상세로 내려가는 구조, 큰 값과 작은 단위, 기간 선택, 데이터 출처 확인.
- TrainOracle: 기존 Pretendard/Lucide/틸·아이보리 토큰, 기록·일지·계획 연결과 코칭 맥락.
- 관찰한 UI 구조를 자체 코드로 구현한다. 제공자 로고·전용 아이콘·폰트 자산을 복제해서 동일 앱처럼 표시하지 않는다.
- 보조 ui-ux-pro-max 검색은 실행했지만 제안된 빨강/금색·Fira·가로 journey는 현재 제품에 부적합하여 채택하지 않았다.

| 건강/회복 | 지표별 오늘값·측정 기간·출처·갱신 시각 | 일/주/월/연, 일별 표, 상세 출처 | 수면 미측정과 0시간을 구별 |
| 출처/정정 | 원 제공자·전달 경로·기기·원본 ID·수정 이력 | 원값과 정정값 확인, 충돌 선택 | 출처 불명/구형 요약만 존재 |
| 우리 앱 분석 | 확인된 사실→일지→계획 대비 | 관련 운동 상세로 드릴다운 | 자료 부족·AI 이용 불허를 별도 설명 |

운동 상세 첫 화면은 “거리/시간/페이스” 중심 2열 또는 3열 지표와 출처 한 줄로 시작한다.
랩이나 심박 등의 풍부한 정보는 이름 있는 구획으로 바로 진입한다. 모든 항목을 무한히 접힌 도움말 속에 숨기지 않는다.
데이터가 없는 지표를 거대한 빈 카드로 채우지 않고, 상세의 “제공되지 않은 항목”에서 원인과 가능한 다음 행동을 보여준다.

### 운동 상세 기본 배열

```text
← 가져온 기록                 운동 시작 날짜·시각
달리기                         출처 · 전달 경로
거리             시간 종류             평균 페이스
[요약] [구간] [차트] [경로] [출처]
선택한 영역의 실제 데이터와 표 / 기록 없음 사유
내 일지 보기 · 계획과 비교
```

정확한 ID/날짜/선택/스크롤 위치로 복귀한다. 뒤로 가기는 저장 동작이 아니다.
일지 저장 시각(savedAt)을 운동 시작 시각(startedAt)으로 표시하지 않는다.

## 5. 값과 상태의 공통 계약

각 값은 수치만으로 전달하지 않는다.

```ts
// 다음 센서 확장을 위한 설계 계약. 현행 journal schema에 추가하지 않은 후보다.
type MetricFact = {
  metricId: string
  value: number | null
  unit: string
  statistic: "sample" | "mean" | "max" | "min" | "total" | "providerScore"
  window: { start: string; end: string } | null
  source: { provider: string; transport: string; device?: string; sourceRecordId: string }
  method: string | null
  availability: "present" | "not_recorded" | "not_supported" | "not_received"
    | "authorization_unknown" | "invalid"
}
```

- `0`은 확인된 0이다. 미수신/null/손상/조회 실패와 다른 상태다.
- 권한 조회 API가 공개하지 않는 상태는 “권한 거절”로 단정하지 않는다. HealthKit 읽기 결과가 비어도 거절인지 기록이 없는지 구별할 수 없는 경우를 포함한다.
- 원 제공자와 전달 경로를 분리한다. 예: Garmin → Apple Health → TrainOracle.
- 파일 업로드만으로 제조사 인증·원본 진위·AI 허용을 추정하지 않는다.
- 같은 운동을 여러 경로로 받아도 UUID/시간 근접만으로 파괴적 병합하지 않는다. 원본별 관측과 선택된 대표 표시를 분리한다.
- 원값·단위·시각·수정본·사용자 정정은 보존한다. 포맷팅은 원본 수치를 바꾸지 않는다.
- 값 표시 허용과 일지 보관 허용, 분석/자체 호스팅 LLM 허용은 각각 확인한다.

## 6. 시계열과 차트 역설계 계약

### 공통 모델

- 실제 timestamp를 가진 표본 사용. 모든 표본을 등간격인 것처럼 배치하지 않는다.
- 시간축은 시작 후 경과 또는 실제 시각을 명시한다. 일시정지 제외 축은 제공된 pause/timer 근거가 있을 때만 사용.
- 누락/센서 중단 구간은 선을 끊는다. 전후 점 사이를 보간해 측정한 값처럼 표시하지 않는다.
- 공급자 평균/최대와 앱이 계산한 요약은 서로 다른 필드다. 샘플 평균을 공급자 평균과 동일하다고 이름 붙이지 않는다.
- 다운샘플링은 화면 렌더에만 적용. 원표본의 극값·공백·시간 순서 보존을 검증하고 합계/코칭 입력에 재사용하지 않는다.
- GPS 폴리라인 축약도 표시 사본에만 적용. 원좌표·정확도·끊김은 별도 보존.
- 1개 표본은 점 하나, 0개는 빈 상태. 축 분모 0, 동일값 시리즈, 동일 timestamp, 역순 timestamp, timezone 전환을 별도 처리.

### 필수 조작

1. 한 지표 선택 → 평균/범위·단위·측정 구간.
2. 탭/드래그 또는 키보드 좌우 → 해당 시점의 값·시간·출처.
3. 영역 확대 → 범위 표시, “전체 보기”로 복구. 확대 버튼도 제공해 pinch만 강제하지 않음.
4. 겹쳐 보기 → 각 축의 단위와 범례, 공통 시각. 다른 단위 두 개를 한 y축에 올리지 않음.
5. 랩 선택 → 해당 범위 강조; 원본 랩에 시작/종료가 없으면 가짜 시간 범위를 만들지 않음.
6. 그래프/표 전환 → 같은 표본, 같은 단위, 같은 누락 상태.
7. 모바일 320/375/430px, 200% 글자, 키보드, reduced-motion에서 기능 유지.
8. 색·선·텍스트 병행. hover에만 정보를 두지 않음.

### 제공자 특유의 의미

- Garmin instantaneous pace와 average lap pace를 서로 덮어쓰지 않는다.
- Apple 심박 영역 설정과 time-in-zone은 해당 운동 시점의 경계/방식을 보존한다. 현재 나이로 과거 영역을 재계산하지 않는다.
- iOS 27/watchOS 27의 공개 zone API는 심박·사이클링 파워의 조건부 수신 경로다. 구형 OS와 자료가 없는 운동은 원본 심박 차트를 유지하고 zone만 미제공으로 처리한다. 러닝 파워 zone이 같은 API에 포함된다고 확대하지 않는다.
- Apple HRV SDNN을 Garmin HRV 값과 같은 지표 평균으로 합치지 않는다.
- 공급자 readiness/Body Battery 등을 TrainOracle “회복 점수”로 재명명하지 않는다.
- 미래의 통합 코칭에는 검증된 의미·허용 출처만 연결하며, 이러한 상세 UI 준비가 AI 권한을 열지 않는다.

## 7. 데이터 저장 확장 계획

현행 입력 제한은 파일 10MiB, 100,000 points이고 account-journal HTTP body 제한은 655,360 bytes이다.
전체 원시 시계열을 현재 journal JSON에 그대로 넣는 방식은 채택하지 않는다.

1. 현행 FileObservationV1과 그 fingerprint를 그대로 읽는 호환 reader 유지.
2. 새 센서 observation은 버전이 있는 별도 구조로 설계. provider namespace + source record ID + revision을 식별자에 포함.
3. 일지에는 작은 manifest/참조와 확인된 요약만; 표본은 계정 소유·암호화·삭제/철회 범위가 연결된 별도 chunk 보관 후보.
4. manifest에 값 종류/원 단위/시간 범위/표본 수/결측 수/내용 해시/상태를 둔다. 미완료 chunk를 완전 수신으로 표시하지 않음.
5. 프론트 schema, 서버 생성 validator, 기존 backup/restore, outbox retry, correction/conflict, export를 한 후보로 검증.
6. 구형 앱의 손실 쓰기를 차단하고 원본 V1 재저장이 그대로 가능한지 확인.
7. 새로운 저장 구조는 이 문서만으로 운영 DB에 적용하지 않는다. 후보 구현과 검증 후 기존 배포 절차를 따른다.

GPS·원본 건강 자료·메모를 연구 보고서, 콘솔, URL, 스크린샷에 포함하지 않는다.
시각 검수에는 합성 fixture를 사용하고, 개인 원본 대조는 별도 비공개 검증 영수증으로 결과만 남긴다.

## 8. 구현 순서와 완료 판정

| 순서 | 납품 단위 | 완료 판정 |
|---|---|---|
| A | 기존 저장 운동 상세 | 저장한 시각/원시간 의미/랩을 정확한 운동에서 재조회·표시, 부분 누락·0·1000랩·320px 확인 |
| B | TCX 심박/고도/케이던스/파워 표본 수집·저장 | namespace 파싱, 시간/단위 검증, checksum/revision, 용량·중단 재시도, 구형 호환 |
| C | 공통 MetricDetail/차트/표 | 실제 표본으로 커서·확대·overlay·빈 구간·접근성 동작, 외부 그래프와 수치 대조 |
| D | GPS/랩·스플릿 연계 | 좌표와 센서 시각 연결, 부분 경로, map 실패/실내 대안, 정확도·개인 경로 보호 |
| E | Garmin/HealthKit 실제 adapter | 실제 허용 필드와 권한별 capability, 기기 운동 1건 이상 원본 대조, 삭제·연결 해제 |
| F | 건강/수면/공급자 평가 | 지표별 API 제공 확인, 기간·측정 방식·갱신 시각, 중복 출처 우선순위 |
| G | TrainOracle 통합 화면/코칭 | 상세 원자료에서 근거로 역추적, 제공자별 이용 허용·사용자 동의·모델 운영 별도 검증 |

A의 완료를 B~G의 완료로 보고하지 않는다. 제공자가 노출하지 않는 값은 “구현 완료”나 임의 점수로 대체하지 않는다.
개발자는 아래 표의 근거 칸을 실제 수신/저장/화면 영수증으로 채운 후에만 기능 완료로 표시한다.

## 9. 검수 시나리오

| 입력/조건 | 기대 결과 |
|---|---|
| 시간 종류 미확인 TCX | 원본 초 표시; 이동 시간 또는 순간 페이스로 오표시하지 않음 |
| 활동 시간 확인, 개별 랩 시간 미확인 | 활동 confirmation을 개별 랩 원본 의미에 덮어쓰지 않음 |
| 일부 랩 거리/시간 없음 | 해당 셀만 미기록. 전체 합계 발명 없음 |
| 거리 0/시간 0 | 확인된 0 표시. 무한 페이스 생성 없음 |
| 시작 시각 offset과 표시 시간대 다름 | 원 offset과 날짜 기준을 둘 다 읽을 수 있음 |
| 날짜 넘김/여행/DST | 저장된 활동 날짜 불변, 기기 현재 timezone에 따라 일지가 이동하지 않음 |
| 같은날 운동 두 건 | 이름/ID가 맞는 상세로 이동, 첫 기록으로 잘못 열리지 않음 |
| 1000랩 | 첫 20개+명시적 더 보기; 전부 접근 가능 |
| 샘플 0/1/같은 값/역순/끊김 | 빈 상태/점/유효축/검증/선 끊김 |
| 여러 회사 데이터 같은 운동 | 출처별 관측 보존, 이중 거리 합계 방지, 사용자 검토 |
| HealthKit 빈 조회 | “권한 거절” 확정 문구 없음 |
| 계정 A→B, 늦은 응답 | A의 데이터나 커서 상태가 B 상세에 남지 않음 |
| 저장 응답 없음/조회 실패 | pending/unknown 유지; 저장 성공 배지로 전환 안 함 |
| 데이터 일부만 허용 | 허용 필드만 표시. 연결 성공을 모든 필드 허용으로 확대하지 않음 |
| 원본 수정본 수신 | 기존 지문과 revision 대조, 임의 last-write-wins 없음 |
| 320px/200% 글자/키보드 | 문서 가로 넘침 없음, 조작 44px, 이름과 focus 유지 |

## 10. 현재 납품과 미완료

- 준비: 공식 항목·동작 조사, 현행 코드 격차, 필드 상태표, 공통 상세/시계열/저장 계약과 구현 순서.
- 구현 후보: 기존 FileObservation을 활용하는 ImportedActivityDetail와 일지 상세 연결. 정확한 변경/검증은 [로컬 검증 결과](../verification/wearable-detail-20261031/README.md) 참고.
- 미완료: 센서 표본 수집/저장, 고급 차트/지도, 건강 추세, 공급자 고유 평가 수신, 실제 개인 계정 데이터 대조.
- 별도: 운영 배포 및 실제 Garmin/Apple OAuth·권한·기기 검증. 이 명세는 그 성공 증거가 아니다.
