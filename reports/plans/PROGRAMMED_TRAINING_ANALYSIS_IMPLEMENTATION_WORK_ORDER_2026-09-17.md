## 3. 스펙 우선 정비

### 3.1 문서 처리 방식

기존 스펙 전체를 새 문서로 대체하지 않는다. 외부 기록 통합, 분석·시각화, 지표 알고리즘, 출처 채택, 누적 거리, 훈련 설명·프라이버시, 일지 연결·다음 주기 적응 계약의 **해당 조항에만** 이번 범위를 추가한다. 과거 결정을 삭제하지 않고 유지·추가·수정·보류를 구분한다.

실행 단계에서 좁은 채택표 하나를 추가한다. 채택표는 `형식 프로필 + 필드 + 계산 용도 + 요구 조건 + 제외 용도 + 버전`을 갖는다. 승인된 지시서의 근거를 적되 전문가 독립 승인·문서 정본 승격·실행 완료라고 표시하지 않는다. 이슈는 해당 표를 실제로 열어 재계수하고 실행 증거가 필요한 것은 증거 전까지 닫지 않는다.

### 3.2 이번에 채택할 계산 경계

| 입력/용도 | 적용 범위 | 적용하지 않는 범위 |
|---|---|---|
| 확인한 파일의 날짜·거리 | 자신의 활동 요약, 주·월 거리, 비교 기간 합계 | 경기 기록 인증, 능력 점수, 자동 증량 |
| 의미가 확인된 시간 | 같은 의미별 합계, 평균 페이스와 과거 비교 | 이동/경과/본운동 시간을 서로 치환 |
| 의미 미확정 시간 | 원본 필드와 값을 참고로 표시 | 페이스 산출·기간 통합·계획 시간 준수 판정 |
| 명시적 랩·구간 | 구간 목록, 사용자가 대응을 확인한 계획 구간 비교 | 랩을 자동으로 본운동/회복으로 분류 |
| 사용자가 직접 입력한 정확한 RPE | 현재 채택된 계획 RPE 비교·기존 다음 후보 경로 | 기기 effort를 RPE로 변환, 평균으로 회복·능력 판정 |
| 계획 목적·사용자 선택 목적 | 각각의 출처를 유지한 구성 이력 | 목적 횟수를 실제 대사 비율·능력 부족으로 표현 |
| PB/SB 및 목표기록 | 현재 별도 적격성 계약을 통과한 기록만 기존 페이스 계산에 사용 | 파일에서 가장 빠른 구간을 자동 PB·경기 기록으로 채택 |

파일 업로드 및 확인이 모든 계산을 허용하는 단일 버튼이 되지 않도록 한다. 다만 기술 상태를 사용자에게 여러 번 승인받는 화면으로 풀지 않는다. 지원 프로필의 정상 입력은 한 번의 `저장하고 분석 보기`로 처리하고 모호한 항목만 추가 확인한다.

## 4. 데이터와 공개 인터페이스 설계

### 4.1 기존 기반을 확장한다

현재 `PreparedDeviceActivity`의 초·미터·시간 의미·출처 구조를 공통 내부 자료형으로 추출해 재사용한다. 기존 `analysisEligible: false` 준비 계약은 유지한다. 별도 파일 어댑터가 확인된 파일 관측을 만들고, 분석 투영기가 용도별 채택표를 확인한다. 외부에서 전달받은 `analysisEligible`·신뢰도·허용 플래그는 권한으로 읽지 않는다.

현재 `ImportedActivity`의 문자열 요약은 기존 화면/저장 호환용으로 남기고 선택적인 버전형 구조화 근거를 추가한다. 분석은 새 정밀 근거가 있으면 이를 사용하며 두 자리 반올림 문자열을 역산하지 않는다. 옛 가져오기 기록은 그대로 읽되 새 근거가 있었던 것처럼 승격하지 않는다.

| 파일 관측 근거 | 버전, `FILE_UPLOAD` 출처, 형식/프로필, 원본 활동 ID가 있으면 그 값, 내용 지문, 파서 버전 | 공급자 표시명은 검증되지 않은 표시 정보. 원파일·자유 문장·GPS 경로를 포함하지 않음 |
| 시간·거리 관측 | 미터·초, 원천 필드, 시간 의미, 날짜/시작 시각/시간대의 확인 상태 | `ELAPSED / TIMER / MOVING / SOURCE_DEFINED / UNKNOWN`. 값이 없으면 null |
| 구간 관측 | 원본 순서·구간 ID·거리·시간·의미, 명시돼 있을 때만 종류 | 종류가 없으면 UNKNOWN. 계획으로 채워 넣지 않음 |
| 파일 처리 결과 | 성공 항목, 제외 항목의 안전한 원인 코드, 자료 수, 부분 실패 | 파일 전체를 빈 배열로 바꿔 성공으로 표시하지 않음 |
| 분석 결과 | 사용한 기록/수정본 참조, 지표별 표본 수, 제외 이유, 비교 기간, 계산/채택 버전 | 메모 원문·파일명·GPS·토큰 없이 요청 시 계산. 영구 보고서 저장소는 만들지 않음 |
| 구간 비교 결과 | 정확한 계획 정체성, 대응된 실제 구간, 차이, 비교 불가 이유 | 준수 점수·회복 판정·허용 오차 임계값을 새로 만들지 않음 |
| 다음 선택 맥락 | 현재 계획/자료 버전, 사용한 관측, 사용자 반복/다양성 선호, 기존 적격 기록 참조 | 현재 계획 불변. 사용자가 명시적으로 다음 계획을 선택해야 저장 |

날짜만 있는 CSV에 시작 시각을 자정으로 만들어 넣지 않는다. 날짜/오전·오후는 운동의 불변 ID로 사용하지 않는다. 필드의 출처, 숫자 품질, 사용 목적 허용 여부는 별개 값이다.

### 4.3 숫자·단위·시간 처리

- 숫자는 전체 문자열 문법으로 검사한다. `5 miles`, `1:30`, `12abc`, NaN, Infinity를 숫자 앞부분만 잘라 채택하지 않는다. 단위 표기의 해석을 지원하지 않으면 해당 행의 문제를 표시한다.
- 현재 CSV/JSON의 `date`, `distanceKm`, `durationMin` 형식은 유지한다. 알려진 열의 순수 숫자에 단위를 반복 질문하지 않는다. 새 선택 열로 시간 의미·원본 ID·시작 시각을 제공할 수 있으며, 임의 열 이름 추론기는 만들지 않는다.
- CSV의 중복 헤더, 부족하거나 초과한 열, 잘못 닫힌 인용부호를 명시적으로 처리한다. 빈 값과 실제 0을 구분하고, 0거리·0시간으로 페이스를 나누지 않는다.
- TCX의 `TotalTimeSeconds`는 명시적인 프로필 정의가 없는 한 `SOURCE_DEFINED`으로 보존한다. 표시할 수 있지만 이동 시간으로 부르지 않는다. 사용자가 확인한 해석은 별도 확인 메타데이터이며 원출처를 변경하지 않는다. 일부 랩의 시간이 없으면 있는 랩의 합을 전체 활동 시간이라고 표시하지 않고 부분 합과 누락 수를 함께 둔다.
- GPX 시간은 유효한 첫/끝 시각의 경과 시간으로 표시한다. 서로 다른 `trkseg` 사이를 직선으로 연결하지 않는다. 잘못된 좌표는 거리 계산의 연결을 끊으며 앞뒤 유효 점을 바로 잇지 않는다. 역순·누락 시각은 관련 시간 계산을 제한하되 관계없는 유효 관측까지 모두 버리지 않는다. GPS로 계산한 거리는 계산값이라는 출처를 유지한다.
- 날짜 경계는 원본 시각과 확인한 시간대로 결정한다. 파일에 시간대가 없으면 기기 기본 시간대를 확인값으로 제시하고 사용자가 바꿀 수 있게 한다. 불명확한 지역 시각은 임의 UTC 변환하지 않는다.
- 첫 완결 시험과 R1 출시는 TCX 한 형식에서 수행한다. 같은 정규화/검증 경로에 CSV·JSON·GPX를 R2에서 차례로 연결한다. 형식별로 확인 가능한 필드만 채택하며 다른 형식의 미완성 때문에 검수된 TCX 출시를 막지 않는다.

### 4.4 정체성·중복·수정

- `journalEntryId`(서비스 기록), `sourceObservationKey`(원관측), `contentRevisionFingerprint`(관측 내용 수정본)를 분리한다. 기존 `journalEntryId`는 변경하지 않는다. 파일 행 번호·배열 순번은 새 관측의 정체성으로 사용하지 않는다.
- 새 가져오기는 새 관측 키와 기존 v1 가져오기 ID를 모두 조회한다. 기존 ID 계산기의 `format + sourceIndex + 요약 활동` 경로는 호환 조회에만 남긴다. 행이 재정렬되어 옛 ID가 일치하지 않으면 기존 가져오기 요약으로 후보를 찾되, 요약 일치만으로 정밀 근거를 자동 덧붙이지 않는다. 명확한 동일 사본 또는 사용자 확인 후에만 같은 기록에 새 관측 키를 연결한다.
- 원본 활동 ID와 형식 프로필이 있는 파일은 그 정체성과 내용 지문을 함께 대조한다. ID는 같고 내용이 다르면 수정 후보이지 별도 운동 또는 최신본 확정이 아니다.
- 원본 ID가 없으면 형식·시작 시각·정규화 내용 지문으로 같은 사본 후보를 찾는다. 파일 해시는 같은 파일 재시도의 증거일 뿐 실제 동일 운동이나 진짜 공급자의 증거가 아니다.
- 같은 파일 안의 동일 행, 행 순서 변경, 다른 형식의 유사 기록, 동일 날짜의 실제 두 운동은 각각 구분한다. 자동 확정은 명확한 동일 사본 재시도에 한정하고 나머지는 `기존 기록에 연결 / 별도 운동으로 저장 / 제외`로 확인한다.
- 날짜·거리 유사성만으로 기록을 합치지 않는다. 정정·삭제 후보를 최신 수신 시각만으로 덮어쓰지 않는다. 삭제 표식이 있는 기록은 재가져오기만으로 복구하지 않는다.
- 현재 일반 편집에서 불변인 날짜·계획 링크 규칙은 유지한다. 잘못된 날짜는 명시적인 기존 삭제/새 기록 저장으로 수정하며 자동 날짜 재배치는 이번 범위에 넣지 않는다.
- 같은 운동·같은 날짜의 원자료 정정은 사용자가 변경 필드를 확인한 뒤 같은 `journalEntryId`의 새 revision으로 저장한다. 불명확한 관측은 정정 후보로 남기며 별도 운동 생성은 명시적으로 선택해야 한다. 기존 imported-fact 불변 검사를 일반 편집에서 풀지 않는다. 별도 가져오기 정정 명령에 소유 계정·예상 revision·이전 내용 지문·새 관측·확인한 변경 필드를 요구하고 서버가 검증한다. 기존 메모·직접 입력 RPE·계획 링크·완료 상태는 정정으로 변경할 수 없다.
- 수정본이 바뀌면 연결된 비교는 예전 관측을 비교했다는 상태로 전환하고 재확인 전 새 관측에 대응을 자동 재사용하지 않는다. 충돌과 정정 전 이력은 현재 보존 정책을 따른다.

## 5. 온라인 보관과 호환성

새 근거는 기존 암호화 계정 일지 문서의 선택 필드로 보관한다. 범용 파일 보관함·새 분석 DB·원본 파일 서버 업로드를 만들지 않는다. 자유 메모·TCX Notes·임의 파일 제목을 분석용 이름으로 복사하지 않고 `가져온 달리기` 같은 고정 라벨을 기본으로 사용한다. 기존 기록의 제목은 보존하되 분석 근거로 읽지 않는다.

- 신규 구조화 근거와 비교 연결에는 계정 일지 codec V3을 사용하고 V2도 계속 읽는다. 실행 시 이미 다른 V3이 있으면 충돌 없이 다음 버전을 배정하고 표와 시험을 함께 갱신한다. 브라우저·서버 validator·본인용 백업 왕복을 함께 수정한다. V2 번호 아래에 새 필드를 끼워 넣지 않는다.
- V2 문서의 기존 쓰기는 종료 기한 없이 유지한다. 일괄 강제 승격은 하지 않는다. V2→V3은 새 근거/비교 연결을 추가할 때 명시적 revision 검사를 거쳐 수행하며 기존 날짜·메모·RPE·계획 링크·식별자·출처가 무손실임을 검사한다. 서버가 가진 현재 문서가 V3이면 같은 기록을 V2로 낮춘 쓰기는 거절한다. 새 형식을 해석하지 못해 빈 문서를 보내는 것도 거절한다.
- 호환 서버와 V2/V3 dual-read 클라이언트를 먼저 배포하며 이때 V3 쓰기는 꺼 둔다. 읽기/쓰기 지원 버전 정보를 기존 계정 요청에 명시적으로 교환하는 좁은 기능 협상을 추가한다. 이 정보는 형식 호환용일 뿐 인증·소유권 증거가 아니다. 서버는 실제 문서 구조와 수정 권한을 별도로 검증한다.
- V3 문서는 V3 지원을 확인한 클라이언트에만 정상 문서로 전달한다. 구형 요청에는 명시적인 업데이트 필요 응답을 보내고 빈 목록·삭제 응답·일부 필드만 V2로 위장한 문서를 보내지 않는다. 구형 이미 배포된 앱에 새 안내 문구가 저절로 생긴다고 가정하지 않는다. 실제 구형 빌드가 오류 응답에서 로컬 projection/outbox를 지우지 않는지 시험한다. 이를 보장하지 못하면 V3 쓰기를 열지 않고 호환 조치부터 한다.
- 최소 호환 클라이언트는 고정 날짜가 아니라 V3 읽기·손실 방지·재시도 시험을 통과한 릴리스 SHA로 정하고 배포 기록에 남긴다. 쓰기 활성화 이후에도 V3를 읽는 서버로만 복구하며 V2-only 서버로 되돌리지 않는다.
- 로그인 사용자는 기존 계정 outbox·수정본 충돌·서버 확인 경로를 재사용한다. 전송 전/전송 중/계정 저장 완료/충돌/실패를 구분한다. 초안 보호가 계정 저장 완료를 대신하지 않는다.
- 로그아웃·A계정→B계정→A계정 전환 후에는 이전 작업의 비동기 응답을 폐기한다. 계정이 바뀌면 새 확인 없이 이어 저장하지 않는다.
- 비로그인 상태의 파일 미리보기와 기존 기기 사용은 유지한다. 온라인 보관을 원하는 사용자는 로그인한 대상 계정을 확인한 뒤 저장한다. 기존 기기 기록을 자동 귀속시키지 않는다.
- 분석은 현재 계정의 현재 수정본을 기준으로 계산한다. 미전송 초안의 숫자가 필요하면 별도 미리보기로만 보이고 계정 합계에 섞지 않는다.
- 기존 10MiB 파일 제한과 서버 요청 크기 제한을 유지한다. 초기 파싱 예산은 파일당 활동 1,000개·트랙 포인트 100,000개, 활동당 랩 1,000개로 두며 운영 방어값임을 명시한다. 초과를 조용히 자르지 않고 분석 전 해당 파일/항목을 거절한다. 생리학적 한도가 아니다.
- 파싱 상한 이내라는 이유로 저장 가능하다고 가정하지 않는다. 현재 서버 본문 상한 655,360 bytes와 초안 본문 상한 100,000 code units 등 해당 경로의 실제 제한을 암호화/인코딩 후 요청 크기로 다시 확인한다. 클라이언트와 서버가 같은 제한을 검사하며 너무 큰 항목은 저장 전 구체적으로 알린다. 랩·메모를 조용히 자르거나 제한을 자동으로 높이지 않는다.
- 오래된 근거 없는 가져오기 기록은 자동 채택하지 않는다. 새 방식으로 재가져온 사본과 사용자가 정확히 연결한 경우에만 근거를 추가한다. 원자료에 없던 정밀도·랩·시간 의미를 복원하지 않는다.
- 취소·재시도에 필요한 정규화 결과만 기존 초안 보호 경로에 두고 원파일은 남기지 않는다. 현재 삭제·휴지통·충돌 보존 정책을 새 값으로 덮어쓰지 않는다.
- 공유·친구 비교·기본 내보내기에는 새 근거를 자동 추가하지 않는다. 본인용 백업은 새 버전을 지원하되 원문 비밀 정책을 유지하고, 구형 백업 복원 시 새 근거가 없는 상태를 그대로 보존한다.

## 6. 분석·비교·다음 선택 구현

### 6.1 분석 투영

전역 `isEligibleForAnalysis`를 모든 외부 값에 true가 되도록 바꾸지 않는다. 출처·필드·용도·버전·확인 상태를 검사하는 단일 투영 경로를 추가하고 기존 직접 입력 투영과 합쳐 사용한다. 허용 여부는 앱/서버의 채택표에서 계산하며 백업이나 파일 안의 권한 필드를 믿지 않는다.

첫 외부 보고서는 기존 분석 화면 안의 `가져온 기록 분석` 영역으로 제공한다. 다음 통합 단계에서 날짜·거리 등 채택된 지표만 기존 주·월 누적과 이전 비교에 합류한다. 별도 계산 엔진을 만들지 않고 같은 투영 결과를 사용한다. 출처 필터로 전체/직접 입력/파일 기록을 볼 수 있게 한다.

- 거리·시간·RPE는 지표별 표본 수와 제외 수를 따로 계산한다. 자료 없음, 전부 제외됨, 일부 사용됨을 구분한다.
- 시간 의미가 다른 합계를 하나로 합치지 않는다. 전체 운동 시간으로 표현할 수 없으면 종류별로 표시한다.
- 기록별 평균 페이스의 단순 평균을 기간 대표 페이스로 사용하지 않는다. 비교 가능한 시간·거리가 둘 다 있는 표본만 합산해 계산하고 계산 정의를 보여 준다.
- 걷기·자전거 등은 별도 활동으로 유지하며 러닝 마일리지에 더하지 않는다. 종목 미확정은 사용자가 확인하기 전 러닝 합계에서 제외한다.
- 과거 파일 추가·수정·삭제로 합계가 바뀐 경우 실제 최근 운동량 증가와 구분한다. 관측 기간, 자료 기준 시점, 계산 버전을 기록한다.
- 에너지 구성은 기존 분류 계약과 명시적 목적만 사용한다. 미분류를 BASE나 MIX로 채우지 않는다. 목적별 횟수·거리·시간은 따로 표시하고 목표 비율·능력 부족·기여율은 만들지 않는다.

### 6.2 해설과 근거

기존 `방법 / 이유·근거 / 주기·기록` 상세 화면과 설명 영수증을 재사용한다. 공통 용어 정의, 검토된 템플릿 설명, 실제 배치 이유를 연결하되 새 문장을 화면마다 복제하지 않는다.

훈련 해설은 목적·에너지 특성·운동 구성·회복 이유·주기 역할·기대와 한계·근거를 포함한다. 해당되지 않는 설명은 그 이유를 표시한다. 받은 훈련표가 기존 지원 표기 또는 구조화 입력으로 읽히면 정확한 구조를 해설하고, 모호한 회복/세트는 확인 전 수치나 목적을 발명하지 않는다. 모든 자연어 훈련표를 이해한다고 약속하지 않는다.

외부 코치의 훈련표는 계산 가능한 반복·거리·휴식과 일반 원리를 설명할 수 있지만 코치가 그 선수에게 선택한 이유를 대신 만들어내지 않는다. 검토된 템플릿과 정확히 일치하거나 별도 채택된 구성에만 그 템플릿의 세부 근거를 연결한다. 비슷한 훈련이라는 이유로 개인 적합성·청소년 적용·주기 배치 승인을 상속하지 않는다.

자신의 기록을 사용한 부분과 일반 훈련 원리를 구분한다. 최신 일지 분석은 재계산하지만 과거 계획의 당시 근거·수치·설명 버전은 그대로 남긴다. 설명 로딩 실패 시 기존 처방은 보존하고 설명 제공 범위만 알린다.

### 6.3 계획과 실제 구간 비교

계획 링크는 기존 계획 버전·세션 내용 지문·날짜·오전/오후 검사를 유지한다. 원본 계획이 없으면 요약만으로 당시 세션을 재구성하지 않는다. 현재 불변 링크가 없는 사후 기록의 비교는 기존 `plannedSessionLink`를 추가/교체하지 않는다.

사용자가 확인한 대응은 해당 계정 일지 V3의 선택 필드 `comparisonRelations` 안에 `ComparisonRelationV1`으로 저장한다. 별도 범용 DB는 만들지 않는다. 필수 값은 관계 ID, 일지 ID, 확인 당시 revision, 관측 내용 지문, 불변 계획/세션 지문, 사용자 확인 구간 대응, 관계 버전, 생성/해제 시각이다. 원관측과 사용자 대응은 분리한다. 저장 명령은 기대하는 일지 revision으로 동시 변경을 검사한다. 관계를 저장하면서 생기는 일지 revision 증가 자체는 관측 변경으로 취급하지 않는다.

불변 원계획 조회가 검증된 경우에만 영구 관계를 저장한다. 원계획이 없으면 해당 세션에서만 임시 나란히 비교하고 저장된 비교라고 안내하지 않는다. P4 전체 완료에는 원계획이 있는 지원 경로의 관계 저장·재열기가 포함된다. 관계는 표시·비교 전용으로 RPE 적격성·적응·보상·안전 권한이 없다. 계정 격리·삭제 표식·백업·정정 후 오래된 비교 표시를 함께 검증한다.

자동 대응 후보는 양쪽에 명시된 구간 의미가 있고 구간 수·순서·종류·목표 단위가 정확히 일치할 때만 제시한다. 실제 거리/시간의 유사도·허용 오차를 대응 조건으로 쓰지 않는다. 의미 없는 자동 랩·누락·추가·UNKNOWN 구간이 있으면 사용자가 대응을 고른다. 자동 후보도 사용자가 확인한 뒤 차이를 계산한다. 원본 순서를 보존하고 제외·미대응 구간도 남긴다. 확인 전에는 나란히 보여 주되 오차·준수 판정을 계산하지 않는다.

구간별 거리·시간·페이스·회복의 차이를 수치로 표시하되 새로운 성공/실패 허용 오차, 적합 점수, 효과 판정은 만들지 않는다. 회복 종류나 시간 의미가 다르면 비교 제한을 표시한다. 총합만 있는 파일로 반복별 기록·세트 회복을 역산하지 않는다.

이전 수행 비교는 같은 템플릿 버전·구조·거리/시간 단위·회복 조건을 우선한다. 조건이 다르면 무엇이 다른지 보여 주고 동일 훈련의 향상으로 단정하지 않는다. 코스·날씨를 입력하지 않았다면 자동 보정했다고 말하지 않는다.

### 6.4 다음 훈련 선택

- 결과 화면의 다음 행동은 `다음 훈련 고르기`다. 기본 선호는 중립이며 사용자가 `같은 방법으로 비교` 또는 `다른 구성 살펴보기`를 선택할 수 있다.
- 후보 검색·정렬·배치는 기존 방법 레지스트리와 적격성 엔진을 호출한다. 분석 화면에 두 번째 추천 엔진을 만들지 않는다.
- 파일 분석은 실제 기록과 비교 맥락을 제공한다. 파일 속 거리·페이스만으로 강도·양·빈도를 변경하지 않는다. 기존 정확한 계획 링크의 직접 입력 RPE, 적격 PB/SB, 명시적 요청 등 현재 채택된 입력만 적응 경로에 전달한다.
- 파일 기록만 있는 사용자도 기존 계획 입력을 짧게 완료해 후보를 고를 수 있다. 개인 참고 페이스는 현재 적격 경기 기록으로 계산하며, 없는 기록을 파일의 빠른 구간으로 대체하지 않는다. 미지원 조합에는 기존 시간·RPE 안내를 유지한다.
- 같은 조건의 실제 다른 방법이 하나뿐이면 하나만 보여 준다. 장기 목표인 MAIN별 다양한 방법을 삭제하지 않되, 이번 연결 작업을 이유로 미채택 방법·배치 정책·용량을 활성화하지 않는다.
- 선택 후에도 적용 중인 계획을 조용히 수정하지 않는다. 기존 제안/승인/저장 경로에서 다음 계획의 정체성과 근거를 기록한다. 안전 확인은 최종 적용 직전에 다시 수행한다.
- 기존 계획의 저장·실행·휴식·건너뜀·통증 확인 흐름을 유지한다. 가져오기 또는 해설 읽기는 운동 완료·출석 보상으로 취급하지 않는다.

## 7. 화면과 상호작용 명세

기존 디자인 토큰, Pretendard, Lucide 아이콘, 간결한 정보 위계와 도움말을 사용한다. 새 하단 탭, 대형 대시보드, 매번 뜨는 안내 화면을 추가하지 않는다.

| 화면 | 기본 표시 | 펼쳐 보기/추가 행동 | 전환 규칙 |
|---|---|---|---|
| 파일 선택 | 지원 형식·파일 선택 | 형식별 안내 | 읽는 중 진행/취소. 취소해도 기존 기록 유지 |
| 확인 | 인식한 활동 수·날짜·거리, 해결이 필요한 항목 | 시간 의미·중복 후보·세부 행 | 정상 항목은 일괄 확인, 모호한 항목만 추가 선택 |
| 저장 결과 | 계정 저장 완료/전송 대기/부분 실패 | 실패 항목 재시도 | 완료 후 사용자가 결과를 읽을 수 있게 분석 요약으로 이동 |
| 활동 분석 | 실제 기록, 계획/이전과의 주요 차이 | 사용한 자료·제외 이유·계산 정의 | `계획과 비교` 또는 `다음 훈련 고르기` 중 맥락에 맞는 주 행동 하나 |
| 훈련 상세 | 정확한 방법과 회복 | 이유·근거, 주기·기록 | 기존 탭 유지. 돌아오면 선택·탭·스크롤 복원 |
| 다음 선택 | 가능한 후보와 실제 차이 | 근거·한계·상세 수치 | 명시적 선택 전 자동 저장/현재 계획 교체 없음 |

스크롤은 현재 질문·선택 영역으로 부드럽게 이동하되 사용자 조작 중에는 반복해서 끌어내리지 않는다. 전환 모션은 기존 토큰을 쓰고 줄인 모션에서는 즉시 전환한다. 자동 초점으로 모바일 키보드를 불필요하게 띄우지 않는다. 성공 안내는 짧게 사라져도 저장 상태는 다시 확인할 수 있어야 한다.

320px·375px에서 가로 넘침이 없어야 한다. 200% 글자 확대에서는 한 화면 강제보다 내용 접근과 세로 스크롤을 우선한다. 터치 영역은 시각 아이콘 크기와 별도로 44px 이상 유지한다. 차트는 표 대안·단위·기간·표본 수를 제공한다. 색만으로 신뢰도나 실패를 구분하지 않는다.

카피 기본값: `계정에 저장했어요`, `인터넷에 연결되면 저장을 마칠게요`, `일부 기록은 확인이 필요해요`, `이 시간에는 멈춘 시간이 포함돼요`, `같은 조건의 이전 기록이 아직 없어요`. 내부 원인 코드는 고객지원용으로만 보이고 사용자에게 코드명·정책 플래그를 나열하지 않는다.

| P9 | 독립 검토 + 총괄 | R2 통합 검수·형식별 순차 공개·최종 인수인계 | 네 형식 전체의 지원 필드별 흐름 확인. 랩 없는 형식에 구간 비교를 약속하지 않음 | 전체 종료 |

P1과 P2A는 인터페이스가 정해진 뒤 병행한다. P3 이후 병행은 파일 소유권이 겹치지 않는 범위에서만 한다. 문서·PR·커밋만으로 단계 완료를 계산하지 않는다. 서버 호환 배포와 기능 공개는 분리한다. R1을 끝내지 않고 네 형식·새 추천·새 저장소를 동시에 확장하지 않는다. P8의 각 형식은 검수 후 순차 공개할 수 있으며, 전체 완료는 P9까지 충족해야 한다.

각 작업자의 시작 입력은 `기준 SHA / 소유 파일 / 선행 단계 증거 / 사용 계약 버전 / 합성 실패 사례`다. 종료 산출물은 `변경 diff / 실제 실행 명령과 결과 / 실패 주입 확인 / 호환성 영향 / 남은 결함 / 다음 단계 입력`이다. 총괄은 인계받은 정확한 버전에서 연결 시험을 하고, 통합되기 전 개별 모델의 PASS를 제품 전체 PASS로 합산하지 않는다.

### 9.2 실행 범위

- 개발 중에는 변경 영역 단위/계약 시험, 타입 검사, 해당 화면 시나리오만 수행한다. 문서 전용 변경으로 전체 브라우저 시험을 반복하지 않는다.
- 계정 저장·출처·분석 합계 변경은 중요 변경이다. 정확한 릴리스 후보에서는 저장소의 필수 계약·앱 품질·브라우저 관문을 모두 통과해야 한다. 기존 CI를 줄이기 위해 의미 있는 시험을 삭제하지 않는다.
- 기존 `app` 스크립트의 `typecheck`, 관련 unit/KST 테스트, 계정 validator 검사, 해당 account e2e와 전체 릴리스 관문을 사용한다. 검증기 생성 산출물은 소스와 함께 갱신해 브라우저·서버 차이를 검사한다.
- CI가 사용하는 Node/WebCrypto 환경에서 재현한다. 환경 오류를 제품 결함과 구분하되 검사를 실행하지 않은 채 과거 환경 문제라고 넘기지 않는다.
- 시험 데이터는 합성 자료를 기본으로 한다. 사용자 실제 파일을 새로 요구하거나 모델에 보내지 않는다. 실제 계정 확인이 필요하면 승인된 시험 계정과 합성 기록으로 수행한다.
- 20개 기존 가상 관점을 체크리스트로 재사용하되 핵심 실제 브라우저 경로는 무기록·워치 전용·상세 일지·청소년 자율·AM/PM 선수·코치 공유 제한을 각각 확인한다. 가상 검토를 실사용자 조사로 보고하지 않는다.

## 10. 배포·롤백·운영 확인

1. 런타임 작성자와 다른 검토자가 정확한 패치/PR의 계산·권한 또는 UX를 검수한다. 문서상 채택 범위와 실제 변경을 대조한다.
2. §2.1의 방식으로 검수된 코드를 main에 반영한다. main push가 자동 배포를 시작한다면 필수 CI 통과 후에만 publish되도록 기존 관문을 확인한다. 기존 stale SHA 방지와 동시 실행 취소 정책을 유지한다.
3. 서버의 V2/V3 읽기·손실 쓰기 거절과 호환 클라이언트를 배포한다. 새 근거 쓰기와 형식별 파일 분석 플래그는 독립적으로 기본 비활성이다. 실제 구형 빌드의 오류 처리까지 검증한 뒤 최소 호환 SHA를 기록한다.
4. 승인된 시험 계정에서만 V3 저장과 TCX 분석을 열어 R1 전체 흐름·계정 전환·재시도를 검증한다. 과학적 임계값이나 실제 개인 자료를 시험 편의를 위해 추가하지 않는다.
5. R1을 공개하고 합성 파일 저장→재열기→분석→비교→기존 후보 선택을 확인한다. 서버 저장 확인과 같은 계정의 다른 브라우저 조회를 따로 확인한다. 개인정보 원문을 로그나 PR에 넣지 않는다.
6. R2는 CSV·JSON·GPX를 각자 검수한 뒤 순차 공개한다. 공개 지원 형식/필드 안내와 실제 플래그가 일치해야 한다.
7. 분석 결함이면 관련 분석 플래그를, 저장 호환 결함이면 신규 근거 쓰기도 끈다. 기존 계정 기록·훈련·일지의 정상 기능은 유지한다. V3 문서가 존재하면 V2-only 서버로 되돌리지 않는다. 원자료나 새 근거를 삭제하는 복구는 하지 않는다.

운영 지표는 원문 없는 형식별 파싱 성공/제외 수, 계정 저장 완료/대기/충돌 수, 분석 포함/제외 원인, 비교 가능/불가, 다음 선택 진입/완료를 사용한다. 기존 운영 수집 경로가 없다면 별도 추적 서비스를 새로 붙이지 않고 합성 시험과 최소 오류 코드로 시작한다. 거리·통증·메모·파일명·정밀 시각을 분석 이벤트로 전송하지 않는다.

잘못된 계정 접근, 근거 소실, 중복 합산, 계획값을 실제값으로 채택, 원문 유출, 승인 밖 처방 변화는 공개 중단 사유다. 모호한 시간 때문에 일부 비교를 제공하지 못하는 것은 정확한 제한 안내와 함께 지원 범위로 남길 수 있다.

## 11. 완료·인계·중단 보고

### 전체 완료 조건

- 지원 파일이 온라인 보관과 채택된 분석까지 실제로 연결된다. 저장함만 완성한 상태가 아니다.
- 기존 일지·계획 해설을 재사용하고, 지원 자료는 실제 구간/이전 수행 비교로 이어진다.
- 다음 훈련 선택은 기존 후보·페이스·안전·적응 조건을 지키며 실제 저장·재열기가 된다. 버튼만 있거나 계획 생성 화면만 연결한 것은 완료가 아니다.
- 새 데이터와 기존 기록/백업/구형 클라이언트의 호환, 계정 격리, 취소·재시도·정정·삭제가 검증된다.
- 독립 검수·main 반영·배포·공개 화면 확인이 각각 기록된다. PR을 사용한 경로에는 병합 근거도 남긴다. R1/R2 적용 범위와 미지원 항목이 사용자 안내와 일치한다.
- 새 과학적 진단·공식·훈련량·생리 자료 채택을 몰래 추가하지 않았다. 스펙 초안과 정본 상태도 구분했다.

### 다음 작업자를 위한 상태표

실행 시 각 P0~P9 행에 `NOT_STARTED / IN_PROGRESS / IMPLEMENTED_UNVERIFIED / VERIFIED / INTEGRATED_MAIN / DEPLOYED_VERIFIED / BLOCKED` 중 실제 상태를 적는다. P2A/P2B와 P8의 세 형식은 각각 상태를 둔다. DONE 하나로 코드·검증·배포를 합치지 않는다. 인계에는 정확한 SHA, 변경 파일, 실행 명령과 결과, 검수 의견, 남은 결함, 다음 가능한 작업, 외부 입력 필요 여부를 남긴다.

기술 범위 안에서는 하나를 마친 뒤 매번 승인을 기다리지 않고 다음 단계로 진행한다. 다만 새 처방 수치·새 개인정보 용도·비용 또는 생산 운영 권한을 이 문서로 확대하지 않는다. 외부 입력 때문에 막힌 부분만 격리하고 가능한 나머지는 계속한다. 중단 시에는 `무엇이 끝났는지 / 무엇이 미완인지 / 왜 멈췄는지 / 누가 무엇을 제공하면 재개되는지 / 백그라운드 작업이 남아 있는지`를 명확히 보고한다.

**최종 판단 기준:** 사용자가 자신의 기록을 덜 입력하고도 믿을 수 있는 해석과 비교를 얻고, 그 근거를 확인하며 실제 다음 훈련을 선택할 수 있는가. 파일 지원 수·문서 수·모델 수·CI 초록색만으로 이 목표를 대체하지 않는다.

| 발견 | v1.1 처리 | 실행 중 필요한 증거 |
|---|---|---|
| codec 전환·구형 손실 방지 미결정 | V2 유지, 조건부 무손실 승격, dual-read 선행, V3 손실 쓰기 거절 | 실제 구형/호환 클라이언트·서버 조합 시험 |
| 새 관측 키와 기존 ID 단절 | 서비스 ID/관측 키/내용 지문 분리, legacy 조회, 명시적 같은 기록 정정 | 행 재정렬·재가져오기·CAS 정정 시험 |
| 비교 관계 보관·권한 공백 | 일지 V3 안의 표시 전용 관계, 정확한 원계획이 있을 때 저장 | 재열기·백업·삭제·계정 격리·적응 비활성 시험 |
| 동일 구조 자동 대응 기준 모호 | 명시 의미·수·순서·종류·단위 일치 + 사용자 확인 | 미대응/누락/UNKNOWN 반례 |
| 네 형식 동시 확장으로 첫 완료 지연 | TCX R1 전체 경로 먼저, 나머지 R2 독립 확장 | R1과 전체 완료 상태 분리 |
| worktree/브랜치 지시와 저장소 규칙 충돌 | 현재 AGENTS에 맞춘 main 통합과 커밋 전 독립 검수 | 검수 diff와 실제 커밋 동일성 |

강제 데이터 변환 시점·별도 정정 레코드·새 범용 비교 DB 같은 선택은 이번 범위에 넣지 않는다. 기존 보존·권한·편집 불변식을 지키는 최소 기술안으로 결정했다. 따라서 위 여섯 항목 때문에 새로운 제품 승인 질문을 만들지 않는다. 실행 도중 실제 구조가 이 전제를 깨면 차이와 대안을 제시하며 해당 단계만 보류한다.

## 13. 장단점과 범위 확장 기준

| 선택 | 얻는 점 | 단점/비용 | 보완과 확장 조건 |
|---|---|---|---|
| 프로그래밍된 계산·검토된 해설 | 재현·수정·출처 추적이 쉽고 외부 AI로 개인 자료를 보내지 않음 | 자유 문장/사진을 자동 해석하는 범위가 좁음 | 미지원 입력을 정직하게 안내. 수요와 오류 유형이 쌓인 뒤 형식별 파서를 추가 |
| TCX 먼저 끝까지 | 의미 있는 분석부터 다음 선택까지 빨리 검증 | 다른 워치/파일 사용자는 새 분석을 나중에 받음 | 기존 가져오기는 유지하고 R2 형식별 완료를 별도 추적 |
| 원관측과 쓰임새 분리 | 같은 기록을 요약에는 쓰고 처방에는 아직 쓰지 않는 구분 가능 | 계약·시험 수가 늘어남 | 용도별 단일 투영기를 두고 화면별 자격 판단 복제를 금지 |
| 기존 암호화 일지에 근거 추가 | 계정 격리·백업·재시도 인프라 재사용 | 버전 전환과 기존 클라이언트 검증 필요 | 호환 읽기 선배포, 선택적 승격, 새 쓰기 별도 중단 가능 |
| 명시적 구간 대응 | 준비/회복/자동 랩을 잘못 비교할 위험 감소 | 모호한 파일에서는 확인 동작 필요 | 확실한 대응 후보를 한 번에 확인. 불확실한 항목만 수정 |
| 기존 후보 엔진에 연결 | 이미 정한 안전·개인 페이스·적응 범위를 유지 | 새로운 파일만으로 처방 다양성이 갑자기 늘지는 않음 | 미채택 방법은 별도 근거·스펙·수치 검수로 확장. 없는 다양성을 표시하지 않음 |

유효한 오래된 기록은 역사 비교에서 제외하지 않는다. 현재 PB/SB의 신선도 요건과 과거 분석의 날짜 범위를 혼동하지 않는다. 기기 교체·수동 수정·자료 누락은 변화의 대안 설명으로 표시할 수 있으나 자동 원인 판정을 내리지 않는다. 계산 가능한 사실을 제공하는 것과 선수의 회복·능력·향상 원인을 판단하는 것은 별개다.

계획 변경 시 기존 목표를 삭제해 완료율을 올리지 않는다. 새 요청은 `추가 / 기존 범위 교체 / 후속 보류`와 근거를 기록한다. 제품 결정·민감정보의 새 용도·새 과학적 처방 수치는 오너 결정 대상으로 남기고, 그 외 승인 범위의 호환성·오류 처리·검수 순서는 작업자가 책임지고 완수한다.

## 14. v1.2 실행 계약 보완

오너가 실행을 승인한 [종합 개선안](PROGRAMMED_ANALYSIS_REVIEW_SYNTHESIS_AND_IMPROVEMENT_PROPOSAL_2026-09-17.md)을 적용한다. 이전 13장을 축약하지 않는다. P0의 좁은 채택 근거는 [FILE_ANALYSIS 채택 결정](../../PROGRAMMED_FILE_ANALYSIS_ADOPTION_2026-09-19.md)이다. 기존 11개 묶음과 27개 시험은 유지한다.

### A. 버전 호환

| 요청 | capability 없음 또는 V2 | V2/V3 지원 |
|---|---|---|
| status | 기존 가용 상태. 전체 기록이 V2라는 보증 아님 | 가용 상태. 문서 지원 정보는 별도 |
| read/list/history | 요청 범위에 V3이 있으면 UPGRADE_REQUIRED. 조용한 제외·빈 성공 금지 | 기존 커서·페이지 크기로 양쪽 반환 |
| save | V2 유지, V3을 V2로 덮어쓰기 거절 | 새 기능 없으면 V2 유지. 명시적 근거/비교 쓰기만 V3 |
| delete/restore | V2 기존 동작. V3은 호환 앱 필요 | 소유권·revision·이력 유지, 무손실 복원만 |

HTTP 426은 구형 빌드의 실패 보존 시험 후 확정한다. 어떤 오류도 projection·초안·outbox 삭제나 저장 완료로 바꾸지 않는다. status마다 전체 계정 스캔을 하지 않는다.

### B. 가져오기 정정

같은 엔드포인트에 `correctImportedObservation` action을 추가한다. 인증 계정, documentId, operationId, expectedRevision, previousContentRevisionFingerprint, replacementObservation, confirmedChangedFields를 검증한다.

| 조건 | 결과 |
|---|---|
| 같은 operation + 같은 요청 | 최초 결과 재사용 |
| 같은 operation + 다른 요청 | OPERATION_REUSED |
| revision/이전 지문 불일치 | 충돌, 덮어쓰기 없음 |
| 삭제된 기록 | 복구하지 않음 |
| 정상 | 같은 ID 새 revision, 메모/RPE/원출처/계획 링크/완료 상태 보존 |

서버가 내용 지문을 다시 계산하고 과거 비교는 이전 관측 기준으로 남긴다. V2→V3은 정정뿐 아니라 명시적 근거 추가·비교 관계 추가에도 목적별 검증 후 허용한다. 일반 save로 불변식을 우회하지 않는다.

### C. 정체성

| 입력 차이 | 처리 |
|---|---|
| 안정적 원본 ID | 계정 범위 + 형식 프로필 + 원본 ID의 원관측 키 |
| 원본 ID 없음 | 별도 재가져오기는 후보 확인. operation 재시도만 자동 식별 |
| 값 5 / 5.0 | 같은 정규 수치 |
| 바깥 파일 행 순서 변경 | 정체성에 영향 없음 |
| 랩 순서/실제 관측 변경 | 내용 지문 변화 |
| parser 코드 버전만 변경 | 내용 의미가 같으면 새 운동/수정본으로 만들지 않음 |

일지 ID·원관측 키·내용 지문은 각각 유지한다. 허용 필드만 canonical JSON에 넣고 기존 SHA256 도구를 재사용한다. 표시 반올림·Notes·파일명·GPS·토큰은 지문에 넣지 않는다. 센서 정확도를 소수 자릿수로 주장하지 않는다.

### D. 서버 쓰기 중단

| 동작 | 신규 근거 쓰기 비활성 |
|---|---|
| 기존 V2/V3 읽기·일지 일반 수정 | 계정 권한이 유효하면 유지 |
| 새 근거·정정·새 비교·관련 승격 | 서버에서 차단 |
| 일반 save/복원으로 우회 | 실제 변경 필드 검사로 차단 |
| 설정 확인 실패 | 새 쓰기는 일시적 실패, 기존 자료 보존 |

기존 ACCOUNT/ACCOUNT_JOURNAL_V2와 계정 자격 검사를 재사용한다. 새 설정 플랫폼은 만들지 않는다. 파일 형식별 분석 활성과 서버 쓰기 허용을 혼동하지 않는다.

### 유지·추가·수정·보류

- 유지: 파일→보관→분석→비교→기존 다음 선택, P2A 해설/용어집/복귀, 11개 묶음, 기존 계정·처방 권한.
- 추가: 위 요청/정정/식별/서버 중단 표와 구형 클라이언트 반례.
- 수정: 불명확 시간은 관련 계산만 제외한다. 정상 항목 먼저 저장 가능하나 계정/인증/호환 실패 후 새 쓰기는 중단한다.
- 보류: 외부 AI·원본 데이터 레이크·새 처방 수치·자동 병합. TCX 출시로 R2 완료를 주장하지 않는다.

## 15. 2026-09-19 실행 인계

지시서에 따른 코드 구현과 로컬 검수는 [진행 보고서](../implementation/PROGRAMMED_FILE_ANALYSIS_PROGRESS_2026-09-19.md)에 단계별로 기록했다.
TCX와 CSV/JSON/GPX의 합성 저장·분석·비교·다음 선택 경로를 구현했으며, 공개 기능은 아직 켜지 않았다.
독립 검수와 기존 배포본의 자료 보존 시험은 [증거 색인](../evidence/programmed-file-analysis-2026-09-19/README.md)에 보관한다.

새 앱이 기존 서버에 보내는 호환성 필드 때문에 기존 일지 요청도 거절될 수 있음이 재현되었다.
따라서 다음 실행자는 [서버 선배포 및 공개 실행 순서](../implementation/PROGRAMMED_FILE_ANALYSIS_RELEASE_RUNBOOK_2026-09-19.md)를 먼저 따른다.
운영 서버·마이그레이션·공개 설정과 실제 공개 검증은 미완료다. 로컬 구현 완료를 이 지시서 전체 완료로 바꾸지 않는다.
