# TrainOracle 오픈소스 기반 화면 개선 최종 기획

작성일: 2026-10-15 KST
상태: 승인 범위 로컬 구현·집중 검사·타입·빌드 완료 · 미게시
로컬 검토 기준: `0b3c12f67617ff610005dbb558388c4b5899bb83`

목표는 홈부터 훈련, 일지, 오라클까지 사용자가 현재 볼 내용과 다음 행동을 구분하게 하는 것이다. 모든 항목을 큰 카드로 만들지 않는다. 실제 오픈소스의 요약, 목록, 선택 구조를 선별해서 가져오고 기존 TrainOracle 색상, 서체, 훈련 정보와 저장 방식을 유지한다.

이번 기획은 사용자가 보낸 여섯 화면의 문제와 앞선 전반 배치 검토를 함께 포함한다. 앱 설치, 서버 이전, 처방 수치 변경, 새 분석 알고리즘, 계정 기능 확대는 포함하지 않는다. 구현 및 게시 전에는 [저장소 최신 상태 정책](../operations/REPOSITORY_FRESHNESS_POLICY.md)에 따라 현재 main과 다시 대조한다.

## 1 채택 방향

[EasyPanel Templates](https://easypanel.io/templates)는 화면 부품 모음이 아니라 앱 배포 템플릿 목록이다. 목록에서 찾은 앱의 원본 저장소를 확인하고 아래 범위만 채택한다. EasyPanel의 Docker 이미지 버전과 원본 저장소의 검토 커밋은 서로 다르므로 혼용하지 않는다.

| 원본 | 가져올 부분 | 적용 방식 | 가져오지 않을 부분 |
| --- | --- | --- | --- |
| Umami | 작은 제목과 큰 값의 위계, 반응형 수치 묶음 | MIT 소스의 표시 부분을 추출해 기존 CSS로 이식 | 추적 SDK, 서버, 통계 계산, 빈 값의 0 처리, 숫자 카운트업 |
| Cal.diy | 한 줄 보기 전환의 선택 상태와 구성 | MIT SegmentedControl 구조를 기존 선택 부품에 이식하고 접근성 보완 | 예약 엔진, 로그인, 시간대 계산, 날짜 선택기의 과거 날짜 제한 |
| Memos | 작성 진입과 시간순 기록 탐색의 구분 | Home의 작성 진입과 목록 분리 방식을 기존 일지 화면에 적용 | 메모 편집기, 서버 API, 공개 공유, 권한 모델, 새 자동 포커스 |
| Formbricks | 현재 질문 하나와 이전 및 다음 진행 | 상호작용 방식만 참고 | 설문 코드 복사, 외부 임베드, 계정이나 몸 기록 전송 |
| Radix Primitives | 선택값과 키보드 조작 관리 | 같은 화면의 보기 전환에 RadioGroup을 제한적으로 사용 | 모든 이동의 탭화, 기존 리더에 Dialog 중복 적용 |

**코드 재사용과 화면 구성 참고를 구분한다.** Umami와 Cal.diy는 실제 표시 코드의 선별 이식 대상이다. Memos와 Formbricks는 흐름 참고이며 해당 앱을 앱 안에 설치하거나 통째로 복사하지 않는다.

Formbricks의 확인한 `packages/surveys` 경로는 기본 AGPLv3 범위다. 일부 SDK의 MIT를 설문 UI 전체의 라이선스로 읽지 않는다. [Typebot](https://github.com/baptisteArno/typebot.io/blob/e77b21c5b385ffe49006a742dd47b52fb6bfa79c/LICENSE)은 확인한 리비전에서 FSL 조건을 사용한다. 이번에는 Typebot 코드와 채팅형 질문 구조를 채택하지 않는다.

실제 이식 시 원본 URL, 커밋, 경로, 변경 이유와 저작권 및 MIT 고지를 기존 오픈소스 고지 체계에 기록한다. 제품 로고, 스크린샷, 캐릭터, 폰트 등의 권리까지 코드 라이선스로 일괄 허용됐다고 보지 않는다.

## 2 가져온 부품의 구현 경계

### 수치 요약

Umami의 MetricsBar와 MetricCard에서 값, 라벨, 보조 정보의 배치를 가져온다. 기존 집계 결과를 전달받는 표시 부품으로 만들며 계산과 저장 책임은 넣지 않는다.

- 값마다 단위와 실제 집계 기간을 함께 둔다. 최근 4주 거리와 최근 8주 기록 종류를 같은 기간으로 표시하지 않는다.
- 원본의 `value = 0`, `Number(value) || 0` 처리를 가져오지 않는다. 확인되지 않은 값, 없는 값, 실제 0을 구분한다.
- 증가율이나 초록 및 빨강의 좋고 나쁨 판정을 자동으로 추가하지 않는다. 운동량이 늘었다는 사실만으로 좋은 결과가 되지 않는다.
- 모바일은 짧은 값 두 개를 비교할 때만 2열로 쓴다. 큰 글씨나 320px 화면에서 공간이 부족하면 1열로 흐른다. 제목과 단위를 줄이지 않는다.
- `@umami/react-zen`, Next.js, React 19, Motion을 함께 도입하지 않는다. 현재 React 18 및 기존 CSS에 맞는 표시 부분만 이식한다.

### 보기 전환

Cal.diy의 SegmentedControl을 기준으로 같은 화면에서 `달력 / 하루씩`, `월간 달력 / 기록 묶음`처럼 보기를 바꾸는 작은 컨트롤을 만든다.

- 원본의 Tailwind 클래스는 TrainOracle의 기존 토큰과 CSS에 매핑한다. 전체 Tailwind와 전역 초기화 스타일은 넣지 않는다.
- 현재 값을 부모 화면이 소유한다. 날짜, 월, 입력 초안과 돌아갈 위치는 선택 부품이 초기화하지 않는다.
- 원본의 반복 가능한 ID 생성과 그룹 접근성은 그대로 복사하지 않는다. 확인된 React 18 호환 [Radix RadioGroup](https://www.radix-ui.com/primitives/docs/components/radio-group)을 조작 기반으로 사용하고, 화면마다 고유 이름 및 레이블과 포커스를 제공한다. 구현 때 게시된 정확한 버전을 lockfile에 고정한다.
- 선택 상태는 배경, 글자 굵기와 명확한 아이콘으로 표시한다. 회전한 CSS 선을 체크 표시로 사용하지 않는다.
- RadioGroup의 화살표 키는 선택값을 바꿀 수 있으므로, 눌러 다음 질문으로 이동하는 취향 질문 버튼에는 이 부품을 적용하지 않는다.
- 다른 페이지나 오버레이로 이동하는 버튼은 보기 전환이 아니다. 하단 내비게이션과 오라클의 취향 및 읽을거리 목적지는 기존 이동 계약을 유지한다.

Radix Tabs나 Dialog는 이번 필수 도입 대상이 아니다. 특히 `useReaderDialog`가 이미 뒤로가기, 포커스와 스크롤을 관리하므로 새로운 Dialog 엔진을 덧씌우지 않는다. Tabs를 추후 도입하더라도 `forceMount`만으로 비활성 패널 숨김과 초안 보존이 해결된다고 보지 않는다.

### 달력

날짜표는 기존 엔진을 유지한다. Cal.diy DatePicker는 기본 과거 날짜 제한과 Date 변환을 포함하므로 직접 이식하지 않는다. 이름이 비슷한 `CalendarSwitch`도 월 이동 부품이 아니라 연결 캘린더 설정용이므로 사용하지 않는다.

[DayPicker의 월 이동 구조](https://daypicker.dev/docs/navigation)는 참고할 수 있지만 패키지는 이번에 추가하지 않는다. 기존 ISO 날짜, 오늘, 선택일, 7열, 오전 및 오후, 훈련 역할, 장식 대표 그림, 달력 복귀 계약을 유지한다. 훈련의 의미를 작은 점이나 예약 가능 여부로 대체하지 않는다.

## 3 공통 화면 구성

| 사용 목적 | 기본 모양 | 기준 |
| --- | --- | --- |
| 다른 곳으로 이동 | 아이콘, 짧은 제목, 방향 표시가 있는 가로 행 | 기존 CategoryCard의 작은 행 형태를 재사용한다. 큰 설명과 큰 빈 공간을 넣지 않는다. |
| 같은 화면의 보기 전환 | 작은 선택 바 | Cal.diy 구조와 Radix 조작 기반. 실제 목적지 이동과 구분한다. |
| 숫자 비교 | 값과 단위 중심의 작은 요약 묶음 | Umami 표시 구조. 있는 값만 사용한다. |
| 실제 훈련 | 시간대, 역할, 이름, 핵심 구성, 열기와 기록 행동 | 기존 훈련 표시에서 순서와 간격을 고친다. 예약 앱의 내용으로 대체하지 않는다. |

훈련은 파랑, 일지는 황토색 계열, 오라클은 보라, 몸 기록은 분홍, 기록 입력은 청록의 기존 카테고리 색을 유지한다. 본문 전체를 색칠하지 않고 아이콘, 작은 배경, 선택 상태와 필요한 행동에 사용한다. 훈련 역할 및 위험 색은 별도 의미이므로 카테고리 색으로 덮지 않는다.

카드 중첩은 줄이고 같은 그룹은 하나의 표면에서 행으로 나눈다. 화면마다 큰 선택 카드, 밑줄 링크, 아코디언, 검정 버튼을 같은 비중으로 섞지 않는다. 이 규칙은 [시각 기준](../../docs/UX_UI_VISUAL_STANDARD.md)과 [작업 중심 UX 계획](TASK_FOCUSED_UX_PATCH_PLAN_2026-10-08.md)을 이어받는다.

## 4 첨부한 여섯 화면의 수정 결정

### 사진 1과 6 오라클

상단의 큰 세 선택 상자를 낮추고 목적지별 역할을 분명하게 한다. `내 훈련`은 현재 위치, `러닝 취향`과 `읽을거리`는 해당 화면으로 이동하는 경로로 유지한다. 현재 코드의 이동 콜백을 임의로 같은 페이지 탭 상태로 바꾸지 않는다.

내 훈련 요약에서는 거리와 훈련 종류를 작은 수치 묶음으로 배치하고 각각의 집계 기간을 표시한다. 최근 기록과 훈련표는 짧은 이동 행으로 정돈한다. 일반 훈련 글은 개인 결과와 분리하여 `훈련 읽을거리`라는 짧은 제목 및 글 제목만 보이고, 본문은 열어서 읽는다.

데이터가 적을 때 빈 지표를 늘리지 않는다. 확인된 결과는 남기고 예시는 예시라고 표시한다. 읽기 실패, 분석 제외와 확인 대기를 단순한 기록 없음으로 바꾸지 않는다. 현재 연결된 수행 검토가 없어서 표시되는 일반 읽을거리를 분석 전체가 없다는 조건으로 잘못 바꾸지 않는다.

관련 파일: `screens/Trends.tsx`, `screens/trends/PersonalOraclePanel.tsx`, `screens/home/HomeCoachingSummary.tsx`, `styles/category-cards.css`.

### 사진 2 훈련 만들기

현재 질문을 먼저 보이게 하고 종목 선택은 읽기 쉬운 2열을 유지한다. `10km 한 달 훈련표`는 별도 경로임을 알 수 있는 작은 추천 행으로 두며, 종목 질문보다 큰 별도 제목 화면을 추가하지 않는다. 개인 계획 파일은 하단 보조 행으로 낮춘다.

일반 종목의 `10km`와 목표형 `10km 한 달 훈련표`를 합치지 않는다. 후자는 9.5일 마이크로사이클 3개, 전자는 기존 종목 및 기록 기반 계획 경로다. 기존 목표 목록과 시작일 및 D-day 기능을 보존하고 이 레이아웃 작업으로 증량이나 회복량을 정하지 않는다.

제목에 보이는 사각 테두리는 실제 포커스 원인과 CSS 적용 범위를 먼저 확인한다. 비대화형 제목의 프로그램 포커스 표현만 조정하고, 키보드로 조작하는 버튼의 포커스는 남긴다. 전역 `outline: none`은 금지한다.

관련 파일: `screens/PlanBeta.tsx`, `components/instant-plan/InstantPlanEntryForm.tsx`, `screens/plan-beta/GoalTrainingProgramFlow.tsx`와 해당 선택 화면 CSS.

### 사진 3 지난 일지

`일지 / 몸 기록`은 콘텐츠 종류 선택, `월간 달력 / 기록 묶음`은 일지 안의 보기 선택으로 크기와 위치를 구분한다. 두 단계 모두 같은 큰 카드처럼 보이는 상태를 없앤다. 달력 제목과 월 이동을 한 묶음으로 정렬한다. 선택한 날짜의 기록은 기존 하루 리더에서 바로 읽도록 유지하고, 달력과 리더의 날짜, 스크롤 및 포커스 복귀를 보존한다. 새 인라인 기록 패널을 추가하지 않는다.

Memos처럼 작성 진입과 기록 목록의 역할을 나누되 자유 메모 편집기를 일지 작성기 대신 넣지 않는다. 월간 달력이나 기록 묶음의 기본 선택을 임의로 바꾸지 않는다. 기록 묶음의 기존 9일 및 10일 교대 구간을 실제 훈련 계획의 마이크로사이클과 동일한 것으로 이름 붙이지 않는다.

달력의 훈련 역할, 오전 및 오후, 꾸민 날의 대표 그림은 유지한다. 꾸미기 편집 도구는 다시 달력 첫 화면에 펼치지 않는다. 원문 종이의 좌표나 스티커 저장값을 목록 크기에 맞춰 다시 쓰지 않는다.

관련 파일: `screens/JournalArchive.tsx`, `screens/JournalArchiveSummary.tsx`, 월간 및 주기별 달력 표시와 `journal-calendar.css`.

### 사진 4 하루 훈련

이 화면은 우선순위가 가장 높다. 현재 일부 요약에서는 훈련 이름과 전체 시간 다음에 기록 버튼이 먼저 나오고 실제 처방을 여는 경로가 약하다.

기본 순서를 `오전 또는 오후와 훈련 역할 → 훈련 이름 → 핵심 거리 또는 시간 및 반복 → 훈련 내용 보기 → 운동 기록`으로 바꾼다. 이미 상세 내용이 펼쳐진 상태라면 열기 버튼을 중복 표시하지 않고 실제 운동 순서 뒤에 기록 행동을 둔다.

- 첫 카드에서 메인훈련인지 회복인지 기존 분류에 따라 바로 보인다. 역할을 오전 및 오후로 추정하지 않는다.
- 상세를 열면 달리기, 사이 휴식, 반복과 정리가 현재 처방 그대로 나온다. 새 총시간이나 거리 환산을 만들지 않는다.
- 핵심 수치, 빠르기 및 RPE, 휴식, 실제 적용 불가와 안전 상태는 실행 판단 전에 확인할 수 있어야 한다. 계산 원리와 용어 설명만 뒤로 보낸다.
- 날짜 이동, 달력 전환, 계획 수정, 기록 작성 후 돌아오기를 같은 날짜와 세션에 연결한다.
- 실제 일지 저장과 계획 완료 체크를 합치지 않는다. 연계가 없으면 완료한 것처럼 표시하지 않는다.

일반 계획만 고치고 조정 계획을 남기지 않는다. `PlanSchedulePreview`, `ActivePlan`, `InstantPlanTodayView`, `AdjustedPlanSchedule`, `AdjustedPlanScheduleV3`, `MultiAdjustedPlanScheduleV3`와 `PlanDayReader`의 변형을 함께 확인한다. 조정 계획의 원본 보존 확인 등 필수 단계는 유지한다.

### 사진 5 러닝 취향

첫 화면의 주 행동은 `질문 3개 시작` 하나다. 매니저는 제목과 시작 행동 근처에 배치하고 독립된 빈 블록처럼 떨어뜨리지 않는다. 읽을거리, 친구 비교, 프로필 설정은 작고 명확한 보조 행으로 구분한다.

한 번에 한 문항을 보여주는 기존 구조를 유지하며 Formbricks의 활성 질문 중심 흐름을 참고한다. 현재 선택의 짧은 피드백 뒤 다음 질문으로 이동하고 이전 질문으로 돌아가면 답이 남는다. 이미 구현된 140ms 피드백을 확인한 뒤 보완하며, 재미를 위해 가짜 분석 대기 시간을 추가하지 않는다. 움직임 줄이기 설정에서도 선택과 이동이 명확해야 한다.

처음 세 질문은 `STRUCTURE`(계획 취향) 축으로 유지한다. 이를 전체 러닝 성격, 능력 검사, 여섯 축의 완성 결과처럼 표현하지 않는다. 결과를 먼저 보여주고 다른 취향은 선택적으로 이어간다. 응답하지 않은 축의 점수는 만들지 않는다.

게스트 응답이 새로고침하면 사라지는 조건은 시작과 결과에서 짧게 알린다. 친구 비교의 수동 입력은 게스트와 계정 사용자 모두 가능하며 친구 자료는 화면 안에서 임시로만 사용한다. 닫거나 새로고침하면 사라지는 조건을 유지한다. 연결 초대 비교는 기존 계정, 저장 응답 및 준비 상태 조건을 유지한다. 외부 공유의 별도 동의와 계정 공개 관문을 우회하지 않는다.

관련 파일: `screens/OracleProfileExperience.tsx`, `OracleProfileV2.tsx`, `OracleFriendComparisonV2.tsx` 및 기존 질문 표시 부품.

| 화면 | 적용할 변경 | 유지할 것 |
| --- | --- | --- |
| 홈 | 실제 다음 훈련을 내용이 먼저 보이는 카드로, 최근 일지를 짧은 날짜 행으로, 분석 결과는 작은 요약으로 | 앱 정체성, 현재 생성 이미지, 상태별 실제 다음 행동 |
| 기록 종류 선택 | 큰 세로 카드의 빈 공간을 줄이고 목적별 짧은 선택으로 | 서로 다른 기록 양식, 기존 저장 및 임시 저장 |

| 읽을거리 | 첫 글의 긴 본문 대신 제목 및 짧은 소개, 주제와 목록으로 이동 | 전체 글과 근거를 찾는 경로 |

| 계획 비교 | 큰 화면에서 같은 항목의 요약끼리 나란히, 전체 일정은 넓게 | 작은 화면의 세로 비교와 변경 전후 조건 |
| 몸 기록 이력 | 기존 이력을 읽기 좋은 날짜 및 부위별 행으로 정리 | 저장소 분리, 동기화, 충돌 보존, 원본 및 이전 기록 |

이미 잘 맞는 2열 몸 부위 선택, 순서가 중요한 목표 기록 목록, 달력 7열, 큰 화면의 개인 요약 및 코칭 구분을 변화 자체를 위해 다시 바꾸지 않는다. 새 캐릭터 제작이나 3D 도입은 이번 배치 개선의 선행 조건이 아니다. 기존 승인 에셋을 정확한 제목과 행동 곁에 재배치한다.

## 6 크기와 이동 규칙

- 현재 간격, 서체, 둥글기와 카테고리 토큰을 재사용한다. 원본 앱의 색상과 우리 앱의 색상을 섞어 별도 디자인 체계를 만들지 않는다.
- 화면당 현재 작업 제목을 명확히 둔다. 동일한 제목을 작은 라벨과 큰 제목으로 반복하지 않는다.
- 입력은 좁고 집중된 폭, 달력과 결과는 더 넓은 폭을 허용한다. 기존 모바일 프레임 너비 하나를 전역 변경하지 않고 화면 유형별로 적용한다.
- 모바일 320px 및 375px, 큰 글씨에서도 터치 영역 44px을 유지한다. 높이를 줄이기 위해 글자나 버튼을 축소하지 않는다.
- 핵심 선택을 가로로 숨기지 않는다. 날짜 레일의 다음 날짜 일부 노출은 의도된 탐색 표시인지 확인하고, 모든 부분 노출을 넘침 오류로 처리하지 않는다.
- 하단 탭과 고정 행동 영역에 가려지는 본문이 없게 안전 여백을 둔다. 브라우저 주소창, 화면 회전, 키보드가 열린 상태를 포함한다.
- 카드 전체 클릭과 내부 버튼이 중첩되지 않게 한다. 제목은 버튼처럼 꾸미지 않고, 버튼은 이름과 실제 결과가 일치해야 한다.
- 뒤로가기, Escape, 닫기는 기존 최상단 화면부터 처리한다. 탭 선택이나 보기 전환이 입력을 버리지 않도록 기존 이탈 확인을 유지한다.
- 사용자 스크롤을 강제로 계속 이동시키지 않는다. 단계 진입의 필요한 포커스와 원래 날짜 및 읽던 위치의 복귀를 분리한다.

| 상태 | 기본 화면에서 보여줄 것 | 금지할 것 |
| --- | --- | --- |
| 확인된 결과 있음 | 실제 요약과 해당 내용을 여는 행동 | 임의 점수와 건강 또는 훈련 성공 해석 |
| 기록이 적음 | 있는 정보와 적합한 기록 또는 예시 진입 | 물음표와 빈 지표 카드 반복 |
| 실제 기록 없음 | 기록 시작 또는 명확한 예시 | 개인 분석처럼 보이는 가짜 수치 |
| 읽는 중 또는 확인 대기 | 짧고 정확한 상태, 가능한 기존 행동 | 빈 데이터로 확정하거나 오류 숨기기 |

| 계정 전환 | 해당 소유자 데이터가 확인된 뒤 표시 | 다른 계정의 값, 장식, 초안 노출 |

이 표는 새 저장 및 분석 규칙을 정의하지 않는다. 기존 상태를 화면에서 정확하게 표현하기 위한 기준이다.

## 8 구현 순서와 파일 소유권

### 1단계 공통 부품과 우선 화면

통합 담당자가 현재 main, 관련 변경과 파일 소유권을 확인한다. Umami 요약 표시 및 Cal.diy 보기 전환 이식 범위를 고정하고 출처 고지를 준비한다. 공통 CategoryCard와 선택 표시 CSS는 한 담당자만 변경한다.

첫 적용 화면은 하루 훈련, 오라클 요약, 지난 일지다. 세 화면에서 실제 수치, 다른 단계의 선택, 날짜와 상세 연결을 확인한 뒤 같은 부품을 나머지 화면에 확장한다. 첫 세 화면만 완성하고 전체 적용 완료라고 보고하지 않는다.

### 2단계 화면별 병렬 작업

| 작업 묶음 | 소유 영역 | 다른 작업과의 경계 |
| --- | --- | --- |
| 훈련 | 훈련 생성 진입, 일정 변형, 하루 리더 내용, 비교 | 처방 엔진 및 저장 스키마를 수정하지 않음 |
| 일지와 기록 | 일지 탐색, 기록 종류 선택, 작성 배치, 컨디션과 이력 | 장식 좌표 및 몸 기록 저장소를 수정하지 않음 |
| 오라클과 취향 | 요약, 읽을거리, 취향 진입 및 결과 배치 | 집계 알고리즘, 축별 채점, 계정 공개 조건을 수정하지 않음 |
| 통합 | 공통 표시 부품, CSS, 홈, 더보기, 좁은 화면과 큰 화면 | 공유 파일 변경을 한곳에서 조정 |

깊은 구현 판단은 Sol 6.1, 명확한 문구 및 CSS 조정과 독립 검토는 Luna를 사용하는 기존 역할 구분을 따른다. 한 파일을 여러 작업자가 동시에 수정하지 않는다. 공통 부품의 사용 계약을 먼저 전달한 뒤 병렬 화면 작업을 진행한다.

### 3단계 연결과 회귀 확인

화면별 클릭 결과, 입력 후 돌아오기, 같은 날짜 및 월 복귀, 저장 실패를 연결해서 확인한다. 해당 변형과 실제 위험이 있는 경계를 고친 뒤 최종 묶음에서 관련 검사와 빌드를 한 번 수행한다. 새 검사에는 저장소의 결함 주입 지침을 적용한다. 매 문구 수정마다 전체 검사를 반복하지 않는다.

## 10 제외와 완료 구분

이번 변경에서는 훈련 증량과 회복 수치, 페이스 및 안전 규칙, 계정과 저장소, 포인트, 새로운 공유, 새 서버, 분석 SDK, 전면 React 업그레이드를 건드리지 않는다. 오래된 Handoff 시안의 신규 코치 기능이나 미채택 자동 점수를 이번 디자인 개선에 함께 구현하지 않는다.

계획 완료와 앱 완료를 구분한다. 이번 산출물은 원본 조사와 채택 결정 및 구현 순서다. 코드 이식, 라이선스 고지 반영, 로컬 검사, 병합, 배포와 실제 계정 확인은 각각 별도로 보고한다. 새 디자인을 숨기기 위한 별도 배포 주소를 만들지 않고 기존 정식 경로를 기준으로 통합하며, 게시 권한은 구현 요청과 분리해서 따른다.
