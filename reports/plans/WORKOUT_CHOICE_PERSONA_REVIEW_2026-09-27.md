## 1. 공격적 결론

**이 기능의 실패는 ‘버튼이 없다’보다 ‘눌렀더니 무엇이 바뀌었는지 모른다’에서 발생할 가능성이 크다.**

단순한 `+/-`, `다른 훈련`, `덜 힘들게`만 붙이면 다음 네 문제가 남는다.

1. 총거리와 한 번 거리가 섞여 운동량이 크게 달라진다.
2. 더 쉬워졌다는 문구와 실제 속도·회복·횟수가 충돌한다.
3. 다양하게 고른 것 같지만 같은 훈련의 숫자만 바뀐다.
4. 초안·확정 계획·이미 한 운동이 섞여 일지와 다음 주기의 근거가 오염된다.

따라서 표면은 단순하게 하되 **행동의 정확한 의미, 완전한 구성 교체, 저장 상태, 현재 권한**을 내부에서 유지하는 안으로 고쳤다. 새로운 훈련의 용량 적합성을 이번 UX 검토로 승인하지 않는다.

### 무작위 검토 자체에 대한 비판

- 삭제/안전 변경 등 비정상 요청이 많이 섞여 실제 사용성 평가를 대신하지 못한다.
- 행동 코드의 출현 횟수는 기능 커버리지나 상태 전이 커버리지가 아니다.
- 공급 근거·대상 적합성·운동 결과는 이 자료로 검증되지 않는다.
- 자동 생성된 순서에는 `뒤로` 이후 편집 버튼 등 접근할 수 없는 요청이 있다. 구현 테스트에서는 DOM에서 가능한 행동만 누르는 탐색과 API/상태층 잘못된 호출 시험을 분리해야 한다.
- 동일 작성자가 기획과 검토를 했으므로 공통된 오해가 남을 수 있다. 실제 앱 구현 후 별도 검수자가 화면을 설명 없이 사용하게 해야 한다.

| T07 | 홀수 반복에서 나눠 하기 | 임의 올림/버림/잔여 숨김 없음 |
| T08 | 느리게→원래대로→빠르게 | 초/페이스 부호 혼동 없음, 근거 범위 밖 목표 없음 |
| T09 | 조절 연타→닫고 재열기→더 늘리기 | 기준점을 초기화해 제한 우회하지 않음 |
| T10 | 안전 이상 신호→원래대로→적용 | 이상 신호가 유지되고 변경 실행 차단 |
| T11 | 적용 두 번→첫 응답 유실→재시도 | 논리적 변경 1회, 불확실한 저장을 성공 처리하지 않음 |
| T12 | 오프라인 변경→다른 기기 수정→온라인 | 두 수정본 보존, 충돌 선택, 조용한 덮어쓰기 없음 |
| T13 | 오후 훈련 조절→달력→일지 | 오전/다른 날짜 불변, 같은 저장 세션 연결 |
| T14 | 이미 한 훈련→다른 방법 | 과거 수정 대신 다음 가능한 훈련 경로, 실제 기록 보존 |
| T15 | 키보드/스크린리더로 조절·근거·취소 | 스와이프 의존 없음, 포커스·변경 알림 일관 |
| T16 | 320px·글자 확대·모션 감소 | 수행 필수 정보 전부 읽힘, 가로 넘침 없음, 행동 동일 |

## 5. 장점과 남는 단점

| 관점 | 얻는 점 | 남는 단점 | 대응 |
|---|---|---|---|
| 입문 사용자 | 설계 용어 없이 바로 할 훈련 | 정보가 너무 없으면 왜 다른지 모름 | 차이 1줄, 이유 상세, 적격성을 짧게 표시 |
| 숙련 선수 | 정확한 숫자·반복·세트, 빠른 미세 변경 | 자유 입력보다 제약이 있음 | 가능한 전체 구성 탐색, 필요 범위를 다음 근거 묶음으로 확대 |
| 선수/코치 | 같은 수치 원본과 근거 확인 | 새로운 조합 검토가 지속적으로 필요 | 공통 근거 재사용, 배치 정책과 개별 구성을 분리 |
| UX | 즉시 변화·undo가 탐색 부담 완화 | 너무 많은 조절은 오히려 결정을 방해 | 기본 카드 1개, 조절 2~3개, 나머지는 더 조절 |
| 신뢰 | 무엇이 바뀌었는지 보임 | ‘확정 전’ 상태를 계속 놓칠 수 있음 | 미리보기 표식, 마지막 적용, 저장 상태를 같은 위치에 |
| 운영 | 수치 임의 생성 없이 재현 가능 | 공급 검토가 속도를 좌우 | 버튼 개발과 동시에 실제 공급·채택을 핵심 작업으로 관리 |

## 6. 추가로 발견해 기획에 보강할 사항

1. **예상 시간과 상한의 구별:** 회복을 늘리면 세션이 더 길다. '덜 힘들게'를 '짧게'로 자동 해석하지 않는다.
2. **근력·점프·교차훈련:** 기록한 여러 운동을 달리기 거리로 억지 변환하지 않는다. 현재 러닝 처방 편집 범위 밖의 활동을 수정하지 않고 실제 수행에 별개 보존한다.
3. **휴식일:** OFF에서 `다른 훈련`을 통해 새 MAIN을 추가하는 우회 통로를 만들지 않는다. 쉬는 날 변경은 별도의 일정·노출 검토를 거친다.
4. **여행·자정·시간대:** 날짜가 바뀌어도 '지금 편집 중인 세션'이 다음날 세션으로 치환되면 안 된다. 날짜 표시와 슬롯 identity를 분리한다.
5. **전문 단위:** 트레드밀 km/h 표시는 기존 목표의 단위 변환이고 새로운 생리학 모델이 아니다. 속도 단위 선택은 최초 필수 질문이 아니다.
6. **좋아요와 추천:** 마음에 든 훈련 저장은 UI 선호다. 훈련 완료·효과·안전·체력 향상 증거로 사용하지 않는다.
7. **바꾸지 않아도 성공:** 탐색 없이 오늘 훈련을 수행할 수 있는 기본안을 유지한다. 조절을 많이 해야 좋은 사용자라는 흐름을 만들지 않는다.
8. **실제 시행착오 수집:** 불만족 이유는 '시간이 길어요/장소가 안 맞아요/다른 방식이 좋아요' 같은 선택형으로만 선택적으로 받는다. 매번 이유를 요구하지 않으며 민감한 메모·기록 원문을 분석 로그로 보내지 않는다.
