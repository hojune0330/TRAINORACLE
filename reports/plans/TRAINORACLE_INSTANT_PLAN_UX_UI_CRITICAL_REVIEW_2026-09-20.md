## 판정

**전략은 유지하되, 현재 기획을 그대로 UI로 구현하는 것은 권하지 않는다. 단순한 화면을 만드는 원칙은 있지만, 적게 생각하고 바로 행동하게 만드는 설계는 아직 덜 닫혀 있다.**

앞선 기획에서 가장 먼저 고칠 것은 세 가지다.

1. 한 줄 자유 입력을 기본으로 확정한 결정.
2. 프로그램을 채택하는 첫 결과와 매일 수행하는 화면을 모두 ‘오늘 훈련’으로 취급한 결정.
3. 제작자 프로그램의 존재와 정체성을 지나치게 뒤로 숨긴 결정.

문서의 입력 필드 수·버튼 수·응답 속도만으로 UX 완성도를 판단하면 안 된다. 사용자에게 남긴 추론, 생활에 맞는지 판단하는 부담, 버튼의 실제 의미, 잘못 입력한 뒤 복구하는 비용까지 포함해야 한다.

## 핵심 발견

| 우선순위 | 발견 | 기획 수정 |
|---|---|---|
| P0 | 첫날 훈련만 보고 전체 프로그램을 시작하게 됨 | 기간·횟수·시간 부담·첫 일정의 최소 약속을 시작 전에 표시 |
| P0 | 미니멀함 때문에 실제 수행 지시까지 접힐 수 있음 | 실행 정보는 보이고 원리·출처의 긴 설명을 접기 |

P0는 첫 제품 흐름을 확정하기 전에 닫아야 할 문제다. 아직 만들어지지 않은 새 화면의 관찰된 결함을 뜻하지 않는다. 아래에서 문서상 확인, 기존 화면 관찰, 사용성 가설을 구별한다.

## 1. 한 줄 입력은 간편함의 증거가 아니다

**기획상 확인:** §2 A는 `5km 25분 / 5km 22분 목표`라는 문장을 입력하고 파서의 해석을 확인하도록 한다.

**위험 가설:** 사용자는 거리·숫자·단위·목표라는 표현을 조합해야 한다. 모바일에서는 문자/숫자 키보드를 바꾸고 `25:30`, `25.30`, `25분30초` 중 어떻게 써야 할지 생각할 수 있다. 제한된 문법만 받으면 간단한 대화 입력처럼 보이면서 실제로는 문법을 맞추게 하는 UI가 된다.

**수정 권고:** ‘한 번의 짧은 입력 묶음’은 유지하되, 자연어가 기본이라는 결정은 해제한다.

```text
내 기록                         목표
[ 5km ▾ ]     [ 25 분 ] [ 00 초 ]

              내 계획 받기
```

- 위는 위계 예시다. 선택 항목마다 별도 화면으로 이동하지 않는다.
- 종목이 제작자 링크/기존 설정에서 확정되면 미리 채우고 수정 위치만 남긴다.
- 시간은 숫자 키패드로 입력한다. 자동 서식은 숫자를 바꾸거나 커서를 예측 불가능하게 움직이지 않아야 한다.
- 기록/목표 의미와 분·초 라벨은 입력 후에도 남는다. 플레이스홀더만 쓰지 않는다.
- 기존 기록을 재사용하면 값을 보이고 즉시 계속할 수 있게 한다.
- 자연어·붙여넣기는 보조 입력 후보로 유지한다. 사용자 실험에서 실제로 유리하면 기본안이 될 수 있다.

**수용 기준:** 같은 모바일 과업에서 입력 시간뿐 아니라 키보드 전환·수정·의미 오해를 비교한다. 잘못 해석된 기록/목표로 제출한 경우는 완료 성공으로 세지 않는다. 필드가 하나냐 세 개냐는 합격 기준이 아니다.

## 2. 첫 결과는 프로그램을 이해하는 화면이어야 한다

**기획상 확인:** §2 B는 ‘오늘의 훈련’에 큰 비중을 두고 전체 일정을 링크로 접은 상태에서 `이 계획 시작`을 요구한다.

**위험 가설:** 오늘 훈련만 괜찮아 보여 시작했는데 이후 횟수·긴 훈련·주말 배치가 생활과 맞지 않을 수 있다. 오늘이 휴식일이면 사용자는 프로그램을 받은 가치 자체를 느끼기 어려울 수도 있다.

**수정 권고:** 처음 채택할 때와 매일 사용할 때의 정보 위계를 분리한다.

```text
내 추천 프로그램 / [제작자]의 [프로그램]

[기간] · 이 기간에 훈련 [횟수]
보통 [소요시간] / 가장 긴 훈련 [시간 또는 범위]

첫 훈련   [날짜]   [핵심 내용]
이번 일정 [날짜별 간단한 흐름]

[ 이 일정으로 시작 ]
시작일·요일 바꾸기       전체 훈련
```

- 값은 실제 승인된 프로그램에서 계산한다. 불명인 소요시간을 만들어 넣지 않는다.
- 9일·10일 주기라면 그 주기의 횟수로 보여준다. 억지로 ‘주 N회’로 바꾸지 않는다.
- 긴 훈련처럼 생활 제약을 크게 만드는 항목은 평균값 뒤로 감추지 않는다.
- 시작일·요일 수정은 조건부 생활 조정이다. 방법론·강도·주기 유형을 고르는 고급 설정과 구별한다.
- 아직 허용된 일정 변환이 없다면 편집 버튼으로 가장하지 않고 제공 범위를 정확히 표시한다.

**수용 기준:** 시작 버튼을 누르기 전에 사용자가 ‘언제부터, 얼마나 자주, 얼마나 시간을 쓰는 계획인지’를 설명할 수 있어야 한다. 날짜를 바꿀 때 기록 입력부터 다시 시작하지 않아야 한다.

## 3. 미니멀 UI가 수행 정보를 숨기면 안 된다

**기획상 확인:** §2 C는 ‘핵심 내용 한 줄’과 `훈련 보기`를 제시하지만, 실행에 꼭 필요한 정보와 긴 근거를 나누는 UI 명세는 없다.

**위험 가설:** 준비·본운동·회복·정리, 목표 페이스의 단위가 접혀 있으면 사용자가 훈련을 추측하거나 여러 화면을 오가야 한다. 한 줄 제목이 간단한 운동을 뜻하지는 않는다.

**수정 권고:** 재방문 오늘 화면에는 실제 수행 정보를 읽을 수 있게 펼친다.

```text
[제작자] · [프로그램] · [현재 회차]
오늘 [날짜] · [훈련 이름]

준비       [확정된 지시]
본운동     [분량·반복·해당 단위의 페이스]
사이 회복  [확정된 시간·방식]
정리       [확정된 지시]

오늘은 어려워요          왜 이 훈련인가요?
수행 후: 훈련 기록 남기기
```

- 필요하지 않은 항목은 만들지 않는다. 복잡한 세션은 기존 처방 의미를 보존해 묶는다.
- `400m 한 번의 시간`과 `1km당 페이스`는 바로 옆 라벨로 구별한다. 숫자만 크게 보이고 단위는 읽히지 않는 UI를 피한다.
- **기본 표시:** 실행 수치/순서, 기준의 현재성 문제, 적용 차단, 저장 실패 등 현재 행동을 바꾸는 상태.
- **펼치기:** 훈련 원리, 긴 출처, 계산 방식, 변경 이력 상세.
- 200% 글자 확대에서는 세로 스크롤을 허용한다. 모든 지시를 한 화면에 넣기 위해 글자를 줄이지 않는다.

**수용 기준:** 화면을 본 사용자가 ‘무엇을, 어떤 순서로, 어느 정도, 중간에 어떻게 쉬면서’ 수행하는지 설명할 수 있어야 한다. 실제 코치 지시의 누락 여부는 별도 도메인 검토로 확인한다.

## 4. 모든 화면에 큰 버튼 하나가 필요한 것은 아니다

**기획상 확인:** `내 계획 받기`, `이 계획 시작`, `훈련 보기`가 핵심 행동이다. 실제 측정기 없이 측정 시작처럼 표시하지 말라는 경계는 이미 있다.

**위험 가설:** ‘시작’이 계획 등록인지 지금 운동 시작인지 모호하다. 이미 오늘 훈련을 읽을 수 있는데도 `훈련 보기`를 누르게 하면 불필요한 경유가 된다.

**수정 권고:** 버튼 수보다 동작 의미를 명확히 한다.

| 위치 | 권장 행동 | 의미 |
|---|---|---|
| 일반 입력 | 내 계획 받기 | 필요한 사실을 확인하고 추천 결과로 이동 |
| 제작자 소개, 개인화 전 | 내게 맞춰 보기 | 선택한 원본을 적용 가능한지 확인 |
| 확정 가능한 결과 | 이 일정으로 시작 | 보이는 프로그램·기준·시작일을 확인하고 활성화 |
| 오늘 훈련 | 실행 정보 자체를 바로 표시 | 읽고 운동하러 나가는 것도 성공 |
| 추가 안내가 필요한 세션 | 훈련 순서 자세히 | 실제 추가 내용이 있는 경우만 제공 |
| 수행 후 | 훈련 기록 남기기 | 수행 보고/기록을 작성. 측정 성공과 구별 |

로그인이 필요하면 `계정에 저장하려면 로그인`이라는 실제 조건을 적용 지점에서 보여준다. 로그인 완료·취소·뒤로 가기 후 같은 프로그램과 입력으로 돌아오게 한다. 결과를 버리고 첫 화면으로 보내지 않는다.

**수용 기준:** 버튼을 누르기 전에 다음에 일어날 일을 설명하게 한다. 오늘 훈련을 확인하고 앱을 닫은 사용자를 클릭 부족으로 실패 처리하지 않는다. 다만 앱을 닫았다고 실제 수행을 추정하지도 않는다.

## 5. 목표 입력은 결과의 약속까지 정직해야 한다

**기획상 확인:** 목표 페이스를 현재 능력으로 쓰지 않는 규칙과 목표만 있는 사용자를 위한 시작 프로그램 채택 작업이 있다. 결과 제목과 기대 수준은 덜 구체적이다.

**위험 가설:** `5km 22분 목표`를 넣고 기간이 있는 프로그램을 받으면 ‘이 기간 후 22분을 달성하도록 개인화됐다’고 읽을 수 있다. 내부 계산이 보수적이어도 카피가 더 큰 약속을 할 수 있다.

**수정 권고:** 목표와 이번 프로그램의 역할을 분리해 가까이 표시한다.

> 내 목표: 5km 22분  
> 이번 프로그램: [검토된 시작 단계의 실제 목적]

목표를 저장했지만 처방에 반영하지 않았다면 개인화를 과장하지 않는다. 시작 단계 후 자동 적응이 아직 없으면 자동으로 다음 수준에 맞춰진다고 암시하지 않는다. 실제 후속 프로그램이나 다음에 필요한 확인만 안내한다.

**수용 기준:** 사용자가 이 프로그램의 목적과 목표의 관계를 설명할 수 있어야 한다. 목표 달성/기간 보장의 오해가 반복되면 입력보다 결과의 제목·구조부터 고친다.

## 6. 따라하기 상품의 존재와 원본성을 남겨야 한다

**기획상 확인:** §4는 일반 홈에서 `다른 프로그램 보기`를 열어야 제작자 메뉴를 볼 수 있게 한다. 오늘 화면에는 제작자 정체성의 표시가 명시되어 있지 않다.

**위험 가설:** 일반 방문자는 두 번째 핵심 상품의 존재를 모르고 지나갈 수 있다. 제작자 링크 유입자는 시작한 뒤 평범한 체크리스트만 남으면 자신이 왜 이 프로그램을 골랐는지 느끼기 어려울 수 있다.

**수정 권고:** 두 경로의 공통 엔진과 저장은 유지하되, 선택한 사람과 프로그램은 화면에 남긴다.

- 첫 방문: 자동 추천 입력 아래 **대표 제작자 프로그램 한 개**를 보조 위계로 노출한다. 자동 추천과 똑같이 큰 버튼 두 개로 경쟁시키지 않는다.
- 탐색 이름: `다른 프로그램`보다 `선수·코치의 프로그램`처럼 목적을 드러낸다. 실제 공급자 구성에 맞는 명칭을 사용한다.
- 프로그램 소개: 실제 대상, 기간·훈련 부담, 기록 없이 시작 가능한지, 첫 훈련 미리보기를 보여준다.
- 결과/오늘/재방문: 제작자·프로그램명·현재 회차와 원본 관계를 짧게 유지한다.
- 원본 관계 문구: 실제로 해당하는 `같은 구성 · 페이스만 조정` 또는 `[원본] 기반` 한 가지를 사용한다. 여러 배지를 나열하지 않는다.
- 인물 이미지와 말은 실제 사용이 허용된 자료만 쓴다. 가짜 추천사·팔로워 수·개인 코칭 암시를 만들지 않는다.
- 이미 진행 중인 사용자의 오늘 화면을 다른 상품 홍보로 밀어내지 않는다.

**수용 기준:** 신규 사용자가 자동 추천과 따라하기가 모두 가능함을 알아차리되 자동 경로에서는 상품 탐색을 강제하지 않는다. 제작자 경로에서는 시작 후에도 누구의 무엇을 수행하는지 알 수 있어야 한다.

## 7. 맞지 않을 때와 돌아왔을 때의 화면이 부족하다

**기획상 확인:** 기존안에 저장 실패·일정 변경·철회 규칙은 있지만, 홈 상태별 화면과 주 행동이 한 표로 연결되지 않았다.

**수정 권고:** 새 설정 메뉴를 늘리지 말고 기존 오늘 영역을 상태에 따라 바꾼다.

| 상태 | 가장 먼저 보일 내용 | 가능한 다음 행동 |
|---|---|---|
| 계획 없음 | 간편 입력과 대표 프로그램 | 추천 받기 / 해당 프로그램 확인 |
| 시작일 전 | 첫 훈련 날짜와 준비할 내용 | 첫 일정 확인 |
| 오늘 예정 | 실제 수행 내용 | 안내 확인 / 허용된 변경 |
| 오늘 수행 보고 있음 | 수행 확인과 다음 훈련 | 기록 수정 또는 다음 일정 확인 |
| 같은 날 다음 세션이 남음 | 이미 한 세션과 남은 세션 구분 | 남은 세션 확인. 하루 전체 완료로 오표시하지 않음 |
| 휴식일 | 휴식임을 명확히 표시, 다음 훈련 | 다음 일정 확인 |
| 공백/기준 재확인 필요 | 이어가기 전 필요한 사실 | 기존 계약이 요구하는 짧은 재확인 |
| 프로그램 완료 | 실제 수행 사실과 다음 단계 | 가능한 후속 프로그램 하나 또는 목표 재설정 |
| 개인 적용 불가 | 고른 프로그램명, 이유 한 줄 | 같은 제작자의 적합 버전 또는 다른 대안 하나를 명시적으로 제안 |
| 저장 대기/실패/충돌 | 보존된 결과와 정확한 상태 | 해당 복구 행동 |

공백의 기간, 재개 조건, 훈련 변경 수치는 이 리뷰에서 새로 정하지 않는다. 기록이 없다는 이유로 운동을 하지 않았다고 단정하지 않는다. `밀린 훈련`, 붉은 실패 달력, 연속 기록 상실 같은 부채감을 만드는 표현을 기본으로 두지 않는다.

부적합한 제작자 프로그램을 다른 원본으로 조용히 바꾸지 않는다. `기록 없이 시작 가능`으로 소개한 상품이 실제로는 현재 기록을 요구하면 출시 실패다.

## 8. 기존 UI에서 관찰한 문제와 유지할 것

### 실제로 본 근거

- 2026-09-14 합성 데이터 캡처 `home-375.png`: ‘오늘 운동을 기록해요’와 큰 기록 버튼, 분석·계획·예시·학습 네 진입, 일지 예시와 콘텐츠가 보인다.
- 같은 날짜 `plan-375.png`: 종목 선택 화면에 `1/11` 진행 표시가 보인다.
- 같은 날짜 `returning-home-record-first-320x568.png`: 내 기록/오늘 기록 중심이며 화면 아래에 네 기능 진입이 이어진다.
- 현행 코드 `TrainingHome.tsx:154–184`에도 WELCOME 기록 CTA와 분석·계획·예시·학습 네 버튼이 존재한다. TRAINING 상태는 다음 훈련을 우선 배치하는 분기가 있어, 모든 복귀 사용자에게 기록만 우선한다고 일반화하지 않는다.

### 해석

현재 캡처의 중립색·선·타이포는 절제되어 있다. 그러나 **보기에 정돈된 기능 메뉴가 곧 사용자의 결정을 대신해 주는 홈은 아니다.** 새 전략에서 처음 계획을 받으려는 사람에게 기록 남기기를 가장 크게 보여주는 것은 목적과 맞지 않는다.

기획의 새 입력 한 줄을 기존 홈 위에 하나 더 얹으면, 기존 네 버튼·예시·콘텐츠·새 제작자 카드가 경쟁하는 화면이 될 수 있다. 신규 간편 진입의 첫 위계를 재배치해야 한다. 기존 기록 기능 자체는 계속 접근 가능해야 한다.

`1/11`은 촬영 당시 기존 계획 흐름의 관찰값이다. 최신 배포에서도 11단계라고 단정하지 않는다. 새 간편 흐름에 기존 전체 설정 단계를 그대로 이어 붙일 경우 제품 약속과 어긋난다는 위험을 보여주는 참고다.

### 유지할 시각 언어

- 기존 Pretendard·토큰·중립 바탕·얇은 선·절제된 틸을 재사용한다.
- 금색/새 폰트/거대한 마케팅 헤드라인 등 일반 디자인 검색 결과를 새 기준으로 가져오지 않는다.
- 첫 화면의 가장 큰 정보는 현재 사용자의 과업에 맞춘다. 첫 결과에서는 프로그램과 부담, 수행 화면에서는 실제 훈련 지시다.
- 카드마다 테두리와 버튼을 반복하기보다 역할별 영역을 묶는다. 모든 정보에 같은 크기·같은 강조를 주지 않는다.
- 정상 상태의 검토/보안/정책 배지를 늘리지 않는다. 행동을 바꾸는 오류·적용 불가·오래된 기준은 보이게 한다.
- 제작자 소개에는 허용된 이미지와 짧은 말로 사람의 정체성을 살릴 수 있다. 과도한 장식 없이도 상품의 특징은 남아야 한다.

## 9. 수정된 화면 역할

| 화면 | 사용자가 바로 알아야 하는 것 | 주된 정보 | 접어도 되는 정보 |
|---|---|---|---|
| 신규 간편 진입 | 무엇을 넣으면 무엇을 받는가 | 종목/기록 또는 목표, 대표 프로그램 하나 | 서비스 장문 설명 |
| 추천 결과 | 내가 받아들일 일정과 부담은 무엇인가 | 프로그램 정체성, 기간·횟수·시간, 첫 일정, 적용 기준 | 전체 원리·상세 근거 |
| 오늘 수행 | 지금 무엇을 어떻게 하는가 | 준비/본운동/회복/정리와 수치 단위 | 과학적 배경·긴 출처 |
| 제작자 프로그램 소개 | 누구의 무엇이고 나도 시작 가능한가 | 저자, 대상, 실제 부담, 첫 훈련, 개인화 범위 | 저자 이력 전체·상세 변경 이력 |
| 복귀/오류 | 지금 이어갈 수 있는가 | 현재 상태와 다음 행동 | 기술적 원인·감사 정보 |

`자세히`, `기준 바꾸기`처럼 목적이 모호한 링크는 `왜 이 훈련인가요?`, `기준 기록 바꾸기`, `시작일·요일 바꾸기`로 구체화한다. 링크 이름만으로 다음 화면을 예측할 수 있어야 한다.

## 10. 구현 전에 검증할 최소 과업

첫 검증은 설계 비교를 위한 소규모 관찰이다. 참가자가 적은 관찰 결과를 전환율 향상이나 대다수 선호의 통계적 증명으로 쓰지 않는다.

1. **모바일 입력 비교:** 자유 한 줄과 작은 구조화 묶음에서 기록/목표·분초를 입력한다. 시간·키보드 전환·오류·수정 수를 비교한다.
2. **프로그램 이해:** 추천 결과를 보고 기간·횟수·생활 부담·시작일을 설명한다. 마음에 안 드는 요일을 수정한다.
3. **운동 준비:** 오늘 화면만 보고 수행 순서·핵심 수치·회복 방식을 설명한다. ‘보기’ 왕복이 필요한지 관찰한다.
4. **목표 기대:** 목표만 넣은 결과가 무엇을 약속하고 무엇을 아직 판단하지 않았는지 설명한다.
5. **따라하기 이해:** 제작자 링크에서 시작해 개인화 전후 무엇이 같고 달라졌는지 설명한다.
6. **맥락 복구:** 로그인 취소/성공, 뒤로 가기, 네트워크 실패 후 입력과 프로그램을 잃지 않고 이어간다.
7. **생활 복귀:** 휴식일·이미 수행·공백·프로그램 종료에서 다음 행동을 찾는다.

UI 수용 조건:

- 375px 기본 화면과 320×568 작은 화면을 확인한다. 글자 200% 확대에서는 세로 스크롤을 허용하고 핵심 수치·단위·오류를 잘라내지 않는다.
- 모바일 키보드가 열린 상태에서 입력·오류·진행 행동을 확인한다. 고정 하단 버튼/탭이 키보드와 겹치지 않게 한다.
- 터치 영역은 현행 44px 기준, 키보드 포커스 표시·순서·모달 복귀를 유지한다.
- 기록/목표·분/초·원본/개인본은 색만으로 구분하지 않는다.
- 오류는 해당 필드 근처에 수정 행동과 함께 표시하고 보조기기에서도 알 수 있게 한다.
- 결과 로딩 중 가짜 AI 추론 문구·불필요한 대기 연출을 넣지 않는다. 실패 시 입력을 보존한다.
- 메인 동작 2회 목표와 별개로 실제 응답한 사실·수정·재입력·추가 화면 수를 기록한다.
- 모델 응답 시간, 첫 결과 시간, 계획 이해 시간, 운동 준비 완료 시간은 서로 다른 지표로 본다.

## 11. 앞선 실행 계획에 반영할 수정

| 기존 작업 | 수정할 완료 기준 |
|---|---|
| IP-02 간편 시작 계약 | 최초 채택/매일 수행/복귀 상태를 분리하고 질문·통제권·적용 의미 확정 |
| IP-04 한 줄 입력 | ‘자유 한 줄 확정’ 대신 구조화 입력과 비교한 결과로 기본 UI 선택 |
| IP-05 시작·오늘 화면 | 결과에 프로그램 부담 표시, 오늘에 수행 정보 표시, 모호한 ‘보기’ 경유 제거 |
| CP-01 프로그램 공급 | 저자·대상·첫 훈련·부담·원본 관계·실제 후속 단계까지 상품 자료 준비 |
| CP-03 개인 적용본 | 원본 정체성의 연속 표시, 적용 불가/로그인 복구에서도 선택 맥락 유지 |
| RT-01 재방문 | 완료·휴식·공백·프로그램 종료를 포함한 상태별 다음 행동 |
| QA-01 검증 | 계약 검사와 별도로 위 이해·실행 과업 및 모바일 UI 조건 검증 |

가장 먼저 시각화할 것은 **모바일 입력, 프로그램 결과, 오늘 수행** 세 화면과 제작자 진입 변형이다. 그 화면에서 사람들이 실제로 어디서 멈추는지 확인한 뒤 구현 세부를 닫는다. 지금은 새 추천 알고리즘보다 이 화면 간의 역할을 바로잡는 작업이 우선이다.
