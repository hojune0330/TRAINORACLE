## 1. 결론과 문서 관계

**기록은 짧게 끝나고, 필요한 경우에만 실제 수행을 확인한다. 다음 일정은 확인된 사실과 채택된 정책으로 제안하며, 사용자가 선택한 뒤에 바꾼다.**

이 문서는 [전체 A~G 개발 계획](PLAN_EXECUTION_REVIEW_AND_REPLAN_IMPLEMENTATION_PLAN_2026-09-28.md)과 [홈·코칭 UX 계획](PLAN_EXECUTION_HOME_AND_COACHING_UX_2026-09-28.md)을 대체하거나 축약하지 않는다. [일지 트리거 검토](../review/JOURNAL_TRIGGER_AND_REPLAN_SPEC_REVIEW_2026-09-29.md) 이후 발견한 기존 계약과 복잡성 위험을 반영하는 상세 보완안이다.

유지할 목표는 사실 비교, 영향 설명, 다음 훈련 교정, 남은 주기 재구성, 장기 주기 연결, 계정 적용, 홈·일지·달력의 공통 코칭이다. 메모 정리 보조 기능을 먼저 완성해야만 이 목표를 개발할 수 있는 구조로 만들지 않는다.

### 사용자에게 보이는 세 경로

| 상황 | 기본 흐름 | 생기지 않아야 할 부담 |
|---|---|---|
| 빨리 기록하고 싶은 날 | 기존 선택 → 기록 저장 → 끝 | 메모 입력, 분석 동의, 구간 설문 강제 |
| 다르게 운동한 내용을 남기는 날 | 실제 운동 선택/입력 → 계획과 차이 확인 → 필요할 때 다음 일정 보기 | 이미 쓴 반복·회복을 다시 질문 |
| 글로 쓰는 것이 편한 날 | 분석용 글 작성 → 원할 때 `운동 내용 정리` → 수정 가능한 요약 확인 | 문장마다 팝업, 모든 문구의 승인 버튼 |

사용자는 이 세 경로를 매번 자유롭게 오갈 수 있다. 전문 선수도 간편 기록을 쓸 수 있고 초보자도 상세 기록과 근거를 볼 수 있다. 청소년·혼자 훈련하는 사용자를 일괄 제외하거나 코치 연결을 새 필수 조건으로 만들지 않는다. 기존 안전·권한 정책은 별도로 유지한다.

### 계약 불일치 처리 원칙

1. DAILY_LOG의 하류 소비자 없음 표기와 `plan-beta-flow.ts`의 현재 메모 안전 평가 경로가 다르다. North Star §4에는 이 연결이 구현됐다고 명시돼 있다. 따라서 **기능이 전혀 승인되지 않았다고 단정하지도, 모든 메모 분석이 승인됐다고 확대하지도 않는다.** 정확한 안전 경로의 채택·범위·검증 기록을 찾아 좁게 동기화한다.
2. NOTE_SAFETY는 일반 운동 문장 파서가 아니라 민감 안전 결과의 하류 전달 초안이다. 그 opaque envelope를 일반 반복·거리 기록의 저장 형식으로 전용하지 않는다.
3. 2026-09-08 계정보관 승인은 오래된 일괄 서버 금지를 보관·조회·복구에 한해 갱신한다. 분석·외부 모델·공유 권한까지 바꾸지 않는다.
4. 사용자 확인 후 메모 유래 수치의 영속·설명형 비교·계획 소비를 각각 좁게 채택해야 한다. 이 문서 작성으로 채택 완료가 되지 않는다. 채택 전에는 직접 구조화 입력 경로로도 비교 개발을 계속할 수 있다.
5. 기존 공개 기능을 오래된 문서 한 줄로 꺼버리거나, 모든 `false`를 일괄 `true`로 변경하는 수정은 금지한다.

| 방식 | 장점 | 단점 | 결론 |
|---|---|---|---|
| 모든 글을 자동 해석하고 질문 | 사용자가 기능을 놓치지 않음 | 오인식·사생활 불안·저장 방해·잦은 질문 | 첫 버전에서 제외 |

선택된 방향은 **직접 구조화 입력 + 선택형 글 정리 + 검토된 교정 정책**이다. 글 정리의 성공률을 높이려고 미확인 의미를 추측하지 않는다. 한 번 확인한 숫자를 반복 질문하지 않는다.

## 5. 화면별 상세 흐름

### 5.1 기록 진입과 저장

- 기존 운동 결과·시간대·힘든 정도·몸 상태 흐름을 유지한다. 이 설계 때문에 새 필수 페이지를 넣지 않는다.
- 기존 요약의 `운동 추가`, `글 추가`, `이대로 저장`을 재사용한다.
- `운동을 마쳤어요`는 거리·회복·강도까지 계획과 같다는 의미가 아니다. 그대로 저장할 수 있으며 정확한 대응이 없는 항목은 모르는 상태로 둔다.
- `계획과 다르게 했어요`를 선택한 경우에도 저장은 가능하다. 실제 운동을 이미 입력했다면 다시 묻지 않는다.
- 안전 확인이 필요한 경우 기존 안전 경로를 따른다. 일반 글 정리의 선택권을 안전 상태 해제 버튼으로 만들지 않는다.

### 5.2 분석용 글의 정리 도구

노출 위치는 분석용 글 편집 영역 안이다. 비밀 글에는 이 버튼·후보 수·분석 배지를 표시하지 않는다. 글 존재 여부를 홈 코칭의 개인화 신호로 쓰지 않는다.

```text
오늘의 훈련 메모
[사용자가 작성하는 글]

[운동 내용 정리]       [글만 남기기]
```

첫 사용의 짧은 안내: `글에서 찾은 운동 내용을 확인한 뒤 기록에 넣어요.`
긴 지원 범위와 처리 방식은 `어떤 내용을 정리하나요?`에 둔다. 메모 원문은 현재 기기에서만 해석하며, 승인된 계정 글 보관은 별도 경로임을 구분한다.

- 타이핑 중 자동 파싱·자동 저장·자동 화면 전환 없음.
- 요청 시 현재 편집 중 revision을 고정한다. 결과 도착 전 글이 바뀌면 해당 결과는 폐기한다.
- 결과 대기 중에도 취소·뒤로가기·글만 저장 가능. 추출 실패가 일지 저장 실패가 되지 않는다.
- 광범위한 과거 일지를 묵시적으로 재분석하지 않는다.

### 5.3 운동 하나를 한 번에 확인

합성 입력: `오늘 400m를 6번 했고 반복 사이에는 2분 걸었어.`

```text
이렇게 운동했나요?
400m × 6회
반복 사이 2분 걷기

[수정]                 [기록에 넣기]
다른 내용은 글에 그대로 남아요.
```

- 거리·반복·회복을 각각 세 번 승인시키지 않는다. 관련 값 전체를 한 눈에 보여주고 묶어서 확인한다.
- `기록에 넣기`는 아직 서버 저장 완료가 아니다. 기존 작성 요약에 실제 운동 행을 반영하고, 기존 저장 동작으로 함께 저장한다. 이미 저장된 일지를 열어 정리했다면 새 revision 저장을 명시적으로 수행한다.
- 후보를 발견했다는 이유로 모든 항목을 자동 선택하지 않는다. `기록에 넣기` 전에 확인값과 바뀔 기존 값이 보인다.
- 여러 운동은 운동별 묶음으로 보여준다. 첫 운동만 몰래 반영하거나 나머지를 버리지 않는다. 다중 입력은 `선택한 내용 넣기` 한 번으로 수락할 수 있고 항목별 제외·편집이 가능하다.
- 기존 값과 충돌하면 두 값을 보여주고 해당 필드만 사용자가 선택한다. 최신 문장이라는 이유로 덮어쓰지 않는다.
- 간편 경로의 추가 확인은 한 묶음 또는 한 핵심 질문을 목표로 한다. 더 많은 정보가 필요하면 `나중에 확인` 또는 상세 편집으로 보낸다. 여러 안전 확인을 억지로 하나로 축약하는 상한은 아니다.
- 취소·거절한 후보는 같은 작성 세션에서 반복 출몰하지 않는다. 문장 원문이나 해시를 저장해 장기 거절 목록을 만들지 않는다.

### 5.4 저장 직후

저장 결과가 먼저다. `계정에 저장했어요`, `아직 전송하지 못했어요`, 충돌 상태를 실제 저장 결과에 맞춰 보여준다.

일반 변화가 확인됐을 때의 예:

```text
계정에 저장했어요
계획 10회 → 기록 6회
[다음 훈련 확인]
```

이때 `4회 부족`, `목표 실패`, `내일 보충`으로 단정하지 않는다. 숫자 확인만으로 특정 생리학적 효과를 판정하지 않는다. 다른 훈련 추가·의도적 변경 이유는 원하면 구조화 선택으로 남길 수 있지만 저장을 막지 않는다.

동일 계획 수행을 검증할 정보가 없으면 긍정적인 준수 배지도 경고도 만들지 않는다. 기록 저장 자체는 정상 완료다. 중요한 미해결 사항이 없으면 별도 추가 화면 없이 끝낸다.

### 5.5 코칭 상세와 변경 미리보기

코칭 상세의 첫 화면은 `확인된 차이 → 다음에 할 일 → 이유 보기`다. 상세 근거는 기존 전체 화면 reader에 둔다.

- 계획과 실제 수치: 같은 구간·같은 단위·같은 범위만 나란히 표시.
- 의미: 현재 정책이 설명할 수 있는 범위만. `운동량은 줄었지만 다음 훈련을 어떻게 바꿀지는 아직 정하지 못했어요` 같은 부분 결론 허용.
- 다음 행동: 사실 확인, 다음 일정 확인, 제안 검토 중 가장 필요한 하나.
- 변경안: 원래 일정과 제안 일정을 실제 날짜·요일·오전/오후로 표시. 바뀐 것과 유지한 것이 구분된다.
- 적용: `이 일정으로 변경`을 누른 뒤 서버 재검증·저장. 원래 계획은 과거 기준으로 남긴다.
- 적용 불가/정보 부족일 때 작동하지 않는 확정 버튼을 보여주지 않는다. 가능한 사실 비교와 기록 수정을 제공한다.

### 5.6 홈과 반복 방문

- 새 전역 탭을 만들지 않는다. 홈의 훈련 코칭, 해당 일지, 달력 날짜 상세에서 같은 결과를 연다.
- 가장 중요한 미해결 한 건을 먼저 보여주고 나머지는 짧은 목록 진입으로 남긴다. 사건 여러 개를 하나로 삭제하지 않는다.
- `읽음`, `나중에 확인`, `사실 수정됨`, `변경안 적용됨`은 다른 상태다. 화면을 열었다고 안전/교정 문제가 해결되지 않는다.
- 일반 확인을 미뤘다는 이유로 앱 전반을 잠그지 않는다. 안전 상태는 기존 승인된 경로로 별도 전달한다.
- 같은 사실·정책 revision이면 홈을 열 때마다 새 사건으로 만들지 않는다. 새 기록이나 정책으로 판단이 달라질 때만 갱신하고 변경 이유를 남긴다.
- 메모 쓰기·분석 수락·통증 없음·훈련 추가에 포인트를 연결하지 않는다. 거절하거나 모른다고 답해도 불이익 없음.

### 5.7 화면·모션 합격 기준

- 기본 내용은 한 질문과 주요 행동 하나. 설명을 감추되 저장 실패·충돌·안전 확인·변경 대상은 감추지 않는다.
- 기존 self-hosted Pretendard, 색·간격 토큰, lucide 아이콘, 44px 터치 영역 유지. 새 테마나 카드 속 카드 없음.
- 단일 선택은 기존 짧은 전환을 재사용. 숫자 편집·여러 항목 선택·저장·일정 적용은 자동 전환/확정하지 않는다.
- 글 편집 시 자동 스크롤로 커서를 빼앗지 않는다. 결과가 생성됐을 때만 결과 제목으로 한 번 이동하되 사용자가 스크롤 중이면 강제로 끌지 않는다.
- reduced motion에서 애니메이션을 생략해도 정보·조작은 같다. 화면 낭독은 결과 도착을 한 번 알리고 매 수치마다 반복하지 않는다.
- 320/375px, 200% 글자에서 취소/확정 접근 가능. 큰 글자에서는 세로 스크롤을 허용하고 스와이프만으로 조작하게 하지 않는다.
- 용어집·일지·달력·홈 사이 이동 후 원점·스크롤·선택 운동·작성 초안을 복원한다.

## 6. 내부 구조: 네 가지를 섞지 않는다

```text
직접 입력 / 승인된 파일·워치 관측 ─────────────┐
                                            ├→ 적격한 구조화 수행 근거
분석용 글 → 로컬 후보 → 사용자 확인 → 별도 채택 ┘
                                                   ↓
                    정확한 과거 계획·구간 대응 → 사실 차이
                                                   ↓
                    채택된 영향 정책 → 교정안 → 사용자 선택
                                                   ↓
                                      계정 원자적 적용

기존 안전 평가 → 독립 안전 게이트 ───────────────→ 적용 가능 여부
```

1. **관찰:** 무엇을 했다고 입력·확인했는가.
2. **해석:** 계획과 무엇이 다른가, 무엇은 알 수 없는가.
3. **권고:** 채택된 규칙상 다음 일정에 어떤 선택이 가능한가.
4. **적용:** 최신 근거·권한을 확인하고 어떤 새 계획을 저장했는가.

화면에서 이 단계를 네 개의 필수 페이지로 강요하지 않는다. 내부 권한과 책임만 분리한다. 사용자에게는 필요에 따라 저장 한 번, 추가 확인 한 번, 일정 변경 한 번으로 끝나게 한다.

## 7. 최소 데이터 확장안

새 범용 신호 서버나 별도 메모 분석 저장소부터 만들지 않는다. 기존 journal/exerciseLog, 계획 링크, account repository를 우선 사용한다. 아래 이름은 설계 역할이며 아직 존재하는 파일·확정 스키마가 아니다.

| 역할 | 필요한 정보 | 저장/소비 경계 |
|---|---|---|
| 일시 추출 후보 | 이번 편집 revision token, 운동/행 후보, 필드·단위, 명확/확인 필요/지원 밖 | 메모리 전용. 원문 조각은 편집 화면 밖으로 전달하지 않음. 일반 로그 금지 |
| 확인된 운동 관측 | 기존 component/row ID, 허용된 수치·단위·범위, 파생 규칙/확인 버전, 확인한 값, 일지 revision | 좁은 채택·서버 스키마 반영 뒤 저장. raw/quote/symptom/embedding/text hash 없음 |
| 계획 구간 대응 | 원래 plan revision/occurrence/segment, 실제 component/row ref, 대응 종류 | 값 복제보다 ref 사용. 한 값의 범위가 달라지면 재확인 |
| 비교 근거 묶음 | 적격 구조화 필드만의 digest, 원본 revision, completeness, 정책 버전 | 비밀 메모·자유 제목·운동명·메모 사용 이력 제외 |
| 검토 상태 | 계정 범위, 대상 occurrence와 evidence key, 읽음/보류/해결 사유 | 메모 원문·민감 어휘 없는 최소 상태. 읽음은 해결이 아님 |
| 교정 제안 | 원본/제안 revision, 근거 refs, 정책/구성 버전, 유지·변경 지도, safety epoch | 기존 재설계 계약 재사용. 일지 사본이나 원문 저장 금지 |

### 출처 규칙

- 직접 탭한 수치, 기기 측정 수치, 파일에서 확인한 수치, 글에서 추출 후 확인한 수치를 구별한다.
- 사용자 확인은 자기보고의 명시적 수락이지 객관적 측정/독립 검증이 아니다. 확인된 파생값을 전역 EXPLICIT로 바꾸지 않는다.
- 기존 provenance에 수용 가능한 표현인지 먼저 검토한다. 부족하면 국소적인 필드 확장과 등록된 파생 규칙을 추가하고 분석별 소비 범위를 좁힌다.
- 기존 직접 입력값은 자동 후보로 덮어쓰지 않는다. 실제 수치 수정은 새 일지 revision과 기존 저장 경로를 따른다.
- 글 유래 값의 표시 허용과 미래 계획 입력 허용은 별도다. 계획 소비 채택 전에는 사실 기록/승인된 설명 범위에 머문다.
- 원문 해시·단어 수·언어·감정점수·증상 코드로 민감 문장을 우회 저장하지 않는다. 안전 정보와 운동 수치가 함께 있는 문장에서 안전 어휘를 일반 파생값에 묻어 넣지 않는다.

### 저장 revision과 분석 근거 version의 분리

일지 저장 revision은 동시 수정 방지용이다. 그 값이 바뀌었다고 반드시 새 훈련 사실이 생긴 것은 아니다. 분석 근거 version은 허용된 구조화 값·원본 계획 대응·소비 권한·관련 정책만으로 갱신한다.

- 비밀 메모만 수정하면 비공개 보관 동작 이외의 코칭·알림·점수·근거 지문은 바뀌지 않는다. 메모 수정 시각을 새 훈련 신호로 쓰지 않는다.
- 물리적 저장 revision 충돌은 기존 저장 계층에서 처리하되, 일반 코칭에 `새 내용 발견`으로 노출하지 않는다. 적용 전 재조회 결과 구조화 근거와 안전 epoch가 동일하면 불필요한 새 교정안을 만들지 않는다.
- 명시적인 파생 분석 권한 철회, 구조화 수행 수치 수정, 새 안전 상태는 해당 소비 범위의 재검증 사유다. 비밀 원문을 읽거나 해시하지 않고 허용된 권한/구조화 이벤트로 처리한다.
- 현재 저장 envelope로 이 분리가 가능한지 W2에서 검증한다. 단순히 `savedAt`을 모든 근거의 버전으로 재사용하지 않는다.

### 값의 의미

- 10회×2세트는 총20회, `총6회`는 세트별6회가 아니다. 나눔이 불명확하면 세트 수를 발명하지 않는다.
- 반복 사이 회복, 세트 사이 회복, 운동 후 휴식은 서로 다르다.
- 회복 없음, 명시적0초, 미기록을 구분한다. 마지막 반복 뒤의 회복 포함 여부 없이는 총 회복을 확정하지 않는다.
- 본운동 시간, 준비·정리 포함 전체 시간, 워치 경과 시간, 실제 움직인 시간을 구분한다.
- 거리형·시간형의 변환은 필요한 속도 근거가 있을 때만 기존 승인 모델로 수행한다. 준비·정리·근력·점프를 러닝 km로 바꾸지 않는다.
- 세션 RPE와 특정 반복 RPE를 섞지 않는다. 평균 페이스만으로 개별 반복의 목표 달성을 판정하지 않는다.

## 8. 문장 처리 범위와 반례

첫 버전은 광범위한 한국어 이해가 아니라 **닫힌 운동 표기와 명시적 실제 수행 표현의 입력 보조**다. 정확한 지원 문법·단위·한도는 구현 전 fixture 목록으로 고정한다. 신뢰도 90% 같은 미보정 수치를 붙이지 않는다.

| 합성 문장/표기 | 후보 처리 | 금지할 추론 |
|---|---|---|
| 오늘 400m 6회, 반복 사이 2분 걷기 | 명시된 운동 묶음을 확인 제안 | 에너지 계열/강도/완료율 자동 확정 |
| 10개 하려다가 6개만 했어 | 정확한 연결 운동이 있는 경우 실제 총반복6 후보, 거리 미상 유지 | 10을 실제값으로 사용, 부족분 자동 추가 |
| 6개씩 두 세트 했어 | 세트별6×2 후보 | 총6으로 축약 |
| 총6개를 두 세트로 했어 | 총6·2세트, 세트별 분배는 미상 | 3+3으로 자동 배분 |
| 쉬는 시간을 60초에서 2분으로 늘렸어 | 새 값120초 후보, 반복/세트 회복 모르면 한 질문 | 60초 저장, 회복 완료/동일 자극 단정 |
| 6~8개 정도, 몇 번 했는지 기억 안 나 | 범위/불명확. 확정 반복값 제안 안 함 | 중간값7 저장 |
| 다음에는 6개만 해야겠다 | 향후 희망. 필요하면 별도 요청 진입 | 오늘의 실제 반복6으로 저장 |
| 코치가 10개 하라고 했는데 안 했어 | 지시와 미수행을 구분할 수 없으면 보류 | 수행10 또는0 자동 저장 |
| 친구는 6개, 나는 4개 | 복수 인물 문맥 지원 전 자동 후보 보류 | 첫 숫자를 본인 수행으로 사용 |
| 어제 6개, 오늘은 자전거 | 복수 시점은 지원 범위 밖으로 보류/직접 기록 | 현재 일지에 두 운동 합산 |
| 10×400m 2set r60 R3 / 오늘 일부만 | 처방 표기와 실제 완료 범위가 다름. 입력 보조와 완료 사실 분리 | 전체20회 실제 수행으로 복사 |
| 힘들었지만 끝까지 했어 | 자유 감상은 보존, 필요한 수치만 직접 질문 가능 | RPE9·피로 누적·부상 위험 수치 생성 |
| 통증 없었어 / 어제 아팠어 / 친구가 아파 | 일반 파서는 운동 수치로 사용하지 않음. 기존 안전 처리와 별도 문맥 검수 | 파서가 안전 판정을 CLEAR로 바꾸거나 현행 D9가 문맥을 모두 이해한다고 주장 |
| 달리기 대신 자전거30분, 스쿼트3세트 | 여러 운동 묶음 확인, 종류별 수치 보존 | 달리기30분 등가/에너지 기여율 자동 생성 |

명확한 숫자 하나가 있어도 인물·시점·부정·인용·계획/실제 구분이 모호하면 해당 후보를 확정적으로 추천하지 않는다. 지원 범위 밖 문장은 오류가 아니라 직접 선택으로 이어지는 정상 경로다. 운동명에 임의 텍스트를 추가하더라도 그 이름을 분석/추천 입력으로 읽지 않는다.

### 파서의 기술적 제한

- 기존 글·운동 입력 한도 안에서 처리하고 실행 시간·후보 개수·정규식 복잡도를 제한한다. 무제한 재귀·백트래킹, 글 입력 중 메인 스레드 정지는 반려한다. 수치는 구현 성능 시험으로 정하고 훈련 처방 한도로 재사용하지 않는다.
- 숫자/단위 정규화가 허용 문법 밖이면 보류한다. 소수점·전각 문자·곱셈 기호·작은따옴표의 의미를 fixture로 명시하고 무조건 초 또는 분으로 바꾸지 않는다.
- 음수·NaN·Infinity·누락 단위·충돌하는 합계는 기존 저장 검증 전에 후보 단계에서 거부한다. 올바른 원문과 초안은 보존한다.
- 외부 링크 열기, 코드 실행, 원격 모델 호출은 파서 기능이 아니다. 글 안의 지시문은 시스템 명령이 되지 않는다.
- 오류 관측에는 오류 종류와 파서 버전만 허용한다. 원문이 포함될 수 있는 exception 문자열·입력 스냅샷·콘솔 출력은 남기지 않는다.

## 9. 안전 경로와 프라이버시

### 독립 경로

- 분석용 메모의 기존 D9 평가를 글 정리 버튼 뒤로 옮기지 않는다. 일반 추출을 쓰지 않아도 현재 승인된 안전 처리 경로는 유지한다.
- 비밀 메모는 안전 평가·운동 추출·분석·추천에서 무신호다. 비밀 글 선택을 몸 상태 확인을 했다는 의미로 쓰지 않는다.
- 운동 추출 후보 거절, 정상 운동 완료, 좋은 워치 수치, 글 삭제/수정은 기존 D9_ACTIVE/UNKNOWN 해제 이벤트가 아니다.
- 위험 감지 결과는 현재 정제된 래퍼를 거친다. `D9Result.evidence[].clause`를 새 코칭·로그·감사·서버 객체에 복사하지 않는다.
- NOTE_SAFETY의 opaque 전달안과 현재 로컬 경로의 차이는 W0에서 대조한다. 미채택 release/crypto/권한을 이미 구현된 것으로 표시하지 않는다.
- 단어만으로 미래 재설계, 통증 부위 추출 저장, 의학적 진단을 하지 않는다. 안전 표현 문맥 개선은 별도 안전 검토로 다룬다.

### 수정·철회·삭제 정책 제안

| 사건 | 일반 운동 후보/확인 사실 | 교정 제안/안전 상태 |
|---|---|---|
| 확인 전 글 수정 | 이전 후보 즉시 폐기 | 아직 계획 영향 없음 |
| 확인 후 글만 수정 | 확인된 수치를 몰래 다시 추출·변경하지 않음. 원문 revision 종속 후보는 재검토 | 원문만 바뀌고 유효한 구조화 확인값이 같으면 분석 결과를 임의 변경하지 않음 |
| 운동 수치 직접 수정 | 새 구조화 revision, 기존값과 원본 이력 보존 | 이전 근거에 묶인 미적용 제안 무효화 |
| 분석용에서 비밀 글로 전환 | 글 유래 소비 권한 철회. 유지하고 싶은 수치는 별도 직접 입력으로 명시 확인 가능 | 관련 미적용 제안 무효화. 안전 상태는 별도 승인된 해제 경로까지 유지 |
| 일지 삭제/휴지통 | 삭제 표식에 맞춰 해당 일지의 분석 근거 제외 | 미적용 제안 무효화. 이미 적용된 과거 계획/영수증을 몰래 되돌리지 않음 |
| 파서/정책 업데이트 | 과거 확인값 재추출 금지. 필요 시 현재 근거로 새 버전 검토 | 이전 제안 재검증. 새 일정 자동 적용 없음 |
| 계정 전환/로그아웃 | 진행 중 후보/화면 결과 폐기, 해당 계정 초안의 기존 보호 유지 | 다른 계정에 결과/알림/제안 잔존 금지 |

이 표는 권장 상세정책이며 채택 전 자동 실행 권한이 없다. 특히 비밀 전환 시 파생 사실 처리와 이미 적용된 영수증의 최소 보존은 계정보관/삭제 계약과 함께 결정한다. 승인된 보관기간을 새로 늘리지 않는다. 원문 수정 시마다 값을 지우거나, 반대로 철회 뒤에도 조용히 계속 소비하는 극단을 피한다.

## 10. 실제 수행과 계획의 대응

- 원래 계획 revision과 occurrence를 먼저 확정한다. 날짜가 같다는 이유로 현재 계획을 과거 일지에 대신 붙이지 않는다.
- AM/PM 변경이나 날짜 이동은 자동으로 다른 occurrence에 재귀속하지 않는다. 원래 계획에 대한 시간 변경인지 다른 운동인지 확인할 경로를 제공한다.
- `완료 + 같은 시간대`는 운동 구성 일치 증거가 아니다. `MODIFIED` 파생값도 사용자가 직접 변경을 고백한 것으로 설명하지 않는다.
- 사용자 보고로 대응한 것과 워치 구간이 검증된 것을 구분한다. 확인한 자기보고 숫자의 산술 비교는 가능하지만 실측이라고 표시하지 않는다.
- 여러 actual row가 한 planned segment에 대응할 수 있다. 같은 row를 여러 세션 부담에 중복 합산하지 않는다.
- 두 일지가 같은 occurrence를 참조하면 무조건 중복으로 삭제하지 않는다. 분할 기록인지 중복인지 미해결 상태로 두고, 합치기/별도 수행 선택의 정확한 계약을 마련한다.
- 워치 자료가 늦게 오면 기존 기록에 대한 후보 관계만 제안한다. 수동 값·메모·꾸미기를 덮어쓰지 않는다. 기존 파일/워치 수용 계약의 출처·확정·중복 규칙을 사용한다.
- 자료를 못 읽은 상태와 읽었는데 자료가 없는 상태를 구분한다. 미수행·미기록·자료 대기는 각각 다른 값이다.
- 정확한 시각 없이 날짜/AMPM만 있으면 두 운동 사이 정확한 회복시간을 계산하지 않는다. 달력은 저장된 날짜와 표시 시간대 규칙을 따른다.

## 11. 영향 판단과 다음 일정 교정

### 강한 개입의 의미

사용자가 일일이 달력을 수리하지 않도록 **확인된 변화의 관련 범위를 시스템이 찾아 한 번에 설명하고 제안**한다. 모든 운동 차이를 위험으로 보거나, 기록 직후 전체 일정을 자동 변경하는 뜻이 아니다.

| 결과 | 조건의 성격 | 사용자에게 할 일 |
|---|---|---|
| 사실만 표시 | 비교 가능한 차이 존재, 영향 판단 없음/불필요 | 차이와 불확실성 표시. 임의의 `유지해도 안전` 결론 금지 |
| 추가 확인 | 구간·수치·대응의 핵심 모호함 | 판단을 바꿀 질문 하나 우선. 선택적으로 나중에 |
| 다음 훈련 검토 | 채택된 정책상 관련 미래 세션 확인 필요 | 영향 받는 다음 훈련과 이유 표시 |
| 남은 일정 재구성 | 좁은 변경만으로 채택 조건 충족 불가 | 현재 주기의 변경 지도를 제안 |
| 더 넓은 주기 검토 | 경기/중주기 목적과 현재 해법 충돌 | 자동 목표 변경 없이 범위 선택 요청 |
| 안전 확인 | 독립 안전 상태가 요구 | 일반 추천을 안전 해제로 사용하지 않음 |

### 정책 패키지가 반드시 답해야 하는 질문

1. 정확히 어떤 사실을 사용하며 어떤 출처·확인·최소 자료가 필요한가?
2. 같은 수치 차이라도 종목·주기 목적·원래 방법·앞뒤 세션에 따라 무엇이 달라지는가?
3. 바꿀 수 있는 항목은 훈련 종류·배치·구성 중 무엇이고 바꾸지 못하는 것은 무엇인가?
4. 기존 채택된 configuration 중 어느 것을 사용할 수 있는가? 새 용량·간격이면 근거/한계를 어떻게 검토했는가?
5. 강도·양·빈도·밀도 중 하나를 줄이는 대신 다른 것을 몰래 올리지 않는가?
6. 못 한 훈련을 자동 보충하지 않는가? 목적과 경기일을 사용자의 명시 선택 없이 바꾸지 않는가?
7. 알려지지 않은 근력·점프·자전거 부담을0으로 간주하거나 러닝으로 환산하지 않는가?
8. 유지안이 가능한지 먼저 평가하고, 해법이 없을 때 정직하게 보류하는가?
9. 현재 주기 교정과 다음 주기 PB/SB·명시 요청 경로의 권한을 구별하는가?
10. 불확실한 자기보고 사실·늦은 관측·추가 통증이 들어오면 어떤 제안이 무효화되는가?

반복 수가 줄었다는 이유만으로 체력 저하를 판단하지 않는다. 회복이 길어졌다는 이유만으로 모든 해당계 세션의 목적을 동일하게 설명하지 않는다. 목적·운동 구조별 검토된 설명을 사용한다. 이번 문서에서는 10%, 48시간, 72시간 등 새로운 처방 임계값을 발명하지 않는다.

정책은 정확한 입력 → 권장 결과 → 검토된 구성 → 반례를 담는 작은 패키지로 추가한다. 일반 방향 승인을 새로운 숫자의 포괄 승인으로 쓰지 않고, 오너가 승인한 기존 범위는 불필요하게 다시 묻지 않는다. 부족한 숫자만 근거 검토 후 한 묶음으로 최종 채택 요청한다.

## 12. 저장·동시성·실패 복구

기존 `account-journal-record-service.ts`, schema, 저장 queue/finalization, 계정별 수명주기를 확장한다. 파생 결과만 별도 localStorage에 저장하는 이중 원본을 만들지 않는다.

### 순서

1. 서버가 새 optional 필드/버전/소비 범위를 먼저 읽고 검증할 수 있게 한다.
2. 클라이언트가 capability 확인 후 기록과 확인 사실을 같은 저장 단위로 전송한다.
3. 서버가 일지 revision을 확인하면 그 적격 근거로 교정안을 만든다. 기기 초안만이면 미리보기/저장 대기를 구분한다.
4. 적용 시 plan revision, evidence revision/digest, 정책/구성 버전, 안전 epoch, 계정·권한을 재검증한다.
5. 새 계획·lineage·원본 보존·적용 영수증을 하나의 원자적 성공으로 확정한다.

### 실패별 기대 동작

| 실패 | 기대 동작 |
|---|---|
| 파서 오류/시간 초과 | 글과 운동 초안 보존, 직접 입력/그대로 저장 가능 |
| 구형 서버·클라이언트 | 지원하지 않는 파생 필드를 조용히 버리지 않음. 기존 upgrade/capability 경로 |
| 네트워크 끊김 | 미전송 작업 보호. 계정 저장/계획 적용 완료라고 표시하지 않음 |
| 같은 기록을 다른 기기에서 수정 | 기존 충돌 UI, 최신값 무조건 덮어쓰기 금지 |
| 계획 적용 중 응답 유실 | idempotency key로 결과 조회. 성공 여부 모르는 상태에서 새 적용 자동 재시도 금지 |
| 적용 전 새 실제 기록/통증 | 오래된 제안 거부, 최신 정보로 다시 검토 |
| 적용 성공 후 일지 수정 | 이미 적용된 과거 영수증 보존, 새로운 필요 검토 생성. 자동 롤백 금지 |
| 기능 롤백 | 새 파생/교정 진입을 끄되 원본 일지·확인값·적용 이력 보존. 과거 계획 읽기 가능 |

오프라인 재설계 엔진을 별도로 만들지 않는다. 게스트의 기존 기기 기록은 유지하되 계정 교정 적용 성공과 구분한다. 연결된 계정 원본이 기준이며 기기 초안 보호를 없애지 않는다.

## 13. 단계별 구현 묶음과 출고 조건

아래 W0~W8은 기존 A~G를 실행 가능한 단위로 나눈 **계획**이다. 새 스레드 발주나 코드 구현을 이번 문서에서 수행하지 않았다.

| 묶음 | 작업/주요 소유 파일 | 선행 | 완료 조건 | 기존 계획 |
|---|---|---|---|---|

### 작업자 충돌 방지

- 코어 작업자가 typed result·출처·영향 정책을 소유한다. UX 작업자는 별도 계산기나 임시 추천 숫자를 만들지 않는다.
- 저장 작업자는 확정된 스키마 경계 안에서 계정 쓰기를 소유한다. UI feature flag만으로 서버 권한을 열지 않는다.
- 파서 작업자는 후보까지만 소유한다. 안전 evaluator/계획 엔진을 수정하지 않는다.
- `QuickSessionForm`/공통 schema 같은 공유 파일의 변경자는 한 명으로 고정하거나 직렬 병합한다. 병렬 작업자는 인터페이스와 fixture로 합의한다.
- 기능별 PR은 자신의 구현/시험/미완료 범위를 적는다. 문서가 준비된 것과 실제 공개된 것을 구별한다.

무작위 검수는 고정 seed를 남겨 재현 가능한 행동열로 만든다. 입력·취소·뒤로가기·계정 변경·네트워크 실패를 섞되 운영 계정/실제 민감자료는 사용하지 않는다. 단계 수만 늘린 무의미한 테스트가 아니라 동일 값 중복 저장, 권한 오염, 원점 복귀, 상태 수명을 관찰한다.

### 반드시 실패를 확인할 결함 주입

1. 파생 AS_PLANNED를 직접 확인으로 표시하도록 변조하면 문구/소비 검사가 실패해야 한다.
2. 미래/타인/인용 숫자를 실제 후보로 만들면 문맥 fixture가 실패해야 한다.
3. 총6회×2세트를12회로 잘못 저장하면 총/세트 범위 검사가 실패해야 한다.
4. 확인 전 후보를 분석 projection에 넣으면 경계 검사가 실패해야 한다.
5. 비밀 글 내용·길이·존재만 바꾸면 비공개 저장 외 결과는 불변이어야 한다.
6. 과거 plan revision 대신 현재 plan을 비교하면 원본 대응 검사가 실패해야 한다.
7. 반복회복과 세트회복을 바꾸거나 워치 중복을 합하면 비교 검사가 실패해야 한다.
8. 안전 epoch/근거 revision 검사를 제거하면 실제 동시 적용 시험이 실패해야 한다.
9. 응답 유실 후 같은 idempotency key를 재사용했을 때 적용 영수증이 두 개가 되면 실패해야 한다.
10. 읽음/나중에 확인을 해결 상태로 바꾸면 검토 상태 검사가 실패해야 한다.

중간 검사는 변경한 영역 중심으로 묶고, 출시 전 통합 검수를 한 번 수행한다. 동일 전체 회귀를 무조건 매 단계 반복하지 않는다. 문서 형식 검사와 실제 UI/계정/정책 검증 결과를 분리한다.

## 16. 남은 채택 항목과 시작 기준

### 추가 질문 없이 권장안으로 설계할 범위

- 기본 기록 경로 유지, 글 정리는 선택형, 비밀 글 무신호.
- 그룹 확인, 기존 입력 재사용, 저장/분석/적용 성공 분리.
- 새 하단 탭 없이 홈·일지·달력 공통 상세.
- 직접 입력으로 먼저 비교 완결, 텍스트 기능 때문에 전체 교정 개발을 막지 않음.
- 원본 불변, 과거 계획/일지 유지, 계정 전환·오프라인 안전한 실패.

### 구현·공개 전에 좁게 확정할 항목

1. 글에서 확인한 비민감 운동 수치를 어디까지 저장·설명·교정 입력에 사용할지. 기존 원문 금지를 해제하는 것이 아니라 새로운 파생 확인 경로를 정확히 채택한다.
2. 분석용 글을 비밀로 전환할 때 파생값 철회·직접 재입력·이미 적용된 영수증 보존의 세부 처리. 기본 권장은 §9다.
3. 현재 주기의 어느 변경 유형부터 어떤 승인된 구성으로 교정할지. 코드 작업자가 임의 간격/용량을 정하지 않고 W5에서 근거와 정확한 규칙을 한 번에 준비한다.
4. 기존 NOTE_SAFETY 보류사항 중 이번 변경이 실제로 의존하는 항목과 후속 채택 상태. 현재 계획의 필요를 이유로 실명 심사나 암호 바인딩 증거를 허위 생성하지 않는다.

이 항목들은 세부안을 준비하지 않은 채 사용자에게 추상적인 승인을 반복 요청할 사유가 아니다. W0에서 현재 승인 내역을 먼저 대조하고, 미해결 부분만 선택지·장단점·권장안·영향 기능을 묶어 올린다. 승인된 범위의 작업은 계속할 수 있도록 의존성을 분리한다.

## 18. v0.2 실행 현황과 피로도 제한

오너의 개선 진행 승인에 따라 W0의 출처 수리와 W4의 읽기 화면 개선을 먼저 구현했다. 아래 상태는 로컬 구현 기준이며, 나머지 범위는 삭제하거나 완료 처리하지 않는다. §3의 결함 줄번호와 §17의 미실행 목록은 v0.1 당시 관측이다.

| 작업 | 현재 상태 | 정확한 범위 |
|---|---|---|
| W0 정합성·출처 | PARTIAL_LOCAL | AS_PLANNED/MODIFIED의 직접 확인 오표현 제거. RPE는 나란히 표시만. 비교 계약 RT4 개정. 메모 하류 채택 전수 동기화는 남음 |
| W1 실제 구간 대응 | NOT_STARTED | plan segment와 exercise row의 명시적 연결 및 수정·철회 모델 |
| W2 계정 저장 | NOT_STARTED | 새 대응/확인 자료의 계정 스키마·권한·동시성 검증 |
| W3 선택형 글 정리 | NOT_STARTED | 비밀 글 제외, 사용자 요청·묶음 확인, 확인 전 소비 금지 |
| W4 사실 비교·UI | PARTIAL_LOCAL | 요약/계획·기록/이유, 스와이프, 행동 고정, 일지 재연결. 수치 차이 계산은 W1 이후 |
| W5 영향 정책 | NOT_STARTED | 근거와 채택된 범위별 결정표 준비 |
| W6 일정 교정 | NOT_STARTED | 검토된 구성으로 남은 일정 제안, 자동 보충 금지 |
| W7 계정 적용 | NOT_STARTED | 전후 달력·원자적 수락·검토 상태 |
| W8 통합·배포 | NOT_STARTED | 현재 영역의 로컬 검사는 실행했으나 전체 출시 검수와 배포는 미수행 |

피로도 기준은 다음 구현에도 유지한다.

1. 간편 기록의 필수 입력·저장 단계는 늘리지 않는다. 읽기 화면의 모든 탭을 방문하도록 강제하지 않는다.
2. 요약은 한 줄 결과, 최대 3개 핵심 수치, 다음 행동을 먼저 제공한다. 상세 운동과 근거는 요청할 때 표시한다.
3. 좌우 넘기기, 직접 탭, 화살표, 키보드를 함께 지원한다. 세로 스크롤·텍스트 선택·핀치 확대를 빼앗지 않는다.
4. 일반 글자 크기의 작은 화면에서는 요약을 한 화면에 우선 배치한다. 글자 확대·긴 사용자 자료까지 억지로 맞추려고 글자를 줄이거나 정보를 잘라내지 않는다.
5. 통증·충돌·원본 누락은 제목부터 알린다. 긴 설명을 접는 것이 안전 상태를 숨기는 동작이 되지 않게 한다.
6. 각 내용의 스크롤과 홈 복귀 위치를 보존한다. 관련 없는 자료 갱신 때문에 읽던 화면을 닫지 않는다.

실행 수치, 실패 1건, 미실행 범위는 [구현 보고서 RT4](../implementation/PLAN_EXECUTION_COACHING_IMPLEMENTATION_2026-09-29.md)에 분리했다. 새 스펙 정본 승격·OPEN 이슈 종결·전체 재설계 완료를 선언하지 않는다.

변경 이력 v0.2: ADD 실행 현황/피로도 기준. UPDATE 출처 오류·RPE 표현·짧은 읽기 화면. KEEP W0~W8 전체 목표와 기존 정책 제한. DEFER 새로운 파서·수치 정책·계정 쓰기·출시.
