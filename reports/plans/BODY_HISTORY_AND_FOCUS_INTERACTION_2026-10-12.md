## 1. 목표와 현재 상태

오너는 새 단순 몸 그림의 형태·크기를 승인했다. 이어서 부위를 고르면 크게 보이는
반응, 기타 직접 입력, 다음 방문에 다시 불러오기, 부상 이력 관리 화면을 요청했다.
이 문서는 **오너 승인 구현 계획**이다. 그림 교체 완료와 확대·기타·이력 구현 완료를 혼동하지 않는다.
진행 및 검증 상태는 `reports/review/BODY_HISTORY_IMPLEMENTATION_2026-10-12.md`를 따른다.

2026-10-12 구현 인수: 확대·기타 입력·이력·계정 v4·백업 v6 코드를 연결하고
로컬 검증했다. 이미 배포된 구형 기기 앱의 v1 전체 배열 저장은 새 companion을
지울 수 있다는 P1 때문에 배포를 보류했다. 이후 오너가 **저장소를 분리해 보호한 뒤
배포 준비**를 승인하여 canonical 분리·원본 보존·충돌 확인·삭제 생명주기를 구현했다.
최신 근거는 `reports/review/CANONICAL_LOCAL_JOURNAL_IMPLEMENTATION_2026-10-12.md`를 따른다.
이는 구형 바이너리를 수정한 것이 아니며, 실제 운영 배포·전체 릴리스 검사 완료와도 구분한다.

현재 구현은 부위 이름 버튼 10개와 1–5/해제 선택, 일지의 `painParts` 보관을 제공한다.
이 구조에 사용자 문장을 key로 추가하는 간편한 방식은 채택하지 않는다. 기존
`bodyPartLabel`은 모르는 key를 `기타 부위`로 표시하고, 구조화 분석 경로도 `painParts`를
읽는다. 자유 글이 구조화 부위 ID나 분석 자료가 되면 안 된다.

## 2. 화면 위치: 하단 탭은 유지

추천 진입은 **일지 → 몸 기록**이다. 하단에 여섯 번째 탭을 더하지 않는다.

- 일지 상단에 `일지 / 몸 기록` 두 영역을 둔다. 일지 영역 안의 기존 월별·주기별
  탐색은 그대로 유지한다. 몸 기록으로 갈 때 마지막 날짜·월·스크롤을 기억한다.
- 기록하기 → 컨디션·메모 → 몸 상태에서 `이력 보기`로 같은 화면에 들어갈 수 있다.
  작성 중 입력을 보존하고 돌아왔을 때 선택 중이던 부위와 초안으로 복귀한다.
- 홈에는 부상 요약 카드나 통증 점수를 새로 늘어놓지 않는다.
- 몸 기록이 없으면 제목과 `몸 상태 남기기` 행동만 둔다. 0점 그래프·빈 경고 상자를 만들지 않는다.
- 처음에는 `몸 기록`으로 표시한다. 사용자의 기록을 앱이 진단한 부상명처럼 부르지 않는다.

기본 흐름:

`부위 선택 → 확대된 부위에서 정도 선택 → 기존 입력 확인 → 명시적 저장`

다시 방문:

`최근 기록한 부위 선택 → 오늘 정도만 선택 → 저장`

## 3. 선택 부위 확대

- 기존 부위 버튼을 누르면 **부위 이름 + 확대 그림 + 정도 선택**에 집중한다.
- 모바일은 기존 접근 가능한 시트/대화상자 패턴을 재사용한다. 큰 화면은 같은 내용을
  작은 대화상자로 표시한다. 선택할 때마다 원래 부위 목록의 위치가 밀리지 않게 한다.
- 원본 생성 bitmap을 확대 표시한다. CSS로 몸 그림을 새로 그리지 않는다. 새 그림이
  꼭 필요한 뒤쪽 안내 등은 같은 스타일의 이미지 생성으로 만들고 공동 검수한다.
- 확대용 이미지는 보존된 고해상도 생성 원본에서 표시 크기에 맞춰 내보낸다. 80px 안내용
  경량 이미지를 과도하게 늘려 흐려지게 하지 않고 확대 화면에서만 필요한 자산을 읽는다.
- 확대 시작점은 기존 SVG의 좌표를 재사용하지 않고 새 PNG에 맞는 표시 전용 mapping으로
  검수한다. 이 mapping은 저장되는 통증 부위 ID·정도·일지 좌표와 무관하다.
- `오른 무릎`은 **사용자 자신의 오른쪽**이다. 그림을 보는 사람의 오른쪽과 혼동하지 않게
  제목을 항상 표시한다. 햄스트링은 뒤쪽, 기존 좌우 미지정 `정강이`는 임의 한쪽을 가리키지 않는다.
- `기타` 자유 입력만으로 특정 위치를 추정하거나 빨갛게 표시하지 않는다. 위치가 확인되지
  않은 항목은 전체 기호와 입력한 이름으로 표시한다.
- 현재 그림이 앞·뒤나 특정 부위를 충분히 구분하지 못하는 경우, 정확한 부위 그림을 생성·검수한
  뒤 위치 확대를 연결한다. 그 전에는 이름으로 선택할 수 있게 유지하며 틀린 위치를 강조하지 않는다.
- 한 번의 짧은 확대·이동만 사용하고 반복 맥박·흔들림·축하 효과는 넣지 않는다.
  움직임 줄이기에서는 즉시 전환한다. 이미지 실패 시 이름과 정도 선택만으로 동작한다.
- 포커스는 부위 제목/현재 선택값으로, 닫기·Escape·브라우저 뒤로는 원래 부위 버튼으로
  복귀한다. 배경 조작은 막고 스크롤·키보드·큰 글씨에서 정도와 닫기를 가리지 않는다.
- 수치 선택만으로 일지를 저장하지 않는다. `해제`는 현재 입력 취소이지 회복 완료가 아니다.
- 정도를 고르면 작성 중 초안에 반영하고 원래 부위 목록으로 돌아온다. 같은 부위를 다시 눌러
  고칠 수 있고, 이어서 다른 부위를 고른다. 부위마다 `적용 → 확인 → 다음`을 반복하게 만들지 않는다.

## 4. 기타 부위와 재사용

부위 목록 마지막의 **`기타 부위`**를 누르면 먼저 부위 이름을 입력한다.
예시는 합성 문구 `왼쪽 발목` 정도로 한 개만 보여준다. 추가 메모는 선택 사항으로 뒤에 둔다.

1. 부위 이름 입력 → 정도 선택 → 기존 입력 확인 → 저장.
2. 실제 저장에 성공한 항목만 다음 방문의 `최근 기록한 부위`에 다시 보인다.
3. 다시 선택하면 **부위 이름만** 이어 쓰고, 오늘의 정도는 새로 고른다.
4. 지난 정도·날짜·메모는 펼쳐 보는 참고 자료이며 오늘 값으로 자동 복사하지 않는다.
5. 저장 전 취소한 이름은 저장된 부위나 과거 이력처럼 남기지 않는다.
6. 오타 수정, 최근 목록에서 숨기기, 기록 삭제를 별개로 처리한다. 목록에서 숨겨도
   과거 날짜의 원문과 이름은 남는다. 전체 삭제 요청은 별도의 삭제 절차를 따른다.
7. 명칭은 안전한 일반 텍스트로 표시한다. HTML/URL 실행·로그/분석 이벤트 전송·AI 분류 금지.
   같은 이름이라고 자동 병합하거나 왼쪽/오른쪽을 추측해 고치지 않는다.
8. 같은 이름을 다시 입력하면 기존 항목을 한 줄로 제안한다. 기존 항목 재사용과 새 항목 생성은
   사용자가 정한다. 모든 입력마다 별도 중복 확인 팝업을 띄우지 않는다.

**다시 불러오기 = 작성 편의. 오늘도 아프다고 자동 저장하기 = 금지.**

## 5. 이력 화면

### 첫 화면

- 주 행동 `오늘 상태 남기기`.
- 실제 기록이 있는 부위만 이름·마지막 기록일로 나열한다. 과거 항목을 `현재 아픈 곳`이라고
  단정하지 않는다. 입력 없는 날을 통증 없음이나 연속 통증으로 계산하지 않는다.
- 각 행을 누르면 해당 부위의 날짜별 기록으로 들어간다.

### 부위 상세

- 부위 이름, `상태 남기기`, 최신 기록을 먼저 보여준다.
- 날짜별 정도·직접 쓴 내용·연결된 원본 일지로 이동할 수 있다.
- 동일 날짜 여러 기록은 개별 시간/출처를 유지한다. 임의 최대값이나 평균 한 줄로 원문을 대체하지 않는다.
- 충분한 직접 기록이 있을 때만 `변화 보기`를 연다. 실제 입력 지점만 표시하고 빈 날을
  0으로 채우거나, 추정 곡선·회복률·예상 복귀일·부상 위험 점수를 만들지 않는다.
- 이전 기록에서 다음 기록으로 이동하는 화살표와 날짜 선택을 제공하되 기존 뒤로 복귀를 유지한다.
- 첫 버전 이력은 **현재 저장된 원본 일지의 관측 목록**이다. 과거 일지를 수정하면 그 결과를
  반영한다. 수정 전 모든 값을 영구 보존하는 감사 로그나 별도 의료 기록 보관을 뜻하지 않는다.
  별도 장기 보관·수정 이력은 기존 휴지통 정책과 구분해 이후에 결정한다.

### 같은 부위가 다시 불편해졌을 때

- 같은 부위의 이름 재사용과 같은 사건/기간으로 묶기는 구분한다.
- `새 기록 묶음으로 시작`은 필요할 때만 더보기에서 제공한다. 날짜 간격을 보고 자동으로
  재발·재부상·새 사건을 판정하지 않는다.
- 묶음의 `기록 마침`은 사용자의 정리 동작이며 `완치` 또는 훈련 안전 허가가 아니다.
- `통증 없음`을 넣으려면 사용자가 오늘 값을 명시적으로 선택해야 한다. 미입력·해제와 다른 상태로
  저장할 계약이 준비되기 전에는, 기존 빈 객체를 통증 0 이력으로 바꾸지 않는다.

## 6. 저장·보안·호환 경계

다음 항목은 UI부터 임의 구현하지 않고 공통 계약을 먼저 고정한다.

- 기존 일지와 통증 ID를 보존한다. 과거 `painParts`는 읽기 어댑터로 이력에 표시하며 재저장하지 않는다.
- 자유 입력 부위는 소유자에 묶인 임의 식별자로 참조한다. 표시 이름과 과거 이름 snapshot을
  분리할 수 있어야 하고, 이름 변경으로 과거 원문이 바뀌면 안 된다.
- 기존 부위 이력은 소유자가 볼 수 있는 원본 일지에서 계산한다. 새 `HEALTH` 문서나
  이력 전용 저장기를 먼저 만들 필요가 없다. 저장된 정도를 별도 이력 DB에 중복 기록하지 않는다.
- 기타 부위는 기존 `JOURNAL`에 선택적·버전 지정 비공개 동반 필드를 추가하는 최소 경로부터
  검토한다. 고유 ID와 표시 이름 snapshot을 분리하고 정도는 단일 원본으로 둔다. 현 계정 codec은
  알 수 없는 필드를 포함한 입력을 그대로 수용하지 않으므로 클라이언트·서버 validator·작성 초안·
  백업/복원 계약을 함께 준비한다. 구현 중 별도 문서가 불가피하다는 근거가 생기면 계약 결정을
  먼저 갱신하며 임의의 새 동기화 체계를 만들지 않는다.
- 새 필드가 구형 앱 저장에서 소실되지 않게 버전·편집 capability 검사를 한다. 모르는 버전을
  기본값으로 덮지 않고 원본·충돌 초안을 보존한다.
- 새 기타 부위의 정도도 기존 안전 확인을 조용히 우회하면 안 된다. 구조화된 숫자와 직접 입력 여부만
  허용된 안전 경로에 연결하며, 명칭·메모 원문을 분석/모델/처방에 전달하지 않는다.
- 계정 사용자에게 몰래 기기 전용 이력을 만들지 않는다. 계정 지원·동의·운영 관문이 닫혀 있으면
  저장 범위를 명확히 제한한다. 온라인 공개는 이번 기획 승인으로 열리지 않는다.
- A/B 계정 전환·로그아웃 시 최근 부위·초안·늦은 응답·이력 cache도 소유자별로 격리한다.
- 이력은 raw 로컬 전체 snapshot이 아니라 기존 `loadEntries`/`filterVisibleJournalEntries` 경로를
  사용한다. 비동기 응답에는 계정과 scope generation을 함께 확인한다. 미연결 기기 자료를
  로그인한 사람의 과거 부상으로 자동 귀속하지 않는다.
- 로컬 보관 실패·계정 pending·거절·revision 충돌을 성공으로 표시하지 않는다.
- 원본 일지 삭제·수정, 이력 수정, 휴지통 복원, 계정 전체 삭제와 철회에 참조가 같이 반영되어야 한다.
  삭제된 기록이 별도 최근 목록/이력 복사본에서 살아나지 않게 한다.
- 휴지통 항목은 기본 이력에서 제외하고 복원한 원본만 다시 표시한다. 완전 삭제 시 연결된
  개인 명칭 snapshot·파생 cache도 정리한다. 다른 남아 있는 기록이 쓰는 부위까지 삭제하지 않는다.
- 전체 백업은 새 자료를 선택 복원 가능하게 버전 확장한다. 예전 백업에 새 자료가 없으면 기존 자료를
  유지한다. 기본 안전 내보내기에 자유 부위 이름·메모를 자동 포함하지 않는다.
- 자동 코치/보호자 공유, 알림, 재활 훈련, AI 진단, 기존 계획 자동 수정은 이번 범위에서 제외한다.

## 7. 구현 순서와 필수 검수

1. **확대 인터랙션:** 저장 구조와 분리해 먼저 적용. 새 이미지 위치·좌우/뒤쪽·정강이·이미지 실패·320px/
   200% 글씨·Escape/브라우저 뒤로·원래 버튼 복귀를 확인한 뒤 오너와 함께 본다.
2. **기존 부위 이력:** 1과 병렬로 기존 기록을 읽는 `몸 기록`과 날짜별 원문 연결을 만든다.
   새 저장 구조를 기다리느라 이미 있는 기록까지 숨기지 않는다. 계산 결과를 원본에 다시 쓰지 않는다.
3. **기타·최근 부위 저장 계약:** 명칭/ID/원본/버전/소유자·삭제·백업부터 고정하고 입력 UI를 연결한다.
   화면 작업과 저장 검토는 파일 담당을 나눠 병렬로 진행하되 아직 연결 안 된 UI를 저장 가능하게 공개하지 않는다.
   저장된 기타 이름을 기존 이력 화면에 통합한다. 사용자 기록 묶음·변화 그래프는 기본 이력 검수 후
   두 번째 단계로 둔다. 이 단계가 없어도 부위별 과거 기록을 잃거나 다시 입력하게 하지 않는다.
4. **통합:** 기존 일지 수정·안전 확인·복원과 맞춰 확인하고, 데이터 경계 검사를 최종 묶음에서 한 번 실행한다.
5. **공동 검수·배포:** 오너의 실제 선택 흐름 확인 후 별도 배포. 그림 승인과 신규 민감정보 구조 승인을 혼동하지 않는다.

최소 수용 시나리오: 첫 부위 선택, 두 부위 동시 입력, 기타 작성 후 취소, 저장 후 재방문,
오늘 정도 미입력, 같은 부위 새 묶음, 과거 이름 수정/숨김, 기록 수정·삭제·복원,
오프라인·저장 실패·A/B 전환·늦은 응답·백업의 구버전, 미입력과 명시적 통증 없음,
높은 기타 통증의 기존 확인 경로, 이미지 실패·큰 글씨·키보드.

필수 금지 반례: 어제 통증의 오늘 자동복사, 취소한 기타 이름의 영속화, 삭제 기록 재출현,
타 계정 최근 부위 노출, 기타 4/5의 안전 누락, 명칭 원문의 분석/로그 전송, `해제`로 완치 판정.

## 검토 지위

기획은 사용자 최신 요청과 현재 코드·상위 계약을 대조한 제안이다. `NOTE_SAFETY_SIGNAL...`과
`RULE_SPEC_D1_D9`의 초안/업로드 지위를 런타임 승인으로 승격하지 않는다. 현재 North Star의
승인된 본인 계정 보관 예외는 인정하되 별도 공개 관문은 유지한다.

### 독립 검토 반영

- Sol 6.1 최대 추론: 기존 일지에서 읽기 전용 이력 계산, 최근 이름과 오늘 정도 분리,
  자유 글 key 금지, 계정 codec/소유자/삭제 경계를 검토했다. UI와 기존 이력은 먼저 병렬 진행,
  기타 저장 계약은 뒤에 연결하는 순서로 반영했다. 원격 서버가 임의 key를 실제 거부하는지는
  확인하지 않았으며 서버 보안 검증 완료로 보고하지 않는다.
- Luna 최고 추론: 기존 부위·1–5 입력과 캡처를 바탕으로 확대·기타·이력 동선을 독립 검토했다.
  선택 후 초안 반영/시트 닫기/원래 버튼 복귀, 검토되지 않은 위치 강조 금지, 같은 이름 재사용 제안,
  첫 버전에서 그래프·묶음보다 날짜별 원문 우선을 반영했다. 기존 A01–A12 가상 시나리오 재사용이며
  실제 중학생 사용 시험이나 신규 12명 조사는 아니다. 월별 최대 통증 요약을 부위별 이력으로
  대체하거나 같은 것으로 부르지 않는다.
