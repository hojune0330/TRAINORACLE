## 0. 작업 목적과 완료 상태

AthleteTime의 구간 시간·랩·레인·페이스 표·스플릿 기능을 TrainOracle의 기존 기록·처방·일지에 정합되게 연결한다. 원본 화면이나 계산 모듈 전체를 복사하지 않는다.

이 문서는 상세 계획에서 승인된 실행 지시서로 이어졌다. 실행 상태는 §12와 별도 검수 보고서로 확인한다. 문서 자체는 정본 승격이나 공개 배포의 증거가 아니다.

완료는 다음을 각각 증명하는 것이다.

1. 기록/목표 → 정확한 구간 시간.
2. 도구·근거 → 직전 화면·선택·스크롤 복귀.
3. 허용된 훈련 → 미리보기 → 명시 적용.
4. 기록 변경 → 보호된 남은 계획 갱신, 당시 일지 불변.
5. 평지 트랙·구간표·페이스 표의 계산과 의미 일치.
6. 계정 저장이 포함된 경우 서버 확인·충돌·실패·결과 불명의 올바른 처리.

SC 시설 규격은 별도 직접 확인이 필요하다. 그 작업을 제외하거나 전체 완료로 위장하지 않는다.

## 1. 시작 전 읽기와 작업 경계

순서대로 다음을 읽는다.

1. `PRODUCT_NORTH_STAR.md`, `AGENTS.md`.
2. `MULTI_EVENT_PACE_REFERENCE_CONTRACT.md`, `SAME_EVENT_RACE_PACE_BINDING_CONTRACT.md`.
3. 계획·상세 처방을 연결할 경우 관련 `TRAINING_SESSION_PRESCRIPTION_CONTRACT.md`, 현재 허용 범위, 활성 계획 편집·계정 저장 계약.
4. `docs/UX_UI_VISUAL_STANDARD.md`, 기존 디자인 인수 패키지와 위험 검토.
5. 상위 계획 §15~24와 원본 F-01~07.

계산/기록 코어, 엄격 스키마, 계정 저장, `AppShell`의 이력은 서로 연결돼 있다. 도메인 인터페이스가 확정되기 전 화면 작업자가 임의 새 필드를 저장하지 않는다.

직전 감사의 합성 388건은 원본 차용 조사다. 새 기능의 실행 증거로 재표시하지 않는다. 기존 미추적 문서·에셋과 타 작업자의 수정은 보존한다.

## 2. W1 — 경계 계약·스키마 맵

**선행:** 계획 v0.2와 원본 감사.
**범위:** 스펙 부속 계약, 기존 스키마·콜백·저장 경로 대조. 아직 화면/운영 변경은 하지 않는다.

### 작업

- 읽기 계산, 개별 훈련 적용, 기존 링크 일괄 갱신을 구분한다.
- 저장 실제 기록, 직접 입력 실제 기록 초안, 목표 초안, 예측, 수동 구간 숫자를 구분한다.
- 원본/평가/계산/훈련 적용 스냅샷의 각 의미를 기존 필드에 매핑한다. 필드가 없으면 UI 임시값인지 저장 필수값인지 기록한다.
- 7종목·하프 거리·60m 제한·목표 적용·예측 비교 전용·일지 보호 규칙이 유지되는지 표로 정리한다.
- 현재 `paceTargetsChanged`의 숫자 변화 판단과 명시 근거 변경의 차이를 정리한다. 자동 새 기록 알림의 무변경 처리와 사용자 선택 변경을 분리한다.
- 직접 입력 값을 저장 실제 기록으로 바꾸려면 기존 기록 등록 경로를 거쳐야 한다. 임시 ID로 실제 경기 근거를 만들지 않는다.
- 새로운 범위의 판정/공식은 만들지 않는다. UI 표 간격이나 행 제한은 처방 증감 규칙이 아님을 명시한다.

### 산출물

`입력 종류 × 계산 종류 × 화면 종류 × 적용 가능 여부` 매트릭스, 스키마 맵, 콜백 책임표, 최소 부속 계약. 실제 파일 이름과 기존 지원 범위를 확인해 기록한다.

### 종료 조건

모든 적용 버튼의 근거와 쓰기 주체가 정해져 있다. 같은 숫자의 목표/실제 변경, 다른 실제 근거 변경을 어떻게 보존할지 명시돼 있다. 새 연구/템플릿/권한 승인 없이 진행 가능한 범위가 분리돼 있다.

## 3. W2 — 입력·산술·포맷터

**선행:** W1 인터페이스.
**주 소유:** 기존 `record-pace` 재사용과 작은 순수 계산/표시 모듈.

### 작업

- 시·분·초의 빈 원문, 미완성 원문, 유효 숫자를 구분한다.
- 소수 초·유한값·양수 합계·각 필드 범위를 검증한다.
- 기존 `raceAverageSeconds`, 하프 호환, 반올림 함수를 재사용한다. 시계 표기는 같은 반올림 값에서 표현한다.
- 무효 입력이 생기면 현재 결과·적용 가능성을 해제하며 사용자 원문을 지우지 않는다.
- 서로 다른 입력 버전의 결과·구간표가 섞이지 않게 단일 스냅샷을 사용한다.
- 균등 구간표와 마지막 부분 거리를 만들고, 상위 계획 §18의 누적 반올림 규칙을 구현한다.
- 가속/직접 구간 조정은 총합을 보존한다. 고정 구간의 시간이 총합을 넘으면 거부한다.
- 페이스 표 범위·간격·최대 행 수를 순수한 표시 규칙으로 관리한다. 무제한 행 생성과 0/음수 페이스를 막는다.

### 수치 대조군

| 입력 | 정밀 결과 | 기본 표시/의미 |
|---|---|---|
| 800m 121.5초 → 200m | 30.375초 | 30.4초, 800m 평균 속도 |
| 1500m 240초 → 400m | 64초 | 1:04 또는 64초 |
| 10000m 2400초 → 400m | 96초 | 1:36 또는 96초 |
| 하프 5400초 → 1km | `5400*1000/21097.5` | 원본 거리 유지, 초 단위 표시 |
| 1500m, 400m 구간 | 400+400+400+300m | 마지막 300m 누락 없음 |
| 10km 2400초, 가속 조정 | 내부 합계 2400초 | 최종 누적 40:00 |
| 59.999초 | 공통 반올림 후 60초 | 1:00/1:00.0 |
| 시1·분0·초-1 | 무효 | 필드 수정, 과거 결과 적용 불가 |

### 종료 조건

PC-01~06·19·23·24 중 순수 입력·계산·표시 규칙에 해당하는 모듈 검증 결과가 있다. 화면 조작 부분은 W3/W6와 W7의 완료 조건으로 넘기고 미실행으로 표시한다. 구간표 합계와 단위가 일치하며, 잘못된 값을 모두 거부하는 구현으로 망가뜨렸을 때 유효 대조군이 실패한다.

## 4. W3 — 핵심 계산 화면·문구

**선행:** W1의 상태/콜백, W2의 결과 계약.
**주 소유:** `PaceCalculator` 제안 화면 및 기존 공통 UI.

### 작업

- PACE-01~04·08을 구현한다. 기존 기록이 있으면 재입력 없이 결과를 연다.
- 기록 없는 사용자는 종목 선택과 구조화 시간 입력만 먼저 받는다. 날짜·출처는 실제 기록 저장 시 기존 화면에서 받는다.
- 첫 결과에 관련 숫자 3개, 기준 종류와 이름, 필요한 날짜 상태만 보여준다.
- 저장 실제 기록은 읽기 전용이다. `목표로 계산`은 임시 목표 초안이며 원본 PB를 수정하지 않는다.
- 기준 선택 목록의 중복 기록·동일 날짜 모호성·오래된 기록·목표 표식을 보존한다.
- 물음표는 짧은 용어, `계산 근거`는 긴 설명으로 분리한다.
- 결과와 표의 공간을 고정하고 기준 변경만 짧게 강조한다. 입력 중 자동 이동을 하지 않는다.
- 키보드 `완료`, 포커스 복귀, 화면낭독기 요약, 줄인 모션을 지원한다.

### 기본 사용자 문구

| 상황 | 권장 문구 |
|---|---|
| 진입 | 페이스 계산 |
| 빈 입력 | 어느 종목 기록인가요? |
| 시간 입력 | 기록 시간을 알려주세요 |
| 저장 기준 | 800m 최근 경기 · 2:01.5 |
| 임시 입력 | 직접 입력한 경기 기록 · 2:01.5 |
| 목표 입력 | 800m 목표 · 2:00 |
| 전체 구간 | 구간 더 보기 |
| 도움말 | 이 시간은 어떻게 계산했나요? |
| 오래된 기록 | 오래된 기록 기준이에요. 날짜를 확인해 주세요. |
| 실제 원본 변경 | 기준 기록이 바뀌었어요. 다시 골라 주세요. |
| 미완성 초 | 초를 마저 입력해 주세요. |
| 음수/범위 오류 | 초는 0 이상 60 미만으로 입력해 주세요. |
| 적용 불가 | 계산은 볼 수 있지만, 이 훈련에는 적용할 수 없어요. |

오류 상태의 한 줄 이유가 실제 차단 원인과 일치해야 한다. 전문 용어만 나열한 개발자 코드를 사용자 문구로 보여주지 않는다.

### 종료 조건

375px 기본 화면에서 기준·핵심 숫자·다음 행동을 바로 읽는다. 320px·200% 확대에서는 내용 손실 없이 재배치/스크롤된다. 기본 보기가 수행 정보를 빼거나 선수용에만 숨기지 않는다.

## 5. W4 — 진입·뒤로가기·계정 생명주기

**선행:** W3 단계 정의.
**주 소유:** 통합 담당의 `AppShell`, lazy 화면 등록, `Trends`, PC 경로.

### 작업

- 오라클의 기존 기록 도구 가까이에 `페이스 계산` 입구를 연결한다.
- 새 오버레이 종류의 마커 검증과 의미 있는 단계의 push/replace 규칙을 추가한다.
- 종목 → 입력은 단계 이동, 자동 계산·숫자 변경은 상태 변경, 도구·근거는 상세 진입으로 분리한다.
- 상위 상태에 초안을 유지해 도구 왕복 시 값이 사라지지 않게 한다.
- 복귀 컨텍스트에 출발 위치·day/slot·segment·scroll/focus·owner/revision을 연결한다. 값은 내부 메모리의 최소 컨텍스트로 보관하고 URL에 개인 기록을 싣지 않는다.
- 기존 미저장 일지/계획의 `runDraftSafeNavigation`을 우회하지 않는다.
- 지연된 복귀 요청은 계정·컨텍스트·수명 확인 후 한 번만 소비한다. 계정 변경 뒤의 오래된 callback을 무효화한다.
- 서비스 PC 경로와 `DesktopWorkspace` 쇼케이스를 구분해 같은 계산 컴포넌트가 동작하는지 확인한다.

### 종료 조건

PC-07·20·22·25가 통과한다. 도구 왕복과 브라우저 뒤로/앞으로가 원점을 보존한다. 20회 숫자 변경이 20개의 뒤로가기 이력이 되지 않는다.

## 6. W5 — 개별 처방·남은 일정·일지 연결

**선행:** W1의 적용/스냅샷 계약, W2·W3·W4.
**주 소유:** 기존 계획 편집·기준 연결·계정 저장 담당.

### 작업

- 개별 모드의 선택된 세션/구간을 고정한다. 다른 목적·날짜·구간을 자동 확장하지 않는다.
- 새 기준 선택은 기존 카탈로그 편집/같은 종목 상세 경로를 쓰고, 일괄 갱신은 기존 링크 갱신 경로를 쓴다.
- 선택 시 부작용 없는 전후 미리보기를 준비한다. 대상·숫자·유지할 반복/회복이 보이는 화면에서 명시 적용한다.
- 직접 입력 숫자와 경기 기록 근거를 구분한다. 거리만으로 기준 종목을 지정하지 않는다.
- 기존 실제 안전 상태가 적용 시 재검증되는지 확인한다. 계산기에서 `문제 없음`을 새로 만들어 안전 통과로 사용하지 않는다.
- 보호 슬롯·오늘 미시작 확인·AM/PM·수동 고정·시간 예산을 현재 계약대로 검사한다.
- 명시 다른 실제 근거/버전과 같은 표시 숫자의 처리, 실제↔목표 처리에 각각 회귀 테스트를 추가한다.
- 계정·계획·기록·일지 버전을 적용 직전 재검증한다. 저장 성공·실패·충돌·결과 불명을 구분한다.
- 완료되면 같은 훈련으로 복귀한다. 되돌리기는 원래 스냅샷을 쓰고 새 수행 자료가 생긴 슬롯은 보호한다.
- 당시 일지에 기록된 처방은 불변이며, 새 기준과 실제 수행을 다음 주기에 사용하는 과정은 기존 적격 근거로 제한한다.

### 종료 조건

PC-10~12·16~18·21~22가 통과한다. 기록 저장만으로 계획을 변경하지 않으며, 적용 후 온라인 확인 없이 완료를 선언하지 않는다. 기존 범위를 넘는 종목 예측/언덕/스프린트/근력 적용을 열지 않는다.

## 7. W6 — 추가 도구·시설 근거

**선행:** W2의 순수 도구 산술, W3·W4의 공통 화면 흐름.
**주 소유:** 트랙/표 도구 담당. 기록 타입·계정 저장·훈련 템플릿 소유권 없음.

### 작업

- PACE-05 구간표, PACE-06 트랙 도구, PACE-07 페이스 표를 같은 입력 스냅샷으로 연결한다.
- 레인 규격·측정선·거리 원본을 한 곳에서 관리하고 표준 가정·출처 버전을 표시한다.
- 같은 출발선 한 바퀴와 스타거를 사용하는 경기 400m를 별도 모드로 읽는다.
- 기본 화면은 선택 레인의 결과만, 전체 레인 비교는 펼치기로 제공한다.
- SC는 시설 도형 원문과 적용 범위를 직접 확인해 기록한다. 원문에 맞는 표준 구성만 명시하고 다른 시설을 동일한 값으로 가정하지 않는다.
- 규격 근거가 미확인인 계산은 비활성으로 남긴다. 나머지 계산 도구 구현은 독립 진행한다.
- 페이스 표의 등급·비생리학적 판정을 제거하고 실제 숫자·단위를 표시한다.
- 행 수 제한·표 접근성·구간 정밀값/누적값·직접 조정 실패 복구를 확인한다.

### 종료 조건

PC-06·08~09·15·23~24가 통과한다. 시설 근거 직접 확인 여부를 별도 표로 보고하며 산술 합계 검사로 시설 적합성을 증명했다고 표시하지 않는다.

## 8. W7 — 집중·공격적 최종 검수

**선행:** 관련 W2~W6 구현.
**범위:** 변경 함수·화면·계획 연결·날짜/계정 경계. 불필요한 전체 회귀 반복은 피한다.

### 작업

- 상위 계획 PC-01~25를 실제 테스트 파일/이름/결과에 매핑한다.
- 계산·UI·기록·계정 저장·배포 증거를 별도 항목으로 보고한다.
- 유효 대조군과 거부 대조군을 모두 둔다. 항상 거부하는 구현으로도 통과하는 테스트는 보완한다.
- 격리된 모듈에 낡은 결과 유지, 합계 보정 제거, 잘못된 목표 표식, 보호 슬롯 허용을 주입해 관련 테스트가 이름으로 실패하는지 확인한다.
- 상위 계획 §11·§22.2의 합성 관점과 고정 seed 무작위 여정을 실행한다. 실제 사람이나 외부 독립 검수로 표현하지 않는다.
- 화면은 320/375px, 데스크톱, 200% 글자, 키보드, 줄인 모션을 확인한다.
- 실계정 왕복이 수행되지 않았다면 `NOT_RUN`으로 보고한다. 익명 API 차단을 로그인 저장 성공으로 읽지 않는다.

### 종료 조건

발견 결함에 수정/미해결/범위 밖 판정이 붙어 있다. 핵심 산술·복귀·보호 슬롯·저장 결과 판정 결함이 남아 있으면 그 경로는 공개하지 않는다. 검증 수만으로 품질을 주장하지 않는다.

## 9. W8 — 통합·공개·후속 인계

**선행:** W7의 범위별 통과, 기존 공개 정책과 필요한 승인 범위.

### 작업

- 문서와 실제 제공 범위·버튼·차단 상태가 일치하는지 마지막으로 확인한다.
- 기존 저장 형식·과거 계획·일지 링크를 그대로 읽는지 확인한다.
- 릴리스 과정은 기존 `lean-ci`·수동 배포 절차와 필수 검사 정책을 따른다. 실패/스킵을 성공으로 표기하거나 필요한 관문을 임의 우회하지 않는다.
- 소스 버전, 공개 번들, 공개 화면 클릭, 계정 적용이 확인된 경우의 왕복을 각각 남긴다.
- 읽기 계산만 공개된 경우, 계획 적용까지 완료한 것으로 보고하지 않는다. SC가 미확인 상태면 별도 조건부 항목으로 보고한다.
- 실제 배포 이후 원점 복귀·기준 한 줄·소수 초·무변경/실패 문구만 짧게 공개 화면에서 확인한다.

### 종료 조건

사용자에게 계산/도구/개별 적용/일괄 적용/일지 보존/계정/시설 규격의 실제 상태가 한 표로 보고돼 있다. 남은 조건부 작업은 담당·이유·다음 행동을 가진다.

## 10. 작업 순서와 통합 소유권

```text
W1 계약·인터페이스
  → W2 산술 + W3 화면
  → W4 진입·복귀
  → W5 계획·일지·계정
  → W6 추가 도구·시설 근거
  → W7 집중 검수
  → W8 공개 확인·인계
```

W2/W3는 W1 이후 독립 파일에서 병행 준비할 수 있다. W6 산술도 W2 이후 준비 가능하지만 통합·완료는 공통 화면과 복귀를 포함한다. 이 가능성은 지금 실제 작업자를 실행했다는 뜻이 아니다.

| 공유 영역 | 한 곳에서 결정할 것 | 다른 영역이 하면 안 되는 일 |
|---|---|---|
| 기록/기준 코어 | 입력 의미·정밀도·스냅샷 | UI가 별도 경기 예측/근거 생성 |
| 계획 적용 | 대상·미리보기·보호·쓰기 | 계산 화면이 직접 서버 변경 |
| AppShell 이력 | 단계·원점·owner·복귀 | 도구별 임의 `window.history` 로직 |
| 트랙 규격 | 원전·상수·적용 범위 | 색/그림만 보고 실제 거리 확정 |
| 계정 저장 | 요청·버전·영수증·실패 | localStorage 성공을 온라인 완료로 표시 |
