# 목표 훈련표 미리보기 개선

오너 요청: 결과에 납득할 근거가 없고 기대가 되지 않는다. 디자인·반응형·클릭 반응·모션도 개선한다.

## 해결한 문제

- 기본 설정인 9.5일마다 3일 훈련이 접힌 메뉴에 있어 월 9회의 이유가 드러나지 않았다.
- 첫 쉬운 훈련 하나만 크게 보여 주요 훈련이 들어 있는지 알기 어려웠다.
- 구간 순서를 긴 문장으로만 읽어야 했다. 준비/정리가 없는 훈련도 모두 포함한 것처럼 보였다.

## 화면과 동작

- 실제 달력 `source.days`로 주요 훈련·쉬운 훈련·휴식 수를 표시한다. 공유 날짜가 있는 프레임별 휴식 합은 쓰지 않는다.
- 횟수 설정과 수정 버튼을 상단에 노출한다. 목표·날짜·훈련 방식은 보존해 재생성하며 실패하면 수정/재시도 화면에 머문다.
- 1·2·3차 탭과 실제 날짜별 훈련 목록에서 원하는 훈련을 고른다.
- 검증된 `resolveCatalogBinding().steps`를 순서 그대로 표시한다. 구간당 1.8초의 순서 미리보기는 사용자가 눌러야 시작하며 실제 운동 시간 재생이 아님을 표시한다.
- 정지·이전·다음·전체 구간 선택을 제공한다. 백그라운드 전환, 훈련 변경, 움직임 줄이기, 시작 전 확인 진입 시 재생을 멈춘다.
- 휴대폰은 세로, 700px 이상은 훈련 목록과 구간 설명을 나란히 배치한다. 44px 버튼, 선택 테두리, 키보드 포커스와 짧은 전환을 사용한다.

## 유지한 경계

훈련 생성량/속도/회복/원본/저장 형식은 변경하지 않는다. 목표와 현재 실력을 구별하며 향상률·달성 확률·가상의 성장 단계를 만들지 않는다. 선택·재생으로 저장/훈련 시작하지 않는다. 기존 시간 확인과 몸 상태 확인을 유지한다. 이미 저장한 계획의 동작은 기존 경로를 유지한다.

## 확인

- 미리보기 4건과 기존 흐름 29건 통과. 이후 횟수 수정·생성 실패 재시도 검사 1건 추가 통과.
- 실제 브라우저 320/375/900px 확인: 가로 넘침 없음, 차수/구간 선택, 3일→4일 수정 시 같은 목표·날짜로 9회→12회 생성 확인. 계획 시작은 실행하지 않았다.
- 독립 원본/코드 검토에서 나온 목표 속도 감속 안내와 편집 상태 초기화 문제를 반영했다.
- 배포 여부는 이 문서가 아니라 해당 커밋의 배포 영수증과 공개 화면으로 확인한다.
