## 1. 이번 요청을 제품으로 옮기면

**기록을 남기면, 계획과 달라진 훈련을 이해하고 다음에 무엇을 할지까지 이어서 알려준다.**

가벼운 차이는 그대로 진행하도록 이유를 설명한다. 의미 있는 차이는 다음 훈련을 확인하게 하고, 필요하면 남은 주기나 중주기를 재설계한다. 시스템이 먼저 알려주되 실제 일정을 바꾸기 전에는 사용자가 전후 일정을 확인한다. 강한 개입을 잦은 경고나 자동 증량으로 구현하지 않는다.

기능은 [신규 비교·재설계 계약](../../specs/reconstruct/PLAN_EXECUTION_DEVIATION_AND_REPLAN_CONTRACT.md)에 묶는다. 이 문서는 전체 구현이 완료되었다는 보고가 아니다. 현재 코드가 지원하는 관찰과 앞으로 만들 판단·적용을 분리한다.

오너의 추가 요청에 따라 **홈에 상설 훈련 코칭과 읽을거리 진입을 배치**한다. [홈·코칭 UX 구현안](PLAN_EXECUTION_HOME_AND_COACHING_UX_2026-09-28.md)은 첨부 화면·현재 Home 코드 대조, 정보 순서, 상태별 버튼, 읽기/검토/적용 구분, 와이어프레임, 접근성·복귀·검수 기준을 포함한다. 기존 A~G 코어 계획을 줄이거나 홈 개편으로 대체하지 않는다.

## 3. 사용자 흐름과 화면 분담

### 기본 경로

1. 일지 저장 성공을 먼저 표시한다.
2. 이미 아는 차이는 다시 묻지 않는다. 필요한 경우 `일부만 했어요`, `다른 운동도 했어요`처럼 한 번에 하나의 선택을 받는다.
3. `달라진 내용` 한 줄과 `다음 훈련 확인`을 보여준다. 일지 저장을 다시 하게 만들지 않는다.
4. 추천 결론을 먼저 보여준다: 일정 유지 / 다음 훈련 변경 / 남은 일정 다시 구성.
5. 달력에서 바뀔 날짜·오전/오후·훈련과 그대로인 부분을 확인한다.
6. `이 일정으로 변경`으로 적용한다. 서버가 확인한 뒤에만 완료를 표시한다.

항상 전 과정을 강제하지 않는다. 유의미한 변경 여부가 아직 불명확하면 추가 질문 하나 또는 자료 도착 후 확인으로 줄인다. 실제 변경이 없다면 일정 비교/적용 단계를 만들지 않는다.

| 진입점 | 역할 |
|---|---|
| 일지 저장 직후 | 오늘 바뀐 사실을 가장 적은 추가 입력으로 확인 |
| 일지의 원래 계획 보기 | 과거 비교와 당시 교정 이유 다시 확인 |
| 계획 달력의 해당 날짜 | 오전·오후 및 다음 일정과의 관계 확인 |
| 홈의 훈련 코칭 | 상설 진입. 중요한 검토 한 건과 다음 행동 우선, 관련 다음 훈련은 중복 없이 통합 |
| 홈의 읽을거리 | 내 기록 코칭 이력과 일반 훈련 설명/예시를 구분하여 제공 |
| 별도 전역 하단 탭 | 첫 구현에서는 만들지 않음. 공통 상세 화면을 재사용 |

기본 보기에도 수행 숫자와 일정 변경은 모두 보인다. 전문 보기는 입력·규칙·기전·출처를 더 보여주는 방식이다. 긴 이유가 달력과 다음 행동을 아래로 밀지 않도록 접어둔다.

## 4. 개발 작업 묶음

모든 코드 작업의 초기 상태는 NOT_STARTED다. 이번 문서 작성과 원본 대조를 아래 작업의 구현 완료로 세지 않는다.

### A. 원본·수행 대응 기반

대상: journal/exercise-log schemas, planned-session-link, 원본 계획 조회 및 계정 저장 adapter.

- 정상/조정/다중 세션 계획을 공통 읽기 projection으로 제공한다. 저장 형식을 강제로 단일 구버전으로 내리지 않는다.
- 새 `ExecutionAlignment`는 계획 occurrence/segment와 실제 component/row의 정확한 대응을 가진다. 과거 v1 링크는 그대로 읽는다.
- 이미 존재하는 운동 기록 수치를 중복 저장하지 않고 필드 ref + revision으로 참조한다.
- source read completeness, account scope, 중복/상충 상태, total/work/recovery time의 범위를 전달한다.
- 워치 자료는 향후 기존 수용 adapter를 통해 연결하며, 연동이 끝났다는 가정을 선행 조건으로 삼지 않는다. 직접 입력으로 먼저 완결 가능한 경로를 만든다.

완료 조건: 기존 원본/일지 무손실, 복합/일2회/수동+기기 중복 반례, 읽기 실패가 빈 자료가 아닌 것을 증명.

### B. 설명 가능한 비교기

대상: 신규 domain comparator와 explanation projection. 기존 RPE 추세 수집기의 제외 규칙은 유지.

- dimension별 planned/actual/unknown을 출력한다. 숫자 차이와 영향 판단은 서로 다른 결과다.
- 실제 범위가 같은 거리·시간·반복·세트·회복만 비교한다.
- RPE-only, 목표 페이스, 복합형, 근력/점프/대체 운동별로 비교 가능 범위를 표시한다.
- 자기보고 완료와 실제 구성 일치를 구별한다. 단순 평균 페이스가 모든 반복을 대표하지 않는다.
- 설명은 실제 사용한 사실/규칙 ref에 묶는다. 규칙이 없는 부분은 새로운 기전을 생성하지 않는다.

완료 조건: 확인된 차이는 읽을 수 있고, 지원하지 않는 생리학 판단은 나오지 않는다. 프라이버시 금지 입력을 바꾸어도 결과가 바뀌지 않는다.

### C. 영향 정책과 교정 범위

대상: 별도 versioned impact policy registry 및 Formation 경계 패치.

- `OBSERVE/CLARIFY/REVIEW_NEXT/REPLAN_REMAINDER/REVIEW_BLOCK`과 독립 안전 상태를 계산한다.
- 변경 이유·의도는 맥락으로 사용하며 구조화 사실과 분리한다.
- 최소 하나의 정확한 실제 사용 범위에 대해 근거 검토와 오너 채택 기록을 만든다. 예시 수치나 전체 제품 승인을 새 간격/용량으로 확대하지 않는다.
- 각 규칙에 필요한 자료·불확실성·허용 액션·반례를 둔다. 모든 차이를 일정 변경으로 만드는 기본 규칙은 금지한다.

완료 조건: 동일 입력/정책 버전은 동일 판단, 불완전 자료와 실제 미수행을 구분, 기존 next-frame trigger에 우회 진입하지 않는다.

### D. 남은 일정 교정 엔진

대상: `impl/src/plan-generator`의 별도 재설계 모듈 + 현재 선택/전체 계획 검증기의 재사용 adapter.

- 원래 목표와 경기·시간·고정 일정, 수행 완료/진행 중 세션을 고정한 dependency graph를 만든다.
- 유지부터 검토하고 필요한 미래 구간만 교체·이동한다. 승인된 기존 configuration만 공급한다.
- 실제 수행이 원래 계획보다 많든 적든 새 catch-up이나 자동 증량을 만들지 않는다.
- 변경안 전체의 빈도·배치·회복·시간·혼합 운동 관계를 검사한다. 모르는 부담을 하나의 점수로 합하지 않는다.
- 현재 주기 내 해법이 없거나 목표 앵커와 충돌하면 더 넓은 범위의 검토를 제시한다. 남은 주기를 통째 재구성할 수 있지만 그 이유와 변경 범위가 명시되어야 한다.
- 중주기 재설계는 실증된 현재 주기 교정 다음 단계로 연결한다. 18프레임 계보가 있다는 이유만으로 24주 적응 처방이 이미 된 것으로 취급하지 않는다.

완료 조건: 정확한 before/after/unchanged map, 원본 불변, 무해법 이유, 다차원 우회 방지, 전체안 정책/숫자 채택 근거.

### E. 계정 적용과 과거 보존

대상: 현 계정 plan repository/서버 RPC/계획 lineage와 journal references.

- 계획 revision + 실제 기록 revision + 규칙/구성 버전 + safety epoch + 권한을 적용 시 재검증한다.
- 계정별 mutation lock과 서버 원자적 적용을 기존 구조에 맞춰 사용한다. UI 메모리 성공은 영수증이 아니다.
- 새 계획과 과거 스냅샷·계보·적용 영수증이 함께 확정된다.
- 늦은 기록/동시 기기/응답 유실/계정 전환/적용 후 새 안전 정보 경로를 처리한다.
- 적용 취소/원래대로는 미래에 대한 새로운 제안이며 과거 수행 기록을 지우지 않는다.

완료 조건: 실제 테스트 계정의 재접속/재조회로 같은 결과, 중복 적용 0, 원본 일지 보존. 운영 개인자료 없이 합성 자료 사용.

### F. 일지·달력·홈의 하나의 검토 흐름

대상: 기존 JournalOriginalPlan 계열, 일지 저장 성공 경로, Plan 화면/달력 상세, 공통 navigation.

홈의 `Home.tsx`, `TrainingHome.tsx`, `home-view-model.ts`도 범위에 포함한다. 상세 UX는 [홈·코칭 구현안](PLAN_EXECUTION_HOME_AND_COACHING_UX_2026-09-28.md)을 따른다. 현재 상단의 큰 분석 소개와 6개 토픽 격자를 그대로 둔 채 코칭 박스를 추가하지 않는다. 기존 분석 기능은 보존하고 위치/표현을 재구성한다.

- 한 질문·한 행동, 이미 입력한 값 재질문 금지, 추가 운동/상세 입력/나중에 검토 지원.
- 계획/실제/권장 다음 행동을 짧게 보여주고 근거는 확장.
- 달력 비교는 실제 년월·요일·오전/오후를 유지한다.
- 자동 스크롤/포커스는 선택 구간을 보이게 하되 입력 중 끌어당기지 않는다. reduced motion은 즉시 전환.
- 뒤로가기·용어집 복귀·브라우저 새로고침·온라인 적용 중 이탈을 포함한다.
- 홈 요약과 상세는 동일한 비교 결과/version을 사용한다. 읽음·검토 해결·서버 적용을 구별하고 여러 미해결 항목을 한 건으로 소실하지 않는다.
- 개인 코칭/일반 글/합성 예시를 분리한다. 근거 없는 매일 분석, 계정 변경 뒤 남는 이전 기록, 화면만 열어도 해결되는 알림은 금지한다.
- 기록만 쓰는 사람의 간편 기록과 기존 분석·학습·꾸미기 접근은 유지한다. 코칭을 모든 사용자의 필수 관문으로 만들지 않는다.

완료 조건: 사용자가 무엇이 달랐고, 무엇을 왜 바꾸는지 설명할 수 있는 화면. 320/375px·200% 글자·키보드 접근성. 앱 저장과 분석 권한 경계를 그대로 유지.

### G. 최종 검수·공개

- 중간에는 변경 영역에 필요한 검사를 묶어 실행한다. 같은 전체 suite를 매 단계 반복하지 않는다.
- 최종에는 아래 반례·실화면·계정 저장을 합쳐 검사한다. 문서 PASS나 녹색 빌드만으로 완료하지 않는다.
- 기능별 공개 범위를 분리한다: 사실 비교, 교정안 제시, 계정 적용, 중주기 확대. 덜 완성된 단계의 버튼을 완성된 척 노출하지 않는다.
- 기본 꺼짐 상태의 구현물을 `사용자가 사용할 수 있음`이라고 보고하지 않는다.
- 리뷰 → 병합 → 배포 → 해당 공개 경로 확인 후 마무리한다. 이 문서 작성 시점에는 이 단계가 실행되지 않았다.

## 5. 순서와 병렬 작업 경계

`A → B → C → D → E → F → G`를 기본 의존 순서로 둔다. UI 시안/문구는 B의 typed result가 고정된 뒤 F에서 병렬 준비 가능하고, E의 동시성 설계는 C와 병렬 검토 가능하다. D가 없는 상태에서 F가 허위 추천 결과를 만들어 채우면 안 된다.

| 담당 영역 | 소유 | 금지 |
|---|---|---|
| 코어 작업자 | A/B/C/D의 데이터·정책·계보 | UX 이유로 수치·안전 권한 변경 |
| 저장 작업자 | E의 온라인/충돌/원자성 | 최신 원본 확인 없이 클라이언트 초안을 기준으로 쓰기 |
| UX 작업자 | F의 문장·전환·접근성·달력 비교 | 별도 비교 계산, 잘못된 등가성/회복 보장 문구 |
| 독립 검수자 | G의 반례·원본 재계산·실화면 | 작성자 evidence만 재인용해 독립 검증이라고 하기 |

이는 역할 분담안이지 작업자 발주/실행 기록이 아니다. 현재 열려 있는 `codex/workout-choice-runtime-completion` 작업은 방법 공급/조절 범위다. 이번 시스템은 별도 변경 묶음으로 검토하며 기존 공개 범위를 조용히 넓히지 않는다.
