# 트레인오라클 단계형 화면 전환과 정보 노출 패치 계획

현재 할 일만 보여주고, 해당 입력이나 선택이 끝나면 다음 작업으로 전환한다. 단어를 쉽게 풀면서 문장이 길어지는 문제는 설명을 덧붙이는 대신 정보의 위치와 순서를 바꿔 해결한다. 훈련 수행에 필요한 수치와 안전 상태, 저장 실패는 숨기지 않는다.

사용자가 승인한 것은 이 개선 방향과 전면 패치의 기획이다. 이 문서는 구현 순서와 인수 조건이며 구현 완료나 운영 배포 기록이 아니다. 새 훈련량, 나이별 계수, 보상 가격, 결제 조건을 승인하거나 활성화하지 않는다.

## 기준과 적용 범위

- 기준 소스는 `42a3b7817e3e33caf543e6af9417d65c2890cbc5`다. 2026년 10월 8일 확인 시 로컬 HEAD와 갱신한 `origin/main`이 같았다. 구현 착수 전에는 다시 확인한다.
- 제품 전체를 대상으로 하되 입력과 선택, 비교와 확인, 읽기와 탐색에 서로 다른 패턴을 적용한다. 모든 화면을 강제 순서형으로 바꾸지 않는다.
- 기존 Pretendard, 색상과 간격 토큰, 평면 위계, 제목 역할, lucide 아이콘을 유지한다. 참고 화면의 파란색, 어두운 배경, 둥근 카드와 큰 빈 공간을 그대로 복제하지 않는다.
- 이미 구현된 빠른 계획 질문, 빠른 일지 질문, 도움말, 상세 읽기, 복귀 및 초안 보호를 확장한다. 새 탐색 체계나 저장 체계를 병행해서 만들지 않는다.
- 기존 보유 재료, 꾸밈 좌표, 기록 및 계획 원본, 개인정보와 안전 판단, 계정별 저장 규칙은 유지한다.

## 1 사용자가 요청한 전환 방식

첨부 사례에서 확인된 순서는 별점 선택, 후기 입력, 선택 사항 확인, 등록, 완료 및 실제 보상 확인이다. 사용자는 처음에 별점만 보고, 이를 선택한 뒤 후기 입력으로 이동했다. 다음 항목을 전부 접어 둔 긴 페이지가 아니라 현재 단계 자체가 바뀌는 구조를 적용한다.

기본 구조는 다음과 같다.

`현재 질문 → 유효한 답 → 다음 질문 → 필요한 내용 함께 확인 → 명시적 저장 또는 적용 → 실제 결과 → 닫기 또는 다음 행동`

- 다음 단계는 아직 시작하지 않았다면 본문과 화면 읽기 순서에 노출하지 않는다. CSS로만 가린 입력을 남기지 않는다.
- 이전 답은 수정 가능한 짧은 요약으로 보존한다. 질문과 설명을 모두 아래에 누적하지 않는다.
- 선택 즉시 넘어가도 되는 단일 선택은 바로 다음 질문으로 간다. 해당 선택이 다음으로 이동한다는 사실을 접근 가능한 안내에 포함한다.
- 숫자와 글 입력, 복수 선택은 사용자가 `다음`을 누른다. 입력 길이나 특정 숫자에 도달했다는 이유로 자동 이동하지 않는다.
- 계획 적용, 일지 저장, 구매, 삭제, 동의, 안전 상태 확인은 선택만으로 실행하지 않는다. 영향이 드러나는 별도 확정 행동을 유지한다.
- 선택 항목은 필요한 사용자가 열게 한다. 메모나 사진을 넣지 않는 사용자가 빈 추가 단계들을 차례로 통과하게 만들지 않는다.
- 단계 전환은 입력 완료의 표현일 뿐이다. 훈련 수행 완료, 의학적 승인, 계정 저장, 포인트 지급을 뜻하지 않는다.

## 3 화면 유형과 공통 구성

### 입력과 선택 화면

상단은 뒤로가기와 작업 이름, 본문은 현재 질문과 답, 하단은 다음 행동으로 구성한다. 첫 입력 전에 목표를 소개하는 별도 소개 화면을 반복하지 않는다.

- 단일 선택은 한 번 누르면 진행한다. 이전 선택으로 돌아가면 선택값을 그대로 보여준다.
- 단계 수가 분기에 따라 달라지면 허위 `3/5`나 진행률을 만들지 않는다. 현재 단계 이름을 기본으로 쓰고 실제 남은 단계가 확정된 흐름에서만 숫자를 쓴다.
- 최소 글자 수나 강제 메모를 새로 도입하지 않는다. 코칭에 불필요한 질문은 보상 조건으로 만들지 않는다.
- 입력 검증은 해당 입력 가까이에 표시한다. 버튼만 비활성화한 채 이유를 숨기지 않는다.
- 한 화면 높이에 맞추기 위해 글자와 버튼을 축소하지 않는다. 키보드와 큰 글씨가 켜졌을 때는 필요한 세로 스크롤을 허용한다.

### 비교와 최종 확인 화면

전체를 함께 보아야 판단할 수 있는 항목은 한 화면 또는 연속된 하나의 검토 영역에서 제공한다.

- 계획 A와 B의 차이, 변경 전후 훈련, 한 훈련의 준비부터 정리까지, 최종 저장 내용이 대상이다.
- 비교에는 같은 항목과 같은 단위를 사용한다. 시간형과 거리형 구성을 비교할 수 없으면 근거 없이 환산하지 않는다.
- 작은 화면은 세로 비교를 허용하되 같은 항목의 대응 관계를 유지한다.
- 모든 상세 설명을 읽어야 `적용`이 활성화되는 방식은 쓰지 않는다. 필요한 입력과 실제 안전 확인만 적용 조건으로 둔다.

### 읽기와 탐색 화면

홈, 달력, 오라클 주제 선택, 기록 목록, 설정에는 자유 탐색을 유지한다. 카테고리를 순서대로 완료해야 다음 카테고리가 열리는 구조로 만들지 않는다.

- 목록은 짧은 항목을 보여주고 선택한 내용만 상세로 연다.
- 실제 결과의 핵심 한 줄이나 숫자는 미리 보여준다. 결과가 있다는 이유만 알리고 모든 내용을 도움말 뒤에 숨기지 않는다.
- 자료가 없는 경우 확인된 상태에 맞는 기록 시작, 실제 다음 일정, 명시적인 예시 중 적합한 경로를 제공한다. 물음표와 빈 지표 상자를 반복하지 않는다.

### 완료 화면

완료한 대상과 상태를 먼저 말한다. 완료 전의 입력 폼은 다시 길게 보여주지 않는다.

- 일지 저장 완료에는 `일지 보기`를 기본 행동으로, `꾸미기`를 보조 행동으로 둔다. `닫기`로 출발 화면에 돌아갈 수 있다.
- 계획 적용 완료에는 `첫 훈련 보기`와 닫기를 제공한다. 즉시 운동을 수행한 것으로 기록하지 않는다.
- 기존 보상 정책의 실제 지급이 확인된 경우에만 받은 포인트를 작은 보조 정보로 표시한다. 추가 질문에 답하면 새 포인트를 준다는 정책은 만들지 않는다.
- 일지는 저장됐지만 계정 보상 확인이 대기 중이거나 요약 조회가 실패한 경우 일지를 다시 저장하게 하지 않는다. 기존 계정 지급 상태를 다시 조회하는 진입을 완료 화면에 연결한다. 현재 모든 실패에 이 재시도 동작이 구현돼 있다고 가정하지 않는다. 기기 보상 원장 저장 실패는 계정 조회 실패와 분리해 기존 복구 규칙을 따르며, 조회 재시도를 새 지급 요청으로 바꾸지 않는다.
- 장식용 체크나 매니저 그림은 짧은 완료 피드백에만 쓴다. 입력 단계마다 축하 애니메이션을 넣지 않는다.

## 4 짧고 명확한 문구 기준

쉬운 말은 긴 풀어쓰기가 아니다. 한 문장에는 하나의 행동만 두고, 숫자와 단위는 함께 표시한다. 한 줄 제한 때문에 말줄임표로 중요한 조건을 잘라내지 않는다.

| 현재 문제가 되는 표현 방식 | 기본 표시 방향 | 설명 위치 |
| --- | --- | --- |
| 본운동 체감 노력 제안 같은 겹친 수식 | `빠르기` 또는 `힘든 정도`와 짧은 실제 기준 | 척도 뜻은 작은 도움말 |
| 회복 구간과 세트 구조가 중첩된 긴 공식 | `달리기`, `사이 걷기`, `반복`을 구분한 순서 | 기존 공식 표기는 자세히 보기 |
| 길게 또는 짧게 | `총 32분`, `10분씩 3번`, `사이 1분 걷기`처럼 실제 구성 | 왜 이 구성을 골랐는지는 하단 |
| 모든 훈련 수치가 기록에서 계산된 것은 아니에요 | 적용된 범위에 `내 기록 기준 페이스` 표시 | 계산 범위와 고정 구성은 페이스 설명 |
| 훈련 방법과 근거를 같은 버튼에 묶기 | `운동 순서 보기`와 하단 `이 훈련을 고른 이유` 분리 | 원리와 출처는 후자 |
| 일반적인 자세히 보기 반복 | 대상이 있는 `페이스 설명`, `입력 내용 수정` | 목적이 같은 도움말은 한곳에 모음 |

위의 32분 예시는 기존 생성 결과를 보여주는 표현 예시이며 새 권장 운동량이 아니다. 고정 훈련의 수치를 문구를 줄이기 위해 바꾸지 않는다.

기본 문구는 제목 한 문장, 필요한 보조 문장 한 개 이내를 우선한다. 복잡한 조건을 억지로 한 문장에 넣지 말고 현재 단계의 입력이나 상태로 분리한다. 안전 안내와 실제 오류는 이 길이 권고를 이유로 삭제하지 않는다.

`쉽게 설명 보기`는 기존 저장된 설명을 별도 읽기 화면에서 보여주는 이름이다. 이번 범위에 음성 재생, 새 AI 응답, 개인 기록의 외부 전송은 포함하지 않는다. 음성이 없다면 `설명 듣기`라고 표시하지 않는다.

## 5 화면별 적용 계획

| 화면 | 기본 노출 | 단계별로 열 것 | 함께 남길 것 |
| --- | --- | --- | --- |
| 홈 | 오늘의 주 행동, 실제 짧은 결과, 주요 목적지 | 기록 시작, 계획 만들기, 개별 결과 상세 | 오늘 맥락, 현재 오류, 꾸미기와 훈련 배우기의 발견 가능한 진입 |
| 계획 입력 | 현재 질문 하나 | 종목, 기록 선택 또는 입력, 부족한 훈련 조건, 몸 상태 확인 | 이미 선택한 종목과 기록의 짧은 요약 및 수정 |
| 계획 결과 | 한 계획의 실행 요약과 명시적 적용 | 일정 수정, 다른 계획 비교, 다른 훈련 선택 | 적용할 기간, 실제 훈련 횟수, 회당 총시간, 미확정 조건과 안전 상태 |
| 오늘 훈련 | 전체 소요 시간, 준비와 본운동과 휴식과 정리의 짧은 순서 | 상세 구간, 설명, 수행 후 기록 | 수행에 필요한 전체 구성과 중단 안내, 전체 순서 보기 |
| 훈련 변경 | 선택한 훈련과 바꿀 항목 | 훈련 선택, 필요한 구간 값, 조건 확인, 변경 검토 | 변경 전후 실제 수치 및 명시적 적용 |
| 일지 작성 | 현재 질문 또는 입력 묶음 | 수행 결과, 필요한 실제 수치, 힘든 정도, 몸 상태, 선택 메모 | 날짜와 대상 훈련, 최종 저장 전 입력 요약과 수정 |
| 일지 수정 | 저장된 요약과 수정할 항목 | 선택한 항목만 편집 | 기존 값, 저장과 취소, 미저장 보호 |
| 일지 읽기와 달력 | 달력과 선택한 날짜 또는 기록 | 선택 기록 원문, 여러 기록 펼치기, 꾸미기 | 날짜 탐색, 기록 수, 간단히와 모두 펼치기 |
| 오라클 | 선택 가능한 주제와 실제 결과 미리보기 | 주제 선택, 필요한 추가 입력, 해당 결과, 근거 | 실제 결과와 예시의 구분, 자료 부족 또는 오류 상태 |
| 꾸미기 | 대상과 미리보기 | 재료 선택 후 관련 도구, 구매 확인 | 결과 미리보기, 적용 또는 저장 상태, 뒤로가기와 되돌리기 |
| 파일 가져오기 | 파일 선택 또는 준비 안내 | 선택한 파일의 미리보기, 확인, 저장 | 가져올 내용과 오류, 원본 보존, 재시도 |
| 로그인과 계정 | 선택한 인증 방식과 필요한 입력 | 해당 방식의 인증과 복구 | 필수 동의, 인증 오류, 계정과 기기 자료 구분 |
| 설정과 자료 관리 | 목적이 보이는 목록 | 선택한 설정이나 관리 작업 | 삭제와 복원의 영향, 되돌릴 수 없는 작업의 확인 |

홈과 하단 탭에 새 대형 메뉴나 완료해야 할 과제 목록을 추가하지 않는다. 현재 하단 목적지 이름과 역할은 유지한다. 전용 입력 흐름에서는 하단 다음 또는 저장 행동과 전역 탭이 겹치지 않도록 기존 작업 화면 경계를 확장한다. 출발 탭과 목적지는 보존하며, 보이는 탭 이동은 기존 이탈 보호를 거친다.

꾸미기는 최초 진입에서 기존대로 일지를 기본 선택한다. 매번 대상을 고르는 시작 단계를 새로 강제하지 않는다. 일지의 기존 저장 방식과 달력의 초안 및 명시적 적용을 구분하고, 구매 확정은 두 편집 상태와 별개로 유지한다. 재료를 하나 놓을 때마다 완료 화면을 통과하게 하지 않으며 선택한 대상의 도구만 보여준다.

## 6 대표 흐름

### 처음 계획을 만드는 사람

`종목 선택 → 기록 선택 또는 기록 없이 진행 → 기존에 없는 조건만 질문 → 몸 상태 확인 → 계획 검토 → 이 계획 적용 → 첫 훈련 보기`

- 종목을 선택하기 전부터 종목별 기록 입력과 상세 템플릿을 전부 렌더링하지 않는다.
- 기존 기록을 선택하면 종목, 시간, 날짜를 다시 입력하지 않는다. 현재 처방에 쓰기 위한 유효성 확인은 별개다.
- 이전 검토에서 확인한 최근 운동 수준과 회당 가능 시간의 부족을 반영할 입력 계약을 준비한다. 현재 편하게 가능한 달리기, 최근 운동 빈도, 이번 계획 외의 고정 훈련, 회당 시간 제한 중 생성에 실제로 사용할 사실만 묻는다.
- 나이나 학교 부문만으로 운동량을 줄이거나 늘리지 않는다. 모르는 답을 0, 정상, 훈련 가능으로 채우지 않는다.
- 새 입력을 받으려면 사용할 목적과 저장 범위, 확인 시점, 재질문 조건이 먼저 정해져야 한다. 답을 받아 놓고 생성에 사용하지 않으면서 맞춤이라고 표시하지 않는다.
- 가능한 시간이 짧다고 준비운동과 휴식을 자동 삭제하지 않는다. 승인된 완전한 구성 중 조건에 맞는 안을 선택한다. 없으면 임의 축소안 대신 시간 또는 구성 선택을 수정할 경로를 준다.
- 새 입력에서 구체적 운동량을 결정하는 규칙은 별도의 훈련 도메인 검토 대상이다. UI 공통화와 분리해 진행한다.

### 오늘 훈련을 보려는 사람

`오늘 훈련 → 전체 소요 시간과 짧은 실행 순서 → 필요하면 구간 상세 → 운동 후 기록`

운동 안내를 보기 위해 매 구간마다 완료를 눌러야 하는 필수 진행표를 만들지 않는다. 첫 화면에서 전체 구성을 확인할 수 있어야 한다. 구간별 안내를 추가해도 `다음 구간 보기`는 읽기 위치만 바꾸며 타이머, 수행 완료, 일지, 포인트를 자동 생성하지 않는다.

### 훈련 후 일지를 남기는 사람

`실제로 어떻게 했는지 선택 → 해당 결과에 필요한 입력 → 힘든 정도와 몸 상태 → 입력 확인 및 저장 → 저장 결과 → 일지 보기 또는 꾸미기`

- 휴식과 건너뜀을 선택한 사람에게 달린 거리와 힘든 정도를 강제로 묻지 않는다. 실제 가벼운 활동은 휴식과 구분하고 기존 저장 계약을 따른다.
- 계획을 그대로 했다고 선택해도 예정 거리, 시간, 페이스를 실제 측정값으로 채우지 않는다.
- 일부 수행이나 변경을 선택하면 해당 차이에 필요한 입력만 연다. 완료나 부분 수행을 뒤에서 바꾸면 연관된 표시와 확인을 다시 검토한다.
- 메모와 추가 운동, 꾸미기는 선택 행동이다. 이를 하지 않아도 기존 유효 기록을 저장할 수 있다.
- 마지막 필수 입력 뒤 확인과 저장 화면을 보여주며 자동 저장 확정이나 자동 보상 완료로 넘어가지 않는다.
- 기존 일지의 한 항목 수정은 전체 질문을 다시 수행하지 않고 해당 항목만 수정한 후 돌아온다.

### 오라클을 보려는 사람

`궁금한 주제 선택 → 이미 있는 자료로 결과 표시 → 필요한 경우에만 추가 사실 입력 → 결과 → 다음 관련 주제 또는 닫기`

이미 볼 수 있는 결과를 가상의 진행률이나 강제 질문 뒤에 숨기지 않는다. 추가 자료가 없으면 현재 확인 가능한 범위를 보여주고 입력은 다음 선택으로 둔다. 결과를 봤다는 이유로 출석과 연속 과제를 완료했다고 처리하지 않는다.

## 7 상태와 복귀 계약

공통 화면 틀은 표시와 이동만 관리한다. 훈련 계산, 안전 승인, 기록 저장, 포인트 지급은 기존 담당 계층이 계속 소유한다.

| 상황 | 필수 동작 |
| --- | --- |
| 답을 골랐음 | 입력 초안 갱신과 허용된 다음 단계 전환만 수행 |
| 이전 답 수정 | 관계없는 답은 유지하고 영향받는 계산과 확인만 무효화 |
| 단계 뒤로가기 | 바로 전 단계와 답, 필요한 포커스 복원 |
| 도움말 닫기 | 도움말을 열었던 질문과 입력 위치로 복귀 |
| 흐름 닫기 또는 탭 이동 | 출발 화면 복귀, 기존 미저장 보호를 한 번만 실행 |
| 브라우저 뒤로가기 | 기존 히스토리를 소유한 AppShell에서 오버레이와 복귀를 처리. 단계별 히스토리는 현재 모든 흐름에 존재하지 않으므로 공통화 2단계에서 연결 계약과 동작을 확인하고 적용. 별도 전역 뒤로가기 처리기는 금지 |
| 새로고침과 재진입 | 일지 등 기존 계정별 초안 저장이 가능한 범위에서 답과 현재 단계 복원. 현재 PlanBeta 미완료 입력은 같은 복원 보장이 없으며 이전 보관 계획의 입력 재사용과 구별. 지원 전에 자동 보관이라고 말하지 않음 |
| 저장 중 중복 누름 | 한 작업으로 유지하며 중복 쓰기와 중복 지급 방지 |
| 서버 저장 성공과 기기 복사 실패 | 기존 저장 결과가 이 구분을 실제로 제공하는 경로에서 계정 저장 성공은 유지하고 기기 복사 문제만 분리 표시. 새 복사 계층을 만들지 않음 |
| 전송 대기 | 안전하게 보관됐는지 구분. 계정 저장 완료와 포인트 지급 완료를 앞서 표시하지 않음 |
| 결과 불명과 충돌 | 초안을 보존하고 기존 상태 확인과 재시도 경로 사용. 새 작업 ID로 무조건 다시 보내지 않음 |
| 계정 변경과 늦은 응답 | 이전 소유자의 답과 결과를 새 계정에 보여주거나 적용하지 않음 |
| 날짜 또는 계획 변경 | 읽기 위치 변경과 처방 재계산을 분리하고 필요한 기존 승인만 다시 확인 |

내부 상태도 입력 유효, 확인 필요, 제출 중, 보관 또는 전송 대기, 저장 확인, 결과 불명, 실패를 구분한다. 화면의 단일 `완료` 값으로 대체하지 않는다. 보상 상태는 저장 상태와 분리하고 기존 정책과 원장을 읽는다.

전체 앱에 새로운 전역 뒤로가기 처리기를 추가하지 않는다. 기존 `browserNavigation`, `AppOverlayNavigation`, `useNavigationReturnFrame`, 계획 초안 가드, 폼 초안 경계를 연결한다. 한 번의 뒤로가기로 두 단계가 사라지거나 같은 이탈 확인이 두 번 열리지 않게 한다.

PlanBeta의 미완료 입력을 새로고침 후 복원하는 기능까지 추가하려면 계획용 초안의 저장 및 계정 계약을 먼저 정한다. 일지의 초안 저장 형식을 그대로 복사하지 않는다. 이전 보관 계획의 입력을 시작값으로 사용하는 기능이나 이탈 경고가 존재한다는 이유로 미완료 입력 복원이 구현됐다고 판단하지 않는다.

## 8 반응형과 접근성

- 새 화면은 320px, 375px, 큰 화면과 200% 글자 확대에서 확인한다. 좁은 화면을 기준으로 넓은 화면도 휴대전화 폭에 고정하지 않는다.
- 하단 행동은 안전 영역과 키보드 위에서 입력을 가리지 않게 배치한다. 고정 버튼을 사용하면 본문 끝 여유와 마지막 입력 접근성을 함께 보장한다.
- 이전 단계에서 사라진 필드는 키보드와 화면 읽기 순서에도 남지 않아야 한다. 오류가 있는 입력은 해당 단계로 돌아가며 접근 가능한 오류 이름을 제공한다.
- 단계가 바뀌면 제목 또는 적절한 입력으로 초점을 옮기되, 모바일에서 매번 키보드를 강제로 열지 않는다.
- 상위 답을 수정한 경우 바뀐 내용을 알린다. 포커스 이동이나 애니메이션 도중 추가 탭이 다른 선택으로 해석되지 않게 한다.
- 버튼은 최소 44px 터치 영역을 유지한다. 짧은 물음표 아이콘도 접근 가능한 설명 이름과 충분한 누름 영역을 가진다.
- 움직임 줄이기 설정에서도 같은 입력과 복귀가 가능하다. 가짜 로딩, 자동 넘김 카운트다운, 단계별 축하 연출을 넣지 않는다.
- 필수 수행 수치를 줄 수나 높이 제한으로 자르지 않는다. 여러 반복 구조는 실제 의미가 보존되는 그룹으로 표시한다.

## 9 구현 순서와 병렬 분담

| 순서 | 작업 | 완료 기준과 병렬 경계 |
| --- | --- | --- |
| 0 | 최신 main 및 열린 작업 대조, 화면별 노출 목록 확정 | 통합 담당 한 명, 공통 파일 소유권 고정. 기존 미추적 자료 보존 |
| 1 | 확인된 수행 안내 결함 수정 | 오늘과 일정의 개별 총시간 표시, 긴 기본 표기 분리, 경로별 중단 안내 일치. 훈련 수치 변경 없음 |
| 2 | 공통 단계 화면과 도움말 및 완료 패턴 | 상태 계약, 기존 단일 히스토리 소유자에 대한 단계 뒤로가기 연결, 포커스, 키보드, 저장 결과 분리. 빠른 일지 한 흐름으로 먼저 검증 |
| 3 | 계획 입력과 선택 및 변경 | 기존 기록 재사용, 필요 항목만 질문, 실제 비교와 최종 적용. 새 처방 규칙은 별도 검토된 것만 연결 |
| 4 | 일지 네 양식과 수정 및 완료 | 초안과 기록 종류 보존, 선택 입력 분리, 단일 항목 빠른 수정, 실제 저장과 지급 분리 |
| 5 | 홈과 오라클 및 파일과 꾸미기와 계정 및 설정 | 화면별 표에 따라 선택한 기능만 표시. 전체 보기와 주요 진입 보존 |
| 6 | 통합 검수와 단계 공개 준비 | 변경 경계 중심 검증, 실제 학생 이해도와 반복 사용자 동선 확인, 최종 묶음 릴리스 관문 |

공통 인터페이스 확정 뒤 계획, 일지, 탐색 화면은 병렬로 맡길 수 있다. 문구와 CSS와 합성 자료는 낮은 작업자에게 분담하고, 훈련 자격, 계정 저장, 보상 및 공통 이동 계약은 통합 담당자가 검토한다. 같은 파일을 여러 작업자가 동시에 수정하지 않는다.

공통화 대상은 얇은 표현 컴포넌트이며 단계 상태는 각 기능이 소유한다. 이동과 보호 및 복귀는 기존 API를 사용한다. 공통 화면 틀은 한 담당자가 소유한다. `AppShell.tsx`, `PlanBeta.tsx`, `PlanCandidates.tsx`, 공유 스타일, 폼 초안 타입은 인계 지점에서 통합 담당자만 변경한다. 다른 담당자는 화면별 어댑터를 작성하고 통합 담당자가 연결한다. 범용 플로우 엔진과 새 전역 상태 저장소를 먼저 만드는 방식은 피한다.

| 담당 | 실제 재사용 지점 | 새로 정리할 책임 |
| --- | --- | --- |
| 통합 및 공통 표시 | `AppHeading`, `InfoDisclosure`, `TermHelp`, `useActiveContentScroll`, `useOrderedStepMotion` | 얇은 단계 화면 틀, 이전 답 요약, 하단 행동, 완료 결과의 공통 표현 |
| 이동과 초안 | `browserNavigation`, `AppOverlayNavigation`, `useNavigationReturnFrame`, `usePlanDraftNavigationGuard`, `useFormInputDraft` | 기존 이탈 확인의 단일 실행, 소유자와 이동 수명 확인, 실제 복원 가능 범위 표시 |
| 계획과 수행 안내 | `PlanIntake`, `PlanCandidates`, `InstantPlanTodayView`, `PlanSchedulePreview`, `WorkoutNotation` | 결정 필수 항목과 도움말 분리, 같은 처방의 실행 요약과 전체 순서 |
| 일지 | `QuickSessionForm`, `PostSessionForm`, 기존 경기 및 하루 마무리 양식, `useFormFinalization` | 답에 따른 단계, 기존 기록의 빠른 수정, 저장 결과와 후속 행동 |
| 탐색 화면 | `TrainingHome`, `HomeOraclePreview`, `JournalArchive`, `More`, 기존 꾸미기와 계정 화면 | 선택한 상세만 열고 주요 진입과 전체 보기 유지 |

전체 시간 같은 필수 표시 여부를 사용자용 라벨 문자열과 비교해 결정하는 구조는 정리한다. 표시 역할과 한국어 문구를 분리해 문구를 바꾸어도 총시간이 사라지지 않게 한다. 이는 읽기용 표시 계약이며 저장된 처방을 재계산하거나 변경하는 작업이 아니다.

확인 시 열린 PR #353은 개인 계획 읽기 성능 및 브라우저 검사 정합성을 다루며 위 공통 파일과 여러 관련 검사에 겹친다. 해당 변경을 무조건 병합하지 말고 반영 여부와 현재 main 내용을 먼저 대조한다. 초안 PR #349 미니게임은 이번 패치 의존성이 아니다. 이번 기획에서 PR, 검사 상태, 배포를 변경하지 않았다.

## 10 검증과 수용 기준

각 검사는 구현한 묶음에서 한 번씩 필요한 범위로 실행한다. 기획만으로 통과를 기재하지 않는다.

| 묶음 | 반드시 확인할 것 |
| --- | --- |
| 노출 | 앞 답 완료 전 다음 질문이 본문과 접근성 트리에 없음. 이미 있는 결과와 안전 정보는 숨기지 않음 |
| 전환 | 단일 선택 한 번, 텍스트와 복수 선택은 다음 버튼. 이중 클릭과 키보드 입력 완료가 중복 전환을 만들지 않음 |
| 이해 | 학생이 도움말 없이 전체 시간, 할 일, 반복, 사이 휴식, 중단 조건을 자기 말로 설명할 수 있음 |
| 반복 사용 | 저장된 사실을 재사용하고 한 항목 수정에 전체 흐름을 다시 요구하지 않음. 기존 빠른 작업보다 필수 클릭이 늘면 원인 검토 |
| 처방 일치 | 오늘, 달력 상세, 전체 순서, 편집 미리보기의 거리와 시간과 반복 및 회복 합계가 같은 저장 처방과 일치 |
| 초안과 복귀 | 뒤로가기, 닫기, 탭 이동, 도움말 왕복, 계정 변경에서 초안 및 출발 위치 계약 유지. 새로고침 복원은 지원한 기능별로 확인하고, PlanBeta 미지원 범위를 복원 성공으로 표시하지 않음 |
| 저장과 보상 | 일지 성공과 보상 실패 분리, 전송 대기와 성공 구분, 결과 불명에서 중복 저장과 중복 지급 없음 |
| 안전 | 통증과 불확실 상태, 미확정 처방, 기준 기록 변경, 더 긴 구성의 기존 확인을 단계 전환으로 우회하지 않음 |
| 접근성 | 작은 화면, 200% 글씨, 키보드, 화면 읽기, 움직임 줄이기, 하단 안전 영역에서 조작 가능 |
| 성능 | 미선택 상세와 자료는 필요 시 불러오고 화면 전환마다 저장소 전체를 다시 읽지 않음. 숨김으로 인한 초안 유실 없음 |

실제 학생 확인은 운동을 시키는 시험이 아니라 화면 이해도 과제로 시작한다. 초보 학생, 운동부 경험자, 시간 제한 사용자, 반복 작성자를 구분한다. 합성 페르소나 검토를 실제 학생 검증으로 대체하지 않는다. 수행과 부상 예방 효과의 검증은 이 UI 시험의 범위가 아니다.

새 분석 이벤트나 개인 건강 자료 수집 없이 합성 기록으로 단계 수, 왕복 횟수, 스크롤, 입력 손실을 먼저 확인한다. 사용성 측정 때문에 일지 원문이나 통증 내용을 로그로 남기지 않는다.

## 11 공개와 되돌리기 경계

대규모 패치라도 한 번에 모든 화면을 교체하지 않는다. 공통 틀, 계획, 일지, 나머지 탐색 화면의 순서로 묶고 각 묶음이 독립적으로 이전 표시로 돌아갈 수 있게 한다. 되돌리기는 UI와 새 진입만 대상으로 하며 저장된 일지와 계획, 구매, 보상 원장을 되돌리거나 삭제하지 않는다.

저장 형식 변경이 없는 표시 묶음을 먼저 진행한다. 새로운 처방 입력과 계정 저장 형식이 필요한 묶음은 호환 읽기, 쓰기 지원, 기존 초안 처리까지 준비한 뒤 연결한다. 화면 단계 변경을 근거로 계정 공개, 백엔드 활성화, 새 훈련 템플릿 승격을 하지 않는다.

최종 보고는 기획, 구현, 로컬 검사, 독립 검토, main 반영, 공개 배포, 실제 계정 확인, 실제 학생 확인을 분리한다. 새 URL을 계속 만드는 대신 기존 정식 주소를 유지하고 기존 미리보기와 자산을 보존한다. 배포는 해당 단계의 명시적 요청과 기존 릴리스 관문을 따른다.
