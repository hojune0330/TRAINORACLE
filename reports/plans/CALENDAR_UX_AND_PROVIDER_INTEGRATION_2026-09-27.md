## 1. 목적

계획과 일지를 실제 연월·요일로 탐색한다. 월간 달력은 탐색 창이며 7·9·9.5·10일
계획 또는 중·대주기 규칙을 주 단위로 재편성하는 훈련 엔진이 아니다.
구글·아이폰 달력의 익숙한 연월 제목, 이전/다음 달, 오늘, 날짜 선택을 차용한다.
브랜드 색과 Pretendard, 기존 훈련 이름·도움말·안전·계정 저장 계약은 유지한다.

## 2. 이번 화면 구현

- 공용 MonthCalendar: 일~토 7열, 실제 월의 모든 날짜, 앞뒤 달 날짜 구분.
- 오늘은 채운 원, 선택한 날은 셀 테두리. 서로 다른 상태다.
- 월말·연말·윤년은 기존 로컬 날짜 헬퍼로 계산. UTC 변환으로 하루를 이동하지 않는다.
- 자정과 화면 복귀 때 오늘 표시를 갱신한다. 자정이라고 사용자가 읽던 날짜를 강제로 바꾸지 않는다.
- 계획 날짜에는 오전/오후와 짧은 훈련 분류를 표시한다. 날짜를 누르면 해당 날짜의
  실제 두 세션을 함께 볼 수 있고, 각 세션의 방법·이유·기록을 별도로 연다.
- 원래 후보가 접혀 있어도 날짜를 누르면 수행 내용을 확인할 수 있다.
- 계획 범위 밖을 선택하면 일정 없음을 표시한다. 빈 날을 휴식 처방·수행 완료로 만들지 않는다.
- 일지는 첫 화면부터 현재 월을 보여준다. 기록이 없는 달도 탐색 가능하다.
  기록한 날짜는 기존 하루 일지 리더로 연결한다. 월별 요약과 9.5일 보기 경로를 보존한다.
- 일지 셀은 종류·건수만 표시한다. 메모·개인 제목은 월간 셀에 꺼내지 않는다.
- 키보드 화살표와 Home/End로 날짜를 탐색한다. Enter/Space로 선택한다.
  키보드 탐색만으로 훈련이나 기록을 수정하지 않는다.

## 3. 계획과 일지의 관계

권장: 하나의 날짜 체계와 달력 컴포넌트를 공유하되 계획과 일지의 의미를 섞지 않는다.
계획 탭은 예정 훈련, 일지 탭은 실제 작성한 기록이 중심이다.
향후 통합 보기에서는 `계획 / 일지 / 함께` 필터와 하루 상세 안의 `예정 / 실제`를 둔다.

일지의 오전/오후 구분은 명시적으로 저장된 activitySlot 또는 연결된 세션 정보를 사용한다.
savedAt은 작성 시각이며 실제 운동 시각으로 해석하지 않는다. 시간대를 고르지 않은 기록은
`시간대 미기록` 그룹에 남긴다. 저녁에 작성한 오전 운동을 오후 운동으로 옮기지 않는다.
계획 날짜와 일지 날짜가 같다는 이유만으로 자동 연결·완료 처리하지 않는다.

## 4. 외부 연동 선택지

| 방법 | 가능한 일 | 한계 | 권장 위치 |
|---|---|---|---|
| ICS 파일 | 사용자가 선택한 일정의 일회성 복사 | 수정·삭제가 자동 반영되지 않음. 반복 가져오기에 중복 가능 | 보조 내보내기 |
| 개인 구독 주소 | TrainOracle의 변경을 외부 달력이 다시 읽음 | 공급자 새로고침 지연. 구독 주소 소지자가 읽을 수 있는 위험 | 아이폰/공통 우선 후보 |
| Google Calendar API | 전용 달력에 일정 생성·수정·삭제 | 별도 OAuth 동의, 토큰·재시도·연결 해제 관리 필요 | 구글 자동 반영 |
| 양방향 편집 | 외부 변경도 수신 | 충돌·누락·반복·안전 판정 우회 위험 | 현재 미구현, 우선순위 낮음 |

권장 방향은 TrainOracle를 계획 원본으로 두는 단방향 자동 반영이다. 외부 달력에서
시간을 바꿨다는 이유로 훈련 내용·부하·날짜를 원본에 자동 채택하지 않는다.
2026-09-27 대화에서 방식 선택을 요청했으며, 답변 전에는 새 접근 권한이나 공개 구독을 만들지 않는다.
구글 로그인 완료는 Google Calendar 접근 동의가 아니다.

## 5. 구현 전 확정할 계약

1. 데이터 최소화: 기본 내보내기는 훈련 날짜·시간대·제목만. 상세 처방 포함은 별도 선택.
   비밀/일반 메모 원문, 통증, 건강 지표, 개인 최고기록·선수 근거를 기본 제외한다.
2. 시간: AM/PM을 임의로 09:00/18:00으로 만들지 않는다. 정확한 시각이 없으면
   날짜 일정에 오전/오후를 제목으로 표시하거나 사용자가 직접 시간을 지정한다.
3. 시간대: 계획의 civil-date와 사용자가 택한 IANA timezone을 보존한다.
   여행·서머타임에 종일 일정의 날짜가 이동하거나 9.5일이 10일로 재생성되지 않게 한다.
4. 정체성: 계정+계획+세션 식별자에서 안정적인 외부 event ID를 매핑한다.
   제목이나 날짜만으로 동일 이벤트를 판단하지 않는다. 재시도는 멱등적으로 수행한다.
5. 수정/삭제: 승인된 원본 revision만 반영, 삭제 표식과 원격 반영 상태를 보존한다.
   연결 해제는 향후 전송 중지와 원격 기존 일정 정리 여부를 구분해 안내한다.
6. 구독 보안: 충분히 무작위인 회수 가능한 토큰, 서버에는 해시만 보관,
   로그·오류 추적에서 원문 토큰 제거, 요청 제한·revocation·계정 격리 검사.
   URL 소지자가 볼 수 있음을 동의 화면에 명시하고 공개 검색 색인 금지.
7. Google: 가능한 경우 앱이 생성한 전용 달력만 다루는 calendar.app.created 범위 검토.
   다른 개인 캘린더 전체 읽기·쓰기 권한을 먼저 요청하지 않는다.
8. 진실성: `마지막 반영`, `전송 대기`, `연결 해제`, `실패·다시 시도`를 구분.
   파일 다운로드를 연결 완료나 자동 동기화 완료로 표시하지 않는다.
9. 안전: 과거 Formation Calendar Sync 초안의 epoch/lineage 요구를 확인한다.
   화면 개선 승인으로 미채택 Formation·DB·양방향 수정 계약을 통째로 활성화하지 않는다.

## 6. 순서와 검수

- 이번: 날짜 화면 개선, 공용 달력, 기존 일지 리더·AM/PM 연결, 로컬 검수.
- 다음: 사용자가 연동 방식을 선택하면 위 계약을 구체화하고 서버 저장/권한 설계.
- 이후: 합성 일정으로 생성→수정→삭제→재시도→철회→재연결 실측.
  실제 계정 연동은 전송 범위 확인 후 수행한다. 개인 건강 데이터를 시험 삼아 보내지 않는다.
- 배포는 별도 상태다. 로컬 스크린샷이나 단위 테스트가 공개 배포 증거는 아니다.

검사 항목: 320/375px·데스크톱, 200% 글자 확대, 모션 감소, 키보드, 자정,
월말·연말·윤년, 선택일과 오늘 분리, 계획 밖 날짜, 오전/오후, 메모 비노출,
계획 원본 불변, 일지 열기·뒤로가기.

  앱 생성 보조 달력을 다루는 calendar.app.created 등 범위를 분리한다.
- [Apple iCloud 구독 달력](https://support.apple.com/en-ie/102301): 웹 주소로 구독하고
  iCloud 계정의 다른 기기에서 볼 수 있다. 실제 공급자 갱신 지연은 별도 시험한다.
- 저장소 근거: PRODUCT_NORTH_STAR.md §3.1, docs/UX_UI_VISUAL_STANDARD.md,
  FORMATION_CALENDAR_SYNC_ACCEPTANCE_DECISION.md. 마지막 문서는 과거 차단된 준비 패킷이며
  현재 외부 동기화가 구현되었다는 증거가 아니다.
