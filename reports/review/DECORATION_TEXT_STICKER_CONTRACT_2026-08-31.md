## 0. 왜 계약 문서가 다시 필요한가 (한 줄)

P5는 v3 아이템 스키마에 **사용자 입력 텍스트**라는 새 데이터 종류를 넣는다.
카탈로그 ID만 저장하던 지금까지와 달리 자유 문자열이 저장·백업·복원 전 경로를 흐르므로,
필드 계약을 먼저 고정해 P4 때와 같은 마이그레이션 리스크를 원천 차단한다.

## 1. 스키마 확장 (버전 번호는 3 유지)

새 키·새 버전을 만들지 않는다. v3 `pageItemSchema`를 **하위 호환 방식으로 확장**한다.

```ts
type DecorationPageItemV3 =
  | { itemId: PlacementDecorationId; transform: Transform }            // 기존 (변경 없음)
  | { itemId: "TEXT_STICKER"; text: string; inkId: TextInkId; transform: Transform }  // 신규
```

### 계약 항목별 확정 사항

| # | 계약 | 값 | 근거 |
|---|---|---|---|
| T1 | 식별자 | `itemId: "TEXT_STICKER"` 리터럴 — 카탈로그 배치 ID 집합에 **추가하지 않는** 전용 리터럴 | 상점·보유·비용 개념이 없는 사용자 콘텐츠이므로 카탈로그와 분리 |
| T2 | 텍스트 길이 | **1~20자** (`String.length` 기준, 앞뒤 공백 trim 후 판정, 빈 문자열 저장 금지) | 마스터 플랜 §3-16. 결합 이모지는 length가 더 크게 세어질 수 있으나 단순성을 위해 length 기준 고정 |
| T3 | 허용 문자 | 제한 없음(개행만 공백으로 치환). 렌더는 **텍스트 노드**로만 — XSS 무관 | §3-17 |
| T4 | 금칙어 | **적용하지 않음** — 기존 코드베이스에 커뮤니티 금칙어 정책이 존재하지 않음을 확인(2026-08-31 검색: 금칙어/banned/profanity 부재). 로컬 전용 개인 일지이므로 신설하지 않는다 | §3-17 "재사용 여부만 확인" → 재사용할 대상 없음으로 확정 |
| T5 | 색 | `inkId: TextInkId` — 텍스트 스티커 전용 잉크 팔레트 리터럴 6종: `TEXT_INK_NAVY`(#1F3A5F) · `TEXT_INK_BLACK`(#26241F) · `TEXT_INK_RED`(#B3372E) · `TEXT_INK_GREEN`(#2E6B4F) · `TEXT_INK_VIOLET`(#5B4A8A) · `TEXT_INK_ORANGE`(#B4632A) | §3-16 "잉크 팔레트 색". 기존 `INK_DECORATION_IDS`는 페이지 글자색 1종(INK_NAVY)뿐이라 재사용 불가 — 전용 팔레트 신설. 색값은 종이 톤(--paper) 위 대비 4.5:1 이상 |
| T6 | transform | 기존 v3 transform **그대로 재사용** (4~96 / 0.3~3 / ±180, 라운딩 동일) | §3-16 |
| T7 | 페이지 상한 | 텍스트 스티커도 **24개 상한에 합산** — 별도 상한 없음 | v3 계약 C1 유지 |
| T8 | 복제 | 일반 아이템과 동일(+4%/+4%, 24 초과 거부). 텍스트·잉크 그대로 복사 | §2.4 |
| T9 | z-순서 | 배열 순서 규칙 동일 | v3 계약 C2 |
| T10 | 스키마 판별 | zod discriminated-ish union: `itemId === "TEXT_STICKER"`이면 `text`/`inkId` **필수**, 아니면 **금지**(strict 유지) | 구조 오염 방지 |

### 하위 호환성

- **기존 v3 데이터**(text 없는 아이템)는 확장 스키마에서 그대로 유효 — 마이그레이션 불필요, 버전 3 유지.
- **구버전 v3 파서가 신규 데이터를 만나는 경우**: strict 파서가 `TEXT_STICKER` 아이템을 거부한다. 웹 앱 특성상(GitHub Pages, 항상 최신 번들 로드) 혼용 창은 새로고침 전 탭뿐이며, 그 탭은 저장 시점에 자신이 읽은 상태를 다시 쓰므로 텍스트 스티커만 소실될 수 있다. **방어**: 파서에서 아이템 단위 실패는 페이지 전체 거부가 아니라 **해당 아이템만 제외**하도록 이번에 함께 완화하지 **않는다** — strict 전량 거부 원칙 유지가 데이터 정합성에 더 안전하고, 혼용 창이 실질적으로 없기 때문. (P4 §4와 같은 논리)
- 백업 파일: `full-backup.v3` 형식 태그 **변경 없음** — decorations 필드가 확장 스키마로 검증될 뿐. v3 백업에 텍스트 스티커가 포함되어도 복원 경로는 동일.

## 2. 편집 UX 계약

| # | 계약 | 값 |
|---|---|---|
| U1 | 진입 | 꾸미기 도구 모음에 "텍스트 스티커" 도구 추가 → 탭 시 입력 시트(모바일 하단 시트) 오픈 |
| U2 | 입력 시트 | 20자 카운터(`n/20`), 잉크 6색 스와치(44px, 선택 상태 aria-pressed), 확인 버튼 "붙이기" / 재편집 시 "고치기" |
| U3 | 배치 | 확인 시 페이지 중앙 부근(50±지터) 자동 배치 — 일반 아이템 추가와 동일 경로 |
| U4 | 재편집 | 캔버스에서 텍스트 스티커 **더블탭 = 입력 시트 재오픈**(텍스트·잉크 수정). 일반 아이템의 더블탭(scale/rotation 리셋)은 텍스트 스티커에는 적용하지 않는다 — 리셋은 컨텍스트 미니바/키보드로 대체 가능 |
| U5 | 접근성 | 아이템 aria-label `"글 스티커: ${text}"`, 선택 시 `"글 스티커: ${text} 선택됨."` 프리픽스, 재편집 버튼 대체 경로(선택 테두리에 연필 핸들 44px — 더블탭 불가 사용자용) |
| U6 | Undo/Redo | 텍스트/잉크 수정도 이력 커밋 1회로 스택에 쌓인다(기존 20단계 스택 재사용) |
| U7 | 렌더 | `<span>` 텍스트 노드, 폰트 `var(--sans)`, 기본 크기 16px × scale, `white-space: nowrap`(20자 한 줄), 최대 폭은 transform scale에 위임 |

## 3. 검증 계획 (구현 PR 게이트)

1. **스키마 왕복**: TEXT_STICKER 아이템 저장→로드→저장 동일성. text/inkId 누락·초과(21자)·빈 문자열·일반 아이템에 text 오염 → 전부 파싱 실패.
2. **20자 경계**: 20자 통과 / 21자 거부 + 카운터 UI.
3. **재편집**: 더블탭·연필 핸들 양쪽에서 시트 오픈 → 수정 → 저장 반영, Undo로 이전 텍스트 복원.
4. **복제**: 텍스트·잉크 보존 + 오프셋 + 24 상한.
5. **백업 왕복**: full-backup.v3 내보내기→복원에서 텍스트 스티커 보존, v2 백업 복원 회귀 무영향.
6. **XSS 스모크**: `<img onerror=...>` 류 입력이 텍스트 그대로 렌더(e2e에서 pageerror 0 + innerHTML 미사용 확인).
7. **e2e**: 도구 열기→입력→붙이기→드래그→새로고침 유지→더블탭 재편집→삭제 시나리오, 4개 프로젝트.
