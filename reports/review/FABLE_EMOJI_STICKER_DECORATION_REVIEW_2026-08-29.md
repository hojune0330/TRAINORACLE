## 0. 결론 요약 (오너가 이것만 읽어도 되는 문단)

**"애플 이모지"는 방식에 따라 합법과 침해가 갈립니다.**

| 방식 | 판정 |
|---|---|
| 이모지를 **유니코드 텍스트**로 렌더 → 아이폰 사용자는 자동으로 애플 이모지를 봄 | ✅ 완전 합법, 자산 0바이트, **권고안** |
| 애플 이모지 **이미지(PNG/스프라이트)를 앱에 번들** | ❌ 저작권 침해. Apple Color Emoji는 라이선스가 존재하지 않는 애플 독점 아트워크. 애플은 실제로 타사 이모지 상품에 법적 대응한 전례가 있음 |

한국 사용자 다수가 아이폰이므로, 텍스트 렌더 방식만으로 "익숙한 애플
이모지" 목표가 **아이폰에서는 100% 달성**됩니다. 안드로이드 사용자는
자기 기기의 이모지(삼성/구글)를 보게 되는데, 이 역시 그 사용자에게는
"가장 익숙한 것"이므로 초반 전략("익숙한 것 활용")과 오히려 정합합니다.

V1은 **큐레이션된 이모지 스티커 그리드(추가 의존성 0)**로 시작하고,
전체 이모지 검색 픽커는 V2에서 검토를 권고합니다.

## 2. 애플 이모지 — 법적·기술 판정 상세

1. **Apple Color Emoji 폰트/아트워크는 비라이선스 독점물**이다. 웹폰트
   추출, PNG 스프라이트 번들, 서버 리사이즈 제공 전부 침해. Emojipedia가
   기록한 애플의 단속 사례가 있다.
2. **유니코드 코드포인트 자체는 누구의 소유도 아니다.** `"🔥"`라는
   문자를 저장·표시하는 것은 완전히 자유. 렌더링은 사용자의 기기 폰트가
   수행 → iOS/맥은 애플 그림, 갤럭시는 삼성 그림.
3. **"파생 이모지"**(스킨톤 조합, ZWJ 시퀀스: 👩‍🚀, 🏃🏽‍♀️ 등)도 동일 —
   텍스트로는 자유, 애플 그림 파일로는 불가.
4. 크로스플랫폼 **동일 룩**이 꼭 필요해지면 합법 대안은 둘뿐:
   - **Noto Color Emoji** (OFL) — 구글 스타일
   - **Twemoji** (CC-BY 4.0, 출처표기 필요) — 트위터 스타일
   단, 둘 다 "애플 룩"은 아니며 웹폰트는 수 MB급이라 모바일 퍼스트
   원칙과 충돌. → **V1에서는 채택하지 않음을 권고.**

### 정직성 관점 주의 1건

플랫폼별로 그림이 달라지므로, 공유 이미지 내보내기(향후 팔로워 다이어리
공유)에서는 "보낸 사람이 본 것"과 "받는 사람이 볼 것"이 다를 수 있다.
공유 기능 설계 시 이모지를 그 시점의 렌더로 래스터화할지, 텍스트로
보낼지 계약이 필요하다 (OI로 기록, §10).

정확히는 JavaScript(React) 라이브러리 선택 문제이며, 후보 3안:

## 4. 데이터 설계 — 카탈로그 확장 (스키마 v3)

### 4.1 원칙

- 이모지 스티커는 **이미지 자산이 아니라 유니코드 문자열**로 저장.
  `assetPath` 없음 → 렌더는 `<span>` 텍스트.
- 기존 `DecorationCatalogItem`에 신규 카테고리 `EMOJI_STICKER` 추가,
  배치는 기존 `pagePlacements`(date+slot+itemId) 재사용.
- 코드포인트 검증: 저장 전 정규화(NFC) + 카탈로그 화이트리스트 대조.
  임의 문자열 주입 불가(기존 placementItemIdSchema 방식 유지).

### 4.2 스키마 스케치

```ts
// decoration-catalog.ts 확장
export type EmojiStickerItem = {
  readonly id: `EMOJI_${string}`          // 예: "EMOJI_FIRE"
  readonly category: "EMOJI_STICKER"
  readonly emoji: string                   // "🔥" (NFC, VS16 포함 가능)
  readonly name: string                    // "불꽃" — 항상 한글 이름
  readonly group: EmojiStickerGroup        // §5.2 큐레이션 그룹
  readonly compatibleSlots: readonly DecorationSlot[]
  readonly cost: 0                         // V1: 전량 스타터(무료)
  readonly starterOwned: true
}
```

- **v2→v3 마이그레이션**: ownedItemIds에 이모지 스티커 전량 자동 부여
  (스타터), 기존 배치·소유·포인트 그대로. superRefine의 스타터 보장
  목록에 이모지 세트 포함.
- **백업/복원**: itemId 문자열이므로 기존 backup-file 경로 무수정 통과.
  단 v3 스키마 인지 버전 범프 필요.
- **슬롯 확장 검토**: 현행 4슬롯(테이프/코너/여백/푸터)에 이모지
  전용 다중 배치 슬롯 `BODY_STICKER_1..3` 추가를 제안. 현행은
  날짜+슬롯당 1개 제한이라 이모지 여러 개를 붙이는 다이어리 감성에
  부족. 자유 좌표(drag-anywhere)는 V1 반대 — 겹침·가독성 검증 비용이
  크고 375px 화면에서 오배치 빈발. **고정 슬롯 다중화가 종이 다이어리의
  "칸에 붙이는 스티커" 감성과도 맞다.**

### 4.3 렌더

`DecorationAsset`에 분기 추가:

```tsx
if (item.category === "EMOJI_STICKER") {
  return <span className={`${className} decorated-journal-page__emoji`}
    data-testid={testId} aria-hidden="true">{item.emoji}</span>
}
```

CSS (`decorated-journal-page__emoji`):
- `font-size`: 슬롯별 20/24/28px 3단 (4px 그리드 정합)
- 살짝 기운 각도 `rotate(-4deg ~ 4deg)` — 슬롯별 고정값(랜덤 금지,
  스냅샷 안정성). 종이에 손으로 붙인 스티커의 미세한 비뚤어짐 재현
- **그림자 금지** (A1), 배경 없음, 종이 위 직접 안착
- `user-select: none`

## 5. 디자인 표준 — "끝까지 살리는" 지점

### 5.1 이모지는 유일하게 허용된 "원색"이다

우리 세계는 hairline + 종이톤 + 절제된 에너지 wash다. 이모지는
필연적으로 원색·입체·광택을 가진다. 이 충돌을 다루는 방법:

1. **이모지는 콘텐츠, 크롬이 아니다** — 이모지가 종이(–paper) 위
   "붙인 물건"으로만 존재하면 원색이어도 톤이 깨지지 않는다. 실제
   종이 다이어리에 컬러 스티커를 붙여도 다이어리가 촌스러워지지 않는
   것과 같은 원리. **이모지가 버튼·헤더·탭·차트에 침범하는 순간 반려.**
2. **밀도 상한**: 한 페이지(하루)에 이모지 스티커 최대 3개
   (BODY_STICKER_1..3). 도배는 종이의 여백 질서를 무너뜨린다.
   상한은 스키마(superRefine)로 강제.
3. **크기 질서**: 자유 크기 금지. 3단(20/24/28px)만. 뒤죽박죽 크기가
   가장 빨리 "싸구려 앱" 인상을 만든다.
4. **본문 대비 불가침**: 이모지가 텍스트 줄 위에 겹치지 않는 슬롯
   배치만 허용 (현행 슬롯 모델이 이미 보장).

### 5.2 V1 큐레이션 세트 — 48종 제안 (러너의 다이어리 어휘)

전체 이모지가 아니라, **러너가 일지에 붙일 이유가 있는 것**만:

| 그룹 (탭) | 예시 | 수 |

| 날씨·계절 | ☀️ 🌤️ ☁️ 🌧️ ❄️ 🌸 🍂 🌙 | 8 |
| 몸·컨디션 | 💪 🦵 🫀 😮‍💨 🥵 🥶 😴 🤒 | 8 |
| 달리기·훈련 | 🏃 🏃‍♀️ 👟 ⏱️ 🏁 🏟️ ⛰️ 🛣️ | 8 |
| 기분·감정 | 🙂 😤 😭 🥹 😌 🤩 😑 🫠 | 8 |
| 보상·기념 | 🔥 ⭐ 🏅 🎉 💯 🌟 🍀 ❤️ | 8 |

  ZWJ 시퀀스 렌더 미지원 구형 기기의 두부(□) 폴백 검증 후 개방.
- 확장은 **시리즈 단위**로만(한 번에 한 그룹 8종) — 생성 아이콘
  6기준의 "동일 시리즈는 한 번에" 원칙을 이모지 큐레이션에도 적용.

### 5.3 비밀 포스트잇 × 스티커 — 경계 계약 (가장 중요)

비밀 메모 불변식: **텍스트와 존재 여부 모두 신호 사용 금지.**

- 스티커는 **날짜(페이지)에 붙는다. 메모(항목)에 붙지 않는다.**
  포스트잇 위에 직접 붙이는 UX는 금지 — "비밀 메모가 있는 날에만
  나타나는 시각 요소"가 되어 존재 여부를 간접 누설한다.
- 이모지 스티커 배치 데이터는 어떤 분석·오라클·포인트 입력으로도
  사용 금지 (꾸미기 무권한 원칙 §21과 동일). "🥵를 붙인 날이 많다"
  같은 해석은 오라클에 절대 넣지 않는다 — 스티커는 기분 데이터가
  아니라 장식이다.
- 계약 테스트: 볼트 잠금/해제 상태와 무관하게 같은 날짜의 스티커
  렌더가 동일함을 단언.

### 5.4 효과("작업 효과") — 절제된 물성 모션

- 스티커 부착 순간: `scale(1.15)→1` + 살짝 안착 회전, 220ms,
  `cubic-bezier(0.34, 1.56, 0.64, 1)` 1회. **CSS 트랜지션만** —
  물리엔진·파티클·컨페티 라이브러리 금지 (의존성·톤 모두 위반).
- 떼기: 120ms 페이드+살짝 들어올림.
- `prefers-reduced-motion: reduce` → 모든 효과 즉시 적용(무모션).
- 사운드 없음.

## 8. 반려 기준 미리 고정 (구현 PR 검수 시 적용)

1. 애플(또는 타 벤더) 이모지 이미지 파일이 저장소에 커밋됨 → 즉시 반려
2. 이모지가 UI 크롬(버튼·탭·차트·안전 화면)에 등장 → 반려
3. 외부 CDN에서 이모지 데이터/폰트 로드 → 반려 (오프라인 퍼스트)

6. 스티커 데이터가 오라클·포인트·분석 입력에 등장 → 반려
