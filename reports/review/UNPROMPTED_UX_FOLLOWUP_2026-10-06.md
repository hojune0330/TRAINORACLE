# 처음 보는 사용자 관점 UX 후속 검수

상태: 독립 모의 검수 수집과 후속 수정 완료, 공개 배포 준비. 실제 중학생 사용자 검증이나 사용성 완료를 뜻하지 않는다.

## 검수 방법

- Luna max 작업자 2명에게 이전 결과·정답 경로 없이 사용 목적만 전달했다.
- 계획 만들기와 일지·오라클 탐색을 분리했다. 첫 화면 선택 이유, 실제 버튼 이동, 망설임을 기록한다.
- 합성 사례 및 실제 브라우저 실행과 추론만 한 경우는 각각 구분한다.
- 주 작업자는 기록 40건이 쌓인 별도 격리 브라우저를 사용했다. 실제 계정이나 개인 건강 기록은 사용하지 않았다.
- 127.0.0.1 이외의 브라우저 요청은 차단했다. 계정 저장 검증은 이 범위가 아니다.

## Luna 독립 관찰과 채택 판단

- `gpt-6-luna` max 2명, 총 16개 합성 사례를 준비했으나 독립 브라우저 실행은 **5개 부분 여정**이었다. 16명이 전 과정을 완료했다는 뜻이 아니다.
- 계획 작업자: 320px 1개 부분 여정. 종목/무기록/경력에서 훈련일 선택까지 관찰했다. 주 작업자의 "훈련 숫자 변경 금지"가 합성 선택 금지로 잘못 해석되어 계획 완성까지 진행하지 못했다. 제품 결함으로 집계하지 않는다.
- 일지·오라클 작업자: 375px 3개, 320px 1개 부분 여정. 빠른 기록, 복수 운동 편집, 내 기록/친구 취향 비교, 훈련법 읽기와 복귀를 실행했다. 실제 저장이나 동의 제출은 하지 않았다.
- 실제 관찰에서 명확한 단계 이름과 작성 경로를 수정했다. 내 경기 비교와 친구 취향 비교를 하나로 합치지 않았다.
- 추천 3일이 이미 선택된 것으로 보일 수 있다는 지적은 가설이다. 현재 `selected`와 추천 배지는 별도 상태이므로 처방 기본값이나 선택 로직을 바꾸지 않았다.
- 홈에 기록 선행 조건이 있다는 설명을 덧붙이자는 의견은 채택하지 않았다. 계획은 이미 직접 진입 가능하며 추가 설명은 읽기 부담을 늘릴 수 있다.
- RPE를 모른다는 선택은 유지했다. 운동 기록의 몸 상태 확인을 생략하는 방법으로 간소화하지 않았다. 메모만 남길 때는 기존 하루 마무리 경로를 사용한다.
- 원본 보고서: `LUNA_UNPROMPTED_PLAN_2026-10-06.md`, `LUNA_UNPROMPTED_JOURNAL_ORACLE_2026-10-06.md`. 관찰·가설·환경 한계를 함께 보존했다.

## 실행 근거

- `populated-discovery-journey.spec.ts`: 320/375px 각각 기록 열기·원문 이동·목록 복귀·월 이동·최근 기록 복귀 실행. 수정 전 월 제목 검사 실패, 수정 후 2/2 통과.
- 화면 높이 430px 및 보이는 글자 2배 확대에서 가로 넘침 검사. 실제 기기 키보드·OS 글자 확대 검증은 아니다.
- 관련 컴포넌트 테스트 4파일 40건 통과: labels, PlanSchedulePreview, PlanBeta.persistence-retry, JournalArchive.
- 쉬운 표기를 COACH로 되돌리고 저장 오류 표시를 제거하는 임시 결함을 각각 주입해 새 테스트가 이름대로 실패함을 확인한 뒤 복원했다.
- 테스트 초기 실패 중 원문 비노출 경계와 월 버튼 선택자 오류는 검사 기대값을 바로잡았다. 제품 결함과 구분한다.
- 최종 쉬운 표기·메모 관련 4파일 62건 통과. 기존 메모 테스트의 120초 기대값을 fixture의 실제 150초와 맞췄고 처방 값은 변경하지 않았다. 테스트 간 합성 기록도 격리했다.
- `feature-discovery-journey`와 populated 여정 합계 5건 통과. 쉬운 첫 처방 줄을 추가한 후 계획→일지→같은 훈련 복귀 1건을 다시 통과했다.
- 최신 main `42fc7b8d`의 라운지 소스를 fast-forward로 보존했다. 기능 활성화·운영 SQL·원격 삭제 worker 배포는 하지 않았다.
- 통합 코드 TypeScript 검사 종료 코드 0. 기존 감사 스크립트에서 map의 index가 표시 방식 인자로 넘어가지 않도록 명시적 콜백을 사용했다. 100명 감사 자체를 이번에 실행한 것은 아니다.
- 독립 검수 후 변경한 5개 관련 파일 테스트 103건 통과: QuickSessionForm, EveningCheckin.discovery, InstantPlanEntryForm, OracleExplore, OracleReturnPanel. 두 운동+메모를 먼저 입력한 뒤 몸 상태를 확인하고 한 번만 저장하는 계약, 메모만 저장했을 때 건강 수치가 미기록인 계약 포함.
- 저장 안내 후속 2파일 22건 통과: AppShell.oracle-review-regression, AppChrome. 새 작업에서 일반 안내는 사라지고 안전 검토 안내는 남는지 확인했다.
- `write-first-journey.spec.ts`: 320/375px 2건 최종 통과. 메모 먼저 작성→반복 달리기+근력 추가→운동 결과·몸 상태→기존 메모 확인→저장→새 하루 메모 작성·저장. 이전 완료 안내가 새 화면에 없고 메모 입력칸이 첫 화면에 있는지 확인했다.
- 위 브라우저 검사의 최초 실패는 `기록` 대신 접근성 이름 `기록하기`를 사용해야 했던 검사 선택자 오류였다. 이를 수정한 뒤 촬영 화면에서 실제 완료 안내 가림을 발견하고 제품도 수정했다. 단순 검사 통과와 시각 확인을 분리했다.
- 최종 320px 메모 화면과 375px 훈련 상세 스크린샷을 직접 확인했다. 통과 숫자만으로 사용성이 완료됐다고 하지 않는다.

## 독립 검수의 환경 한계

두 작업자는 개발 중인 같은 Vite 서버를 사용했다. 수정 중 HMR과 선택자 시간 초과가 있었으므로 돌연 홈 복귀를 곧바로 제품 내비게이션 결함으로 분류하지 않는다. 최종 회귀 여정은 수정이 끝난 뒤 실행했으며, 각 작업자의 무안내 관찰 및 가설과 별도로 집계한다.

## 아직 완료로 부르지 않는 항목

실제 사용자가 뜻을 이해했는지, 실제 폰 키보드와 터치가 편한지, 로그인 계정 저장 후 재열기는 이 합성 검사로 증명하지 못한다. 오너와의 짧은 무안내 사용 확인 및 실제 청소년 검수는 별도다.
