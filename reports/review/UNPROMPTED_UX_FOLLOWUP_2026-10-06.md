# 처음 보는 사용자 관점 UX 후속 검수

상태: 수정 및 독립 모의 검수 진행 중. 실제 중학생 사용자 검증이나 사용성 완료를 뜻하지 않는다.

## 검수 방법

- Luna max 작업자 2명에게 이전 결과·정답 경로 없이 사용 목적만 전달했다.
- 계획 만들기와 일지·오라클 탐색을 분리했다. 첫 화면 선택 이유, 실제 버튼 이동, 망설임을 기록한다.
- 합성 사례 및 실제 브라우저 실행과 추론만 한 경우는 각각 구분한다.
- 주 작업자는 기록 40건이 쌓인 별도 격리 브라우저를 사용했다. 실제 계정이나 개인 건강 기록은 사용하지 않았다.
- 127.0.0.1 이외의 브라우저 요청은 차단했다. 계정 저장 검증은 이 범위가 아니다.

## 직접 확인하고 수정한 내용

| 문제 | 변경 | 유지한 경계 |
|---|---|---|
| 지난달 기록에서 최근 일지로 돌아오면 제목은 지난달, 달력은 이번 달 | 표시 중인 달을 제목에도 사용 | 날짜·집계·기록 원본 불변 |
| 훈련 상세 순서가 min/RPE 중심이고 구간 개수를 다시 설명 | 크게 연 훈련의 첫 처방 줄부터 분·초·힘든 정도로 표시하고 중복 안내 제거 | 달력의 코치 표기와 메모 표현 선택, 반복·세트·회복·목표 수치 보존 |
| 월별 기록·훈련 비교가 도움말처럼 표시 | 기능용 펼침 제목과 내용 미리보기 | 기능 삭제·비공개 전환 없음 |
| 크게 연 훈련에서 진행 저장 오류가 뒤 화면에 표시 | 열린 훈련 창에도 오류와 가능한 재시도 표시 | 저장 성공을 꾸며내지 않음, 복구 불확실 시 재시도 금지 유지 |

## 실행 근거

- `populated-discovery-journey.spec.ts`: 320/375px 각각 기록 열기·원문 이동·목록 복귀·월 이동·최근 기록 복귀 실행. 수정 전 월 제목 검사 실패, 수정 후 2/2 통과.
- 화면 높이 430px 및 보이는 글자 2배 확대에서 가로 넘침 검사. 실제 기기 키보드·OS 글자 확대 검증은 아니다.
- 관련 컴포넌트 테스트 4파일 40건 통과: labels, PlanSchedulePreview, PlanBeta.persistence-retry, JournalArchive.
- 쉬운 표기를 COACH로 되돌리고 저장 오류 표시를 제거하는 임시 결함을 각각 주입해 새 테스트가 이름대로 실패함을 확인한 뒤 복원했다.
- 테스트 초기 실패 중 원문 비노출 경계와 월 버튼 선택자 오류는 검사 기대값을 바로잡았다. 제품 결함과 구분한다.
- 최종 쉬운 표기·메모 관련 4파일 62건 통과. 기존 메모 테스트의 120초 기대값을 fixture의 실제 150초와 맞췄고 처방 값은 변경하지 않았다. 테스트 간 합성 기록도 격리했다.
- `feature-discovery-journey`와 populated 여정 합계 5건 통과. 쉬운 첫 처방 줄을 추가한 후 계획→일지→같은 훈련 복귀 1건을 다시 통과했다.
- 최신 main `42fc7b8d`의 라운지 소스를 fast-forward로 보존했다. 기능 활성화·운영 SQL·원격 삭제 worker 배포는 하지 않았다.
- 통합 코드 TypeScript 검사 종료 코드 0. 기존 감사 스크립트에서 map의 index가 표시 방식 인자로 넘어가지 않도록 명시적 콜백을 사용했다. 100명 감사 자체를 이번에 실행한 것은 아니다.

## 독립 검수의 환경 한계

두 작업자는 개발 중인 같은 Vite 서버를 사용했다. 수정 중 HMR과 선택자 시간 초과가 있었으므로 돌연 홈 복귀를 곧바로 제품 내비게이션 결함으로 분류하지 않는다. 최종 회귀 여정은 수정이 끝난 뒤 실행했으며, 각 작업자의 무안내 관찰 및 가설과 별도로 집계한다.

## 아직 완료로 부르지 않는 항목

실제 사용자가 뜻을 이해했는지, 실제 폰 키보드와 터치가 편한지, 로그인 계정 저장 후 재열기는 이 합성 검사로 증명하지 못한다. 오너와의 짧은 무안내 사용 확인 및 실제 청소년 검수는 별도다.
