# 가입·로그인 발견성, 로그인 후 반복, Garmin 연결 구분

검토일: 2026-11-12. 운영 기준 주소: https://trainoracle.io/.

## 확인한 문제와 변경

- 홈에는 작은 로그인 버튼만 있었고 회원가입이 보이는 주요 행동이 아니었다. 비회원 홈에 `회원가입 · 로그인` 주 행동을 추가하고 더보기에서도 한 번에 계정 화면을 연다. 회원은 `내 계정`을 글자로 표시한다.
- 가입 화면의 백업·복원·전체 삭제가 인증과 경쟁했다. 기존 기능을 접힌 보조 영역으로 모았다. 화면/브라우저 뒤로가기는 인증 내부의 이전 단계로 돌아가며 입력을 유지한다.
- 사용자 보고: 아이폰 홈 화면 설치 앱에서 Google 로그인 성공 후 화면이 반복 전환됨. 실제 Account와 계정 범위 조정기를 연결하고 AppShell의 key 재생성 방식을 적용한 검사에서 같은 순환을 재현했다. 기존 코드는 정상 프로필 조회 완료 때마다 범위 재확인을 요청하고, 범위 변경은 Account를 다시 생성하여 다시 재확인을 요청했다. 수정 전 회귀검사는 8회 범위 변경 후 반복 경고로 실패했다. 신규 가입 완료 때만 범위 재확인을 요청하도록 수정 후 안정된 로그인 화면을 확인했다. 계정 변경·삭제·미검증 세션 보호는 유지한다.
- 로그인 상태와 로그아웃을 계정 화면 위로 이동했다. 로그인 후 첫 정렬 위치에도 이 영역과 워치 연결을 함께 둔다. Garmin 연결 해제는 연결 첫 화면에서도 펼칠 수 있다. 트레인오라클 로그아웃과 Garmin 데이터 수신 중단은 서로 다른 동작으로 안내한다.
- 배포마다 앱 자산이 바뀌어도 고정된 `sw.js` 바이트만으로는 열린 PWA에 새 버전을 알리지 못했다. Vite 빌드의 해시된 진입 HTML에서 결정적 해시를 만들어 배포 worker에 붙인다. 동일 앱 재빌드는 불필요한 업데이트를 만들지 않는다. 복귀·온라인 복구 때 업데이트를 확인한다. 미저장 초안·입력값·포커스·인증 교환·처리 중 화면에서는 교체를 미룬다. 빈 홈 메모란만 존재하는 것은 갱신 차단 이유로 삼지 않는다.

## Garmin 인증 방식

1. Google 등으로 **트레인오라클 계정**에 로그인한다. 이는 Garmin 연결 성공이 아니다.
2. Garmin 연결/저장 선택을 확인하고 `동의하고 Garmin 연결`을 누른다.
3. 현재 구현은 `window.location.assign`으로 `https://connect.garmin.com/oauth2Confirm`의 공식 웹 인증을 연다. Garmin Connect 앱의 로그인 상태나 Google 계정을 Garmin 권한으로 대체하지 않는다.
4. Garmin에서 운동 기록이 있는 계정으로 로그인하고 공유를 허용한 뒤 돌아온다. 코드/state와 계정 소유자, 서버의 연결 결과를 확인한다. UI는 실제 ACTIVE 결과와 기록 수신을 구분한다.
5. 워치 기록을 Garmin Connect에 동기화하면 Garmin 서버가 전달한 기록을 받는다. 로컬 Bluetooth 직접 읽기나 Connect 앱 내부 데이터 추출이 아니다.

근거: [Garmin OAuth2 PKCE 공식 문서](https://developerportal.garmin.com/sites/default/files/OAuth2PKCE_1.pdf), [Garmin 프로그램 안내](https://developer.garmin.com/gc-developer-program/overview/).

## 검증 범위

- 실제 Chrome에서 전체 앱의 홈 → 계정, 더보기 → 계정, 인증 내부 뒤로가기/입력 유지 확인. 320×740과 375×812 화면에서 주 CTA 위치 확인. 아이폰 실기기 결과로 부르지 않는다.
- 운영 Auth 설정 읽기: HTTP 200, Google 활성화, 신규 가입 허용. `public-auth-settings.json`에는 민감값 없이 설정 확인 결과만 저장했다. 실제 OAuth 완료·계정 생성의 증거는 아니다.
- Account/Garmin 범위 검사 49개 통과. 로그인 후 반복 재현 회귀 포함. 인증 Gateway 및 계정 범위 검사의 관련 실행도 통과.
- PWA 관련 10개 검사와 빌드 worker 변경 감지 검사 1개 통과. 입력·인증 교환 중 새로고침을 미루고 같은 worker 교체에 한 번만 새로고침하는 경로 포함.
- 타입 검사 통과. 최종 호스팅 빌드와 공개 영수증/자산/화면 확인은 배포 결과 파일에 별도로 기록한다.

## 구분해서 남기는 사항

- 아이폰 홈 앱에서 실제 Google → 복귀 → Garmin 허용 → 실기록 수신까지는 이 작업자의 기기로 실행하지 않았다. 사용자 보고와 코드 재현을 기반으로 수정했으며 실기기 재확인은 별도다.
- 다른 브라우저/앱으로 돌아와 시작 화면의 sessionStorage/PKCE 증명이 없으면 기존 보안 검증은 실패한다. 증명을 복사하거나 검증을 없애지 않았다. 브라우저 간 복귀 호환성을 확인한 것으로 주장하지 않는다.
- 기존 회원도 인증 전에 나이·필수 약관을 확인하는 현재 정책은 변경하지 않았다. 화면 발견성 및 반복 오류 수정과 별도 개선 항목이다.
- 이전 GitHub.io 주소에 설치된 앱인지 여부는 확인되지 않았다. 이번 공개 대상은 canonical 도메인이다. 앱 삭제·재설치 또는 로컬 기록 삭제를 해결책으로 요구하지 않는다.
- 서비스워커 업데이트 원리: [web.dev 공식 PWA 문서](https://web.dev/learn/pwa/service-workers). 기존 실행 중 화면은 갱신 가능한 시점 또는 완전히 닫고 다시 열 때 새 화면을 읽는다.
