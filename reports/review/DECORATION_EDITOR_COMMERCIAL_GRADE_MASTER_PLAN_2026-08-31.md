## 1. 기성 컴포넌트 활용 결정 (데이터 재평가)

오너 지시 "잘 만들어진 컴포넌트 우선"에 따라 bundlephobia 실측으로 재평가했다.

| 후보 | 실측 (min+gzip) | 전이 의존성 | 판정 |
|---|---|---|---|
| `react-moveable@0.56.0` | **73.7KB gzip / 229KB min** | **13개** (@scena/@egjs/@daybrush 생태계) | ❌ 탈락 — 현재 앱 전체 JS(~120KB gzip)의 60%를 조작 레이어 하나에 지불. DOM/스타일 자체 관리라 44px·무그림자 디자인 계약 강제 불가 |
| `interact.js` | ~39KB gzip | 0 | ❌ 탈락 — 명령형 API, React 상태 모델과 이중 소유권 |
| **`@use-gesture/react@10.3.1`** | **8.9KB gzip / 28.6KB min** | **1개** (@use-gesture/core) | ✅ **채택** — 훅만 제공(렌더 무간섭), drag/pinch 동시 바인딩, 멀티터치 경합·취소·관성(velocity) 처리가 상용 검증됨(pmndrs, react-spring 팀). 디자인 계약과 충돌 지점 없음 |
| 스냅/가이드라인 라이브러리 | — | — | 자체 구현 — 우리 좌표계가 %기반 7슬롯→자유배치라 범용 스냅 엔진이 맞지 않음. 중앙선 2줄 + 자석 5%는 30줄 |

**결정: `@use-gesture/react` 1개를 6번째 런타임 의존성으로 추가한다.**
- 근거: 핀치 중 브라우저 기본 줌 차단, 포인터 취소 복구, 드래그·핀치 동시 활성 시 우선순위 등 "직접 만들면 버그로 갚는" 영역이 정확히 이 라이브러리의 검증 범위다.
- 조건: peer로 react만 요구, `touch-action: none`은 이미 우리 CSS에 있음.
- 대체 비용 비교: 자체 2-포인터 구현은 초기 30줄이지만 iOS Safari 제스처 간섭·포인터 유실 엣지를 우리 e2e로 전부 증명해야 함. 8.9KB로 그 검증을 사는 것이 상용 목표에 부합.

## 2. 정밀도·부드러움 사양 (오너 "최소 움직임 단위" 지시 반영)

### 2.1 좌표·수치 계약 (스키마 v3)
- 저장 단위: `xPct/yPct` — **소수 1자리(0.1%)로 라운딩** 후 저장. 375px 기준 0.375px 정밀도로 상용 앱(픽셀 스냅 없는 자유 배치)과 동급이면서 JSON 크기·디프 노이즈 억제
- scale: 0.05 스텝 라운딩, 범위 0.3–3.0으로 확장 (현 0.6–2는 "크게 쓰고 싶다" 요구를 못 받음)
- rotationDeg: 정수 1° 라운딩, 범위 −180~180으로 확장 (현 ±45는 뒤집기 표현 불가). 스냅: 0/±15/±30…±90에 ±3° 자석, 두 손가락 유지 중 스냅 해제 가능
- zIndex: 정수 0–63, 배열 순서와 이중화하지 않고 **배열 순서 = 렌더 순서** 단일 진실(맨앞으로 = 배열 뒤로 이동)

### 2.2 렌더 파이프라인 (60fps 계약)
- 제스처 중: React state 대신 **ref + rAF 배칭**으로 `style.transform` 직접 갱신 (커밋은 pointerup 1회) — 현재 코드는 move마다 setState라 저사양에서 리렌더 병목. 이것이 "부드러움"의 핵심 수정
- `will-change: transform`은 **선택된 항목에만** 부여, 해제 시 제거 (메모리 계약)
- 이동/크기/회전 전부 `transform`만 사용, layout 속성(left/top 재계산) 금지 → 현재 left/top % 스타일을 `translate3d` 기반으로 이관
- reduced-motion: 스냅 자석의 "튕김" 보간 제거, 즉시 배치

### 2.3 조작 어휘 상세
| 제스처 | 동작 | 비고 |
|---|---|---|
| 탭 | 선택 (선택 테두리 + 4버튼) | |
| 빈곳 탭 / Escape | 선택 해제 | |
| 드래그 | 이동. 중앙 H/V 가이드라인 5% 자석 | 가이드라인은 1px 선, --ink-blue |
| 핀치 | 크기 (use-gesture pinch.da[0]) | 손가락 중점 기준 |
| 두 손가락 비틀기 | 회전 (pinch.da[1]) + 15° 자석 | |
| 더블탭 | scale 1.0 / rotation 0 리셋 | 확인 없이, Undo로 복구 가능 |
| 길게(500ms) | 컨텍스트 미니바: 복제 · 맨앞 · 맨뒤 · 삭제 | 44px 버튼 4개 |
| 핸들 | 우하단 크기(44px), 상중앙 회전(44px) — 데스크톱·정밀 조작용 병행 유지 | |
| 키보드 | 화살표 0.5%, Shift+화살표 2%, +/- 0.05 scale, [,] 회전 1°, Delete 삭제, Ctrl+D 복제, Ctrl+Z/Y | |

### 2.4 편집 액션 (오너 "삭제·수정·붙여넣기" 지시 반영)
- **삭제**: 선택 테두리 × 버튼(44px) + Delete 키 + 컨텍스트 미니바. 확인 다이얼로그 없음(Undo가 안전망)
- **복제(붙여넣기)**: 선택 항목을 +4%,+4% 오프셋으로 복사, 새 zOrder 맨앞. 세션 클립보드(메모리)로 다른 날짜 페이지에 붙여넣기 허용 — OS 클립보드는 쓰지 않음(개인정보·권한 불필요)
- **수정**: 선택 → 모든 변환 즉시 가능(이미 충족), 텍스트 스티커는 더블탭으로 내용 재편집(P5)
- **Undo/Redo**: past/future 스택 각 20, 커밋 단위는 pointerup/액션 1회. 저장은 최종 상태만(이력은 세션 메모리)

## 3. 단계별 실행 계획 (승인된 P1~P6 상세화)

### P1 — 조작 기반 + 계약 위반 수정 [즉시 착수]
1. `@use-gesture/react` 도입, 기존 자체 포인터 핸들러를 `useGesture({onDrag,onPinch})`로 교체
2. rAF 배칭 렌더 파이프라인 (2.2)
3. 핸들 44px 히트영역(시각 36 유지, ::after 확장), 회전 상중앙·크기 우하단 분리
4. 빈곳 탭/Escape 해제, 선택 테두리 삭제 버튼
5. 검증: 60fps 트레이스 증적 첨부, e2e(선택/해제/삭제/드래그), 기존 계약 전량

### P2 — 핀치·스냅·리셋
6. 핀치 크기 + 비틀기 회전 (use-gesture pinch), 더블탭 리셋
7. 중앙 가이드라인 + 5% 자석, 회전 15° 자석
8. 검증: Playwright touchscreen 2포인터, 자석 on/off 시나리오

### P3 — 이력·컨텍스트 액션
9. `decoration-history.ts` past/future 스택(20), Redo 버튼, Ctrl+Z/Y
10. 길게 눌러 컨텍스트 미니바(복제·맨앞·맨뒤·삭제), 세션 클립보드 복제
11. 검증: 20단계 왕복, 복제 오프셋·zOrder 계약

### P4 — 스키마 v3 (자유 배치 대공사) [별도 마이그레이션 계약 PR 선행]
12. `pagePlacements`: 슬롯 7칸 → `items[]` 자유 배열(같은 아이템 복수 허용, 페이지당 상한 24), 배열 순서 = 렌더 순서
13. v2→v3 읽기 마이그레이션(슬롯 → 기본 좌표 배열 변환), v3→v2 다운그레이드 불가 명시, 백업 파일 버전 태그
14. 범위·정밀도 확장(2.1) 이 단계에서 함께
15. 검증: 백업/복원 53계약 갱신, v2 파일 복원 회귀, 마이그레이션 왕복 속성 테스트

### P5 — 텍스트 스티커 도구
16. 사용자 입력 텍스트(20자) + 잉크 팔레트 색 + 기존 transform 재사용, 더블탭 재편집
17. 저장은 순수 텍스트(스키마에 `text` 필드), XSS 무관(텍스트 노드 렌더), 금칙어는 기존 커뮤니티 정책 재사용 여부만 확인
18. 검증: 입력·재편집·복제·백업 왕복

### P6 — 마감 디테일
19. 관성 微적용(드래그 놓을 때 velocity 기반 40ms 감속 — reduced-motion 시 제거), 햅틱(`navigator.vibrate(10)` 지원 기기만, 스냅 걸릴 때)
20. 경계 이탈 방지 개선: 회전 고려 AABB로 4% 마진 계산
21. 검증: 저사양 4x throttle 30fps, 최종 시연 영상
