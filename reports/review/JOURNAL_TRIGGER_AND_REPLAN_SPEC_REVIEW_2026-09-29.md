# JOURNAL_TRIGGER_AND_REPLAN_SPEC_REVIEW_2026-09-29.md

## 판정

기존 스펙에 일지/훈련 메모의 일시 분석, 위험 신호 추출, 구조화 신호 전달을 위한 준비가 실제로 있다. 안전 표현 평가기는 코드에도 존재한다. 그러나 일반 수행 문장의 추출과 확인, 계획 구간 대응, 남은 일정 교정까지 완성된 하나의 기능은 아니다.

이번 검토는 로컬 문서와 소스의 정적 대조다. 평가기 정확도 실험, 공개 배포, 모든 과거 승인 기록의 전수 감사는 수행하지 않았다. 운영 선수 자료는 열지 않았고 아래 예문은 합성이다. 코드/안전 판정/스펙 권한을 변경하지 않았다.

## 중요한 정합성 관찰

### 1. 문서와 코드의 안전 소비 상태가 다르다

DAILY_LOG §8에는 `current_downstream_plan_or_SafetyGate_consumer_exists: false` 및 소비자가 없다는 문장이 있다. 실제 plan-beta-flow에는 위 연결이 존재한다. 승인된 후속 예외가 어디에 있는지 추적한 뒤, 안전 확인만 허용된 것인지 문서를 좁은 범위로 갱신해야 한다. 코드가 있다는 사실을 일반 훈련 분석/자동 재설계까지 승인됐다는 뜻으로 해석하면 안 된다.

### 2. 분석 의도와 실제 채택은 별개다

`transient_local_athlete_analysis_allowed: true`는 미래 설계 공간을 제공한다. 같은 블록의 `athlete_analysis_runtime_status: NOT_IMPLEMENTED`, 신호 어휘 `PENDING_SEPARATE_ADOPTION`, 계획 소비 `false`를 생략하고 기능이 준비됐다고 주장할 수 없다. 기존 공격 리뷰에서도 이 오독이 이미 지적됐다.

### 3. 평가기의 원시 결과를 새 기능에 직접 연결하면 안 된다

D9Result에는 일시적 `evidence[].clause`가 포함된다. 현재 UI 래퍼는 이를 제외한다. 새 브리프/코칭/저장 경로에서도 정제된 래퍼를 사용해야 하며, 원시 결과를 통째로 로그/계정/공유에 넣지 않는다. 이것은 현행 유출을 재현한 보고가 아니라 재사용 시의 명확한 위험 경계다.

### 4. 오래된 저장 설명도 그대로 복사하지 않는다

DAILY_LOG §8의 localStorage/암호화 증거 없음 문구와 현재 메모 컴포넌트의 private-note-sync/복구 코드 경로는 시점이 다르다. 이번에는 암호화/온라인 저장 전체를 재검수하지 않았으므로 어느 한쪽을 현재 모든 저장 방식의 설명으로 단정하지 않는다.

## 권장 연결 방식

`분석용 훈련 메모 → 일시 추출 후보 → 사용자 확인 → 출처가 남는 구조화 사실 → 원본 계획 구간 대응 → 차이 설명 → 검토된 교정 정책 → 변경안 확인 → 안전한 계정 적용`

안전 표현 경로는 기존 D9/RVE 경로로 분리한다. 일반 추출 후보의 수락/수정/거절이 기존 위험 상태를 해제하지 않는다. 비밀 메모는 모든 추출 경로에서 제외한다.

| 합성 예문 | 제안할 확인 | 바로 해서는 안 되는 판단 |
|---|---|---|
| 10개 하려다가 6개만 했어 | 이 계획의 반복을 6회 완료했나요? | 부족한 4회를 내일 추가 |
| 쉬는 시간을 60초에서 2분으로 늘렸어 | 반복 사이 회복을 120초로 기록할까요? 세트 사이는 아닌가요? | 거리만 같으니 같은 자극으로 처리 |
| 시간이 없어서 짧게 끝냈어 | 시간이 부족했나요? 실제로 어디까지 했나요? | 체력 부족/회복 불량 판정 |
| 달리기 대신 자전거를 탔어 | 대체 운동으로 기록할까요? | 자전거 시간을 러닝 km로 환산 |
| 오늘은 안 아팠지만 어제는 아팠어 | 시점이 다른 표현으로 구분, 기존 안전 경로 적용 | 아프다는 단어 하나로 오늘 상태 확정 또는 괜찮다는 말로 위험 해제 |
| 다음에는 6개만 해야겠다 | 미래 계획/희망으로 구분 | 오늘 실제 수행 6회로 저장 |
| 친구가 무릎이 아프대 | 타인의 이야기로 구분 필요 | 본인 통증으로 자동 저장 |

위 예문은 현재 추출기가 모두 처리한다는 의미가 아니다. 다음 구현의 반례/수용 기준이다.

## 새로 명세할 부분

1. 신호 종류를 안전, 수행 변화, 변경 사유, 선호/요청으로 분리한다. 같은 키워드가 처방을 직접 결정하지 않는다.
2. 시점, 대상 인물, 부정/가정/인용, 적용 운동/구간, 단위, 계획값/실제값 구분을 후보에 포함한다.
3. 확인 전 후보는 일시 상태이며 분석/계획 입력이 아니다. 확인 후에도 EXPLICIT 직접 입력과 구별되는 파생 출처, 추출/확인 버전, 원본 일지 revision을 남긴다.
4. 거절/수정/메모 목적 변경/일지 삭제 시 파생 후보와 소비 근거의 무효화 정책을 정한다. 원문이나 원문 hash를 일반 분석 지문에 쓰지 않는다.
5. 숫자 추출 불가/충돌 시 한 질문을 제공한다. 모든 사용자에게 상세 문장 작성을 강요하지 않는다.
6. 저장·검토·교정 적용은 각각 별도 성공 상태다. 원문을 공개하지 않으면서 어떤 확인된 사실을 사용했는지는 보여준다.
7. 현재 D9 경로의 승인 이력을 찾고 문서 상태를 일치시킨 후 일반 신호의 정확한 어휘와 소비 권한만 추가한다. 모든 false 값을 일괄 해제하지 않는다.

## 장단점과 우선순위

- 장점: 기존 자유 메모를 적은 입력으로 구체적 사실에 연결하며, 무조건 긴 설문을 만들지 않는다. 외부 LLM 없이 닫힌 표현/숫자 파서부터 시작할 수 있다.
- 단점: 표현 다양성·부정·시점·여러 운동 때문에 오인식이 생긴다. 키워드 사전만 늘리는 방식은 유지보수 비용과 과도한 경고를 키운다.
- 대응: 수행 횟수/회복/운동 변경 등 좁은 구조부터, 문장 원문은 로컬 처리, 한 번의 수정 가능한 확인. 실패 시 직접 선택으로 계속 진행.
- 우선순위: 승인/문서 불일치 감사 → 신호/구간 매핑 계약 → 추출·확인 UI → 구조화 비교 확장 → 교정 정책 및 원자적 적용. 기존 전체 재설계 목표를 삭제하거나 축소하지 않는다.

## 후속 정밀 검토 보완

후속 검토에서 `NOTE_SAFETY_SIGNAL_AND_REVIEW_STATE_CONTRACT.md`, `FORMATION_PRIVACY_GOVERNANCE_DECISION.md`, `DATA_PROVENANCE_RUNTIME_ADOPTION_DECISION.md`, North Star §3.1/§4를 추가 대조했다. 안전 결과의 제한적 전달 초안도 이미 존재한다. 메모 안전 소비는 North Star에 구현 범위가 기록돼 있으므로, 오래된 DAILY_LOG의 false만으로 전부 미승인이라고 결론 내리지 않는다. 동시에 새 일반 파생값 저장·계획 소비까지 승인됐다고 확대하지 않는다.

이전의 선형 메모 추출 순서는 모든 기록의 필수 흐름이 아니다. **직접 구조화 입력으로 비교·교정을 먼저 완결하고, 글 정리는 사용자가 원하는 경우에만 연결하는 보조 기능**으로 정교화한다. 현 로컬 비교기의 파생 관계 표현 결함과 구간 확인 없는 RPE 준수 해석도 선행 수리 목록에 추가했다. 상세 근거·화면·수명주기·개발 순서는 [후속 상세 계획](../plans/JOURNAL_FACT_CONFIRMATION_AND_REPLAN_DETAILED_PLAN_2026-09-29.md)을 따른다. 이 추가 검토는 코드 수리나 새 실행 시험 결과가 아니다.
