## 1. 먼저 읽을 결론

현재 디자인을 버리고 새 시안을 그대로 이식할 필요는 없다. **차분한 앱 바탕, 종이 일지, 정확한 훈련 수치, 소장하는 꾸미기 재료**가 이미 구현돼 있다. 문제는 이 요소들이 화면마다 다른 크기·밀도·겹침 규칙으로 나타나는 데 있다.

권장 방향은 다음과 같다.

1. **기능과 문구는 유지한다.** 로그인·기록·계획 선택·설명·꾸미기의 순서와 저장 동작을 시안에 맞춰 다시 만들지 않는다.
2. **공통 시각 규칙의 빈틈부터 정리한다.** 미정의 색상 변수, 범례의 과도한 세로 공간, 편집기 위 저장 안내 겹침, 지나치게 작은 상태 글자를 먼저 다룬다.
3. **제안의 좋은 표현을 기존 컴포넌트에 적용한다.** 큰 수행 수치, 같은 순서의 요약 지표, 정돈된 운동·회복 블록, 종이 위 재료 전시를 재사용한다.
4. **앱과 다이어리의 개성을 구분한다.** 앱 전체를 크림색 종이·스티커로 채우지 않는다. 기록을 읽고 꾸미는 안쪽은 풍부하게, 탐색·설정·분석 바깥은 차분하게 유지한다.
5. **한 장의 예쁜 시안으로 완료 판정하지 않는다.** 짧은 내용·긴 내용·빈 데이터·작은 화면·편집 중·저장 중을 같은 컴포넌트로 검수한다.

### 2.1 새 PR의 식별 한계

검토 시 GitHub의 열린 PR에서 새 디자인 PR은 확인하지 못했다. 확인된 열린 PR은 상세 계획 선택 작업의 Draft #320이었다. 최신 확인 PR은 #333, main은 위 해시였다. 따라서 특정 신규 PR을 검수·승인했다고 말하지 않는다.

이번 제안 대조에는 main에 실제 존재하는 `design_handoff_plan_beta_extension/`을 사용했다. 이 묶음은 `964c2c6`에서 2026-09-10 추가된 자료다. 사용자가 언급한 새 PR과 동일한지는 **확인 대기**다. 다른 PR이면 해당 diff를 추가 검토해야 한다. 아래의 현재 앱 실측 결과는 그 여부와 별개로 유효하다.

## 3. 발견 사항: 디자인 적용 전에 먼저 정리할 것

심각도는 이번 디자인 적용의 우선순위다. 과학적 처방이나 운영 보안의 전체 위험 등급이 아니다.

### D-01 · P1 · 저장 안내가 꾸미기 서랍을 가린다

- 재현: 빠른 기록 → 상세 기록에서 거리 추가 → 저장 → 곧바로 꾸미기 → 재료 서랍.
- 375px에서 서랍은 y=314.5~609.0, 저장 안내는 y=476.5~623.0이었다. 약 132.5px가 겹쳐 첫 재료 선택을 방해했다.
- 안내는 약 4초 뒤 사라졌다. 영구적으로 편집할 수 없는 결함이라고 과장하지 않는다. 다만 사용자가 바로 다음 행동을 하는 시점에 발생한다.
- 근거: `app/src/AppShell.tsx:49`, `app/src/components/AppShellFrame.tsx:44`, `app/src/styles/app.css:2300`, `app/src/styles/journal-decoration.css:349`.
- 개선: 저장 성공 의미와 문구는 그대로 두고, 편집 모달에서는 모달 안의 상태 영역으로 인계하거나 재료를 가리지 않는 위치에 표시한다. 안전 확인이 필요한 지속 안내를 일반 성공 알림처럼 자동으로 없애지 않는다.
- 검수: 저장 직후 0~4초에 서랍 열기·재료 선택을 실행한다. 타이머가 끝날 때까지 기다린 화면만 검사하면 재발을 못 잡는다.

### D-03 · P2 · 색상 토큰 참조가 연결되지 않은 화면이 있다

- `--accent`, `--line-dark`, `--accent-ink`가 앱 CSS에서 사용되지만 현재 앱/루트 토큰에서 정의를 찾지 못했다.
- 실제 오라클에서 `--accent`, `--line-dark` 값은 빈 문자열이었다. 상태 테두리의 계산 결과도 `0px none`이었다. 단순 검색 의심에서 끝내지 않고 렌더 결과를 대조했다.
- 근거: `app/src/styles/app.css:112`, `app/src/styles/app.css:127`, `app/src/styles/training-lexicon.css:31`, `app/src/styles/plan-beta.css:1665`.
- 개선: 무조건 새 색을 만들지 않는다. 사용 의도별로 현재 `--brand`, `--line-2`, `--brand-ink` 등에 매핑한다. 의미가 다른 변수들을 일괄 치환하지 않는다.
- 검수: 적용 화면의 computed style과 실제 캡처를 함께 검사한다. CSS 변수를 선언했는지만 보는 검사는 부족하다.

### D-04 · P2 · 현재 작은 글자 문제는 폰트 미로딩보다 타입 위계 문제다

- 현재 앱 40개 캡처에서 Pretendard 로딩은 확인됐다. 이번 환경에서 다른 폰트가 로딩됐다고 볼 근거는 없다.
- 반면 오라클 상태 8.5px, 일부 영문 보조 코드 8.5px, 여러 메타 라벨 9~11px가 존재한다. 제목·본문보다 설명과 상태가 지나치게 작아 별개 서체처럼 느껴질 수 있다.
- 근거: `app/src/styles/app.css:130`, `app/src/styles/plan-beta.css:482`, `app/src/styles/compact-tabs.css:26`.
- 개선: 전체 화면을 일괄 확대하지 않는다. 사용자에게 읽혀야 하는 상태·보조설명은 캡션 토큰으로, 수행 정보는 본문 토큰 이상으로 정리한다. 숫자는 같은 Pretendard의 tabular-nums를 유지한다. 반복되는 보조 코드와 하단 탐색 라벨은 별도 밀도로 실측한다.
- 검수: 필수 정보를 색·아이콘·8.5px 글자에만 의존하지 않게 한다. 폰트 파일 동일성 검사는 유지하되 실제 기기별 렌더 차이는 별도로 확인한다.

### D-05 · P2 · 홈의 여백은 많지만 실제 콘텐츠의 첫인상은 약하다

- 새 사용자 홈에서 CTA와 예시 진입 사이가 크게 비어 있다. 1440px 높이 900 화면에서도 폭 520px 앱 안에 큰 공백이 생긴다.
- 근거: `app/src/styles/app.css:1604`의 viewport 최소 높이 + 예시 영역 `margin-block-start:auto`; `TrainingHome.tsx:129`.
- 개선: 현재 환영 문구·CTA·예시로 들어가는 동작은 유지한다. 예시 진입 요소를 실제 일지 미니어처가 보이는 표현으로 확장하거나, 내용 기반 간격으로 공백을 제한한다. 신규 시작 질문·강제 온보딩을 추가하지 않는다.
- 장점: 이미 있는 종이 일지와 재료가 첫 화면에서 제품의 실물을 보여준다.
- 단점: 미니어처의 글씨를 읽는 또 하나의 화면으로 만들면 복잡해진다. 비상호작용 미리보기 한 개와 기존 진입 버튼으로 제한한다.

### D-06 · P2 · 편집기의 바깥 면적과 실제 종이 작업 면적은 다르다

- 모바일 전체 화면 편집과 재료 선택 후 서랍 닫힘은 이미 동작한다. 이를 새 편집기로 교체할 이유가 없다.
- 320px에서 서랍의 제목·분류·하단 도구가 공간을 나누고, 재료가 한 줄 정도 먼저 보인다. 날짜와 기존 기록 수정 버튼도 종이 위쪽을 사용한다.
- 데스크톱에서는 종이가 넓어지면서 데이터 칸도 길게 늘어난다. 단순히 풀화면인 것이 좋은 종이 구도와 같지는 않다.
- 개선: 모바일은 현재 전체 화면을 유지하되 서랍 헤더·필터 밀도를 정리한다. 데스크톱은 종이의 디자인 폭과 편집 작업공간의 폭을 구분한다. 화면 좌표와 저장된 배치 좌표의 변환을 검증하기 전 종이를 임의 축소하지 않는다.
- 스티커 첫 배치에서 라벨과 겹치는 예도 확인했다. 자유 배치를 없애지 말고, 기본 삽입 위치를 여백으로 제안하는 방식을 우선 검토한다. 기존 배치는 이동시키지 않고, 사용자가 본문 위에 배치한 선택을 자동으로 취소하지 않는다.
- 검수: 적용·이동·크기·회전·복제·삭제·되돌리기·새로고침 뒤 동일 좌표, 24개 상한, 계정별 저장을 그대로 지킨다. 이번 리뷰에서는 재료 적용과 서랍 닫힘을 실행했으며 제스처 전 종류를 다시 검증한 것은 아니다.

### D-07 · P2 · 디자인 기준 문서의 범위와 시점이 섞여 있다

## 6. 재사용 중심 디자인 시스템 개선안

### 6.1 우선순위와 파일 역할

1. 제품·안전·개인정보·저장 계약은 시안보다 우선한다.
2. 현재 동작하는 화면의 문구·라우팅·상태 전이는 보존 대상으로 기록한다.
3. `docs/UX_UI_VISUAL_STANDARD.md`를 현행 앱의 시각 기준 진입점으로 정리한다. 과거 배치 규칙은 호환성 설명과 분리한다.
4. 값의 원본은 루트 토큰, 재사용 표현은 현재 컴포넌트/CSS, 시안은 아이디어 원본으로 구분한다.
5. `design_handoff_plan_beta_extension/shared/tokens.css`를 앱에서 import하지 않는다.

문서에는 `CURRENT_APP`, `DASHBOARD_ONLY`, `LEGACY_REFERENCE`, `PROPOSAL_ONLY`처럼 적용 범위를 명시하는 방안을 권장한다. 기존 문서를 삭제하거나 전체를 새 문장으로 줄이지 않는다.

| compact 탭 | 보이는 높이32/터치44의 현행 구분 유지. 필수 본문까지 compact 처리하지 않음 |
| 간격 | 현행 4px 기반 토큰 우선. 한 화면의 실제 기능 그룹 사이에 일관된 간격 사용 |
| 표면 | 앱 바깥은 중립색, 일지/재료 안쪽은 paper. 섹션을 모두 떠 있는 카드로 만들지 않음 |
| 강조 | 제목·여백·1px 구분선·선택 상태로 표현. 왼쪽 색띠/그림자 재도입 안 함 |
| 반응형 | 전체 앱 폭을 한 번에 바꾸지 않음. 편집 작업공간과 읽기 본문 폭만 역할별 검토 |

### 6.3 컴포넌트 도입 순서

새 UI 라이브러리나 병렬 디자인 프레임워크를 도입하지 않는다. React, 현재 CSS, Lucide, 기존 제스처 라이브러리를 유지한다.

| 표현 단위 | 우선 확장 대상 | 새 추상화가 필요한 조건 |
|---|---|---|
| 날짜/슬롯/핵심 값 행 | 현재 훈련·일지 수치 행 | 둘 이상의 실제 화면에서 값/단위/결측 표현이 같을 때만 MetricRow 추출 |
| 훈련 수행 카드 | DetailedPrescriptionView | 거리·시간·복합형을 기존 타입으로 유지하면서 공통 조판만 추출 |
| 과정 블록 | PrescriptionStructure | 숫자·회복·설명 원본을 다시 만들지 않고 구조 표현만 재사용 |
| 훈련 구분표 | PlanSchedulePreview의 범례 | AccountPlanStorage의 덮어쓰기를 줄이고 한 곳에서 반응형 관리 |
| 작은 도움말 | TermHelp·기존 flow-code-help | 호출 경로·포커스 복원을 깨지 않는 공통 규칙만 정리 |
| 상태 안내 | SavedToast·계정 상태 패널 | 전역 성공 알림과 지속 확인 알림, 모달 내부 안내의 배치 우선순위 분리 |
| 재료 타일 | JournalDecorationToolbar의 MaterialTile | 구매/소유/라이선스 로직은 그대로, 미리보기 광학 크기와 하단 라벨만 정리 |
| 본문 설명 | SessionExplanation·TrainingLexicon | 제목·본문·근거 행의 간격 토큰 재사용. 서로 다른 내용을 같은 문장으로 합치지 않음 |

모든 항목을 범용 `Card` 하나로 합치지 않는다. 계획 수행, 기록 읽기, 재료 선택은 시각적 역할이 다르다.

### 6.4 모션

- 이미 있는 진입·단계 이동·서랍·재료 부착 모션을 사용한다. 새 애니메이션 라이브러리는 불필요하다.
- 선택 피드백은 짧게, 화면 이동은 현재 방향을 유지한다. 재방문 때마다 축하 애니메이션을 반복하지 않는다.
- 숫자 변화에 과도한 카운트업을 사용하지 않는다. 훈련 시간·페이스·저장 상태는 즉시 읽혀야 한다.
- 재료는 선택·부착에 반응하되 계속 흔들리며 본문을 방해하지 않는다.
- reduced-motion에서는 의미와 완료 상태가 모션 없이 전달돼야 한다. 숨긴 상태에서 포커스만 이동시키지 않는다.
- 예시 다음 장, 계획 질문, 설명 닫기 뒤의 기존 스크롤·선택 복원을 유지한다.

## 7. 에셋 16개 선별안

[전체 그림 비교](evidence/design-system-reuse-20260912/proposal-assets.png)

신규 모티프 수보다 기존 재료와 함께 보였을 때의 완성도가 중요하다. 현재 앱에도 해·물병·러닝화·스톱워치·체크·새벽 도장이 있다. 같은 주제를 새 파일로 계속 늘리면 재료를 고르기 어려워진다.

| 에셋 | 시각 평가 | 권장 |
|---|---|---|
| stamp-done / stamp-early | 간결한 단색 도장, 현재 종이와 잘 맞음 | 기존 동일 모티프와 비교 후 대체 후보 또는 명시적 변형 팩. 즉시 기존 ID 덮어쓰기 금지 |
| stamp-focus | 선과 도장 질감이 차분함 | 작은 크기에서 중앙 디테일을 읽을 수 있는지 검토 후 후보 |
| stamp-consistency / stamp-tempo | 도장 외형은 활용 가능, 작은 글자 비중 큼 | 외형 아이디어만 우선. 문구·의미는 현재 용어와 재료명 기준 |
| stamp-vo2 | 형태는 단순하지만 V2·VO2 MAX 글씨가 실제 분류와 다름 | 그래픽 참고만. 시안의 용어를 앱에 복사하지 않음 |
| tape-kraft / tape-mint / tape-blush | 여백을 꾸미기 좋고 역할이 명확함 | 현행 종이·잉크와 색 대조 후 별도 테이프 후보. 넓은 불투명 면이 본문을 가리지 않게 기본 위치 검토 |
| sticker-shoe-detail / stopwatch-detail | 러닝 주제가 명료함 | 현행 그림과 선 굵기·광학 크기 비교. 중복이면 추가하지 않음 |
| sticker-heart-detail | 숫자178 BPM이 그림에 박혀 있음 | 측정값처럼 오인되는 숫자를 제거한 별도 후보만 검토 |
| sticker-sun / moon-detail / runner / water-bottle | 채도·입체 하이라이트가 기본 문구 재료보다 강함 | 기본 재료를 대체하지 않음. 귀여운 선택형 컬렉션에서 검토 가능 |

귀여운 컬렉션까지 모두 무채색으로 통일하지 않는다. **앱 인터페이스의 일관성과 사용자가 고르는 재료의 다양성은 다른 문제**다. 기본 재료·귀여운 컬렉션을 현재 분류 안에서 유지한다.

자산 적용 전에는 원본·제작/라이선스 기록, 파일 해시, 동일 모티프 중복, 실제 24/48/96px 및 확대 렌더, 외부 참조·스크립트 여부를 확인한다. SVG라는 이유만으로 안전·권리가 확보됐다고 가정하지 않는다. 가격·소유·획득 규칙은 기존 레지스트리를 통하며 디자인 시안의 가격으로 바꾸지 않는다.

기존 ID와 배치 데이터는 보존한다. 기존 그림을 일괄 교체하면 사용자가 예전에 꾸민 페이지까지 달라지므로, 변형은 새 ID/버전 또는 사전 고지된 명시적 마이그레이션으로 처리한다.

## 8. 사용자 관점별 장단점

실제 사용자 인터뷰 결과가 아니라 이번 화면 대조를 위한 검토 관점이다.

| 관점 | 개선의 이점 | 반대 위험 | 방지 기준 |
|---|---|---|---|
| 처음 온 중학생 | 그림이 있는 실제 일지 예시가 제품을 빠르게 설명 | 장식이 입력 CTA를 밀어낼 수 있음 | 기존 CTA와 짧은 예시가 함께 보여야 함 |
| 버튼 몇 번만 누르는 사용자 | 단순 기록과 완료 영수증은 그대로 빠름 | 주간 회고·꾸미기를 강제하면 번거로움 | 새 필수 단계·작성 요구 없음 |
| 기록을 꾸미는 사용자 | 재료 그림과 종이가 잘 보이고 선택이 편해짐 | 통일을 이유로 취향이 사라짐 | 기본 스타일과 선택형 컬렉션 분리 |
| 전문 선수 | 단위·회복·반복 수가 명확하게 읽힘 | 큰 숫자로 총시간/본운동시간을 혼동 가능 | 의미 다른 수치에 명확한 현행 라벨 유지 |
| 작은 화면·시력 부담 사용자 | 캡션·터치 영역·반응형 범례 개선 | 모든 것을 한 화면에 넣으려 글자를 줄일 수 있음 | 스크롤 허용, 내용 축소·강제 한 줄 금지 |
| 코치·기록 비교 사용자 | 값의 정렬과 읽기 폭 개선 | 시안의 관리 기능이 이미 존재한다고 오인 | 이번 작업은 현행 화면 표현만 개선 |
| 다른 기기로 로그인하는 사용자 | 저장 상태가 화면 어디서나 일관됨 | 예쁜 성공 스탬프가 온라인 저장 완료처럼 보일 수 있음 | 실제 저장 응답과 현재 상태 모델에만 연결 |

## 9. 실행 순서와 완료 관문

후속 이력: 오너가 [상세 계획](../plans/TRAINORACLE_DESIGN_SYSTEM_IMPROVEMENT_PLAN_2026-09-12.md)의 실행을 승인했다. 아래 미착수 표시는 리뷰 작성 당시의 상태로 보존하며, 이후 현황은 [실행 기록](../implementation/TRAINORACLE_DESIGN_SYSTEM_IMPROVEMENT_EXECUTION_2026-09-12.md)을 따른다. 이 보고서의 캡처는 변경 전 증거다.

아래 작업은 **아직 시작하지 않았다**. 이번 결과는 검토와 구현 준비이며 새 기능 발주나 배포 완료가 아니다.

### 묶음 A · 현행 기준·스타일 충돌 정리

- `SKILL.md`, `DESIGN.md`, 시각 표준에 범위/시점/현행 연결 표시. 기존 장과 결정 이력 보존.
- 미정의 토큰을 의도별로 매핑. 원본 CSS 전체 교체 금지.
- 범례의 중복 반응형 규칙, 모달/토스트 배치 소유권, 읽혀야 하는 상태 글자 정리.
- 검수: 현재 문구·라우팅·저장·처방 스냅샷 불변, 결함 재현을 먼저 실패로 고정, 작은 화면 전후 캡처.

### 묶음 B · 계획 수행·설명 컴포넌트

- 시안의 pace card 조판을 기존 renderer에서 구현. 새 SessionPrep 라우트나 countdown은 넣지 않음.
- 숫자와 단위, 본운동과 총시간, 운동과 회복을 같은 순서로 정렬.
- 기본/전문 보기는 같은 수치와 입력을 유지하고, 정보 깊이만 현재 규칙대로 제공.
- 검수: 거리/시간/복합/RPE/기존 계획/설명 로딩 실패, 오전·오후, 긴 훈련명, 비가분 기록. 숫자를 예쁘게 만들기 위해 반올림 계약을 바꾸지 않음.

### 묶음 C · 홈·일지·분석의 시각 일관성

- 현재 진입점과 문구를 유지하면서 예시 미니어처·지표 행·날짜·상태의 표현을 정리.
- 빠른 기록의 단순함을 유지하고 상세 기록은 정보를 삭제하지 않은 채 그룹 간 간격을 정리.
- 분석은 실제 수치와 미기록·제외·근거를 유지. 새로운 평가나 강도 증감을 만들지 않음.
- 검수: 새 사용자/기록 1개/많은 기록/계획 보유/기록 완료/통증 안내. 서로 다른 상태에 같은 완료 그림을 쓰지 않음.

### 묶음 D · 꾸미기·재료

- 기존 전체화면 편집기의 서랍 밀도·그림 광학 크기·상태 메시지만 먼저 개선.
- 승인된 에셋 후보를 작은 묶음으로 추가. 그림 수를 목표로 삼지 않음.
- 저장된 배치와 구매 내역 불변, retire-never-delete 유지. 기존 계정 격리 검사를 그대로 실행.
- 검수: 320/375/태블릿/데스크톱, drawer open/closed, 최대 배치, 긴 텍스트 스티커, drag/pinch/rotation/undo/redo, 데이터 새로고침, 온라인 저장 실패.

### 묶음 E · 인증·관리 상태와 최종 검수

- 인증 후 패널의 fixture를 만들어 시각 검수. 실제 이메일·문자 발송 없이 기본 UI부터 확인.
- 로그인/재전송/실패/오프라인/계정 전환/충돌/복구/삭제 확인의 버튼 위계·포커스·메시지 유지.
- 표본이 아닌 실제 수정 페이지 전체에서 320/375/768/1440, 200% 확대, 키보드, reduced-motion, 폰트 로딩 실패를 확인.
- Chrome 결과를 Safari 실기기 결과라고 보고하지 않는다. 실제 모바일 확인을 따로 남긴다.
- PR별 디자인 검수 → 기존 계약/앱 CI → 병합 → 배포 → 공개 화면 확인. 기능 변경을 디자인 PR에 숨겨 넣지 않는다.

## 10. 범위 밖 관찰과 보류

- `경기기록` 탭을 누르면 실제로 `새 일지` 유형 선택이 열린다. 이름과 목적의 불일치가 의심되지만, 이번 사용자 지시가 **현행 단어·플로우 우선**이므로 이번 시각 개선의 변경 목록에 넣지 않는다. 별도 제품 검토 항목으로만 보존한다.
- 새 시안의 Session Prep/Weekly Wrap/Coach Handoff는 현재 기능 확장 제안이다. 해당 이름의 신규 화면 3개를 이번 디자인 작업에서 만들지 않는다.
- 시안의 `onSessionComplete`, 원시 localStorage 회고, 코치 강도 조정·신호 계산은 현행 시스템에 연결된 것으로 간주하지 않는다. 디자인 차용에서 제외했으므로 이를 고치는 백엔드 작업도 이번 범위 밖이다.
- 신규 디자인 PR 번호는 아직 특정하지 못했다. 다른 PR이면 신규 diff와 에셋을 추가 대조하고 이 문서의 입력 목록·판정을 갱신한다.

## 11. 최종 판정

**디자인 제안의 선택적 활용은 권장. 화면·CSS·기능의 통째 이식은 비권장.**

현행 문구와 이용 흐름을 보존하면서도 충분히 크게 좋아질 수 있다. 가장 먼저 필요한 것은 새 색과 새 카드가 아니라, 기존 디자인 시스템이 화면별로 일관되게 작동하게 만드는 것이다. 이후 핵심 수치의 조판, 종이와 재료의 품질, 읽기·편집 공간의 균형을 다듬는 순서가 비용 대비 효과가 높다.

이번 문서로 구현 완료·디자인 승인·운영 배포·스펙 정본 승격을 주장하지 않는다.
