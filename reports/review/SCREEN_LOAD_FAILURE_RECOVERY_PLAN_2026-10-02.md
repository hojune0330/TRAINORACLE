# 화면 로딩 오류 진단과 재발 방지 계획

## 현재 결론

2026-10-02 사용자가 제공한 오류 화면의 직접 원인은 로컬 미리보기 서버의 종료다.
저장된 훈련계획의 손상은 이번 오류에서 확인되지 않았다. 이 문서는 진단과 개선
계획이며 제품 코드 수정·공개 배포 완료 보고가 아니다.

대상 소스는 `cfffa394f817ac1abfa0fad9c905b1872b7a83d7`, 대상 주소는
`http://127.0.0.1:4434/?app=1`이다. 사용자의 저장소 원문이나 계정·건강 데이터를
추출하지 않았다. 기록 삭제, 계획 재생성, 저장소 초기화, 서비스 워커 삭제도 하지 않았다.

## 1. 직접 확인한 증거

| 관찰 | 결과 |

| 브라우저 로그 | 안내 JS, `file-analysis-BRke8oGo.css`, `sw.js` 요청 실패가 함께 기록됨 |
| 로컬 서버 상태 | 4434 수신 프로세스 없음. 루트와 해당 JS 요청 모두 연결 거부 |

| 기존 오류 화면에서 다시 열기 | 홈은 열림. 실패했던 일지 예시로 다시 이동하면 같은 오류 재발 |

미리보기는 기존 빌드 디렉터리를 그대로 읽는 별도 숨김 프로세스로 다시 열었다.
작업 세션의 실행 핸들에만 의존하지 않지만, 컴퓨터 재시작·수동 종료에도 영구 유지된다는
뜻은 아니다. 현재의 정상 표시를 공개 사이트 배포 상태와 혼동하지 않는다.

## 2. 확인된 결함과 검토할 위험

### P1 파일 로딩 실패를 단순 재렌더로 복구하려 한다

`app/src/components/ErrorBoundary.tsx:84`의 재시도는 경계의 실패 상태만 해제한다.
`DeferredMobileScreens.ts`의 모듈 범위 `React.lazy` 항목은 실패한 로딩 결과를
유지할 수 있다. 실제로 서버 복구 후 같은 안내 화면에서 재발했고 새로고침 후 해소됐다.
버튼이 존재한다는 테스트는 있지만, 실패→연결 복구→같은 화면 성공 시험은 없다.

### P1 보조 화면 실패가 앱 전체를 대체한다

`main.tsx:63`의 전역 경계가 최종 안전망이고, `AppShell.tsx:786`의 화면 영역에는
Suspense만 있다. 안내 화면 파일 하나가 없어도 홈·일지·계획 탐색 전체가 오류 화면으로
바뀐다. 재시도 시 AppShell이 새로 만들어져 직전 화면 대신 홈으로 돌아오는 것도 확인했다.

### P2 오류 안내가 원인과 보관 범위를 구분하지 않는다

서버 연결 실패에도 일지 백업을 최우선으로 제시해 사용자가 기록 손상을 의심하게 한다.
비상 백업은 `trainoracle.journal.v1`의 소유권 확인 가능한 일지만 다룬다.
계획·꾸미기·서버에만 있는 자료까지 백업하는 기능이 아니다.
백업 원본을 읽지 못할 때도 `[]`로 처리되므로, 0건과 확인 실패를 구분하지 않은
"일지는 그대로 있어요" 문장을 데이터 무결성 보증으로 사용해서는 안 된다.

### P2 업데이트·오프라인 복구 시험이 부족하다

`pwa-update.ts`는 포커스 복귀 시 update의 거절을 처리하지 않아 실패 로그를 남긴다.
즉시 새로고침 정책은 "실사용자가 없다"는 과거 주석을 전제로 한다. 현 시점의 작성 중
입력 보호와 함께 재검토해야 한다. 이번 장애에서 실제 입력 손실이 입증된 것은 아니다.
기존 PWA 테스트는 코드 문자열을 검사하며, 실제 오프라인·다중 버전 동작의 증거가 아니다.

## 3. 훈련계획 경로에 대한 판단

`plan-beta-store.ts:181` 이후의 읽기 경로는 JSON·스키마 오류를 `invalid`, 읽기 실패를
`storage_error`, 실제 부재를 `missing`으로 나눈다. 버전 4·5·6의 조정 계획도 별도 검증한다.
`PlanBeta.tsx:334`는 invalid/storage_error를 새 계획 화면으로 넘기지 않고 원본을 유지한다.

이번에 실행한 테스트:
- `does not treat unreadable saved plans as an empty intake or delete them`
- `rechecks changed storage instead of retaining a corrupted adjusted view`

두 시험은 통과했지만 정상·손상 계획의 모든 버전, 서버 계정 복구, 오래 열린 브라우저의
모든 조합을 검증한 것은 아니다. 사용자의 원래 계획이 정상인지도 검사하지 않았다.
로컬 미리보기의 호스트·포트와 공개 사이트는 보관 영역이 다르므로, 다른 주소에서
계획이 안 보이는 현상을 데이터 삭제나 손상으로 단정하지 않는다.

## 4. 권장 구현 순서

### 1단계 미리보기 수명과 준비 상태 관리

- 작업 세션과 분리된 loopback 전용 서버, PID·빌드 경로·포트 기록을 표준 실행 절차로 만든다.
- 포트 충돌 시 기존 서버를 임의 종료하지 않는다. 다른 작업자의 디렉터리도 사용하지 않는다.
- 링크 제공 전에 HTML뿐 아니라 현재 HTML이 참조하는 JS·CSS와 응답 타입을 확인한다.
- 실행 중 빌드 폴더를 갈아엎지 않는다. 새 빌드는 별도 디렉터리에서 확인 후 전환한다.
- 로컬 개발은 SW 등록을 기본 제외하는 방안을 검토하고, PWA 시험용 모드는 별도로 유지한다.
  이미 등록된 SW를 정리할 때는 해당 로컬 scope만 대상으로 하며 사용자 저장소는 지우지 않는다.

### 2단계 실패 종류별 복구

- 화면 파일 로딩 실패, 연결 실패, 저장 데이터 오류, 일반 렌더 오류를 구분한다.
  모든 TypeError를 네트워크 오류로 분류하지 않는다.
- 파일 로딩 실패 안내는 "화면을 불러오지 못했어요. 연결을 확인하고 다시 열어 주세요."
  한 문장과 주 행동 하나로 구성한다. 기술 정보·백업은 필요한 경우에만 펼친다.
- 서버가 없는 로컬 미리보기는 인터넷 문제로만 표현하지 않는다.
- 연결 복구 확인 후 입력 초안 보호가 확인된 경우에 한해 새 문서를 다시 연다.
  실패했던 import만 반복하거나, 무한 자동 새로고침하거나, 임의 query로 모듈을 우회하지 않는다.
- 자동 복구는 최대 한 번으로 제한하고, 실패하면 사용자에게 명확한 다음 행동을 제시한다.
  저장소 접근 자체가 실패하면 초안이 안전하다고 가정해 자동 새로고침하지 않는다.

### 3단계 화면 단위 격리와 복귀

- 탭·보조 화면·계획 상세 주변에 재사용 가능한 지역 오류 경계를 추가한다.
  최상위 경계는 최후 수단으로 유지한다.
- 한 화면이 실패해도 하단 탭·홈 이동을 사용할 수 있게 한다.
- 복귀 정보에는 화면 종류·선택 날짜 등 최소 경로만 담고, 메모·기록 원문·개인 페이스를
  URL이나 오류 로그에 넣지 않는다. 계정 변경 시 이전 계정의 복귀 상태는 폐기한다.
- 기존 초안 보호 경로를 사용한다. 새로고침을 위해 별도 평문 메모 복사본을 만들지 않는다.

### 4단계 계획 보호와 백업 안내 정합성

- 현재 invalid/storage_error 원본 보존을 유지한다. 오류를 빈 계획으로 바꾸지 않는다.
- 지원하지 않는 버전·검증 실패·저장소 접근 실패·계정 로딩 지연을 사용자 행동 기준으로
  나눈다. 검증 실패 상태에서 숫자를 추정하거나 이전 훈련을 자동 교체하지 않는다.
- 한 계획에 문제가 있어도 검증된 다른 계획과 일지는 열 수 있도록 격리한다.
- 비상 백업은 포함 자료·제외 자료·읽기 실패를 명확히 표시한다.
  계획 파일 내보내기는 기존 소유권·암호화·동의 경로를 재사용한다.
- 자동 삭제·초기화·손상 원문 서버 업로드는 하지 않는다.

### 5단계 업데이트와 공개 전 검사

- 자동 업데이트라는 기존 제품 방향은 유지하되, 작성 중 입력 보호가 확인되지 않은
  강제 새로고침은 피하도록 전환 시점과 계약을 먼저 정리한다. 과거 즉시 교체 조항의 변경을 명시한다.
- 현재 버전과 직전 버전의 정적 자산 공존, 실패 응답 캐싱 방지, SW 오류 처리 및
  반복 새로고침 방지를 실제 브라우저에서 검사한다.
- 통과 후에만 병합·배포하고 공개 사이트의 동일 화면 전환을 확인한다.

## 완료 기준

"오류 화면이 있다"나 "다시 열기 버튼이 있다"가 완료 기준이 아니다.
원인을 구분하고, 원본 자료를 보존하며, 실패했던 화면을 다시 열고,
그동안 다른 기능도 사용할 수 있어야 한다.

## 6. 구현 진행 갱신

- 완료: 자산 오류 분류, 연결 확인 후 명시적 새로고침, 탭 단위 오류 격리, 보조 화면 복귀.
- 완료: 초안 보호 전후 재확인, 오류로 사라진 초안의 위험 신호 유지, 다른 화면으로 이동한 뒤 늦게 도착한 복구 응답 무효화.
- 완료: 실제 읽을 수 있는 로컬 일지만 비상 백업, 0건/읽기 실패/소유권 불명/다운로드 실패 구분.
- 완료: 저장된 계획 `invalid`/`storage_error` 안내 분리. 기존 원본 보존·계정 전환 검사는 유지.
- 완료: 업데이트 실패 처리, 입력 화면 중 자동 교체 보류, 로컬 PWA 기본 미등록, 실패 HTML 캐싱 방지와 이전 캐시 보존.
- 완료: 별도 빌드 폴더와 숨김 서버로 미리보기 교체. 실행 중인 빌드 폴더를 덮어쓰지 않음.
- 검증: 파일 요청 차단/복구와 오프라인 PWA를 포함한 16개 브라우저 시나리오 통과. 수정 전 빌드에서는 같은 재시도 검사가 실패함을 확인.
- 범위 제한: 임의의 과거 계획을 자동 수선하거나, 깨진 계획 원문을 서버로 보내지 않는다. 미지원 버전과 필드 손상은 현재 `invalid` 안내 안에 포함한다.
- 공개 배포: 이 문서 작성 시 미완료. 기존 main `cfffa394`의 CI는 app-quality/contract-tests 성공, app-browser 실패로 deploy-pages가 건너뛰어졌다. 이번 수정의 로컬 통과를 공개 배포 통과로 간주하지 않는다.
