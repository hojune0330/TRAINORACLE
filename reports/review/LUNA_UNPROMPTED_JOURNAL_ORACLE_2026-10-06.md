# LUNA 독립 첫 사용자 일지·오라클 검수

검수일: 2026-10-06  
대상: `TRAINORACLE-multi-event-pace-release-20261002`  
진입 주소: `http://127.0.0.1:4466/?app=1`

## 요약

가상 초보 사용자 8개 경우를 구성하고, 그중 **J1~J4 네 브라우저 여정**을 실제 실행했다. 실제 여정은 모두 부분 검수이며 일지 최종 저장이나 친구 자료 비교 완료를 뜻하지 않는다. J1은 기록 내용에 닿기 전에 건강 상태 질문에서 멈췄고, J2는 운동 유형을 미저장 폼에 추가한 뒤 저장하지 않았다. J3는 개인 경기 기록 비교와 러닝 취향 친구 비교의 진입을 각각 탐색했으나 동의·자료 입력은 하지 않았다. J4는 훈련법 글을 열고 목록으로 돌아왔다.

관찰한 세 가지 우선 수정안:

1. **짧은 메모 경로를 첫 화면에서 드러내기.** `오늘 기록 남기기`는 수행 여부·시간·RPE 다음에 운동 후 불편/통증 질문을 보여줬다. 숫자 없이 짧게 쓰고 싶은 사람에게 메모 전용 진입을 제공하거나, 건강 확인이 언제 필요한지와 생략 가능 여부를 같은 자리에서 명확히 안내한다. 안전 확인을 우회하라는 제안은 아니다.
2. **빠른 기록과 여러 훈련 기록의 진입 차이를 설명하기.** 같은 날 러닝과 웨이트는 하단 `기록하기`에서 `훈련 후`를 고른 다음 `운동 내용 추가·수정` 안의 `운동 추가`를 찾아야 보였다. 복수 운동과 “같은 시간은 함께 / 다른 시간대는 새 일지” 규칙을 더 앞에서 알려준다.
3. **내 기록 비교와 친구 비교를 이름부터 구분하기.** `경기 기록 비교`는 실제 화면에서 내 최근 기록과 앞선 기록 또는 예시를 다뤘다. 친구 기록과의 임시 비교는 러닝 프로필의 `친구와 취향 비교` 아래 별도 선택지다. 첫 카드는 `내 경기 기록 비교`처럼 좁혀 부르고 친구 비교는 별도로 안내한다. 직접 비교의 현재 화면 한정·명시 동의 경계는 유지한다.

RPE 화면의 1~10 숫자판은 시각적으로 먼저 나오고 비숫자 건너뛰기는 아래에 있다. 이미 `모르겠어요 · RPE는 비워 둘게요`가 명시돼 있었지만, 초보·숫자 회피 사용자에게는 비숫자 선택을 위에 두는 작은 개선도 권한다.

## 검수 경계

- 첫 브라우저 시도는 샌드박스에서 `ERR_NETWORK_ACCESS_DENIED`로 페이지에 도달하지 못했다. 이를 제품 결함으로 세지 않았다. 승인된 재시도는 지정 주소의 `127.0.0.1`만 허용했고 홈 화면을 불러왔다. 외부 HTTP 요청 차단 기록은 없었다.
- headless Chrome, Playwright, 한국어 로케일, 375×740(J1~J3) 및 320×740(J4)을 사용했다. 격리 컨텍스트마다 새 세션으로 시작했다. 서비스 워커·다운로드는 차단했다. 앱 개발 서버는 중단하지 않았다.
- 실제 브라우저가 보여준 문구·버튼과 Chromium 접근성 트리의 role/name을 근거로 삼았다. 접근성 전체 적합성 검사나 성능 검사는 하지 않았다.
- 사전 열람 문서는 `AGENTS.md`, `PRODUCT_NORTH_STAR.md`, `docs/UX_UI_VISUAL_STANDARD.md`뿐이다. 기존 UX 보고서, 구현 소스, e2e helper는 첫 시도 전이나 검수 중 열지 않았다. 애플리케이션 코드는 수정하지 않았다.
- J1~J3 중에는 저장소 코드 수정과 Vite HMR이 병행 중일 수 있다는 사용자 안내가 있었다. 의도한 클릭으로 인한 화면 전환 외에 갑작스러운 홈 복귀/리로드는 캡처에서 보이지 않았으나, 자동 HMR 이벤트 추적은 하지 않았다. J4는 사용자가 수정을 잠시 고정한 뒤 관찰했다. 따라서 J1~J3 세부 문구는 당시 서버 화면 증거로 한정한다.
- 실제 계정 로그인, 친구 초대, 친구 자료 입력, 건강 상태 선택, 일지 최종 저장은 하지 않았다. J2에서만 가상 테스트 목적의 `근력 운동` 유형을 격리된 미저장 폼에 반영했다. 계정·서버 기록을 만들지 않았다.

첫 실패 기록은 [attempt-01 JSON](evidence/unprompted-20261006/journal-oracle/attempt-01-initial.json), 로컬 허용 재시도는 [홈 스크린샷](evidence/unprompted-20261006/journal-oracle/attempt-02-escalated.png)과 [재시도 JSON](evidence/unprompted-20261006/journal-oracle/attempt-02-escalated.json)에 보존했다. 클릭 이유와 혼동, 화면별 선택지는 [통합 JSON 로그](evidence/unprompted-20261006/journal-oracle/JOURNEY_LOG.json)에 있다.

## 8개 가상 경우와 검증 구분

가상 인물은 실제 사용자 인터뷰·관측이 아니다. J1~J4는 실제 UI를 눌러본 부분 여정이며, 정적 가설은 실행하지 않았다.

| # | 가상 사용자와 목적 | 상태 | 근거/미확인 |
|---|---|---|---|
| 1 | 중1 초보, 숫자 없이 오늘 한 일을 짧게 남김 | **실제 J1 · 부분** | 숫자 생략과 건강 질문까지 확인. 메모/저장은 미확인. |
| 2 | 중3 선수, 같은 날 러닝과 웨이트를 기록 | **실제 J2 · 부분** | 한 운동을 미저장 반영하고 두 번째 편집기를 열었음. 두 종목 완성·저장 미확인. |
| 3 | 지난주 또는 지난달 일지를 다시 찾는 사용자 | **정적 가설** | 일지 탭·달력·월 이동·날짜 상세는 실행하지 않음. 진입·검색 성공 여부를 주장하지 않음. |
| 4 | 친구 경기 기록과 내 기록을 임시 비교 | **실제 J3 · 경로 불일치** | 경기 기록 비교는 내 과거 기록/예시를 보였고 친구 입력은 확인되지 않음. |
| 5 | 러닝 취향 결과를 친구와 일회성 비교 | **실제 J3 · 동의 전 중단** | 직접 입력 경로와 일시 보관·명시 동의를 확인했으나 체크와 자료 입력은 하지 않음. |
| 6 | 숫자·전문용어가 낯선 초보가 달리는 법을 학습 | **실제 J4 · 부분** | 훈련법 글을 열고 돌아옴. 주제 난도와 다른 초보 주제는 미확인. |
| 7 | 화면을 바꾼 뒤 뒤로가기로 입력 복귀 | **혼합** | 앱 안 `← 뒤로`/`이전 화면`은 실제 확인했고 J1 앞선 선택은 남았다. 브라우저 뒤로가기는 실행하지 않은 정적 가설. |
| 8 | 오전 러닝·오후 웨이트 뒤 월별 기록을 확인 | **정적 가설** | J2에서 서로 다른 시간대는 새 일지라는 문구만 관찰. 월별 일지 메뉴·여정은 실행하지 않음. |

## 실패·오선택·미확인

- **목적 미달:** `경기 기록 비교`라는 이름은 친구 기록 비교를 기대하게 할 수 있지만, 실제 화면은 내 과거 기록과 예시였다. 비교 방법을 완료하지 않았다.
- **경로 발견:** J2에서 홈 버튼을 고른 뒤 하단 `기록하기`로 옮긴 것은 오작동이나 오클릭이 아니라, 여러 종목을 남길 더 적합한 경로를 찾으려는 의도적 전환이다. 입력을 시작하지 않아 이탈 손실은 확인하지 않았다.
- **민감 입력 앞 중단:** J1의 건강 질문과 J3의 친구 자료 동의는 검수 경계에 따라 응답하지 않았다. 질문 필수성/저장 후 처리 또는 친구 데이터 처리 전체를 검증하지 않았다.
- **뒤로가기:** 앱 내부 뒤로가기는 확인. 브라우저 뒤로가기 동작, 폼 편집값 보존, 월·날짜·스크롤 포커스 복귀는 실행하지 않았다.
- **HMR:** 사용자 안내상 J1~J3와 동시 구현/HMR 가능성이 있었다. 비의도적 홈 복귀를 UX 결함으로 세지 않았다. 이를 자동으로 감시해 부재를 증명한 것은 아니다.
- **도구 지연:** 일반 샌드박스의 첫 로컬 요청 차단 후 허용된 loopback 재시도로 진행했다. 앱 서버를 새로 시작하거나 중단하지 않았다. 브라우저는 정리 시 닫았다.

## 우선 수정안

1. `오늘 기록 남기기`의 시작에 **`짧은 메모만 남기기`** 또는 동등한 짧은 경로를 분명히 보여준다. RPE를 묻는 경우 숫자보다 `건너뛰기`를 먼저 보이게 하고, 운동 후 몸 상태 확인의 요구 여부와 이유를 명확히 한다. 계획·안전 게이트의 의미를 바꾸지 않는다.
2. 홈에서 **빠른 기록 / 거리·시간을 포함한 훈련 일지 / 여러 운동 추가**의 목적 차이를 선택 전에 알려준다. 동일 시각 운동 묶기와 다른 시간대 별도 일지 규칙도 진입점에 짧게 드러낸다.
3. 오라클의 경기 기록 카드를 **내 과거 기록 비교**와 **친구 자료 임시 비교**로 구분해 이름과 설명을 맞춘다. 친구 비교는 확인된 화면 내 임시 처리·명시적 동의 안내를 계속 유지하고, 이번 검수처럼 실제 동의 전에는 입력이 열리지 않도록 한다.
