## 1. 총평

방향은 건강하다. 특히 **정직성 원칙의 일관성**(기본값 발명 금지, 미승인
공식 미표시, MIXED_UNALLOCATED, 0 치환 금지)과 **안전 권한의 독립**
(D9를 오라클·포인트·모드가 못 건드림)은 현 코드베이스의 철학(거짓 브리핑
금지, 비경제 포인트)과 정확히 이어진다. 보존 원칙(§0)과 준비 문서의
권한 분리(구현 미착수 명시)도 모범적이다.

가장 큰 위험은 기능이 아니라 **밀도**다. §3 네이버형 홈에 명시된 배치를
그대로 렌더링하면 375×667에서 홈이 9개 이상 섹션이 된다. 이는 현재
UX3의 "한 화면 한 주행동"(최종 폴리시 D1) 계약과 긴장 관계다.

## 3. 위험과 결정 필요 사항 (오너 결정 5건)

### R1 — 홈 밀도 (UX 최대 위험) · 결정 필요
§3의 홈 구성(3 CTA + 최근 일지 + 현재 계획 + 주간·월간 거리 + 에너지
시스템 + 오라클 + 추천 콘텐츠 + 포인트·꾸미기 + 팔로워 다이어리)은
≥9 섹션이다. 네이버 홈은 포털이고 TrainOracle은 도구다 — 같은 밀도를
쓰면 토스보다 지저분해진다.
**필요 결정**: 홈 폴드 규율 — "첫 폴드 = 상태 1줄 + 주행동 1개 + CTA 2개,
카드 최대 N개, 나머지는 탭·서브화면" 같은 상한 규칙을 §16에 추가할 것.
§21 "기본 사용은 완전한 제품 경험"은 *접근 가능*이지 *홈 동시 노출*이
아님을 명시하면 충돌이 해소된다.

### R2 — 탭 구조 · 결정 필요
현행 5탭(홈/일지/경기기록/계획/분석)에 오라클·콘텐츠·팔로워 다이어리의
진입 위치가 정의되지 않았다. 모바일 하단 탭은 5개가 한계다.
**필요 결정**: 오라클을 분석 탭 내부로 넣을지, 탭 교체를 할지.

### R3 — 궁합 점수의 성격 · 결정 필요
§13 궁합 점수(25/20/20/15/20)는 가중 공식이다. §7은 "승인된 공식이 없는
부하 점수 미표시"를 요구한다. 부하 점수는 아니므로 직접 충돌은 아니나,
같은 정직성 잣대를 적용하면 **"오너 승인 규칙 기반 안내이며 측정이
아니다"**라는 성격 규정과 화면 고지가 필요하다.

### R4 — 콘텐츠 완독 판정 · 결정 필요
§15 "처음 끝까지 확인하면 1P" vs "체류 시간에 보상하지 않는다" — 완독
판정은 사실상 스크롤·체류 측정이다. 판정 기준(예: 마지막 섹션 도달 +
해설 열람 행위)을 정의하지 않으면 구현 시 모순이 드러난다.

### R5 — 기존 포인트 원장과의 정합 · 감사 항목
현행 engagement v2는 방문 +1P·기록일 +4P다. §15의 콘텐츠 1P·일 10P
상한과의 합산 규칙, 원장 스키마 확장(v3?)이 플랜에 없다. 준비 문서
단계 1(스펙 정합성 감사)의 명시 항목으로 추가할 것.

## 4. UX·UI 지저분해질 수 있는 지점 (심각도순)

1. **홈 9섹션** (R1) — 최우선.
2. **오라클 명칭 7종** (§13: 오라클 해보기·내 오라클 보기·기록·훈련법·
   주기·다음·함께 달리기) — 사용자가 구분 불가. "오라클" 허브 1개 +
   내부 카드 구분으로 명칭 위계를 줄일 것을 권고.
3. **에너지 시스템 원장 시각화** (§7) — 7시스템 × 계획/완료/경험 ×
   4기간 = 84칸 매트릭스. 표를 그대로 내보내면 안 되고, "기간 선택 →
   시스템별 1행 요약 → 탭하면 상세" 3단 구조가 필요.
4. **처방 이중 표기** (§10) — 선수 표기 + 쉬운 설명 병기는 카드를
   길게 만든다. 현행 도움말(TermHelp) 패턴처럼 접기 기본을 권고.
5. **선수용 토글 상시 노출** (§14 "화면 우측") — 헤더에 로그인 버튼·
   더보기가 이미 있다. 세 번째 상시 버튼은 과밀 — 위치 재검토 필요.

## 6. 지속 운영 위험

- §12 유행 훈련법 콘텐츠는 "만들면 끝"이 아니라 **상시 편집·검토
  노동**이다(마지막 검토일 표시 의무). 1인 오너 체제에서 콘텐츠 부채가
  쌓이면 "검토일 오래됨"이 신뢰를 깎는다 — 초기 항목 수를 3~5개로
  제한하는 운영 상한 권고.
- 플랜에 없는 것: localStorage→계정 데이터 마이그레이션 전략, 동기화
  충돌 해결, 알림 정책. 단계 1 감사에서 다뤄야 한다.

## 7. 결론

- 방향·순서·안전 설계: **승인 가능 수준**. 준비 문서의 권한 통제도 적절.
- 단, 구현 착수 전 §3의 R1~R5 오너 결정을 권고. 특히 R1(홈 폴드 규율)은
  결정 없이 단계 3 이후 화면 작업이 시작되면 반드시 지저분해진다.
- 첫 구현은 준비 문서 단계 1(정합성 감사) → 단계 3(거리 분석)이 옳다.
  단계 3은 기존 데이터만으로 가치가 즉시 나오는 유일한 항목이다.
