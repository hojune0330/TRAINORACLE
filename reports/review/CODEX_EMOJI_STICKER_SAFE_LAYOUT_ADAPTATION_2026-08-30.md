# 이모지 스티커 V1 최신 main 안전 이식 보고

- 대상 소스: PR #278, commit `a572ff9`
- 이식 기준: PR #280의 본문 비침범 장식 레일과 최신 `main`
- 상태: 구현 및 로컬 검증 완료, 원격 CI 대기

## 1. 그대로 병합하지 않은 이유

PR #278은 48종 카탈로그, 3개 상한, 저장 호환, 픽커와 reduced-motion
처리가 유효하다. 다만 당시 CSS는 세 이모지 슬롯의 위치를 `top`,
`left`, `right`, `bottom` 좌표로 표현했다. 본문 길이와 글자 확대에
따라 스티커가 글을 가릴 수 있으므로 최신 레이아웃에 그대로 병합하지
않았다.

## 2. 보존한 기능

- 유니코드 텍스트 렌더 이모지 48종, 외부 이미지와 신규 의존성 0
- 날짜별 전용 슬롯 3칸과 페이지당 3개 상한
- 첫 빈 칸 자동 배정, 세 칸이 찼을 때 교체 확인
- 기존 v2 저장 상태의 무료 이모지 자동 획득
- 일지 툴바와 꾸미기 스튜디오의 44px 픽커
- 분석, 오라클, 안전 판단, 포인트 산식과의 분리

## 3. 바꾼 레이아웃

- `BODY_STICKER_1..3` 저장 식별자는 유지한다.
- 화면에서는 본문 아래 `journal-sticker-rail`의 세 셀로 렌더한다.
- 레일은 문서 흐름 안에 있으므로 본문이 길어져도 함께 밀려난다.
- 레일과 스티커는 `pointer-events: none`으로 일지 버튼을 가로채지 않는다.
- 28/24/20px 크기와 고정 회전각은 유지하고, 절대 위치 값은 사용하지 않는다.

## 4. 검증 관문

- 타입 검사와 프로덕션 빌드
- 카탈로그, 저장, 3개 상한, 자동 배정 계약 테스트
- 320px, 모바일, 데스크톱, reduced-motion 실제 브라우저 좌표 검사
- 본문 하단과 스티커 레일 상단의 비겹침 검사
- 레일 내부 3개 스티커, 가로 오버플로, 포인터 비침범 검사
- 전체 앱 단위 테스트 및 전체 브라우저 회귀 검사

원본 페이블 보고서는 PR #278 당시 구현에 대한 역사적 검수 기록이다.
최종 출시 판정은 이 이식 보고서의 최신 `main` 기반 검증 결과를 따른다.
