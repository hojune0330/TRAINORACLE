### F-01. 외부 자료의 수신·확인과 분석·처방 채택 사이의 설계 경계

- **우선순위:** P1 - 신규 외부 분석을 공개하기 전의 설계·채택 전 필수 조건이다. 현재 운영 장애가 재현된 P0가 아니다.
- **판정:** **[사실]** 원안은 원자료 확인, 기술적 분석, 해설, 다음 계획의 네 용도를 별도 조건으로 분리한다. 또한 외부 공급자 활동은 사용자 확인 뒤에도 별도 출처·신뢰 규칙이 수용되기 전까지 통계, 추이, Oracle, 안전, 계획 생성에서 제외된다. 파일 가져오기 코드도 확인 저장 시 `objectiveDataState: "CONFIRMED"`를 둘 수 있지만 거리·시간·페이스 출처는 `DERIVED`로 유지한다. **[미확인]** 이번 정적 검토만으로 현재 런타임이 이 네 용도를 혼동한다는 버그는 확인되지 않았다. **[가설]** 후속 구현이 이 분리를 상태·감사 모델에 옮기지 않으면, 확인된 외부 값과 분석 활성화를 같은 성공 상태로 취급할 수 있다.
- **근거:** `reports/research/PROGRAMMED_TRAINING_ANALYSIS_AND_EVIDENCE_PRODUCT_REVIEW_2026-09-17.md:52-57,61-70,194-205,249-254`; `TRAINORACLE-private-memo-save-hotfix-20260913/specs/reconstruct/EXTERNAL_RECORD_INTEGRATION_SPEC.md:120-149`; `TRAINORACLE-private-memo-save-hotfix-20260913/app/src/domain/import/import-draft.ts:90-107,167-181`; `TRAINORACLE-private-memo-save-hotfix-20260913/app/src/domain/field-provenance.ts:38-48,94,128-143`.
- **사용자 피해/반례:** 이 가설이 현실화된 경우에만, 사용자는 워치 파일을 확인한 뒤 최근 4주 거리와 Oracle 설명에 이미 반영됐다고 믿을 수 있다. 그 기대를 맞추려 외부 `DERIVED`를 `EXPLICIT`으로 바꾸면 서로 다른 공급자·단위의 동일 활동이 거리 합계와 다음 후보 근거에 섞일 수 있다. 확인은 사용자의 직접 입력으로 바뀌지 않는다.

- **장점/비용:** 원안의 이미 분리된 네 용도를 보존하면서 확인 화면과 출처 이력을 정직하게 만든다. 비용은 상태명, 감사 이유, 혼합 필드 표시를 실제 채택 범위에 맞춰 설계해야 한다는 점이다.

### F-02. 외부 활동 시간의 의미가 보존되지 않는 현재 투영

- **우선순위:** P1 - 첫 외부 시간/페이스 비교 또는 시간 합계 전의 채택 조건.
- **판정:** **[사실]** 현재 가져오기 타입은 `distanceKm`, 단일 `durationMin`, `avgPace`만 보존한다. TCX는 각 Lap의 `TotalTimeSeconds` 합계를, GPX는 첫 시각부터 마지막 시각까지의 경과 시간을 같은 `durationMin`에 넣는다. CSV/JSON도 단일 `durationMin`만 받는다. **[미확인]** 이 코드만으로 TCX `TotalTimeSeconds`가 이동시간, 타이머 시간, 실제 작업시간 중 무엇이라고 단정할 수 없다. **[가설]** 그 값을 화면에서 운동시간으로 번역하면 서로 다른 의미의 시간이 비교될 수 있다.
- **근거:** `reports/research/PROGRAMMED_TRAINING_ANALYSIS_AND_EVIDENCE_PRODUCT_REVIEW_2026-09-17.md:70-78,84-88,108-120,130-137,198-201`; `TRAINORACLE-private-memo-save-hotfix-20260913/app/src/domain/import/activity-file.ts:7-17,61-80,92-116,130-167`; `TRAINORACLE-private-memo-save-hotfix-20260913/app/src/domain/import/structured-activity-file.ts:5-12,30-45`.
- **사용자 피해/반례:** 같은 10 km 기록에서 GPX는 정지 시간을 포함한 70분, 다른 파일은 활동 총시간 55분을 줄 수 있다. 둘을 모두 운동시간으로 표시하면 페이스, 훈련 비교, 평균 RPE당 시간 해석이 달라진다. 계획의 반복 사이 60초와 세트 사이 3분은 예정 회복이지 외부 활동 시간의 한 종류가 아니다.
- **수정 방향:** 첫 외부 보고서에는 다섯 개의 대형 시간 필드를 강제하지 않는 최소 모델 후보가 더 맞다. 값(초), 의미(`ELAPSED | MOVING | TIMER | SOURCE_DEFINED | UNKNOWN`), 원본 필드명, 확인된 경우에만 원본 정의 참조를 하나의 외부 활동 시간 관측으로 보존한다. TCX `TotalTimeSeconds`는 승인된 공급자 매핑이 있기 전 `UNKNOWN` 또는 `SOURCE_DEFINED`으로만 남기고 이동시간이나 실제 작업시간으로 추론하지 않는다. 계획의 예정 작업·예정 회복은 외부 활동 시간과 다른 기존 계획 유형으로 둔다. 실제 세그먼트 작업시간은 F-03의 별도 수용 조건 전에는 만들지 않는다.
- **장점/비용:** 과대 스키마가 아직 없는 의미를 꾸며 내는 일을 피하면서, 같은 의미로 확인된 시간만 기술 요약에 집계하게 한다. 랩·회복 상세 비교는 뒤로 미뤄야 하며, 원본 시간 정의를 표시하는 매핑은 필요하다.
- **검증법:** 합성 TCX의 `TotalTimeSeconds`는 의미 미확인 상태로 표시하고, GPX 첫-마지막 시각은 `ELAPSED`로만 표시하는지 확인한다. 서로 다른 의미의 시간은 하나의 합계·페이스 비교에 섞이지 않고, 계획 회복 시간이 외부 시간에 더해지지 않는지도 확인한다. 이번 검토에서는 실행하지 않았다.

### A 단독의 가장 작은 실제 end-to-end 경계: 외부 분석 없는 최소안

**입력 → 처리 → 출력**을 문서만으로 끝내지 않으려면 다음 한 경계가 가장 작고 정직하다.

1. **입력:** 기존 안전·적격성 경로로 선택되어 저장된 현재 계획과, 사용자가 직접 입력한 `EXPLICIT` 구조화 일지값만 사용한다. 외부 파일에서 파생된 값은 가져오기 미리보기/저장 화면에 남아도 이 흐름의 분석 입력이 아니다.
2. **처리:** 저장 계획은 기존 설명 영수증과 세션 지문으로 읽고, 실제 기록은 정확한 계획 링크가 있는 직접 입력 RPE와 계획 진행 표시만 별도로 읽는다. 거리/목적 집계는 현행 직접 입력 분석 경로의 표본·제외·중복·충돌 표기를 그대로 쓴다.
3. **출력:** 한 훈련의 `무엇을 하는가 / 수치와 회복 / 일반 원리와 한계 / 당시 계획과 실제 기록의 구분 / 근거와 모름` 및 최근 4주 거리·8주 직접 선택 목적의 서술적 요약을 제공한다. "실제 반복 비교", "효과", "부족", "다음 계획 변경"은 출력하지 않는다.
4. **수명:** 결과는 요청 시 계산하는 읽기 전용 화면으로 한정하고, 공유본·PDF·이미지·영구 파생 보고서는 포함하지 않는다. 기존 계획의 역사 영수증은 보존하되, 일반 분석 결과를 과거 처방의 이유로 재사용하지 않는다.
5. **안전/권한:** 이 경계는 새 템플릿, 새 과학 공식, 외부 자료 분석, 안전 해제, 자동 증량, 청소년/혼자 훈련 제한을 만들지 않는다. 기존 관문의 결과를 읽을 뿐 재정의하지 않는다.

이 경계는 이미 배포되었거나 실행 검증되었다는 주장이 아니다. A로 진행하려면 합성 입력에 대한 계산·변조·출처·계획 링크·개인정보 경계 확인과 실제 화면/배포 검증이 별도로 필요하다. 이 경계는 외부 분석을 열지 않는 가장 작은 값 경로이며, 외부 활동 분석을 포함한 최종 순서 평가는 7절의 2차 재판정으로 한정해 갱신한다.

## 6. 결론

원안의 가장 강한 부분은 외부 AI 없이도 구조화된 훈련을 설명하고, 계획·실제·일반 근거·개인 관측을 구분하려는 방향이다. 다만 다음 두 경계는 제품 순서에서 합치면 안 된다.

1. **외부 자료의 수신·확인·정규화**와 **분석/처방 채택**.
2. **A/B 전체 계획 후보**와 **MAIN별 독립 방법**.

외부 분석을 제외한 가장 작은 실제 경계는 A다. 그러나 워치 사용자를 보관만 하는 상태로 고정하지 않기 위한 외부출처 E2E의 최종 권고는 7절에서 A+B 병행 준비와 B의 조건부 공개 범위를 구분해 재판정한다. 외부 파일 분석, 실제 반복/랩 비교, 생리 추이, 공유형 파생 보고서는 각각의 출처·시간 의미·세그먼트·무효화 계약이 수용된 다음 단계로 남긴다. 이 결론과 7절은 기능 또는 스펙의 채택 권한을 만들지 않는다.

## 7. 2차 재판정 부록

이 부록은 요청된 세 항목만 재검토한다. F-03부터 F-08까지의 판정은 변경하지 않으며, 이 부록은 실제 사용자 연구, 독립 전문가 승인, 공급자 연동, 새 스펙 채택의 증거가 아니다.

### 7.1 F-01 재판정: P0 재현 버그가 아닌 P1 채택 전 설계 조건

- **재판정/우선순위:** F-01은 P1로 재분류한다. 현재 운영 중인 혼동 버그나 장애를 재현한 결론이 아니라, 외부 분석을 새로 열기 전에 확인해야 할 설계·채택 전 조건이다.
- **근거:** 원안 자체가 원자료 확인, 기술적 분석, 해설, 다음 계획을 분리한다. `reports/research/PROGRAMMED_TRAINING_ANALYSIS_AND_EVIDENCE_PRODUCT_REVIEW_2026-09-17.md:61-78`; 현행 외부 파생 필드는 확인 후에도 분석과 계획에서 제외된다. `TRAINORACLE-private-memo-save-hotfix-20260913/specs/reconstruct/EXTERNAL_RECORD_INTEGRATION_SPEC.md:120-149`; `TRAINORACLE-private-memo-save-hotfix-20260913/app/src/domain/field-provenance.ts:38-48,128-143`.
- **사용자 피해/반례:** 명시적 분리를 구현 상태와 감사 표기에 옮기지 않은 미래 변경에서만, 확인 버튼이 분석 또는 처방 허가처럼 보일 수 있다. 정적 자료만으로 그런 현재 화면·런타임의 존재를 단정하지 않는다.
- **수정 방향:** B를 검토할 때 수신·보관 권한, 확인·연결 권한, 한정 기술 계산 권한, 처방 입력 권한을 각각 별도 질문으로 승인한다. 확인이나 저장은 계산 권한이 아니며, 계산 권한도 처방 권한이 아니다.
- **장점/비용:** 원안의 네 용도 분리와 현행 직접 입력 코어를 그대로 살린다. 대신 B의 허용 필드·용도·감사 이유를 실제로 명시해야 한다.
- **검증법:** 합성 외부 관측이 수신·저장·확인되더라도 기본 분석과 계획 입력에는 남아 있지 않고, B에서 명시적으로 허용한 기술 보고서 한 종류에만 들어가는지 확인한다. 이번 정적 검토에서는 실행하지 않았다.

### 7.2 F-02 재판정: 의미 미확인을 보존하는 최소 시간 모델

- **재판정/우선순위:** 시간 분리는 P1로 유지하되, 다섯 종류 시간 필드를 즉시 도입하라는 기존 수정 방향은 철회한다. 첫 외부출처 경계에는 최소 시간 관측이 더 적합하다.
- **근거:** 현재 TCX는 Lap의 `TotalTimeSeconds`를 합산하고 GPX는 첫 시각부터 마지막 시각까지를 단일 `durationMin`으로 투영한다. `TRAINORACLE-private-memo-save-hotfix-20260913/app/src/domain/import/activity-file.ts:61-80,92-116,130-167`. 이 구현에는 `TotalTimeSeconds`가 moving, actual work, timer 중 어느 것인지를 판정하는 공급자 정의 매핑이 없다.
- **사용자 피해/반례:** `TotalTimeSeconds`를 movingSeconds 또는 actualWorkSeconds로 이름만 바꾸면, 공급자별 정의 차이와 정지 시간을 숨긴 채 잘못된 페이스·시간 비교를 만들 수 있다. 반대로 계획의 예정 회복을 외부 관측과 한 필드에 놓으면 예정과 실제도 섞인다.
- **수정 방향:** 검토용 최소 모델 후보는 `valueSeconds`, `semantic = ELAPSED | MOVING | TIMER | SOURCE_DEFINED | UNKNOWN`, `sourceField`, 그리고 확인된 경우에만 원본 정의 참조다. TCX `TotalTimeSeconds`는 승인된 매핑 전 `UNKNOWN` 또는 `SOURCE_DEFINED`으로 보존한다. 계획 시간은 예정 작업·예정 회복의 별도 유형으로 남기고, 외부 활동에서 actualWork를 추정하지 않는다.
- **장점/비용:** 과대 스키마보다 작고 의미를 발명하지 않는다. 대신 첫 B 보고서는 같은 의미로 확인된 시간만 집계하거나 의미가 다른 시간을 분리 표시해야 하며, 랩·회복 상세 분석은 계속 제외된다.
- **검증법:** 합성 TCX, GPX, 구조화 파일에서 시간값과 의미 라벨, 원본 필드명을 함께 보이고 `UNKNOWN` 시간을 moving 또는 actual work로 계산하지 않는지 확인한다. 계획 예정 회복이 외부 활동 시간 합계와 분리되는지도 확인한다. 이번 정적 검토에서는 실행하지 않았다.

### 7.3 A+B 병행안 반론과 최종 권고

- **우선순위:** P1 - 제품 가치 순서의 재판정이다. 처방·안전 권한을 넓히는 제안이 아니다.
- **근거:** A에는 이미 계획 설명 영수증, 정확한 계획-일지 링크, 직접 입력 RPE 비교와 직접 입력 분석 경로가 있다. `TRAINORACLE-private-memo-save-hotfix-20260913/app/src/domain/training-explanation-receipt.ts:26-72`; `TRAINORACLE-private-memo-save-hotfix-20260913/app/src/domain/plan-journal-evidence.ts:50-117`; `TRAINORACLE-private-memo-save-hotfix-20260913/app/src/domain/personal-oracle.ts:52-147`. 동시에 현재 외부 가져오기는 활동 envelope를 보관할 수 있지만 파생 필드는 분석에서 제외된다. `TRAINORACLE-private-memo-save-hotfix-20260913/app/src/domain/import/import-draft.ts:90-107,167-217`; `TRAINORACLE-private-memo-save-hotfix-20260913/app/src/domain/field-provenance.ts:38-48,94,128-143`.
- **사용자 피해/반례:** A만 최종안으로 고정하면 워치 사용자는 파일을 수신·보관·확인해도 그 기록에서 날짜·거리·시간의 제한된 기술 요약조차 받지 못한다. 반대로 B를 외부 활동의 계획 비교나 처방 근거로 넓히면, 현행 제외 경계와 F-01부터 F-03의 미해결 조건을 우회한다.
- **수정 방향:** 최종 권고는 A와 B의 병행 준비다. A는 현행 자료로 즉시 가치 경로를 유지한다. B는 오너가 선택한 한 공급자·한 원본 namespace에 한정해 활동 날짜, 거리, 의미 라벨이 붙은 시간, 포함·제외·중복/수정 상태를 보여 주는 요청 시 계산의 기술 보고서 한 종류만 E2E로 검토한다. 수신·저장은 기존 envelope/확인 경계에 머물고, 계산은 그 한 보고서의 출처 한정 집계만 허용 후보이며, 처방 입력·안전·새 임계값·새 처방은 계속 허용하지 않는다. B의 공개 전에는 F-01의 적격성 표, F-02의 시간 의미, 원본 ID·수정/삭제 처리, 보고서의 출처·coverage 표기가 정확한 범위로 오너 수용되고 합성 검증되어야 한다.
- **장점/비용:** A는 승인된 코어, 청소년·혼자 훈련의 기존 경로, 계획/RPE 가치를 불필요하게 축소하지 않는다. 조건부 B는 워치 사용자의 첫 분석 가치를 보관 이상으로 넓히되 처방 영향과 교차 공급자 복잡도를 막는다. 비용은 한 공급자라도 필드 의미·수정·삭제·보고서 수명 계약과 검증이 필요하며, 그 게이트가 끝나기 전 외부 분석을 활성화할 수 없다는 점이다.
- **검증법:** 합성 단일 공급자 활동만으로 날짜·거리·시간 의미·출처 범위가 한 보고서에 재현되고, 미확인 시간·중복·수정·삭제는 포함 여부와 이유가 드러나는지 확인한다. 같은 데이터가 Personal Oracle, 누적 거리, 에너지 원장, 계획 생성, 안전 판단에 유입되지 않는지도 별도로 확인한다. 이번 정적 검토에서는 실행하지 않았다.
- **최종 권고:** A 단독은 가장 작은 비외부 경계이지만 최종 제품 순서로는 충분하지 않다. 따라서 A를 유지하면서 B를 위의 한정된 E2E로 병행 준비하는 것이 권고다. 다만 B의 게이트가 수용·검증되기 전에는 외부 자료의 수신·저장만 가능하고 계산·처방 권한은 생기지 않는다. 게이트가 충족된 뒤에도 B는 한 공급자, 날짜·거리·의미 보존 시간, 한 종류의 기술 보고서에만 머물러야 한다.
