## 1. 리뷰 결과: 기능보다 크게 읽히는 주제명부터 수정 권고

이번 명칭 변경으로 새로 생긴 장애와 이전부터 있던 표현 문제를 구분했다. 아래 항목은 대체로 기존 주제명의 문제이며, 오라클을 대표 브랜드로 올린 뒤 더 중요해진 개선점이다. 검토한 공개 게스트 흐름에서 출시 차단 장애는 발견하지 않았다. 전체 계정·처방 기능을 재검증했다는 뜻은 아니다.

### R1 / P2: 강점·보완점은 능력 진단을 약속하지만 실제 결과는 계획과 체감강도 비교다

- 근거: `app/src/domain/oracle-exploration.ts:48`의 제목, 같은 파일 `:60`의 진단하지 않는다는 설명.
- 실제 개인 결과: `app/src/domain/oracle-personal-result.ts:244`부터 연결 일지와 계획 RPE를 비교한다. `:291`에서도 향상 원인·자동 처방을 주장하지 않는다.
- 공개 화면 재현: 320px에서 ‘강점·보완점’을 누르면 ‘계획 RPE 5, 실제 느낌은 7’ 예시가 표시된다. 하단의 제한 설명을 읽어야 제목과 실제 범위 차이를 알 수 있다.
- 권장: 주제명을 **계획과 실제**로 변경하고, 질문은 **계획보다 더 힘들었나요?**처럼 구체화한다. 장래 능력 분석 기능을 삭제하자는 제안이 아니라 현재 구현과 이름을 맞추자는 제안이다.
- 장점: 원인·능력 진단으로 오해하는 것을 줄인다. 단점: 브랜드의 기대감은 줄 수 있으므로 결과에 연결된 다음 행동과 실제 수치를 강화해야 한다.

### R2 / P2: 현재 수준·훈련 후 변화도 실제 비교 범위보다 넓게 읽힌다

- 근거: `oracle-exploration.ts:27,39`의 현재 수준은 같은 종목 기록 비교이며 현재 체력·전체 선수 순위 판정이 아니다. `:130,142`의 훈련 후 변화는 월별 RPE 중앙값 예시이며 훈련 효과의 인과 판정이 아니다.
- 실제 개인 결과: `oracle-personal-result.ts:331-352`는 선택 지표의 월별 기록을 사용하며, RPE가 없으면 거리로 대체할 수 있다. `:371-375`는 월별 중앙값이라는 범위와 한계를 명시한다.
- 권장: **현재 수준 → 경기 기록 변화**, **훈련 후 변화 → 월별 훈련 변화**. 결과 내부의 제목·단위는 실제 지표에 따라 **체감강도 변화 / 거리 변화**로 구체화한다. 대체 지표가 거리인데 제목을 RPE로 고정하면 안 된다.
- 장점: 기록 개선과 현재 능력을 혼동하지 않는다. 단점: 기존 주제와 월별 변화 메뉴가 겹쳐 보일 수 있어 주제 진입과 상세 지표 화면의 역할을 함께 정리해야 한다.

### R3 / P2: 우선 훈련은 구체적인 처방이 아니라 다음 계획을 검토하는 결과다

- 근거: `oracle-exploration.ts:112-121`. 개인 결과는 `oracle-personal-result.ts:267-296`에서 유지·줄이기 검토 문구와 현재 계획으로 가는 행동을 제공한다.
- 위험: 사용자는 우선적으로 해야 할 정확한 운동을 기대하지만 다시 계획을 확인해야 한다. 같은 RPE 자료를 사용하는 ‘강점·보완점’과 결과도 비슷하다.
- 권장: **다음 훈련 점검**으로 명확히 구분한다. 첫 줄에 판단 요약, 바로 다음에 **내 계획에서 확인**을 둔다. 이 화면에서 별도의 숫자 처방이나 자동 증량을 새로 만들지 않는다.
- 장점: 기록에서 다음 행동으로 이어지는 경로가 분명해진다. 단점: 독립 콘텐츠 6개처럼 보이던 외형보다 실제 기능 구분이 작아 보일 수 있다. 기능을 부풀리는 것보다 실제 사용 흐름을 우선한다.

### R4 / P2: 오라클 첫 방문은 브랜드의 가치를 보여주기 전에 기록 부족부터 말한다

- 근거: `app/src/screens/Trends.tsx:120-134`. 기본 화면의 주요 버튼은 첫 기록 남기기이고, 예시는 접힌 안내 안에 있다. 계획 생성으로 곧바로 가는 화면 내 행동도 기본 빈 요약에는 없다.
- 공개 375px 화면: 요약·훈련량·훈련 구성·월별 변화·파일 분석 다음에 ‘분석할 기록이 아직 없어요’가 크게 표시된다. 사용자는 오라클에서 무엇을 얻을지 보기 전에 입력 요구를 만난다.
- 권장: 기록 없는 상태에서는 **오라클** 옆 또는 아래에 **훈련 해석과 계획** 정도의 짧은 기능 안내만 둔다. **예시 결과 보기**를 접지 않은 주 행동으로 제공하고, **훈련 계획 만들기**를 보조 행동으로 둔다. 기록 작성은 이미 있는 하단 기록하기 경로를 유지한다. 기록 보유자는 실제 요약과 다음 행동을 우선한다.
- 장점: 기록이 없어도 결과 가치를 먼저 경험하고 계획으로 갈 수 있다. 단점: 예시와 내 결과를 혼동할 수 있으므로 현재의 **예시 기록 / 내 기록을 분석한 결과가 아니에요** 경계를 반드시 유지한다.
- 긴 브랜드 소개, 추가 배너 여러 개, 가짜 개인 점수는 추가하지 않는다.

### R5 / P3: 일부 행동 문구가 이동할 화면보다 포괄적이다

- 근거: `oracle-exploration.ts:108,147`의 내 훈련 분석 보기, `oracle-personal-result.ts:377`의 내 훈련 분석 열기.
- 권장: **훈련 구성 보기**, **거리 변화 보기**처럼 실제 목적지를 표현한다. 모든 ‘분석’을 ‘오라클’로 기계적으로 교체하지 않는다.
- 장점: 버튼을 누른 뒤의 예측 가능성이 높아진다. 단점: 여러 화면에 문구가 흩어져 있어 주제·행동 계약과 선택자 테스트를 함께 수정해야 한다.

## 2. 유지할 점

- 하단 탭과 화면 제목은 **오라클**로 일치한다. 실제 행동은 **기록하기 / 계획 / 내 기록으로 확인하기**처럼 익숙한 말로 유지된다.
- 예시는 개인 데이터 분석으로 표시되지 않는다. 예시를 보는 검증에서 실제 계정 로그인이나 온라인 저장은 수행하지 않았다.
- 주제 상세에서 뒤로 가면 오라클 탭과 화면으로 돌아간다.
- 320·375·1440px 모두 가로 넘침이 없고 브라우저 실행 오류가 없었다.
- 동의·프라이버시·과학 설명에서 필요한 **분석**이라는 단어는 유지했다. 이번 브랜딩 배포는 계산·처방·안전·계정 정책 변경이 아니다.
- PC의 기본 경로도 실제 앱을 사용한다. 개발용 갤러리는 `workspace` 쿼리로만 선택되므로 이를 일반 PC 사용자 경로 결함으로 보고하지 않았다(`AppShellFrame.tsx:68`).
