## 우선 위험

### P1 · 계획 전체 흐름에서 현재 위치와 남은 질문을 예측하기 어려움

`PlanBeta.tsx:1026`의 기록 입력 제출은 기록 준비 후 `firstUnansweredQuickStep`으로 넘어간다. 종목을 입력했어도 경험, 가능한 훈련일, 몸 상태 질문은 이어진다. `PlanIntake.tsx:121`과 `:146`의 진행 표시는 별도 빠른 질문 배열을 기준으로 계산하며 기록 입력 화면 수와는 관계가 없다. 따라서 기록을 입력한 사용자가 다음 화면의 `2/4`를 계획 전체의 완료 정도로 읽을 여지가 있다. 정적 해석 위험이며 실제 이탈로 측정한 것은 아니다.

이번 폼에는 숫자 단계나 완료율을 만들지 않고 `계획 준비 · 기록 입력`만 표시했다(`InstantPlanEntryForm.tsx:221`). 완료 버튼은 기존 기록/목표 입력 완료 행동을 유지하며 방향 아이콘으로 이어지는 동작을 드러냈다. 전체 흐름의 진행 표시를 통일하는 일은 아직 남아 있다.

**main에 제안:** 기록 입력과 훈련 조건 확인을 전체 계획 완료 수치로 혼동하지 않도록 화면 제목과 현재 질문 이름을 연결한다. 실제 분기·재진입·통증 검토를 세지 않는 고정 총 단계 수를 추가하지 않는다. 몸 상태 질문과 명시적인 계획 선택·시작은 합치지 않는다.

### P1 · 훈련 직후 일지 쓰기가 날짜 상세의 접힌 영역 안에 있음

`PlanSchedulePreview.tsx:239`의 날짜 선택은 독자 화면으로 이어지고, `:453`은 활성 세션의 footer를 `일지·진행 기록` 공개 안에 둔다. 실제 `이 훈련 일지 쓰기`는 `ActivePlan.tsx:459`, 별도의 진행 선택은 `:476`에 있다. 훈련 뒤 바로 기록하려는 사용자는 먼저 날짜를 열고, 다음에 기록 영역을 펼쳐야 한다. 접힌 영역의 이름만으로 '일지 쓰기'의 위치를 알아야 한다는 탐색 부담이 남는다.

**main에 제안:** 활성 세션에서 계획에 연결된 일지 쓰기 행동을 짧게 직접 노출하는 안을 검토한다. 일지 저장을 훈련 완료로 간주하지 않고, 기존 명시적 진행 선택·읽기 전용 미리보기 제한은 유지한다. 이 보고서는 해당 화면을 수정하지 않았다.

### P2 · 일지의 고정 9.5일 이름을 내 계획 기간으로 오해할 수 있음

`JournalArchive.tsx:141`의 월간 달력 옆에는 `9.5일 주기`가 상시 표시된다. 계획 입력의 기간은 `PlanIntake.tsx:94`의 실제 draft에 따르므로 일지 묶음의 이름과 개인 계획 길이가 같다는 보장은 없다. 월간 기록을 찾으러 온 첫 사용자는 두 탭의 역할부터 해석해야 한다.

**main에 제안:** 일지 묶음과 훈련 계획 기간의 구분을 실제 날짜 범위와 함께 확인할 수 있게 한다. 표현 문제를 고치면서 주기 계산이나 저장 모델을 변경하지 않는다.

### P2 · 모바일 글자 확대와 새 선택 행의 실제 배치는 미검증

기준 선택에 짧은 의미 설명을 붙였으므로 작은 폭에서는 줄 수가 늘어날 수 있다. CSS에는 기존 토큰, 최소 터치 크기, 줄바꿈과 줄어들 수 있는 열을 사용했다. 이번 실행은 JSDOM 단위 테스트이며 실제 320px 화면, 확대 글자, 화면 키보드, 스크린리더의 읽기 순서를 보증하지 않는다.

## 폼에 반영한 수정

1. **선택을 대신한 것처럼 표시하지 않기:** 새 진입에서는 `내 기록`이 미리 눌린 것처럼 보이지 않는다. 기존 current/goal 기본 데이터와 계산은 유지하고, 실제 선택 여부만 따로 표시한다(`:90`, `:266`).
2. **같은 이름의 뜻을 고르기 전에 알기:** `내 기록`에는 실제로 달린 시간, `목표만 있어요`에는 앞으로 달리고 싶은 시간, `기록 없이`에는 시간 입력 건너뛰기를 짧게 붙였다. 접근 가능한 버튼 이름은 그대로이며 설명을 별도로 연결했다(`:258`).
3. **페이스와 전체 시간 구분:** 상세 제목에 선택 종목과 전체 시간을 표시하고, 같은 의미를 반복하던 종목 안내·기록 legend를 줄였다(`:291`). 분/초 라벨과 소수·빈칸 안내는 유지했다.
4. **돌아가기와 종목 수정:** 뒤로 가기는 질문 위에 있다. 상세에서 종목만 바꾼 경우 기준을 다시 고르지 않고 상세로 돌아온다. 수정 취소는 `기록 입력으로`이며 시간·날짜·현재/목표 초안을 보존한다(`:213`, `:225`, `:279`). 이 경로는 기존 네 번의 클릭(기준으로, 종목으로, 종목 선택, 기준 선택)을 두 번(종목 수정 열기, 종목 선택)으로 줄인다. 이는 소스/단위 테스트의 경로 구조 비교이며 실제 사용자의 클릭 통계가 아니다.
5. **숨긴 날짜도 상태는 보이기:** 빈 날짜는 `기록 날짜 추가 · 선택`, 입력된 날짜는 `기록 날짜 · YYYY-MM-DD`로 보인다. 빈 날짜가 최근 12개월 기록에서 제외되는 기존 조건은 공개 밖에 표시한다. 오류 때 공개를 자동으로 열고 입력에 초점을 두며, 제목에도 날짜 확인 필요를 표시한다(`:318`).
6. **제출 중 값 보호:** 기존 `disabled` 상태가 시간뿐 아니라 날짜 입력에도 적용된다(`:329`). 새로운 자동 저장은 없으며 종목/기준 이동과 날짜 공개는 제출하지 않는다.

계산, 숫자 파싱, 달력 날짜 검증, 허용 종목 값(하프 21097 포함), 스키마, 저장 함수, 안전 게이트는 바꾸지 않았다. `CURRENT_RECORD`와 `GOAL_ONLY` 초안 분리, 명시적 `NO_RECORD` 제출과 current/goal 완료 버튼 경계를 유지했다.

## 통합 시 참고

종목과 기준 버튼 이름, `기록 입력 완료`/`목표 입력 완료`, 폼 이름 `계획 시작 정보`는 유지했다. 새 종목 수정 버튼의 접근 가능한 이름은 예를 들어 `5km 종목 다시 선택`이다. 상세 제목은 `5km를 달린 전체 시간` 또는 `5km 목표 전체 시간`으로 바뀌었다. 이미 날짜가 있는 편집의 공개 제목은 `기록 날짜`, 빈 날짜일 때는 `기록 날짜 추가`다. 제목이나 날짜 공개 문구를 고정한 통합 검사가 있다면 main이 해당 helper를 조정해야 한다.

이 결과는 좁은 입력 흐름의 개선과 단위 계약 확인이다. 청소년 사용성 인증이나 전체 계획·일지 여정 완료 판정으로 사용하지 않는다.
