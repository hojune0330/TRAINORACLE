| 발견 | 수정 | 확인 범위 |

| 일지는 있는데 `기록 없음`으로 읽힘 | 분석 가능한 기록의 부재와 일지 자체 부재를 구분 | 출처 확인이 필요한 자료를 분석에 임의 편입하지 않음 |
| 빈 분석 화면의 선택지가 과밀함 | 기록 진입 하나를 우선하고 예시 주제는 `예시로 먼저 둘러보기` 안에 유지 | 키보드로 열기·닫기, 예시 접근 보존 |
| 짧은 도움말이 아래 선택부를 가림 | 위쪽 공간이 충분하면 위로 표시, Escape로 닫으면 도움말 버튼에 포커스 복귀 | 경계·배치 단위 검사. 모든 화면에서 무겹침을 입증한 것으로 확대하지 않음 |

로그인하지 않은 사용자의 확인 창은 자동 백업이 아니다. 탭 강제 종료·브라우저 종료 등에서 모든 내용을 복구한다고 약속하지 않는다. 계정 초안 자동 보관과 미로그인 메모리 보호를 구분한다.

## 2. 훈련 화면에서 바뀐 점

1. 오늘 훈련에 `훈련 방법·근거` 버튼을 제공한다. 해당 날짜와 오전/오후 위치를 바로 열고, 닫으면 원래 버튼으로 돌아온다.
2. 승인된 개인 페이스 훈련은 저장된 같은 처방에서 준비·본운동·회복·정리를 읽는다. 설명용 새 수치를 계산하지 않는다.
3. 반복 시간은 읽기 쉬운 초 단위의 `약` 표기이며 원본 소수점 목표는 보존한다.
4. 같은 최소·최대 시간 `35~35분`은 `35분`으로 표시한다. 실제 35~60분 범위는 유지한다. 다음 계획 비교의 줄바꿈 단위도 함께 수정했다.
5. 해당계 선택의 `전력 구간`을 `짧고 강한 구간`으로 고쳤다. 모든 GLY 처방을 전력질주라고 안내하지 않는다.
6. 반복 수·회복 수치가 없는 RPE 기반 MAIN에는 그 한계를 표시한다. 준비·회복·정리를 포함한 총 시간을 고강도로 계속 달리라는 뜻으로 읽지 않도록 한다.

| 적용 종목 | 현재 채택된 기준형 | 반복 사이 회복 |
|---|---|---|
| 800m | 200m × 10회, 같은 종목 기록 기준 | 60초 서서 쉬기 |
| 1500m | 500m × 3회, 같은 종목 기록 기준 | 180초 서서 쉬기 |

이 표는 모든 선수에게 자동으로 배정되는 공통 훈련표가 아니다. 경험·같은 종목 기준 기록·현재성·훈련 목적·명시적 적용·안전 상태 등 기존 적격성 검사를 통과한 범위의 기준형이다. 주기 맥락에 따라 실제 저장된 처방을 읽어야 하며 이 표로 덮어쓰지 않는다.

준비운동 15분(RPE 2~3), 20초 점진 가속 4회와 사이 40초 걷기·조깅, 정리운동 10분(RPE 1~2)을 실제 operationalComponents에서 읽는다.

예: 합성 5000m 기록 18분 31초를 명시적으로 선택했을 때 1000m 목표 원본은 222.2초이며 화면은 `약 3분 42초`로 안내한다. 5회 본운동과 사이 2분 30초 조깅을 보여준다. 선수 상태에 대한 의료 판단이나 성과 보장은 아니다.

### 아직 완성되지 않은 부분

- 10km·하프·마라톤 및 다수 RPE-only 조합은 총 시간·체감 강도 중심이다. 모두 정확한 반복·회복까지 제공한다고 할 수 없다.
- 현재 A/B는 MAIN 방법 두 가지가 아니라 기초·회복 훈련 시간 차이가 중심이다. 서로 다른 MAIN 2개라는 제품 목표를 완성했다고 표시하지 않는다.
- 새 훈련 풀과 수치 조정 기반 코드가 있다는 사실은 검토된 훈련이 활성화됐다는 뜻이 아니다. 위 빈 registry가 실제 공개 범위를 제한한다.
- 기록이 부족한 사용자에게도 따라 할 수 있는 구체적 시간형·거리형 구성을 제공하려면, 기존 오너 근거검토 경로에 따라 정확한 구성과 적용 조건을 채택해야 한다. 검토되지 않은 숫자를 UI 개선으로 추가하지 않았다.
- `METHOD_OWNER_REVIEW_BUNDLE_V3.json`을 다시 파싱해 검토 항목 37개를 확인했다. `SESSION_METHOD_OWNER_DECISIONS_2026-09-08.md`는 시간 정책과 입문 지원 대안의 부분 승인이며 `runtime_activation: false`다. `TRAINING_ADOPTION_READY_PACKET_2026-09-08.md`도 정확한 37개 구성 전체 채택을 부여하지 않는다. 준비된 자료가 없어서가 아니라, 검토안과 현재 운영 공급 사이의 연결이 미완성인 상태다.

## 4. 다음 훈련 확장의 실행 기준

1. 이미 작성된 후보 풀·근거 검토·오너 결정 문서와 실제 registry를 대조한다. 없는 문서나 완료를 추정하지 않는다.
2. 종목 × 목적 × 경험 × 주기 역할별로 `현재 활성 / 검토안 있음 / 수치 없음 / 승인 연결 없음`을 구분한다. 동일 목적의 후보를 고정 쌍으로 묶지 않는다.
3. 우선 순위는 기록 없이 받는 MAIN의 구체적 시간·반복·회복, 그 다음 기록 기반 MAIN 선택 폭과 장거리 범위다. 기존 일2회·주기 연결을 보존한다.
4. 한 훈련은 준비, 한 번의 거리 또는 운동 시간, 목표 강도/근거 있는 페이스, 반복·세트, 반복/세트 회복, 정리까지 읽고 실행할 수 있어야 한다. 해당 없음은 명시한다.
5. 각각의 구성 이유·에너지 공급 특성·회복 이유·적용 범위·한계가 수치와 같은 버전으로 연결되어야 한다. 부족한 이력만으로 능력 결핍을 진단하지 않는다.
6. 후보 수 증가를 강도·양·빈도 자동 증가로 연결하지 않는다. 실제 저장 후 재열기·일지 연결·다음 주기 계보까지 검수한다.
7. 초보 마라톤, 청소년 중거리, 오전·오후 선수의 실제 동선을 각각 확인하고 채택된 조합만 배포한다.

이 단계는 후속 준비 기준이다. 이번 수정으로 새 템플릿 승인, 스펙 정본 승격, 근거 이슈 종결을 선언하지 않는다.
