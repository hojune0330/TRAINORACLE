## 1. 검토 방법

사용자가 지정한 모델과 추론 설정으로 별도 하위 검토자를 실행했다. 하나의 응답에서 세 모델을 흉내 낸 것이 아니다.

| 작업자 | 설정 | 분담 |
|---|---|---|
| Sol | `gpt-5.6-sol`, `high` | 제품 가치·사용자 경험, 6개 가상 관점 |
| Terra | `gpt-5.6-terra`, `max` | 스펙·분석 의미·데이터 구조, 6개 가상 관점 |
| Luna | `gpt-5.6-luna`, `max` | 실패·오입력·운영 신뢰, 8개 가상 관점 |
| 주 검토자 | 현재 작업 | 출시 순서·사업성 가설·범위 보존·상충 의견 통합 |

세 검토자의 1차 보고서를 받은 뒤, 주 검토자가 핵심 인용과 반례를 확인하고 각 검토자에게 2차 교정을 요청했다. 세 보고서의 교정본을 수령해 통합했으며 하위 검토 작업은 모두 종료했다. 페르소나는 실제 사용자 인터뷰가 아니며, 모델 수나 의견 일치가 제품 타당성의 증명은 아니다. 긴 추론 설정 역시 정확성의 증거로 사용하지 않는다.

## 2. 주 검토자의 전략 판정

**방향은 유지하되, 실행 계획은 보완해야 한다.** 외부 AI 의존을 줄이는 선택은 현재 데이터 취급 경계와 맞는다. 그러나 그 자체가 사용자가 다시 방문할 이유는 아니다.

지향점은 다음 문장으로 잡는 것이 좋다.

> 내가 가진 훈련과 기록을 이해하고, 이전과 무엇이 달랐는지 확인하고, 근거가 보이는 다음 훈련을 선택한다.

데이터가 적거나 특정 워치를 쓰지 않아도 시작할 수 있어야 한다. 그렇다고 자료가 없는 사람에게 개인 분석을 지어내지는 않는다. 가진 자료에 맞춰 다음 세 가지 가치를 분리한다.

1. **기록 없어도:** 받은 훈련의 구성과 일반적인 의미를 이해한다.
2. **수행 기록이 있으면:** 계획·이전 수행과 비교한다.
3. **개인 조건과 허용 근거가 갖춰지면:** 개인 참고 페이스와 승인된 다음 후보를 선택한다.

## 3. 원안에서 유지할 장점

- 계산과 설명이 같은 구조화 처방을 읽는다. 숫자와 설명의 불일치를 줄일 수 있다.
- 실제 기록·계획·주관적 느낌을 나눠 다룬다. 단순 완료 클릭이 운동 측정값으로 둔갑하지 않는다.
- 프로그램 기반으로도 개인화한다. AI API를 줄이는 것이 획일적 계획으로 돌아가는 이유는 아니다.
- 원자료·공식·템플릿·설명 버전을 추적한다. 결과의 근거를 되짚을 수 있다.
- 기존 용어집·계산 코드·오라클·출처 계약을 재사용한다. 새 플랫폼을 처음부터 만드는 일을 피한다.
- 비밀 메모는 분석 대상이 아니다. 데이터 수가 많다는 이유로 처방량을 늘리지 않는다.
- 지원 형식과 미지원 형식을 정직하게 구분한다. 모든 파일을 완벽히 읽는다고 약속하지 않는다.

## 4. 주 검토자의 보완 요구

아래는 원안의 설계 보완 사항이다. 현재 서비스에 같은 결함이 실제 발생했다는 판정이 아니다.

### A. 외부 자료 정비를 모든 기능의 선행 조건으로 만들지 않는다

원안 §12는 외부 필드 허용표를 첫 단계, 훈련 해설표를 두 번째 단계에 둔다. 이미 존재하는 계획과 직접 입력 기록으로 제공할 가치도 외부 연동 준비에 묶일 수 있다.

**수정:** 공통 검토 후 두 경로로 나눈다. 기존 적격 자료로 해설·비교를 완성하는 제품 경로와, 공급자별 외부 필드 연결 경로를 분리한다. 두 경로는 같은 결과 모델을 사용한다.

장점은 외부 승인·자료 품질 문제와 무관한 부분을 먼저 완성할 수 있다는 점이다. 단점은 두 입력 경로의 시험이 필요하다는 점이다. 계산을 두 벌 만들지 않고 입력 연결 부분만 분리해 보완한다.

### B. 클릭 수를 성공 지표로 고정하지 않는다

원안 §10의 세 번 안팎 선택은 일반 사용 흐름의 목표일 수 있으나, 단위·대상 선수·회복 방식이 모호한 입력까지 세 번에 끝내면 잘못된 확인을 유도한다.

**수정:** 알려진 형식은 짧게, 모호한 항목은 필요한 부분만 확인한다. 성공 기준은 클릭 횟수가 아니라 결과 이해·올바른 수정·다음 행동의 명확성이다. 뒤로 가기와 수정 시 기존 입력·선택·스크롤을 유지한다.

### C. 모든 가치를 한 화면에 몰아넣지 않는다

가져오기·해설·비교·개인 추천·공유는 서로 다른 사용 목적이다. 홈에 기능 다섯 개를 같은 무게로 추가하면 다시 어려운 앱이 된다.

**수정:** 기존 일지·계획·분석 흐름 안에서 관련 행동을 제공한다. 하나의 기록에서는 `이번 훈련 보기`, 기존 계획에서는 `방법과 이유`, 분석에서는 `이전 훈련과 비교`처럼 현재 대상이 명확한 진입을 둔다. 별도 거대 분석 포털이나 새 하단 탭은 초기 필수 조건이 아니다.

### D. 비율보다 분모와 비교 조건을 먼저 정의한다

“8주 중 4주 기록”은 실제 운동의 절반을 알고 있다는 뜻이 아니다. “파일 10개 중 8개를 읽음”은 파일 처리 범위이며 선수 훈련 전체의 80%가 아니다.

**수정:** 파일 처리 범위, 분석에 포함된 기록 수, 지표별 표본 수를 분리한다. 실제 전체 훈련의 분모를 모르면 자료 완전성 퍼센트를 만들지 않는다. 시간·거리·RPE 비교에 같은 표본 수를 재사용하지 않는다.

### E. 추천의 다양성을 효과보다 앞세우지 않는다

기존 승인 방향은 같은 목적의 실제로 다른 방법을 선택할 수 있게 하는 것이다. 매번 새로운 훈련이 나오면 더 개인화된 것처럼 보일 수 있지만, 같은 훈련을 반복해 비교할 기회를 잃을 수 있다.

**수정:** `같은 방법으로 비교`, `다른 구성 살펴보기`를 선택지로 남긴다. 순위 변화는 사용자가 바꾼 조건과 채택된 규칙으로 설명한다. 이름·반복 수만 바꾼 가짜 다양성이나 임의의 강도 상승은 허용하지 않는다.

### F. 분석 자료가 늘어나는 것과 가치가 늘어나는 것을 구분한다

많은 그래프를 제공하면 유료 가치가 생긴다는 가정은 검증되지 않았다. 사용자는 이미 워치 앱에서 거리·페이스를 볼 수 있다.

**수정:** 단순 합계의 재현보다 **받은 훈련의 해석**, **계획과 실제 차이**, **회복 조건까지 포함한 과거 비교**, **선택 이유가 보이는 후보**를 핵심 가치 가설로 둔다. 실제 차별화 여부는 사용자 검증이 필요하다.

### G. AI 비용 절감만으로 운영비를 판단하지 않는다

외부 AI 추론을 없애도 공급자 규격 변경, 파일 읽기 실패 지원, 설명 콘텐츠 검토, 버전 변경, 삭제 후 재계산, 저장 비용은 남는다.

**수정:** 비용을 `연결 유지 + 자료 교정 지원 + 계산·보관 + 콘텐츠 검토 + 운영 대응`으로 나눠 추적한다. 범용 파일 수용 약속을 늦추고 자주 쓰는 형식부터 확대한다. 이번 검토로 비용 절감률이나 매출을 숫자로 단정하지 않는다.

### H. 직접 입력과 정확한 데이터를 같은 말로 사용하지 않는다

현재 출처 경로에서 `EXPLICIT`이 분석에 사용되는 것은 운영 허용 규칙이다. 사람이 적은 값이 언제나 워치 값보다 정확하다는 과학적 판정이 아니다. 수동 입력에도 단위 착오·오기입·다른 선수 자료가 있을 수 있다.

**수정:** 출처 방식, 값의 품질 검사, 사용 권한, 분석 적용 조건을 분리한다. 데이터가 직접 입력됐다는 사실만으로 모든 후속 분석에 적합하다고 설명하지 않는다. 반대로 외부 데이터도 승인된 품질·의미·사용 조건을 충족하면 정당한 분석 입력이 될 수 있어야 한다.

### I. 과거 자료 추가를 최근 훈련 증가로 설명하지 않는다

과거 파일을 한꺼번에 가져오거나 새 출처가 분석에 채택되면 같은 기간의 합계가 갑자기 달라질 수 있다. 실제 운동을 더 한 것이 아니라 알고 있는 기록의 범위가 바뀐 것이다.

**수정:** 보고서에는 관측 기간과 계산 기준 시점을 구분한다. 새 기록 반영·수정·제외로 달라진 수치와 실제 다른 기간의 변화 비교를 분리한다. 채택 정책 변경으로 과거 자료가 포함되면 갱신 이유를 짧게 알린다. 그 변화만으로 능력 향상·훈련 증량을 권고하지 않는다.

### J. 데이터 품질 상태와 안전 상태를 합치지 않는다

거리의 단위나 랩 의미를 모르는 것과 선수의 안전 신호가 불명확한 것은 같은 종류의 불확실성이 아니다.

**수정:** 품질이 낮은 항목은 관련 계산을 제외하거나 확인 요청한다. 그것만으로 D9 판정을 새로 만들거나 변경하지 않는다. 반대로 좋은 거리·심박 자료가 들어왔다고 기존 D9 상태를 해제하지 않는다. 계획 적용과 설명 열람의 권한도 구분한다.

## 5. 구현 선택지 비교

| 선택지 | 얻는 것 | 잃거나 부담지는 것 | 판단 |
|---|---|---|---|
| 외부 AI로 먼저 범용 해석 | 다양한 비정형 입력 처리의 가능성 | 현재 사용자 방향과 개인정보 경계에 맞지 않음. 수치·원문 신뢰 검증은 여전히 필요 | 현재 우선안에서 제외 |

| 모든 자료를 위한 대형 통합 기반부터 구축 | 장기 확장 범위가 넓음 | 사용자에게 보이는 가치가 늦어지고 처리 형식이 곱해짐 | 초기 범위로 부적합 |

평가는 설계상의 장단점 비교이며 실측 비용·실사용 만족도 순위가 아니다. 로컬 LLM 제작은 권장안의 필수 선행 작업으로 두지 않는다.

| 자료가 없는 첫 사용자 | 자신의 기록과 분명히 구분된 예시 또는 직접 계획 진입 | 하고 싶은 작업 선택 | 가짜 개인 점수·분석 |
| 전문가 | 동일 결과의 구간 수치·근거·예외 상세 | 상세 펼치기·표로 비교 | 별도 선수 모드에만 필수 방법 숨기기 |

기본 화면은 `무엇을 했나/할 것인가 → 무엇이 달랐나 → 다음에 확인하거나 선택할 것`의 순서다. 경고와 저장 상태는 눈에 보이고, 긴 계산 설명·출처 목록은 펼쳐 본다. 근거를 숨겨 불편하게 만들지 않도록 도움말 이름은 내용을 설명한다.

기존 디자인 표준의 종이·잉크·Pretendard·토큰·44px 조작 영역을 유지한다. 일반 UI 검색 도구의 어두운 대시보드·기술 폰트·마케팅 퍼널 추천은 이 프로젝트에 채택하지 않는다. 단계적 설명, 오류 복구, 줄인 모션과 접근성 점검만 보조 관점으로 활용했다.

## 7. 개발 전후에 확인할 성공 기준

다음은 제안하는 평가 항목이며 실측 결과나 승인된 수치 목표가 아니다.

- **첫 가치 도달:** 지원되는 자료로 사용자가 의미 있는 해설·비교 중 하나에 도달하는가.
- **이해:** 계획 수치와 실제 수행값, 개인 참고 페이스와 수행 보장을 구분하는가.
- **교정 부담:** 불명확한 항목만 묻는가. 알려진 값까지 재입력하게 하지 않는가.
- **데이터 신뢰:** 동일 입력·정책 버전에서 결과가 재현되고, 수정·삭제 후 낡은 결과가 현재처럼 남지 않는가.
- **반복 사용:** 새 기록이 들어왔을 때 이전과 비교할 이유가 생기는가. 단순 출석이나 거리 보상으로 유도하지 않는가.
- **설명 품질:** 실제 구성의 차이를 설명하는가. 모든 훈련에 같은 문장을 붙이지 않는가.
- **운영 가능성:** 지원하지 않는 파일을 만났을 때 사용자가 다음 행동을 알 수 있고 담당자가 비밀 원문을 받지 않고도 처리 범위를 파악할 수 있는가.

이벤트 수집을 도입한다면 업로드 원문·개인 기록값·건강 정보가 아니라 최소한의 기능 성공/오류 유형부터 검토한다. 텔레메트리 추가도 이번 문서만으로 승인하지 않는다.

## 8. 출시 단위 제안

| 단위 | 사용자 결과 | 선행 조건 | 이번에 포함하지 않을 것 |
|---|---|---|---|
| A | 기존 계획·적격 기록의 해설과 비교 | 현행 설명·계산·출처 경로 및 화면 복귀 검증 | 외부 자료 전면 개방 |
| B | 한 가지 채택된 외부 입력의 수신부터 결과까지 | 해당 필드 사용 규칙, 단위·중복·정정·삭제·계정 경계 | 모든 워치·임의 엑셀 동시 지원 |
| C | 실제 반복 기록을 가진 세션 비교 | 랩 의미·운동/경과 시간·회복 연결의 정확한 규칙 | 센서값만으로 생리학적 능력 판정 |
| D | 분석에 사용한 적격 근거가 드러나는 다음 후보 | 정확한 후보·템플릿·공식·안전/증감 조건 | 자동 증량·무제한 조정 |

A와 B의 기반 검토는 병행할 수 있다. B의 제공자 준비 때문에 A를 일괄 보류하지 않는다. 각 단위는 화면 버튼 추가가 아니라 입력·계산·설명·저장/갱신·실제 화면 검수까지 하나의 기능으로 끝낸다.

**반대 방향의 낭비도 막는다:** A에는 이미 구현된 코드가 많다. 먼저 기존 사용자 경로를 확인하고, 이미 동작하는 해설·비교를 다시 만들지 않는다. A가 종료 조건을 이미 충족하면 완료로 확인하고 B에 개발 자원을 집중한다. A를 먼저 본다는 이유로 워치 전용 사용자에게 필요한 B를 기약 없이 미루는 것은 권장안이 아니다.

초기 연결 단위 B는 한 공급자 또는 한 명확한 파일 형식, 최소 필드, 한 보고서로 제한한다. 새로운 통합 플랫폼·영구 보고서 저장소·모든 건강 지표를 동시에 도입하지 않는다. 공통 입력/상태 모델을 정하는 작은 합의 후 독립 범위로 나눈다.

## 10. 독립 검토 통합

### 10.1 Sol 1차 검토의 수용과 재검토

[Sol 제품·UX 검토](./PROGRAMMED_ANALYSIS_SOL_PRODUCT_UX_REVIEW_2026-09-17.md)는 조건부 진행 의견을 냈다. 주 검토자는 다음 인용을 직접 다시 열어 대조했다.

- `SessionExplanation.tsx:23`: 기존 상세 탭은 `방법 / 이유·근거 / 주기·기록`이다. 새 이름의 별도 상세 체계로 중복시키지 않는다.
- `ImportStages.tsx:182-190`: 가져온 숫자는 주간 통계·추이·계획에 들어가지 않는다는 소스 문구가 있다. 수신·저장 성공을 분석 완료로 안내해서는 안 된다.
- `product-features.ts:13-23`: 안전 기본값은 공개 배포 설정의 증거가 아니다. `EasyFaq.tsx:75-76`의 연령 안내도 현행 법률 결론이나 모든 배포의 실제 정책을 독립 입증하지 않는다.

핵심 수용 사항은 기존 화면 재사용, 데이터 없는 첫 가치, 허용 범위 내 다음 행동, 저장 상태와 분석 상태 구분, 차트별 읽기 방식이다.

다음 항목은 그대로 채택하지 않고 2차 반론 검토를 요청했다.

1. 구현 순서·정보구조 문제를 P0로 부른 것은 실제 운영 치명 결함과 혼동될 수 있다. 설계 보완 우선순위로 재분류한다.
2. 날짜·AM/PM·계획 ID·원자료 ID를 묶어 기본키로 삼는 제안은 정정과 계획 없는 운동에 약하다. 불변 정체성과 변경 가능한 표시 속성을 분리하는 대안을 검토한다.
3. 외부 연결을 계속 후순위로 미루지 않는다. 기존 자료 경로와 첫 외부 자료 완결 경로를 분리하되 둘 다 결과까지 끝내야 한다.

주 검토자의 추가 제한: 모든 카드에 다음 행동 버튼을 붙이거나 정상 상태 여섯 가지를 늘어놓는 방식은 채택하지 않는다. 결과 단위에서 의미 있는 다음 행동 하나를 우선하고, 정상 상태는 압축하며 오류·충돌·전송 대기 등 행동이 필요한 상태는 보인다.

Sol 2차 검토에서 설계 P1 재분류, 불변 운동 정체성과 출처별 관측/수정본 분리, 공개 배포·법률 주장 제한, A/B 경로 병행의 범위 제한을 반영했다. 해당 검토자는 정적 검토를 마치고 종료했다.

### 10.2 Terra 1차 검토의 수용과 재검토

[Terra 기술·스펙 검토](./PROGRAMMED_ANALYSIS_TERRA_SPEC_ARCHITECTURE_REVIEW_2026-09-17.md)는 기존 코어 재사용에 동의하면서, 출력 이전에 데이터 의미와 실제 운영 범위를 구분해야 한다고 지적했다.

주 검토자는 `import/activity-file.ts:7-16,92-116,130-167`을 다시 열었다. 단일 `durationMin`으로 내보내지만 TCX는 Lap의 `TotalTimeSeconds`를 합산하고 GPX는 첫 시각과 마지막 시각의 차이를 사용한다. 또 이 TCX 경로는 개별 랩을 합산하므로 그 결과만으로 반복별 실제 수행 비교를 할 수 없다. 이는 소스에서 확인한 표현 범위의 한계이며, 이번에 실제 파일을 실행해 피해를 재현한 결과는 아니다.

| 기술 쟁점 | 통합 방향 |
|---|---|
| 수신·확인·분석 적격·처방 적격 | 독립 상태로 보존. 사용자 확인은 출처 변경이 아님 |
| 서로 다른 시간 의미 | 값·단위·원천 필드·시간 의미를 보존. 알 수 없으면 미확정 |
| 계획과 실제 반복 비교 | 정확한 연결 및 실제 구간 자료가 있을 때만 계산. 날짜 일치는 자동 연결 근거가 아님 |
| A/B 계획과 MAIN별 방법 | 다른 개념으로 명시. 전체 후보가 둘이라고 MAIN별 독립 방법 둘이 모두 운영된다고 주장하지 않음 |
| 설명과 계획 버전 | 현재 영수증·내용 지문 재사용. 과거 이유를 최신 설명으로 덮어쓰지 않음 |
| 분석 보고서와 공유본 | 최신 화면 재계산, 역사적 처방 설명, 고정 내보내기를 서로 구분 |
| 검토된 설명 | 편집 검토·정확한 템플릿 채택·독립 과학 검토를 같은 말로 포장하지 않음 |
| 짧은 표기 입력 | 기존 지원 문법과 구조화 확인을 활용. 회복 방식이 없으면 임의 보완하지 않음 |

Terra가 대조한 현행 범위에서는 A/B의 주요 구성과 쉬운 훈련 시간 차이, 독립 방법·다중 배치의 별도 권한을 구분한다. 이 관찰은 사용자 제품 목표인 MAIN별 실제로 다른 방법 제공을 폐기하자는 뜻이 아니다. **승인된 목표, 코드 기반, 운영 채택, 공개 배포를 각각 남겨야 한다**는 뜻이다. 원격·공개 상태는 이번에 확인하지 않았다.

Terra 2차 검토에서 F-01은 현재 장애를 재현한 P0가 아닌 채택 전 설계 P1로 교정했다. 시간은 여러 필드를 일괄 도입하기보다 값·의미·원천 필드를 보존하는 최소 관측 모델을 제안했다. TCX의 `TotalTimeSeconds`가 이동 시간 또는 실제 본운동 시간이라는 단정은 하지 않는다. 최종 제품 순서도 기존 자료 A만으로 끝내지 않고, 한 외부 출처·최소 필드·한 기술 보고서 B를 병행 준비하는 방향으로 재판정했다. 이는 새 권한 채택이 아니라 후속 설계 범위 제안이다.

### 10.3 Luna 1차 검토의 수용과 재검토

[Luna 실패 시나리오 검토](./PROGRAMMED_ANALYSIS_LUNA_FAILURE_SCENARIO_REVIEW_2026-09-17.md)는 중복, 시간·단위 의미, 부분 저장, 정정·삭제, 공유와 운영 경고를 집중 검토했다.

주 검토자는 다음 두 지점을 직접 다시 열었다.

- `structured-activity-file.ts:18-20,30-44`는 문자열 숫자에 `Number.parseFloat`를 사용한다. 숫자 접두사 뒤의 단위가 조용히 무시될 수 있는 정적 경로다. 이 문제는 합성 실행으로 따로 확인할 가치가 높다. 이번에는 실행하지 않았다.
- `import/account-import.ts:79-87`에는 파일 형식·행 위치·활동 내용으로 계정 기록 ID를 만들고 동일 사본을 재사용하는 코드가 이미 있다. 따라서 멱등성 자체가 전혀 없다는 해석은 기각한다. 같은 내용·순서의 재수입, 행 순서 변경, 같은 파일 안의 반복 행, 여러 공급자 자료는 각각 별도 사례다.

재검토 요청 사항:

1. 실제 존재하지 않는 일부 인용 경로를 교정하고 파일 존재를 검사한다.
2. 자료형이 일반적인 기능을 표현하지 않는다는 사실을 곧바로 현재 서비스의 재현된 결함이라고 부르지 않는다.
3. 수동으로 올린 파일은 공급자 원본의 삭제 사실을 자동으로 알 수 없다. 향후 연동의 삭제·정정·철회 정책 요구와 현재 약속된 기능의 결함을 구분한다.
4. 동의 철회가 과거 보관 자료를 즉시 모두 삭제한다는 정책은 이 검토에서 만들지 않는다. 접근 중단·동기화 중단·분석 사용 중단·자료 삭제의 의미를 구분한다.
5. 알려진 형식의 명확한 단위까지 매번 묻지 않는다. 접미사·혼합 단위·불명확한 열 등 모호한 부분만 확인한다.
6. local-first를 계정 정본의 대안으로 채택하지 않는다. 로컬 파싱·미전송 초안 보호와 최종 계정 보관을 구분한다. 원본 파일 통째 보관과 비밀 메모 공유도 이 검토로 허용하지 않는다.

운영 측면에서는 원문을 고객지원에 보내게 하기보다 오류 원인과 처리 상태로 문의를 해결하는 방향을 수용한다. 다만 모든 원인 코드와 권한을 사용자 화면에 한꺼번에 나열하는 제안은 채택하지 않는다. 현재 행동에 필요한 대표 문제와 다음 조치 하나를 먼저 보여준다.

Luna 2차 교정본에서 잘못된 인용 경로, 재수입 안정 ID 누락, 수동 파일과 공급자 삭제의 혼동, 단위 재질문 범위, 원문 비공개 경계, 로컬 처리와 계정 정본의 구분을 수정했다. 이 보고서의 `확인된 결함/결손`은 코드상 관찰한 구조 또는 표현 범위의 부족을 뜻하며, 실제 서비스 피해를 재현했다는 뜻으로 채택하지 않는다. 특히 중복·공유 유출·탭 종료 후 소실·모바일 정지는 이번 정적 검토에서 실제로 재현하지 않았다. 파일 해시·행 위치는 보조 추적 자료이지 출처 인증이나 실제 동일 운동의 보편적 증명도 아니다.

## 11. 스무 가지 관점의 통합 결론

아래는 실제 사용자 조사가 아니라 세 검토자가 나눠 수행한 가상 관점이다. 같은 결론이 여러 행에 나타나더라도 독립적인 사용자 검증 표본 수로 합산하지 않는다.

| 관점 | 가장 중요한 요구 | 개선 방향 |
|---|---|---|
| 첫 방문·무기록 사용자 | 자료가 없다는 이유로 빈 화면만 보지 않기 | 기존 예시·받은 훈련 해설 또는 계획 진입. 가짜 개인 점수는 없음 |
| 워치만 쓰는 바쁜 러너 | 다시 일지를 다 쓰지 않기 | 채택된 외부 기록은 실제 분석까지. 필요한 주관값만 선택 입력 |
| 상세 일지 사용자 | 쌓인 기록에서 의미 찾기 | 회복·구성 조건을 포함한 이전 수행 비교, 비밀 메모 분리 |
| 혼자 훈련하는 청소년 | 쉬운 설명과 자기 선택 | 기존 훈련 범위 유지. 계정·공유·안전 조건은 별도 표시 |
| 하루 두 번 훈련하는 선수 | 두 세션을 섞지 않기 | 불변 운동 정체성, 가변 날짜·슬롯, 정확한 계획 연결 |
| 여러 선수를 보는 코치 | 최신 자료와 검토 이유 구분 | 초기에는 선수 주도 단일 자료. 다중 선수 권한·목록은 별도 범위 |
| 스포츠 분석 연구자 | 관측과 효과 추론 분리 | 기록된 목적·실제 측정·일반 기전의 지위를 구분 |
| 처방 코치 | 실제 다른 방법과 부하 맥락 | 전체 A/B와 MAIN별 방법 구분, 반복 선택과 다양성 모두 유지 |
| 데이터 엔지니어 | 입력 의미 보존 | 단위·시간 의미·출처·수정본을 계산 전에 보존 |
| 스키마 설계자 | 계획과 실제를 같은 값으로 쓰지 않기 | 관측·계획·완료 표시·추정값의 별도 모델 |
| 출처·버전 감사자 | 과거 근거를 현재 문장으로 위조하지 않기 | 기존 설명 영수증 재사용, 일반 분석은 기준 시점 명시 |
| 유지보수 담당자 | 같은 엔진 두 벌 만들지 않기 | 기존 파서·합계·설명·화면 재사용, 부족한 연결만 확장 |
| 여러 서비스에서 가져오는 선수 | 중복과 실제 두 번 운동 구분 | 확실한 동일 사본과 유사 후보를 분리, 조용한 자동 병합 금지 |
| 완료 표시를 먼저 누른 사용자 | 자신의 체크와 실제 수행 구분 | 체크만으로 측정·완료율·효과를 만들지 않음 |
| 오래된 엑셀 보유자 | 잘못 읽힌 단위를 알아차리기 | 알려진 형식 재사용, 모호한 단위만 변환 전후 확인 |
| 정정·삭제·철회 사용자 | 무엇이 바뀌고 무엇이 남는지 알기 | 원본 수정과 결과 갱신, 공유본 한계, 권한/삭제 상태 분리 |
| 저사양·불안정 네트워크 사용자 | 진행 중 기록을 잃지 않기 | 파일/행 처리 예산, 부분 저장 상태, 재시도·계정 확인 구분 |
| 개인정보 보호를 원하는 학부모 | 동의한 범위만 공유 | 새 보고서도 대상별 필드 제한 적용. 관계 연결이 전체 동의는 아님 |
| 운영 담당자 | 비밀 원문 없이 문의 해결 | 안전한 오류 분류·상태 확인·대표 조치, 경고 묶기 |
| 조작 파일 입력자 관점 | 신뢰 가장과 처리량 공격 차단 | 이름·확장자를 인증으로 사용하지 않음. 문법·좌표·규모 검증 |

## 12. 의견이 갈린 부분의 최종 통합 원칙

| 쟁점 | 한쪽의 이점 | 반대쪽의 위험 | 통합 권고 |
|---|---|---|---|
| 해설부터 vs 외부 자료부터 | 기존 자료는 빨리 가치 제공 | 워치 사용자가 계속 보관만 하게 될 수 있음 | 기존 흐름의 빈틈만 A에서 보완, 제한된 외부 경로 B도 결과까지 완성 |
| 많은 확인 vs 빠른 완료 | 잘못 읽힌 값의 피해 감소 | 경고 피로와 이탈 | 결정에 영향을 주는 모호함만 질문. 알려진 규칙은 재사용 |
| 풍부한 근거 vs 간결한 화면 | 판단 이유를 충분히 확인 | 사용자에게 관리자 화면처럼 보임 | 수행·비교가 앞, 긴 근거는 펼침. 오류는 숨기지 않음 |
| 보수적 요약 vs 코칭 가치 | 근거 없는 진단 예방 | 단순 합계 앱에 머묾 | 관측 사실 다음에 허용된 비교·확인·후보 선택 연결 |
| 최신 분석 vs 과거 이유 보존 | 정정 반영과 당시 선택 이해 | 최신 계산이 과거 근거를 덮어씀 | 분석 재계산과 처방 설명의 역사 보존을 별도 처리 |
| 로컬 처리 vs 온라인 보관 | 개인정보 최소 처리·오프라인 회복 | 기기에만 남아 분실되는 제품으로 회귀 | 로컬은 파싱/초안 보호, 승인된 계정 경로가 보관 기준 |
| 정밀 공유 vs 철회 가능성 | 코치와 풍부한 자료 소통 | 내보낸 이미지/PDF 회수가 불가능 | 원격 링크 권한과 이미 내려받은 사본의 한계를 구분. 초기 영구 공유는 후속 |

모델들의 의견은 투표로 확정하지 않는다. 코드로 확인한 사실은 남기고, 과장된 심각도·존재하지 않는 경로·불필요한 제한은 교정한다. 새 스펙 채택과 개인 처방 수치 변경 권한은 이번 검토에서 생기지 않는다.

## 13. 분석의 깊이를 잃지 않기 위한 기준

외부 AI를 사용하지 않아도 분석이 깊을 수 있다. 다만 아래 네 종류의 답을 같은 확신으로 말하지 않는다.

| 답의 종류 | 제공할 수 있는 내용 | 필요한 조건 | 넘어가면 안 되는 주장 |
|---|---|---|---|
| 관측 사실 | 기록된 거리·시간·반복·회복·RPE | 의미가 확인된 입력과 계산 | 기록 없는 운동을 0으로 확정 |
| 비교 | 같은 방법의 이전 수행, 계획과 실제 차이 | 같은 시간 의미·구성·연결 관계, 비교 조건 표시 | 다른 회복·코스·환경의 결과를 곧바로 능력 변화로 해석 |
| 해석 | 검토된 훈련 목적과 구성 이유, 관찰된 경향 | 기존 설명 버전과 실제 사용한 자료 | 에너지 분류 횟수를 생리학적 능력이나 에너지 기여율로 변환 |
| 다음 선택 | 같은 방법 반복 또는 승인된 다른 구성·참고 페이스 | 적용 대상·필요 근거·기존 조정 권한 충족 | 파일이 늘거나 출석이 쌓였다는 이유만으로 강도·양·빈도 증가 |

**에너지 시스템 누적은 특히 주의한다.** 목적별 수행 횟수, 거리, 시간은 각각 다른 관측이다. 8초 반복과 40분 지속주를 한 회씩 했다고 노출량이 같지 않으며, 두 수치를 공통 부하로 환산할 근거가 없으면 별도로 표시한다. 분류가 없으면 MIX로 임의 배정하지 않고 미분류로 남긴다. 계획 목적, 직접 선택한 목적, 실제 측정된 값도 서로 구분한다. 이 검토는 새 부하 공식을 채택하지 않는다.

개인별 해석은 `이번 비교에서 사용한 것 / 없는 것 / 비교에서 제외한 것`을 추적한다. 화면에는 현재 결론을 바꿀 수 있는 제한만 짧게 보여 주고 전체 근거는 펼친다. 실제 기온·코스·휴식 조건이 없을 때 이를 자동으로 보정했다고 말하지 않는다.

## 14. 프로그램 중심 전략의 단점과 대응

| 단점 | 그대로 두면 생기는 문제 | 대응과 남는 비용 |
|---|---|---|
| 지원 형식 밖의 자료에 약함 | 어떤 자료든 가져오라는 약속과 충돌 | 지원 형식을 공개하고 미지원 자료는 확인 경로로 보냄. 모든 파일 자동 이해는 약속하지 않음 |
| 규칙도 틀릴 수 있음 | 같은 오류를 매우 일관되게 반복 | 단위·시간·중복·연결 결함 주입 시험. 결정적 계산을 과학적 타당성으로 포장하지 않음 |
| 설명 콘텐츠가 빠르게 늘어남 | 종목×목적×구성×대상별 복사 문장과 오래된 설명 | 공통 정의·템플릿 설명·배치 이유의 기존 층 분리와 버전 참조 재사용. 검토 작업은 계속 필요 |
| 예외 확인이 많아질 수 있음 | 입력을 줄이려는 제품 방향과 충돌 | 알려진 형식·확정 단위는 재사용하고 결과를 바꾸는 모호함만 질문 |
| 설명이 반복적으로 느껴질 수 있음 | 매일 들어와도 같은 일반론 | 새 기록과 이전 기록의 실제 차이부터 보여 줌. 새로움만을 위한 무작위 처방은 하지 않음 |
| 수치가 권위처럼 보임 | 계산 가능하다는 이유로 회복·체력·효과를 과신 | 관측·비교·해석·선택을 구분하고 모르는 항목은 모른다고 표시 |
| 외부 서비스 변경 비용 | AI 사용료는 줄어도 연동 운영비가 증가 | 출처별 매핑과 계약 시험, 실패 원인 집계. 비용 절감률은 운영 실측 후 판단 |

이 방향의 장점은 설명 가능성·재현성·개인정보 최소 처리·기존 코어 재사용이다. 그러나 **외부 AI를 쓰지 않는다는 사실만으로 보안·정확성·개인화가 완성되지는 않는다.** 브라우저 코드, 온라인 보관, 공유와 접근 권한은 계속 별도 책임이다.

## 15. 후속 개발의 우선순위와 종료 조건

아래 표는 차후 작업을 위한 권고 순서다. 이번 검토에서는 작업 지시 발행·개발·배포를 수행하지 않는다. 이미 승인된 제품 방향을 다시 묻기 위한 표도 아니다. 구현 시 최신 로컬 계약과 진행 중 작업을 대조해 중복을 제거해야 한다.

| 순서 | 작업 범위 | 완료를 판단할 결과 | 시작 전에 막을 것 |
|---|---|---|---|
| 0 | 현재 기능·스펙·실행 상태 대조 | 이미 되는 경로, 연결만 부족한 경로, 신규 범위의 목록 | 문서 목표를 실사용 완료로 간주하거나 이미 있는 기능 재개발 |
| 1 | 입력 의미의 최소 공통 계약 | 단위·시간 의미·정체성·수정본·계획/실제·허용 용도의 표 | 범용 데이터 플랫폼과 새 병렬 스키마부터 만들기 |
| 2A | 기존 계획·적격 기록의 해설/비교 빈틈 | 한 사용자가 현재 화면에서 방법→이유→자신의 이전 수행을 잃지 않고 이동 | 기존 기능이 충족하면 재개발하지 않고 확인으로 종료 |
| 2B | 한 외부 출처의 실제 분석 경로 | 가져오기→확인→계정 보관 확인→허용된 한 보고서까지 완료 | 단순 저장 성공을 분석 완료라고 부르기, 승인 전 일반 통계/처방으로 자동 유입 |
| 3 | 실제 구간 비교 | 반복·세트·회복의 의미가 맞는 자료만 계획과 나란히 표시 | 총합만으로 실제 인터벌 구성을 복원 |
| 4 | 제한된 개인 선택 연결 | 어떤 자료와 규칙으로 후보가 남았는지 확인하고 같은 방법/다른 방법 선택 | 다양성을 이유로 자동 증량, 불명확한 기록으로 개인 능력 진단 |

2A와 2B는 공통 의미 계약을 합의한 뒤 서로 다른 파일·역할 범위로 병행할 수 있다. 첫 외부 출처는 이미 검토된 계약, 실제 수신 가능성, 운동 정체성·시간 의미·정정 지원, 사용자 수요를 기준으로 정한다. 이 보고서는 COROS나 특정 공급자의 현재 운영 연결이 완료됐다고 주장하지 않는다.

### 공개 전 확인할 대표 반례

1. `5 miles`를 `5km`로 조용히 읽지 않는다. 알려진 `distanceKm` 형식의 순수 숫자에는 불필요한 재확인을 요구하지 않는다.
2. 같은 사본 재가져오기, 행 순서 변경, 실제 오전·오후 두 운동, 여러 공급자 중복을 별도 시험한다.
3. 경과 시간·타이머 시간·이동 시간이 같은 평균 페이스로 위장되지 않는다.
4. 완료 버튼만 누른 기록에 실제 랩·회복·거리와 능력 향상이 생성되지 않는다.
5. 일부 저장 실패와 계정 저장 완료를 구분하고 다시 시도해도 성공한 사본을 중복 추가하지 않는다.
6. 과거 기록 추가·정정·삭제·분석 채택 변경 뒤 결과가 갱신되며, 과거 처방의 설명은 소급 발명되지 않는다.
7. 비밀 메모·민감 원문·인증정보가 설명·공유·고객지원 자료에 섞이지 않는다.
8. 작은 화면·200% 글자·키보드·줄인 모션에서 다음 행동과 오류가 가려지지 않고 뒤로 가면 맥락이 복원된다.

이 목록은 이번에 통과한 테스트 목록이 아니라 후속 구현의 검증 요구다.

## 16. 공식 기술 자료 보충 대조

주 검토자가 2026-09-17에 다음 일차 자료를 추가 대조했다. 공개 문서만 조회했으며 사용자나 선수의 기록은 전송하지 않았다.

- [ECMAScript parseFloat 규정](https://tc39.es/ecma262/multipage/global-object.html#sec-parsefloat-string): 숫자로 해석 가능한 앞부분만 읽고 뒤의 문자를 무시할 수 있다고 명시한다. 따라서 현행 문자열 입력 경로에서 단위 접미사를 검증해야 한다는 지적은 언어 동작과도 부합한다. 앱 저장까지의 재현 시험을 대체하지는 않는다.
- [Garmin FIT Course의 Lap 필드 정의](https://developer.garmin.com/fit/file-types/course/): `total_elapsed_time`은 일시정지를 포함하고 `total_timer_time`은 제외한다고 구분한다. 같은 초 단위 값도 의미를 합치면 안 된다는 설계 근거다. 이 FIT 정의로 모든 TCX 공급자의 `TotalTimeSeconds` 의미를 대신 판정하지 않는다.

이번 검토는 새로운 운동 효과 논문 체계 검토가 아니다. 과학적 효과·대상별 적용 범위는 기존 출처와 채택 계약을 유지하며, 새 처방이나 공식 확대 시 별도 근거 대조가 필요하다.

- 변경하지 않음: 앱 코드, 운영 스펙·채택 상태, 개인정보 정책, 처방 수치, 실제 계정·선수 자료, Git 커밋·PR·배포.
- 실행하지 않음: 런타임 테스트·실제 사용자 조사·현재 공개 서비스 및 원격 Git 최신 상태 검증. 문서 구조 확인은 실행 테스트로 계산하지 않는다.
- 종료: 하위 검토자 세 명 모두 작업 종료. 별도 개발이나 백그라운드 작업은 진행 중이 아니다.
- 문서 확인: 검토 보고서 4개와 원안의 제목·단일 최종 표식·후행 내용 및 상대 파일 링크를 확인했다. 검토 보고서의 `app/src`·`specs` 인용 파일 경로도 존재를 확인했다. 원안의 추가 부록을 제외한 본문을 복원한 SHA-256이 검토 전 값과 일치한다. 대조 체크아웃은 위 커밋을 유지하고 변경 파일이 없다. 이는 구조·보존 확인이며 인용한 모든 주장이나 앱 실행을 자동 검증한 결과가 아니다.
