- 이번 산출물은 추가 발견과 수정 우선순위다. 아래 제안은 아직 새로 구현하거나 배포하지 않았다.
- 앞선 배경·계획 문구 수정과 기존 미커밋 변경은 보존했다. 계산, 처방, 계정 저장에는 변경을 가하지 않았다.
- 작업 위치: `TRAINORACLE-multi-event-pace-release-20261002`, `codex/multi-event-pace-release-20261002`.
- 실제 화면 확인: 로컬 375 x 812에서 홈, 오라클 훈련 탭, 페이스 도구, 일지 달력, 기록 선택·빠른 기록. 나머지는 소스 확인이다.
- 기존 가져온 기록이 있는 상태와 합성 입력을 사용했다. 이번에는 실제 일지 저장, 계획 활성화, 경기 기록 저장, 운영 계정 저장을 수행하지 않았다. 임시 입력 초안의 자동 보존과 실제 기록 저장은 구분한다.
- 빠른 기록의 미저장 입력 확인창에서 브라우저 제어가 멈췄다. 이후 화면 재현을 완료했다고 표현하지 않는다.
- 전체 상태 조합, 320px, 200% 글자 확대, 키보드, 운영 로그인 저장, 실제 중학생 사용 검증은 이번 감사의 완료 범위가 아니다.

## 판단 기준

1. 처음에는 지금 필요한 질문 또는 행동이 먼저 보여야 한다.
2. 답한 질문은 선택값과 수정 진입점으로 줄일 수 있지만, 현재 답할 질문은 숨기지 않는다.
3. 글을 접어도 접힌 메뉴가 많으면 피로감은 남는다. 관련 기능을 이름이 분명한 묶음으로 정리한다.
4. 숫자·단위·처방 기준은 유지한다. 출처, 분석 제외, 저장 실패, 통증 확인을 미관 때문에 없애지 않는다.
5. 선은 경계를 한 번만 표시한다. 달력 칸, 표, 입력 테두리, 초점, 오류, 선택 표시까지 일괄 제거하지 않는다.
6. 빠른 경로와 자세한 경로의 차이는 입력 순서·깊이다. 가능한 운동 종류나 메모 유무로 잘못 설명하지 않는다.

## 특히 먼저 고칠 흐름

### 빠른 기록

- 현재: 결과 선택지 전체 + 시간대 질문 -> 강도 선택지 전체 + 강도 설명 + 통증 질문.
- 제안: 현재 질문 하나 + 짧은 진행 표시. 이전 답은 '운동 마침 · 오전'처럼 요약하고 수정할 수 있게 한다.
- 선택 즉시 다음 질문으로 갈 수 있는 경우 별도 '다음' 버튼을 추가하지 않는다.
- '모름', 메모 먼저 쓰기, 여러 운동, 부분 수행, 중단, 쉬거나 건너뜀을 삭제하지 않는다.
- 통증은 질문 자체를 숨기지 않는다. 숫자 선택이 끝난 다음 주 질문으로 보여준다.
- 돌아가기, 새로 열기, 저장 실패에서도 입력과 선택값을 보존해야 한다.
- 단계 수는 사용자가 느끼는 질문 흐름과 맞춘다. 내부 상태 수만으로 '1/3'을 설명하지 않는다.

### 오라클

- 기본 화면은 실제로 볼 수 있는 내 결과와 다음 행동을 우선한다.
- 예시, 가져온 자료, 직접 입력 자료의 자격을 구별한다. 일부 데이터가 있다는 이유로 모든 분석을 열지 않는다.
- 메뉴를 하나의 의미 없는 '더보기'에 몰아넣지 않는다. 각 묶음 이름으로 기능을 예상할 수 있어야 한다.
- 점수 근거, 분석 제외 수, 자료 없음·불명확 상태는 숫자 가까이 남긴다.
- '없어요'가 여러 영역에서 반복될 때에는 가능한 행동을 한 곳에서 안내한다. 다른 기능의 부족 자료까지 같다고 단정하지 않는다.

### 메모와 달력 상세

- 메모 정보량 대분류는 항상 즉시 선택 가능하게 유지한다. '쉬운 표현'과 '간단한 정보량'은 서로 다른 설정이다.
- 결과물 -> 표현·꾸미기 -> 복사·이미지 저장·공유의 우선순위로 재배치한다.
- 달력은 날짜·요일·선택 상태를 유지하고, 작은 칸에 모든 설명을 넣지 않는다.
- 날짜를 누르면 기록 요약부터 보여준다. 여러 일지는 선택한 하나를 확대하고 나머지는 찾을 수 있는 목록으로 유지한다.

## 문구 개선 예시

| 현재 | 제안 | 조건 |
| --- | --- | --- |
| 운동 결과와 몸 상태만 | 결과부터 짧게 | 운동·메모 입력도 가능하므로 '만' 제거 |
| 달리기·근력 등 여러 운동을 함께 | 운동별로 자세히 | 빠른 경로에서도 여러 운동을 받을 수 있음 |
| 계획 선호 3문항 시작 | 내 훈련 방식 알아보기 · 질문 3개 | 질문 내용과 결과명을 맞춘 뒤 채택 |
| 트랙·레인 | 트랙 안내 | 현재는 레인 계산이 아니라 안내만 제공 |
| 이번 프로그램의 목적 | 이 계획의 목적 | 구간 단위라면 '이 훈련의 목적' 사용 |
| 계산만으로 기록이나 계획은 바뀌지 않아요 | 계산 미리보기 | 계획 적용 기능이 연결된 문맥에서는 적용 전 상태를 별도 표시 |

문구 단축이 실제 값의 의미를 바꾸어서는 안 된다. 출처 종류, 시간의 범위, 운동·회복의 구분, 예상·실제의 구분을 먼저 확인한다.
