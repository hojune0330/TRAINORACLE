# Oracle Tools 독립 라이브 UX 검수

- 검수일: 2026-10-06 (Asia/Seoul)
- 대상: `https://hojune0330.github.io/TRAINORACLE/?app=1`
- 예상 source: `e83605b6`; 지정 체크아웃의 `HEAD`와 일치. 페이지 UI에서는 배포 SHA를 별도로 확인하지 못했으므로 배포 커밋의 독립 증명으로 해석하지 않음.
- 초점: 중학생이 버튼의 뜻과 다음 행동을 이해할 수 있는지.

## 실행 경계

서로 분리된 Playwright 제어 Edge/Chromium 비영속 게스트 컨텍스트에서 320px, 375px, 320px 폭으로 세 여정만 실행했다. 브라우저 요청은 `https://hojune0330.github.io/TRAINORACLE/` 하위 경로만 허용했다. 세 컨텍스트 모두 허용 경로 요청 7건, 차단 요청 0건, 브라우저 콘솔/페이지 오류 0건이었다.

실제 계정 로그인, 실제 친구 정보, 서버 저장, 제품 코드 수정은 없었다. `1500m 5:10`과 가상 친구 `1500m 6:00`만 격리 컨텍스트 안에서 사용했다. 10월 6일 첫 검수에서는 동의하지 않았고, 10월 7일 후속에서만 사용자가 승인한 합성 시나리오 체크 상태로 비교를 실행했다. 실제 사람의 동의로 간주하지 않았다. 브라우저는 앱 경로의 GET만 허용했고 다른 요청은 차단했다. 화면에 표시된 PubMed 근거 링크도 허용 경로 밖이므로 열지 않았다.

### 1번 세부 관찰

`계산 근거`에는 `구간 시간 = 경기 기록 초 × 구간 거리 ÷ 경기 거리` 공식과 `310초 × 400m ÷ 1500m = 82.66666666666667초`가 표시됐다. 반복 횟수와 휴식은 포함하지 않고, 짧은 구간을 같은 속도로 반복할 수 있다는 뜻이 아니며, 현재 기록과 목표를 구분한다는 주의 문구도 있었다. 설명 화면을 닫고 결과 화면으로 돌아오는 동작은 예상대로 됐다.

장점은 계산의 출처, 단위, 한계, 훈련 지시가 아니라는 점을 한 화면에서 설명한다는 것이다. 반면 중학생에게 긴 소수는 읽기 부담을 주고 결과 화면의 `1:22.7`과 비교할 때 불필요하게 다른 정밀도로 보인다. **표시 개선 의견:** 대표값을 `1:22.7 (82.7초)`처럼 우선 보여주고 정밀 원값은 펼쳐 보이게 한다. 이는 표시 계층만의 제안이며 계산값, 공식 또는 근거 계약을 바꾸자는 뜻이 아니다.

### 2번 세부 관찰

진입 경로와 보조 문구가 임시 기록 비교 목적을 잘 드러냈고, 입력의 수명과 저장 위치도 구체적으로 안내했다. 동의 체크 문구는 `친구가 이 기록의 풀이와 비교에 동의했어요.`였다. 2026-10-07 후속에서는 가상 기록 `1500m 5:10`/`6:00`만 사용하고 체크 상태도 테스트 시나리오로만 설정했다. 실제 친구의 동의로 간주하지 않았다.

미동의 상태에서 `우리 러닝 궁합 보기`를 누르면 화면을 이동하지 않고 `친구가 기록 풀이와 비교에 동의했는지 확인해 주세요.` 경고가 표시됐다. 합성 동의 체크 후에는 결과가 열려 두 기록의 차이 `50초`, 1km 평균 차이 `33.33초`를 보여줬다. 결과는 순위나 궁합 점수가 아니며, 재능·회복력·미래 기록을 입력만으로 알 수 없다고 설명했다. `풀이 근거`는 직접 입력한 종목·기록·달성일만 사용하고 일지·비밀 메모·친구 계정은 읽지 않으며 계획·일지에 자동 저장하거나 AI 서비스로 보내지 않는다고 밝혔다.

`이전 단계로`는 친구 기록 입력 화면으로 돌아가 `6:00`과 테스트용 체크 상태를 유지했다. `풀이 닫기` 후 더보기에서 다시 열자 첫 단계로 돌아와 이전 입력은 보이지 않았다. 닫기·재진입 초기화를 확인했다.

### 3번 세부 관찰

용어집은 검색, 분류, 자주 보는 용어와 각 용어의 짧은 설명을 제공하고, 항목에서 `쉬운 설명`과 `전문 설명`으로 더 깊게 들어갈 수 있었다. VO₂ 항목은 “최대산소섭취량을 측정했거나 매번 최대 노력으로 달리라는 뜻이 아니다”라고 오해를 제한하고, 짧고 강한 구간에서는 여러 에너지 경로가 함께 작동한다고 설명했다. 연구 근거 링크와 개인 대사를 측정하거나 의료 판단을 내리지 않는다는 문구도 보였다.

320px에서 주 콘텐츠의 세로 스크롤은 정상 동작했고 가로 넘침은 보이지 않았다. 용어 목록은 내부 주 영역 6,740px, 상세 화면은 2,645px 높이였고, 상세 화면에서 실제 휠 입력 후 스크롤 위치가 604px로 이동했다. `VO₂`, `ATP-PCr`, `인원질`, `해당과정`, `산화 대사`, `최대산소섭취량`, `대사 기여도`는 중학생에게 어려울 수 있으나, 쉬운 설명, 예시, 오해 방지 문구가 완충 역할을 했다. PubMed 원문 자체는 열지 않았으므로 출처 내용이나 최신성은 이번 검수 범위에서 확인하지 않았다.

## 확인된 문제와 제안

1. **홈 예시 펼침 행 키보드 재확인:** 첫 접근성 스냅샷에서는 `오라클 결과 예시 보기`가 `group` 텍스트로 나타났지만, 실제 Tab 이동으로 native `<summary>`에 포커스가 갔다. Enter로 펼쳐지고 Space로 닫혔다. 키보드 조작 장애는 재현되지 않아, 스냅샷의 역할 표기만으로 제품 결함으로 단정하지 않는다.
2. **계산 근거의 소수 표기:** 위의 `82.66666666666667초`는 계산 내용을 투명하게 보여주는 장점이 있지만, 대표 결과 `1:22.7`과 함께 놓이면 중학생에게 불필요한 정밀도와 표기 불일치를 만든다. 대표 반올림값 우선, 정밀 원값 펼침이 적절하다. 계산과 근거 계약은 변경하지 않는다.
3. **친구 동의 CTA의 상태 표현 및 문구:** 체크가 비어 있어도 CTA는 시각적으로 활성처럼 보이지만, 실제 클릭은 동의 안내 경고를 표시하고 진행을 막았다. 동의 우회는 관찰되지 않았다. 미체크 상태를 비활성화하거나 선행 동의를 안내하는 방안을 검토할 수 있다. `궁합`은 중학생에게 기록 비교보다 점수나 성향 판정처럼 들릴 수 있어 목적을 직접 말하는 문구가 더 명확할 수 있다.

## 선택자·환경 기록

샌드박스 초기에 발생한 `ERR_NAME_NOT_RESOLVED`는 사용자 승인 후 동일 URL 허용 필터 아래 재시도해 페이지 로드에 성공했으며 제품 결함으로 세지 않았다. 접근성 이름 없는 홈 행은 실제 접근성 트리 확인 후 표시 텍스트로 재시도해 동작을 확인했다. 용어집에서는 같은 표시 텍스트가 두 버튼에 매칭되는 선택자 모호성이 있어 실제 접근성 이름 `강한 유산소 반복VO₂`로 다시 선택했다. 검색창 선택 시도는 상세 화면에 해당 입력이 없어서 실패한 테스트 제어기 선택 오류였다. 이 locator/도구 오류는 제품 결함으로 분류하지 않았다. 홈 summary는 첫 스냅샷에서 `group`으로 표현됐지만 Tab 포커스 후 Enter/Space 동작은 정상 확인되어, 역할 스냅샷만으로 조작 불가 결함으로 단정하지 않는다.
