# 독립 모의 첫 사용자 검수: 계획 시작 경로

검수일: 2026-10-06  
대상: `http://127.0.0.1:4466/?app=1`  
모의 사용자: 기록 없는 중학생 초보. 합성 종목 1500m만 경로 확인용으로 선택했으며 실제 기록 시간·날짜는 입력하지 않았다.

## 요약

- **실제 확인:** 빈 홈에서 계획 만들기를 눌러 종목과 기록 유무를 고르고, 기록 없이 진행해 초보 경험을 선택했다. 흐름은 `훈련 조건 · 3/4`의 훈련일 수 선택까지 도달했다.
- **미완료:** 주 작업자가 전달한 `훈련숫자 변경 금지`를 합성 입력 선택까지 금지하는 것으로 해석해 더 선택하지 않았다. 원래 범위는 제품 처방 코드의 숫자를 변경하지 말라는 뜻이며 합성 훈련일 선택은 허용됐다. 이는 검수 지시의 모호함과 실행 한계이지 사용자 제한이나 제품의 생성 불가가 아니다. 계획 생성, 첫 훈련 상세, 합성 일지 저장·재검색은 시도하지 못했다. 계획 완성/통과로 집계하지 않는다.
- **입력 횟수:** 성공한 UI 선택 6회(계획 진입 2, 종목 2, 무기록 1, 초보 경험 1). 선택 locator 실패 4회(무기록 문구 3회, 경험 문구 1회)는 클릭으로 세지 않았다. `actions.jsonl`에 선택 이유와 결과를 기록했다.
- **환경:** 격리 Playwright Chromium, 320×740만 실행했다. 요청 차단 때문에 로컬 주소 접속은 승인된 권한 상승 세션으로 수행했다. 외부 호스트는 허용하지 않았다. Vite HMR과 겹쳐 홈 화면이 다시 나타났으며, 사용자 설명에 따라 제품 Back 결함으로 판정하지 않았다.
- **변경 금지 준수:** 제품 코드, 계정, 안전 상태, 기존 훈련 숫자, 개인 기록은 변경하지 않았다. 브라우저 컨텍스트는 닫았다.

## 실제 경로

1. 홈에는 `오늘 기록 남기기`가 짙은 주 버튼으로, `훈련 계획 만들기`는 그 아래 보조 링크로 보였다. 오늘 기록 없음도 표시됐다.
2. 계획 진입 화면은 `계획 준비 · 기록 입력`이라고 쓰였지만 실제 질문은 `어떤 종목을 준비하세요?`였다. 800m부터 마라톤까지 종목을 제시했다.
3. 합성 검수 종목으로 1500m를 선택하자 `내 기록 / 실제로 달린 시간`, `목표만 있어요 / 앞으로 달리고 싶은 시간`, `기록 없이 / 시간 입력 건너뛰기`가 분리돼 나왔다. 이 중 기록 없이를 선택해 진행했다.
4. `훈련 조건 · 2/4`에서 달리기 경험을 물었고 `달리기를 막 시작했어요`가 추천으로 표시됐다. 이를 선택했다.
5. `훈련 조건 · 3/4`에서 “이번 9일 중 며칠 훈련할까요?”를 물으며 3일 추천, 4일, 5일, 6일, 매일을 제시했다. 이 입력은 훈련 숫자에 해당하므로 선택을 멈췄다.

## 핵심 개선안

1. **홈 계획 진입 안내 (실제 관찰):** 기록 버튼이 첫 행동으로 강하게 보여 기록이 먼저 필요하다고 오해할 수 있다. 계획 링크 가까이에 `기록이 없어도 계획을 만들 수 있어요`처럼 무기록 진입 가능성을 알려 준다.
2. **단계명 정합성 (실제 관찰):** 종목 선택 단계의 `계획 준비 · 기록 입력`을 `계획 준비 · 종목 선택`으로 바꿔 질문 및 선택지와 맞춘다.
3. **추천과 선택 상태 (실제 관찰 + 미검증 가설):** 다음 화면의 3일은 `추천`이라고 쓰였지만 이 검수에서는 선택 상태와 생성 후 결과를 진행하지 않았다. 추천 표시와 현재 선택 표시를 구별하고, 그 선택이 계획의 어떤 의미인지 짧게 설명한다. 실제 사용자가 혼동하는지는 추가 확인 전까지 가설이다.

## 나머지 7경우: 미실행 가설

아래는 화면 행동으로 확인하지 않았다. 어느 것도 통과로 집계하지 않는다.

| 경우 | 가설 / 후속 확인점 |
|---|---|
| 학교 1500m 기록 | 기록 날짜와 실제 달린 시간을 넣을 때 학교 기록을 현재 기록으로 고르고 저장할 수 있는지 미확인. 이번 경로에서 1500m는 종목 선택일 뿐 기록 입력이 아니다. |
| 목표만 있음 | 목표 시간을 현재 능력 기록과 혼동하지 않고 목표 전용 경로로 끝까지 생성되는지 미확인. |
| 종목 실수 수정 | `종목 다시 선택` 버튼은 실제로 보였지만 눌러 보지 않았다. 종목 수정 뒤 다른 입력이 보존되는지는 미확인. |
| 시간과 페이스 혼동 | 숫자 입력 화면에 도달하지 않았다. 단위, 시간 형식, 페이스 의미가 구별되는지 미확인. |
| 기록 날짜 모름 | 날짜를 비워 두거나 모름으로 진행할 수 있는지 미확인. |
| 폰 키보드 | 320×740에서 첫 화면과 계획 초기 단계의 가로 넘침은 관찰되지 않았지만, 키보드를 띄운 숫자 입력은 하지 않았다. 375×740은 미실행. |
| 뒤로가기 | 앱의 Back 동작을 시험하지 않았다. HMR 중 홈으로 보인 현상은 이 경우의 증거가 아니며 Back 결함으로 보지 않는다. |
