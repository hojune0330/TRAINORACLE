## 이번에 추가로 고친 부분

| 영역 | 문제 | 개선 |
|---|---|---|
| 계획 질문 | 달력 예시와 지난 답변이 현재 질문보다 먼저 나왔다 | 현재 질문과 선택지를 먼저 배치 |
| 지난 답변 수정 | 선택한 값들이 여러 버튼으로 항상 보였다 | 아래의 `선택한 내용 바꾸기`에서 수정 가능. 값을 삭제하지 않음 |
| 선택 없는 버튼 | 이동 핸들러가 없을 때도 수정 버튼이 보였다 | 이 상태에서는 값만 표시하고 작동하지 않는 버튼을 없앰 |
| 단계 안내 | 조건 질문의 분수가 전체 흐름의 완료율처럼 보일 수 있었다 | `계획 준비 · 운동할 날`처럼 현재 질문의 의미 표시. 접근성 레이블의 질문 범위는 유지 |
| 달력 예시 | 요청 기간과 달리 9일 예시가 고정될 수 있었다 | 7·9·10일 요청 기간을 사용. 옛 9.5일 값은 원본을 유지하고 날짜 10칸으로 표시 |
| 준비 상태 | 3/3 표기가 실제 계획 완성과 혼동될 수 있었다 | `준비 중` 표시와 기존 예시 안내 유지 |
| 다음 계획 | 새 계획안 요청 행동이 설명 안에 접혀 있었다 | 적격 주기 종료 후 `다음 계획안 만들기`를 바로 표시 |
| 검토와 적용 구분 | 새 계획·기록 검토·보류 계획 확인이 비슷하게 보였다 | 기록 검토는 보조 행동으로 표시. 선택한 계획 보기와 실제 시작 행동은 별도 이름 유지 |
| 기록 묶음 | 날짜 범위가 있는데 9.5일 설명이 상시 반복됐다 | 실제 날짜 범위 유지, 내부 묶음 설명은 `주기 시작일과 표시 기준`으로 이동 |
| 어려운 단어 | 빠른 기록·안내에 RPE가 노출됐다 | `힘든 정도`, `7/10` 같은 직접적인 표현. 용어 도움말과 원본 값 유지 |
| 모르는 힘든 정도 | 미입력과 0/10이 혼동될 수 있었다 | `모르겠어요 · 비워 둘게요`, 요약은 `입력 안 함`. 저장값을 추측하지 않음 |

## 보존한 계약

- 다음 계획안 요청은 자동 활성화가 아니다. 기존 부모 흐름의 최신 저장값·주기 완료·권한·통증 상태·보류 계획 검사를 통과해야 한다.
- 이미 선택한 다음 계획의 실제 시작 전에는 기존 몸 상태 확인을 유지한다.
- 훈련 강도·반복·거리·휴식·빈도는 이 작업으로 증가하거나 바뀌지 않는다.
- 과거 일지·처방·수동 기록을 새 표시 방식으로 재계산하지 않는다.
- 설명·기록 수정·달력 예시·검토 도구는 없애지 않고 이름 있는 진입점으로 보존한다.
- 원본 RPE와 미입력의 기존 저장 의미를 유지한다.
- 계정·서버 기능 보류를 이번 공개 웹 변경으로 해제하지 않는다.

- 스크린샷: `evidence/ux-backlog-20261007/browser/live-followup-ux-ready-pla-6c318--without-scrolling-at-320px-mobile-chromium/start-visible.png`, `start-double-text.png`. 후자는 시나리오에서 글자를 두 배로 확대한 상태이며 기본 화면이 아니다.
