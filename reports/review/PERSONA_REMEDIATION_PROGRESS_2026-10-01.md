## 결론

100개 합성 페르소나의 [원본 검수](PERSONA_100_INTEGRATED_REVIEW_2026-09-30.md)에서
발견한 다음 문제를 실제 코드와 스펙에 반영했다. 실제 사람 100명의 사용성 시험이 아니며,
원본 100개를 수정 후 전부 다시 실행했다고 주장하지 않는다. 반복 실행 횟수와 사람 수를
합산하지 않는다. 운영 계정이나 실제 선수의 일지는 사용하지 않았다.

가장 큰 미완료는 **첫 생성 MAIN의 상세 연결**이다. LT/GLY 강도와 전체 시간의 기존
임시 상한이 검토된 상세 템플릿과 충돌한다. 이 기본값 변경은 오너 답변을 기다리고 있다.
이번 저장 후 직접 교체는 이미 승인된 수동 선택 범위이며 기본 자동 증량의 승인이 아니다.

## 개선한 흐름

| 구역 | 이전 문제 | 현재 구현 | 남은 경계 |
|---|---|---|---|
| 저장 후 훈련 변경 | 후보 단계에서만 같은 목적의 카탈로그 교체 가능 | 앞으로 할 미기록 슬롯 하나를 직접 교체하고 이전 계획 보관 | V3 일반 계획에 한정. 별도 PACE/코치·조정 계획은 원래 경로 유지 |
| 다른 훈련 추천 | 45/60분 같은 용량 변형이 서로 다른 방법 수를 부풀림 | 방법군 먼저, 적격 숫자 변형 다음 순서로 선택. 본운동·회복·세트 경계 보존 | 다양성이 과학적 우월성이나 동일 부담을 의미하지 않음 |
| 상세 일지 | 35개 구간에서 18페이지를 차례로 이동 | 세트·운동/회복 구간 바로 이동과 원래 이름·수행 표기 제공 | 상세 입력은 선택 사항. 빠른 기록에 강제하지 않음 |
| 입력 오류 | 범위 밖 숫자를 말없이 버려 실제 입력과 저장값이 달라질 수 있음 | 원문 숫자를 비공개 초안에 보존하고 저장 차단. 저장 시 오류 구간 자동 열기·초점 이동 | 초안은 실제 수행 근거가 아니며 계획값을 자동 복사하지 않음 |
| 변경 중 이탈 | 미래 훈련을 고르다 탭을 바꾸면 미적용 변경 소실 | 기존 이탈 보호 재사용, 명시 취소로만 이동. 저장 중 이동 차단 | 자동 저장 기능으로 표현하지 않음 |

## 공격적으로 다시 확인한 경계

1. **방법군 합침의 과잉 일반화**: 독립 GPT-6.1 Sol ultra 검수에서 단일 자식 그룹의
   반복 회복과 마지막 한 번의 회복이 같은 방법으로 합쳐지는 P2를 찾았다. 단일 자식이라도
   반복 그룹이나 SET이면 경계를 보존하도록 수정했고 같은 독립 6개 검사 모두 통과했다.
   현재 117개 원본에서 실제 충돌 쌍을 발견했다는 뜻은 아니다. 유효한 합성 구조로 재현했다.
2. **서버의 클라이언트 주장 신뢰**: 일지 버전 비교만으로는 요청의 보호 슬롯 목록을
   검증할 수 없다. 서버가 소유자에 한정된 암호화 일지를 25개씩 읽고 실제 날짜·시간대·
   계획 연결과 구조화 근거 지문을 대조하도록 보강했다. 이후 일지 변경이나 누락은 기존
   전체 버전 검사와 계획 CAS를 같은 트랜잭션에서 확인한다. 신규 DB 마이그레이션은 없다.
3. **다른 날짜 수행과 시간대 미지정**: 날짜를 달리해 수행한 일지도 원래 계획 슬롯을
   보호한다. `UNSPECIFIED`/`SINGLE`을 오전·오후가 확정된 기록처럼 취급하지 않는다.
4. **거짓 성공과 원본 유실**: 응답이 불명확하면 재적용을 잠그고 확인 필요로 표시한다.
   원래 계획을 되돌려 덮어쓰거나, 계정 저장 실패를 기기 저장 성공으로 바꾸지 않는다.
5. **검수 증거 오염**: 100개 코어 감사의 기준 SHA와 출력 폴더가 과거 값으로 고정돼
   있었다. 실행 당시 HEAD/dirty 상태와 고유 실행 폴더를 사용하도록 바꿨다. 과거 증거를
   최신 통과 결과로 덮어쓰지 않는다.
6. **진행 결과·날짜의 서버 재확인**: 요청의 보호 목록과 날짜를 그대로 믿지 않는다.
   이전 계획에 완료/휴식/건너뜀 결과가 있거나 통증 확인 상태면 교체 전이를 거절한다.
   변경 영수증의 달력 시간대와 서버 현재 시각으로 날짜를 재계산하고, 날짜가 지난 변경은
   읽기 전과 저장 직전에 다시 막는다. 이미 커밋된 요청의 영수증 재조회는 계속 허용한다.
   시간대는 달력 맥락이며 이용자의 물리적 위치를 증명하지 않는다.

서버 독립 검수 작업은 도구 중단으로 완료되지 않았다. 위 서버 수리는 주 작업자의 직접
재현과 회귀 검사에 근거하며, 독립 승인으로 표기하지 않는다.

## 현재 확보한 실행 증거

- 집중 앱 검사: 11개 파일 **79/79 통과**. 방법군, 미래 교체, 기존 실제 수행 재계획,
  상세 일지, 비공개 초안, 이탈 보호를 포함한다.
- 계정·장기 이력 검사: 3개 파일 **85/85 통과**. 100개 과거 계획, 18개 V6 프레임,
  보관 상한·충돌·잘못된 응답·소유자 격리를 포함한다.
- 진행 결과·시계 보호 추가 후 관련 검사: 3개 파일 **41/41 통과**. 위 검사와 중복된
  항목이 있으므로 합계에 다시 더하지 않는다. 새 날짜·진행 결과 사례는 5개다.
- 서버 최종 검사: **22/22 통과**. 로컬 PostgreSQL에서 수동 교체의 실제 암호화 일지
  읽기와 커밋·응답 재조회까지 포함한다. 운영 DB에 쓰지 않았다.

  검사가 이름으로 실패했다(exit 1). 올바른 코드에서는 같은 검사가 통과한다.
- 독립 방법군 재검수: **6/6 통과**. [원본 보존·재검수 증거](evidence/persona-remediation-2026-10-01/independent-method-recheck.json).

## 장점과 부담

- 기존 계획을 보존하므로 과거 일지 비교가 새 훈련으로 바뀌지 않는다. 대신 변경할 때마다
  버전이 늘어나며 기존 보관 상한을 계속 지킨다. 상한 도달 시 몰래 과거를 지우지 않는다.
- 방법군 단위 추천은 같은 조깅의 숫자 변형이 추천을 독점하지 않게 한다. 단, 조건에 맞는
  방법이 하나뿐이면 다른 방법을 지어내지 않고 이유를 알린다.
- 세트 바로 이동은 자세히 쓰는 사람의 반복 클릭을 줄인다. 모든 구간을 한꺼번에 펼쳐
  화면을 길게 만드는 방식은 피했다. 숫자 오류도 다시 찾게 하지 않는다.
- 서버 일지 실물 대조는 보호 판단의 신뢰성을 높이지만 긴 기록 이력에서 읽기 비용이
  늘어난다. 작은 묶음으로 처리하며, 향후 최적화는 신뢰 가능한 서버 메타데이터로 해야 한다.
  검사를 빼거나 클라이언트의 완료 주장을 믿는 최적화는 하지 않는다.

## 남은 순서

1. W1 오너 결정 수신 후 기본 상세 처방의 정확한 RPE·총시간 정책과 최초 생성 흐름 반영.
2. W2 서버/계정 경로 독립 재검수 완료. 모바일 게스트 통과를 이 항목의 대체 증거로 쓰지 않음.
3. 실제 iOS 글자 확대와 최종 릴리스 후보 검사. 로컬 합성 확대를 실제 기기 전체 검증으로
   표현하지 않는다. 이번 변경은 계정 저장 경계를 포함하므로 릴리스 전 필수 관문을 생략하지 않는다.
4. `account-plan-collection`, `account-journal`에 현재 생성 검증기가 들어간 서버를 먼저
   배포·확인한 후 앱을 배포한다. 앱만 먼저 열면 이전 서버 스키마가 새 교체 영수증을
   거절할 수 있다. 신규 DB 마이그레이션이나 키 교체는 이번 변경에 포함되지 않는다.
5. 공개 화면과 승인된 운영 테스트 계정에서 새 계획 저장·교체·일지 원본 조회를 확인한다.
   현재 운영 계정 시험, 푸시, 배포는 수행하지 않았다.

이번 문서는 새 훈련 용량 승인, 임상 효과 확인, 스펙 정본 승격, 운영 저장 성공의 증거가 아니다.
