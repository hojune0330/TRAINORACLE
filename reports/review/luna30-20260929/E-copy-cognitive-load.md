## 판정 경계

- `CONFIRMED_RUNTIME`: 새 headless 브라우저 문맥에서 4194 Vite 미리보기를 실행 확인. 앱 요청 외 호스트는 차단.
- `CONFIRMED_CODE`: 현재 원문 코드와 이번 turn에서 실행한 지정 테스트가 보여준 범위.
- `NOT_TESTED`: 해당 persona 경로의 브라우저 실행 증거가 없음. PASS로 확대하지 않음.
- 계획-실제 비교는 현재 읽기 전용 사실 투영이다. 담당 계약은 `DRAFT_FOR_REVIEW`, `runtime_authority: false`, `replan_write_runtime: NOT_IMPLEMENTED`로 적혀 있다 (`specs/reconstruct/PLAN_EXECUTION_DEVIATION_AND_REPLAN_CONTRACT.md:9`, `:13`, `:14`, `:16`, `:17`). 재설계 엔진 부재는 현 구현 버그로 판정하지 않았다.
- 절차상 한계: `AGENTS.md`가 지정한 `design_handoff_plan_beta_extension/20 Handoff Risk Review.html`을 열었다. 다른 검수 문서를 읽지 말라는 사용자 경계와 충돌한다. 이 문서를 판정 근거로 쓰지 않았고 아래 결과는 현재 스펙·코드·이번 실행에 한정하지만, 보고서 블라인드 독립성은 완전하지 않다.

## 검수 결과

- 공격 경로: 빈 기록에서 `훈련을 바꿨을 때 읽어보기`를 개인 분석 또는 처방으로 오인하려고 열기.
- 결과: **NO_FINDING / CONFIRMED_RUNTIME.** 홈은 조건부 설명을 표시하고 일반 글은 개인 분석이 아니라고 다시 명시한다. 합성 브라우저 probe는 P22 단계까지 진행되어 이 경로 assertion을 통과했다. 일반 글 열기로 저장이 바뀌지 않는 점은 이번 Vitest에서도 확인.

- 재현: 새 브라우저 문맥에서 `http://127.0.0.1:4194/?app=1&uitest=1` 열기 → 코칭 일반 안내 펼치기 → 첫 글 열기 → 일반 정보 고지 확인.

### P22 낮은 RPE로 완료한 사용자

- 전제: 연결된 계획은 RPE 2~4, 완료 기록은 명시 입력 RPE 1인 합성 케이스.
- 정상 경로: 홈 비교 열기 → 요약에서 실제/계획 RPE와 판단 한계 확인.
- 공격 경로: 동일한 낮은 RPE를 파생/미확인 출처로 넣어 사실로 승격되는지 확인.
- 결과: **CONFIRMED_CODE / NO_FINDING.** 명시 RPE는 관측값과 계획 범위로 나란히 투영하고, 같은 구성을 했는지 미확인이라고 표시한다. 출처가 없거나 파생이면 제외한다. 낮은 값으로 향상·준수·증량 결론을 만들지 않는다. 다만 low-RPE 상세 문구의 live 확인은 **NOT_TESTED**: 별도 headless probe가 요약 확인 후 상세 fact 문구 assertion에서 멈췄다. 이것을 결함이나 PASS로 해석하지 않았다.
- 증거: `plan-execution-review.ts:85`, `:87`, `:88`, `:93`, `:95`; `ExecutionReview.tsx:33`, `:35`; `plan-execution-review.test.ts:26`, `:30`, `:31`, `:33`, `:34`.
- 재현: 합성 상태에 RPE 2~4 계획과 완료·명시 RPE 1을 넣고 요약을 연다. 공격 변형은 `fieldProvenance.rpe`를 생략하거나 `DERIVED`로 둔다. 이번 실행에서 상세 fact assertion은 통과하지 않았으므로 상세 결과를 재현 완료로 보고하지 않는다.

## 요약

확인된 결함은 P2 1건(일지 비교의 다중 접힘), P3 1건(중복 충돌 행 식별 불가)이며 둘 다 코드 확인이고 해당 화면의 브라우저 재현은 미실행이다. 홈 빈 상태와 현재 코드의 낮은 RPE/휴식/혼합 운동 사실 투영에서 추가 결함은 확인하지 못했다. 계획 재설계·적용 경로는 채택/실행되지 않은 범위로 남겼다.
