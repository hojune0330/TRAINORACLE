## 추가 발견한 돌아오기 문제

- 훈련법 목록의 화면 안 뒤로 버튼이 화면을 먼저 닫고, 폐기 과정의 늦은 브라우저 POP이 부모의 포커스 복귀 예약을 취소했다. More 제목 자체의 포커스 정책 문제로 단정하지 않았다.
- 현재 활성 화면이 소유한 Back 항목을 먼저 소비하는 작은 helper를 재사용 경계에 추가하고, 훈련법 목록 버튼 하나만 연결했다. More/AppShell 구현, 임의 timeout, 전역 자동 스크롤은 변경하지 않았다.
- 중복 클릭·상위 화면·처리 중 POP·저장 중 차단·계정 전환을 별도 계약으로 확인한다. 차단·대기 중에는 ‘처리됨’으로 반환하여 일반 뒤로가기 fallback으로 우회하지 않는다.
- 영구 E2E `navigation-origin.spec.ts`에 해당 복귀 경로를 추가했다. 모바일 Chromium/320px 두 검사 통과. 복귀 후 두 animation frame가 지난 뒤에도 원래 ‘훈련법 읽기’ 버튼 포커스 유지.
- 초기 utility 캡처 결과의 `passed:false`는 발견 당시 증거로 보존한다. 수정 후 브라우저 통과는 위 별도 회귀 검사로 구분한다. 초기 실패를 소급해 통과로 바꾸지 않는다.
- 뒤로가기 ledger·flow hook·AppShell 복귀의 추가 집중 검사 3파일 50개 통과. UI 묶음과 합쳐 **22파일 258개**, E2E는 **9개** 통과다. 재실행한 같은 테스트는 합계에 넣지 않는다.
- 최초 비상승 unit은 worker 시작 timeout으로 검사 0개가 실행된 시도다. 해당 시도는 성공/제품 실패로 계산하지 않고, 같은 3파일을 상승 환경 단일 worker로 실행해 통과했다.
