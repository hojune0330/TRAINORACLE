# 기록·메모·달력 배경 정합성 검토

검토일: 2026-10-07

검토 기준 소스: `a94a768fa2fb3463976ddf4356f2e0a2b4ed4a05`

상태: 개선 제안. 이번 검토에서는 제품 코드, 저장 자료, 테마 선택, 운영 배포를 변경하지 않았다. 현재 승인된 `docs/UX_UI_VISUAL_STANDARD.md`를 대체하는 확정 규칙도 아니다.

## 1. 결론

**조작하는 앱 화면은 깨끗하게, 완성된 일지·훈련 메모만 꾸미게 한다.**

사진의 문제는 단순히 배경색이 진한 것이 아니다. 줄노트의 선, 버튼의 실제 구분선, 오른쪽 아래 트랙 곡선이 서로 다른 규칙으로 겹친다. 입력과 선택이 이어지는 화면 전체에 그림을 배치하는 구조가 원인이다. 그림의 투명도를 낮추는 것만으로는 이 중복을 해결하지 못한다.

- 질문·선택·입력·저장·오류·안전 안내: 기존 디자인 토큰의 단색 바탕. 본문 뒤에 종이 무늬나 그림을 깔지 않는다.
- 일지 읽기: 내용과 숫자를 먼저 읽을 수 있는 깨끗한 본문. 기존 꾸미기와 원본 보기에서 소유한 테마와 배치를 확인할 수 있게 한다.
- 훈련 메모: 현재의 노랑·분홍·흰 단색 종이는 유지한다. 꾸미기 도구와 내보내기 버튼은 종이 바깥에 둔다.
- 달력: 경기·MAIN·신경성·기본·회복 등 정보를 전달하는 색, 오늘, 선택 날짜는 유지한다. 그림은 날짜 칸 바깥의 여백에만 둔다.
- 새 배경 선택 질문이나 필수 설정 단계를 추가하지 않는다. 기존 `꾸미기` 진입점을 보존한다.

## 6. 구현 순서와 보존 계약

1. 현재 시각 표준 중 기록 입력의 종이·대표 장식 허용 범위를 새 방향에 맞춘 제안 패치로 정리한다. 이 문서 자체를 이미 승인된 규칙으로 간주하지 않는다.
2. 공통 기록 입력 배경을 먼저 정리해 4개 입력 화면에 같은 기준을 적용한다. 투명도 조정만 하는 예외를 만들지 않는다.
3. 빠른 기록 요약과 일지 바깥 배경을 정리한다. 구분선은 내용 항목의 실제 경계에서만 사용한다.
4. 일지의 읽기·꾸미기·원본 표시 경계를 구현한다. 기존 진입점과 개인 저장 배치는 보존한다. 기본 읽기에서 정보를 숨기거나 한 화면 전체를 별도 카드 안에 넣지 않는다.
5. 달력과 훈련 메모가 내부에 표시되는 경로를 함께 정리한다. 날짜 영역은 보호하고 이미 단색인 메모 구성은 재디자인하지 않는다.
6. 테마 미리보기·실제 배치·설명·인쇄의 일치를 확인한다. 검토 자료와 제품 코드 배포 증거는 별도로 보고한다.

바꾸지 않는 것:

- 훈련 수치, 처방 설명, 수행 결과, 안전 판정, 입력값과 저장 계약.
- 테마 ID, 인벤토리·구매·획득 내역, 기존 사용자 선택, 스티커 좌표와 원본 배치.
- 계획·일지·달력 날짜 이동, 훈련 역할 색, 오늘·선택 표시, 접근 가능한 상태명.
- 메모의 숫자·회복·기준 기록, 간단히/자세히 기능과 내보내기 내용.

전체 CSS에 `background: none !important`를 적용하거나 전역 종이 토큰을 갈아엎지 않는다. 정보색·선택 상태·메모 종이색·인쇄를 각각 범위 안에서 다룬다.

## 7. 구현 후 최소 확인 기준

- 4개 입력 화면에서 테마 이미지가 질문·버튼·입력·오류·안전 안내 뒤에 나타나지 않는다.
- 긴 메모를 펼치거나 키보드를 열어도 장식이 확대되거나 새로운 선이 생기지 않는다.
- 320px·375px·글자 200%에서 글을 자르지 않으며 숫자와 선택 상태를 읽을 수 있다.
- 장식 6종을 선택한 상태와 장식 없음에서 같은 입력 가독성을 유지한다.
- 꾸미기에 들어가면 기존 소유 테마·스티커·좌표가 그대로 보인다. 뒤로 돌아오면 날짜와 내용 위치가 유지된다.
- 달력의 오늘·선택·경기·MAIN·회복 등의 표시를 색 외의 의미와 함께 유지한다.
- 메모 화면과 복사·저장된 결과의 수치가 같고, 개인 메모나 계정 정보가 추가되지 않는다.
- 키보드 초점·선택·읽기 안내·줄인 모션이 유지된다.

이번 완료 범위는 원인 확인, 관련 경로 점검, 증거 수집, 개선안 작성이다. 제품 수정·개선 후 사용성 검증·배포 완료를 의미하지 않는다.
