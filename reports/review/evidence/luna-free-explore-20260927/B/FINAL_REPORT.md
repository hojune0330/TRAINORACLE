# TrainOracle 자유 탐색 UX 리뷰 · 그룹 B

일자: 2026-09-27  
범위: R06-R10, 로컬 `http://127.0.0.1:4209/?app=1`  
데이터: 전부 합성. 독립 Playwright browser context별로 저장소를 분리했다.

## 판정

요청한 다섯 명 전원이 12회 이상 탐색한 검토는 **완료되지 않았다**. 최신 감사 가능한 실행(attempt 03)에서 상태가 바뀐 실제 클릭만 세면 R06 6회, R07 6회, R08 12회, R09 12회, R10 5회다. 12회 기준과 시작 상태를 모두 충족한 페르소나는 R08 한 명이다. R09는 행동 수는 충족했지만 계획만 있는 시작 상태를 준비하지 못해 유효한 R09 검토로 완료 처리하지 않았다.

| 페르소나 | 격리 시작 데이터 | 최신 유효 행동 수 | 결과 |
|---|---:|---:|---|
| R06 | 합성 일지 1개 | 6/12 | 미완료. 상세 화면에서 실행기 클릭 11회가 제한시간 초과 |
| R07 | 합성 일지 8개 | 6/12 | 미완료. 상세 화면에서 실행기 클릭 17회가 제한시간 초과 |
| R08 | 최근 기록 없음/휴식 상태 | 12/12 | 행동 수 완료 |
| R09 | 기록 0개, 활성 계획 없음 | 12/12 | 행동 수 완료, 요청된 계획 전용 시작 상태는 실패 |
| R10 | 일지 3개, 같은 날 오전·오후 2개 | 5/12 | 미완료. 상세 화면에서 실행기 클릭 12회가 제한시간 초과 |

행동 수는 페이지 제목·본문·URL 가운데 하나 이상이 바뀐 클릭만 집계했다. 실패한 클릭 시도는 행동 수에 더하지 않았다. attempt 01의 별도 컨텍스트 수는 R06 3, R07 3, R08 12, R09 12, R10 2이며 attempt 03 수에 합산하지 않았다.

## 실제 탐색 경로

- **R06:** 홈의 `현재 수준`에서 “최근 5km 기록은 24분 10초” 확인 → `일지` → 9월 20일 → `일지·메모 원문 열기` → 일지 목록으로 이동 → 같은 날짜 재진입. 원문 화면에서는 합성 5km·31분·6:12/km가 보였다.
- **R07:** 홈의 `훈련 비교`에서 “중간값은 5km와 6km” 확인 → `일지` → 9월 18일 → 원문 열기 → 목록 복귀 → 같은 날짜 재진입.
- **R08:** `오늘 기록 남기기`의 빠른 기록 화면 → 기록이 비어 있는 일지 → 새 일지 선택 → 계획 화면 → 분석의 기록 없음 상태 → 홈 복귀 → `일지 예시 보기`의 민지 일지 → 9.5일 주기 일지의 빈 상태.
- **R09:** `강점·보완점` 예시 → 계획 화면 → `내 계획 받기` → 개인 계획 파일 불러오기 화면(파일은 고르지 않음) → 빈 일지 → 새 일지 선택 → 분석에서 기록·진행 중 계획이 없다는 상태 → 해당 주제와 일지로 이동.
- **R10:** 전체 일지 → 9월 24일 → 합성 회복 훈련 원문(3km·20분·6:40/km) → 목록 복귀 → 같은 날짜 재진입. 9월 25일 오전·오후 두 세션을 같은 날짜에서 펼쳐 보는 행동까지는 도달하지 못했다.

## 발견 후보

1. **개인 결과와 예시 결과의 출처를 결과 가까이에서 구별할 것 (P2, 확인 필요).** R06의 한 건은 5km·31분인데 `현재 수준`은 5km·24분 10초를 표시했고, R07의 합성 거리는 3km와 5km인데 `훈련 비교`는 중간값 5km와 6km를 표시했다. 홈에는 `내 기록 · 결과 예시` 전환 문구가 있었지만 이 실행 로그에는 선택 모드가 남지 않아, 개인 분석 결함인지 예시 모드인지는 판정할 수 없다. 결과마다 선택된 모드, 기준 기록 수·기간을 표시하고 개인 데이터가 부족하면 예시임을 명시하는 방안을 권한다.
2. **계획 준비와 활성 저장 상태를 명확히 나눌 것 (P2, 후속 검증 필요).** R09 fixture 준비 화면은 “계획이 준비됐어요”와 `이 일정으로 시작`을 함께 보여줬다. 화면 캡처 뒤 시작 동작을 완료하지 못했고 탐색 context에는 활성 계획 저장 키가 없었다. “준비됨”이 저장 완료로 오해되지 않게 현재 상태와 다음 동작의 효과를 분명히 할 후보가 있다. 실제 저장·재방문 보존은 이번 증거로 검증되지 않았다.
3. **분석 빈 상태의 다음 행동 위계를 더 선명하게 할 것 (P3).** R08의 분석 화면은 기록 없음, 직접 적은 거리 없음, 에너지 시스템 기록 없음, 진행 중 계획 없음 등을 각각 알려줬다. 결측을 숨기지 않는 점은 좋다. 다만 처음 돌아온 사용자가 다음에 할 일을 고르기 쉽도록 대표 진입 하나를 먼저 제시하고 나머지 상태 설명은 압축하는 안을 검토할 수 있다.
4. **첫 화면의 목적지 구분은 강점으로 유지할 것.** 393×852 캡처에서 분석 주제 6개, 기록·계획 진입, 학습·꾸미기·예시, 하단 주요 탭이 한 화면에 보였고 겹침은 관찰되지 않았다. 홈에서 직접 갈 곳을 고르는 흐름은 발견 가능했다. 이번 캡처는 393px 폭 한 장이며 글자 확대·375×667·스크린리더 검증으로 확대 해석하지 않는다.

## 실행 관찰과 코드 확인

- attempt 03은 실제 서버 URL에 연결했고, 각 페르소나는 서로 다른 Playwright browser context를 사용했다. 저장된 일지 수는 reload 전후 R06 1, R07 8, R08 0, R09 0, R10 3으로 유지됐다. 이는 해당 격리 브라우저 localStorage 재방문 관찰이며 계정·기기 간 보존 증거가 아니다.
- `pageerror`는 다섯 context에서 관찰되지 않았다. 외부 요청은 전부 차단했고 `www.react-grab.com`, `fonts.googleapis.com` 요청이 차단 기록에 남았다. 외부 서비스 쓰기·동기화는 수행하지 않았다.
- 실행기 실패는 앱 오류로 분류하지 않았다. 일지 상세가 열린 상태에서 페이지 배경의 달력·하단 탭까지 후보 버튼에 넣어 클릭을 반복한 흔적이 있다. 역할이 `dialog`인 실제 상세 화면으로 타깃을 한정하지 못한 탐색기 선택 범위 문제로 보이며, 이 때문에 R06/R07/R10의 행동 수와 R10 이중 세션 확인이 부족하다.
- 소스에서 `app/src/domain/journal-local-storage.ts`의 일지 저장 경로와 `app/src/domain/plan-beta-store.ts`의 계획 저장 키를 확인했다. 브라우저에서 확인한 것은 합성 상태의 localStorage 저장·reload뿐이다. 제품 소스 변경, 테스트/CI 실행, 배포 확인은 하지 않았다.

## 실패와 경계

- 첫 탐색 실행: R06 3, R07 3, R08 12, R09 12, R10 2회. 달력 상세 화면의 타깃 선택 실패는 `attempt-01-actions.json`에 보존했다.
- 두 번째 실행은 화면 탐색과 캡처 뒤 기록 JSON 저장 시 `ReferenceError: planProvisioning is not defined`로 종료됐다. 이 실패 실행의 최종 행동 로그는 만들어지지 않았다. 캡처는 남아 있다.
- attempt 03은 로그를 남겼으나 R06/R07/R10이 12회에 도달하지 못했고, 계획 준비 상태도 활성 계획으로 확정되지 않았다. 따라서 다섯 명 전체 UX 평가는 부분 결과다. PASS 판정은 내리지 않는다.
- 사용자가 진행 중이라고 알린 배포/CI에는 접근하거나 개입하지 않았다. Luna Max가 이 세션의 실제 실행 모델이었다는 근거도 없어, 해당 모델의 독립 리뷰로 표시하지 않는다.
