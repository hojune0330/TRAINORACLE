# 현재 100개 페르소나 재검수

## 판정

로컬 합성 브라우저 경로의 오류를 수리했다. 독립 코어는 새 회귀 없이 통과했지만,
첫 자동 MAIN의 상세 공급은 19/85에 머무르므로 제품 전체 완료로 승인하지 않는다.
운영 계정, DB, GitHub CI, 배포, 실제 iOS는 이번 증거의 범위 밖이다.

기준 HEAD는 `eb2e4caf99e219b090cd490d51b1c754db1f680b`다. 변경 중인 파일은
각 실행 source와 [빌드 영수증](build-receipt.json)에 기록했다. 최종 런타임 파일과
실행 당시 감사기 SHA-256은 [브라우저 결과](browser-results.json)에 있다.
증거 수집 이후 config에 기존 run ID 재사용 거절만 추가했다. 제품 동작 변경은 아니다.

## 역할 분리

- 독립 검수: GPT-6.1 Sol, reasoning `ultra`, 별도 작업자. 코어 원본 100개와
  카탈로그 연결·저장·재읽기를 재실행하고 자체 대조 시험을 추가했다.
- 주 작업자: 실제 앱 브라우저 100개 경로, 화면 캡처 검토, 결함 수리 및 재검사.
- 두 검사의 100개는 별도 행렬이다. 실제 사람 200명 또는 독립 UX 리뷰어 100명으로
  표현하지 않는다. 시간대 반복과 후속 재시도도 고유 페르소나 수에 합산하지 않는다.

브라우저 결과에는 페이지 오류, 차단된 외부 요청, 가로 넘침, 44px보다 작은 버튼
등의 관찰이 없다. 그러나 이것은 아래의 시험 범위 안에서만 유효하다.

## 실제 수정

### 빈 편집기

초보 GLY처럼 검토된 적격 대체 구성이 없는 조건에서 `entry`가 없으면 화면이 비었다.
이제 대체 구성이 없는 이유와 현재 훈련이 유지된다는 상태를 짧게 알린다.
다른 날짜 선택과 기존 계획 확정은 유지한다. 미검토 템플릿이나 새 숫자는 만들지 않았다.
스펙에 빈 편집 영역 금지와 기존 처방 보존을 명시했다.

### 제목과 도움말 겹침

375px에 합성 200% 확대를 적용했을 때 제목의 긴 한글 단어와 물음표가 겹쳤다.
헤더가 필요한 만큼 줄을 바꾸고 긴 단어를 감싸도록 수정했다. 텍스트 실제 영역과
버튼의 충돌을 검사에 추가해 수정 전 실패를 확인했다.

- [수정 후](heading-after-200pct.png)
- [320px 실제 계획 화면](active-320px.png)

### 시험 코드의 노후화

구간 기록 시험 화면에 공용 숫자 입력 상태가 빠져 있었다. 이를 실제 컴포넌트와
동일하게 연결하고 훈련 변경 시 입력 상태를 지운다. 숫자 입력이 소수 타이핑 보존을
위한 textbox로 바뀐 점도 선택자에 반영했다. 반복 기록 확대 시험의 배열 타입을
명확히 했다. 실제 앱을 약화하거나 테스트를 생략해 통과시키지 않았다.

감사기는 이전 baseline 카탈로그가 아닌 현재 원본을 읽고 실행별 출력 폴더를 쓴다.
이미 적용된 값을 다시 선택했을 때 적용 버튼이 비활성인 정상 동작을 막힘으로 오인하던
조건도 교정했다. 첫 pilot 6개의 1실패는 이 시험기 문제였고 제품 결함으로 세지 않았다.

## 내용 검수의 핵심

현재 ID 117개 중 운동 116개는 적격 조건 한 조합과 명시적 합성 숫자를 주었을 때
연결·선택·로컬 저장·재읽기가 된다. OFF 1개는 운동 없음이다.
이는 모든 조건에서 자동 제공된다는 뜻이 아니다.

독립 원본 코어에서 정상 생성 82개 중 MAIN이 있는 프로필은 57개다.
그 MAIN 85개 중 상세 연결은 19개, 범위 안내는 66개다. BASE/REC의 MAIN 없는
25개는 실패 분모에 넣지 않는다. 초보·중급·숙련자의 모든 조건을 전수검사한 것도 아니다.

| 목적 | MAIN | 상세 연결 | 남은 원인 |
|---|---:|---:|---|
| LT | 19 | 0 | 기존 RPE 5~6과 상세 6~7 불일치 |
| VO2 | 15 | 9 | 준비·회복·정리 포함 총시간 상한 |
| GLY | 17 | 0 | 기존 RPE 7~8과 상세 8~9, 목표·전체 시간 미확정 |
| ATP-PC | 17 | 0 | 실제 가속·감속 공간 확인 필요 |
| MIX | 17 | 10 | 전체 시간 상한과 구성 조건 |

상세 원문은 [독립 코어 보고서](core/REVIEW.md), 집계는 [코어 요약](core/summary.json)을
참조한다. 보고서 원문이 지칭하는 전체 원시 로그는 로컬
`.scratch/persona-100-core-final-20261001/`에 보존했다. Git에는 주요 검수 결과와
대조 증거만 복사하며 수백 개의 반복 원시 파일을 모두 올리지 않는다.

## 공격적 UX 해석과 후속 우선순위

1. **최우선은 자동 상세 공급이다.** 목록 추가보다 W1의 강도·총시간 정책 충돌을
   해결해야 한다. 사용자가 상세 편집기에서 일일이 숫자를 채워야만 완성되면
   간단한 계획 생성이라는 제품 목표를 달성하지 못한다.
2. **필요한 확인은 해당 순간 한 번만 한다.** ATP-PC의 공간 여부, 언덕·장비 등
   실제 조건은 짐작하지 않는다. 모든 사람에게 긴 사전 문진을 늘리기보다 해당
   훈련을 제시할 때 짧게 확인하고 적격 대안을 유지한다. 아직 구현 완료가 아니다.
3. **주기 연결과 숫자 변환을 구분한다.** 현재 주기 문맥과 일반 다음 주기 이동은
   구현됐다. 상세 카탈로그의 검토된 감소/유지 정책은 B06 결정과 정확한 변화량
   근거가 필요하다. 원본 ID만 바꾸거나 최대 예상시간을 훈련량으로 취급하지 않는다.
4. **확대 화면은 스크롤을 허용한다.** 정보를 잘라 한 화면에 억지로 넣지 않는다.
   정상 글자 크기에서는 핵심 행동을 먼저, 확대에서는 겹침 없이 읽도록 한다.
5. **자동 시험은 미적 완성의 판정자가 아니다.** 현재 화면은 정상 폭에서 구분이
   명확하지만 생성 결과의 보조 버튼 여러 개와 상세 편집기의 긴 설명은 실제 사용자
   관찰이 필요하다. 이번에는 임의로 중요한 확인을 숨기거나 흐름을 다시 늘리지 않았다.

## 한계와 재현

- 브라우저는 seed가 고정된 변형 경로이며 무제한 랜덤 탐색이 아니다.
- click helper의 자동 스크롤이 있으므로 스크롤 0회·낮은 피로도·실제 터치 성공률의
  근거로 사용하지 않는다. 일부 키보드 동작도 전체 키보드 접근성 감사가 아니다.
- 200%는 CSS 확대다. 실제 iOS 글자 크기, VoiceOver, 휴대폰 키보드 검증은 별도다.
- 통신은 로컬 정적 파일만 허용했고 저장은 합성 게스트 저장소다.
- 전체 앱 회귀·운영 계정 CAS·DB0041·서버 배포·공개 배포를 실행하지 않았다.
- 이번 변경은 국소 UI/스펙/감사기 수정이다. 관련 검사에 집중했고 릴리스 후보의
  전체 관문은 배포 시점에 별도로 통과해야 한다.

재현 시 app 디렉터리에서 `TRAINORACLE_PERSONA_BROWSER_RUN`에 새 이름,
`TRAINORACLE_PERSONA_BROWSER_ORIGIN`에 현재 빌드의 loopback 주소를 지정하고
`playwright test --config playwright.persona-100.config.ts`를 실행한다.
기존 run 이름은 증거 보존을 위해 거절한다. 현재 카탈로그와 빌드가 같은 소스인지
먼저 확인한다. 이번 정적 빌드 보조 스크립트는 로컬 scratch에 보존했다.
