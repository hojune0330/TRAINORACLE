## 해결한 문제

시작일을 바꿨는데 이전 장소·장비 답변이 새 날짜에도 확인된 것처럼 사용되는 문제를
수리했다. 실제 날짜·오전/오후·계정·정확한 구성에 임시 확인을 연결한다. 같은 환경
조건은 해당 날짜들을 한 번에 보여주고 한 번만 응답하게 한다. 날짜별 반복 질문과
재확인 직후 다른 상세 훈련 조건을 연달아 묻는 흐름은 억제한다.

입력한 구간·회복 시간과 훈련 경험은 보존한다. 확인만으로 계획을 저장하지 않는다.
새 구성 적용은 그 슬롯에만 유효하고, 미확인 상태는 기본 시작과 A/B 선택 모두를 막는다.
기존 범위 계획을 만드는 사용자에게 새 환경 질문을 무조건 요구하지 않는다.

독립 검수에서 추가로 발견한 네 P2도 실제로 수정했다.

| 결함 | 수정 |
|---|---|
| 날짜 A→B→A에서 예전 체크 부활 | 문맥이 바뀌면 환경 응답 자체 폐기 |
| 묶음 확인 뒤 체크 해제가 다시 켜짐 | 직접 해제한 응답을 이전 확인으로 덮어쓰지 않음 |
| 구간 숫자 변경 뒤 예전 환경 답변 재사용 | 수치 draft를 확인 문맥에 포함, 새 답변 요구 |
| 제거한 구성 재호출 시 예전 승인 재사용 | 현재 후보에서 없어진 확인 키 제거 |

## 증거

- 부모 관련 5파일 **45/45**를 UTC/KST 각각 통과했다. 시간대 반복을 90개로 합산하지 않는다.
- 독립 수용 **11/11**을 UTC/KST 각각 통과했다. 수정 전 R01~R04 기대 단언은 바꾸지 않았다.
  [독립 보고서](independent/REVIEW.md)는 시험 범위와 확인한 소스 지문을 따로 명시한다.
- 부모의 네 보호 제거는 각각 해당 회귀 한 개가 이름으로 실패했다. 독립 작업자의 날짜 키·
  시작 차단·슬롯 제한 제거도 각각 실패했다. 제품 파일은 변조하지 않았다.
- 최종 브라우저 **3/3**: 320px, 375px CSS 200%+모션 감소, 1280px에서
  생성→상세 적용→날짜 변경→미선택 재확인→명시적 시작→로컬 저장→재읽기를 실행했다.
  확인만으로 저장되지 않음, 가로 문서 넘침 0, 페이지 오류 0, 외부 요청 0을 확인했다.
- 앱/e2e 타입 검사, 로컬 빌드, diff 검사를 통과했다. 빌드의 기존 폰트 경로·청크 크기·
  혼합 import 경고를 무경고라고 표현하지 않는다.
- [320px](mobile-320.png), [375px 합성 확대](mobile-375-css-zoom-200.png),
  [1280px](desktop-1280.png)는 위 최종 빌드에서 캡처했다.

최종 화면 육안 검토에서 CSS 200% 확대의 하단 주 탭 일부가 화면 밖으로 밀리는 양상을
관찰했다. 이 검사는 문서 가로 넘침만 검사하므로 고정 탭 전체 가시성의 통과 증거가 아니다.
실제 OS 글자 확대와 구별해 후속 전체 앱 확대 접근성 검수 대상으로 남긴다. 현재 변경의
조건 확인·시작 버튼은 사용할 수 있었지만 모든 화면의 확대 UX를 승인한 것은 아니다.

## 정직한 범위

첫 계획 UI의 일시적 최신성 확인이다. 저장 스키마, 서버 권한, 미래 환경의 보장 또는
이미 저장한 계획의 날짜별 확인 증명으로 승격하지 않는다. 묶음 질문에서 일부 날짜만
불가능하면 해당 훈련 편집/날짜 변경으로 돌아가야 하며 부분 승인 UI는 아직 없다.

초기 브라우저 3개는 미래 계획의 실제 제목 `첫 훈련을 확인하세요`를 `오늘 훈련`으로
기대한 시험 오류로 실패했다. 선택자를 교정했다. 초기 mutation scope도 모호한 문자열
대상 두 개를 발견해 실행 전에 멈췄다. 이를 제품 결함이나 성공한 결함 주입으로 세지 않는다.
독립 검수의 초기 runner/fixture 오류는 독립 보고서에 별도로 남아 있다.

원본 100명 페르소나 검수나 운영 계정·실제 iOS·배포를 다시 완료한 증거가 아니다.
W1 최초 MAIN 상세 공급 부족과 B06 카탈로그 다음 주기 수치 변환은 아직 해결하지 않았다.
이번 수정에서 강도·양·빈도를 늘리거나 실제 처방 수치를 새로 승인하지 않았다.

## 재현과 파일 배치

`parent-source`는 당시 `.scratch/schedule-condition-20261001/` 실행 파일의 원문이고,
`independent-source`는 당시 `.scratch/schedule-condition-review-20261001/` 원문이다.
두 디렉터리를 저장소 루트 아래 위 경로에 복원한 후 로컬 의존성으로 실행한다. env 파일을
읽지 않는 설정이며 브라우저는 127.0.0.1:4428 외부 요청을 차단한다.

```powershell
node .scratch/schedule-condition-20261001/run.mjs UTC
node .scratch/schedule-condition-20261001/run.mjs KST
node .scratch/schedule-condition-review-20261001/run.mjs UTC contract
node .scratch/schedule-condition-review-20261001/run.mjs KST contract
```

부모 mutation 모드는 `revoke`, `withdrawal`, `numeric`, `prune`이며 의도된 해당 단언
실패가 정상이다. 독립은 `date`, `gate`, `crossslot`을 사용한다. 독립 O01~O03은 수정 전
버그 존재를 확인한 영수증이며 정상 수용 시험에서 제외한다. 원문과 수정 전 결과도 보존했다.
구조화 결과의 절대 경로는 당시 실행 위치다. 새 위치의 실행 증거로 오인하지 않는다.

브라우저는 `build.mjs`의 새 출력 폴더를 사용해 별도 터미널에서 로컬 미리보기를 켠 뒤
`node app/node_modules/@playwright/test/cli.js test --config .scratch/schedule-condition-20261001/browser.config.ts`
로 실행한다. `build-receipt.json`은 덮어쓰지 않으므로 같은 출력 폴더로 반복 실행하지 않는다.
