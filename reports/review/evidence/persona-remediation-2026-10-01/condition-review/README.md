# 조건 확인에서 상세 훈련으로 연결하는 흐름

## 판정과 범위

기준 `872d841b` 이후 좁은 UX 보완이다. 기존 상한 안에서 계산되고 가속·감속 공간
확인 하나만 남은 미연결 MAIN을 발견하여 실제 날짜·오전/오후의 기존 편집기로 안내한다.
운동·회복 수치를 확인하고 실제 공간 확인란을 누른 뒤 명시적으로 적용한다.
원래 계획 시작을 강제로 막는 질문은 추가하지 않았다.

자동 처방 확대 완료가 아니다. 카탈로그 원본·RPE/시간 상한·D9·저장 구조·다음 주기
수치 변환은 변경하지 않았다. 새 조건을 자동 확인하거나 경기 기록으로 스프린트 시간을
만들지 않는다. 첫 자동 MAIN 19/85라는 앞선 표본 수치를 이 UI 변경으로 고쳐 쓰지 않는다.

## 구현

1. 순수 발견 함수는 A/B 모두 검증된 최초 계획인지 확인하고, 양쪽의 현재 강도·총시간
   상한을 만족하는 구성만 찾는다. 내부의 조건 가정은 실제 응답으로 반환하거나 저장하지 않는다.
2. 결과의 짧은 진입 버튼은 날짜·오전/오후를 표시한다. 클릭 시 pair·slot·catalog ID·지문·
   시작일·계정 범위를 다시 확인하고 정확한 편집기로 이동한다. 첫 항목으로 대체하지 않는다.
3. 확인란은 미선택 상태다. 열기나 체크만으로 계획을 변경·저장하지 않는다. 미적용 편집
   중에는 새로운 이동 요청을 무시하고 기존 적용/취소 경로를 유지한다.
4. 해당 훈련을 적용하면 같은 화면 문맥에서 다음 날짜의 질문을 연이어 표시하지 않는다.
   기존 수동 편집 기능은 유지하며 저장은 원래 계획 확정 경로가 담당한다.

### 테스트 자체 공격

- 공간 확인을 미리 체크하는 변조: `opens the exact slot with no preconfirmation ...` 실패.
- 미적용 편집 보호를 제거하는 변조: `does not erase an in-progress answer ...` 실패.
- 연속 질문 억제를 제거하는 변조: 적용 뒤 다음 질문이 다시 생겨 첫 흐름 시험 실패.
- RPE 상한 비교를 제거하는 변조: `rejects matching valid pairs whose rpe ceiling ...` 실패.

독립 리뷰는 최초 B만 상한을 바꾼 반례가 A/B 불일치에서 먼저 막힌다는 사각을 찾았다.
정상으로 검증되는 동일 A/B 반례를 추가하고 그 정상성을 먼저 단언했다. RPE 비교문을
제거하면 `P-ATP-T`가 잘못 발견되는 실제 실패를 확인했다. 총시간 반례는 binder를 포함한
전체 동작의 거절을 증명하며, 중복된 시간 비교문 하나만의 독립 증명으로 표현하지 않는다.

### 검사 환경의 시행착오

- 없는 `tsconfig.app.json` 경로로 시작한 명령은 실패했다. 실제 `tsconfig.json`으로 재실행했다.
- scratch Playwright 설정의 ESM 선언·명시 파일 import 누락으로 첫 두 시작이 실패했다.
  설정 수정 뒤 3개가 실행됐다. 이 둘은 제품 결함이나 테스트 통과로 세지 않는다.
- 기존 빌드의 큰 청크·동적 import·폰트 경로 경고는 남는다. 배포 환경 검증은 아니다.
