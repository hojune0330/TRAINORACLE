## 1. 판정

**방향은 유지한다. 다만 현재 안만으로 구현하면 취향 설문과 캐릭터는 생기지만,
사용자가 기대한 입체적인 러닝 분석은 얇게 남을 가능성이 크다.**

점수나 캐릭터를 없애자는 검수가 아니다. 질문 수나 화면 글자 수보다
**서로 다른 답변에 서로 다른 유용한 해석을 제공하는 규칙과 콘텐츠**를 채워야 한다.

[검수 대상 설계안](../plans/ORACLE_RUNNING_PROFILE_SCORE_CHARACTER_PLAN_2026-10-04.md)의
문항·계산·캐릭터·실제 기록·행동·반응·UI·저장·검수 장을 모두 읽었다.
[현재 프로필 계약](../../specs/reconstruct/RUNNING_PROFILE_CONTRACT.md),
[마스터 플랜](../../TRAINORACLE_MASTER_PLAN.md) §13~14,
[기존 질문](../../app/src/domain/running-profile.ts),
[기존 결과 화면](../../app/src/screens/RunningProfile.tsx)과도 대조했다.

아래 P1/P2는 **새 설계를 구현하기 전에 보완할 우선순위**다.
점수 기능이 현재 배포되어 오작동하고 있다는 의미가 아니다.
V1의 좁은 구현 범위와 확장안의 미착수를 구분한다.

## 2. 핵심 발견

### D1 · P1 · 원래 요청한 평가 영역과 결과 명세의 깊이가 다르다

- 위치: 설계안 53~72, 227~293행.
- 취향 여섯 축에는 문항과 계산식이 있지만 대회 성향·종목별 특징·웨이트 방식·
  훈련 반응은 기존 선택값 재사용이나 후속 검토에 주로 머문다.
- 선택값을 저장하고 보여주는 것과 그 선택의 의미를 풀어주는 것은 다르다.
  현재 4개 설명 항목과 예시 1개만으로는 분야별 읽을거리가 보장되지 않는다.
- 기록 도전 점수만으로 순위 경쟁·대회 운영·관심 종목을 대신하지 않는 경계는 옳다.
  하지만 그 뒤에 제공할 적극적인 설명이 아직 비어 있다.
- 보완: §3의 8영역마다 입력, 직접 사실, 허용 해석, 사례, 다음 행동, 결측 화면을 정의한다.
- 완료 기준: 영역마다 데이터가 있는 결과와 없는 결과를 적어도 한 개씩 실제 문장으로
  작성하고, 사용할 입력 ID까지 연결한다. 모두 점수화할 필요는 없다.

### D2 · P1 · 다른 개념을 한 점수에 넣거나 비슷한 말을 반복한다

- 위치: 설계안 94~117, 119~121행.
- IN1은 숨찬 운동의 즐거움, IN2는 빠른 구간에 대한 기대, IN3는 강한 구간이
  섞인 구성의 선호다. 빠른 짧은 구간을 좋아하지만 긴 숨찬 운동을 싫어하는 사람과
  강한 연속주를 좋아하지만 반복주를 싫어하는 사람이 섞일 수 있다.
- CH2의 기록 비교 재미는 PB 도전 동기와 같지 않다.
  SU1~2의 알아보기·배우기는 실제 수행 선호와 다르다.
  WE1의 학습 관심, WE2의 운동 자체 즐거움, WE3의 일정 포함 의향도 구분해야 한다.
- ST1~3과 EX1~3은 관점 차이가 일부 있으나, 사용자에게 같은 질문의 반복처럼
  느껴지는지 확인할 필요가 있다. 현재는 검토하겠다는 선언만 있다.
- 보완: 점수 문항은 정의한 한 개념에 맞추고, 연속/반복·거리/시간·평지/언덕·
  개인/동행 같은 **훈련 형태의 선택은 별도 범주형 응답**으로 연결한다.
  학습 관심과 경험·선호·실행 가능성도 구분한다.
- 완료 기준: 각 문항에 “무엇을 측정하고 무엇은 측정하지 않는가”와 오해 사례를 붙인다.
  강한 연속주 애호가에게 인터벌 선호를 붙이지 않는 사례를 통과해야 한다.
- 이는 이번 문항의 실제 타당성 실패를 입증한 결과가 아니라 문구와 정의 사이의
  내용 불일치 및 사용자 해석 위험이다. 사람 대상 확인은 아직 필요하다.

### D3 · P1 · 캐릭터 명명에 필요한 입력과 조합 규칙이 완결되지 않았다

- 위치: 설계안 193~225행, 현재 running-profile.ts 14~40행.
- “인터벌 애호가”는 해당 방식에 직접 동의한 경우만 허용하지만,
  현재 V1 선택지와 새 24문항에는 인터벌 선호를 명확하게 확인할 입력이 없다.
  IN3의 강한 구간이 섞인 훈련은 특정 반복주에 대한 확인으로 충분하지 않다.
- “훈련 설계자”는 계획을 따르는 편안함을 설계 능력처럼 읽히게 할 수 있다.
  예컨대 “계획형 러너”처럼 측정한 내용에 맞는 이름이 더 적합하다.
- 여섯 축의 후보 유무만 해도 64개 조합이 가능하다.
  조합별 일러스트 64장이 필요한 것은 아니지만, 3개 이상 후보·모두 후보·동률·
  후보 없음·부분 응답에서 어떤 제목과 설명을 내보낼지 결정 규칙이 필요하다.
- 보완: 직접 확인되지 않은 특정 훈련법 이름은 일반 이름으로 대체한다.
  대표 그림은 선택 가능하게 하고, 풀이 조합은 입력 순서와 배열 순서에 의존하지 않게 한다.
- 완료 기준: 후보 집합의 순서를 바꿔도 같은 풀이를 만들고,
  화면의 모든 캐릭터 수식어를 실제 응답으로 추적할 수 있어야 한다.

### D4 · P1 · 0~100 표시와 캐릭터 경계의 민감도를 더 설명해야 한다

- 위치: 설계안 141~182, 208~218행.
- 제안식의 125개 유효 응답 조합을 전수 계산했다.
  실제 표시 가능한 값은 13개다: 0, 10, 15, 25, 35, 40, 50, 60, 65, 75, 85, 90, 100.
- 한 문항을 한 단계 올리는 300개 경우에서 점수 변화는 5 또는 10점이었다.
  24개 경우에서는 해당 축이 캐릭터 후보인지도 바뀌었다.
  이는 조합 집합에서 센 수이지 실제 사용자 변화 확률이 아니다.
- 예: 4·4·3은 65점, 4·4·4는 75점이다. 마지막 답 하나로 캐릭터 후보 조건을 통과한다.
  182행의 갑작스러운 분류 확정을 피하겠다는 원칙을 동작 규칙으로 더 명확히 해야 한다.
- 2·5·5, 3·4·5, 4·4·4는 모두 75점이지만 첫 경우에만 응답 차이 조건이 적용된다.
  현재 차이 표시는 일부 문제를 줄이지만 동일 점수의 뜻이 하나라는 보장은 아니다.
- 보완: 숫자는 유지한다. “3문항 응답 요약”과 문항별 답을 확인할 수 있게 하고,
  한두 번의 재응답을 안정된 성격 변화나 성장으로 부르지 않는다.
  캐릭터는 현재 답에 맞는 추천 그림이며 과거 결과와 다른 날짜의 결과로 관리한다.
  편집 중 점수는 바뀌어도 매 터치마다 캐릭터 전체를 전환하지 않는다.
- 완료 기준: 응답 편집은 즉시 계산 미리보기, 묶음 완료 시 결과 확정,
  온라인 저장 성공은 별도 상태다. 근거 없이 임계값을 옮기거나 이전 점수를 유지해
  진짜 응답을 숨기는 방식으로 문제를 덮지 않는다.

### D5 · P1 · “반응”의 조건이 없으면 훈련 구성이 바뀐 것을 몸의 변화로 읽을 수 있다

- 위치: 설계안 41, 281~293행; 현재 프로필 계약 27~29행.
- 기존 화면은 월별 RPE를 관찰 자료로 보여주며,
  조건 일치나 훈련 효과의 증거가 아니라는 안내도 이미 있다.
  따라서 기존 화면이 회복력을 확정한다는 결함 주장은 하지 않는다.
- 다만 이번 확장에서 적극적인 풀이를 추가하려면 월별 집계만으로는 부족하다.
- 반례: A월은 RPE 3 운동 8회, RPE 8 운동 2회이고,
  B월은 RPE 3 운동 2회, RPE 8 운동 8회라면 중앙값은 3에서 8이 된다.
  각 종류의 운동이 느껴진 강도는 같아도 월 중앙값은 바뀐다.
- 보완: 전체 월별 차이는 “기록된 운동의 체감 강도 분포”로 둔다.
  비슷한 훈련의 비교는 목적·구성·실제 반복/시간·휴식·측정 방식·환경의 알려진
  차이를 함께 표시한다. 조건 누락을 같음으로 채우지 않는다.
- 완료 기준: 비교 가능한 세션 쌍과 제외 이유, 횟수, 날짜를 출력한다.
  1쌍은 개별 비교이고 반복 신호가 아니다. 반복 경향을 부를 최소 수와 기간은
  지표별 채택 문서에서 정하며 임의의 횟수를 생리학적 보증으로 쓰지 않는다.

### D6 · P1 · 경기속도 지수만으로 사용자가 기대한 “능력 파악”을 충족하지 못한다

- 위치: 설계안 243~279행.
- 같은 종목 기준 100에 대한 속도 비교는 계산 의미가 명확하지만,
  결국 두 기록의 비율이다. 단독 기록 사용자·다종목 사용자·반복훈련 위주 선수에게는
  자신이 무엇을 잘하고 어떤 조건에서 달라지는지 설명이 거의 남지 않는다.
- 반대로 자료 부족을 이유로 생리학적 능력 점수를 꾸며내는 것은 해결책이 아니다.
- 보완: 지금 제공 가능한 “수행 특성”과 별도 측정이 필요한 “생리 능력”을 나눈다.
  실제 기록, 동일 조건 반복의 편차, 계획 대비 완료 구간, 기간별 기록 변화를
  각자 단위로 제공한다. 수행 데이터는 능력을 엿보는 자료이지 완전한 진단이 아니다.
- 완료 기준: 기록 1개 / 같은 종목 2개 / 다종목 / 구간별 일지 / 적격 측정 자료별로
  서로 다른 결과 구성을 마련한다. 공식 점수표나 CS·ASR의 도입 대기를
  모든 의미 있는 수행 분석의 보류로 확대하지 않는다.

### D7 · P2 · 낮거나 복합적인 취향은 풍부한 결과를 얻기 어렵다

- 위치: 설계안 208~225행.
- 후보를 높은 점수 쪽에서만 만드는 구조다. 여섯 축이 모두 보통이거나
  높지 않은 사람에게 “나만의 러너”와 일반 설명만 남으면 경험의 밀도가 불균형하다.
- 낮은 사회 선호에서 혼자 달리기 사랑을 역추론하지 않는 원칙은 유지해야 한다.
- 보완: 직접 선택한 조용한 러닝·익숙한 코스·기분에 따른 선택 등 긍정적 취향을
  활용하되, 없는 응답은 만들지 않는다. 숫자 점수와 별도로 선택형 장면·스타일을
  대표 그림에 반영할 수 있다. 그림 선택 자체를 새 성향 측정값으로 쓰지는 않는다.
- 완료 기준: 높은 점수 없음 / 복수 높은 점수 / 미응답 / 상황 의존에서
  각각 근거가 다른, 완성도는 동등한 결과를 제공한다.

### D8 · P2 · 적은 클릭과 충분한 정보의 연결 규칙이 부족하다

- 위치: 설계안 125~135, 297~308행.
- 기존 3문항을 끝낸 사람이 점수를 보려고 다시 6문항을 답하면,
  첫 점수 결과까지 최대 9문항을 거치며 일부 의미가 반복될 수 있다.
  실제 이탈률을 측정한 것은 아니지만 설계상 추가 행동은 확인된다.
- 첫 6문항이 강도·계획으로 고정되어 있어 대회·친구·풍경이 주요 관심인 사람의
  첫 정량 결과가 본인의 목적을 충분히 반영하지 못할 수 있다.
- 보완: 기존 결과와 직접 점수 모듈 진입을 분리한다.
  기존 응답은 문맥과 관심 모듈 제안에만 쓰고 임의 점수로 환산하지 않는다.
  문항 묶음을 고르는 추가 단계를 무조건 넣기보다 진입 맥락에 맞는 기본 묶음과
  작은 “다른 항목” 진입점을 제공한다. 같은 축은 같은 문항 세트로 계산한다.
- 완료 기준: 처음/기존 응답/중단 복귀/점수 수정의 최단 흐름과 탭 수를 기록하고,
  답을 보존한 상태로 부분 결과에서 나올 수 있어야 한다.

### D9 · P2 · 전문선수에게 필요한 결과 확장과 처방 연결이 구체적이지 않다

- 위치: 설계안 231~234, 281~293, 341행; 마스터 플랜 §13~14.
- 앱 사용 제안만으로 끝나면 선수가 원하는 종목·구간·주기·AM/PM 해석이 부족하다.
  기본/선수 보기를 같게 유지한다는 것과 선수의 운영 정보를 제공하지 않는 것은 다르다.
- 보완: 공통 결과는 그대로 두고, 적격 자료가 있는 경우 구간별 수행,
  오전/오후 분리, 경기 준비 구간, 비교한 계획 버전을 더 열어볼 수 있게 한다.
  계획 후보는 기존 승인된 목적·부하·회복 조건을 통과한 후보 안에서만 취향을 참고한다.
- 완료 기준: “인터벌을 좋아함”이 곧 “인터벌 추가”가 되지 않아야 한다.
  추천 이유에는 취향, 주기 목적, 수행 관찰을 서로 구분해서 제시한다.
  이번 프로필 모듈이 처방 엔진을 직접 수정하지 않는 경계는 유지한다.

### D10 · P2 · 풀이와 과학적 검증을 실행 가능한 작업 단위로 내려야 한다

- 위치: 설계안 345~352, 360~375행.
- 문항/계산/풀이 버전 보존과 검증 단계는 있다.
  그러나 각 축의 근거, 결과 문장별 발동 조건, 질문의 시간 범위,
  상상한 선호와 경험한 선호의 저장 방식, 재응답 후 비교 규칙은 아직 부족하다.
- “내용 타당성 검토”만 적으면 작업자는 수식 테스트를 통과한 것을
  의미 검증까지 끝낸 것으로 오해할 수 있다.
- 보완: 문항별 의미표, 주장별 근거표, 결과 콘텐츠 목록, 저장·삭제 파생물 목록,
  사람 대상 질문 이해도 점검표를 각각 산출물로 지정한다.
- 완료 기준: 대상을 모르면 낮은 신뢰도 숫자를 발명하는 대신 적용 범위를 한정한다.
  연구 전 자체 점수 공개와 검증된 검사라는 주장은 별도 완료 상태로 보고한다.

## 3. 보존해야 할 8영역과 필요한 상세

아래는 보완 제안이다. 새 처방·척도의 공개 승인을 뜻하지 않는다.
행동 이력은 전 영역에 걸쳐 별도 사실로 연결한다.

| 영역 | 입력 | 제공할 상세 | 만들지 않을 해석 |
|---|---|---|---|
| 경기·수행 특성 | 실제 기록, 동거리 비교, 구간별 실제 수행 | 종목별 기록·날짜, 변화 초, 동일 조건 구간의 차이, 비교 가능 범위 | 기록 하나로 에너지 능력·재능·근섬유 확정 |
| 러닝 동기·생활 취향 | 직접 답한 목표·교류·환기·탐색·건강 목적 | 함께 존재하는 동기, 직접 선호한 상황, 선택 이유 | 동기 간 점수 차이를 검증된 우선순위로 확정 |
| 훈련 방식 | 강도 취향과 별도의 형태 선택 | 연속/반복, 시간/거리, 평지/언덕, 계획/자율의 직접 선호 | 짧고 빠름=숨참=인터벌 취향으로 등치 |
| 대회 | PB·완주·순위·경험 목적, 선택한 전술, 실제 스플릿 | 원하는 대회 경험과 실제 페이스 전개를 따로 설명 | 중거리 전술 경기를 마라톤 균등 페이스 기준으로 감점 |
| 보조운동 | 가동성·코어·플라이오·대체운동 선호·경험·제약 | 종류별 관심, 해본 운동, 접근 가능한 방식 | 안 했음을 싫어함이나 능력 부족으로 처리 |
| 웨이트 | 운동 자체 관심, 학습 필요, 장비, 실제 수행 | 맨몸·기구·지도 방식, 관심과 실행 여건의 차이 | 기구 사용=고중량 선호, 설문=근력 |
| 종목 | 좋아하는 종목과 실제 경기 이력 | 관심 거리, 경험한 거리, 종목별 실제 기록 특성 | 미경험=0점, 단일 예측으로 종목 전향 권고 |
| 관찰된 반응 | 비교 가능한 훈련, RPE 등 적격 자료, 알려진 조건 | 실제 차이, 일관/불일치한 관찰, 다음에 비교할 자료 | 월 RPE 변화=체력 변화, 한 번의 반응=원인 확정 |

각 영역을 점수 하나로 압축하지 않는다. 반대로 설명할 수 있는 사실을
“알 수 없음” 한 문장으로 끝내지도 않는다. 확인된 내용, 모르는 이유,
있으면 더 알 수 있는 자료를 구별한다. 추가 입력은 분석을 이용하기 위한 강제가 아니다.

## 4. 풀이 콘텐츠를 만드는 계약

### 4.1 풀이 한 항목의 필수 구성

1. 제목: 무슨 특징인지 쉬운 말로 말한다.
2. 관찰 사실: 선택한 응답 또는 실제 수치·기간·분모.
3. 의미: 그 사실에서 말할 수 있는 범위.
4. 조건: 이런 상황에서는 다르게 해석해야 하는 점.
5. 다음 행동: 자세히 보기·비교하기·수정하기·검토된 방법 확인 중 하나.
6. 근거 묶음: 입력 ID/버전, 계산 버전, 콘텐츠 버전, 관련 연구 또는 제품 규칙.
7. 미제공 조건: 필수 자료 없음·미수신·충돌·부적격을 구분.

필수 필드가 첫 화면에 전부 보인다는 뜻은 아니다.
첫 화면은 그림/이름, 핵심 숫자, 핵심 풀이 한 문장으로 시작한다.
상세를 열면 “왜 이런 결과인지”가 실제 입력까지 이어져야 한다.

### 4.2 같은 일반 문구를 반복하지 않을 조건

- 취향과 행동이 일치: 어떤 항목·기간에서 일치하는지 적는다. 성실성 점수는 만들지 않는다.
- 취향과 행동이 다름: 차이를 보여주되 시간·환경·계획 때문이라고 추측하지 않는다.
- 사용자가 제약을 직접 답함: 그 응답을 병기하되 실제 행동의 원인으로 확정하지 않는다.
- 경기 목표와 관심 종목이 다름: 둘 다 유지하며 시스템이 관심 종목을 교정하지 않는다.
- 동일 숫자·다른 답변: 차이가 풀이에 필요한 경우 질문별 응답을 반영한다.
- 자료가 늘어남: 새 자료로 추가된 사실을 표시하고, 기존 결과가 틀렸다고 임의 서술하지 않는다.
- 응답이 바뀜: 취향 결과만 갱신한다. 실제 수행·처방 당시 값은 그대로다.

콘텐츠는 각 축의 높은 경우만 작성하지 않는다.
각 축마다 해석 가능한 낮은 응답, 중간, 높은 응답, 응답 혼재, 조건 의존,
미완성을 어떻게 다룰지 정한다. 이는 **콘텐츠 상태 목록**이며 검증된 심리 구간표가 아니다.
원점수 옆 문장은 실제 답에 맞추고, 임의의 점수 구간을 자연적 유형이라고 부르지 않는다.

### 4.3 깊이를 보여주는 합성 예시

다음은 실제 사용자 결과가 아닌, 필요한 콘텐츠 수준을 설명하는 합성 사례다.

- 직접 응답: 반복 구간이 있는 훈련을 선호하고 계획을 미리 보는 것이 편하다고 답함.
- 실제 경기: 같은 종목·비교 가능한 조건의 5km 기록 22:10, 21:40.
- 일지: 당시 처방 400m x 6, 반복 목표 90초. 실제 구간 92, 91, 93, 94, 92, 95초.
  실제 회복 시간은 미기록. 이 훈련은 추천 예시가 아니라 이미 주어진 처방과 수행의 비교 예시다.

첫 결과:
“계획형 러너 · 반복 구간이 있는 훈련을 선호해요.”
“5km 30초 단축 · 400m 6회 기록 · 평균 92.8초”

펼친 풀이:
“5km 두 기록의 차이는 30초예요. 400m는 6회 기록했고 평균은 92.8초로,
당시 목표보다 평균 2.8초 늦었어요. 반복을 모두 기록한 것과 목표 초를 모두
지킨 것은 달라요. 실제 휴식 시간이 없어 구성 전체를 지켰는지는 확인할 수 없어요.
이 한 세션으로 특정 능력 부족을 판단하지는 않아요.”

다음 행동:
“구간별 비교”를 누르면 6개 구간과 당시 목표를 확인한다.
이미 있는 “계획과 다르게 수행했을 때” 흐름으로 이어지며, 프로필이 임의로 다음 훈련을 늘리지 않는다.

숫자는 계산 가능하고 해석은 구체적이지만, 운동 효과의 원인과 생리 능력은 발명하지 않는다.

## 5. 점수·숫자·캐릭터의 권장 관계

- 취향 점수: 직접 응답 요약. 점수가 높아야 더 좋은 결과인 구조가 아니다.
- 수행 수치: 시간·거리·반복·편차처럼 원 단위 우선.
- 상대 지수: 기준 기록을 명시한 개인 내 비교. 100은 만점이 아니다.
- 외부 기준 점수: 사용권한·종목 매핑·대상 범위가 확인된 모델만 별도 표기.
- 캐릭터: 직접 확인한 취향을 읽기 쉽게 묶은 표현. 신체 등급이 아니다.
- 자료 범위: 답한 항목 수·적격 기록 수·날짜·출처를 표시한다.
  자료가 많다고 자동으로 “분석 정확도 90%”를 부여하지 않는다.

과학적 근거가 있는 것은 개념·측정 방식·검토된 계산 각각이다.
제품 전체를 단번에 검증된 성격검사라고 부르지 않는다.
“재미로 살펴보세요” 안내와 함께, 각 숫자가 무엇인지 보여주는 방향을 유지한다.

## 6. UX와 저장의 세부 보완

### 6.1 입력

- 첫 방문: 점수 체험으로 직접 들어오면 기존 3질문을 필수 선행시키지 않는다.
- 기존 응답자: 이미 답한 범주형 내용은 보여주되 정량 문항의 답으로 자동 환산하지 않는다.
- 조건 의존: 추가 문항을 강제로 이어 붙이지 않고 현재 조건 선택으로 요약할 수 있다.
- 모름/건너뜀: 실패나 낮은 점수가 아니다. 별도 결과 상태로 끝낼 수 있어야 한다.
- 복수 선택: 첫 탭에 다음 화면으로 넘어가지 않는다. 단일 선택과 다르게 확인한다.
- 동일 축의 서로 다른 문항 세트를 임의 배정하지 않는다. 동등성 없이 점수를 비교할 수 없기 때문이다.
- 숫자 설명 때문에 모든 응답 화면에 긴 주의문을 반복하지 않는다.

### 6.2 결과

- 한 화면에 여덟 영역을 모두 펼치지 않는다. 요약에서 관심 영역으로 한 번에 진입한다.
- 그림·점수·구체적 사실이 먼저고, 연구·계산·제약은 펼쳐서 본다.
- 전문 보기에서도 동일 숫자와 출처를 유지한다. 세트/랩·주기·AM/PM을 추가로 제공한다.
- 결과 갱신은 숫자 강조 정도로 알리며 매 방문마다 설문이나 캐릭터 애니메이션을 강요하지 않는다.
- 기본 크기에서는 한눈에 읽히도록 하고 200% 확대에서는 스크롤을 허용한다.
- 설명을 닫거나 뒤로 갈 때 선택한 영역과 위치를 복구한다.
- 높은 점수의 그림만 화려하게 만들지 않는다. 미완성 결과도 벌점처럼 보이지 않게 한다.

### 6.3 수명과 파생 결과

- 응답일, 선택한 시간 범위, 경험/상상 여부, 비교 자료의 기간을 분리한다.
  기간을 아직 확정하지 않았다면 장기간 안정된 성향 변화라고 출력하지 않는다.
- 제출 전 초안 / 현재 계산 미리보기 / 서버 저장된 결과를 구분한다.
- 기록 수정·삭제는 해당 기록을 사용하는 관찰 결과만 다시 계산한다.
  취향 점수를 실제 기록 변화로 수정하지 않는다.
- 응답 삭제 시 현재 캐릭터·점수·공유 미리보기 캐시를 함께 무효화한다.
  과거 수정본 보관 정책과 삭제의 실제 범위는 기존 계정 계약에 맞춘다.
- 이전 버전 점수는 그때의 문항과 함께 보관하고 새 버전과 차이 점수를 자동 계산하지 않는다.
- 친구와 비교할 때도 현재 동의된 필드·버전·기간만 사용한다.
  질문 응답·몸 상태를 재미 요소라는 이유로 자동 공개하지 않는다.

## 7. 합성 상황 20개로 한 수동 설계 검토

아래는 질문과 규칙을 상황에 대입한 **작성자의 수동 검토**다.
브라우저 자동 실행, 독립 모델 검수, 실제 사용자 연구 결과가 아니다.

| ID | 상황 | 기존 안에서 확인한 점 또는 빈틈 | 필요한 결과 |
|---|---|---|---|
| 01 | 첫 러닝 전 상상으로 답함 | 경험 맥락 저장 명세가 없음 | 상상한 취향으로 표시, 수행 능력 생성 안 함 |
| 02 | 강한 연속주는 좋고 반복주는 싫음 | 인터벌 이름에 필요한 입력 없음 | 일반 이름 또는 직접 답한 연속주 선호 |
| 03 | 짧게 빠르게 달리는 것은 좋지만 오래 숨찬 것은 싫음 | IN1~3이 서로 다른 뜻일 수 있음 | 형태와 강도 선호 분리 |
| 04 | 기록 그래프는 좋아하지만 PB 경쟁엔 무관심 | CH2가 다른 관심을 섞을 수 있음 | 기록 관찰 취향과 기록 도전 동기 구분 |
| 05 | 계획은 좋아하지만 교대근무로 자주 변경 | 기본 금지 규칙은 있음, 실제 풀이 없음 | 직접 답한 여건과 관찰 사실을 나란히 설명 |

## 9. 근거 재확인과 적용 한계

- [COSMIN 내용 타당성 방법론](https://link.springer.com/article/10.1007/s11136-018-1829-0)은
  문항의 관련성·빠진 개념·이해 가능성과 응답 선택지·회상 기간을 점검하며,
  높은 내적 일관성만으로 필요한 개념을 제대로 측정했다고 볼 수 없다고 설명한다.
  이는 PROM을 위한 방법론이다. 이번 취향 제품의 공식 인증 기준이라고 주장하지 않고
  질문의 내용 검토 원칙을 참고했다.
- [PRETIE-Q 대학생 여성 대상 검증](https://pubmed.ncbi.nlm.nih.gov/18274947/)은
  선호와 내성을 구분해 검토했다. 이 연구가 자체 3문항·0~100점·75점 캐릭터 경계나
  모든 한국 러너 집단의 타당성을 보증하지는 않는다.
- [포르투갈어 PRETIE-Q 검증 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC10378368/)에서도
  일부 문항이 선호와 내성 중 어떤 의미로 읽히는지 검토하고 집단 간 동등성을 다룬다.
  원 척도조차 문항의 의미와 적용 집단을 확인한다는 사례로만 사용한다.

위 문헌은 수치와 캐릭터를 금지하는 근거가 아니다.
**좋은 개념을 참고했는지, 우리 질문이 그 개념을 실제로 묻는지,
우리 점수가 사용자에게 어떤 뜻으로 읽히는지**를 따로 확인해야 한다는 근거다.
