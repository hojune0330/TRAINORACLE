# 훈련 주기·추천 근거 검토 — 2026-10-24

상태: 구현 동반 연구 보고. 새 훈련량·증량·회복 수치의 채택 문서가 아니다.

기준: `81c0b7f8e19decc201a22e858b0cac38736feb12`와 2026-10-24 작업 중 소스의 정적 대조. 화면 개선과 다른 작업자의 변경은 진행 중이므로 아래 내용은 공개 배포·실계정 동작·사용자 이해도·훈련 효과의 검증 결과가 아니다. 이 보고서는 소스 수정이나 테스트를 수행하지 않았다.

## 1. 결론

**이번에는 기존 처방을 정확히 설명하고, 날짜·훈련·기록을 연결한다. 독립된 7일 훈련법이나 새 증량표는 추가하지 않는다.**

- 현재 일반 계획의 7·9·9.5·10일은 서로 검증된 네 가지 주기법이 아니다. 기준 원장은 모두 19반일/9.5일이고 표시기간을 선택한다. 다만 선택한 기간에 가용일을 다시 배치하므로 훈련 날짜와 밀도에도 영향이 있다. 단순 달력 필터라고 설명해도 틀린다.
- 10km 프로그램은 기존 구성으로 만든 9.5일 세 묶음이다. 30분과 60분 목표를 바꾸는 것만으로 훈련량이 커지거나 작아지지 않는다. 목표 속도 사용을 직접 고른 경우에만 해당 구간에 목표 평균 속도를 쓴다.
- 적격 후보 제공, 목록 순서, 방법 다양성, 과거 자기보고 완료 이력은 개인에게 효과가 가장 클 훈련을 예측한 결과와 다르다.
- 조사한 원 연구는 강도 분배·기간별 배치·개인 반응을 함께 볼 필요성을 뒷받침한다. **7일·9.5일·10일 중 하나가 모든 러너에게 우월하다는 직접 비교 근거는 이번 검색에서 확보하지 못했다.** 이는 관련 연구가 전혀 없다는 단정이 아니다.

### 기본값과 추천이 만들어지는 방법

- 일반 간편 입력의 `QUICK_INTAKE_DEFAULTS`는 혼합 목적, 9일 표시, 시간대 무관, 하루 1회다. `RECOMMENDED_ANSWERS`는 5000m·초보·3회 등을 고정 편의 선택으로 표시한다. 사용자 능력을 분석한 값이 아니다. 사용자가 답한 값과 기본값의 출처를 구분해야 한다. 근거: `app/src/screens/plan-beta/plan-intake-navigation.ts`.
- 10km 프로그램 화면은 첫 가용 횟수 3, 시간대 `VARIES`로 시작한다. 프로그램 생성기의 기본 후보는 `BALANCED`, 시간 기준 기본 목적은 `LT_INTENT`다. 목표 속도 선택은 `MIXED_INTENT`로 별도 처리한다. 근거: `GoalTrainingProgramFlow.tsx`, `goal-training-program.ts`의 `settingsSchema`와 `readSettings`.
- 10km 시간 기준 경로의 `requestFor`에는 `goalMinutes`가 전달되지 않는다. 같은 경험·일수·시간·목적이면 목표 시간만 변경해도 세션 구성·분량의 계산 입력은 같다. 반면 `goalPaceSessionOptions`는 직접 고른 목표 시간을 `GOAL / RACE_AVERAGE_V1`로 넣는다. 원본 식별자와 설명까지 동일하다는 주장은 아니며, 이번 확인은 정적 데이터 흐름 검토다.
- 신규 상세 MAIN은 적격 구성과 시간 조건을 확인한 뒤 `(seed + day + slotOffset) % options.length`로 고른다. EASY는 강도·시간 제한을 통과한 구성 중 총시간이 긴 순서다. 이 선택은 개인 효과 예측 순위가 아니다. 근거: `impl/src/prescription/catalog-session-binding.ts`.
- 기존 상세 방법 추천기는 적격성·목적·문맥 우선순위, 선택적 반복 선호, 카탈로그 순서로 정렬한다. `plan-template-options.ts` 호출부의 세 우선순위는 모두 0이다. 중립 설명은 이미 ‘현재 조건과 목적에 맞는 목록 순서 · 우열을 뜻하지 않아요’다. 그 설명을 제거하고 ‘최적 추천’으로 바꾸지 않는다. 자기보고 완료 횟수와 실제 구간 수행 증거도 구분한다.

| 의심점 | 상태·근거 | 조치 |

| 기본값이 개인 맞춤 추천처럼 보임 | **위험 확인.** 두 입력 경로에 고정 기본값이 있고 일반 입력에는 추천 뱃지용 고정 상수가 있음 | 표시 모델에서 선택/기본값 구분. 기존 자료에 출처가 없으면 ‘직접 선택’이라고 소급 생성하지 않음 |
| 목표 30분과 60분의 훈련이 충분히 달라진다는 기대 | **계산 차이 확인.** 시간 기준 경로에는 목표 시간이 배합 입력이 아님. 목표 RP 선택만 별도 계산 | 목표 제목 아래 실제 적용 기준을 설명. 목표별 점진 증량이나 달성 가능성은 새 모델 검토 대상으로 남김 |
| 추천이 효과 우선순위로 읽힘 | **부분적으로 방어됨.** 중립 추천 이유가 이미 목록 순서·우열 아님을 명시. 카탈로그 기본 선택은 효과 랭킹이 아님 | 기존 정직한 설명 재사용, 추천이라는 단어와 초기값/후보의 뜻 통일 |
| 일반 계획과 10km의 시간·페이스 설명 불일치 | **구조상 위험 확인, 전체 화면 미검증.** 둘 다 원본 카탈로그 재계산 경로가 있으나 표시 컴포넌트가 나뉨 | 같은 읽기 전용 구간 표시 모델 사용. 준비가 없는 원본에 ‘준비 포함’ 등을 덧붙이지 않음. 실제 비교 검사는 통합 작업에서 수행 |
| 수정·취소·시작 후 선택 날짜·읽던 위치 소실 | **이 연구에서는 미재현.** UI 동작 검토 범위 | 구현 담당의 좁은 상태 전환 검사로 확인. 보고서만으로 수정 완료 주장 금지 |
| 시작 버튼이 비활성인 이유 불명 | **차단 조건 확인, 화면 이해도 미검증.** 몸 상태, 전체 시간, 기존 계획, 계정 capability·저장 충돌 등 원인이 분리돼 있음 | 버튼 근처에 현재 해결 가능한 원인과 행동 표시. 안전 체크를 단순 확인 한 번으로 합치지 않음 |
| 기록과 다음 계획 관계 불명 | **경로 있음, 전체 적응은 아님.** 정확한 일지 연결·RPE/수행 비교와 제한된 후속 감량이 구현돼 있음 | 사용한 기록·유지/변경 이유 표시. 미연결/미측정 기록을 반영했다고 하지 않음 |
| 7·9·10일을 독립 주기로 오해 | **정적 근거 확인.** 기준 원장은 9.5일 고정, 가용일은 기간별 재배치 | 표시기간과 훈련 단위 분리. 새 주간 설계는 기존 enum만 바꾸어 구현하지 않음 |
| 휴식일이 많으므로 계획이 비효율적이라는 추정 | **효과 근거 없음.** 휴식 수는 원본의 달력 날짜 집계, 사용자 활동 전체/회복 완료를 뜻하지 않음 | 총횟수보다 실제 강도·시간·목적·선택조건을 먼저 설명. 휴식 숫자를 줄이려는 임의 증량 금지 |

## 6. 지금 연결할 것과 다음 결정

| 분류 | 결정 | 다음 작업·완료 조건 |
|---|---|---|
| 현행 유지 | 기존 용량·강도·동일 종목 RP·안전·19반일·저장 원본 | UI 전후 실제 처방/합계/시작 대상이 같음. 시간·경험을 바꾼 결과는 기존 생성기의 새 결과로만 생성 |
| 기존 기능 연결 | 반영 조건 표시, 구간 순서, 하나의 선택 날짜, 일지에서 당시 계획 비교, 허용된 미래 편집, 다음 주기 유지/감량 이유 | 날짜 이동은 저장하지 않음. 입력 취소·실패 시 원본 유지. 비교 불가/기록 없음/회복 완료를 구별 |

| 새 규칙 검토 필요 | 고정 요일 기반 7일 생성기 | 대상 종목·경험, 가용 요일, 주요 훈련/회복 배치, 연속 주 경계, 누락/경기 충돌, 기존 계획 이전 정책을 하나의 버전 있는 원본으로 확정. 본 보고서로 활성화하지 않음 |

이번 연구의 권고 순서는 **설명·동선 정합성 → 실제 기록과 연결된 기존 수정/다음 주기 → 고정 요일 요구를 받는 새 주간 설계 검토**다. 새 주기 연구 때문에 현재 화면 개선 배포를 늦추지 않으며, 화면 개선이 훈련 효과를 입증했다고 보고하지 않는다.
