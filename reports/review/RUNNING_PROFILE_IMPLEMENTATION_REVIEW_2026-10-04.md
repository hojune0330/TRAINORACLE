# 오라클 러닝 프로필: 첫 구현과 검수

Date: 2026-10-04
Base: `9839a6fb`, checkout `TRAINORACLE-multi-event-pace-release-20261002`
Status: LOCAL_IMPLEMENTATION; production release not executed.

## 1. 디렉터 결정

진입점은 오라클의 `내 러닝 프로필`이다. 흥미를 유발하는 짧은 질문과 자기 설명을
제공하지만, 검증되지 않은 MBTI 점수나 생리학적 유형 판정은 붙이지 않는다.

| 영역 | 이번에 구현한 것 | 구현하지 않은 것 |
|---|---|---|
| 취향 | 첫 3문항 + 선택형 추가 6문항, 복수 동기, 수정/삭제 | 검사 점수, 확률, 고정 16유형 |
| 경기 기록 | 기존 출처 관문을 통과한 같은 종목 기록 비교 | GPS 피크 기반 MSS/ASR, 선천적 재능 |
| 최근 훈련 | 일지의 적격 목적별 횟수와 기간 | 실제 대사 기여율/정답 비율 |
| 변화 | 월별 RPE 중앙값과 설명 | 훈련 효과/체력 저하/회복 완료 확정 |
| 보관 | 기존 암호화 계정 문서 + 임시 아웃박스 + 버전 충돌 확인 | 기기 저장을 계정 저장으로 표시 |

좋아함, 경험 없음, 실행 제약, 실제 행동을 서로 대신하지 않는다. 목표/처방/안전
엔진에는 새 응답을 연결하지 않았다. 원문 메모, 개인 이름, 외부 AI 전송, 포인트,
친구 자동 공유는 추가하지 않았다. 기존 경기 기록이 있어도 날짜가 없거나 목표뿐인
경우에는 무조건 기록 없음으로 표시하지 않는다.

## 2. 사용자 흐름

1. 오라클 → 내 러닝 프로필 → 3문항으로 시작.
2. 동기는 여러 개 선택 후 다음. 강도·동행은 탭하면 다음 화면.
3. 선택을 건너뛰어도 결과 확인 가능. `아직 모름`은 실제 응답으로 보존.
4. 취향 / 경기 기록 / 최근 훈련 / 변화 네 화면을 짧게 전환.
5. 대회·종목·보조운동·웨이트·제약은 원할 때 추가. 결과 수정·응답 삭제 제공.
6. 뒤로가기·앞으로가기에도 열린 프로필의 응답 유지. 닫으면 게스트 체험은 초기화.
7. 게스트는 저장 없는 체험이라고 표시. 로그인 응답은 서버 확인 후에만 저장 완료.

첫 화면에 긴 연구 설명은 넣지 않는다. 출처 종류는 항상 표시하고 근거와 한계는
접힌 설명에 둔다. 기본/전문 사용자를 갈라 정보를 숨기거나 처방을 바꾸지 않는다.

## 3. 저장·동시 수정

- `RUNNING_PROFILE` 계정 문서, 소유자별 고정 ID, 엄격한 입력 필드 허용 목록.
- 새 서버/DB 지원 여부를 먼저 확인. 구버전·장애·조회 실패는 빈 응답으로 처리하지 않음.
- 기존 암호화 IndexedDB 아웃박스와 Web Locks, 서버 CAS 사용.
- 확인 응답을 잃으면 원래 작업 ID와 바이트를 재전송. 두 번 저장된 것으로 만들지 않음.
- 편집 중 다른 기기의 응답이 바뀌면 재확인. 삭제된 원격 문서 자동 부활 금지.
- 계정 변경·화면 종료 뒤 지연 응답은 표시하지 않음.
- 온라인 복귀/창 복귀 시 안전하게 보관된 대기 응답 재시도. 미보관 입력은 이탈 확인.
- 질문 도중 제출 전 입력은 메모리 상태다. 앱 강제 종료까지 자동 복원한다고 약속하지 않음.
- 현재 응답 삭제는 빈 응답 문서 저장. 기존 수정본 보관 정책까지 즉시 삭제한다고 약속하지 않음.

기기 키와 암호화 임시 저장은 동일 출처 XSS나 기기 운영자에 대한 완전한 보호를
뜻하지 않는다. 브라우저 데이터 삭제/퇴거 가능성도 남는다. 서버 확인 전에는
계정 보관 완료라고 하지 않으며, 게스트 답을 로그인 계정에 자동 이전하지 않는다.

## 4. 검수와 수정

| 발견 | 수정 |
|---|---|
| 새 화면을 닫기 처리에서 빠뜨릴 수 있음 | 공통 닫기/과거 history 무효화에 새 화면 추가 |
| 계정 재조회 중 예전 캐시를 확인 완료로 표시 | 재조회 완료 전 LOADING, 실패 시 FAILED |
| 편집 도중 계정 버전이 바뀌면 반복 실패만 안내 | 새 계정 답변 비교와 명시적 저장/계정 선택 제공 |
| 결과 탭 사이 이동으로 질문 이력이 불어남 | 결과 탭은 history 교체, 질문 이동은 보존 |
| 긴 복수 응답을 제목에 전부 나열 | 짧은 제목 + 전체 답변은 아래 목록에 보존 |
| 320px 탭 글자가 어색하게 나뉨 | `취향`으로 축약, 한국어 단어 경계 우선 줄바꿈 |
| 경기 시간 막대가 길수록 능력이 좋아 보일 수 있음 | 경기 기록은 날짜와 시간으로 비교 |
| 거리 집계가 몸의 반응으로 대신 나타날 수 있음 | RPE가 아니면 반응으로 표시하지 않음 |
| 계획 기능 활성 여부와 일지 수신 상태가 혼동될 수 있음 | 로그인 일지는 READY 확인을 추가 |

## 5. 검증 증거

Node 24.19.0. 전부 합성 데이터/로컬 환경이며 실제 회원 응답을 사용하지 않았다.

| 구분 | 결과 | 증명 범위 |
|---|---|---|
| 관련 단위·계약·화면 7파일 | 52/52 PASS | 응답, 저장 프로토콜, 기존 Oracle/탐색 회귀 |
| 계정 서버 핸들러 전체 파일 | 77/77 PASS | 암호화, 인증, 소유권, 충돌, 새 capability 및 기존 경계 |
| 새 DB 로컬 PGlite | 2/2 PASS | 관련 마이그레이션 체인+0051, 새 종류 CAS, 재시도, 보상 제외, 익명 차단 |
| 생성된 계정 검증기 | 최신 일치 + 2/2 PASS | 브라우저/서버 스키마 일치, 서버의 브라우저 의존 방지 |
| 실제 Chromium 저장 테스트 | 1/1 PASS | 실제 암호화 IndexedDB, 서비스 재열기, 잃은 확인 재시도, 충돌, 계정 격리 |
| 배포용 빌드의 화면 흐름 | 4/4 PASS | 320/375/1440px, 200% 텍스트, 키보드, 줄인 모션, 뒤로가기/닫기 취소 |
| 타입 검사 | app + e2e PASS | TypeScript 계약 |
| 빌드 | PASS | 번들 생성; 공개 배포 아님 |
| 변경 형식 검사 | PASS | 공백/패치 형식 |

30개 고정 난수 시드로 각각 80번, 총 2,400번의 응답 편집을 검사했다. 이는
무작위 선택에 대한 합성 검사이지 30명 사용자 조사나 독립 심리검증이 아니다.

결함 주입: `JOURNAL_HANDLER_MUTATION=running-profile-identity`로 메모리에 올린
서버 모듈에서 소유자별 ID 검사를 제거했을 때, `running profile requires support
and protects identity, privacy and reward metadata`가 **200 != 422**로 실패했다.
디스크의 원본 경계는 변경하지 않았다. 정상 소스는 해당 검사와 핸들러 77건 통과.

처음 Vitest 기본 fork 실행은 테스트 시작 전 워커 타임아웃이었다. 성공으로 세지
않았고 threads 단일 워커로 실제 테스트를 실행해 위 결과를 얻었다.

빌드에는 기존 폰트 상대 경로, 정적/동적 import 혼용, 큰 번들 경고가 남아 있다.
이번 빌드 통과를 번들 최적화 완료나 모든 경고 해결로 표시하지 않는다.

## 6. 공개 전 남은 실행

아직 커밋/푸시/PR/CI/운영 DB 변경/Edge Function 배포/Pages 배포를 하지 않았다.

1. 문서·코드 변경 묶음 리뷰와 커밋. 현재 다른 작업트리 작업은 건드리지 않음.
2. 기존 운영 변경 절차로 `0058_running_profile_account_storage.sql` 적용 (main 인증·목적 동의 이력 충돌로 0051/0057에서 이동).
3. 새 검증기를 포함한 account-journal 서버 배포, 지원 응답 확인.
4. 프런트 배포, 실제 로그인 계정에서 응답 저장/재열기/계정 전환 확인.
5. iPhone Safari·다른 실제 기기 간 응답 수정 확인. Chromium 모의 모바일과 구분.

DB → 서버 → 프런트 순서. 구버전 서버에서는 저장 성공처럼 우회하지 않고 확인
실패를 표시한다. 로컬 테스트용 원격 응답 모형은 운영 로그인 증거가 아니다.
공개 시 선택형 선호 응답의 처리 목적·보관 안내가 실제 개인정보 고지와 맞는지도 확인한다.
작업은 이 로컬 구현·검수 지점에서 종료하며 백그라운드 개발은 이어지지 않는다.

## 7. 후속 연구와 제품 방향

이번 첫 버전의 장점은 입력이 짧고 자기보고와 관찰 자료의 구분이 명확하며,
기존 처방에 잘못된 권위를 추가하지 않는다는 것이다. 한계는 검증된 유형 점수,
생리학적 능력 프로필, 선호와 행동의 정량 비교, 친구 공유가 아직 없다는 점이다.

다음은 문항 이해도 확인과 자료 적용 범위 보강을 우선한다. 선호를 바탕으로 한
재미있는 표현은 가능하지만 통계 검증 없는 확률/백분위로 포장하지 않는다.
CS/ASR, 원 척도 사용, 처방 변경, 친구 공유는 각각 연구/안전/동의 관문을 갖춘 뒤
추가한다. 연구 백로그는 별도 근거 문서에 보존했다.
