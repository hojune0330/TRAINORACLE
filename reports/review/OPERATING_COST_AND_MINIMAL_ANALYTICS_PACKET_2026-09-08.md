2026-09-08 공식 문서를 직접 확인했다. 현재 우리 계정의 청구·SMTP 설정을 열어본

SMTP가 연결되어 있다면 새로 가입하지 말고 그것부터 확인한다.

## 2. 비용 검토를 위한 예상 사용량

다음은 수요 예측이 아닌 산술 시나리오다. 로그인 세션을 유지하면 매일 인증 메일이
필요하지 않으므로 활성 사용자 수를 발송 수로 바로 치환하지 않는다.

- 200명이 첫 가입에 각각 1통: 200통. 재발송·계정 복구는 별도.
- 200명이 한 달에 각각 4회 이메일 인증: 800통/월.
- 200명이 30일간 매일 인증: 6,000통/월, 하루 200통. 이는 불필요한 재로그인 버그가 없는지도 확인할 스트레스 시나리오다.
- Google 로그인 비중과 세션 유지에 따라 실제 이메일 수요가 달라진다.

권장: 기존 발송 서비스·도메인 소유를 먼저 확인하고, 동시 가입량과 재발송을 포함한
요금안을 제시한다. 카드 등록·유료 전환은 항목별 월 예상액과 상한 승인 뒤에만 한다.
문자 인증은 이번 초기 순서에서 후순위이므로 공급자 계약과 실번호 발송을 시작하지 않는다.

## 3. 최소 행동 통계의 구체적 제안

승인된 목적은 사용자가 어디서 막히는지 개선하는 것이다. 운동 내용과 개인을
분석하는 것이 아니다. 다음은 구현 전 검토안이며 지금 전송을 켜지 않는다.

| 제안 이벤트 | 허용 결과 | 금지 정보 |
|---|---|---|
| JOURNAL_SAVE_RESULT | SUCCESS / STORAGE_FAILURE / VALIDATION_FAILURE | 일지 ID·제목·메모·통증·운동 수치 |
| PLAN_SELECTION_RESULT | COMPLETED / CANCELLED / VALIDATION_FAILURE | 선수 기록·페이스·템플릿 조합·나이·신체 정보 |
| AUTH_FLOW_RESULT | SUCCESS / CANCELLED / PROVIDER_FAILURE | 이메일·전화·토큰·계정 ID·원시 오류 |
| CONTENT_OPEN | 발생 횟수 | 읽은 글의 민감한 분류·사용자 프로필 |

각 이벤트는 고정 enum으로 직렬화한다. 임의 문자열 속성, 전체 URL/query,
사용자 식별자, 브라우저 지문, 세션 녹화, DOM, 원시 에러 스택을 받지 않는다.
여러 이벤트를 개인별로 연결하지 않는 첫 버전은 정확한 사용자별 전환율이나
재방문율을 계산할 수 없다. 이벤트 건수를 사용자 수라고 표시하지 않는다.

초기 선택안은 기존 서버에서 허용 이벤트의 일 단위 합계만 보관하는 방식이다.
이것도 서버 요청 로그에 IP가 남을 수 있으므로 자동으로 익명이라고 주장하지 않는다.
로그 설정·동의/철회 UI·보관 기간·최소 표본 표시 기준을 적용 전에 검토한다.
인증/서비스 이용에 필수라는 식으로 분석 동의를 강제하지 않는다.
수집 거절·전송 실패가 일지 저장이나 계획 생성 실패로 이어져서는 안 된다.

## 4. 포인트 합산 검토에 실제로 확인한 기존 값

`app/src/domain/engagement.ts`에서 방문 1P/일, 적격 일지 4P/일을 확인했다.
현재 로컬 원장은 방문 날짜와 일지 날짜로 중복을 제거한다. 콘텐츠 완독 원장은
없다. `training-content-store.ts`는 현재 알려진 콘텐츠 ID의 북마크만 저장한다.

새 콘텐츠 1P/첫 완독, 일 최대 10P를 합치면 이 세 가지 획득 경로의 하루 최대는
1 + 4 + 10 = 15P다. 이는 이 경로의 산술 상한이며 모든 향후 보상까지 포함한
전역 상한이나 변경 승인으로 해석하지 않는다.

적용 전 시험: 구 버전 잔액 보존, 이미 구매한 재료 보존, 반복 방문·새로고침·
문서 개정 재지급 금지, 일 10개 상한, 잘못된 ID 거부, 저장 실패 시 지급 성공
표시 금지, 계정 동기화가 적용되는 경우 두 기기 중복 제거. 로컬 전용인 동안에는
두 기기 사이 통합 지급을 이미 보장한다고 표시하지 않는다.
