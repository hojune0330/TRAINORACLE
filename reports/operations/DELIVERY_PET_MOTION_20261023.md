## 제작·검사 근거

- 편집 원본·Tripo 원본·프롬프트·해시·실제 비용은 `character-art/pet-motion-v1/`에 있다.
- 이번 확장에 Studio 220크레딧을 사용했고 마지막 확인 잔액은 1,060이었다.
  새 결제나 API 충전은 하지 않았다. 이 수치는 제작 당시 기록이다.
- 기존 집중 검사와 TypeScript 결과, 375×844 실제 돌보기·잠자리 검수는
  `character-art/pet-motion-v1/review/expansion-runtime-check.json`에 남아 있다.
- 최종 커밋의 필수 검사는 GitHub `TrainOracle CI` 실행으로 확인한다.
  제작 시점의 `DELIVERY.json`은 배포 영수증이 아니며 `published:false`는 당시 상태다.
- 병합 시 추가로 실행한 로컬 방 잠금 검사는 Windows worker가 시작되지 않아 미실행이다.
  권한 환경을 바꾼 한 차례 재시도도 같았다. 통과로 세지 않으며 최종 CI가 해당 검사를 포함한다.
- 첫 CI `39888950879`의 UTC/KST 단위 검사에서 이전 기록 이관 사례 두 건이 실패했다.
  v1 테스트 자료를 최신 `createHome`에서 만들어 v2 소품 필드까지 섞은 것이 원인이었다.
  v1 자료를 당시 저장 형식으로 고정했고, 이관 후 소품 기본값도 확인한다.
  실제 저장 로직·이관 검증·보존 조건은 바꾸지 않았다. 최종 재검사 결과는 수정 커밋의 CI를 따른다.
- 수정 뒤 Windows 검사 실행을 별도 프로세스(`forks`)로 바꿔 해당 이전 기록·방 잠금
  두 파일의 15개 검사를 통과했다. 이 실행 방식 변경은 로컬 명령에만 적용했다.
- 두 번째 CI `39891286287`은 UTC/KST와 실제 배포 화면 4종을 통과했고,
  320px 검사 전용 화면의 빠른 일지 입력 1건만 실패했다. 첫 답변 직후 같은 위치를
  자동으로 다시 클릭해 기존 400ms 연속 입력 방지가 동작한 경우다. 같은 목적의
  기존 `launch-ready` 검사와 같이 다음 답변을 키보드로 명시적으로 선택하도록 고쳤다.
  제품 동작·연속 입력 방지·기존 단언은 유지한다. 수정한 320px 사례 1건은
  로컬 실제 브라우저에서 22.9초에 통과했고, 최종 CI를 다시 확인한다.

## 수동 게시와 공개 확인

커밋의 `[manual-pages]`는 자동 게시만 막는다. 검사 생략 표식은 사용하지 않는다.
해당 커밋의 필수 관문 통과 후 유지보수 중인 build/publish 도구와 `--account-held`로
최신 `gh-pages` 위에 정상 커밋을 게시한다. 기존 preview·이전 해시 자산·저장 키를 보존한다.

공개 완료는 [정식 배포 영수증](https://hojune0330.github.io/TRAINORACLE/trainoracle-deploy-receipt.json)의
`sourceSha`, GitHub Pages의 게시 커밋과 `built`, 공개 동작 파일을 대조해서 판단한다.
이 문서의 작성이나 제작 검수 통과만으로 공개 완료를 뜻하지 않는다.
펫 기록은 기존 브라우저 저장 범위이며 계정 공개·다른 기기 동기화·실제 사용자 기록 쓰기는 이번 범위가 아니다.
