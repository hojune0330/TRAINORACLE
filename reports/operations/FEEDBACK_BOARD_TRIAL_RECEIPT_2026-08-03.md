- 만료 경계 보정 확인: 2026-08-03 03:25 KST
- 시험 프로젝트 ref: `texspxlpjungyarkvtkc`
- Region: Seoul (`ap-northeast-2`)
- 공개 계정·동기화·공유 상태: 계속 OFF
- 시험 종료 시 서버 `FEEDBACK_BOARD`: OFF

## 적용 결과

Supabase CLI `2.111.0`으로 `0025_feedback_board_abuse_retention.sql`과
`0026_feedback_board_expiry_boundary.sql`을 시험 프로젝트에 적용했다. 적용 뒤
migration 목록에서 로컬과 원격 모두 `0001`부터 `0026`까지 일치했다.
`0026`은 만료됐지만 아직 정리되지 않은 문의를 숨기고 사용자·운영자 댓글로
되살리지 못하게 막는다. 비밀번호·access token·anon key·service role key는 이
영수증과 Git에 기록하지 않았다.

## 실제 RPC 시험

합성 문의만 사용했고 시험이 끝난 뒤 모두 삭제했다.

| 확인 항목 | 실제 결과 |
|---|---|
| 서버 스위치 OFF에서 새 문의 | 거부 |
| 같은 문의 요청 재전송 | 같은 문의 1건 유지 |
| 내 기기 영수증으로 목록 읽기 | 1건 확인 |
| 다른 영수증으로 목록 읽기 | 0건 |
| 다른 영수증으로 댓글 추가 | 거부, 내부 서버 오류로 노출하지 않음 |
| 같은 댓글 요청 재전송 | 같은 댓글 1건 유지 |
| 익명 사용자의 운영자 목록 호출 | HTTP 401, SQLSTATE 42501로 거부 |
| 운영자 전용 목록으로 문의 발견 | 성공 |
| 운영자 답변 뒤 사용자 화면 재조회 | `TrainOracle 답변` 확인 |
| 다른 영수증으로 문의 삭제 | `false`, 삭제 안 됨 |
| 소유 영수증으로 문의 삭제 | 성공 |
| 만료 문의 정리 함수 | 서비스 역할에서만 실행 성공 |
| 만료됐지만 아직 정리되지 않은 문의 조회·댓글·운영자 답변 | 합성 문의로 모두 거부 확인 |
| 동시 댓글 60건 공격 | 49건 수락, 11건 거부, 최초 글 포함 정확히 50건 저장 |
| 영수증을 61번 바꾸는 도배 | 60건 수락 뒤 61번째 거부, 삭제 후 잔여 0건 |
| 시험 데이터 잔여 | 0건 |

만료 경계 시험은 한 트랜잭션 안에서 합성 문의를 만든 뒤 사용자와 운영자
양쪽 경로를 확인하고 되돌렸다. 이후 별도 조회에서 합성 문의, 만료 문의 모두
0건이고 서버 `FEEDBACK_BOARD`가 다시 OFF임을 확인했다.

## 공개 조건

이 영수증은 시험 서버의 데이터 경계가 작동했다는 증거다. 공개 앱에서 문의판을
열 때는 아래 세 값이 모두 맞아야 한다.

1. 서버 `FEEDBACK_BOARD=true`
2. `TRAINORACLE_FEATURE_FEEDBACK_BOARD=true`
3. `TRAINORACLE_KILL_FEEDBACK_BOARD=false`

문제가 생기면 서버 스위치를 먼저 닫고 kill 변수를 켠다. 로컬 일지, 계정 OFF,
동기화 OFF, 공유 OFF 상태에는 영향을 주지 않는다.
