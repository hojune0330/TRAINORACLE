## 한 줄 결론

현재 공개 사이트는 **회원가입 없이 기기에 저장하는 무료 일지와 로컬 훈련계획 베타**로 사용할 수 있다. 계정, 동기화, 원격 공유, 서버 기반 코치 계획 제안, 제품 분석은 운영 DB 적용 영수증과 공개 설정이 없으므로 계속 닫아 둔다.

이 문서는 외부 전문가의 승인을 요구하지 않는다. 서비스 운영자가 기능별 증거를 확인하고 하나씩 공개하거나 닫는 기준만 고정한다.

## 운영 DB 영수증

> 아래 `0001`~`0018` 목록과 실행 순서는 이 문서가 작성된 당시의 역사 기록이다.
> 현재 실행에는 `docs/SUPABASE_SETUP.md`의 `0001`~`0026` 절차만 사용한다.

저장소에는 `0001_journal_sync.sql`부터 `0018_server_operations.sql`까지 18개 migration이 순서대로 있다.

| 확인 항목 | 상태 | 공개 판단 |
|---|---|---|
| 운영 Supabase 적용 영수증 | 없음 | 운영 DB에 적용됐다고 간주하지 않음 |
| 시험 Supabase 적용 영수증 | 없음 | 서버 기능 공개 준비가 끝났다고 간주하지 않음 |
| 저장소 Actions 변수 | 계정·기능 공개 변수 없음 | Pages 공개판의 서버 기능은 닫힘 |
| `github-pages` 환경 변수 | 계정·기능 공개 변수 없음 | 배포 환경의 우회 공개 없음 |
| 저장소·환경 secret | Supabase 공개 설정 없음 | 공개판에서 계정 연결 불가 |

영수증이 없다는 것은 migration 코드가 틀렸다는 뜻이 아니다. **실제 DB에서 실행됐다는 증거가 없으므로 공개 권한도 주지 않는다**는 뜻이다.

## 기능을 여는 순서

한 번에 여러 기능을 열지 않는다. 각 단계는 앞 단계가 정상일 때만 진행한다.

1. 운영과 분리된 시험 Supabase에 migration 0001~0018을 순서대로 적용하고 프로젝트·시각·migration 목록·성공 결과를 영수증으로 남긴다.
2. 계정만 연다. 동기화·공유·계획·분석은 계속 닫아 둔다. 로그인, 만 14세 미만 보호자 확인, 삭제와 30일 정리 경로를 확인한다.
3. 동기화만 추가로 연다. 서로 다른 두 계정의 자료가 섞이지 않고, 나만의 메모 평문이 서버·로그·분석에 나타나지 않는지 확인한다.
4. 공유를 연다. 자격 미확인 표시, 초대·철회·시즌 갱신, 미성년자 최초 연결 확인을 점검한다.
5. 계획 제안을 연다. 선수 확인 전 활성 계획이 바뀌지 않고 경고 계획이 두 번 확인되는지 점검한다.
6. 제품 분석은 별도 선택 동의와 30일 삭제 작업의 실영수증을 확인한 뒤 마지막에 연다.
7. 실험 피로도는 위 서버 기능과 별개로, 원하는 사용자에게만 보이는 실험 표시를 재확인한 뒤 결정한다.

각 단계에서 문제를 발견하면 그 기능만 다시 닫는다. 전체 무료 일지를 멈추지 않는다.
