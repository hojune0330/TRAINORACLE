## 판단과 현재 범위

연구 8건은 사회비교·게임화 효과가 맥락에 따라 다름을 보인다. 회고·수집·아바타의 재방문·훈련안전 효과는 미확인이다. 모듈은 검증 전 가설이다.

부모 제공 코드 인벤토리(미재검증): `friend-running-oracle.ts` 공유 입력은 `BEST_RECORD`, `RECENT_DISTANCE`, `ENERGY_HISTORY`뿐; 취향·캐릭터·설문은 공유 불가. 함께 달리기는 공동 준비·마무리, 각자 페이스, 회복 중 재집결이라는 정적 출력이다. 공통 선택 x/y에는 신규 스키마와 문항·상대·목적별 동의가 필요하다.

## 안전·검증 및 조사 한계

거리/강도 증가, 휴식일 보충, 매일 출석, 친구 앞서기와 보상·장식 해금을 묶지 않는다. 친구 공유는 항목·상대·기간·목적별 사전 동의, 최소 입력, 미성년·코치 정책, 즉시 철회가 선행되어야 한다. 현재 payload로 공통 선호나 캐릭터 궁합을 만들 수 없다. 시험 시 재방문·저장·공유와 활동량을 분리하고 압박감·연속 불안·알림 끔·연결 해제를 중단 지표로 기록한다. 회고·수집·아바타의 재방문 효과와 안전성은 미확인이다.

Exa 미설정. 문서화된 Reddit OpenCLI 검색을 1회 시도했으나 결과 내용이 없어 사용하지 않았고, 중복 회피를 위해 Reddit 댓글은 수집하지 않았다. 내장 웹 검색 및 페이지 직접 열기를 사용했다. Jina Reader는 접근 불가; CAPTCHA·렌더 실패·초록·검색 발췌는 출처별 표시했다.

## R2 부록: 라이브러리 연결과 재방문 운영안

### 1. PB 카드와 기존 페이스 미리보기의 경계

M12의 “증량·잠재력 추론 금지”는 새 PB 프로필이 훈련 처방·계획을 자동 변경하지 않는다는 뜻이다. 기존 승인된 기록→페이스 변경 미리보기 경로는 막지 않는다. 라이브러리 B06의 목표/실제 구분과 기존 진입 조건을 그대로 적용한다. 미리보기는 제안 검토이지 저장·적용이 아니며, 기록 확인과 기존 안전·적용 절차는 별개로 유지한다.

### 2. 52주제 라이브러리 대비 친구 입력 단계

라이브러리 E01~E06 검토 결과다. 현재 코드 상태는 부모 제공 인벤토리와 `05-data-and-editorial-boundaries.md`의 D-FRIEND 대조를 사용했으며, 이번 R2에서 코드를 재검증하지 않았다.

부모 라이브러리는 A~H의 52개 독립 질문(6+7+7+8+6+6+6+6)이지 52개 재방문 화면이 아니다. M01~M16은 B/G의 기록·회고와 E의 친구 콘텐츠를 다시 묶는 전달 방식이며, 새 친구 취향 수집은 E03/E04에만 한정한다. E01/E02/E05 및 B06을 복제하거나 대체하지 않는다.

### 3. 여섯 방문 순서와 카피

각 방문에서 질문은 0~1개, 응답은 선택 사항이다. `닫기`/`건너뛰기`는 항상 보이고, 무응답 뒤 독촉·연속 방문 알림은 보내지 않는다.
아래 카피의 5km·4회는 합성 예시이며 실제 사용자 기록이 아니다.

| 방문 | 콘텐츠 순서와 한 줄 카피 | 선택 질문(최대 1개)·조용한 종료 |
|---|---|---|
| 시작 | 인사 → 입력 범위/기준일 → 나와 과거·동의된 친구·비교 끔 선택. **“먼저 내 기록에서 확인된 장면부터 볼게요.”** | “어떤 장면부터 볼까요?” 선택하지 않아도 기본 카드만 열고 닫기 가능. |
| 새 PB | 종목·거리·기록·날짜·출처 확인 → 동조건 과거 기록 나란히 → 원하면 기존 페이스 미리보기 진입. **“새 5km 기록을 지난 확인 기록과 나란히 정리했어요.”** | “기존 기록을 바탕으로 페이스 변경 미리보기를 열까요?” 미리보기 진입은 기존 승인 조건에 한함; 거절·닫기 무알림. |
| 월말 | 기간·자료 범위/누락 → 월간 사실 → 같은 조건의 지난달/동의된 친구 비교. **“이번 달에 확인된 기록은 4회예요; 미수신 자료는 합계에 넣지 않았어요.”** | “나만 볼까요, 동의된 기록과 비교할까요?” 유효한 동의·동일 기준 없으면 개인 기록만; 닫기. |
| 새 자료 없음 | 마지막 갱신일 → 저장 장면 또는 일반 읽을거리. **“새 기록은 아직 없어요; 저장한 풀이와 일반 읽을거리는 그대로 열 수 있어요.”** | “보관한 이야기를 다시 볼까요?” 무응답이면 현재 화면 유지 후 조용히 닫기. 새 분석 생성 안 함. |
| 공백 후 복귀 | 환영 → 지난 장면/새로 시작/건너뛰기. **“다시 왔네요; 지난 결과는 그대로 두었고 밀린 훈련은 만들지 않았어요.”** | “지난 풀이를 이어 볼까요?” 선택 답을 받지 않아도 닫기; 공백일·깨진 연속 표시 없음. |
| 동의 철회 | 즉시 접근 차단 → 관리되는 저장/파생물 무효화 상태와 외부 복사 한계 표시. **“비교 접근을 닫았어요; 관리되는 결과는 무효화 처리 중이고 외부 저장 이미지는 회수할 수 없어요.”** | 질문 없음. 처리 상태/도움말만 선택 제공, 완료 버튼으로 조용히 종료; 재동의 유도·알림 없음. |

### 4. 철회 후 남을 수 있는 사본 5종과 처리

다음은 설계상 위험·처리 요구이며 현재 구현 완료를 뜻하지 않는다. 즉시 보장할 것은 신규 접근·생성 차단이고, 물리적 삭제는 각 보관 위치의 검증이 필요하다.

| 잔존 위험 | 처리 원칙·한계 |
|---|---|
| 앱 메모리·로컬 저장·보관함에 남은 풀이 | 철회 이벤트에서 비교 화면/보관 항목 무효화, 로컬 재표시 차단 후 삭제·동기화. 재접속·오프라인 캐시 경로도 확인한다. |
| 서버 파생 풀이·공유 링크·썸네일·CDN 캐시 | 원본 관계/필드 권한을 철회 즉시 거부하고 파생 ID를 폐기·재계산 제외; 관리되는 URL 취소 및 CDN purge 결과를 확인한다. |
| 다운로드한 이미지·기기에 저장한 캡처 | 신규 생성·재공유와 관리 링크는 차단한다. 이미 다운로드·복사된 외부 파일을 원격 회수할 수 있다고 약속하지 않고, 공유 전 이 한계를 알린다. |
| 친구가 이미 본 화면·저장본·알림 미리보기 | 이후 열람·푸시를 중단하고 필요 시 사실대로 철회를 알린다. 수신자의 캡처·기억·외부 재게시 삭제는 보장할 수 없다. |
| 백업·분석 로그·대기 작업·복원본 | 대기 작업 취소, 복원 시 tombstone/권한 재검사, 백업 만료기한과 로그 최소화 명시. 콘텐츠 원문을 감사 로그에 복제하지 않고 만료까지 잔존을 고지한다. |
