## 1. 결론: AI 대화창보다 훈련을 이해할 수 있는 결과물을 먼저 만든다

권장 방향은 **자료 정리 → 계산 → 비교 → 검토된 설명 → 허용된 다음 선택**이다.

외부 AI 없이도 선수에게 다음을 제공할 수 있다.

- 코치에게 받은 훈련을 반복·세트·운동·회복으로 풀어 설명한다.
- 실제로 기록된 거리·시간·반복 수행과 계획을 나란히 비교한다.
- 주간·월간 거리와 훈련 목적별 누적을 근거 수치와 함께 보여준다.
- 비슷한 훈련을 했던 과거 날짜를 찾아 비교한다.
- 승인된 계산과 템플릿 범위 안에서 개인 기록 기준 페이스와 서로 다른 훈련 후보를 제공한다.
- 사용자가 공유하거나 코치와 검토할 수 있는 훈련표·요약 자료를 만든다.

이는 단순 기록 보관으로 후퇴하는 것이 아니다. 훈련 설계와 근거 있는 코칭을 담당하는 코어를 먼저 강화하는 순서다. 로컬 LLM이 완성될 때까지 기다릴 필요도 없다.

여기서 줄이는 것은 **외부 생성형 AI로 선수 자료를 보내는 경로**다. 계정 서버, 온라인 저장, COROS 등 워치 연동 API까지 없애자는 뜻이 아니다. 온라인 저장을 기준으로 삼고, 미전송 임시 기록을 보호하는 기존 방향은 유지한다. 로컬 LLM 역시 정확성·권한·삭제·기기 성능 문제를 자동으로 해결하지 않는다.

## 3. 자료를 네 가지 용도로 나누면 위험을 줄이면서 활용할 수 있다

| 용도 | 사용자에게 주는 가치 | 허용 조건 |
|---|---|---|
| 원자료 확인 | 이 파일에 어떤 날짜·거리·훈련이 들어 있는지 확인 | 허용 파일 형식, 소유자, 단위, 날짜, 크기 제한과 미리보기 검증 |
| 기술적 분석 | 실제로 기록된 거리·반복·시간과 차이를 계산 | 해당 출처·필드의 분석 사용 규칙 채택 및 중복·충돌 처리 |
| 훈련 설명 | 구성의 의미와 알려진 원리·한계를 읽음 | 검토된 설명집 연결, 관측 사실과 일반 교육 내용 분리 |
| 다음 계획에 사용 | 개인 조건에 맞는 승인 후보를 선택 | 별도 처방 적격성·최신성·템플릿 채택·안전 조건 |

앞의 조건을 만족했다고 뒤의 권한까지 자동 획득하지 않는다. 반대로 처방에 쓸 수 없다는 이유만으로 합법적으로 확보한 자료의 유용한 정리·열람까지 모두 포기하지 않는다.

다만 **현재 제외된 외부 필드로 새로운 요약 통계를 만드는 것 역시 분석**이다. 이를 단순 미리보기라고 이름만 바꿔 활성화하지 않는다. 원자료 확인과 계산된 분석 화면은 계약과 UI에서 분리한다.

자료의 종류도 구분한다.

- **받은 훈련 계획:** 하기로 한 구성이다. 실제 수행으로 집계하지 않는다.
- **워치·직접 입력한 수행 기록:** 기록된 운동이다. 계획과 같았다고 가정하지 않는다.
- **경기 기록:** 종목·날짜·기록 방식·출처를 보존한다. 오래된 최고기록은 현재 컨디션 증거가 아니다.
- **사용자 느낌:** 직접 고른 RPE·기분 등이다. 심박수나 속도로 대신 채우지 않는다.
- **연구·훈련법 자료:** 일반 근거다. 특정 선수에게 같은 효과가 생긴다는 개인 증거가 아니다.

## 5. 첫 핵심 결과물: 내 훈련 해설표

한 훈련마다 다음을 한 자료로 제공한다. 첫 화면에는 수행 방법과 핵심 결과만 두고 상세는 펼쳐 본다.

1. **무엇을 하는가:** 거리형·시간형·복합형의 운동과 회복 순서.
2. **얼마나 하는가:** 본운동 반복 수·거리·알려진 운동시간·회복시간. 준비·정리운동은 별도 표시.
3. **어떤 목적이 적혀 있는가:** 사용자가 선택한 목적, 원계획의 명시된 목적, 규칙으로 분류한 후보를 구별.
4. **왜 이런 구성인가:** 검토된 설명집의 원리와 이 구성의 수치. 외부 코치가 실제로 의도한 이유를 추측해서 단정하지 않음.
5. **무엇과 비교할 수 있는가:** 같은 훈련의 이전 수행, 같은 목적의 다른 방법, 당시 조건과 차이.
6. **무엇은 아직 모르는가:** 회복 방식, 실제 완료 수, 미입력 RPE, 기준 기록 등 필요한 부분만 표시.

### 계산 예시: 주어진 표기를 해설 자료로 바꾸기

`10×400m 2set @5000m RP r60초 R3분`을 사용자가 **2세트, 세트당 10회, 반복 사이 60초, 세트 사이 3분**으로 확인했다고 가정한다. 세트 사이에는 반복 휴식에 세트 휴식을 더하지 않고, 세트 휴식으로 대체하며 마지막 반복 뒤 회복은 계산에서 제외하는 조건이다.

| 항목 | 계산 결과 |
|---|---|
| 본운동 반복 | 2 × 10 = 20회 |
| 본운동 거리 | 20 × 400m = 8,000m |
| 반복 사이 회복 | 2 × 9 = 18회, 18 × 60초 = 1,080초 |
| 세트 사이 회복 | 1회, 180초 |
| 계획된 회복 합계 | 1,260초 = 21분 |
| 본운동 수행시간 | 기준 페이스가 없으면 미정 |
| 전체 세션 시간 | 준비·정리·이동 등이 없으면 확정하지 않음 |

현재 표기 파서의 완성된 입력 예시라고 주장하는 것이 아니다. 원문에는 회복 방식이 없으므로 정지·걷기·조깅 여부를 별도로 확인해야 한다. 표기는 읽었지만 해당 선수에게 수행 가능한 적절한 훈련인지 채택한 것도 아니다.

확인된 5000m 기록이 18분 31초이고 같은 종목 RP 환산의 승인 조건을 만족한다면, 산술상 400m는 `1,111초 × 400 / 5,000 = 88.88초`다. 이 값은 **해당 기록의 평균 속도를 옮긴 참고값**이지 20회 수행 능력이나 권장 훈련량을 보증하지 않는다. 목표기록과 실제 최고·시즌 기록도 구분한다.

이런 자료가 이미 충분한 제품 가치다. AI가 자유롭게 쓴 문장 대신 같은 구조화 처방에서 도식·숫자·설명을 함께 만든다.

## 6. 누적 자료를 판단에 쓸 수 있게 만드는 분석

### 6.1 확인 가능한 사실부터

- 주간·월간 거리와 시간: 날짜 경계와 포함된 기록 수를 함께 표시.
- 예정 훈련, 완료 버튼, 실제 기록: 서로 다른 줄로 표시.
- 반복 수행: 실제 개별 반복 기록이 있을 때만 편차·후반 변화 계산.
- 훈련 목적 구성: 계획 의도와 사용자가 기록한 목적을 분리해 집계.
- 오전·오후: 같은 날 두 훈련을 하나로 합치지 않고 시간 순서 보존.
- 개인 기록 변화: 같은 종목·기록 조건을 확인한 뒤 추이 표시.

거리 합계가 낮아졌다고 훈련을 덜 했다고 단정하지 않는다. 기록 누락이나 기기 변경 때문일 수 있다. 시간·거리·RPE 각각 표본 수가 다를 수 있다.

### 6.2 비교는 비슷한 조건을 명시한다

`같은 방법`, `비슷한 구성`, `같은 목적`을 별도 비교 수준으로 둔다. 거리만 같아도 회복·강도·세트가 다르면 같은 훈련으로 합치지 않는다. 날씨·노면·고도·기기·기록 방식은 확보된 항목만 사용하고 없으면 모름으로 둔다.

예: “지난 기록보다 반복 평균이 2초 빨랐고 회복은 30초 길었어요.”는 관측 비교다. “회복을 늘려서 실력이 좋아졌어요.”는 그 자료만으로 할 수 없는 인과 판단이다.

최고기록 전 4주와 다른 시기를 나란히 보는 기능도 유용하다. 다만 잘된 시기만 골라 특정 훈련의 효과를 증명하지 않는다. 충분한 비교 표본이 없으면 일정표와 관측 사실만 보여준다.

### 6.3 에너지 시스템 분석은 명칭을 정직하게 사용한다

ATP-PC·해당과정·산화 대사는 에너지 공급 경로이며, BASE·LT·VO2 등은 훈련 분류다. 서로 같은 종류의 측정값으로 취급하지 않는다.

- “LT 목적 4회, GLY 목적 2회”는 기록된 훈련 유형의 횟수다.
- 세션 전체 시간이 있다고 그 시간을 한 대사 경로만 사용한 시간으로 계산하지 않는다.
- MIX는 명시된 구간 배분이 없으면 나누지 않는다.
- 계획 횟수·실제 횟수·알려진 운동시간의 비율은 분모를 각각 표시한다.
- 특정 목적이 적게 기록됐다고 해당 능력이 부족하다는 진단을 하지 않는다.

원하는 지표를 많이 만들기보다 **기록 범위 내에서 답할 수 있는 질문을 늘리는 것**이 목표다.

## 7. 개인화도 프로그램으로 할 수 있다

프로그램 기반이라는 말은 모든 사람에게 같은 훈련을 주겠다는 뜻이 아니다. 선택 조건과 계산 근거가 명확한 개인화는 가능하다.

권장 처리 순서:

1. 종목·주기 목적·가능 시간·시설·선호·승인된 선수 정보를 읽는다.
2. 이미 채택된 템플릿 중 적용 대상과 안전 조건에 맞는 것만 남긴다.
3. 목적은 같지만 실제 운동·회복 구조가 다른 후보를 고른다.
4. 공식과 기준 기록의 적용 조건을 만족하면 개인 참고 페이스를 계산한다.
5. 사용한 조건과 제외한 정보를 설명한다.
6. 사용자가 선택·조정·건너뛰기할 수 있게 한다.

기존 두 후보 원칙, 고정 짝짓기 금지, 실질적 구성 차이 검증, 오전·오후 및 소·중·대주기 연결을 유지한다. 다양성을 위해 무작위로 양·강도·빈도를 올리지 않는다. 현재 승인된 증감 조건을 유지하며 데이터가 많아졌다는 이유로 새 증감 권한을 만들지 않는다.

추천 순서를 설명하는 규칙은 사용할 수 있지만 “이 훈련과 궁합 93점”처럼 검증되지 않은 정밀 점수는 먼저 만들지 않는다. `시간에 맞음`, `같은 목적의 다른 구성`, `이전과 같은 방법`, `비교할 자료 부족`처럼 이유가 보이는 추천부터 제공한다.

청소년·혼자 훈련하는 사용자에게 일괄 제한을 새로 만들지 않는다. 종목·연령·경험 등은 기존 템플릿별 승인 조건으로 처리하고, 성별·학교 부문 이름만으로 운동 능력이나 적정 부하를 정하지 않는다.

## 8. 설명 원본과 계산을 같은 자료에 묶는다

새 자유서술 엔진을 만들기보다 기존의 세 층을 강화한다.

| 층 | 담는 내용 | 변경 책임 |
|---|---|---|
| 공통 용어집 | 정의, 흔한 오해, 별칭, 출처 | 용어·과학적 내용 검토 |
| 훈련별 설명집 | 목적, 운동·회복 구성 이유, 기대·한계, 적용 대상 | 정확한 템플릿·수치의 근거 검토와 채택 |
| 개인 보고서 | 실제 사용 입력, 계산 결과, 날짜·주기, 비교 조건·누락 | 해당 계산 코드와 출처 적격성 |

출력마다 원자료 참조, 단위, 계산 규칙 버전, 템플릿·설명 버전, 실제 사용 입력을 추적한다. 선수의 개인 자료와 학술 출처는 별도 목록이다. 서술을 바꾸면 내용 버전도 바뀌어야 하며, 과거 처방의 이유를 최신 설명으로 덮어쓰지 않는다.

“같은 입력이면 같은 출력”은 재현성을 뜻할 뿐 과학적 타당성을 보증하지 않는다. 잘못된 공식을 프로그램으로 만들면 같은 오류가 반복된다. 따라서 계산 정확성·출처 적격성·공식 적용 대상·화면 해석을 각각 검수한다.

## 9. 데이터 허용은 항목과 용도별로 채택한다

첫 외부 자료 분석 채택안은 다음 순서로 작게 잡는 것을 권장한다.

| 우선 | 항목·용도 | 반드시 정할 사항 |
|---|---|---|
| 1 | 운동 날짜·거리·시간의 기술적 요약 | 거리 측정 원천, 운동/경과 시간 구분, 단위·시간대, 중복·수정·삭제 |
| 2 | 실제 제공된 랩·인터벌의 계획 비교 | 자동 랩과 실제 반복 구분, 휴식 랩, 멈춤, 잘린 기록 |
| 3 | 심박 등 생리 데이터의 제한적 추이 | 기기·측정 위치·결측·품질, 기기 변경 전후 비교, 사용 목적 |
| 4 | 다음 후보에 쓰는 입력 | 최신성·적용 공식·승인 템플릿·안전 경계, 기존 증감 조건 |

첫 단계 승인도 곧 모든 공급자와 모든 항목의 승인을 뜻하지 않는다. 공급자별 구조·의미·품질을 확인한다. 승인 이후에는 같은 형식의 가져오기마다 긴 동의 절차를 반복하지 않도록 하되, 충돌·새로운 사용 목적·권한 변경은 별도로 확인한다.

최근 경기기록을 목표 페이스에 쓰는 조건과 오래된 훈련 이력을 과거 비교에 쓰는 조건은 다르다. 하나의 신뢰 점수로 전부 합치지 않는다.

## 10. 사용자 화면: 세 번 안팎의 선택으로 결과에 도달

핵심 입구는 자유로운 AI 질문창이 아니라 다음 세 가지다.

- `내 기록 가져오기`: 읽힌 날짜·종류를 확인하고 필요한 오류만 고친다.
- `받은 훈련 풀어보기`: 반복·회복·거리·페이스를 그림과 문장으로 확인한다.
- `지난 훈련과 비교`: 비교할 두 기록을 고르고 달라진 점을 본다.

결과 화면은 `한눈에 / 자세히 / 계산·근거`로 나눈다. 처음에는 실제 훈련 구성과 핵심 비교를 보여준다. 복잡한 설명은 펼쳐 읽되, 입력 누락으로 계산이 불가능한 항목이나 중요한 주의는 숨기지 않는다.

워치 기록이 있는 사용자는 다시 일지를 전부 적지 않아도 된다. 선택적 RPE 등 정말 필요한 정보만 받는다. 자세한 일지·꾸미기·비밀 메모는 별도 선택으로 남긴다.

코치와 공유할 한 장 자료는 훈련 구조·실제 수행·비교·출처 범위 중심으로 만든다. 메모·건강 원자료·개인 근거는 기본 제외하고, 공유 범위를 명시적으로 확인한다. HTML 자료가 먼저이며 PDF·이미지 내보내기는 같은 데이터와 설명을 재사용하는 후속 기능으로 둔다.

별도 실패 점검:

1. **계획을 실제 기록으로 집계:** 데이터 종류 분리 없이는 가장 큰 오해를 만든다.
2. **워치 기록 중복:** COROS와 다른 서비스에서 같은 운동을 받아 합계가 두 배가 될 수 있다. 확실한 식별자·동일 사본과 의심 중복을 구분하며 조용히 자동 합치지 않는다.
3. **시간 의미 혼합:** 운동시간·경과시간·휴식시간을 같은 duration으로 취급하지 않는다.
4. **훈련 목적 추측:** 400m 반복이라는 이유만으로 LT·VO2·GLY 중 하나를 확정하지 않는다.
5. **사후 근거 창작:** 나중에 들어온 일지가 원래 계획을 만든 이유였다고 말하지 않는다.
6. **자료가 적을 때의 잘못된 평가:** 미기록을 0회·낮은 노력·체력 부족으로 바꾸지 않는다.
7. **불필요한 채점:** 회복일이나 기록 누락에 죄책감을 주는 점수·훈련량 보상을 붙이지 않는다.
8. **과거 상태 은폐:** 기록 수정·삭제 후 보고서를 갱신하거나 이전 버전임을 알린다.
9. **사람 검토 오인:** 프로그램 검사나 오너 채택을 외부 스포츠과학자 독립 검수라고 표시하지 않는다.
10. **공급자 연결과 분석 완료 혼동:** 데이터 수신 성공과 분석 적격성·실제 사용자 결과를 각각 검증한다.

## 12. 권장 구현 순서와 종료 조건

현재는 검토 단계다. 아래는 후속 작업 순서이며 작업자를 실행하거나 코드를 수정하지 않았다.

### 1단계: 기존 코드와 사용할 데이터의 범위를 연결

- 외부 자료의 필드별 분석 허용표를 작성한다. 먼저 날짜·거리·운동시간·경과시간과 정확한 출처를 다룬다.
- `EXTERNAL_RECORD_INTEGRATION_SPEC`, 출처 계약, 분석·거리 계약의 충돌을 수정할 패치를 준비한다.
- 기존 직접 입력 기록의 분석 경로는 유지한다. 수신 성공을 분석 승인으로 바꾸지 않는다.
- 종료 조건: 어떤 필드가 어떤 화면·계산·계획에 쓰이는지 추적 가능하며, 채택되지 않은 항목은 그대로 제외된다.

### 2단계: 훈련 해설표를 하나의 실제 흐름으로 완성

- 지원 훈련 표기/기존 계획 → 구성 확인 → 계산 → 검토된 설명 → 한눈에 보는 자료를 연결한다.
- 원계획 작성자의 의도, 일반 원리, 계산 결과를 구분한다.
- 종료 조건: 위 2×10×400m와 시간형·복합형·불완전 입력에서 숫자와 설명이 일치하고, 사용자에게 왜 미정인지 드러난다.

### 3단계: 가져온 실제 기록과 누적 분석 연결

- 채택된 외부 필드부터 실제 통계·계획 비교·이전 수행 비교에 연결한다.
- 주간·월간 합계, AM/PM, 수정·삭제·충돌, 기기 변경, 부분 기록을 검증한다.
- 종료 조건: 업로드 후 사용자 보고서까지 실제 값으로 이어지며, 중복·누락·권한 제한이 숨겨지지 않는다.

### 4단계: 다음 선택에 도움이 되는 자료로 확장

- 현재 승인된 후보 추천·페이스·조정 기능에 사용할 수 있는 입력만 연결한다.
- 새로운 훈련 구성은 정확한 근거 검토 자료와 오너 채택 경로를 따른다.
- 공유용 요약과 장기 주기 비교를 같은 근거 모델에 연결한다.
- 종료 조건: 현재 사실, 과거 비교, 다음 제안이 구분되며 자동 증량·안전 해제·비밀 메모 사용이 발생하지 않는다.

**각 단계는 문서만 작성하고 종료하지 않는다.** 구현 승인을 받은 후에는 데이터 입력부터 화면 결과까지 완성하고 검수·배포 여부를 따로 보고한다. 외부 공급자 승인이나 계정 권한이 필요한 부분은 구체적인 재개 조건을 남긴다.

## 13. 후속 검증 계획

- 변조: 반복·회복·설명 버전 변경 시 옛 숫자와 설명이 남지 않는지 검사.
- 출처: 가져온 값을 직접 입력으로 위장하거나 임의 메타데이터로 승인할 수 없는지 검사.
- 데이터: 동일 사본·충돌 사본·공급자 수정/삭제·두 번 훈련·날짜 경계·오래된 기록을 검사.
- 프라이버시: 비밀 메모의 내용·존재·길이를 바꿔도 분석 결과가 달라지지 않는지 검사.
- 처방: 설명 열람이나 자료 추가만으로 새 템플릿·증감·D9 해제가 발생하지 않는지 검사.
- UX: 처음 온 사용자, 워치만 쓰는 사용자, 중고등부 선수, 하루 두 번 훈련하는 선수, 코치가 같은 근거를 오해 없이 읽는지 검사.
- 접근성: 320/375px, 글자 200%, 키보드, 줄인 모션, 차트의 표 대안과 단위를 검사.
- 독립성: 작성자가 만든 예상 JSON만 재검산하지 않고, 합성 원파일과 확인된 수동 계산을 별도로 대조.
