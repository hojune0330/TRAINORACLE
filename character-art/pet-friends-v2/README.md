# 우리 집 친구들 v2 · 새 친구 36종

2026-10-19. 일지와 함께 친구를 만나고 입양하는 기능 확장에 사용할 새 캐릭터 에셋이다. 기존 12종과 함께 쓰면 총 48종이다. 이 폴더의 담당 범위는 이미지 생성·최적화·명세·로컬 에셋 검수이며, 입양 규칙과 저장·게임 화면 구현은 별도 담당 범위다.

## 완성한 에셋

- 새 동물 24종과 독자적인 꿈 친구 12종, 총 36종.
- 1종당 1536×1024 PNG 원본 1장과 같은 크기의 투명 WebP 1장.
- 각 시트는 3열×2행, 동일한 512×512 칸 6개다. 총 216가지 상태 그림이다.
- 행 우선 순서: `awake → happy → eating → playing → sleeping → waking`.
- 여섯 상태의 핵심 자세이며 연속 애니메이션 6프레임이라는 뜻은 아니다.
- 선택 PNG 36장 합계 **54,694,752바이트**. 실행용 WebP 36장 합계 **4,559,106바이트**.
- WebP 36장 모두 150,000바이트 이하. 최대는 `deer.webp` **149,680바이트**다.

내장 OpenAI imagegen을 이미지마다 별도로 호출했다. 총 38회로 36종 선택본을 만들었다. 페럿과 아홀로틀은 셀 경계를 넘은 첫 시트를 한 번씩 재생성했다. CLI/API 이미지 생성으로 전환하지 않았으며, 그림 자체를 SVG/CSS/canvas나 코드로 다시 그리거나 마스킹하지 않았다.

기존 `pet-visitors-v1`의 레서판다와 거북이를 직접 보고 따뜻한 2D 동화체, 얇은 갈색 윤곽, 둥근 몸과 작은 표정을 글로 정리해 새 생성 프롬프트에 사용했다. 기존 시트는 변경하지 않았다. 제삼자 캐릭터 이미지나 로고를 입력으로 사용하지 않았다. 꿈 친구에는 사람의 성별이나 복장을 부여하지 않았다.

## 파일과 연결 계약

- `sources/{id}.png`: 선택한 원본 PNG 36장. 생성 결과의 픽셀을 변경하지 않았다.
- `sources/variants/`: 최종에서 제외한 첫 페럿·아홀로틀 시트 2장. 셀 경계 문제의 원본을 보존했다.
- `generation.json`: 실제 프롬프트, 내장 도구, 날짜, 기본 저장 경로, 선택본과 제외본 기록. 도구가 시드를 제공하지 않아 `seed: null`이다.
- `prepare-assets.mjs`: 선택 원본 복사와 WebP 포맷 변환. 원본 해시가 같은 WebP는 다시 인코딩하지 않는다. 알파를 바꾸거나 그림을 다시 그리지 않는다.
- `prepare-contact.mjs`: 원본을 아이보리 위에 합성한 검수 전용 비교판을 만든다. 캐릭터 그림은 다시 그리지 않는다.
- `verify-assets.mjs`: 36 ID·종류 수, 원본/실행본 크기·해시·바이트, 알파 픽셀 동일성, 셀 경계를 검증한다.
- `qa/{id}-on-ivory.jpg`: 상태 6개를 크게 보는 검수 파생본. 실행용 파일이 아니다.
- `qa/contact-01.jpg`부터 `contact-06.jpg`: 6종씩 2열×3행으로 합성한 비교판. 각 종의 전체 시트는 384×256으로 보인다.
- `qa/contact-index.json`: 패널별 ID 목록.
- `qa/validation.json`: 최종 수치 검사와 알파 잔류 경고.
- `inventory.json`: 이 폴더와 실행용 폴더의 전체 파일 SHA-256·바이트. 자기 자신은 해시 목록에서 제외한다.
- `../../app/public/games/pet-friends-v2/pets/{id}.webp`: 실제 게임이 소비할 36개 시트.
- `../../app/public/games/pet-friends-v2/manifest.json`: 각 실행본·원본의 SHA-256·바이트, 3×2·512칸·상태 순서·가시 윤곽 경계 검사.
- `../../app/public/games/pet-friends-v2/gallery.html`: 실제 WebP를 상태별로 펼쳐 보는 에셋 보관함.

실행용 경로는 `games/pet-friends-v2/pets/{id}.webp`다. 기존 `pet-room-v1` 12종의 파일과 경로를 덮어쓰지 않는다. 기존 `PetArt.tsx`와 같은 3×2 프레임 계약을 사용하지만, 이 에셋 작업에서 제품 TypeScript·CSS·저장 코드는 수정하지 않았다.

## 검수 결과와 정확한 한계

2026-10-19 로컬 검사에서 36 ID와 216 상태 칸이 빠짐없이 존재하고, PNG와 WebP가 모두 1536×1024 RGBA임을 확인했다. 각 WebP의 SHA-256·바이트가 manifest와 일치하며, **PNG 원본과 WebP의 알파 값은 모든 픽셀에서 완전히 같다**.

통합 담당자는 `contact-01`부터 `contact-06`까지 36종·216자세를 직접 확인했다. 캐릭터 정체성·여섯 자세 구분·그릇/공·잠든 몸·육안 잘림 검수를 마쳤다. 실제 캐릭터 윤곽을 잡는 `alpha > 8` 기준으로 모든 셀의 가장자리 2px에는 침범 픽셀이 없다.

다만 **완전히 alpha=0인 경계라고 주장하지 않는다.** 내장 생성 원본에는 셀 경계에 `alpha 1~3/255`의 미세한 잔류 픽셀이 합계 12,250개 있다. 대부분 alpha 1이고 조랑말은 최대 2, 달나방은 최대 3이다. 원본의 잔류를 그대로 보존했으며 코드 마스킹이나 추가 재생성은 하지 않았다. 이 한계는 통합 담당자가 원본 보존 및 경고 기록 조건으로 수락했다. 검수 결과값은 `PASS_WITH_SOURCE_ALPHA_RESIDUE_WARNING`이다.

가시 윤곽의 최소 여백이 12px보다 작은 자세도 경고로 남겼다: 여우 공놀이 5px, 코알라 공놀이 8px, 달나방 공놀이 3px. 세 자세 모두 셀 안에 들어가고 육안 잘림이 없다는 확인을 받았다.

포맷 변환·알파 대조·에셋 시각 검수와 실제 게임 흐름·빌드·CI·배포·실계정 사용 검증은 별개다. 이 담당 작업은 커밋·푸시·배포하지 않았다.

## 다시 준비하거나 확인할 때

기존 Node 실행 파일과 설치된 sharp 경로를 사용한다. 새 이미지 생성 CLI나 의존성 다운로드는 필요 없다.

```text
node character-art/pet-friends-v2/prepare-assets.mjs /absolute/path/to/sharp
node character-art/pet-friends-v2/prepare-contact.mjs /absolute/path/to/sharp
node character-art/pet-friends-v2/verify-assets.mjs /absolute/path/to/sharp --inventory
```

실행 이미지 36장은 모두 선택 원본과 연결되어 있다. 새 종이나 상태 순서를 바꾸는 작업은 별도 생성본과 manifest·소비 카탈로그의 같은 계약을 함께 확인해야 한다.
