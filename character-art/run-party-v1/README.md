## 3. 스타일 계약

오너 지시인 **기존 디테일의 약25%**를 따른다. 한 자산당 주요 덩어리3~5개, 주색3개 이하, 작은 글씨/로고/그물망/나사/신발끈/개별 손가락/털/잎맥 없음. 얼굴은 점눈2개까지. 작은 캐릭터를 수많은 장식으로 구분하지 않는다.

작업 팔레트: navy `#252337`, cream `#FFF3D6`, mint `#20BEA7`, coral `#F46C66`, yellow `#FFCE3A`, blue-gray `#8EA7B5`. 이는 아트 목표색이며 런타임 UI에서는 기존 `--game-*` 의미 토큰을 우선한다. 새 CSS 색 리터럴을 복사하는 지시가 아니다.

적과 아군은 색 외에도 실루엣·기저 표시로 구분한다. 실제 충돌물은 장식보다 선명하고 그림자 대신 접지 타원/범위 표시를 사용한다. 모든 신규 형태는 독자 디자인이며 Roblox 캐릭터·식물·타워 모델을 참조 입력으로 업로드하지 않는다.

## 4. 모델·렌더 납품 규격

- 원본: GLB 우선. 기존 Studio Bridge가 FBX를 전달하면 실제 헤더/Blender import로 형식을 확인하고 그대로 보존한다. 확장자만 바꾸지 않는다.
- 신규 소품 목표: 원본 3,000 triangles 이하, 재질1개/텍스처1장(512px 목표). Studio에서 강제할 수 없으면 원본을 보존한 채 로컬 작업본을 단순화한다. 이 수치는 모바일 런타임3D 도입을 뜻하지 않는다.
- 정규화: 작업본 Z-up, 전방+Y, 발/받침 중심 origin, 높이1단위. 기존 FBX의 임포트 축은 확인 후 변환하고 원본을 덮어쓰지 않는다.
- 캐릭터: 기존512×512 투명 PNG, 참조 키420px, 발 기준 y480/골반 x256. 달리기 공중 프레임을 매번 발바닥에 맞춰 눌러 붙이지 않는다. 기존 run의 공통 바닥과 점프의 게임 변위를 유지한다.
- 각도: 기존 side는 보존. 사선 시범은 진행축에 대한 옆 시점에서35도 회전·고도20도부터 시작하되 실제 FBX 전방을 먼저 확인한다. 화면 투영과 맞춘 실제 camera matrix를 산출 manifest에 기록한다. 후방/빙판은 추가 렌더하지 않는다.
- 토리 신규 사선: run8 + idle2 + jump3 + hit1 + fall1 + cheer1 =16프레임. 기존 측면시트와 별도 id를 사용한다. 초기 구현에서 카메라는 지정된 각도 사이에만 전환하며 2D시트로 연속360도 시점을 구현했다고 하지 않는다.
- 소품·적:512px 투명 마스터→256px runtime WebP. 적3실루엣은 별도 셀. 바람 회전 날개는 간단한 별도 파트 또는2프레임으로 만들고 합쳐진 모델을 억지로 회전하지 않는다.
- 신규 전체 런타임 전송량 목표1MiB 이하, atlas최대1024×1024, 게임 경로에서만 지연 로드. 실제 WebP 압축 결과와 디코딩 메모리를 별도 측정한다. 기존 자산54,220bytes라는 값은 기존 패키지 기록이며 신규 용량에 포함하지 않는다.
- 자산마다 alpha bounds/pivot/footprint/방향/가림 범위를 기록한다. 그림의 투명 여백이 충돌 박스를 늘리지 않게 한다.

## 5. 실행 경로·비용 준비

기본은 **기존 Tripo Studio Pro → 내보내기 → 로컬 Blender → WebP**다. Studio에서 파일을 받을 수 있으면 직접 다운로드를 우선하고, 실패하면 이미 사용한 공식 Blender Bridge를 사용한다. 새 API 결제나 로그인 설정을 시작하지 않는다.

| 단계 | 이번 실행 | 제작 시 확인 |
|---|---|---|
| 기존 원본/manifest/프롬프트 준비 | 완료, 신규 크레딧0 | 소스 해시·각도 재사용 |
| Studio 신규 적1종 | 미실행 | 당시 소품25credits/job 기록을 참고하면25 예상. 현재 화면 견적 확인 필요 |
| Studio 신규 바람1종 | 미실행 | 같은 기준25 예상. 첫 자산 검수 후 진행 |
| 합계 | 이번 차감0 | 과거 요율 기준50 예상, 현재 견적·잔액 확정 아님 |
| 오프라인 수정·렌더·패킹 | 미실행 | Tripo 크레딧0, 로컬 연산 시간 발생 |

최근 저장된 Studio 잔액2,910은 앞선 제작 당시 기록이다. 현재 잔액으로 표시하지 않는다. 실행 직전 Pro 상태·두 작업의 실제 표시 비용·출력 배포 조건을 확인하고 작업별 전후 잔액/실제 차감을 기록한다. 이번 요청은 ‘제작 준비까지’이므로 유료 작업 제출·새 플랜 결제·API 충전을 하지 않았다.

API 플러그인 경로는 별도 크레딧이며 기본 경로가 아니다. 향후 사용하려면 `tripo make ... --dry-run --json`으로 모델·각 API 단계·추가 변환 비용을 먼저 확인한다. 이번 패킷은 실행하지 않은 CLI 계획을 검증 완료로 표시하지 않는다. GLB만 필요한 작업에 유료 FBX/리깅/리타깃 체인을 자동 추가하지 않는다.

## 6. 제작자가 받을 파일과 검수

`asset-plan.json`의 status는 제작 완료 플래그가 아니다. 원본이 없는 작업은 `planned`, 기존 자산은 `reuse-source`로 구분했다. 준비 패킷을 자동 유료 배치 입력으로 사용하지 않는다.

제작 후 각 자산 폴더에 `source.(glb|fbx)`, `PROMPTS.md`, `manifest.json`, `review-64-75.png`, `preview.png`를 남긴다. manifest 필수: 도구/버전/날짜, 정확한 프롬프트, seed(없으면null), taskId, 실제 차감, source SHA256, 재질/삼각형 수, 사용 권리 근거, 출력파일·camera matrix·pivot. 계정·결제 캡처/키/서명 URL은 공개 저장소에 넣지 않는다.

합격 순서: 원본 import →64/75px에서 형태 구분 → 사선 접지/가림 → 실제 휴대폰 프레임 → 용량/프레임 비용 → 게임 연결. 토리 사선의 얼굴·옷 뒷부분이 불완전하면 그 각도에서 먼저 로컬 재질을 보정한다. 시점마다 새 토리를 생성해 얼굴을 바꾸지 않는다.
