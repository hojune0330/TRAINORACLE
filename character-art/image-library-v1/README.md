# 게임 이미지 라이브러리 v1

2026-10-16. 오너 요청에 따라 GPT-6.1 Sol 작업자 3명이 디펜스 12종, 맵·장애물 10종, 효과·보상 8종을 개별 생성했다. 30종 모두 저장했으며 통합 담당의 누락·파일·투명 배경·64px 및 모바일 갤러리 검수를 마쳤다. 자세한 결과와 적용 조건은 VALIDATION.md를 따른다.

## 제작 범위

- 원본은 이미지 생성 도구가 만든 개별 투명 PNG. 한 장짜리 설정 시트를 여러 에셋으로 세지 않는다.
- 작은 화면에서 구별되는 단순한 덩어리, 짧은 색 구성, 무광 재질, 일관된 비스듬한 시점을 사용한다. 효과는 화면에 겹치기 위한 정면 이미지다.
- 타워 3계열은 색과 실루엣으로 구별하고, 강화형은 기본형과 가족처럼 보이도록 만든다.
- 기존 Tripo 원본·CC0 Kenney 에셋은 보존한다. 이번 그림을 기존 모델에서 렌더했다고 표시하지 않는다.
- 각 폴더의 PROMPTS.md에 실제 생성 프롬프트와 도구를 기록한다. 도구가 시드를 제공하지 않으면 없다고 적는다.
- production-plan.json은 고정 제작 목록이다. 실제 결과와 검수는 manifest.json에 별도로 기록한다.

## 사용 경계

이미지 파일 준비와 게임 런타임 연결은 별도다. 후속 게임 연결 현황은 `runtime-usage.json`과 `INTEGRATION.md`를 따른다. 타워 성능·가격·보상·훈련 기록은 바꾸지 않는다. 효과 5종은 단일 프레임 원본이며 게임에서는 짧은 확대·투명도 효과를 적용한다. 방향에 따라 회전하는 3D 모델이나 프레임별 스프라이트 애니메이션이라고 표시하지 않는다.

## Tripo 적용 순서

1. 이미지 검수 후 연사·포격·냉각탑과 기지 관문을 우선 변환한다. 한 모델을 게임 크기로 렌더해 검수한 뒤 다음 모델로 넘어간다.
2. 강화형과 회전 장애물·점프 발판·다리는 기본 모델 재사용 및 부품 분리를 먼저 검토한다.
3. 적 4종은 이동 방향과 애니메이션이 필요한 단계에서 변환한다.
4. 나무·바위·허들·리젠 표식·섬은 이미 보유한 Tripo 모델과 비교해 필요한 것만 새로 만든다.
5. 타격·폭발·냉각·대시·강화 효과와 메달·별은 2D로 사용한다. 3D 변환 대상으로 비용을 배정하지 않는다.

구체적인 우선 4종과 재사용 대조 목록은 tripo-queue.json에 기록했다. 모델 파일·회전축·실제 폴리곤 수를 확인하고, 64px 렌더를 본 다음 다음 항목으로 진행한다. 기존 Studio Pro와 별도 API 청구를 혼동하지 않는다. 생성 성공 후 내보내기가 실패한 경우 새 생성으로 재시도하지 않는다.

이미지 제작 단계에서는 Tripo 생성 호출·추가 결제·크레딧 차감이 없었다. 후속 게임 연결 작업에서 Studio 잔액 2,225크레딧을 직접 확인했다. 이후 브라우저 제어 도구 연결이 끊겨 새 모델은 아직 제출하지 못했다. 실제 제작 상태와 비용은 `tripo-queue.json`에 구분한다.

## 출처

자체 서술 프롬프트로 생성한 이미지다. 상용 게임 스크린샷은 기존 기획 비교 자료이며 이 이미지의 복제 소스로 입력하지 않는다. 타사의 캐릭터·로고·작가 이름을 요청하지 않는다. 별도의 CC0·MIT 라이선스를 이미지에 임의로 부여하지 않으며 저장소의 코드 라이선스와 이미지 생성 출처를 구분한다.
