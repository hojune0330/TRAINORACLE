## 실제 게임 구조

세계는 여울밤, 무대는 꿈손님 여관이다. 모루(이끼 여우), 도담(조약돌 거북), 루미(등불 나방)의 서로 다른 조건을 만족하도록 손님과 시설을 배치한다. 밤 마무리는 건너뛸 수 있고 실제 수면을 타이머로 측정하지 않는다.

| 장 | 구현된 새 조건 |
|---|---|
| 1 · 꺼진 여관에 불 하나 | 3×2, 모루–가림막 인접, 모루는 빛 회피, 도담–온돌돌 인접, 루미는 등불 빛 |
| 2 · 창가에 남은 편지 | 모루는 창가 줄, 도담은 안쪽 줄 |
| 3 · 비 오는 밤의 빈자리 | A1·B1 젖은 바닥을 손님이 피함, 온돌돌은 B2 고정 |
| 4 · 서로 다른 좋은 자리 | 둥근등/가림등 선택, 가림등 한 방향 회전, 등불 안쪽 줄 |
| 5 · 같은 지붕 아래 | 4×2 확장, A1·D1 물 회피, 창가 편지함, 작은 돌/긴 돌 선택 |

각 장은 도입→선택적 밤 마무리→직접 다시 왔어요→발견→시설 선택(해당 장)→배치→명시적 확정→저장 성공→장 엽서 순서로 진행한다. 다섯 장이 연속 5일 접속을 요구하지 않는다.

입력은 탭·키보드, 취소·되돌리기·초기화·합법 경로 힌트다. 두 칸 온돌돌은 가로로 붙어 함께 움직인다. 도담이 어느 끝에 인접해도 되지만 다른 조각을 놓을 공간이 줄어든다. 더 많은 손님을 보상으로 지급하는 기능은 없다. 그림의 칸 무늬·메시 표면을 판정 좌표로 사용하지 않는다.

첫판의 유효 배치 예는 `fox screen turtle / moth lamp stone`이다. 대각선은 인접이 아니며 한 조각은 한 번만 나온다. 가림등과 긴 돌은 각각 4장/5장에만 해금한다. 별보기 다락은 다음 시즌 후보이며 현재 구현으로 표시하지 않는다.

## 일지와 게임의 경계

수면의 정본은 기존 EveningEntry의 `sleepH`·`sleepQuality`다. 기존 일지 편집기에서 명시적으로 성공한 저장만 반영한다. 게임이 수면 기록을 복제 생성하거나 별도 일지 폼을 만들지 않는다.

- 일지 날짜·기록 ID·초안·복귀 위치를 보존한다. 잘못 입력한 값도 게임이 임의로 고치지 않는다.
- 같은 날짜 복수 기록은 명시적 선택, 읽기 실패는 미기록과 구분한다.
- 일지 원문·메모·통증·비밀 글을 게임·이미지 생성·공유에 넘기지 않는다.
- 게임 진행은 기기/ownerScope 단위이며 선택한 일지 날짜와 독립적이다.
- 게임 조작·완료·새 여정·친구 방문은 수면·훈련·P를 변경하지 않는다.
- 계정 경계가 바뀌면 이전 게임/일지 연결을 다른 계정에 자동 귀속하지 않는다.
- 게임 진행의 계정 클라우드 동기화·기기 간 복구는 구현하지 않았다.

전체 기록 상태표와 왕복 계약은 `plan.json.journal`을 유지한다. 이전 합성 일지 왕복 증거는 현재 확장본 회귀 검사 결과와 구분한다.

## 보관과 v1 저장 이전

어느 장에서든 `보관하고 새로 시작`을 확인하면 현재 여정을 지우지 않고 새로운 1장을 연다. 보관함의 `이어하기`는 선택한 기존 여정을 active로 바꾼다. 엽서 열람과 친구 방문은 읽기 전용이며 active 여정을 바꾸지 않는다.

저장 형식은 v2지만 키는 `trainoracle:sleep-inn:v1:<ownerScope>`를 유지한다. 유효한 v1은 읽을 때 기본 1장·기본 시설·북쪽 방향을 추가해 v2로 정규화하며 ID·날짜·단계·배치·이력·엽서를 유지한다. 읽기만으로 원본 문자열을 덮어쓰지 않는다. 다음 실제 저장 성공 때 v2가 기록된다. 손상·미지원 형식은 자동 초기화하지 않고, revision 충돌 시 기존 저장을 덮어쓰지 않는다.

## 친구 초대장과 답장

완성 엽서 선택→공유 범위 미리보기→초대장 만들기→직접 링크/코드 전달→받은 쪽의 미리보기→명시적 방문 순서다. 방문자는 고정 인사 세 가지 중 하나를 골라 답장을 만들고 직접 돌려준다. 자동 메시지 발송, 실시간 온라인 표시, 검증된 발신자, 서버 방문함은 없다.

- 공유 필드: `chapter/layout/lampMode/lampDirection/stoneMode`, 답장의 고정 `stamp`.
- 제외: 수면시간·품질·일지 날짜·원문·이름·계정 ID·여정 ID.
- URL payload는 `#sleep-inn=` fragment이며 관련 없는 query/hash를 제거한다.
- 버전·크기·정확한 필드·시설·완성 배치 검증. 체크섬은 훼손 확인으로만 사용한다.
- localhost에서는 휴대 가능한 코드 제공. 복사 거절 시 수동 선택·코드 파일 저장.
- 가져오기는 본인 여정을 덮어쓰지 않는다. 코드에 담긴 방과 인사만 화면에서 보여준다.

## 이미지와 Tripo

기존 이미지 생성 시안·참고 원본 18종은 아래 갤러리에 보존한다. 현재 게임은 room/pieces 배경·기본 조각을 유지하고, 가림등·긴 온돌돌·봉인 편지는 **실제 Tripo 메시를 Blender에서 렌더한 PNG 6개**로 교체했다. SleepInnGame과 SleepInnSocial이 같은 파일을 사용한다.

| 소품 | 최적화 GLB | 삼각형 | 실제 렌더 |
|---|---:|---:|---|
| 가림등 | 615,500 bytes | 5,324 | 북·동·남·서 4방향, 각 512×512 |
| 긴 온돌돌 | 440,172 bytes | 4,800 | 두 칸에 이어지는 단일 512×512 PNG |
| 봉인된 편지 | 454,536 bytes | 4,800 | 512×512 PNG |

Tripo Studio H3.1 생성 3회, 회당 55크레딧으로 **165크레딧을 사용해 2,225에서 2,060이 남았다.** Studio 관측값이며 API 잔액과 구분한다. Blender 후처리는 추가 크레딧을 사용하지 않았다.

원본 GLB 3개(각 64~67MB)는 로컬 ignored sources에 보존하며 원본 SHA-256을 확인했다. 최적화 GLB 3개와 투명 PNG 6개는 app/public/games/sleep-inn/tripo에 있다. 현재 런타임은 경량 PNG를 사용한다. GLB 직접 렌더링이나 자유 카메라 조작 구현으로 표시하지 않는다.

가림등은 Blender에서 후면 가림막과 전면 렌즈를 보강해 방향을 구분했다. 같은 카메라·크기·기준점으로 렌더하며 실제 방향 판정은 코드의 빛 조건이 담당한다. 긴 돌은 두 칸을 잇는 하나의 이미지로 표시한다. 통합 담당자와 자산 담당자가 6개 렌더를 검수했으며 실제 375px 친구 방에서 세 자산의 표시와 console errors가 빈 목록인 것을 확인했다.

기존 imagegen 자료의 의도 요약은 plan.json.production.imagegenAssets, 현재 렌더 목록은 production.runtimeAssets, 전체 Tripo 제작 결과는 production.tripoBatch에 둔다. 생성 seed가 Studio에 노출되지 않은 경우 값을 만들지 않는다.

## 현재 검증 상태

현재 확장본 로컬 focused 검사 61개와 타입 검사, 1~5장 순차 플레이, 가림등 회전 판정 변화, 독립 Chrome·IAB의 초대장·답장 왕복을 확인했다. 보관함→새 여정→5장 완료 복귀와 합성 수면 초안의 버리기·복귀도 확인했다. 실제 수면 일지 저장을 수행한 것으로 표시하지 않는다.

Tripo 3종 렌더 연결 후 영향받은 UI 2파일 15개를 다시 실행해 15/15 통과(14.06초), 전체 TypeScript exit 0, 프로덕션 Vite build 통과(25.31초)를 확인했다. 이전 기능 검사 61개와 이 재검사의 범위를 구분한다. 같은 소스의 필수 CI·공개 배포 결과는 EVIDENCE.md에 별도로 추가한다. 물리 iPhone, 인증된 실제 계정 수면 저장, 실제 이용자의 재미와 반복 방문 효과는 미검증이다. 이전 1장의 49테스트·빌드·캡처는 역사적 증거로 보존한다.
