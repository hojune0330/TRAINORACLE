# 우리 집 친구들 · 첫 돌봄과 방 꾸미기

2026-10-23. 실제 PetRoom 코드에 연결한 로컬 구현이다. 공개 배포 및 실제 중학생 참여 검증은 아직 하지 않았다.

## 바뀐 사용 흐름

- 첫 화면에서 친구와 쓰다듬기·간식·공놀이 버튼을 먼저 본다. 일지 친구 설명은 아래에서 이어 본다. 잠자리 준비는 상단에 유지한다.
- 첫 쓰다듬기 → 발도장 액자, 첫 간식 → 새싹 화분, 첫 공놀이 → 장난감 바구니, 첫 잠자리 준비 → 달 쿠션. 저장된 실제 돌봄에서만 소품이 생긴다.
- 방 꾸미기에서 미리 보고 `이 소품 놓기`를 눌러 적용한다. 소품을 치워도 소유 기록은 남는다. 소품을 받았던 날짜와 친구를 다시 볼 수 있다.
- 없는 소품을 고르면 받는 방법이 나오고 해당 돌보기로 바로 이동한다. 자는 동안에는 먼저 아침 인사를 마치도록 안내한다.
- 입양 미션 3개의 현재 일수와 필요한 일수를 함께 보여 준다. 다음 돌보기로 바로 갈 수 있다. 기존 30일 또는 미션 완료 조건은 바꾸지 않았다.
- 공놀이는 같은 화면에서 `한 번 더 놀기`로 이어진다. 반복 놀이가 돌봄 일수나 소품을 중복 지급하지 않는다.

## 에셋

새로 생성한 투명 WebP 3종, 각각 512×512, 합계 82,018바이트. 장난감 바구니는 기존 에셋을 재사용한다.

- 게임 파일: `app/public/games/pet-room-v1/keepsakes-v1/`
- 원본·정확한 프롬프트·파일 해시: `keepsakes-v1/`
- 생성 도구: built-in image_gen. 추가 Tripo 크레딧 사용 없음.
- 포장 스크립트: `tools/pack-keepsakes.py`. 알파를 보존한 크기 변환과 WebP 인코딩만 한다.

## 저장 및 확인 범위

기존 v2 기록의 선택 소품 필드는 없으면 null로 읽는다. 기존 돌봄·입양·일지 기록은 그대로 유지한다. 소품 선택도 기존 계정 범위, 방 잠금, 이전 저장값 비교, 저장 실패 처리를 사용한다. 보유하지 않은 소품 지정은 거절한다.

- 관련 4개 파일의 36개 검사 통과. 마지막 동선 변경 후 PetRoom의 19개 검사를 다시 통과했다. TypeScript 검사 통과.
- 실패 입력: 보유하지 않은 소품, 알 수 없는 소품, 오래된 저장값, 저장 공간 오류. 실패를 배치 완료로 표시하지 않음.
- Chrome 375×844 화면에서 실제 컴포넌트로 쓰다듬기 → 소품 받기 → 미리보기 → 놓기 → 새로고침 후 복원을 확인했다. 없는 화분에서 간식 주기로 이동하여 화분을 받는 동선도 확인했다.
- 실제 계정과 분리된 개발용 scope에만 저장했다. 일지에 가짜 수면 시간이나 실제 운동량을 기록하지 않았다.
- 화면: `review/game-preview-keepsakes-home.png`, `review/game-preview-keepsakes-picker.png`.

실제 중학생과 확인할 질문은 세 가지다. 첫 화면에서 도움 없이 친구를 돌볼 수 있는가? 새 소품을 받고 어디에 놓는지 찾는가? 다음에 다시 열었을 때 계속 함께하고 싶은가? 현재는 동작과 화면을 확인했으며 이 사용 반응을 측정했다고 주장하지 않는다.
