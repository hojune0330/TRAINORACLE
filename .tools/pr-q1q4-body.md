### Q1 — 추이 화면이 "빠진 일지"를 밝힌다 (완료)

수치를 적었는데 분석에서 빠진 일지를 화면이 말하지 않았다. 사용자는 자기가 적은 값이
왜 그래프에 없는지 알 방법이 없었다.

**착수 전 전제를 실행으로 확인하다가 내 명세가 틀렸다는 것을 발견했다.** 사용자에게는
제외 원인이 하나(가져온 DERIVED 값)라고 설명했지만, 실제로는 **둘**이었다:

```
[출처없음] 분석대상: 0
[가져옴]   분석대상: 0
[손입력]   분석대상: 1
```

`fieldProvenance`가 스키마에서 optional이고 `isEligibleForAnalysis`가 `undefined`에
false를 반환하기 때문에, `acc5940` 이전에 저장된 일지와 출처 없는 백업에서 복원한
일지도 함께 빠진다.

두 원인을 **뭉치지 않은** 이유: 사용자 행동이 정반대다. 가져온 값은 직접 다시 적으면
되지만, 출처 없는 일지는 사용자가 할 수 있는 게 없다(앱 문제). 뭉치면 "직접 적어
주세요"라며 불가능한 일을 요구하는 안내가 된다.

- `hasValueExcludedFromAnalysis()` — 값이 있는데도 부적격인 칸만 센다. "안 적어서 빠진
  것"은 세지 않는다(그것까지 알리면 안내가 소음이 된다)
- `analysisExclusionSummary()` — `excludedImported` / `excludedNoProvenance` 분리
- `Trends.tsx` — 빈 화면과 데이터 화면 **양쪽**에 안내. 가져오기만 한 사용자는 빈
  화면을 보므로 그쪽이 더 중요하다. "거리를 적으면 그래프가 그려져요"라는 오해 유발
  문구를 조건부로 바꿨다
- 계약 테스트 16개 (도메인 9 + 화면 7). 화면 테스트를 따로 둔 이유는 "도메인은 맞는데
  화면이 침묵"하는 실패 모양을 도메인 테스트가 잡지 못하기 때문이다

### Q4 — 일지를 지키면서 계정 잠금을 푸는 길 (도메인 층만)

계정 잠금(`claimSyncOwner`)을 푸는 유일한 수단이 **전체 삭제**였다. 계정만 바꾸려는
사람에게 "일지를 다 지우세요"는 과한 요구다.

`releaseSyncOwner()`는 owner 키만 지운다:
- 일지·계획: 보존 — 이 함수의 존재 이유
- 삭제 기록(tombstone): 보존 — 지우면 지웠던 일지가 새 계정에서 되살아난다
- 동기화 동의: 보존 — 자동 업로드 방지는 호출측(화면) 책임
- 제거 후 다시 읽어 확인. 실패를 성공으로 보고하지 않는다

계약 테스트 12개.
