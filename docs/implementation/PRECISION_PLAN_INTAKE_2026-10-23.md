# 간편·정밀 훈련계획 입력과 결과 전달

상태: 2026-10-23 오너 승인 구현 계약. 새 처방 수치·종목·강도·의학적 승인·DB 변경 권한은 추가하지 않는다.
기준: `ffb3a8e02423c0f0f12c78f1c97204ef15d2b5aa`. 구현·검사·병합·공개·실계정 저장은 별도 증거로 보고한다.

## 입력 계약

- PI-01: 기본 경로는 종목·기록 유무·경험·운동일·몸 상태의 기존 최소 질문을 유지한다. 첫 화면에 정밀 입력을 제공하며 방식 변경만으로 입력한 기록을 지우지 않는다.
- PI-02: 정밀 경로는 경험/대회 날짜, 일정, 훈련 구성의 한 질문씩 선택이다. 단일 선택은 다음 카드로, 숫자·날짜는 명시적 다음으로 이동한다. 현재 묶음과 실제 진행 수, 묶음 이동, 선택 내용 확인, 이전/취소를 제공한다. 스와이프나 강제 스크롤은 요구하지 않는다.
- PI-03: 선택 항목은 적용할 기본값을 보여주고 넘어갈 수 있다. 경험·운동일이 없으면 최종 확인을 완료할 수 없다. 마지막 몸 상태 확인 전에는 생성하지 않으며, 생성/안전/활성화/저장은 기존 공통 경로를 따른다.
- PI-04: 출처는 UI 수명 내에서 직접 선택(USER), 기본값(DEFAULT), 자동 제안(SUGGESTED), 이전 값의 출처 불명(RESTORED_ORIGIN_UNKNOWN)을 구분한다. 기본값과 같은 값을 눌러도 직접 선택이다. 기존 저장에 출처를 소급해서 발명하지 않는다.
- PI-05: 실제 기록·목표 입력의 기존 저장 동작을 버튼에 명시한다. 기록 저장과 계획 시작은 별개이며, 계획 취소가 이미 저장한 기록을 지운다고 설명하지 않는다. 종목 변경으로 무효인 상세 선택은 재사용하지 않는다.

## 결과와 지원 범위

- PR-01: 긴 달력 앞에 실제 기간·운동일/세션 수·확인 가능한 시간, 주요 훈련의 날짜·오전/오후·반복/회복/페이스를 표시한다. 미확인 거리를 0으로 채우거나 9일을 주간으로 부르지 않는다. 긴 과학 설명은 접어도 판단에 필요한 수치·출처·제약은 숨기지 않는다.
- PR-02: 일정·훈련 구성·근거 도구는 달력 전에 둔다. A/B 차이와 선택을 같은 영역에 두며 선택만으로 저장하지 않는다. 선택된 후보의 요약·달력·명시적 시작 동작이 같은 후보를 가리켜야 한다.
- PR-03: 실제 처방 바인딩에서 실제 기록/목표 기록/직접 입력/시간·힘든 정도를 구분한다. 저장된 기록 수, 체크 표시, 목표를 실제 능력이나 수행으로 취급하지 않는다.
- PR-04: 상세 제공 상태는 검증된 연결/확인 대기/조건 필요/입력 필요/시간·힘든 정도 안내/계산 확인 실패를 구분한다. 일반적인 기록 없는 폴백은 계산 실패가 아니다. 특정 PACE_TARGET 선택지 부재를 전체 카탈로그 공급 부재로 확대하지 않는다.
- PR-05: 조건 탐색에 사용한 가정은 적용 완료나 사용자 확인으로 승격하지 않는다. 실제 변경은 기존 조건 확인과 세션 편집 절차에서만 반영한다.

## 날짜·보관 경계

시작 예정일은 기존 일정 배치 역할을 유지한다. 대회 날짜가 `preview_only` 결과를 만들면 해당 제한과 임시 상태를 유지한다. 일반 선택지는 기존 7/9/10일이며 구형 9.5일 계획과 별도 10km 프로그램은 그대로 읽는다. 계정 범위·초안 버전·중복 제출·오래된 결과의 저장 거절을 보존한다. 개인 기록·일지·계정 정보를 새 서비스로 전송하지 않는다.
