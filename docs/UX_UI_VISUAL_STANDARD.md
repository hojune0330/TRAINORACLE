## 0. 한 문장 정체성

### 2026-10-14 오너 요청: 목적별 컬러 카드와 상세 진입

- 홈·훈련·일지·오라클의 탐색은 전체가 눌리는 둥근 카드로 구분한다. 제목과
  현재 날짜·상태를 먼저 보여주고 긴 설명·계획 관리·계산 기준은 이름 있는 상세로 연다.
- 메뉴 정체성은 훈련 파랑, 일지 앰버, 오라클 보라, 컨디션 로즈, 기록 틸로 통일한다.
  루트 `--category-*` 토큰과 같은 lucide 아이콘을 카드·선택·하단 탭에서 재사용한다.
  이 범위는 기존 단일 틸·중립 분류 제한의 예외다. 안전 상태·에너지·달력 역할색은
  재사용하거나 변경하지 않는다. 색에는 반드시 이름과 아이콘을 함께 둔다.
- 카드 반경은 기존 `--r-task-surface`, 조작은 최소 44px, 제목은 줄바꿈한다.
  그림자·색 스트립·전체 화면의 진한 채움 없이 옅은 바탕과 작은 아이콘 면으로 구분한다.
- 홈과 훈련 입구의 짧은 요약을 누르면 기존 전체 처방을 연다. 반복·회복·속도·총시간과
  안전 안내는 그 상세에 모두 보존하며, 현재 오류·미완성 처방 경고는 입구에서도 숨기지 않는다.
- 날짜 탐색·복귀·선택과 저장 계약은 바꾸지 않는다. UI 변경을 훈련량 변경이나
  저장 완료로 취급하지 않는다. 확인된 완료와 단순 선택의 시각 반응도 구분한다.

### 2026-10-12 오너 후속 지시: 몸 안내는 단순 이모지형 생성 이미지

- 몸 상태 안내 그림은 인물·운동복·성별·얼굴 특징이 없는 단순한 이모지형으로 만든다.
  bitmap 생성 도구의 결과를 사용하며 SVG/CSS/canvas로 몸 그림을 다시 그리지 않는다.
- 현재 검수안은 80px 단일 기호다. 앞·뒤 구분이 없는 같은 기호를 반복하지 않고,
  이름 있는 부위 버튼·1–5/해제 조작과 기존 좌우 ID·안전 안내를 보존한다.
- 그림은 클릭해야 하는 작은 표적이나 진단 정보가 아니다. 로드 실패 때 그림과
  빈 슬롯을 제거하되 입력을 계속 사용할 수 있어야 한다.
- 다른 이미지 후보는 실제 진입 경로와 기존 배치를 먼저 확인한다. 이미 적합한
  그림이 있으면 중복 생성·추가하지 않는다. 캡처와 오너 공동 검수는 구분한다.

### 2026-10-12 오너 승인: 불필요한 설명 삭제와 행동 중심 탐색

전 탭과 하위 화면에서 과거에 누적된 설명·중복 집계·도움말을 정리한다.
아래는 기존 §8.3/§8.7의 특정 문구·기능 배치 예시보다 우선하는 새 승인이다.

- 현재 행동에 필요 없는 설명은 다른 펼침으로 옮기기보다 삭제한다. 목적을 명확히
  말하는 버튼·탭으로 기능을 찾게 하며, 설명용 제목과 본문 제목을 반복하지 않는다.
- 계획의 완료 체크 수를 홈·오라클의 분석 결과 대용으로 쓰지 않는다. 훈련표의
  실제 진행과 수정 기능은 유지하며 완료 체크를 실제 거리·시간으로 바꾸지 않는다.
- `하루 마무리`의 표시 이름은 `컨디션·메모`로 통일한다. 수면·몸 상태·메모 중
  원하는 입력으로 바로 들어가고, 모든 선택 입력을 순서대로 완료시키지 않는다.
  기존 일지 종류 식별자·값·저장·초안·통증 확인은 보존한다.
- 별도 기기 상태 입력은 홈의 반복 과제에서 제거한다. 기존 값을 삭제하거나
  정식 일지에 자동 병합하지 않는다. 실제 저장된 과거 값의 접근은 별도 보존한다.
- 정상 저장 범위는 짧고 완결된 문구 한 곳으로 표시한다. `이 기기만`처럼 잘린
  문구를 쓰지 않으며 실패·대기·충돌·읽기 불명·계정 소유 확인은 숨기지 않는다.
- 실제 수치·날짜·단위·RP/RPE·반복·회복·안전 경고와 분석 출처/제외·예시 표시는
  관련 결과와 행동에 남긴다. 데이터 보존·동의·구매·계정 공개 규칙은 바꾸지 않는다.
- 전역 CSS 숨김·작은 글씨·고정 높이로 정보량을 줄이지 않는다. 구현에서 불필요한
  노드를 없애고, 동작이 있는 항목은 이름과 44px 터치 영역·복귀 경로를 유지한다.

### 2026-10-08 오너 재지시: 전 섹션·탭의 둥근 선택 통일

- 오라클의 선택 표현을 특정 화면에 한정하지 않는다. 섹션·분류·보기 전환은
  `app-choice-group`/`app-choice-control`, 기존 공통 탭은 `app-compact-tab`으로 연결한다.
- 선택 면은 기존 `--r-action` 12px, 질문 선택 면은 `--r-task-surface` 16px을 사용한다.
  44px 이상 영역 전체가 눌리는 면이며 11px 축소 글씨·32px 가짜 면으로 압축하지 않는다.
- 선택은 채움·굵기와 기존 aria 상태로 표시한다. 현재 선택에 해당하는 기존 내용만
  보여주고, 이전 선택·초안·복귀를 보존한다. 숨기기만 하는 새 전역 CSS를 만들지 않는다.
- 하단 탭도 둥근 선택 면과 글자로 위치를 알린다. 기록은 이동 탭이 아닌 행동으로 유지한다.
- 일지 종이·달력 날짜·그래프·훈련 수치·저장·삭제·구매는 선택 UI 전역 치환 대상이 아니다.
  이 승인으로 기존 안전 확인·저장 조건·계정 공개를 변경하지 않는다.

### 2026-10-08 오너 후속 승인: 화면 유형별 공통 적용

전 화면 교차검토 뒤 오너가 공통 표현과 화면별 예외를 함께 구현하도록 승인했다.
모든 화면을 같은 순차 입력으로 만들지 않고 네 유형으로 구분한다.

- 입력: 현재 질문 또는 관련 입력 묶음, 수정 가능한 이전 답, 명시적인 저장.
- 결과·비교: 실제 값·단위·실행 순서·변경 전후를 함께 표시하고 부가 근거만 펼친다.
- 탐색: 홈·달력·목록·설정의 자유 이동과 이전 위치를 유지한다.
- 편집 작업면: 일지·달력 종이를 유지하고 선택한 도구의 조작만 제공한다.
- 같은 목적지의 이름과 저장 결과의 표현은 통일하되, 실제 저장·포인트·검토 상태는
  기존 확인 결과를 따른다. 중복 안내를 없애기 위해 실패·재시도·검토를 숨기지 않는다.
- 데스크톱 결과는 `app-shell--results`, 집중 입력은 `app-shell--task`로 구분한다.
  일지 종이·꾸미기 좌표·날짜 칸에 결과 폭이나 전역 모서리 변경을 전파하지 않는다.
- 앱의 기존 움직임 줄이기를 공통 화면에도 적용한다. 새 추적·설정·처방 계산이나
  계정 공개는 이 승인에 포함되지 않는다. 구현·검사·배포 상태는 별도 인계한다.

### 2026-10-08 오너 승인: 참고 영상의 선택 반응과 작은 입체 삽화

오너가 제공한 카카오페이·토스 화면 녹화의 선택 → 결과 → 다음 행동을 참고한다.
브랜드 자산과 화면 전체를 복제하지 않고 아래 범위에서 기존 평면 기준에 예외를 둔다.

- 현재 작업의 버튼·입력은 `--r-action: 12px`, 단계형 선택 면은
  `--r-task-surface: 16px`를 사용할 수 있다. 전역 `--r-md`, 일지 종이,
  달력 날짜 칸과 데이터 표의 모서리는 바꾸지 않는다.
- 틸·아이보리·먹색과 기존 서체는 유지한다. 직접 생성한 무광 입체 오브젝트는
  입구·확인된 완료의 기존 안내에 64px 또는 최대 80px 하나만 배치한다.
  모든 입력, 안전 확인, 실패, 전송 대기에 반복하지 않는다. CSS 그림자는 추가하지 않는다.
- 선택 반응은 해당 버튼에만, 질문 전환은 새 질문 영역에만 적용한다.
  전환은 최대 200ms·8px 또는 짧은 나타남으로 제한하고 흔들림·반복·인위적 대기는 없다.
  전환 중에도 입력과 뒤로 가기를 막지 않으며 OS와 앱의 움직임 줄이기를 존중한다.
- 저장·보상·수치의 변화를 그림이나 연출로 만들어내지 않는다. 완료 삽화는 실제
  확인된 저장에만, 분석 예시는 예시 표기를 유지한 기존 입구에만 사용한다.
- 다른 회사의 로고·삽화·매니저 캐릭터는 복제하지 않는다. 영상의 개인·금융정보와
  캡처는 제품 자산·문서·외부 이미지 생성 입력으로 사용하지 않는다.

위 수치는 참고 영상에서 계측한 값이 아니라 이 앱의 접근성과 짧은 입력을 위한
구현 기준이다. 전체 화면 교체·다크 모드·새 보상 정책 또는 배포 완료를 뜻하지 않는다.

### 2026-10-08 오너 승인 단계 완료에 따른 화면 전환

오너는 별점 선택 뒤 후기 입력이 나타나고 등록 성공 뒤 보상이 확인되는 사례를
기준으로, 현재 작업을 마친 뒤 다음 작업을 보여주는 전면 UX 패치의 기획을 요청했다.
정확한 적용 순서와 예외는 [단계형 화면 패치 계획](../reports/plans/TASK_FOCUSED_UX_PATCH_PLAN_2026-10-08.md)을
따른다. 아래는 승인된 방향이며 전체 구현 또는 배포 완료 기록이 아니다.

- 입력과 선택은 현재 질문 또는 의미상 하나인 입력 묶음만 보여준다. 앞 단계의 답이
  유효해진 뒤 다음 단계로 전환하고, 이전 답은 수정 가능한 짧은 요약으로 보존한다.
  긴 페이지의 모든 질문을 접어 두는 것만으로 이 요청의 구현 완료를 주장하지 않는다.
- 쉬운 표현을 만들기 위해 긴 문장이나 모호한 비유를 추가하지 않는다. 수행할 행동과
  수치는 짧게 표시하고 전문 용어의 뜻, 원리, 계산식은 작은 도움말 또는 이름 있는
  하단 상세로 분리한다. 음성 기능이 없으면 설명 듣기라는 이름을 사용하지 않는다.
- 계획 비교, 전체 훈련 순서, 달력, 저장 전 확인처럼 함께 봐야 판단할 수 있는 정보는
  전체 보기를 유지한다. 총 소요 시간, 반복, 휴식, 중단 기준과 현재 안전 및 저장
  상태를 도움말 뒤로 숨기지 않는다. 읽기 진행을 실제 훈련 완료로 기록하지 않는다.
- 단순 선택은 한 번 누르면 진행할 수 있지만 글과 숫자 입력 및 복수 선택은 명시적인
  다음 행동을 사용한다. 저장, 계획 적용, 구매, 삭제, 동의는 자동 실행하지 않는다.
- 선택 메모와 꾸미기를 필수 단계나 새 보상 조건으로 만들지 않는다. 완료 화면의 보상은
  기존 정책에 따른 실제 지급 확인 후에만 표시하며 입력 완료와 저장 및 지급을 구분한다.
- 기존 초안, 뒤로가기, 계정별 상태와 포커스 복원을 재사용한다. 기존 한 항목 수정에
  전체 질문을 다시 요구하지 않는다. UI 공통화는 새 훈련량이나 나이별 처방 승인이 아니다.

### 2026-10-07 오너 승인: 구간별 작은 안내 이미지

오너는 이미지 활용 확장 시안을 검토한 뒤 실제 개선 진행을 승인했다. 아래 범위에서
§5의 비트맵 사용 영역을 확장한다. UI 아이콘과 데이터 표현을 삽화로 바꾸는 승인이 아니다.

- 일지 종류 선택의 첫 기록 안내, 확인된 빈 일지 달력의 제목, 워치 파일 선택,
  훈련 배우기의 목록 입구에 맥락에 맞는 투명 삽화 하나를 사용할 수 있다.
  계획 시작·페이스 도움말·꾸미기 안내·저장 완료는 기존 상태와 안내 영역 안에서만
  소형으로 사용한다. 새 랜딩이나 필수 팝업을 만들지 않는다.
- 작은 안내는 64px, 목록·파일 입구는 최대 80px를 사용한다. 제목과 안내 옆에
  배치하며 새 카드·설명·빈 공간을 추가해 주요 행동을 아래로 밀지 않는다.
  기존 날짜·버튼·예시 달력·근거와 입력 단위는 유지한다.

## 2. 색 사용 기준

### 2026-09-30 오너 승인: 달력 역할색

[달력 역할 표시 계약](../specs/active/CALENDAR_TRAINING_ROLE_PRESENTATION_CONTRACT.md)에 따라
달력의 세션 면은 경기 노랑·주요 연한 살구·플라이오 민트·기본 흰색·회복 하늘색을
사용한다. 이는 에너지 시스템 색의 전역 교체가 아니라 달력 전용 의미 토큰이다.
오전·오후를 분리하고 텍스트를 병기한다. 아래의 중립 90%·배경 채움 제한은 이 승인된
달력 셀에 한해 예외이며, 나머지 화면·처방·안전 판정에는 그대로 적용한다.

- **중립이 기본**: `--bg`(웜 오프화이트) / `--surface` / `--ink`
  계열 4단계. 화면의 90%는 이 안에서 끝나야 한다.
- **브랜드 틸(`--brand: #0D5F5A`)은 단일 액센트**: 한 화면에 틸이
  두 군데 이상 "면"으로 칠해져 있으면 이미 과하다.
- **의미색(`--ok/--warn/--err/--info/--unc`)은 상태 전달에만**:
  장식 목적 사용 금지. 특히 `--unc`(보라)는 AI 판정 불확실성 전용.
- **에너지 시스템 색 6종**(`--e-base/lt/vo2/gly/atp/rest`)은
  **dot + underline 전용, 배경 채움 금지**가 1차 원칙. 넓은 면이
  필요한 히트맵·차트 셀에만 `--e-*-wash` 4-tier를 쓴다.
- 색만으로 정보를 전달하지 마라 — **항상 텍스트·숫자·패턴 병기**
  (누적 거리 히트맵이 셀 안에 km 숫자를 병기한 것이 표준 사례).

앞으로 만들 에너지 시스템 누적, 9.5일 주기, 중주기 시각화에

2. **미기록 ≠ 0**: 값이 없으면 `—` 또는 "기록 없음". 0으로 그리는

5. **집계 기준·제외 건수를 차트 근처에 공개**: "제외한 기록 N건"

   깔끔하게 보이는 방법이 이 문서다.
6. **판정 문구 금지**: "좋아졌어요/위험해요" 같은 해석은 분석
   화면 권한 밖이다. 서술만 한다.
7. 에너지 시스템 차트에서 **MIXED_UNALLOCATED는 반드시 시각적으로

## 6. 꾸미기(데코레이션) 기준

### 2026-10-02 오너 승인: 일지 꾸미기 통합과 달력 결과 표시

- 편집은 `일지 꾸미기 → 일지 / 달력` 한곳에 모은다. 새 진입은 일지부터 시작하며 달력 화면에는 상시 편집 버튼을 두지 않는다.
- 기존 일지 v3 좌표·배열·24개 한도는 그대로 유지한다. 작성 화면은 종이와 읽기 전용 대표 그림만 사용하고 실제 원문 프레임을 축소 재사용하지 않는다.
- 일지 달력만 공통 종이와 위아래 여백(각 72px, 비어 있으면 생략)을 사용할 수 있다. 날짜표·오늘·선택·훈련 역할색에는 겹치지 않는다. 훈련 계획·입력용 달력은 대상에서 제외한다.
- 날짜 칸과 기존 홈/선택일 요약에는 실제 기록이 있는 날의 마지막 유효한 보유 그림 하나를 16px로 표시한다. 테이프·텍스트·개인 메모는 제외하며 별도 클릭 영역을 만들지 않는다.
- 이 예외는 읽기 전용 결과의 노출 범위만 확장한다. 탭 바·분석·안전 화면을 꾸미거나 장식에 훈련·건강 의미를 부여할 권한은 없다.
- 달력은 별도 v1 문서의 명시적 초안 적용을 사용한다. 구매·포인트는 취소·초기화·되돌리기의 대상이 아니다.

꾸미기는 "예쁘게 만들 자유"가 가장 큰 영역이지만, 자유는 **일지
종이 위에서만** 성립한다.

- **물성 어휘를 지켜라**: `colors_and_type_journal.css`가 정의한
  종이(`--paper`), 연필(`--pencil`), 만년필 청색(`--ink-blue`),
  마스킹 테이프(`--tape/--tape-2`), 형광펜(`--highlighter`).
  새 꾸미기 아이템은 이 물성 중 하나로 설명 가능해야 한다.
  "네온 LED 프레임"처럼 어휘 밖 물성은 톤 붕괴 → 반려.
- **꾸미기는 일지 페이지 프레임 내부에만 렌더**: 탭 바·분석 차트·
  안전 관련 화면에 스티커·테이프가 침범하면 즉시 반려.
- **가독성 우선**: 어떤 꾸미기 조합에서도 일지 본문 대비
  (4.5:1)가 유지되어야 한다. 형광펜 불투명도 상한 0.32 유지.
- 꾸미기·포인트는 처방·안전·템플릿 권한이 없다(마스터 플랜 §21).
  "이 스티커를 달면 훈련 강도 +…" 류의 연결은 시각 문제 이전에
  계약 위반.
- **이모지 스티커**: 유니코드 텍스트 렌더만 허용(플랫폼 이모지
  폰트 위임 — iPhone은 자동으로 애플 이모지로 보인다). 특정 벤더
  이모지 아트워크(이미지·스프라이트·웹폰트) 번들은 저작권 침해로
  즉시 반려. 종이 프레임 내부 전용, 페이지당 최대 3개(전용 슬롯
  3칸), 크기는 3단(20/24/28px) 고정. 세 슬롯은 본문 위 절대좌표가
  아니라 본문과 분리된 전용 레일에 렌더해 글과 터치 영역을 가리지
  않아야 한다. 스티커는 날짜(페이지)에 붙지 메모·항목에 붙지 않으며,
  배치 데이터를 분석·오라클·포인트 입력으로 쓰는 것은 금지.

### 2026-09-30 독립 페르소나 검수: 훈련 변경의 연속성

- 다른 훈련 목록과 무작위 미리보기는 현재 종목·경험·목적의 채택 범위 안에서 고른다.
  조건에 맞지 않는 구성을 먼저 보여주고 마지막 버튼에서만 거절하지 않는다.
- 적용에 필요한 구간 시간은 접힌 도움말에 숨기지 않는다. 입력하지 않은 값을
  자동으로 채우지는 않으며, 입력이 필요한 이유와 적용 상태를 짧게 함께 표시한다.
- 이미 반영한 구성의 기준 기록·직접 입력·환경 확인을 다시 열 때 보존한다.
  새 구성의 더 긴 시간에 대한 확인은 기존 구성의 확인으로 대체하지 않는다.
- 미적용 미리보기가 있으면 기존 계획을 조용히 확정하지 않는다. 적용과 변경 취소를
  명시적으로 제공한다. 이 규칙은 신규 처방 수치·강도·양·빈도 승인이 아니다.
- 최초 기록 입력부터 미저장 이탈을 보호한다. 더 강한 계정 전환·복구 가드를 덮어쓰지 않는다.
- 후보 날짜 상세, 오늘 훈련, 방법 상세는 같은 처방을 읽는다. 본운동과 준비·회복·정리 포함
  전체 시간을 구분하고, 실제 반복·회복이 있는 훈련에 미정 안내를 붙이지 않는다.
- 같은 목적 추첨은 현재 바로 적용 가능한 방법만 사용하며, 같은 슬롯·적격 풀에서는 미노출
  방법을 먼저 보여준다. 추가 입력이 필요한 구성은 수동 목록에서 확인하며 임의로 조건을 채우지 않는다.
- 하나의 변경을 A/B 계획안에 함께 반영할 때 양쪽 조건을 검사한다. 한쪽의 더 짧은 시간을
  넘는 경우 기존 명시 확인을 받고, 그 계획안도 시간이 바뀐다는 사실을 안내한다.
- 거리 회복 구조를 시간 회복으로 덮어쓰지 않는다. 직접 정한 시간은 거리와 함께 별도 표시한다.

- 터치 타깃 최소 `--app-touch-min`(44px). 시각적으로 작아 보여야
  하면 패딩으로 히트 영역을 채워라.
- 모션은 `--ease-out-strong` 이징, 200~350ms. 등장은 opacity +
  8px 이하 translate. 바운스·회전·무한 반복 금지.
- **모든 모션에 `prefers-reduced-motion` 대응 필수** (기존 6곳
  선례). 모션 없이도 상태 변화가 인지되어야 한다.
- 기준 뷰포트 375×667. **가로 스크롤은 결함이다** — e2e가
  `scrollWidth <= innerWidth`를 검사한다. 좁은 화면에서는 4열→2열
  접기(누적 거리 totals 패턴)를 따른다.

### 8.1 승인된 앱 제목·강조 역할 (2026-10-07)

- 화면 제목은 `AppHeading`의 `screen`(24px·700), 홈 대표 제목은
  `hero`(26–32px·700), 보조 섹션은 `section`(18px·700)을 사용한다.
  HTML 제목 단계는 문서 구조대로 유지하며 시각 크기와 별도로 결정한다.
  기존 `--fs-app-section-title`(22px)은 달력 연·월과 기존 묶음 제목의
  호환 역할이다. 새 일반 섹션 제목과 구분하며, 실제 일지 종이의 높이와
  저장 좌표를 바꾸기 위해 이 기존 토큰을 일괄 치환하지 않는다.
- 한 주요 제목에만 짧은 28px 틸 선을 허용한다. 제목 본문은 잉크색을
  유지하고 반복되는 분류 라벨·탐색 순서 번호는 중립색으로 둔다.
  이 선은 넓은 강조 면을 추가하는 규칙이 아니다.
- 대표 행동은 기존 브랜드 채움 하나로 구분한다. 보조 행동·재료·이동은
  무채움으로 유지하며 저장 실패·통증 등 의미색과 안내 우선순위를 바꾸지 않는다.
- 실제 핵심 숫자는 28px·700과 tabular-nums, 단위는 13px로 구분한다.
  숫자 강조를 위해 미기록을 0으로 바꾸거나 근거·기간·제외 건수를 제거하지 않는다.
- 상단 이동 영역의 작은 제목은 별도의 `app-chrome-title` 역할이다.
  하단 목적지는 `aria-current`, 굵은 라벨과 짧은 선택 표시로 구분하며
  `기록` 행동에는 현재 목적지 표시를 붙이지 않는다. 터치 영역은 44px 이상이다.
- 매니저·상황 그림은 앞서 승인된 64/80px 보조 자산으로 유지한다.
  새 제목 역할은 실제 일지의 종이 프레임·저장 좌표·크기·배열을 수정하지 않는다.
  긴 제목은 줄바꿈하며 본문이나 버튼을 줄여 억지로 맞추지 않는다.

### 8.2 확인된 빈 상태의 정보 우선순위 (2026-10-07 오너 요청)

- 결과가 없다는 이유로 물음표·빈 지표·분석 대기 상자를 반복하지 않는다.
  실제로 가진 계획·최근 일지·다음 훈련을 먼저 보여주고, 아무 기록도 없으면
  명시적인 예시나 일반 읽을거리와 가능한 기록 행동을 제공한다.
- 오라클은 계획만 있을 때도 저장된 계획의 진행 표시를 바로 보여준다.
  완료 체크와 실제 수행 기록은 구분하며, 표시 가능한 근거를 접어서 숨기지 않는다.
  집계 기준·개인 메모 미사용·해석 한계는 하나의 보조 펼침 영역에 모은다.
- 오늘 기록이 없다는 안내 문단 대신 기록 행동을 남긴다. 최근 일지가 있으면
  보조 도움말보다 먼저 보여준다. 계획 날짜가 미래일 때 오늘 훈련이라고 부르지 않는다.
- 비교할 코칭 기록이 없으면 기존 일반 훈련 글을 보여주되, 개인 분석·맞춤 처방으로
  표현하지 않는다. 원래 기록·일정·읽을거리의 이동과 복귀 동작은 유지한다.
- 전부 미기록인 차트·표는 그리지 않는다. 실제 값 0, 제외 사유, 지표 선택은 유지한다.
  로딩·읽기 실패·출처 확인 전 상태를 빈 기록으로 취급하지 않는다.

### 8.4 어려운 화면의 제목과 목적 안내 (2026-10-08 오너 후속 승인)

  `TaskGuide`로 현재 할 일을 먼저 표시한다. 작은 이동 제목과 별도로 24px·700의

- 설명은 선택에 필요한 짧은 한 문장만 둔다. 자세한 원리와 근거는 기존 도움말에
  남기고, 계산 결과·단위·출처·제외·안전·저장 실패 안내를 가리지 않는다.
- 문학적 비유보다 실제 내용의 이름을 쓴다. `기록의 리듬` 대신 `400m 평균`,
  `나의 한 장` 대신 `기록 요약`처럼 다음 화면에서 볼 내용을 구분한다.
- 새 64px 보조 그림은 훈련 살펴보기·페이스·경기 기록·훈련 조절의 표지로 사용한다.
  한 작업 화면에 하나만 두고, 연속 입력 단계마다 반복하지 않는다. 로딩·실패·
  적용 중에는 밝은 장식보다 실제 상태를 우선한다. 그림은 결과나 안전 판정이 아니다.
- 그림이 로드되지 않아도 제목·설명·동작은 남는다. 터치와 화면 읽기를 가로채지
  않으며 별도 캐러셀·입장 버튼·강제 안내 단계를 만들지 않는다.
- 제목에는 고정 높이·줄 수 제한을 두지 않는다. 좁은 화면과 큰 글씨에서도 줄바꿈을
  허용한다. 기존 입력·뒤로 가기·계정 범위·처방 수치와 적용 절차는 유지한다.

### 8.5 성향 질문과 선택형 캐릭터 안내 추가 승인 2026-10-08

### 8.6 러닝 취향 육각 그래프와 성향 캐릭터 추가 승인 2026-10-08

오너가 투자 성향 결과처럼 육각 그래프, 항목별 점수와 성향에 따른 캐릭터를 요청했다.

  원하는 답 하나만 고칠 수 있어야 한다. 저장 대기와 실패 안내는 유지한다.

  자동 선정을 추가하지 않는다. 그림을 누르면 짧은 설명을 열고 Escape로 닫는다.
- 캐릭터는 80px 보조 삽화 하나로 표시한다. 이미지 실패에도 이름과 동작은 남는다.

### 8.12 전 화면 정합성 검수와 공통 역할 (2026-10-16 오너 요청)

- 전 화면 점검은 실제 주 탭·도구·상세·입력 중간·결과·시트를 목록으로 관리한다.

- 긴 화면은 앱 내부 스크롤도 포함해 겹치는 구간으로 캡처한다. 문서 전체 캡처 한 장으로
  내부 스크롤 아래가 모두 보인다고 가정하지 않는다. 소스 검토와 실제 렌더 검수를 구분한다.
- 백업 복원·문의·계획 결과처럼 독립 화면의 대표 제목은 공통 screen 역할을 따른다.
  달력 연·월과 묶음 제목의 22px 역할, 긴 원문 본문, 종이 편집면은 별도 역할을 유지한다.
- 훈련 자료의 탐색 목록은 공통 카드 행으로 표시한다. 단계 번호나 선택 면으로 읽기 목록을
  꾸미지 않는다. 자료 출처·검토 상태는 남기고 상세 내용은 기존 글에서 읽는다.
- 페이스 계산 등 보조 목적지는 기존 가로 바로가기 묶음을 재사용한다. 준비 중인 기능을
  사용 가능한 기능으로 표시하지 않으며, 실제 입력·고정 토글·계산 결과는 별도 역할로 유지한다.
- 저장·복원·질문 시작의 주 행동은 브랜드 채움과 행동 반경을 사용한다. 선택 컨트롤 클래스를
  섞어 주 행동의 표현을 지우지 않는다. 저장 실패 안내는 충분한 글자 크기로 계속 표시한다.
- 현재 탭·입력 선택·값 고정은 의미에 맞는 aria 상태와 시각 표식을 함께 제공한다.
  선택 표식은 미선택 상태에서도 자리를 확보한다. 터치 기기에 hover 상태가 붙지 않게 한다.
- 훈련·안전·계정·날짜·초안·구매 계약은 변경하지 않는다. 검수에서 이미 정합인 화면은
  수정하지 않아도 된다. 로컬 캡처·합성 기록 검수와 필수 CI·공개 배포·실계정 확인은
  각각 구분해 인계한다. 로컬 검수 보고서와 캡처를 자동으로 공개 산출물에 포함하지 않는다.

### 8.13 홈의 훈련 미리보기와 정상 상태 문구 축소 (2026-10-18 오너 요청)

- 총시간은 검증된 카탈로그 계산을 재사용하여 준비·회복·정리를 포함한다. 손상된 연결·시간 미확인은
  안내를 남기고 이전 시간 범위로 대체하지 않는다. 총시간으로 안전하게 축약할 수 없는 기존 처방은
  원래 표기를 유지한다. 상세의 구간·RPE·오전/오후 일정과 저장된 수치는 변경하지 않는다.
- 최근 기록의 정상적인 `이 브라우저에 저장됨`·계정 저장 확인 문구는 홈에서 생략한다. 저장 범위는
  일지 상세에서 확인한다. 대기·실패·충돌·확인 미완료와 가져온 기록의 출처 표시는 유지한다.

  `확인된 일부 기록으로 보기`를 반복하지 않는다. 예시 구분·분석 불가와 실제 분석 화면의 근거는 보존한다.
- 공통 카드·색·44px 조작 영역을 재사용한다. 글자를 축소하거나 처방을 삭제해 밀도를 줄이지 않는다.
  이 규칙은 홈 미리보기 범위이며, 달력과 훈련 실행 화면의 주요 분류·시간대 상시 표시는 그대로다.

### 8.14 탐색 카드와 정상 상태 설명의 공통 축약 (2026-10-18 오너 요청)

- 같은 목적지로 이어지는 제목·요약·보기 버튼은 하나의 공통 카드로 묶는다. 이미 제목이 목적을
  설명하는 메뉴에는 사용법 문장을 반복하지 않는다. 유일한 진입 버튼은 없애지 않는다.
- 오늘 훈련의 기본·회복 미리보기만 원본 `EASY` 분류와 검증된 전체 시간이 있을 때 총시간으로
  줄인다. 표시 문구로 분류를 추측하지 않는다. 주요 훈련·분류 미확인·불완전 처방은 핵심 구간을
  유지하며, 전체 처방은 원래 상세에서 읽는다. 기록 저장은 탐색 카드와 분리된 명시적 행동이다.
- 날짜 카드의 오전·오후와 주요·기본·회복·휴식 구분은 유지한다. 실제 진행 기록이 없는 정상
  `예정`만 반복 표시하지 않으며 완료·휴식·건너뜀·안전 확인은 남긴다.
- 일지 관리 토글은 가능한 행동에 맞춰 `추가·수정 / 일지 더 쓰기 / 일지 수정`으로 표시한다.
  과거 일지에도 쓰이는 제목은 `이날 기록`처럼 날짜중립 표현을 사용한다. 본문·꾸미기 경계는 보존한다.
- 날짜 요약에서 실제 요약값이 없으면 ‘내용을 확인할 수 있어요’로 빈 곳을 채우지 않는다.
  원문 읽기 버튼 아래 동일 목적지 안내를 반복하지 않는다. 계획과 실제 기록 구분, 개인 글 비노출,
  출처 미확인·통증 미응답 등 데이터 한계는 보존한다.
- 통증·기분의 정상 저장은 완료 제목 한 번으로 알린다. 기분도 함께 저장한 사실, 실패·검토,
  보상 재시도·백업·보관 범위 등 서로 다른 정보까지 함께 지우지 않는다.
- 취향 입구는 질문 수를 행동에 한 번만 표시하고, 실력 평가가 아니라는 범위는 남긴다.
  훈련법 목록은 제목과 검토 상태를 우선하며 분류·출처·안전 설명은 글 안에서 확인한다.
- 기존 캡처의 화면 목록·문구·진입 경로로 반복 패턴을 찾고 현재 소스에 대조한다. 폐기된 화면,
  비활성 기능, 모달 배경 텍스트를 현재 중복 UI로 오인하지 않는다. 새 캡처는 변경 화면에 집중한다.

### 8.22 전체·영역 하단 탐색 (2026-10-24 오너 승인)

### 8.24 계획 방식과 오라클 정보 위계 (2026-10-25 승인안 구현)

- `간단히 / 직접 설정`은 같은 크기의 선택 면, 서로 다른 Lucide 아이콘과 한 줄 보조말로 구별한다. 선택 표시는 고정 자리에서 바뀐다. 첫 진입 기본값과 기존 입력 흐름은 유지하며 자동 팝업·강제 대기·반복 흔들림은 추가하지 않는다. 차이는 사용자가 눌러 읽는다.
- 분석 상단은 안정된 `내 훈련` 제목과 네 가지 작은 보기 전환으로 구성한다. 페이스 계산·기록 풀이는 보조 도구이며 대표 결과보다 먼저 크게 배치하지 않는다. 조건부 파일 분석은 네 가지 보기와 분리한다.
- 읽기 미완료, 확인된 빈 상태, 기록은 있지만 해당 값이 없는 상태, 실제 값이 있는 상태를 구별한다. `다시 확인`은 상위 기록 조회와 로컬 기록 재읽기를 함께 요청한다. 읽기 실패를 빈 결과·읽기 완료·네트워크 장애로 단정하지 않는다.
- 실제 요약과 예시 축약 여부는 적격 RPE를 포함한 공통 표현 판정을 사용한다. 실제 분석이 있으면 실제 결과를 먼저 보여 주고 예시를 작은 행으로 유지한다.
- 예시는 기존 가상 데이터만 읽는 별도 카드로 표시하고 `예시 · 내 기록 분석이 아니에요`를 차트 가까이에 유지한다. 예시의 내 기록 CTA는 읽기 미완료·실패 시 기록 확인 화면으로, 읽기를 마쳐 필요한 값이 없다고 확인되면 해당 기록 행동으로, 결과가 준비되면 개인 결과로 연결한다. 예시 열람은 저장·보상·처방 입력을 만들지 않는다.
- 월별은 현재 지표 하나와 선택 시트로 정리한다. 명시된 진입 지표를 우선하고, 없으면 실제 값이 있는 지표를 거리·페이스·기분·통증 순으로 찾는다. 사용자가 선택한 뒤에는 다른 값이 생겨도 자동 전환하지 않는다. 거리의 월별 중앙값을 월 누적으로 표현하지 않는다. 월별의 파일 가져오기는 거리의 빈 상태에만 제공한다.
- 지표 시트는 현재 지표 버튼에 포커스를 두고, 위·아래 화살표는 선택을 바꾸지 않고 포커스만 순환한다. Enter·Space·클릭으로 선택하면 즉시 적용하고 닫는다. Tab·Shift+Tab은 모든 버튼을 순환하며, 닫기·Escape·브라우저 Back·배경 클릭은 기존 지표를 유지하고 트리거 포커스로 복귀한다. 다른 지표로 이동하면 이전 지표의 저장 안내를 재사용하지 않는다. 숫자 집계·출처·제외 기준은 바꾸지 않는다.
- 취향의 추가 질문과 내 응답·정보 관리는 별도 입구로 나눈다. 모름·상황마다 다름·경험 없음은 선택적으로 펼치되 서로 다른 응답으로 유지한다. 영역 보기 전환은 오라클 보라색, 질문 답은 공통 선택 면, 주 행동은 브랜드색을 사용한다.

### 8.28 근거가 있는 오라클 이야기와 한 장 기록 (2026-10-26 오너 승인)

### 8.29 훈련 메모의 단계적 읽기 (2026-10-26 오너 요청)

- 훈련 안내는 메모 한 장이다. `간단히`는 본운동·목표·반복·세트·회복과 유의사항,
  `자세히`는 준비·본운동·정리 순서를 보여준다. 훈련 이유는 별도로 펼친다.
  내용이 변하지 않는 전문 보기와 중복된 핵심만·기본 선택을 추가하지 않는다.
- 쉬운 말·훈련 표기는 두 보기 모두에서 바로 선택한다. 정보량과 표현을 혼동하지 않는다.
  날짜·시간대가 상위 리더에 있으면 종이 안의 중복만 생략하며, 복사·PNG에는 보존한다.

  사라질 수 있는 소수 초와 다른 구간의 목표 시간은 남긴다. 처방량은 바꾸지 않는다.
- 펼치기에는 방향 표시와 44px 선택 면을 둔다. 유의사항은 작은 각주로 줄이지 않는다.
  배경과 구분선은 절제하며, 1080px PNG의 본문은 48px 이상·보조 문구는 42px 이상이다.
- 변경 비교는 달라지는 값부터 제시하고, 전체 구성은 기존·변경 각 한 장만 펼친다.
  출처 로드 실패는 재시도를 제공하고, 확인 불가를 검토 완료처럼 보이지 않게 한다.
- 원본 처방·오전/오후·날짜 이동 뒤 닫기와 포커스가 현재 화면으로 돌아와야 한다.
  비활성 리더는 Escape를 가로채지 않으며, 화면·출처·계정 변경 후 오래된 내보내기는 취소한다.
- OS와 앱의 동작 줄이기를 모두 따른다. 합성 검사 통과는 실제 선수의 이해도 검증이나
  공개 배포 완료를 뜻하지 않는다.

  IME 조합·저장 중에는 이동하지 않는다. 자정에는 준비된 미복원·미편집 빈 입력창만
  오늘로 옮기며, 입력·복원·유효화 오류·조합·저장 중인 작성 날짜는 유지한다. 자정 이후
  전날 기록을 확정 저장하면 이전 날짜의 최근 행과 새 오늘 입력창이 함께 보인다.
- 저장된 계획이 있으면 오늘과 내일의 모든 오전·오후 슬롯을 기본 노출한다.
  훈련 이름·실제 MAIN 표기·휴식·저장된 진행 상태를 함께 읽으며 완료·건너뜀을
  이유로 일정을 제거하지 않는다. 해당 날짜 일정 없음과 휴식 계획은 구별한다.
  계획이 없는 상태는 짧은 계획 만들기 진입으로 표시한다.
- 계산된 카탈로그 연결과 기존 훈련 표기만 사용하며 새로운 페이스·시간을 계산하지
  않는다. 출처 검증 대기·읽기 실패·로딩에는 실행 가능한 내용을 노출하지 않는다.
- 홈의 오늘 기록은 메모 입력과 선택 컨디션, 운동 기록 진입을 한 영역으로 묶는다.
  메모는 홈에서 명시적으로 저장하며 기존 evening 정본·용도 선택·암호화·초안·
  계정 최종 저장 관문을 사용한다. 운동 기록은 기존 post-session 경로를 유지한다.
  메모 입력으로 운동 수행이나 계획 완료를 만들지 않는다.
- 기존 기록을 자동 선택해 덮어쓰지 않는다. 저장 성공만 완료로 표시하고 대기·충돌·
  실패에는 입력을 유지한다. 계정 전환은 이전 편집 상태를 폐기하며 날짜가 바뀌면
  작성 시작 날짜를 명시하고 사용자의 새 기록 선택 전까지 저장 날짜를 유지한다.
- 일지·오라클 예시 및 큰 첫 방문 소개는 홈에 노출하지 않는다. 예시의 기존 내부
  경로는 유지한다. 소식·설치 안내는 닫을 수 있는 별도 하단 영역에 배치한다.
- 320/375px·큰 글씨에서 날짜별 훈련·입력·저장을 읽을 수 있게 줄바꿈한다.
  홈 진입만으로 선택 입력에 초점이나 스크롤을 이동하지 않는다. 로컬 합성 검사와
  공개 배포·실계정 저장 검증을 구별한다.

## 9. 이 문서의 지위

### 2026-10-15 어린 선수의 달력 읽기 개선

- 달력 역할에는 같은 Lucide 기호를 반복 사용한다: 주요 Target, 기본 Footprints,
  회복 Leaf, 휴식 Moon, 경기 Flag, 플라이오 MoveUpRight. 기호만으로 분류하지 않고 기존 이름·색을 함께 표시한다.
- 작은 훈련 면은 행동 반경을 재사용하며 밝은 달력 표면에서 읽는다. 주기 범위는 밑줄로 구분하고 역할색을 덮지 않는다.
- 훈련 종류 안내는 눌러 여는 짧은 색·기호 사전으로 제공한다. 메인 분류와 시간대는 계속 기본 노출한다.
- 날짜 상세의 뒤로·이전·다음은 눌리는 면을 명확하게 하고 오전·오후 선택은 색과 밑줄로 구분한다.
- 재미를 위해 출석 압박, 순위, 운동량 보상, 건강 판정, 가짜 완료를 추가하지 않는다.
- 실제 어린 사용자 이해도는 별도 검수이며 합성 브라우저 검사로 대체했다고 보고하지 않는다.

- 마스터 플랜(§3 홈 순서, §21 확정 기본값)과 충돌하면 마스터
  플랜이 우선한다.
- 계약 테스트(`visual-system.contract.test.ts`)와 충돌하면 계약
  테스트가 우선한다 — 단, 그 경우 이 문서를 고치는 PR을 함께 낸다.
- 기준 변경은 오너 승인 + 이 문서 개정으로만 한다. 컴포넌트
  CSS에서 조용히 우회하지 않는다.
