## 0. 한 문장 정체성

**"Scientific Minimalism — Tufte × Linear, 위에 얹힌 종이 다이어리."**

- 앱의 뼈대(탭, 분석, 계획, 오라클)는 **차갑고 정확하게**: 직각,
  hairline, 절제된 색.
- 일지·꾸미기 영역만 **따뜻하게**: 종이 크림톤, 연필·만년필·마스킹
  테이프의 물성.
- 이 두 세계의 경계가 무너지면 "지저분하다"는 인상이 시작된다.
  **어느 세계의 컴포넌트인지 먼저 정하고 시작하라.**

## 1. 절대 규칙 (계약 테스트가 막는 것 — 우회 금지)

`visual-system.contract.test.ts`가 CI에서 강제한다. 아래를 어기면
빌드가 아니라 **머지가** 막힌다.

| # | 규칙 | 이유 |
|---|------|------|
| A1 | `box-shadow` 금지 (`none`만 허용) | 그림자 없는 평면 위계. 깊이는 border와 배경 단차로 표현 |
| A2 | 3~4px 좌측 색 스트립(`border-left: 3px solid …`) 금지 | 과거에 지저분함의 주범이었음. 색 강조는 dot·underline로 |
| A3 | 폰트는 self-host된 **Pretendard Variable 단일** (sha256 고정) | 플랫폼별 렌더링 편차 제거. 한글 라벨에 cursive/Segoe Print류 금지 |
| A4 | 토큰 단일 소스는 루트 `colors_and_type.css` + `colors_and_type_journal.css` | 컴포넌트 CSS에서 새 hex 색을 발명하지 마라. 필요하면 토큰 PR 먼저 |

**신규 색이 필요하면**: 컴포넌트 파일에 hex를 쓰지 말고
`colors_and_type*.css`에 토큰을 추가하는 별도 커밋을 만들고 사유를
주석으로 남긴다.

## 2. 색 사용 기준

- **중립이 기본**: `--bg`(웜 오프화이트) / `--surface` / `--ink`
  계열 4단계. 화면의 90%는 이 안에서 끝나야 한다.
- **브랜드 틸(`--brand: #0D5F5A`)은 단일 액센트**: 한 화면에 틸이
  두 군데 이상 "면"으로 칠해져 있으면 이미 과하다.
- **의미색(`--ok/--warn/--err/--info/--unc`)은 상태 전달에만**:
  장식 목적 사용 금지. 특히 `--unc`(보라)는 AI 판정 불확실성 전용.
- **에너지 시스템 색 6종**(`--e-base/lt/vo2/gly/atp/rest`)은
  **dot + underline 전용, 배경 채움 금지**가 1차 원칙. 넓은 면이
  필요한 히트맵·차트 셀에만 `--e-*-wash` 4-tier를 쓴다.
- 색만으로 정보를 전달하지 마라 — **항상 텍스트·숫자·패턴 병기**
  (누적 거리 히트맵이 셀 안에 km 숫자를 병기한 것이 표준 사례).

## 3. 형태·간격·타이포

- **직각 우선**: 기본 `--r-0`, 입력·버튼 최대 `--r-md`(4px).
  아바타 원형(50%)만 예외. 둥근 카드 남발 금지.
- **간격은 4px 그리드**(`--space-1`~`--space-16`)만 사용.
  임의의 `margin: 7px` 같은 값은 검수에서 지적된다.
- **테두리는 hairline**(`--bw-line: 1px`)이 기본. 강조는 굵기가
  아니라 `--ink` 색 테두리로.
- 타입 스케일은 `--fs-*` 토큰만: 본문 14.5px, 캡션 12px.
  **한 컴포넌트에 폰트 크기 3단계 초과 금지.**
- 한글 줄바꿈은 `word-break: keep-all`, 본문 `line-height` 1.45~1.6.

## 4. 그래프·시각화 기준 (Tufte 원칙)

앞으로 만들 에너지 시스템 누적, 9.5일 주기, 중주기 시각화에
그대로 적용한다.

1. **데이터-잉크 비율 최대화**: 격자선·범례 박스·3D·그라데이션
   장식 금지. 축은 hairline 하나면 충분하다.
2. **미기록 ≠ 0**: 값이 없으면 `—` 또는 "기록 없음". 0으로 그리는
   순간 거짓말이다 (누적 거리 v1이 확립한 계약 — 모든 후속 차트에
   동일 적용).
3. **막대 최소 시각 높이**: 값이 있으면 최소 12px, 미기록 표시는
   8px 회색 스텁 — 구분이 한눈에 되어야 한다.
4. **모든 차트에 접근 가능한 쌍둥이**: `AccessibleTrendTable` 병행
   + `role="img"` aria-label에 전체 데이터 문장 서술. 예외 없음.
5. **집계 기준·제외 건수를 차트 근처에 공개**: "제외한 기록 N건"
   패턴 유지. 예쁜 차트보다 정직한 차트가 먼저고, 정직함이
   깔끔하게 보이는 방법이 이 문서다.
6. **판정 문구 금지**: "좋아졌어요/위험해요" 같은 해석은 분석
   화면 권한 밖이다. 서술만 한다.
7. 에너지 시스템 차트에서 **MIXED_UNALLOCATED는 반드시 시각적으로
   존재**해야 한다(`--e-rest` 계열 회색). 미배분을 숨기고 6색으로
   100%를 채우는 것은 §2 정직성 위반.

## 5. 아이콘 기준 (생성형 포함)

- **UI 아이콘은 lucide-react 단일 세트**: 크기 15/16/18/20 중
  택일, `stroke-width` 기본값 유지, 색은 `currentColor`.
  다른 아이콘 팩 혼용 금지.
- **장식·꾸미기용 생성 아이콘**(스티커, 배지, 오라클 카드 일러스트
  등)을 AI로 생성할 때의 합격 기준:
  1. **팔레트 준수**: 토큰 색(중립 + 종이톤 + 에너지 wash)에서만
     추출. 원색 무지개·네온 즉시 반려.
  2. **선 기반 > 면 기반**: hairline 세계와 어울리는 얇은 선화,
     단색 또는 2색 이내. 사실적 렌더링·그림자·입체 금지 (A1과
     동일 정신).
  3. **SVG 우선**: 벡터로 받아 `currentColor`/토큰 변수로 색을
     바인딩. 비트맵 스티커는 꾸미기 전용 영역에서만, @2x 이상.
  4. **배경 투명 + 시각적 정사각 바운딩**: 크기 뒤죽박죽 방지.
  5. **동일 시리즈는 한 번에 생성**: 배지 12종을 다른 날 다른
     프롬프트로 만들면 반드시 톤이 갈라진다. 시리즈 단위로 생성
     → 나란히 놓고 톤 검수 → 통과분만 반영.
  6. 텍스트가 들어간 생성 이미지 금지 — 글자는 항상 실제 폰트로.
- **이모지는 UI 크롬에 금지**: 사용자가 일지·꾸미기에 직접 입력한
  콘텐츠에서만 허용.

## 6. 꾸미기(데코레이션) 기준

꾸미기는 "예쁘게 만들 자유"가 가장 큰 영역이지만, 자유는 **일지
종이 위에서만** 성립한다.

- **물성 어휘를 지켜라**: `colors_and_type_journal.css`가 정의한
  종이(`--paper`), 연필(`--pencil`), 만년필 청색(`--ink-blue`),
  마스킹 테이프(`--tape/--tape-2`), 형광펜(`--highlighter`).
  새 꾸미기 아이템은 이 물성 중 하나로 설명 가능해야 한다.
  "네온 LED 프레임"처럼 어휘 밖 물성은 톤 붕괴 → 반려.
- **꾸미기는 일지 페이지 프레임 내부에만 렌더**: 탭 바·분석 차트·
  안전 관련 화면에 스티커·테이프가 침범하면 즉시 반려.
- **가독성 우선**: 어떤 꾸미기 조합에서도 일지 본문 대비
  (4.5:1)가 유지되어야 한다. 형광펜 불투명도 상한 0.32 유지.
- 꾸미기·포인트는 처방·안전·템플릿 권한이 없다(마스터 플랜 §21).
  "이 스티커를 달면 훈련 강도 +…" 류의 연결은 시각 문제 이전에
  계약 위반.
- **이모지 스티커**: 유니코드 텍스트 렌더만 허용(플랫폼 이모지
  폰트 위임 — iPhone은 자동으로 애플 이모지로 보인다). 특정 벤더
  이모지 아트워크(이미지·스프라이트·웹폰트) 번들은 저작권 침해로
  즉시 반려. 종이 프레임 내부 전용, 페이지당 최대 3개(전용 슬롯
  3칸), 크기는 3단(20/24/28px) 고정. 세 슬롯은 본문 위 절대좌표가
  아니라 본문과 분리된 전용 레일에 렌더해 글과 터치 영역을 가리지
  않아야 한다. 스티커는 날짜(페이지)에 붙지 메모·항목에 붙지 않으며,
  배치 데이터를 분석·오라클·포인트 입력으로 쓰는 것은 금지.

## 7. 모션·터치·반응형

- 터치 타깃 최소 `--app-touch-min`(44px). 시각적으로 작아 보여야
  하면 패딩으로 히트 영역을 채워라.
- 모션은 `--ease-out-strong` 이징, 200~350ms. 등장은 opacity +
  8px 이하 translate. 바운스·회전·무한 반복 금지.
- **모든 모션에 `prefers-reduced-motion` 대응 필수** (기존 6곳
  선례). 모션 없이도 상태 변화가 인지되어야 한다.
- 기준 뷰포트 375×667. **가로 스크롤은 결함이다** — e2e가
  `scrollWidth <= innerWidth`를 검사한다. 좁은 화면에서는 4열→2열
  접기(누적 거리 totals 패턴)를 따른다.

## 8. "이쁘다"의 검수 체크리스트

PR에 새 시각 요소가 있으면 검수자는 아래를 순서대로 본다.
개발자는 스스로 먼저 채점하라.

```yaml
visual_review_checklist:
  - 세계 구분: 크롬(직각·hairline)인가 종이(다이어리)인가 명확한가
  - 새 hex 색 발명 없음 (토큰만 사용)
  - 그림자/좌측 스트립/cursive 없음 (계약 테스트 통과)
  - 한 화면 액센트 면적: 틸 1곳 이하, 의미색은 상태에만
  - 간격 4px 그리드, 폰트 크기 3단계 이하
  - 차트: 미기록≠0, 제외 건수 공개, 접근성 테이블 쌍둥이 존재
  - 아이콘: lucide 단일 세트 또는 §5 기준 통과한 생성 자산
  - 꾸미기: 종이 프레임 내부, 물성 어휘 내, 본문 대비 유지
  - 375px에서 가로 스크롤 없음, 터치 44px
  - reduced-motion에서 기능 손실 없음
```

10항목 중 하나라도 애매하면 "일단 머지하고 나중에 다듬자"가 아니라
**머지 전에 다듬는다.** 시각 부채는 코드 부채보다 빨리 쌓이고 더
비싸게 갚는다.

## 9. 이 문서의 지위

- 마스터 플랜(§3 홈 순서, §21 확정 기본값)과 충돌하면 마스터
  플랜이 우선한다.
- 계약 테스트(`visual-system.contract.test.ts`)와 충돌하면 계약
  테스트가 우선한다 — 단, 그 경우 이 문서를 고치는 PR을 함께 낸다.
- 기준 변경은 오너 승인 + 이 문서 개정으로만 한다. 컴포넌트
  CSS에서 조용히 우회하지 않는다.
