## 0. 한 문장 정체성

### 2026-10-07 오너 승인: 구간별 작은 안내 이미지

오너는 이미지 활용 확장 시안을 검토한 뒤 실제 개선 진행을 승인했다. 아래 범위에서
§5의 비트맵 사용 영역을 확장한다. UI 아이콘과 데이터 표현을 삽화로 바꾸는 승인이 아니다.

- 일지 종류 선택의 첫 기록 안내, 확인된 빈 일지 달력의 제목, 워치 파일 선택,
  훈련 배우기의 목록 입구에 맥락에 맞는 투명 삽화 하나를 사용할 수 있다.
  계획 시작·페이스 도움말·꾸미기 안내·저장 완료는 기존 상태와 안내 영역 안에서만
  소형으로 사용한다. 새 랜딩이나 필수 팝업을 만들지 않는다.
- 작은 안내는 64px, 목록·파일 입구는 최대 80px를 사용한다. 제목과 안내 옆에
  배치하며 새 카드·설명·빈 공간을 추가해 주요 행동을 아래로 밀지 않는다.
  기존 날짜·버튼·예시 달력·근거와 입력 단위는 유지한다.
- 반복 작성·입력·계산 결과·자료 본문·날짜 칸·안전 확인·전송 대기·실패·충돌에는
  안내 삽화를 반복하지 않는다. 노출은 기존 기록 유무와 화면 단계로 결정하며,
  방문 추적·새 설정·계정 데이터 수집을 추가하지 않는다.
- 안내 이미지는 개인 장식이나 구매할 상품이 아니다. 실제 재료 선택에는 기존
  보유 카탈로그 이미지를 사용한다. 표정이나 그림으로 훈련·건강·저장 성공을 판단하지 않는다.
- 기존 PNG 원본은 보존하고 작은 투명 WebP 파생본을 사용한다. 장식 이미지는
  빈 대체 텍스트·고정 크기·지연 로딩을 갖추고, 이미지 실패가 글과 행동을 막지 않는다.
  새 이미지를 서비스 워커 사전 저장 목록에 추가하지 않는다.
- 서체·토큰·lucide 아이콘·평면 위계와 기존 훈련·안전·저장·구매 계약은 바꾸지 않는다.
  이 승인과 로컬 구현·검증·공개 배포 완료는 구분한다.

### 2026-10-06 오너 승인: 한 번에 한 선택

2026-10-07 선수 피로 감사 후속 승인: 저장 상태 정리, 계획의 중복 선택 통합,
오라클 결과 우선, 기록 재사용·가져오기·읽을거리·더보기의 목적별 이동을 적용한다.

- 저장한 일지 수와 특정 분석에 적격인 근거 수를 같은 이름으로 표시하지 않는다.
  값이 적은 일지도 저장 사실을 먼저 보여주고 미입력은 0으로 대체하지 않는다.
- 빠른 일지 저장 전에 선수가 별도 계획 진행 표시를 선택할 수 있다. 기본 미선택,
  응답 변경 시 선택 해제, 실제 일지 저장 성공 이후에만 기존 잠금·버전 검사를
  거쳐 반영한다. 계획 표시 실패가 성공한 일지를 취소하거나 중복 저장하지 않는다.
- 저장 확인과 처방 수행 확인은 다른 사실이다. 완료 표시로 거리·시간·페이스·회복을
  실제 수행했다고 채우지 않는다. 통증·계정 전환·저장 실패의 방어 조건은 유지한다.
- 상위 화면은 일정·훈련 조절·근거처럼 역할이 드러나는 진입을 제공한다. 소개 화면
  다음에 같은 소개가 반복되거나 각 구성요소가 같은 역할의 메뉴를 중복 제공하지 않는다.
- 파일을 가진 사용자는 바로 가져올 수 있고, 없는 사용자는 기기별 준비 안내부터
  시작한다. 준비 안내를 자동 연동으로 부르지 않는다. 실패·읽기 중 상태에 빈 달력을
  표시해 기록 없음으로 오해시키지 않는다.

2026-10-07 화면 간 간결함 후속 구현:

- 빠른 기록은 결과·시간대·힘든 정도·몸 상태 중 현재 질문 하나를 주 영역에 표시한다.
  이전 답은 수정 가능하게 유지하며, 뒤로 이동한 질문과 답은 초안 복귀 시 함께 보존한다.
  추가 운동·메모·모름·부분 수행·휴식·건너뜀과 명시적인 저장은 유지한다.
- 계획 결과는 기간·횟수·기준 기록, 달력, 첫 훈련을 먼저 표시한다. 합계·목적의 상세는
  이름 있는 펼침으로 제공하며, 적용에 필요한 수행 수치와 안전 상태는 숨기지 않는다.
- 오라클은 확인 가능한 결과를 먼저 보여준다. 읽기 미완료·실패를 빈 기록이나 예시로
  대체하지 않는다. 관심·계속 보기 같은 이동된 기능은 묶음 이름에서도 찾을 수 있어야 한다.
- 메모는 간단히·자세히 선택과 결과물을 먼저, 표현·꾸미기를 그다음 제공한다.
  일지 읽기의 단색 바탕과 사용자가 꾸민 원본 페이지는 분리한다.
- 달력 날짜 상세는 전체 기록 수와 선택 목록을 남기고 선택한 기록만 자세히 펼친다.
  200% 글자 확대에서도 날짜 숫자는 한 덩어리로 읽히며 장식이 숫자를 분리하지 않는다.
- 단계별 뒤로가기와 도구 닫기는 별도 행동이다. 닫기는 진입한 화면으로 복귀한다.
  경기 기록의 새 입력은 종목·시간·날짜로 나누되 기존 기록의 빠른 편집은 유지한다.

2026-10-07 배경·선·계획 문구 후속: 반복·회복이 미정인 훈련은 짧은 상태와
`이 시간 내내 강하게 뛰지 마세요`를 먼저 표시하고, 긴 설명은 이름 있는 도움말로
펼친다. 실제 반복·회복이 있는 처방에는 미정 안내를 붙이지 않는다. 계획의 상태·첫
세션·접힌 설명·달력 바깥에 중복 구분선을 넣지 않는다. 날짜 칸·선택·초점·입력·
저장 실패의 경계는 유지한다. 작성 화면의 전체 테마 그림과 반복 줄무늬를 제거하고
단색 바탕과 읽기 전용 작은 대표 그림만 유지한다. 완성된 일지의 테마·꾸미기·소유
선택·배치 자료는 변경하지 않는다. 이는 표시 변경이며 처방 수치나 안전·저장 판정의
완료 범위를 확장하지 않는다.

2026-10-07 회복·첫 데이터 진입 개선: 오라클의 회복 입력은 짧은 진입과 선택한 상세로
제공한다. 운동의 힘든 정도·몸 상태·통증·수면을 합산하지 않는다. 기존 피로도 실험은
이름 있는 상세 진입으로 보존하고 미입력 값을 5로 채우지 않는다. 기록이 없는 사람에게
운동 파일 가져오기와 최고기록 남기기를 제공하되, 파일 미리보기·저장·분석·기기 자동
연동의 지원 범위를 구분한다. 정확한 경계는 `specs/active/RECOVERY_AND_RECORD_START_UX_CONTRACT.md`를 따른다.

2026-10-07 이전·현재 후속 개선 통합: 계획 입력은 현재 질문을 먼저 표시하고 기록 입력과
훈련 조건을 전체 완료율로 혼동할 고정 숫자 단계를 사용하지 않는다. 이미 답한 항목의 수정과
달력 예시는 이름 있는 진입점으로 질문 아래에 유지한다. 예시는 선택한 7·9·10일 길이를 읽되
생성된 훈련 배치로 표시하지 않는다. 주기 종료 후에는 다음 계획안 만들기를 직접 노출하고,
기록 확인·조정과 선택한 안의 시작을 구별한다. 시작 전 안전·저장 확인은 그대로 유지한다.
일지·계획의 기본 표시는 `힘든 정도`를 사용하며 RPE 원본 필드·의미·물음표 설명은 보존한다.

- 홈의 기록·오늘 훈련을 오라클 예시보다 먼저 보여준다. 예시와 부가 해설은 눌러 연다.
- 계획 첫 입력은 종목 선택, 기록 유무, 필요한 수치 입력으로 나눈다. 뒤로 가도 입력을 유지한다.
- 추천 결과는 실제 달력과 명시적인 시작 행동을 우선한다. 일정·훈련 수정과 추천 근거는 접되 삭제하지 않는다.
- 오라클 세부 분석은 항목을 선택했을 때만 보여준다. 비어 있는 코칭·관심 목록을 긴 본문으로 반복하지 않는다.
- 일지의 달력과 월별 합계를 동시에 펼치지 않는다. 날짜별 상세, 원문, 월별 보기로 이어지는 기존 경로를 유지한다.
- 상태 오류·전송 대기·불완전한 처방·통증 확인·출처 제외 수는 관련 동작과 결과 옆에 유지한다. 접어서 안전 검사나 저장 실패를 숨기지 않는다.
- 합성 페르소나, 실행한 브라우저 이동, 코드 검토, 실제 사용자 검증을 별도로 보고한다.

### 2026-10-01 오너 승인: 오라클 브랜드와 쉬운 행동 이름

- `오라클`은 훈련 해석·추천·계획을 아우르는 시스템 이름이다. 하단 `분석` 탭과
  해당 화면 제목은 `오라클`로 표시하고, 기존 `계획` 탭은 유지한다.
- 홈·결과·계획·근거 화면에는 짧은 브랜드 표시를 사용한다. 설명이나 장식이
  수행할 훈련과 선택 버튼을 아래로 밀지 않도록 기존 보조 제목 스타일을 쓴다.
- 행동은 `내 훈련 살펴보기`, `훈련 계획 만들기`, `다른 훈련 받기`, `수행 결과 비교하기`
  등 실제 목적을 말한다. 모든 행동을 `오라클 받기` 같은 이름으로 통일하지 않는다.
- 기록 없는 사용자의 `예시 결과 보기`와 실제 개인 결과를 구분한다. 이름 변경을
  근거로 개인화 완료·AI 사용·훈련 효과를 새로 주장하지 않는다.
- 데이터 사용 동의·개인정보·계산 기준·제외 사유의 `분석`은 뜻을 보존한다.
  브랜드명을 넣기 위해 과학적 설명이나 안전 안내를 바꾸지 않는다.
- 이 승인은 표시 문구에 한정한다. 경로 식별자·뒤로가기·저장 데이터·계산·안전
  판단·동의 범위·기능 활성화 권한은 바꾸지 않는다. 기존 정본 승격도 뜻하지 않는다.

### 2026-09-20 오너 승인: 홈 IA 구현 방향

UX·UI 리뷰 결과를 구현 방향으로 승인한다. 이는 배포 또는 런타임 검증 완료가
아니다. 기존 홈의 편안한 간격과 오늘 맥락·안전 우선 원칙을 유지하면서 다음을
적용한다.

- 하루 기록은 종류·개수를 묶은 짧은 요약으로, 분석은 짧은 진입으로 제공한다.
  상세 거리·에너지는 분석 화면에 둔다.
- `훈련 배우기`와 `일지 꾸미기`는 홈에서 보이게 하고, 포인트·상점과 휴지통·
  삭제 관리는 홈에서 분리한다.
- 기존 탭은 고정하고 일반 메뉴를 중복 생성하지 않는다. 버튼 라벨은 실제
  도착 화면과 일치시키며 뒤로가기는 진입 원점을 보존한다.
- 모든 콘텐츠를 한 화면에 압축하지 않는다. 큰 글자·알림·상태 설명이 필요한
  경우 세로 스크롤을 허용한다.
- 도메인 안전·저장·보상 계약과 기록만으로 모든 훈련이 완료되었다고 주장하는
  규칙은 변경하지 않는다.

### 2026-09-14 오너 승인: 목적 중심 진입과 설명 분리

이번 승인은 아래 2026-09-12 미감 작업의 문구·흐름 유지 제한을 해당 UX 범위에서 갱신한다.
기록을 주요 행동으로 두고 분석·계획·예시·학습의 진입을 명확히 한다. 기본 사용자의
상세 처방·근거·누적 분석 기능을 삭제하거나 선수용에만 감추지 않는다.

- 짧은 전문 용어는 기존 물음표 도움말, 긴 원리·집계 기준은 기본 닫힌 `InfoDisclosure`를 사용한다.
- 도움말 이름은 `자세히`만 반복하지 않고 `어떤 기록을 분석하나요?`처럼 내용을 알린다.
- 집계 제외 건수가 있으면 차트 옆에 짧게 남기고, 긴 이유·기간·중복·출처 상세를 접는다.
- 저장 실패·전송 대기·충돌·통증 확인·처방 적용 불가·오래된 기준 기록 등 현재 행동에
  필요한 상태는 접힌 설명 안에만 두지 않는다. 공유·삭제·동의·계획 확정도 자동으로 실행하지 않는다.
- 개발용 상태 코드·검수 과정·스키마·런타임 용어를 기본 화면의 설명으로 사용하지 않는다.
  정확한 원본은 근거 화면과 문서에 보존하며, 사용자 문구는 실제 의미로 풀어 쓴다.
- 단일 선택의 기존 다음 단계 전환, 이전 선택과 스크롤 복귀, 44px 터치 영역을 유지한다.
  글자 확대 시에는 세로 스크롤을 허용한다. 정보를 감추기 위한 전역 CSS나 글자 축소는 금지한다.
- 저장 안내는 현재 계정·기기 상태를 따른다. 게스트도 사용할 수 있는 기록 화면에
  자동 초안 보관의 로그인 조건을 전체 기능 차단처럼 표시하지 않는다.

## 2. 색 사용 기준

### 2026-09-30 오너 승인: 달력 역할색

[달력 역할 표시 계약](../specs/active/CALENDAR_TRAINING_ROLE_PRESENTATION_CONTRACT.md)에 따라
달력의 세션 면은 경기 노랑·주요 연한 살구·플라이오 민트·기본 흰색·회복 하늘색을
사용한다. 이는 에너지 시스템 색의 전역 교체가 아니라 달력 전용 의미 토큰이다.
오전·오후를 분리하고 텍스트를 병기한다. 아래의 중립 90%·배경 채움 제한은 이 승인된
달력 셀에 한해 예외이며, 나머지 화면·처방·안전 판정에는 그대로 적용한다.

- **중립이 기본**: `--bg`(웜 오프화이트) / `--surface` / `--ink`
  계열 4단계. 화면의 90%는 이 안에서 끝나야 한다.
- **브랜드 틸(`--brand: #0D5F5A`)은 단일 액센트**: 한 화면에 틸이
  두 군데 이상 "면"으로 칠해져 있으면 이미 과하다.
- **의미색(`--ok/--warn/--err/--info/--unc`)은 상태 전달에만**:
  장식 목적 사용 금지. 특히 `--unc`(보라)는 AI 판정 불확실성 전용.
- **에너지 시스템 색 6종**(`--e-base/lt/vo2/gly/atp/rest`)은
  **dot + underline 전용, 배경 채움 금지**가 1차 원칙. 넓은 면이
  필요한 히트맵·차트 셀에만 `--e-*-wash` 4-tier를 쓴다.
- 색만으로 정보를 전달하지 마라 — **항상 텍스트·숫자·패턴 병기**
  (누적 거리 히트맵이 셀 안에 km 숫자를 병기한 것이 표준 사례).

6. **판정 문구 금지**: "좋아졌어요/위험해요" 같은 해석은 분석
   화면 권한 밖이다. 서술만 한다.
7. 에너지 시스템 차트에서 **MIXED_UNALLOCATED는 반드시 시각적으로

## 6. 꾸미기(데코레이션) 기준

### 2026-10-02 오너 승인: 일지 꾸미기 통합과 달력 결과 표시

- 편집은 `일지 꾸미기 → 일지 / 달력` 한곳에 모은다. 새 진입은 일지부터 시작하며 달력 화면에는 상시 편집 버튼을 두지 않는다.
- 기존 일지 v3 좌표·배열·24개 한도는 그대로 유지한다. 작성 화면은 종이와 읽기 전용 대표 그림만 사용하고 실제 원문 프레임을 축소 재사용하지 않는다.
- 일지 달력만 공통 종이와 위아래 여백(각 72px, 비어 있으면 생략)을 사용할 수 있다. 날짜표·오늘·선택·훈련 역할색에는 겹치지 않는다. 훈련 계획·입력용 달력은 대상에서 제외한다.
- 날짜 칸과 기존 홈/선택일 요약에는 실제 기록이 있는 날의 마지막 유효한 보유 그림 하나를 16px로 표시한다. 테이프·텍스트·개인 메모는 제외하며 별도 클릭 영역을 만들지 않는다.
- 이 예외는 읽기 전용 결과의 노출 범위만 확장한다. 탭 바·분석·안전 화면을 꾸미거나 장식에 훈련·건강 의미를 부여할 권한은 없다.
- 달력은 별도 v1 문서의 명시적 초안 적용을 사용한다. 구매·포인트는 취소·초기화·되돌리기의 대상이 아니다.

꾸미기는 "예쁘게 만들 자유"가 가장 큰 영역이지만, 자유는 **일지
종이 위에서만** 성립한다.

- **물성 어휘를 지켜라**: `colors_and_type_journal.css`가 정의한
  종이(`--paper`), 연필(`--pencil`), 만년필 청색(`--ink-blue`),
  마스킹 테이프(`--tape/--tape-2`), 형광펜(`--highlighter`).
  새 꾸미기 아이템은 이 물성 중 하나로 설명 가능해야 한다.
  "네온 LED 프레임"처럼 어휘 밖 물성은 톤 붕괴 → 반려.
- **꾸미기는 일지 페이지 프레임 내부에만 렌더**: 탭 바·분석 차트·
  안전 관련 화면에 스티커·테이프가 침범하면 즉시 반려.
- **가독성 우선**: 어떤 꾸미기 조합에서도 일지 본문 대비
  (4.5:1)가 유지되어야 한다. 형광펜 불투명도 상한 0.32 유지.
- 꾸미기·포인트는 처방·안전·템플릿 권한이 없다(마스터 플랜 §21).
  "이 스티커를 달면 훈련 강도 +…" 류의 연결은 시각 문제 이전에
  계약 위반.
- **이모지 스티커**: 유니코드 텍스트 렌더만 허용(플랫폼 이모지
  폰트 위임 — iPhone은 자동으로 애플 이모지로 보인다). 특정 벤더
  이모지 아트워크(이미지·스프라이트·웹폰트) 번들은 저작권 침해로
  즉시 반려. 종이 프레임 내부 전용, 페이지당 최대 3개(전용 슬롯
  3칸), 크기는 3단(20/24/28px) 고정. 세 슬롯은 본문 위 절대좌표가
  아니라 본문과 분리된 전용 레일에 렌더해 글과 터치 영역을 가리지
  않아야 한다. 스티커는 날짜(페이지)에 붙지 메모·항목에 붙지 않으며,
  배치 데이터를 분석·오라클·포인트 입력으로 쓰는 것은 금지.

## 7. 모션·터치·반응형

### 훈련 선택·조절 화면 (2026-09-27)

- 실제 수행할 구성과 순서를 먼저 보여준다. 조절 값은 같은 구조화 처방을 읽는다.
- `다른 훈련`은 저장 없는 미리보기다. 변경한 값을 확인한 뒤 명시적으로 적용한다.
- 조절은 처음 두 종류를 우선하고 나머지는 `더 조절`에 둔다. 누를 때마다 전체
  화면을 이동시키거나 확인 팝업을 띄우지 않는다. 적용 실패·조건 변경은 숨기지 않는다.
- 되돌리기·다시하기·초기화는 아이콘과 접근 가능한 이름을 함께 사용한다.
- 합계 표·기술적 기준은 펼침 안에 두되, 회복 방식·시간 등 수행 정보는 숨기지 않는다.
- 수치 방향을 알 수 없으면 +/- 버튼을 만들지 않는다. `반복 줄이기`, `1회 거리 늘리기`,
  `반복 사이 더 쉬기`처럼 실제 변화에 맞는 이름을 쓴다.
- 훈련 선택 성공은 훈련 완수나 안전 승인처럼 축하하지 않는다. 짧은 미리보기 전환만
  제공하고 포인트·연속 선택 횟수로 운동량 증가를 유도하지 않는다.

### 2026-09-30 독립 페르소나 검수: 훈련 변경의 연속성

- 다른 훈련 목록과 무작위 미리보기는 현재 종목·경험·목적의 채택 범위 안에서 고른다.
  조건에 맞지 않는 구성을 먼저 보여주고 마지막 버튼에서만 거절하지 않는다.
- 적용에 필요한 구간 시간은 접힌 도움말에 숨기지 않는다. 입력하지 않은 값을
  자동으로 채우지는 않으며, 입력이 필요한 이유와 적용 상태를 짧게 함께 표시한다.
- 이미 반영한 구성의 기준 기록·직접 입력·환경 확인을 다시 열 때 보존한다.
  새 구성의 더 긴 시간에 대한 확인은 기존 구성의 확인으로 대체하지 않는다.
- 미적용 미리보기가 있으면 기존 계획을 조용히 확정하지 않는다. 적용과 변경 취소를
  명시적으로 제공한다. 이 규칙은 신규 처방 수치·강도·양·빈도 승인이 아니다.
- 최초 기록 입력부터 미저장 이탈을 보호한다. 더 강한 계정 전환·복구 가드를 덮어쓰지 않는다.
- 후보 날짜 상세, 오늘 훈련, 방법 상세는 같은 처방을 읽는다. 본운동과 준비·회복·정리 포함
  전체 시간을 구분하고, 실제 반복·회복이 있는 훈련에 미정 안내를 붙이지 않는다.
- 같은 목적 추첨은 현재 바로 적용 가능한 방법만 사용하며, 같은 슬롯·적격 풀에서는 미노출
  방법을 먼저 보여준다. 추가 입력이 필요한 구성은 수동 목록에서 확인하며 임의로 조건을 채우지 않는다.
- 하나의 변경을 A/B 계획안에 함께 반영할 때 양쪽 조건을 검사한다. 한쪽의 더 짧은 시간을
  넘는 경우 기존 명시 확인을 받고, 그 계획안도 시간이 바뀐다는 사실을 안내한다.
- 거리 회복 구조를 시간 회복으로 덮어쓰지 않는다. 직접 정한 시간은 거리와 함께 별도 표시한다.

- 터치 타깃 최소 `--app-touch-min`(44px). 시각적으로 작아 보여야
  하면 패딩으로 히트 영역을 채워라.
- 모션은 `--ease-out-strong` 이징, 200~350ms. 등장은 opacity +
  8px 이하 translate. 바운스·회전·무한 반복 금지.
- **모든 모션에 `prefers-reduced-motion` 대응 필수** (기존 6곳
  선례). 모션 없이도 상태 변화가 인지되어야 한다.
- 기준 뷰포트 375×667. **가로 스크롤은 결함이다** — e2e가
  `scrollWidth <= innerWidth`를 검사한다. 좁은 화면에서는 4열→2열
  접기(누적 거리 totals 패턴)를 따른다.

### 달력 위치·복귀·예시 (2026-09-30)

- 일지 최초 진입은 최근 실제 기록 날짜로 연다. 미래 오입력·수정 시각으로 결정하지 않는다.
- 직접 탐색한 월·날짜·스크롤을 데이터 갱신이 덮어쓰지 않는다. `최근 일지`와 `오늘`은 별개다.
- 원문에서 Back, 탭 왕복, 하루 리더의 이전/다음 이동 뒤에도 날짜·포커스 의미를 보존한다.
- 후보는 후보 시작일, 진행 계획은 실제 계획 범위로 결정한다. 최근 일지가 처방 날짜를 바꾸지 않는다.
- 로딩·실패를 빈 기록으로 표시하지 않는다. 확인된 빈 상태는 가상의 예시 하나와 기록 시작 경로를 준다.
- 예시는 고정 표기하며 실제 기록·통계·포인트에 쓰지 않는다. 메모·통증·체중을 달력에 자동 노출하지 않는다.
- 달력의 움직임은 OS 또는 앱의 줄이기 설정을 따른다. 모션 때문에 후속 탭이나 뒤로가기를 막지 않는다.

### 8.1 승인된 앱 제목·강조 역할 (2026-10-07)

- 화면 제목은 `AppHeading`의 `screen`(24px·700), 홈 대표 제목은
  `hero`(26–32px·700), 보조 섹션은 `section`(18px·700)을 사용한다.
  HTML 제목 단계는 문서 구조대로 유지하며 시각 크기와 별도로 결정한다.
  기존 `--fs-app-section-title`(22px)은 달력 연·월과 기존 묶음 제목의
  호환 역할이다. 새 일반 섹션 제목과 구분하며, 실제 일지 종이의 높이와
  저장 좌표를 바꾸기 위해 이 기존 토큰을 일괄 치환하지 않는다.
- 한 주요 제목에만 짧은 28px 틸 선을 허용한다. 제목 본문은 잉크색을
  유지하고 반복되는 분류 라벨·탐색 순서 번호는 중립색으로 둔다.
  이 선은 넓은 강조 면을 추가하는 규칙이 아니다.
- 대표 행동은 기존 브랜드 채움 하나로 구분한다. 보조 행동·재료·이동은
  무채움으로 유지하며 저장 실패·통증 등 의미색과 안내 우선순위를 바꾸지 않는다.
- 실제 핵심 숫자는 28px·700과 tabular-nums, 단위는 13px로 구분한다.
  숫자 강조를 위해 미기록을 0으로 바꾸거나 근거·기간·제외 건수를 제거하지 않는다.
- 상단 이동 영역의 작은 제목은 별도의 `app-chrome-title` 역할이다.
  하단 목적지는 `aria-current`, 굵은 라벨과 짧은 선택 표시로 구분하며
  `기록` 행동에는 현재 목적지 표시를 붙이지 않는다. 터치 영역은 44px 이상이다.
- 매니저·상황 그림은 앞서 승인된 64/80px 보조 자산으로 유지한다.
  새 제목 역할은 실제 일지의 종이 프레임·저장 좌표·크기·배열을 수정하지 않는다.
  긴 제목은 줄바꿈하며 본문이나 버튼을 줄여 억지로 맞추지 않는다.
