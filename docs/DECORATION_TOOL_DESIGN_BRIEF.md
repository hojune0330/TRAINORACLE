## 0. 진단 — 왜 "대충 만든 것 같아" 보이는가

현재 상태를 정직하게 적는다. 고칠 대상을 정확히 알아야 한다.

| # | 문제 | 증거 |
|---|------|------|
| D1 | **카탈로그가 앙상하다**: 이모지 48종을 빼면 일러스트 아이템이 **8종**뿐. 테마 2, 스티커 2, 도장 1, 테이프 1, 아바타 1, 잉크 견본 1 | `decoration-catalog.ts` L148-155 |
| D2 | **자산이 낡았다**: 2026-08-04에 생성한 webp 8장. 시리즈 톤 통일 없이 개별 생성됨, 해상도·스타일 편차 존재 | `public/decorations/*.webp` (7~20KB) |
| D3 | **서랍이 '설정 화면'처럼 생겼다**: 세로 1열 리스트 + 아이템마다 "미리보기/사용/제거" 텍스트 버튼 나열. 상용 앱의 꾸미기는 **시각 우선 그리드**인데 우리는 **텍스트 우선 폼**이다 | `JournalDecorationToolbar.tsx` L183-217 |
| D4 | **물성 어휘가 시각화되지 않았다**: 시각 기준 문서(§6)가 종이·연필·만년필·테이프·형광펜 어휘를 정의했지만, 실제 카탈로그에 형광펜·연필 계열이 아예 없다 | `UX_UI_VISUAL_STANDARD.md` §6 vs 카탈로그 |
| D5 | **러너 정체성이 얕다**: "달리기 앱의 다이어리"인데 훈련 어휘(인터벌, LSD, 페이스, PB, 부상 회복)가 도장·스티커로 표현되지 않는다 | 카탈로그 전수 |

이모지 스티커(48종, 6그룹 체계, 전용 레일, 3단 크기)는 **이미 합격**이다.
이 문서의 범위에서 제외하고, 그 완성도를 나머지가 따라잡게 한다.

## 1. 디자인 정체성 — 한 문장과 세 가지 금지

### 1.1 한 문장

**"호보니치 테초 위에 MUJI 문구로 꾸민 러너의 훈련 일지."**

- 앱 크롬은 Scientific Minimalism(직각·hairline·절제)이고, 꾸미기는
  그 위에 얹힌 **종이 세계**다. 꾸미기 아이템은 전부 "실제 문구점에서
  살 수 있는 물건"으로 설명 가능해야 한다: 마스킹 테이프, 고무 도장,
  스티커 낱장, 만년필 잉크, 색연필, 형광펜.
- 디지털에서만 가능한 효과(네온, 글로우, 파티클, 그라데이션 배경,
  3D)는 이 세계에 존재하지 않는다.

### 1.2 레퍼런스 — 무엇을 어떻게 참고하는가

| 레퍼런스 | 가져올 것 | 가져오면 안 되는 것 |
|---|---|---|
| **호보니치 테초 + 유저 꾸미기 문화** | 종이 위 콜라주 감성, 테이프로 구역 나누기, 도장 찍기, "하루 한 페이지" 애착 | 빽빽한 맥시멀리즘 (우리는 여백 유지) |
| **MUJI 문구** | 절제된 색, 크라프트지 톤, 기능적 형태, 로고 없는 담백함 | — |
| **Instagram 스토리 편집기** | 시트 인터랙션 역학: 시각 우선 그리드, 탭 즉시 적용, 캔버스 직접 조작 우선 | 네온·그라데이션·AR 톤 |
| **GoodNotes 스티커 시트** | 스티커를 '시트(낱장 묶음)'로 파는 구조 → 우리의 시리즈 단위 생성·판매와 동형 | — |
| **Day One / Journey** | 일지 앱이 감정·날씨를 아이콘화하는 절제된 방식 | — |
| **Nike Run Club 공유 스탬프** | 러너 어휘의 그래픽화(PB, 완주, 페이스), 훈련 데이터의 자부심 표현 | 스포티한 형광·다이내믹 앵글 (우리는 종이 위 정적 물성) |

### 1.3 세 가지 금지 (반려 사유 최상위)

1. **원색·네온·그라데이션 금지.** 팔레트는 §2의 토큰에서만 추출한다.
2. **사실적 렌더링·그림자·입체 금지.** 선화 + 제한된 면 채움만.
3. **이모지풍 금지.** 일러스트 아이템이 이모지처럼 생기면 이모지
   스티커와 역할이 겹쳐 카탈로그가 무너진다. 일러스트는 항상
   "문구점 인쇄물" 질감이어야 한다.

> **적용 범위.** 위 세 금지는 **기본 재료**(TrainOracle 자체 제작, `decoration-catalog.ts`의
> `baseMaterial` 행)에 적용된다. `decoration-collections.ts`의 **컬렉션**(귀여운 스티커·시즌·
> 굿즈·라이선스 캐릭터)은 각자 `artDirection`을 갖는 의도된 예외이며, 컬렉션 화면 안에서만
> 노출되어 기본 카탈로그와 섞이지 않는다. 컬렉션 자산의 출처·라이선스는 레지스트리에서
> `public/legal/open-source.html`과 `public/collections/<id>/assets.json`으로 자동 생성된다
> (`node app/scripts/generate-collection-docs.mjs`).

## 2. 색·재질 어휘 (자산 생성 시 그대로 쓸 값)

모든 생성 프롬프트에 이 hex를 명시한다. 새 색 발명 금지.

### 2.1 종이·물성 토큰 (from `--paper` 계열)

```yaml
paper_cream:   "#F7F3E8"   # 일지 종이 바탕 — 자산의 배경은 투명이되, 톤 검수는 이 위에서
paper_deep:    "#EFEADC"   # 진한 종이 (테마 배경 후보)
paper_edge:    "#C9C0A6"   # 종이 가장자리·낡은 테두리
grid_dot:      "#DCD4BC"   # 모눈 점
pencil:        "#2B3330"   # 연필 선 — 일러스트 기본 윤곽선 색
ink_blue:      "#1A3A6F"   # 만년필 청색 — 도장·강조 선
tape_sand:     "#E8DCB0"   # 마스킹 테이프 모래색
tape_sage:     "#DDE3D2"   # 마스킹 테이프 세이지
highlighter:   "#FFD740"   # 형광펜 (불투명도 0.32 상한)
brand_teal:    "#0D5F5A"   # 브랜드 틸 — 아이템당 최대 1개 요소에만
accent_red:    "#B3372E"   # 다홍 (기존 TEXT_INK_RED와 통일)
accent_green:  "#2E6B4F"   # 초록 (TEXT_INK_GREEN)
accent_violet: "#5B4A8A"   # 보라 (TEXT_INK_VIOLET)
accent_orange: "#B4632A"   # 주황 (TEXT_INK_ORANGE)
```

### 2.2 일러스트 스타일 규정 (전 시리즈 공통)

```yaml
style_dna:
  윤곽선: "pencil(#2B3330) 계열의 손그림 선, 균일하지 않은 1.5~2px 굵기, 시작·끝이 살짝 열린 스케치 선"
  채움: "단색 플랫 채움 최대 2색 + 종이 여백 활용. 그라데이션·텍스처 남발 금지"
  형태: "시각적 정사각 바운딩, 실루엣이 24px에서도 읽히는 단순한 덩어리"
  질감: "리소그래프/실크스크린 인쇄물처럼 살짝 어긋난 채움(offset fill) 허용 — 유일하게 허용되는 '불완전함'"
  배경: "완전 투명"
  텍스트: "생성 이미지 안에 글자 금지 (도장의 원형 테두리 안 기호는 허용, 문자는 금지)"
  포맷: "SVG 우선. 불가하면 PNG @3x (배치 최대 크기 96px 기준 288px) 후 webp 변환"
```

**톤 검수법**: 같은 시리즈 전 항목을 `paper_cream` 배경 위에 한 줄로
나란히 놓고 스크린샷 → 선 굵기·채움 밀도·기울기 편차가 보이면 해당
항목만 재생성. 시리즈 통과 전까지 카탈로그 반영 금지.

## 3. 카탈로그 재설계 — 항목·구조·개수

### 3.1 구조 원칙

- **카테고리 6종 유지**: THEME / TAPE / STICKER / STAMP / INK / AVATAR.
  (EMOJI_STICKER는 기존 그대로.)
- **시리즈 단위 확장**: 카테고리 안에서 아이템은 반드시 "시리즈"로
  묶여 생성된다. 시리즈 = 한 번의 생성 세션 + 한 번의 톤 검수.
- **개수 목표**: 이모지 제외 현행 8항목(그림 자산 7종 + 잉크
  스와치 1종) → **35항목**(그림 자산 34종 + 잉크 스와치 1종).
  아래 개별 항목 표를 실행 권위로 삼는다. 신규 그림 자산은 27종이며,
  포인트 경제는 무료(starterOwned) 16종 + 유료 19종이다.
- **유료 가격 밴드**: 4P(가벼운 낱장) / 8P(스티커·도장) /
  12P(테마·테이프 세트급) / 20P(아바타). 기존 3종 가격 유지.

### 3.2 카테고리별 상세 명세

#### A. 페이지 테마 (THEME) — 2종 → 6종

종이 자체를 바꾼다. 테마는 "다른 노트로 갈아끼우기"다.

| id | 이름 | 무료/유료 | 디자인 지시 |
|---|---|---|---|
| THEME_TRACK_NOTEBOOK | 트랙 노트 | 무료(기존) | 유지. 기본 줄노트 |
| THEME_SKY_JOURNAL | 하늘 일지 | 12P(기존) | 유지하되 신규 톤 검수 대상 |
| THEME_GRID_FIELD | 모눈 연습장 | 무료 신규 | `grid_dot` 4px 모눈이 살짝 진해진 연습장. 헤더에 pencil 손그림 밑줄 1개 |
| THEME_DAWN_RUN | 새벽 러닝 | 12P 신규 | `paper_deep` 바탕에 상단 1/5만 `ink_blue` 5% wash — 동트기 전 하늘. 과하면 반려: "종이에 푸른 기운이 돈다" 수준 |
| THEME_FOREST_TRAIL | 숲길 트레일 | 12P 신규 | 하단 가장자리에 `accent_green` 손그림 풀잎 라인 하나. 본문 영역은 순수 종이 |
| THEME_RACE_DAY | 레이스 데이 | 12P 신규 | 상단에 `accent_red` 가는 사선 해칭 배너 띠(높이 12px). 결전의 날 느낌을 절제로 |

**테마 공통 계약**: 어떤 테마에서도 본문 대비 4.5:1 유지. 테마는
배경·가장자리·헤더 장식만 바꾸고 본문 타이포는 건드리지 않는다.

#### B. 마스킹 테이프 (TAPE) — 1종 → 6종

페이지 상단(HEADER_TAPE 슬롯)을 가로지르는 종이 테이프. 실물 mt
테이프처럼 **반투명(옵acity 0.85)** + 양끝 찢긴 단면.

| id | 이름 | 무료/유료 | 패턴 지시 |
|---|---|---|---|
| TAPE_CHECKER | 체크 테이프 | 무료(기존) | 재생성: `tape_sand` 바탕 + `paper_edge` 체크 |
| TAPE_SAGE_SOLID | 세이지 무지 | 무료 신규 | `tape_sage` 단색. 가장 담백한 기본값 |
| TAPE_DIAGONAL | 사선 줄무늬 | 무료 신규 | `tape_sand` 바탕 + `ink_blue` 45° 가는 사선 (도로 공사 테이프의 문구점 버전) |
| TAPE_DOT_GRID | 점 테이프 | 4P 신규 | `paper_deep` 바탕 + `pencil` 2px 도트 |
| TAPE_TRACK_LANE | 트랙 레인 | 8P 신규 | `accent_orange` 바탕 + 흰 레인 라인 2줄 — 육상 트랙 단면. 러너 정체성 테이프 |
| TAPE_MOUNTAIN | 능선 테이프 | 8P 신규 | `tape_sage` 바탕 + `accent_green` 능선 실루엣 반복 |

**테이프 공통 지시**: 폭 비율 10:1 가로띠, 좌우 끝은 지그재그 찢김,
살짝(-1.2° ~ +0.8°) 기울여 렌더. 기울기는 CSS가 아니라 배치
transform 기본값으로 준다(기존 tape 클래스 선례 참고).

#### C. 스티커 (STICKER, 일러스트 낱장) — 2종 → 10종

본문 여백(TOP_CORNER, BODY_MARGIN)에 붙이는 낱장. **러너의 하루**를
시리즈 축으로 잡는다. §2.2 스타일 DNA 전면 적용.

| id | 이름 | 무료/유료 | 형태 지시 (24px에서도 읽혀야 함) |
|---|---|---|---|
| STICKER_WEATHER_SUN | 맑은 날 | 무료(기존) | 재생성: pencil 윤곽 태양 + `highlighter` 32% 채움 |
| STICKER_FINISH_LINE | 결승선 | 8P(기존) | 재생성: 체커 깃발 2개 교차, `pencil`+`accent_red` 2색 |
| STICKER_RUNNING_SHOE | 러닝화 한 켤레 | 무료 신규 | 옆모습 운동화 1개, pencil 윤곽 + `brand_teal` 스우시 아닌 단순 라인 1개 (상표 연상 금지) |
| STICKER_WATER_BOTTLE | 물병 | 무료 신규 | 스포츠 물병, `ink_blue` 30% 물 채움 표시 |
| STICKER_STOPWATCH_DOODLE | 스톱워치 낙서 | 무료 신규 | pencil 선화 스톱워치 + 주변 속도선 3획 |
| STICKER_HEART_RATE | 심박 곡선 | 4P 신규 | `accent_red` 심전도 한 획 + 끝에 작은 하트 |
| STICKER_TRAIL_TREE | 가로수 | 4P 신규 | 손그림 나무 1그루, `accent_green` 잎 덩어리 채움 |
| STICKER_MEDAL_RIBBON | 완주 메달 | 8P 신규 | 리본 달린 메달, `highlighter` 32% 원판 + pencil 리본 |
| STICKER_NIGHT_MOON | 야간 러닝 달 | 4P 신규 | 초승달 + 별 2개, `ink_blue` 단색 선화 |
| STICKER_BANDAGE_CARE | 회복 반창고 | 무료 신규 | 교차 반창고, `tape_sand` 채움 + pencil 윤곽 — 부상 회복일 표시 |

#### D. 도장 (STAMP) — 1종 → 8종

### 3.3 시리즈 생성 프롬프트 템플릿 (하위 에이전트가 그대로 사용)

시리즈마다 **한 번의 호출**로 전 항목을 나란히 생성한다. 예 — 도장 시리즈:

```text
A single cohesive sheet of 8 rubber stamp designs for a runner's paper
training diary, arranged in a 4x2 grid on a transparent background.
Style: hand-carved rubber stamp prints with slightly imperfect ink
coverage (5-10% ink gaps), uniform 2px organic linework, flat single-
color ink per stamp. No text, no letters, no numbers anywhere.
Colors strictly limited to: deep fountain-pen blue #1A3A6F, muted
vermilion red #B3372E, forest green #2E6B4F.
Stamps: (1) circle border + sleeping crescent moon in blue,
(2) circle + one bold check stroke in green, (3) double circle +
two laurel branches in red, (4) circle + rising half sun in blue,
(5) circle + three raindrops above footprints in blue, (6) wide oval
+ one long winding road stroke in green, (7) square border + one
sawtooth wave stroke in red, (8) circle + small sprout in green.
Aesthetic: Japanese stationery (hobonichi/MUJI), letterpress zine,
NOT emoji-like, NOT glossy, NOT 3D, no shadows, no gradients.
Each stamp fits a square bounding box of equal size.
```

생성 후: 개별 크롭 → 투명 배경 확인 → `paper_cream` 위 톤 검수 →
`decorations/` 에 `stamp-<slug>.webp`(@3x)로 저장. 다른 시리즈
(스티커·테이프·아바타·테마)도 동일 템플릿 구조로: 스타일 문단은
§2.2를 복사하고 항목 목록만 교체한다.

## 5. 서랍(드로어) UI 전면 재설계

### 5.1 문제의 핵심

현행 서랍은 "아이템 관리 목록"이다. 상용 앱의 꾸미기는 "재료 서랍을
열어 손으로 집는" 경험이다. 목록 → **시각 우선 그리드**로 전환한다.

### 5.2 새 구조 (위→아래)

```text
┌─ 서랍 (bottom sheet / 데스크톱 우측 패널 — 현행 위치 유지) ─┐
│ [grabber 4×36px]                                            │
│ 꾸미기 도구        베타 포인트 · 사용 가능 12P      [∨숨기기] │
│ ┌─ 카테고리 칩 행 (가로 스크롤, aria-pressed) ─┐            │
│ │ 전체 · 스티커 · 테이프 · 도장 · 테마 · 아바타 │            │
│ └───────────────────────────────────────────┘            │
│ ┌─ 아이템 그리드: 모바일 3열 / 데스크톱 4열 ─┐              │
│ │ ┌────────┐ ┌────────┐ ┌────────┐          │              │
│ │ │ 시각칸  │ │ 시각칸  │ │ 시각칸 🔒│  …      │              │
│ │ │ 이름    │ │ 이름    │ │ 8P     │          │              │
│ │ └────────┘ └────────┘ └────────┘          │              │
│ └───────────────────────────────────────────┘              │
└─────────────────────────────────────────────────────────────┘
```

### 5.3 아이템 타일 명세

- **크기**: 최소 88×96px (시각칸 56px + 이름 줄). 타일 전체가 터치
  타깃(44px 규정 초과 충족).
- **시각칸**: 자산 이미지를 `paper_cream` 배경 미니 카드 위에 렌더 —
  "종이 위에 놓였을 때"를 서랍에서 미리 보여준다. 테마는 종이 모서리
  접힌 미니 페이지 썸네일, 잉크는 색 스와치 원형(§3.2-E), 테이프는
  기울어진 가로띠 그대로.
- **이름**: `--fs-caption` 1줄, `keep-all` 말줄임.
- **상태 오버레이**:
  - 보유+배치형: 탭 = 즉시 페이지에 붙임(현행 '사용'과 동일 동작).
    타일 우상단에 현재 페이지 배치 수 뱃지(1 이상일 때만, `--ink` 원형).
  - 보유+전환형(테마·잉크·아바타): 탭 = 즉시 적용. 적용 중 항목은
    `--ink` 2px 테두리 + 좌상단 체크.
  - **미보유(유료)**: 시각칸 우하단에 자물쇠 12px + 타일 하단에
    `{cost}P` 라벨. 탭 = **타일 그 자리에서 확장되는 확인 행**
    ("12P로 받기 / 취소") — 별도 다이얼로그 금지, 실수 구매 방지와
    흐름 유지를 동시에.
- **미리보기**: 탭 앤 홀드(400ms) = 페이지에 임시 프리뷰(현행
  previewJournalDecoration 재사용), 손 떼면 해제. 데스크톱은 hover
  600ms. 접근성 대체: 타일에 컨텍스트 메뉴 버튼 불필요 — 대신
  '적용 후 즉시 undo 가능'이 이미 보장되므로 홀드 미리보기는
  부가 기능으로 취급한다(없어도 기능 손실 없음, §7 모션 원칙).
- **제거**: 서랍에서 제거 버튼을 없앤다. 제거는 캔버스에서 항목
  선택 → 선택 액션 바(기존)에서. 서랍은 "넣는 곳", 캔버스는
  "다루는 곳" — 역할을 가른다. 단 전환형(테마·잉크)은 기본값으로
  되돌리기가 필요하므로 '기본으로' 타일을 각 카테고리 맨 앞에 둔다.

### 5.4 정렬·그룹 규칙

- 칩 '전체'일 때: 카테고리 섹션 헤더(`--fs-mono-xs` 대문자 스타일
  기존 t-mono-xs)로 구분된 연속 그리드. 순서: 스티커 → 도장 →
  테이프 → 테마 → 아바타 (사용 빈도 가설 순).
- 각 섹션 안: 무료 먼저, 유료는 뒤에 몰지 말고 **시리즈 원래 순서**
  대로 섞어 배치 — 유료가 자연스럽게 눈에 밟히게 하되 광고처럼
  몰아두지 않는다.
- 검색·즐겨찾기는 이번 범위에서 만들지 않는다 (34종에는 과설계).

### 5.5 빈 상태·엣지

- 기록 없는 날: 현행 문구 유지("기록이 없는 날에는 테마만…").
  배치형 타일은 dim 처리(opacity 0.45) + 탭 시 notice로 사유 안내.
- 페이지 24개 상한 도달: 배치형 타일 전체 dim + 상단 notice 1줄.
  타일별 에러 반복 금지.
- 포인트 부족 유료 타일: 확장 확인 행에 "N P 더 필요해요" 인라인
  표기(현행 persistent notice 문구 재사용).

## 6. UX 흐름 계약 (기존 자산 보존)

이미 검증된 것을 부수지 마라. 아래는 **변경 금지** 목록이다.

1. 편집기 진입: 홈 카드 → 오늘 상세 자동 오픈 (PR #306) 유지.
2. undo/redo 20단계, 구매는 undo 스택 미오염 유지.
3. 낙관적 동시성(STALE_STATE reload) 유지.
4. 포커스 트랩, aria-modal, 이모지 전용 레일, 페이지당 24개 상한,
   이모지 3슬롯, constrainToPage 기하 유지.
5. `prefers-reduced-motion` 전면 대응 유지. 새 모션(타일 확장 확인
   행, 홀드 프리뷰)도 reduce에서 즉시 상태 전환으로 대체.
6. 접근성: 모든 타일 `aria-label` = "{이름} {상태문}" (예: "결승선
   스티커 붙이기", "하늘 일지 테마 12P로 받기"). 스크린리더 흐름이
   현행 계약 테스트를 계속 통과해야 한다.

## 8. 자체 채점표 (하위 에이전트는 제출 전에 채운다)

```yaml
decoration_redesign_checklist:
  - 한 문장 정체성("호보니치×MUJI 러너 다이어리")으로 전 항목 설명 가능한가
  - 새 hex 발명 0건 — §2.1 팔레트만 사용했는가
  - 시리즈 단위 생성 + paper_cream 위 톤 검수 스크린샷이 있는가
  - 이모지풍·네온·그림자·3D·이미지 내 문자 0건인가
  - 24px 축소에서 모든 스티커·도장 실루엣이 읽히는가
  - 서랍이 목록이 아니라 시각 우선 그리드인가 (타일 88×96 이상)
  - 유료 구매가 인라인 확인 행인가 (별도 다이얼로그 0건)
  - 서랍에서 제거 버튼이 사라지고 캔버스 선택 흐름으로 이관됐는가
  - 변경 금지 목록(§6) 위반 0건 — 기존 계약·e2e 통과하는가
  - reduced-motion·포커스 트랩·aria-label 전 타일 적용됐는가
  - 375px 가로 스크롤 0, 터치 44px, 대비 4.5:1 유지되는가
  - PR 분할(§7)을 지켰는가
```

하나라도 "애매"면 머지 전에 다듬는다. 이 문서와
`UX_UI_VISUAL_STANDARD.md`가 충돌하면 시각 기준 문서가 우선하고,
충돌 발견 시 이 문서 개정 PR을 함께 낸다.
