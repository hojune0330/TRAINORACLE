# 기기 우선 처리와 단순 운영

2026-10-16 구현 기준: `3f08bf1fe900e688df2b8e0b60fe56b51856e273` 위의 작업 패치.
사용자 승인: 휴대폰 처리와 무료 자원을 우선하고 꼭 필요한 부분만 유료화하는 구조 구현.
기존 계정 중심 보관 계약·공개 관문·처방 숫자는 변경하지 않는다.

## 책임을 나누는 기준

| 기기 | 정적 호스팅 | 기존 계정 서버 |
|---|---|---|
| 화면, 훈련 계산, 관측 파일 해석, 초안·미전송 사본 | 앱 코드·공개 이미지·용어/도움말 | 인증, 소유권, revision 충돌, 중복 보상 방지, 승인된 계정 보관·복구 |

기기 계산은 계정 원본을 없앤다는 뜻이 아니다. 로그인 사용자의 원본은 승인된
계정 경로에 두고, 서버 확인 전에는 계정 저장 완료라고 표시하지 않는다.
브라우저 종료 후 자동 전송, 삭제/분실한 휴대폰의 무조건 복구를 약속하지 않는다.
외부 LLM·새 DB·범용 동기화 서비스·별도 큐·상시 서버를 추가하지 않았다.

## 이번 구현과 재사용

- 읽은 문자열이 65,536 UTF-16 코드 단위 이상인 비 XML 파일(CSV/JSON)은
  필요할 때만 전용 Web Worker를 만든다. 이 기준은 파일 바이트 크기 제한과 별개다.
  기존 파서를 그대로 실행하므로 날짜·숫자·출처·분석 활성 조건은 동일하다.
  완료·취소·실패·30초 상한에서 worker를 종료한다. 원파일은 서버에 보내지 않는다.
- 작은 파일과 TCX/GPX는 기존 기기 파서를 유지한다. XML은 DOMParser가 필요하다.
  worker 미지원/생성 불가 시 기존 파서를 사용하지만 실행 중 실패·청크 로딩 오류는
  무거운 일을 다시 시작하지 않고 명시적으로 실패한다. 취소 후 늦은 응답도 버린다.
- 확인된 기기 일지 쓰기와 암호화 초안 IndexedDB readwrite 완료 뒤에
  `navigator.storage.persisted()/persist()`를 요청한다. 페이지 수명 동안 최대 한 번,
  거절·미지원은 비차단이다. 기록·키·서버 revision을 변경하거나 자동 삭제하지 않는다.
  이는 브라우저의 자동 정리 위험을 줄이는 보조 수단일 뿐 백업/용량/영구 보장을 뜻하지 않는다.
- 계정 서비스에 이미 있는 중복 조회 합치기, 800ms 전송, durable outbox,
  immutable operation, CAS, 현재 계획 우선 조회를 재사용한다. 비용을 줄인다며
  백업 전 최신 조회·소유자 검증·충돌 검사·구매 검사를 캐시로 대체하지 않는다.
- 기존 lazy 화면, 공개 이미지 지연 로딩과 SW 해시 자산 캐시를 유지한다.
  꾸미기 컬렉션 전체 사전 캐시, 미전송 기록 자동 정리, 대형 로컬 모델은 추가하지 않는다.

## 한 번에 버전 확인

저장소 루트에서 Node 24.19.0으로 실행한다.

```powershell
node .tools/check-release-channels.mjs
```

조회는 공개 main SHA, 구주소/새 도메인의 영수증, 모바일 release-config만 사용한다.
같은 SHA는 `SAME_SOURCE`, 다른 SHA는 `DIFFERENT_SOURCE`, 실패/잘못된 형식은
`UNKNOWN`이다. 다르면 종료 코드 1이다. 다른 SHA를 무조건 오래된 버전이라고
판정하지 않으며 실제 bytes·로그인·앱스토어 공개 증거를 대신하지 않는다.
청구/실사용자/개인 기록은 읽지 않는다. 이 도구 때문에 사용자 앱마다 버전 조회를
하거나 새 모니터링 서비스를 운영하지 않는다. 배포 담당자가 릴리스 때 실행한다.

## Cloudflare Pages 준비 — 아직 게시하지 않음

기존 `TRAINORACLE-DOMAIN/scripts/prepare-domain.mjs`로 만든 검증된 산출물을 사용한다.
원본을 재빌드하거나 별도의 환경 변수를 몰래 섞지 않고 검증 후 새로운 폴더로 복사한다.

```powershell
node .tools/prepare-cloudflare-pages.mjs DOMAIN_DIST NEW_OUTPUT FULL_SOURCE_SHA
```

- 부모 폴더는 존재해야 하며 NEW_OUTPUT은 아직 없는 폴더여야 한다. 입력과 겹치면 거절한다.
- exact source SHA, DOMAIN 영수증, 전체 파일 목록/해시, 필수 도움말·이전 안내를 검사한다.
- 계정 OFF·연결 백엔드 OFF를 유지한다. 인증키 유사 내용, symlink, 시크릿/소스맵,
  추가 파일·변조, Functions/`_worker.js`/라우팅 덮어쓰기는 거절한다.
- 무료 정적 배포 예산인 파일 20,000개·파일당 25MiB를 검사한다. 공급자 정책은
  실제 이전 시 다시 확인한다. 파일 수를 줄인다며 자산·기존 기록을 삭제하지 않는다.
- HTML/SW/매니페스트/영수증은 재검증하고, `/assets/`가 모두 해시 파일일 때만
  해당 경로에 1년 immutable 캐시 헤더를 추가한다. 버전 없는 그림을 영구 캐시하지 않는다.
- 생성 영수증은 `NOT_PUBLISHED`이다. 입력의 회귀검사 상태를 승격하지 않는다.
  기존 source CI와 운영 공개 전 파일 검증은 별개로 유지한다.
- 실패한 출력은 지우거나 다시 덮지 않는다. 완성 영수증이 없는 폴더는 게시하지 않는다.
  오류를 해결한 후 다른 새 폴더에서 준비한다.

### 실제 이전 순서와 별도 작업

1. source 최신 변경을 검수·필수 CI 후 고정하고 DOMAIN과 MOBILE에 같은 SHA를 지정한다.
   모바일 설정 갱신은 바이너리 재빌드·서명·스토어 배포를 대체하지 않는다.
2. 위 도구로 정적 산출물을 준비한다. Cloudflare 프로젝트/배포 권한으로 preview를
   게시하고 실제 HTML·JS·CSS·worker·이미지·헤더와 오프라인/백업 경로를 확인한다.
3. `trainoracle.io`를 유지한 호스트 이전에만 DNS를 전환한다. Porkbun/Zoho의
   MX·SPF·DKIM·DMARC 등 메일 레코드를 먼저 보존한다. 네임서버 변경은 별도 운영 작업이다.
4. HTTPS·apex/www·캐시 업데이트를 확인한다. 구 GitHub.io 주소는 보존하고 자동
   리디렉션하지 않는다. 다른 origin의 localStorage/IndexedDB는 저절로 이전되지 않는다.
5. 문제 시 새 UI/쓰기를 보류한다. 기록·새 문서·구매 내역을 삭제하거나 구형 writer로
   되돌리지 않는다. account OFF 해제는 기존 ACCOUNT_PUBLIC_RELEASE_GATE를 통과해야 한다.

Cloudflare 계정 접근, DNS 전환, 운영 키/DB, 실제 계정 왕복, 스토어 서명/제출과
유료 전환은 이번 로컬 구현·검수의 완료 증거에 포함되지 않는다.

## 지출과 복구

- 공개 정적 파일은 정적 호스팅에 둔다. 개인 업로드/대형 모델은 자동 도입하지 않는다.
- 유료 전환은 사용자 수 하나가 아니라 DB 용량·실제 전송량·함수 사용·복구 요구를
  보고 결정한다. 서버 복구/백업 필요가 먼저 유료화 사유일 수 있다.
- 사용량은 공급자 대시보드에서 확인한다. 비용 한도 기능은 모든 청구를 막는
  하드 한도로 가정하지 않는다. 임의로 카드 등록·자동 증설·새 유료 서비스를 만들지 않는다.
- 서버 데이터·암호화 키·파일 저장소의 백업은 별도로 복원 시험을 한다. 앱의
  개인 백업과 30일 수정본은 서버 재해 복구의 대체가 아니다.
- 원문·부상·파일명·GPS를 비용 계측용 외부 분석 도구에 보내지 않는다.

## 이번 패치의 확인 범위

- 앱과 E2E TypeScript 검사, 계정 OFF 로컬 프로덕션 빌드 통과.
- 파일 가져오기·기기 저장·계정 초안/동기화 관련 집중 검사 266개 통과.
  그중 파일 파서 검사 64개는 UTC와 한국 시간대에서 각각 확인했다.
- 정적 호스팅 준비·버전 확인·기존 CI 범위 판별 검사 14개 통과.
- 모바일 Chromium 파일 가져오기 7개, 실제 IndexedDB 초안 경계 검사 5개 통과.
  worker 사용, 취소 뒤 늦은 결과 배제, 명시적 확인 전 저장 안 함, 저장 보호 요청
  거절 시 초안 유지, 탭 간 쓰기·계정 분리를 합성 데이터로 확인했다.
- Cloudflare 준비 도구는 합성 산출물로 정상 입력과 변조·관문 위반을 확인했다.
  실제 DOMAIN 산출물 이전, Cloudflare 게시, DNS 변경은 수행하지 않았다.
- 전체 CI/릴리스 관문, 실기기 iPhone/WebView, 실제 로그인 계정 왕복,
  앱스토어 배포는 이번 검사의 범위가 아니다. 기존 큰 번들 경고도 남아 있다.
- 최종 공개 메타데이터 확인(2026-10-16 14:56 UTC): main `0164233d`,
  구주소 `3f08bf1f`, 새 도메인 `2b42210e`, 모바일 설정 `0b3c12f6`로 서로 다르다.
  작업 중 main에 추가된 세 커밋은 게임 구현과 그 CI 검사이며, 이번 실행 코드와
  겹치지 않는다. 공유 CI 파일은 다른 위치를 수정한다. 위 검수는 `3f08bf1f` 기반
