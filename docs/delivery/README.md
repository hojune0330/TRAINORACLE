# 개발·검사·보존형 배포 안내

2026-10-15 오너 승인 범위: 개발 병목 개선, 기존 공개 범위의 보존형 배포.
제품 최고 지침과 계정 공개 관문을 대체하지 않는다.

## 적용 방식

- 일반 작업 브랜치는 PR로 한 번 검사한다. 같은 브랜치의 push 검사와 PR 검사를
  중복 실행하지 않는다. main push와 수동 전체 검사는 유지한다.
- 같은 PR의 이전 검사는 최신 실행으로 대체한다. main 게시 중에는 취소하지 않는다.
- 운영 메모만 바뀌면 dependency 설치/앱 검사/배포를 생략하고 명확히 별도 분류한다.
  허용 목록 밖의 정책·스펙·소스·자산·설정·알 수 없는 변경은 전체 관문을 유지한다.
- UTC/KST, 브라우저 4종과 두 실행 경로, 전용 저장 시나리오는 유지한다.
  브라우저 generic은 app-quality가 만든 같은 실행의 산출물을 받아 재빌드를 줄인다.
- 각 검사에는 상한이 있다. 시간 초과는 실패이지 합격이 아니다. 로그를 보고 제품
  결함/fixture/환경/대기를 구분한 뒤 해당 단계만 고친다. 통과할 때까지 제한을 늘리지 않는다.
- 브라우저 CI는 최종 실패 3건이면 실패로 끝내고 합성 실패 화면/trace를 3일 보존한다.
  성공 실행의 전체 목록과 기존 재시도 횟수는 유지한다. 미완료 경로는 합격이 아니다.

## 게시 경로

명시적으로 수동 게시를 선택한 경우 main 병합 커밋에 `[manual-pages]`를 넣는다.
이 표식은 자동 게시만 생략하며 필수 검사에는 영향을 주지 않는다. 같은 main의
필수 관문 통과를 확인한 뒤 아래 보존형 게시 도구로 수동 게시한다.

로컬 built-preview 검사에서는 `app`에서
`node scripts/run-local-preview-tests.mjs <Playwright 선택 인수>`를 사용할 수 있다.
서버 준비, HTTP 응답, 실제 브라우저의 앱 탐색 렌더를 먼저 확인한 후 요청한
검사만 실행한다. 기본 브라우저 경로가 격리된 환경에서는 설치된 경로를
`PLAYWRIGHT_BROWSERS_PATH`로 명시한다. 이 경로는 기존 전체 CI 관문을 대체하지 않는다.

CI도 기존 검증된 .tools/build-oracle-pages-release.mjs와
.tools/publish-oracle-pages-release.mjs를 쓴다. 기존 공개 설정과 --account-held를
유지하고, previews/·이전 해시 자산을 보존한다. root 삭제·force push는 없다.
main/gh-pages 경합, 파일 변조, dirty target, 자산 충돌은 게시 전에 거절한다.
CI 영수증은 실행 ID/시도 번호를 포함하며 Pages의 실제 built도 별도로 확인한다.

문서만 추가된 main과 공개 SHA는 다를 수 있다. freshness는 배포 SHA의 조상 관계와
완전한 변경 목록에서 운영 메모만 확인되면 RUNTIME_UNCHANGED로 구분한다.
영수증 SHA를 꾸며 맞추지 않는다. 파일 목록이 잘리거나 확인 불가하면 예외를 주지 않는다.
미해결 과거 브랜치 경고는 이 변경으로 해소됐다고 처리하지 않는다.

## 후속 작업 규칙

승인된 범위는 재승인 없이 계속한다. 새 정책·계정 공개·DB 전환·개인 데이터 삭제·
권한 확대·추가 유료 자원은 이번 승인으로 확대하지 않는다. 다른 PR의 일지·저장
변경을 배포 도구 수정과 묶어 병합하지 않는다.

실제 source SHA, CI 결과, Pages SHA/built, 공개 파일 확인, 실계정 결과를 나눠 보고한다.
필수 검사가 기존 결함으로 실패하면 정확한 실패를 남기고 해당 결함을 고친다.
문서 정리만으로 배포 완료나 실계정 검증 완료를 선언하지 않는다.
