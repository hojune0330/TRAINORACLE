# 포인트 기준: 1P = 0.1원

결정: 오너 2026-10-09. "앱이나 웹에서 쓰는 포인트는 그냥 원 가치의 1/10로 하자. 모든 건 그 기준으로 가자."

확인한 해석(질문으로 확인): 1P는 0.1원이다(10P = 1원). 적립과 가격은 이 기준에 맞게 다시 설계한다. 게임 메달은 이 기준에서 빼고 원 가치가 없는 채로 둔다.

## 1. 무엇에 적용하나

| 대상 | 적용 | 이유 |
|---|---|---|
| TrainOracle P(일지·방문 적립, 꾸미기 구매) | **적용**. 모든 표기·가격·적립·내역은 1P = 0.1원으로 환산할 수 있게 설계한다 | 오너 결정 |
| 미니게임 메달 🏅 | **적용 안 함**. 원 가치가 없고 P로 바꿀 수 없다 | 게임 결과물에 현금성 가치를 붙이면 게임산업법 제28조 3호·제32조 1항 7호, AdMob 정책, 앱인토스 정책에 걸린다(REWARDS_ADS_PLAN) |
| 미니게임 점수·별·게임 에너지 | 적용 안 함 | 같은 이유 |
| 앞으로의 현금성 전환(토스포인트·기프티콘) | 전환할 때 1P = 0.1원으로 계산한다. **전환 기능 자체는 별도 승인 사항이다** | 선불업 해당 여부와 변호사 확인이 먼저다 |

## 2. 지금 숫자와 문제

| 항목 | 지금 | 원 환산(1P = 0.1원) |
|---|---|---|
| 일지 기록한 날 | 4P | 0.4원 |
| 방문한 날 | 1P | 0.1원 |
| 꾸미기 가격 | 4~20P(테마 12, 테이프 4·8, 스티커 4·8, 도장 4·8, 아바타 20) | 0.4~2원 |
| 컬렉션 개별 / 일괄 | 4P / 80P | 0.4원 / 8원 |

1원 미만 단위는 사람이 가치를 느끼기 어렵다. 토스 만보기는 단계마다 10~20원, 하루 최대 140원이다(2023 토스피드). 그래서 **적립과 가격을 모두 ×10** 하면 기존 사용자가 가진 가치는 그대로이고, 원 단위가 읽힌다.

## 3. 2차 숫자 (×10 재설계)

| 항목 | 2차 | 원 환산 | 비고 |
|---|---|---|---|
| 일지 기록한 날 | **40P** | 4원 | 하루 1회. 서버가 KST 오늘 날짜인 일지만 인정하는 기존 규칙을 유지 |
| 방문한 날 | **10P** | 1원 | 하루 1회 |
| 기록 연속 보너스 | 7일째 **+30P**, 30일째 **+100P** | 3원 / 10원 | 오너 결정 2026-10-09 "연속 보너스 소량만". 지금 배지·보상 규칙(7·30일)과 같은 날짜를 쓴다. 연속이 끊기면 다시 1일부터 센다 |
| 꾸미기 가격 | 40·80·120·200P | 4·8·12·20원 | 지금 가격 ×10 |
| 컬렉션 개별 / 일괄 | 40P / 800P | 4원 / 80원 | ×10 |
| 무료 보상·시즌·기본 재료 | 0P | 0원 | 그대로 |

정기 적립 상한: 하루 50P(5원). 한 달(30일) 1,500P(150원). 연속 보너스를 더해도 한 달 최대 1,720P(172원)다(7·14·21·28일째 +30P, 30일째 +100P). 이 금액은 운영 예산과 앞으로의 전환 한도를 정할 때 쓴다.

## 4. 기존 보유분 전환 규칙 (개발 담당)

- 사용자에게 보이는 원칙은 **"숫자가 10배가 되고 가치는 그대로"**다.
- 서버 `account_reward_summary`는 `points = journals*4+visits`로 계산한다. 2차에서는 `journals*40+visits*10`으로 바꾸고, `spentPoints`도 10배로 보정한다(구매 기록에 남은 가격 ×10).
- 로컬 `engagement.ts`의 `JOURNAL_DAY_POINTS = 4`, `DAILY_VISIT_POINTS = 1`과 꾸미기 카탈로그 가격, `decoration-schema`의 `spentPoints` 하한 검증도 같은 비율로 바꾼다.
- 전환은 한 번에 원자적으로 한다. 앱 버전이 섞여 있어도 잔액이 틀리지 않게 `pointScale: 10` 같은 버전 표시를 둔다. 구버전 앱은 새 문서를 읽으면 업데이트 안내를 보여준다(기존 `UPGRADE_REQUIRED` 흐름 재사용).
- 전환 후 처음 앱을 열면 안내 시트를 한 번 보여준다(문구: COPY_DECK `point.migration.*`).

## 5. 표기 규칙

| 규칙 | 예 | 금지 |
|---|---|---|
| P 숫자에는 천 단위 쉼표를 쓴다(4자리부터) | `1,250P` | `1250P` |
| 원 환산은 괄호 안 보조 표기로, **잔액과 가격 옆에만** 쓴다 | `1,250P (125원)` | 적립 알림마다 원을 붙이기 |
| 원 환산은 내림하고 "약"을 붙이지 않는다. 10P 미만이면 원을 쓰지 않는다 | `45P (4원)`, `5P` | `45P (4.5원)`, `약 4원` |
| "현금"이라는 단어는 기준 안내에서만 쓴다. 전환 기능이 열리기 전에는 "현금으로 바꿀 수 있어요"라고 말하지 않는다 | "1P는 0.1원 가치로 계산해요" | "현금처럼 쓰세요" |
| 메달은 원·P와 같은 줄에 두지 않는다 | `🏅 12` | `🏅 12 (1.2원)` |
| P 아이콘은 `p-coin` 에셋, 메달은 `medal` 에셋을 쓴다. 문자 "P"만 쓸 때는 숫자 바로 뒤에 붙인다 | `40P` | `40 P`, `P40` |

## 6. 바뀌는 기존 문구 (모두 COPY_DECK에 있음)

| 위치 | 지금 | 2차 |
|---|---|---|
| FAQ "포인트를 돈으로 바꿀 수 있나요?" | 베타 포인트는 꾸미기에만 쓰고 현금으로 바꿀 수 없어요 | `faq.points.cash` |
| 홈 꾸미기 카드 안내 | 현금으로 바꾸거나 다른 사람에게 보낼 수 없어요 | `home.decoration.note` |
| 오픈소스 고지 "가공과 서비스 제공" | 현금이나 재산상 가치가 없는 베타 포인트 | 생성기 문구 변경 필요(`legal.points`). 법률 확인 후 |
| 방문 알림 | 오늘 방문 +1P가 반영됐어요 | `rewards.visit.awarded` (+10P) |
| 꾸미기 부족 알림 | 포인트가 {n}P 더 필요해요… 1P… 4P | `decoration.insufficient` |

**주의:** "현금이나 재산상 가치가 없다"는 지금 고지는 1P = 0.1원 기준과 충돌한다. 2차 문구는 다음 두 가지를 구분해서 말한다.
- 기준: 1P를 0.1원 가치로 계산한다.
- 지금 할 수 있는 것: 앱 안 꾸미기에만 쓰고, 현금·다른 사람에게 보내기는 아직 안 된다.

전환 기능을 열 때 약관·개인정보처리방침·선불업 검토와 함께 문구를 다시 바꾼다(WORK_SPLIT O-2).

## 7. 오너 결정 (2026-10-09 확정)

1. 연속 보너스: **소량만**. 7일째 +30P(3원), 30일째 +100P(10원). 7일 보너스는 7일마다 반복하고, 30일 보너스는 30일째 한 번만 준다.
2. 고지 문구·유효기간·명칭: **추천안대로**. 고지 문구는 COPY `legal.points`, 유효기간은 적립일부터 5년, 명칭은 "포인트"("베타 포인트"는 쓰지 않음). 법률 확인 후 약관·고지에 반영한다(E-5).
