# 별빛 릴레이 숲 · 넓은 전장과 러닝 연결 인수인계

작성일: 2026-10-17 (KST). **로컬 검수 일부 완료 · CI·공개 배포 미완료.**
현재 작업 트리의 구현 계약과 완료 범위를 정리한다. 단위 검사 6파일·60건,
기존 지도 phone E2E 2건, 판타지 phone/desktop E2E 2건이 통과했고,
390×844 브라우저 화면과 랜드마크 접촉시트를 수동 확인했다. 초기 타입 검사는
통과했으나 최종 재검사는 진행 중이다. 실제 iPhone 핀치·친구전·전체 밸런스와
재미·공개 배포가 합격했다는 의미는 아니다. 실행 조건과 초기 실패·수정 이력은
[로컬 검수 기록](../../reports/operations/DELIVERY_FANTASY_MAP_2026-10-17.md)에 있다.

## 목표와 범위

휴대폰 한 화면에 전장을 모두 축소해 넣는 대신, 넓은 지도에서 전투 위치를
옮겨 보며 배치·강화를 판단한다. `별빛 샘 → 수정 다리 → 숲의 관문`이라는
동일 세계를 디펜스와 러닝에서 각 장르의 시점으로 표현한다.

디펜스는 경로·건설 지점·타워 상성·여섯 웨이브를 유지하고, 러닝은 기존
달리기·점프·대시·장애물 판정을 유지한다. 서로의 자원·강화·능력치를 주고받는
규칙은 이번 범위에 없다. 세계 이름과 지역·아트, 활동 사이 이동만 연결한다.
신규 멀티플레이 서버나 친구 대전도 이 맵 추가의 완료 범위로 세지 않는다.

## 지도 계약

| 항목 | 현재 소스의 정의 |
|---|---|
| 식별자 | `starlight`, 표시 이름 `별빛 릴레이 숲` |
| 도메인 영역 | 24 × 16 |
| 렌더 월드 | 2280 × 2080, 기존 단위 `x × 90`, `y × 120` 유지 |
| 건설 지점 | 14개, 저장된 지점 번호가 의미를 가지므로 출시 후 순서 변경 금지 |
| 지역 | 별빛 샘 / 수정 다리 / 숲의 관문 |
| 경로 | 세 구역을 통과하는 하나의 고정 경로, 총 길이 40.5 도메인 단위 |
| 전투 | 기존 6웨이브, 신규 적 종류·타워 종류를 이 작업에 함께 늘리지 않음 |
| 기존 지도 | `forest`, 숲길 관문 12 × 10 / 8지점 정의 유지 |

`fieldSize()`는 도메인 크기에 여백을 더해 월드 크기를 계산한다. 옛 전장을
확대된 그림으로 늘린 것이 아니므로 타워 사거리·적 크기와 지점 간 거리는
도메인 수치 기준으로 판단한다. 길·지점·입구·관문이 배경 장식보다 우선이다.

| 웨이브 | 침입 지역 | 경로 시작 거리 | 경로상의 시작 위치 |
|---|---|---|---|
| 1–2 | 별빛 샘 | 0 | `(0, 3.5)` |
| 3–4 | 수정 다리 | 14.5 | `(10, 8)` |
| 5–6 | 숲의 관문 | 29.5 | `(16, 9)` |

입구는 동시에 세 개 열리는 방식이 아니라 **두 웨이브마다 순서대로 바뀐다.**
준비 화면은 다음 웨이브의 입구를, 전투 중에는 현재 입구를 알려야 한다.
후반 입구가 더 안쪽에서 시작하기 때문에 첫 구역에 한 투자만으로 후반 전체를
덮는다고 가정하면 안 된다. 이동·강화·판매의 판단이 실제로 유효한지는 별도
밸런스 검증 대상이다.

## 시점과 조작

현재 구현은 정사영 2D 아트의 **이동·확대/축소**다. 카메라를 자유롭게 회전하는
3D 공간이나 모든 장면을 새로 렌더하는 기능으로 설명하지 않는다.

| 조작 | 의도한 동작 | 검수에서 확인할 경계 |
|---|---|---|
| 한 손가락/마우스 드래그 | 지도 이동 | 드래그 종료가 타워 선택 탭으로 처리되지 않음 |
| 두 손가락 핀치 | 두 손가락 중심 기준 확대/축소 | 손가락 한 개가 떨어진 뒤 화면이 튀거나 잘못 선택되지 않음 |
| ＋ / − | 버튼으로 확대/축소 | 지도의 최소 전체 보기 배율과 최대 1.65 제한 |
| 전체 지도 | 월드 전체가 들어오는 배율로 복귀 | 월드 경계를 넘어 빈 영역으로 이동하지 않음 |
| 선두 따라가기 | 살아 있는 적 중 가장 앞선 적을 추적 | 수동 이동·확대가 추적을 해제하고 사용자가 다시 켤 수 있음 |
| 미니맵 | 누른 월드 위치로 이동, 현재 시야 표시 | 그려진 길·적·시야 사각형이 실제 전장 좌표와 일치 |
| 지역/건설 지점 번호 | 해당 위치에 초점 이동·지점 선택 | 화면 밖 지점도 이동 후 선택 상태와 조작 패널이 일치 |

Phaser 렌더, DOM의 지점 번호, 미니맵이 같은 좌표 변환을 사용한다. 모션 감소
설정에서는 추적 보간을 줄이되 길·적·선택 위치의 정보는 유지해야 한다.
렌더러 로드 실패 시에는 간소한 전장과 건설 지점 번호 선택 경로를 제공한다.
그 경로가 새 지도 전체에서 실제로 사용 가능한지는 후속 검수 대상이다.

## 에셋의 역할과 연결

| 파일 | 역할 | 제작 경로 |
|---|---|---|
| `ground.webp` | 넓은 전장의 저대비 지형 바탕. 길·지점은 코드에서 덧그림 | imagegen 텍스트 신규 생성, 원본 크기 유지 WebP 변환 |
| `panorama.webp` | 러닝 측면 원경과 라운지의 세계 소개 | imagegen 텍스트 신규 생성, 원본 크기 유지 WebP 변환 |
| `gate.webp` | 관문 목표의 큰 실루엣 | 기존 유료 Tripo 관문 + Blender 룬·색·이끼 가공 |
| `crystal.webp` | 길을 가리지 않는 지역 표식 | 기존 유료 Tripo 기반 + Blender 수정 군락 제작 |
| `bridge.webp` | 지도 밖 장식과 같은 세계를 읽게 하는 다리 | 기존 유료 Tripo 바위 + Blender 석조 다리 제작 |

세 랜드마크는 512 × 512 투명 WebP, 지면 원점 `(0.5, 0.78)`이다. 다리의
통행면을 실제 길로 사용할 때는 `manifest.json`의 `pathAlignmentOrigin`
`(0.5, 0.615971)`을 적용해야 한다. 현재 디펜스의 다리는 장식 위치에 있으며,
그 그림 자체를 적이 걷는 통로·물리 판정으로 해석하지 않는다.

소품 제작 완료와 실제 배치의 가독성 검수는 별개다. 확대했을 때 윤곽과 시점이
조화되는지, 원경의 장식과 길이 겹치지 않는지, 위기 상황에서 적·탄환·기지보다
배경이 먼저 보이지 않는지를 실제 전투에서 확인한다.

- [제작·원점·Blender 재현 기록](../../character-art/fantasy-world-v1/README.md)
- [imagegen 원문 프롬프트·파일 해시](../../character-art/fantasy-world-v1/PROMPTS.md)
- [공개 크레딧](../../app/public/game/fantasy-world-v1/CREDITS.md)
- [랜드마크 원장](../../character-art/fantasy-world-v1/ledger.json)

**신규 Tripo 생성 0건·크레딧 0은 재사용 소품 세 개에만 해당한다.** 두 배경의
imagegen 사용량이나 비용을 0이라고 주장하지 않는다. 새 외부 에셋 구매·API
충전은 이 작업에 포함되지 않았다.

## 러닝 연결과 기존 진행 보존

라운지에 `판타지 · 별빛 릴레이 숲` 러닝 코스를 독립 입구로 둔다. 기존 도시
캠페인의 해금 순서를 바꾸거나 이전 도시 완주를 요구하지 않는다. 러닝의 세
구간은 `별빛 샘`, `수정 다리`, `숲의 관문`이며 기존 track/mud/spikes 규칙을
쓴다. 세계의 아트가 같아도 디펜스 타워 강화가 러너의 에너지·속도로 옮겨가지
않고, 러닝 성과가 디펜스 전투력·금화를 주지 않는다.

디펜스의 `이 숲을 달려보기`, 러닝과 라운지의 같은 세계 입구로 활동을 바꾼다.
이동 버튼이 다른 게임의 진행 중 저장을 조용히 대체하지 않도록 검수한다.

- 기존 `forest` 저장·기록은 `trainoracle.tower-defense.checkpoint.v1` /
  `trainoracle.tower-defense.records.v1` 키에 그대로 둔다.
- `starlight` 저장·기록은 각각 위 키에 `.starlight`를 붙여 분리한다.
- 기존 데이터에서 `mapId`가 없으면 `forest`로 읽는다. 새 지도 지점 번호를
  기존 저장 슬롯에 넣거나 기존 8지점의 의미를 재배열하지 않는다.
- 알 수 없거나 손상된 기존 저장을 새 판으로 덮어쓰지 않는다. 읽기·쓰기의
  현재 맵 일치, 준비 상태 저장, 저장 후 다시 읽기 확인을 유지한다.
- 러닝 중간 저장은 별도 게임 저장이며 현재 원문과 예상 원문이 같은 경우에만
  교체한다. 새 코스 입장이 기존 저장을 임의 삭제할 근거가 되지 않는다.
- 러닝의 기존 도시 성과는 도시 ID별로 보존하고 `starlight` 항목을 추가한다.

## 레퍼런스에서 가져온 범위

공식 자료의 지도와 요소 분리를 참고했다. 정적 스크린샷은 화면 이동·핀치·
프레임 속도·조작감의 증거가 아니다. 각 게임을 직접 플레이해 검증했다거나
원작 에셋을 재사용할 권한을 받았다는 뜻도 아니다.

| 공식 자료 | 이번 설계에 참고한 범위 | 주장하지 않는 것 |
|---|---|---|
| [Kingdom Rush 전략 가이드](https://play.kingdomrush.com/kingdom-rush-strategy-guide) | 길·건설 위치·방어 목표를 구분해 읽는 지도 구성 | 화면만 보고 카메라 이동 방식이나 실제 밸런스 확정 |
| [Infinitode 공식 프레스 키트](https://infinitode.prineside.com/?m=press_kit_en) | 경로·건설 요소·선택 정보가 구별되는 단순한 전장 표현 | 정적 이미지로 핀치·추적·입력 지연 검증 |
| [Element TD 공식 사이트](https://www.eletd.com/) | 지형 장식과 전투 영역의 구분, 굽은 길의 배치 참고 | 원작 모델·텍스처·UI를 복사하거나 공개 재배포 |
| [Phaser 카메라 문서](https://docs.phaser.io/phaser/concepts/cameras) | 카메라 bounds·scroll·zoom·follow 개념과 API 범위 | 문서를 사용했다는 이유만으로 우리 제스처·미니맵 구현 합격 |

기존 [게임 품질 기준](GAME_QUALITY_REFERENCE_DECISIONS.md)과
[타워 디펜스 비교 기록](TOWER_DEFENSE_REFERENCE_REBUILD.md)을 계속 적용한다.
상용 스크린샷은 배치 분석용이며 새 배경 생성 입력이나 런타임 그림으로
복제하지 않았다. Phaser의 코드 라이선스와 생성 아트의 권리를 분리한다.

## 로컬 검수와 남은 인수 조건

작업 담당의 실행 결과를 다음 범위로 반영했다. 문서 담당은 검사를 다시 실행하지
않았다. 상세 기록의 검사 시간은 테스트 소요 시간이며 게임의 실제 플레이 시간이나
휴대폰 프레임 성능이 아니다.

| 항목 | 현재 확인 범위 | 남은 범위 |
|---|---|---|
| 카메라 | E2E 드래그·전체 지도·지역 이동·추적 켜기/수동 해제, 390×844 수동 전체 지도·지역 화면 | 실제 iPhone의 두 손가락 핀치·손가락 해제·미니맵 연속 입력 |
| 여섯 웨이브 | 판타지 phone/desktop 모두 체력20·100처치·잔액492로 완주, 순차 입구 예고 및 판매·재배치 | 여러 전략 간 균형·사용자의 실패 원인 이해·재방문 재미 |
| 저장과 회귀 | 단위 검사와 기존 지도 E2E, 판타지 저장·이어하기·분리 슬롯 확인 | 공개 배포본에서 기존 저장을 유지한 실제 브라우저 왕복 |
| 러닝 연결 | TD 결과 → 판타지 러닝 준비 화면, 수동 러닝 시작·일시정지 화면 | 러닝 전체 판의 장애물·낙하·지속 제스처 및 실기 성능 |
| 제작 에셋 | 랜드마크 320/96px 접촉시트 검수, 배경·소품 파일 납품 | 실제 기기 확대·혼잡 전투에서 지속적인 판독성 |
| 릴리스 | 초기 타입 검사 통과, 최종 타입 검사 진행 중 | 발행 소스 SHA·CI·Pages SHA·공개 파일 및 화면 확인 |

기존 지도에서 누락 아트·좁은 화면 경로를 E2E로 확인했더라도 판타지 맵의
모든 누락 조합·렌더 실패·모션 감소를 검수했다고 확대하지 않는다. 친구 대전과
실제 iPhone 검수는 이번 확인 범위 밖이다. 최종 타입 검사·CI·배포 결과는
완료 증거를 확보한 뒤 위 링크의 검수 기록에 별도로 갱신한다.

생성된 에셋 수, 정적 캡처 한 장, 문서 작성, 국소 검사 결과를 전체 게임의
완성이나 공개 배포의 증거로 대신하지 않는다.
