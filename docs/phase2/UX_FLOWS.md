# 2차 UX 기획: 화면 · 흐름 · 상태

화면 ID는 UI_SPEC, COPY_DECK, WORK_SPLIT과 같은 이름을 쓴다. 문구는 모두 COPY_DECK의 키로 적었다(예: `wallet.title`).

## 0. 원칙

1. **할 일 하나**: 화면마다 굵은 버튼은 하나다. 나머지는 글자 버튼으로 둔다(1차 결과 카드에서 검증한 방식).
2. **돈처럼 보이는 숫자는 정확하게**: P 잔액·가격 옆에만 원 환산을 붙인다. 적립 알림에는 붙이지 않는다(과장 방지).
3. **게임과 돈을 섞지 않는다**: 메달과 P는 같은 화면에 나란히 두지 않는다. 게임 화면에는 P를 표시하지 않는다.
4. **동의는 필요할 때 한 번**: 광고 동의는 광고를 처음 보려 할 때 묻는다. 앱 첫 실행 때 묻지 않는다.
5. **실패해도 잃지 않는다**: 오프라인이거나 저장에 실패하면 이 기기에 남기고, 무엇이 남았는지 말한다.

## 2. 흐름

### 2.1 포인트 기준 전환 (A)
```
앱 실행 (전환된 서버 응답을 처음 받음)
  └ S1 시트: 제목 point.migration.title
       본문: 숫자 10배 · 가치는 그대로 · 1P = 0.1원 · 지금은 꾸미기에만
       예시 줄: "기존 125P → 1,250P (125원)"  ← 사용자 실제 잔액으로 계산
       [확인] (굵은 버튼 하나)   [자세히 보기 → S2]
  └ 다시 보지 않음(기기·계정 둘 다 기록)
```
- 잔액을 확인하지 못하면(오프라인) 예시 줄을 숨기고 문구 `point.migration.offline`을 쓴다.
- 구버전 앱이 새 형식 문서를 받으면 업데이트 안내(`point.upgrade`)를 보여주고, 잔액은 표시하지 않는다(잘못된 숫자 금지).

### 2.2 포인트 지갑 (B)
```
더보기 › 포인트
  S2
  ├ 잔액 카드: [P 코인] 1,250P  (125원)          ← 숫자 크게, 원은 보조
  │   "1P = 0.1원으로 계산해요" (S1 링크)
  │   이번 달 적립 +480P · 사용 −200P
  ├ [일지 쓰고 40P 받기]  ← 굵은 버튼. 오늘 이미 받았으면 [꾸미기 둘러보기]
  ├ S4 적립 방법 (접힘): 일지 40P · 방문 10P · 7일 연속마다 30P · 30일 연속 100P · 유효기간 5년
  ├ S3 최근 내역 5줄: 날짜 · 사유 · ±P · 잔액
  │   [전체 내역]
  └ 안내: 지금은 꾸미기에만 써요 · 다른 사람에게 보내기 · 현금 전환은 아직 없어요
```
- 로그인하지 않았으면: 잔액은 이 기기 기준이고, 문구 `wallet.guest`를 붙인다. 로그인 버튼은 글자 버튼으로 둔다.
- 계정과 기기 합계가 다르면(동기화 중): 숫자 옆에 "확인 중" 표시를 하고, 굵은 버튼은 그대로 둔다.

### 2.3 꾸미기 구매 (A)
```
서랍에서 아이템 선택 → 가격 칩 "80P"
  잔액 충분: [80P로 열기] → 성공 토스트 decoration.bought
  부족: 칩 회색 + 안내 decoration.insufficient ("40P 더 필요해요 · 일지 1번이면 돼요")
```
- 부족 안내는 남은 P를 일지 횟수로 바꿔 말한다(올림 ⌈부족/40⌉).

### 2.4 미니게임 2차 (C)
```
결과 카드 G1
  ├ 메달 줄: 🏅 +1 · 오늘 n번 더   (1차 구현)
  ├ [광고 보고 메달 +2] (글자 버튼, 하루 3회, 조건 충족 시에만 노출)
  │     처음: D1 동의 시트 → 동의하면 D3 광고 → 끝까지 봄: 메달 +2 토스트
  │                                         건너뜀/실패: 보상 없음 안내, 게임은 그대로
  ├ 굵은 버튼: 다음 도시 / 다시 도전 / N구간부터 다시
  └ 지도로 돌아갈 때: 전면 광고 조건(처음 3판 제외, 3판에 1회, 3분 간격, 동의한 14세 이상) 충족 시 D3
도시 완주 → 스탬프 획득 애니메이션(G3 스탬프가 지도에 찍힘)
시즌 마지막 도시 완주 → G4 시즌 완료 카드(엠블럼 · 모은 별 · 다음 시즌 열림) → [다음 시즌 지도]
```
- **경기 중, 구간 사이, 강화 선택 중에는 어떤 광고도 넣지 않는다.**
- 광고 버튼 노출 조건: 광고 제공자가 있음 + 14세 확인 + 광고 동의 + 오늘 3회 미만. 하나라도 빠지면 버튼 자체를 숨긴다. 단 동의 전에는 "광고 보고 메달 +2"를 보여주고, 누르면 D1을 띄운다.

### 2.4.1 광고 배치: 채널에 따라 바뀌는 배치 (오너 결정 2026-10-09 "추천안대로 유동적인 배치")

배포 채널을 하나로 고정하지 않는다.
- 광고 **자리**(placement)는 고정한다: 결과 카드 리워드, 도시 사이 전면, 지도 하단 배너.
- 자리마다 어떤 형식을 쓸지, 켤지는 **채널 설정 한 곳**에서 정한다.
- 개발 담당은 자리마다 `AdBreakProvider`를 호출하기만 한다. 채널별 어댑터가 형식을 고르고, 지원하지 않는 형식이면 "unavailable"을 돌려준다. 그러면 자리 자체가 숨는다.

| 자리 ID | 위치 | 웹(PWA) — AdSense H5 Games Ads | 앱인토스 — 토스 인앱 광고 | 스토어 앱 — AdMob | 지원하지 않을 때 |
|---|---|---|---|---|---|
| `result-bonus` | 결과 카드, 굵은 버튼 위 글자 버튼 | `adBreak({type:'reward'})` | 리워드 광고 | Rewarded | 버튼 숨김. 메달은 한 판 1개 그대로 |
| `between-cities` | 도시 완주 후 지도로 돌아갈 때 | `adBreak({type:'next'})` | 전면 광고 | Interstitial | 건너뜀 |
| `map-banner` | 투어 지도 맨 아래(경기 화면 아님) | 꺼 둠(H5 게임 광고에 배너 없음) | 배너 | Banner(적응형) | 영역을 접어 빈칸을 남기지 않음 |

같은 규칙을 모든 채널에 적용한다:
- 경기 중·구간 사이·강화 선택 중에는 광고 없음
- 처음 3판 유예, 전면은 3판에 1회 + 3분 간격
- 리워드는 하루 3회, 보상은 메달만
- 14세 이상 확인과 동의가 있을 때만
- 광고 클릭에는 보상 없음

자리별 켜기·끄기와 빈도 숫자는 원격 설정으로 바꿀 수 있게 한다. 나중에 운영자가 앱을 다시 배포하지 않고 조정할 수 있다. 다만 위 규칙의 상한은 넘을 수 없다(코드 상한).

### 2.5 광고 동의 (D)
```
D1 시트
  제목 ad.consent.title
  ① 나이 확인: [만 14세 이상이에요] [14세 미만이에요]
       14세 미만 → ad.consent.under14 안내 후 닫기. 광고 버튼을 영구 숨김(설정에서 다시 바꿀 수 있음)
  ② 무엇에 동의하는지 3줄(ad.consent.points): 광고를 보면 메달만 받음 · 맞춤 광고 사용 여부 · 언제든 끄기
  ③ [동의하고 광고 보기] (굵은) / [나중에] (글자)
D2 설정: 광고 보기 켬/끔 · 맞춤 광고 켬/끔 · 나이 확인 다시 하기 · 동의 기록 날짜
```
- 동의 기록(날짜·버전)은 계정이 있으면 계정에, 없으면 기기에 저장한다. 철회하면 즉시 광고 버튼이 사라진다.

## 3. 공통 상태 패턴 (E1)

| 상태 | 표시 | 문구 키 |
|---|---|---|
| 빈 상태 | 에셋 일러스트 + 한 줄 + 굵은 버튼 하나 | `state.empty.*` |
| 불러오는 중 | 300ms 넘을 때만 자리 표시 줄(스켈레톤). 스피너 금지 | — |
| 오프라인 | 화면 위 얇은 띠 "오프라인 · 이 기기에 저장돼요" | `state.offline` |
| 저장 실패 | 해당 카드 아래 한 줄 + [다시 시도] 글자 버튼 | `state.saveFailed` |
| 동기화 중 | 숫자 옆 작은 "확인 중" | `state.syncing` |
| 업데이트 필요 | 카드 대신 안내 + [새로고침] | `state.upgrade` |
| 잠김(게임) | 자물쇠 + 여는 조건 한 줄 | `tour.locked.*` |

## 4. 접근성·조작 기준

- 터치 영역은 44×44px 이상이다. 게임 패드는 1차 크기를 유지하고, "크게" 설정에서는 124px.
- 모든 숫자 변화(적립·메달)는 `role="status"`로 읽어 준다. 원 환산은 읽기 문장에 "125원 가치"로 붙인다.
- 색만으로 상태를 구분하지 않는다: 잠김에는 자물쇠, 부족에는 글자, 장착에는 "장착 중" 글자를 함께 쓴다.
- 움직임 줄이기: 스탬프·엠블럼·코인 애니메이션은 정지 이미지로 대체한다.
- 360px 폭에서 가로 스크롤이 없어야 한다. 글자 200% 확대에서도 굵은 버튼이 화면 안에 있어야 한다.

## 5. 측정(개발 담당이 이벤트를 붙일 자리)

`PRODUCT_ANALYTICS` 동의가 있을 때만 수집한다.
- 지갑 진입
- 기준 시트 확인
- 꾸미기 구매 성공·부족
- 광고 동의 노출·동의·거절
- 리워드 광고 시작·완료·건너뜀
- 스탬프북 진입
- 시즌 완료 카드 노출

게임 점수는 수집하지 않는다.
