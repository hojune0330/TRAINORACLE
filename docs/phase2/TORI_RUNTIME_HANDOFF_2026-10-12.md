# 토리 에셋 연결 준비 — 2026-10-12

상태: **초안 / 에셋 전달 대기 / 배포 미완료**. PR #354의 정적 원본 후보에 이어 게임 연결 코드를 준비했다. 이 문서는 캐릭터 검수 D-12b나 게임 연결 E-14의 완료 승인이 아니다.

## 현재 사용 경로

- 기존 Studio 모델을 재사용하는 DCC Bridge 경로를 우선한다. 추가 모델·배경·소품을 생성하지 않았다.
- 공식 Blender Bridge 1.0.34 및 Blender 4.5.14 LTS를 작업용 폴더에 준비했다. Blender 배포 파일은 공식 SHA-256과 대조했다.
- 로컬 Bridge는 `127.0.0.1:60600`에만 수신한다. Studio UI는 연결 중에 머물렀으며, 파일 수신·Blender 가져오기는 확인되지 않았다. 브라우저 권한 안내 여부를 사용자에게 확인 요청했다. 원인을 로컬 네트워크 권한 문제라고 확정하지 않는다.
- 공식 안내: [Studio/API 구분](https://www.tripo3d.ai/help/api-plugins/tripo-studiotripo-api), [Pro Blender Bridge](https://www.tripo3d.ai/integrations/blender).

API 키·브라우저 세션·서명 다운로드 URL·계정/결제 화면은 Git에 넣지 않는다. 기존 [정적 원본 및 해시 패키지](../../character-art/tori/tripo/2026-10-12/README.md)는 수정하지 않았다.

## 코드와 기대 파일

`app/src/screens/treadmill/runner-art.ts`는 토리 전용 atlas를 한 번만 요청한다. 이미지 로딩 전·실패·잘못된 크기에는 기존 Canvas 캐릭터를 사용한다. 다른 다섯 캐릭터도 기존 경로를 유지한다. 정적 초상은 이미지 로딩 뒤 다시 그리며, 언마운트된 초상은 다시 그리지 않는다.

예정 파일: `app/public/game/characters/tori/tori-atlas-v1.webp`.
**현재 이 파일과 동작 프레임은 아직 없다. 사용자의 에셋 완성·배포 요청은 유효하지만, 이 초안은 릴리스 준비가 끝나지 않았다.**

| 항목 | 렌더 계약 |
|---|---|
| 원본 프레임 | 512×512 투명 PNG, 골반 중심 x=256, 발 기준선 y=480 |
| 런타임 atlas | 1024×1024, 256×256 셀 4×4 |
| 셀 0–7 | 달리기 8프레임 |
| 셀 8–9 | 대기 2프레임, 현재 정적 UI는 8 사용 |
| 셀 10–12 | 점프 상승·정점·하강 |
| 셀 13–15 | 부딪힘·낙하·완주 환호 대표 포즈 |
| 게임 표시 | 캐릭터 기준 높이 75px, 기존 발 원점·충돌 규칙 유지 |

달리기는 렌더러가 관리하는 위상을 사용하고, 점프는 게임의 수직 속도로 단계를 선택한다. 따라서 달리기 위상이 점프 포즈를 순환시키지 않는다. 대시/지침은 원본 프레임에 작은 시각 변형을 적용한다. 이것은 별도 원본 동작을 만들었다는 뜻이 아니다.

## 이어서 할 일

1. Studio의 기존 토리에서 리그와 달리기·대기·점프 파일을 확보한다.
2. 원본 파일 보존과 해시 기록 후 실제 스켈레톤·클립을 검사한다. 고정 카메라로 렌더하고 64/75px 가독성, 접지, 좌우 다리, 프레임 이음새와 변형을 검수한다.
3. atlas와 개별 프레임, 재현 스크립트, 생성/동작 출처를 추가한다. 기존 자체 제작 에셋 고지는 Tripo 파생 캐릭터와 구분해서 수정한다.
4. 실제 이미지가 있는 상태에서 데스크톱·모바일 게임, 이미지 실패 폴백, 일시정지·모션 감소를 확인한다.
5. PR 검토·병합 후 최신 main과 기존 계정 공개 보류 설정을 유지하는 배포 절차를 실행한다. 파일 전달이나 코드 검사만으로 배포 완료라고 하지 않는다.
