## 1. 적용 범위

PR #339 사후 검토 PMR-01~03의 수정 계약이다. 로그인 사용자의 승인된 계정 보관,
D9, 훈련 처방, 공유 및 분석 권한은 변경하지 않는다. North Star 3.1을 따른다.
이 코드는 기기 비밀 메모 복구 코드이며 DB 비밀번호나 운영 백업 키가 아니다.

## 2. 보존과 확인

- 현재 암호문뿐 아니라 휴지통에 보존된 암호문까지 코드 확인에 포함한다.
- 휴지통 읽기는 수정·정리·삭제를 수행하지 않는다. 읽기 불확실을 빈 상태로 간주하지 않는다.
- 다른 계정 또는 소유권이 불명확한 암호문은 복호화 대상으로 가져오지 않는다.
- 기존 암호문이 있으면 새 코드 생성을 허용하지 않고 기존 코드 입력을 안내한다.
- 소유자, journal, vault, trash, ownership, 세션 코드가 비동기 검증 중 바뀌면 중단한다.
- 기존 메모의 내용·ID·날짜·휴지통 보관 기간은 코드 복구에서 변경하지 않는다.

## 3. 기존에 다른 코드가 섞인 자료

사용자가 복구 모드를 직접 열고 두 코드를 모두 보관했다고 확인한 경우만 처리한다.
모든 대상 암호문이 제공된 코드 중 하나로 실제 복호화되는지 먼저 확인한다.
첫 번째 코드로 열리지 않는 암호문만 같은 내용으로 재암호화한다. 내용은 메모리에서
잠시 다루고 평문 저장·로그·서버 전송·LLM 컨텍스트·분석에 넣지 않는다.

localStorage 여러 키를 실제 DB 트랜잭션이라고 주장하지 않는다. 검증 후 저장은
순차적이며 쓰기 실패/상태 변경 때 일부 암호문이 첫 번째 코드로 바뀌어 있을 수 있다.
이 경우 성공으로 표시하거나 코드를 자동 폐기하지 않는다. 두 코드를 유지해 같은
작업을 재시도하도록 안내한다. 두 코드 중 하나로 여전히 열리는 암호문을 보존하고,
알 수 없는 다른 탭의 새 값을 롤백으로 덮어쓰지 않는다.

모든 저장 readback과 현재 범위 검사가 끝난 뒤에만 준비 완료 및 세션 코드 설치를
허용한다. 코드가 부족하거나 암호문이 손상됐으면 원문을 추측하지 않는다.

## 4. 화면

- 타이핑 시작 시 textarea 위에 긴 안내를 삽입하지 않는다.
- 입력창 아래 작은 준비 버튼을 두고 사용자 선택/저장 요청에만 상세를 연다.
- 준비 완료는 현재 세션/계정 범위의 실제 코드 상태를 따른다.
- 코드가 사라졌다면 입력 내용 보존 상태로 다시 준비할 수 있어야 한다.
- 준비와 실제 일지 저장은 별개다. 준비만 끝나고 글이 저장됐다고 표시하지 않는다.

## 5. 필수 시험

휴지통만 존재하는 경우, 복원 후 읽기, 혼합 코드 복구, 잘못된 코드 무변경,
중간 저장 실패와 재시도, 소유자 및 각 저장소 변경, 준비 이후 코드 제거,
모바일 첫 타이핑의 입력창 위치와 고정 저장 바 가림을 확인한다.
