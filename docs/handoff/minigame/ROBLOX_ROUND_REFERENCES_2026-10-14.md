# 현재 Roblox 레퍼런스와 라운드·시점 확장안

작성: 2026-10-14. 상태: **레퍼런스 조사 및 후속 기획, 새 라운드 미구현**.

오너 요청: “2.5d이지만 방향을 바꾸는 형태나 시점 변경을 통해 더 박진감 줄 수 있나? … 라운드가 끝나면 다른 시점 라운드가 시작된다거나. 종목이 달라진다거나.” 이어서 “레퍼런스로 넣어 지금 로블록스에서 유행하는 게임으로”.

현재 친구 경기의 시간제 밀어내기·무한 리젠·능력 초기화는 유지한다. 아래 원작의 영구 육성, 최후 생존, 역할 고정은 채택하지 않는다. 현재 구현과 배포 상태는 [구현 인계](IMPLEMENTATION_2026-10-14.md)를 따른다. 이 문서는 신규 라운드 구현 완료나 배포 승인을 뜻하지 않는다.

## 현재 유행 확인 방법

2026-10-14 약 21:23 KST에 로그인하지 않은 브라우저로 [Roblox 공식 Top Playing Now](https://www.roblox.com/ko/charts/top-playing-now)를 직접 읽었다. 차트 진입 화면에 **전체 기기 및 위치 결과**가 표시됐다. 아래는 화면에 표시된 반올림 접속자 수의 순간 관측이며 일간 사용자, 유지율, 국내 순위 또는 일정 기간 평균이 아니다. 확인 직후에도 수치는 바뀔 수 있다.

한국어 메뉴가 해당 항목을 “지금 가장 많이 듣는 음악”으로 번역했지만 URL은 `top-playing-now`다. [공식 설명](https://www.roblox.com/charts/top-playing-now)은 현재 온라인 플레이어 수로 선정한다고 밝힌다. 일반 차트의 대한민국/컴퓨터 필터가 적용된 ‘톱 트렌드’와 전체 기기·위치의 현재 접속자 목록을 혼동하지 않는다.

초기 검색 색인의 1일~1개월 전 수치는 최종 표에서 제외했다. 상세 페이지의 비동적 텍스트에 나오는 “no running experiences”를 실제 접속자 0으로 해석하지 않았다. 원작 메커니즘은 제작자가 작성한 공식 설명에서 확인했으며, 직접 플레이하거나 게임 내 카메라 영상을 검수한 것은 아니다. 아래 시점 배치는 **우리 게임의 제안**이다.

인기 접속자는 후보 선정 근거다. 특정 설계 때문에 재방문하거나 우리 이용자도 재미있어할 것이라는 인과 증거는 아니다. 이번 조사에는 새 Reddit 이용자 평가를 포함하지 않았다. 기존 Reddit 근거는 [장애물 기획](HAZARD_APPROACH_AND_DEPTH_PLAN.md) 및 [연구 자료](RESEARCH.md)와 구분해 읽는다.

## 적용 방향: 같은 친구와 이어 하는 러닝 스포츠 시리즈

카메라만 바꾸지 않고 **다음 라운드에서 타이밍과 공간 사용이 달라지게** 한다. 우선 두 라운드로 조작·시점 변화를 검증하고 세 번째 종목을 확장한다. 45~60초×2~3라운드는 테스트 시작안이며 현재 90초 구현을 바꾼 값이나 오너 확정값이 아니다.

| 순서 | 우리 라운드 제안 | 화면·방향 | 플레이 변화 | 연결 레퍼런스 |
|---|---|---|---|---|
| 1 · 우선 | 트랙 밀어내기 | 측면, 오른쪽 진행 | 연속 허들 사이에서 회복·점프·상대 밀치기 | Keyboard Escape의 발판 리듬 + RIVALS의 짧은 승부 |
| 2 · 우선 | 커브 오르막 | 사선 앞쪽으로 이어지는 코스. 라운드 사이에 시점을 바꾼 뒤 안정적으로 추적 | 좁은 다리·넓은 회복 지대·오르막 묶음으로 대시 타이밍 변화. 첫 버전은 자동 경로 추종 | WRONG WAY!의 코너 예고·코스 리듬 |
| 3 · 후속 | 빙판 밀어내기 | 약간 높은 사선 시점의 평면 경기장 | 관성이 남아 멈출 위치를 예상하며 밀치기. 떨어져도 무한 리젠 | Illegal Soccer에서 가져온 ‘스포츠 + 몸싸움’ 발상. 빙판 자체는 우리 제안 |
| 별도 실험 | 내리막 추격 | 캐릭터 뒤·위에서 전방을 보는 시점 | 원근으로 다가오는 허들·좁아지는 길. 상대 위치를 읽으며 밀치기 | Keyboard Escape의 속도 압박. 후방 카메라는 우리 제안 |

첫 두 라운드는 **꾹 누르기=달리기, 상방 스와이프=점프, 두 번 누르기=대시/근접 밀치기**를 유지한다. 자동 코너를 돈다고 화면 좌우 입력이 갑자기 반전되면 안 된다. 실제 좌우 이동·빙판 자유 이동은 새 입력 설계가 필요하므로 첫 두 라운드의 스킨 변경으로 취급하지 않는다. 달리기·점프·대시의 목적이 분명한 상태에서만 추가한다.

라운드 사이에는 다음 코스와 변화 한 가지를 보여준다. Ball VS Ball의 ‘후보 중 선택’을 번안한다면 각자 같은 후보에서 **이번 라운드에만 적용되는 이점/비용이 있는 강화 하나**를 고르게 한다. 예: 접지 상승/대시 거리 감소, 점프 비용 감소/밀치기 저항 감소. 숫자와 후보는 미정이며 서버의 공통 선택 마감과 기본값이 필요하다. 선택 UI 때문에 상대를 무기한 기다리게 하지 않는다.

시리즈 초안은 각 라운드의 기존 판정(밀어내기 횟수 → 낙하 적은 순 → 공동 순위)으로 라운드 승점을 부여하고 전체 승점을 비교한다. 지형별 밀어내기 빈도가 달라서 모든 KO를 단순 합산하지 않는다. 동률은 공동 순위부터 검증한다. 경기 중 무한 리젠, 모든 참가자의 다음 라운드 진입, 마지막 결과에서 같은 방 재대결을 유지한다. 구체적인 승점·시간은 후속 플레이 검증으로 정한다.

## 카메라·장애물 규칙

- 큰 시점 전환은 라운드 정산 이후, 다음 출발 이전에 한다. 서버는 전환 중 판정·득점을 멈추며 전원에게 같은 시작 시각을 준다. 진행 중 라운드에서 클라이언트만 시간을 멈추지 않는다.
- 전환 중 누르고 있던 입력을 해제한다. 다음 라운드에는 공통 카운트다운을 사용한다. 느린 기기에서 준비가 늦으면 무적 상태로 혼자 먼저 출발하거나 남의 점수를 올리지 않는다.
- 플레이 중에는 진행 방향을 따라 부드럽게 추적하고, 큰 회전 대신 코스 곡률·소실점·배경 속도차로 방향 변화를 보여준다. 정밀 점프 직전에는 시점 변화량을 낮춘다.
- 주행면·러너 발·장애물 접지점을 같은 월드 좌표와 투영으로 그린다. 장식만 기울여 2.5D처럼 보이게 하지 않는다. 충돌은 서버 월드 좌표에서 유지한다.
- 커브 뒤의 장애물도 필요한 반응 시간을 확보한다. 화면 밖부터 연속 접근시키는 기존 수정은 유지한다. ‘박진감’을 화면 중앙 즉시 생성으로 구현하지 않는다.
- 카메라 전환과 최대 대시에도 좌우/하단 빈 화면이 없어야 한다. HUD·예고는 캐릭터와 충돌물의 경로를 가리지 않는다. 모션 감소에서는 회전 연출을 생략하고 정해진 시점으로 전환한다.

## 에셋·구현 범위

1. 기존 트랙·나무·바위·허들을 재사용해 직선/사선 구간을 만든다. 속도·코너·노면 리듬부터 검증하고 신규 유료 생성은 먼저 요구하지 않는다.
2. 현재 측면 캐릭터 이미지를 단순 회전해 뒷모습으로 쓰지 않는다. 사선·후방 시점에는 대응 프레임이 필요하다. 사용할 수 있는 3D 원본과 리그가 실제로 있는지 확인한 뒤 같은 모델에서 렌더링하거나 추가 제작 범위를 결정한다.
3. 서버에 시리즈/라운드 식별자, 전환 상태, 공통 마감, 라운드별 점수와 최종 결과를 추가해야 한다. 기존 90초를 여러 개의 UI 타이머로 잘라 붙이는 것으로 끝나지 않는다.
4. 빙판·공 게임·후방 시점은 각각 입력·충돌·에셋 부담이 다르다. 먼저 ‘트랙 → 사선 오르막’ 두 라운드에서 친구가 자발적으로 재대결하는지 확인한다.

## 다음 구현의 합격 증거

- 서로 다른 두 브라우저에서 라운드 전환, 무한 리젠, 같은 최종 순위와 같은 방 재대결 확인.
- 늦게 도착한 이전 라운드 입력·점수가 새 라운드에 섞이지 않음. 전환·리젠 중 이탈해도 무한 대기하지 않음.
- 작은 휴대폰에서 최대 대시·가장 앞 위치·커브 진입 시 장애물의 가시성과 접지 연속성 확인. 빈 여백·HUD 가림·중앙 즉시 등장 없음.
- 두 라운드에서 플레이 선택이 실제로 달라지는지 사람에게 확인. 같은 조작을 같은 타이밍에 반복한다면 배경만 바뀐 상태로 판정.
- 재방문 효과는 현재 Roblox 접속자 수로 대신 증명하지 않음. 초대 입장 완료, 경기 완료, 결과 후 같은 방 재대결, 다음 방문 재플레이를 별도로 평가. 추적 수집은 자동 도입하지 않음.

공동 작업자 참고: 이번 변경은 문서만이다. 새 카메라·빙판·후방 프레임·시리즈 서버 상태는 아직 구현하지 않았다. 참고 게임의 이름·브랜드·캐릭터·맵·음원은 우리 에셋으로 복제하지 않는다.
