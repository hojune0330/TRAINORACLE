# UX·UI 2차 개선 (규칙 v2)

작성일: 2026-10-07. 상태: **PR #349 위의 후속 커밋 / 플레이테스트 전**. 1차 구현의 방향(트레드밀·무행동 추락·구간 사이 강화·판마다 초기화)은 유지하고, 백로그 P0/P1 중 코드로 다룰 수 있는 항목을 처리했다. 아래 수치는 모두 게임 밸런스용이며 실제 훈련·신발·부상과 관계없다.

## 1차 구현에서 발견한 문제

| # | 문제 | 근거 |
|---|---|---|
| 1 | 판정과 그림이 달랐다 | 장벽은 22px로 그리지만 충돌 반경은 화면 폭 기준 2.8%. 화면이 넓으면 “안 닿았는데 맞음”, 좁으면 반대 |
| 2 | 강화 선택이 무의미했다 | 봇 측정에서 9개 강화 조합의 완주율이 거의 같았다(21~24/24). 강화가 결과를 바꾸지 않음 |
| 3 | 장애물이 예고 없이 나타났다 | 3.7초 간격 고정 생성. 화면 밖에서 들어오기 직전 알 방법이 없음 |
| 4 | 실패 원인이 남지 않았다 | 실패 문구 한 줄. 무엇을 바꿔야 하는지 알 수 없음 |
| 5 | 탭바·긴 설명·조작이 한 화면을 다퉜다 | 모바일에서 강화 카드가 탭바 아래로 잘림(1차 스크린샷) |
| 6 | 상태 피드백 부족 | 에너지 소진·피격·착지·대시 충전이 캐릭터나 버튼에 드러나지 않음 |
| 7 | 터치 반응 | 점프·대시가 `click`(손을 뗄 때)에 동작해 타이밍 게임에 늦음 |

## 바꾼 것

**규칙(`treadmill.ts`, v2)**
- 판정을 그림과 같은 단위로 바꿨다. 가로는 벨트 폭의 비율, 세로는 논리 px. 장애물 종류별 `halfWidth/height`를 그리기와 판정이 공유한다.
- 장애물을 **고정 코스 데이터**로 옮겼다(구간별 등장 시각). 같은 코스를 반복하며 익히는 재미와, 이후 공통 시드·친구 고스트의 기반이 된다. 가시밭은 가시 사이에 장벽 하나를 섞었다.
- 1.4초 전 예고(`upcomingHazards`), 다음 장애물(`nearestHazard`), 점프 가이드 구간(`jumpWindow`)을 엔진에서 제공한다.
- 실패 원인(`failure: fall | spike`)과 판 기록(`stats`: 부딪힘·넘은 장애물·점프·대시·쉰 시간·최저 에너지), 실패 원인 기반 한 줄 팁(`treadmillTip`).
- 에너지 소진 상태(`exhausted`)를 명시. “누르고 있으면 회복 안 됨”을 화면이 말할 수 있다.
- 강화의 이점·비용을 다시 짰다. 봇 측정으로 서로 다른 조합이 다른 결과를 내는지 확인했다.

| 강화 | 이점 | 비용 | 의도 |
|---|---|---|---|
| 접지 밑창 | 진흙 전진 +50% · 부딪혀도 덜 밀림(½) | 점프 +3 | 진흙에 강하지만 가시밭에서 에너지를 더 남겨야 함 |
| 스프링 밑창 | 점프 −4 | 달리기 전진 −12% | 가시밭에 강하지만 진흙에서 밀림 |
| 일정한 박자 | 달리기 소모 −20% | 대시 충전 +1초 · 회복 −10% | 범용. 위기 탈출이 약해짐 |

**화면(`TreadmillGame.tsx`, `draw.ts`, CSS)**
- 상태별 패널: 시작 전 세 줄 규칙 → 플레이 중 조작 → 구간 사이 강화 → 결과. 한 시점에 한 가지 선택만 보인다.
- 게임 화면에서 하단 탭바를 숨겼다(오버레이와 같은 방식). 뒤로가기는 헤더에 유지.
- HUD: 3구간 진행 막대, 시간, 에너지 게이지(부족하면 `--err`). 일시정지는 헤더 오른쪽 아이콘(`Esc`/`P`).
- 엄지 조작: 달리기(넓게, 꾹), 점프·대시(누르는 순간 동작). 버튼 높이 88px. 대시 버튼 아래 충전 막대.
- 경고 줄과 경기장 테두리 색이 상황(중립·주의·위험)을 함께 알린다. 문구가 항상 병기되어 색만으로 전달하지 않는다.
- 캔버스: 뒤쪽 위험 구역이 가까워질수록 진해짐, 앞쪽 예고 링, 점프 가이드 띠, 지금 뛰면 되는 장애물 테두리, 착지 그림자, 착지 찌그러짐, 피격 깜빡임·“쿵!”, 소진 표정, 대시 잔상, 벨트 롤러.
- 강화 카드: 이점(+, `--ok`)과 비용(−, `--warn`)을 분리, 다음 구간에 맞는 강화 표시, 보유 수, 다음 구간 설명.
- 결과: 실패 위치·원인 제목, 버틴 시간·넘은 장애물·부딪힘·**이번 접속 최고**(메모리만, 저장·전송 없음), 원인 기반 팁, 다시 시작.
- 진동: 지원 기기에서 피격 시 짧게(`navigator.vibrate`). 미지원이면 무시.
- 모션 감소: 바닥 흐름·보폭·깜빡임·잔상·패널 등장 애니메이션 정지, 피격은 정적 테두리로 대체. 기능 차이 없음.

UX 기준 문서(§1·§2·§3·§7) 확인: 그림자·좌측 스트립 없음, 새 hex 없음(토큰만, 캔버스도 CSS 토큰을 읽음), 직각·4px 이하 모서리, 4px 간격, 터치 44px 이상, 375px 이하 2열 접기, lucide 아이콘만 사용, 이모지 없음.

## 밸런스 측정 방법

`treadmill.test.ts`의 `balance guard`가 같은 순수 엔진으로 단순한 플레이어 전략을 돌린다.

- 무행동, 계속 달리기만, 점프 연타는 **완주하지 못해야** 한다.
- 달리고·쉬고·점프 타이밍을 맞추는 전략은 **세 강화 모두로 완주**할 수 있어야 한다.
- 접지 밑창 2개는 에너지 예비를 적게 두면 가시밭에서 실패해야 한다(비용이 실제로 작동하는지).

봇 완주는 사람에게 재미있다는 증거가 아니다. 사람의 플레이테스트에서 쉬움/어려움이 확인되면 `TREADMILL_RULES`와 `TREADMILL_STAGES[].course`부터 조정하고 이 가드를 함께 갱신한다.

## 아직 하지 않은 것

- 실제 휴대폰에서의 동시 터치(달리기 유지 + 점프) 확인. 코드상 포인터별로 추적하고 `touch-action: none`이지만 실기기 검증이 필요하다.
- 사람 플레이테스트, 난이도·재방문 판단.
- 잔디·뻘·산악·우주·복합 도로, 공통 시드, 친구 고스트(고정 코스 데이터가 첫 기반).
- 효과음. 기존 앱에 오디오 정책이 없어 추가하지 않았다.
