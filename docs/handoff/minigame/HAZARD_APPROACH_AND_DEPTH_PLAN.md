## 이번 수정

카메라가 전방 러너를 따라갈 때 엔진의 고정 생성 좌표 x=1.06이 화면 안으로 들어왔다. 러너 x=0.88, 달리기 카메라 기준 생성 지점은 화면 약 65%라 실제 장애물이 중간에서 나타났다. 이전 `!` 예고만으로는 이 불연속을 해결하지 못했다.

`hazard-view.ts`는 코스의 미생성 장애물도 기존 속도로 역산해 같은 경로 위에 그린다. 생성 전 위치는 `hazardEntry + hazardSpeed × 남은 시간`이다. 화면 밖에서 들어오고 엔진 활성화 시 같은 ID의 실제 장애물로 이어진다. 미리 보이는 장애물은 충돌·점수·저장 데이터에 넣지 않는다. 기존 생성 좌표 1.06만 공통 상수로 옮겨 수치와 물리는 유지한다. 기존 엔진의 1/120초 활성화 오차 범위 안에서 연결한다.

오른쪽 `!`는 화면 밖 장애물의 화면 진입 시간 기준으로 표시한다. 이미 보이는 장애물에 고정 생성 시점 경고를 중복 표시하지 않는다. 다음 화면 밖 장애물의 경고는 표시할 수 있다. 카메라 자체 이동에 따른 진입 예측 변화가 있어 `!`의 시간은 반응 시간 보증이 아니다.

검수: 화면 가장자리에서 첫 등장, 전방 러너의 생성 전 가시성, 생성 시 중복/위치 점프 없음, 일시정지/복구, 실제 그리기 호출. 생성 전 그리기를 제거하는 실제 결함을 주입해 렌더러 테스트 실패를 확인한다. 브라우저는 실제 입력으로 앞쪽까지 이동하며 접근→활성화 연속성을 확인한다. 배포/최종 검사 결과는 연결 PR에 기록한다.

## 목표와 현재 제약

재방문할 이유는 장애물을 읽고 다른 리듬으로 통과하는 재미다. 조작은 꾹 달리기·상방 스와이프 점프·더블탭 대시를 유지한다. 영구 능력치 강제 누적, 신규 역할·포지션 또는 실시간 서버를 추가하지 않는다.

현재 서울은 90초 동안 허들/가시 36개다(구간별 9/12/15). 후속 도시에는 추가 배치가 있다. 개수만 늘리면 에너지와 점프 간격 문제부터 생긴다. 먼저 종류와 배치 리듬을 확장하고, 완주 가능한 패턴만 코스에 넣는다.

## 장애물 확장 순서 — 제안, 미구현

| 우선 | 내용 | 플레이 선택 | 구현/검증 조건 |
|---|---|---|---|
| 1 | 낮은 허들·콘 묶음·작은 통나무 | 같은 기본 점프를 서로 다른 외형으로 읽기 | 기존 허들 판정 재사용. 실제 점프 높이/폭과 그림 일치. 배경 장식 허들과 구분되는 외곽선 |
| 2 | 두 번 점프하는 연속 허들 | 착지 후 바로 다음 점프, 또는 앞에서 손을 놓아 간격 확보 | 초기 배치안 1.4~1.8초 간격. 캐릭터 전진/대시/강화에 따라 접촉 간격이 바뀌므로 전체 시뮬레이션 통과 후 채택. 점프 2회 비용을 확보할 회복 구간 포함 |
| 3 | 넓은 물웅덩이 | 점프로 넘기 또는 에너지를 아끼며 밟고 감속 감수 | 신규 비치명적 판정. 젖은 바닥 범위와 감속 시간 명확히 표시. 점프+대시 조합으로도 통과 가능한 최대 폭 산정 후 채택 |
| 이후 | 예고 후 솟는 짧은 장벽 | 바닥 표시를 보고 타이밍 선택 | 화면 밖에서 들어오는 것과 바닥에서 올라오는 것은 서로 다른 패턴. 표시 없는 즉시 생성 금지. 첫 확장에서는 보류 |

첫 시범 구간은 30초: 단일 장애물 학습 → 두 장애물 리듬 → 물웅덩이 선택 → 회복 공간. 무작위로 개별 장애물을 흩뿌리지 않고 검증된 짧은 패턴을 조합한다. 기본/접지/스프링/절약 강화 및 도시별 벨트 속도에서 점프 비용·착지 간격을 검사한다. 좁은 휴대폰과 최대 대시에서 첫 가시성부터 필요한 조작까지 1.2초 이상을 초기 목표로 측정하되, 아직 보장된 수치로 제품에 표기하지 않는다.

가시 즉사는 추가 밀도의 기본 재료로 쓰지 않는다. 기존 가시는 유지하고, 새 종류는 실수 후 회복할 수 있도록 설계한다. 배경 잔디의 장식 게이트는 관람석/표지판으로 대체하는 편이 실제 장애물 구분에 유리하다.

## 미세 2.5D 시점 — 제안, 미구현

기존 전방 지연 추적 위에 **진행 방향에 반응하는 원근 변화**를 얹는다. 무작위 화면 흔들림 대신 대시 진입 때 소실점이 전방으로 옮겨지고 회복하면 돌아오게 한다.

- 시범 범위: 소실점 좌우 화면 폭 ±3%, 지평선 높이 ±1%. 전환 약 0.4~0.7초. 이 값은 플레이 검수 전 시작값이다.
- 새 공통 투영 함수에서 주행면·러너 발·장애물 바닥·점프 안내를 함께 변환한다. 장식층만 따로 기울여 장애물 접지가 어긋나는 방식은 사용하지 않는다. 충돌은 기존 월드 좌표에서 계산한다.
- 먼 배경은 작게, 가까운 노면은 크게 반응한다. HUD는 고정한다. 조작 입력 좌표는 화면 제스처 기준 그대로 둔다.
- 최대 변환에서도 좌우/하단 빈 공간을 덮을 여유 배경을 그린다. 카메라가 장애물을 화면 안으로 끌어들일 때도 이번 접근 렌더링을 사용한다.
- 움직임 줄이기에서는 추가 원근 변화를 0으로 고정한다. 일시정지에서는 현재 시점을 동결하며 복귀 카운트다운 중에도 이동하지 않는다.

구현 순서는 접근 버그 수정 배포 → 외형 3종/연속 허들 시범 → 공통 2.5D 투영 → 물웅덩이 판정이다. 새 Tripo 제작 없이 기존 에셋과 간단한 도형으로 먼저 조작감·가독성을 검증한다. 추가 유료 생성, 실시간 멀티플레이와 계정/훈련 연동은 이 기획의 실행 범위가 아니다.
