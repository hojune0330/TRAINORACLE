# 미니게임 보상·광고·현금성 포인트 설계안

작성일: 2026-10-09.

오너 요청 요지:
- 일지 포인트를 나중에 현금성 포인트로 바꿀 생각이 있다.
- 포인트를 안전하게 구성할 방안이 필요하다.
- 광고를 넣을 구간과 적당한 보상이 필요하다.
- 토스 미니게임 형태가 이상적이다.

상태: **설계안과 게임 쪽 규칙 모듈만** 있다(`app/src/domain/minigame/rewards.ts`). 광고 SDK, 네트워크 연결, 현금성 포인트 기능은 구현하지 않았다. 아래 법·정책 내용은 공개 자료를 조사한 결과이고, 법률 자문이 아니다. 출시 전에 전자금융·게임 분야 변호사 확인이 필요하다.

## 1. 결론

**게임 결과는 절대 돈이 되면 안 된다.** 현금성 보상은 게임 바깥의 정해진 행동(일지 작성, 출석, 광고주가 비용을 내는 미션)에만 고정 금액과 상한을 두고 준다.

토스와 카카오페이도 이 구조다.

| 구분 | 토스·카카오페이가 하는 것 | 근거 |
|---|---|---|
| 누가 돈을 내나 | 광고주. 카카오페이 리워드 광고 상품은 "광고비 내 차감하여 포인트 비용 추가 청구 없음"이라고 명시한다 | https://ads.kakaopay.com/ads/rewarded |
| 누가 포인트를 발행하나 | 선불전자지급수단 발행업자로 등록된 회사. 토스포인트 약관에 "선불전자지급수단의 일종"이라고 되어 있다 | https://toss.im/docs/10623/10625 |
| 무엇에 주나 | 걸음 수 구간, 광고 보기·버튼 누르기, 상품 구경 등 **보거나 참여한 행동**. 하루 상한과 소액 고정이다 | https://toss.im/tossfeed/article/how-much-toss-apptech |
| 무엇에 안 주나 | 게임 점수·승패·순위. 앱인토스 정책은 이를 "사행성 유도"로 명시해 금지한다 | https://developers-apps-in-toss.toss.im/guide/marketing/promotion |
| 토스쇼핑 | 판매자가 게재비를 내면 피드를 볼 때마다 1~10원을 지급한다. 지급 수단은 일반 토스포인트로 보인다(일부 미확인) | https://shopping-docs.toss.im/ads/setup/point |

TrainOracle은 아직 선불업자가 아니다. 그래서 "포인트를 직접 현금화"하는 형태를 그대로 따라 하면 위험하다. 따라 할 수 있는 것은 **광고주나 회사 예산으로 정해진 행동에 소액을 주는 구조**다.

## 3. 권장 구조: 장부 3개를 섞지 않는다

```
[게임 메달 🏅]        [TrainOracle P]                  [현금성 보상 (미래)]
 미니게임 플레이        일지 작성·출석 (지금)               광고주·회사 예산
 리워드 광고 시청       고정액·하루 상한                    앱인토스 프로모션 또는 기프티콘 발송
 → 게임 꾸미기·이어하기  → 앱 안 꾸미기 (지금)               → 토스포인트·기프티콘
   현금 교환 영구 불가    현금화 전 변호사 검토               게임 결과와 무관한 행동에만
```

1. **게임 메달**(`rewards.ts`, 이번 구현)
   - 한 판을 8초 이상 하면 결과와 상관없이 1개를 준다. 하루 5개까지다.
   - 메달을 주는 함수에는 점수·별·완주가 **입력으로 들어가지도 않는다**(테스트로 고정).
   - 리워드 광고를 끝까지 보면 +2개, 하루 3번까지다. 보기 전에 보상을 고지하고 사용자가 직접 선택한다. 건너뛰어도 게임은 그대로 쓸 수 있다.
   - 쓸 곳은 게임 캐릭터 색상·트랙 꾸미기, 실패 시 "구간부터 다시" 무료 횟수 같은 **게임 안 혜택뿐**이다.
   - P·기프티콘·현금으로 바꾸는 함수는 만들지 않는다. 바꾸는 코드가 생기면 테스트가 실패한다.
2. **TrainOracle P**: 현재처럼 일지 작성(×4)과 방문(×1)으로 쌓고, 앱 안 꾸미기에만 쓴다.
   - 미니게임은 P를 읽지도 쓰지도 않는다(기존 테스트 유지, 이번에 리워드 모듈까지 확장).
3. **현금성 보상(나중)**: 다음 중 하나를 고른다.

| 방식 | 장점 | 주의 |
|---|---|---|
| **앱인토스 프로모션**: 토스가 회사 예산으로 토스포인트를 지급 | 선불업 부담이 토스에 있다. "토스 미니게임 형태"와 가장 가깝다 | 게임 결과 보상 금지, 1인당 5,000P 이하, 사전 검수. 지급 대상은 가입·튜토리얼·간단한 미션·친구 초대처럼 게임 결과와 무관한 행동이다 |
| **기프티콘 발송**(기프티쇼 비즈 등): 이벤트 경품 | 구조가 단순하다 | 회사 비용이다. 점수·순위와 연동 금지. 세무 처리와 경품 한도는 확인 필요 |
| **리워드 광고 네트워크·오퍼월**(버즈빌·애드팝콘 등) | 광고주 돈으로 보상하고 수익도 남는다 | 보상이 **우리 앱 포인트로** 지급되므로, 그 포인트를 현금화하는 순간 선불업과 AdMob 문제가 다시 생긴다 |
| **P를 직접 현금화** | 사용자 체감이 가장 크다 | 선불업 등록 대상인지 먼저 판단해야 한다. 발행잔액·연간 발행액 집계, 약관, 본인인증, 14세 이상 제한이 필요하다 |

**추천:** 1단계는 게임 메달(앱 안)과 P(앱 안)이다. 2단계에서 현금성이 필요해지면 **앱인토스 프로모션**으로 일지 작성 연속일, 첫 기록 같은 비게임 미션에만 소액을 준다. 미니게임 결과는 어느 단계에서도 현금성 보상과 연결하지 않는다.

## 4. 광고 자리 (토스 미니게임 형태)

| 자리 | 형식 | 조건 | 보상 |
|---|---|---|---|
| 결과 카드의 "광고 보고 메달 +2" | 리워드(사용자가 선택) | 하루 3회까지. 보기 전에 보상을 고지한다. 끝까지 봤을 때만 지급한다 | 게임 메달만 |
| 도시를 마친 뒤 지도로 돌아갈 때 | 전면 | 처음 3판은 표시하지 않는다. 3판에 1회, 직전 표시 후 3분 이상 지나야 한다. **경기 중·구간 사이·강화 선택 중에는 절대 표시하지 않는다**. 닫기 버튼을 분명히 둔다 | 없음 |
| 지도 아래 배너 | 배너 | 경기 화면에는 두지 않는다 | 없음 |

공통 조건:
- 14세 이상 확인과 광고 동의가 없으면 광고를 하나도 보여주지 않는다(`interstitialDue`, `rewardedOffered`가 false).
- 광고 클릭에는 보상을 주지 않는다. 앱인토스와 AdMob 모두 금지한다.
- 기본값은 광고 없음(`NO_ADS`)이다. 광고 네트워크는 `AdBreakProvider` 인터페이스에 붙인다.
- 웹이면 AdSense H5 Games Ads(`adBreak()`)를, 앱인토스면 토스 인앱 광고를, 앱이면 AdMob을 붙이게 된다. 어느 것이든 가입·승인이 필요하다.

## 6. 오너·법률 결정이 필요한 것

1. 배포 채널: PWA만 쓸지, 앱(스토어)으로 낼지, 앱인토스로 낼지. 적용되는 광고·심사 정책이 달라진다.
2. 러닝 투어 등급분류: GRAC 또는 스토어 IARC로 받을지.
3. P 현금화 방식(앱인토스 프로모션 / 기프티콘 / 직접 현금화)과 선불업 해당 여부.
4. 메달 사용처: 꾸미기 상점, 이어하기, 둘 다 중에서.
5. 연령 기준: 14세 이상으로 할지 성인으로 할지, 본인인증 방식.
6. 광고 네트워크 선택, 개인정보처리방침·약관 개정.
7. 경품 세무 처리.
