# 모바일 자동 정지 수정과 재사용 가능한 출시 안내

## 요청과 재현

사용자가 iPhone 브라우저에서 8/30초에 이유 없이 일시정지된 화면을 제보했다.
해당 기기의 원격 로그는 없으므로 그 순간의 이벤트 하나를 확정하지 않는다.
기존 공개 번들에 대한 모바일 Playwright 재현에서 아래 두 경우 모두 `running` 기대와 달리 `paused`가 됐다.

- `a delayed frame keeps playing without catching up the stall`: RAF 한 번이 900ms 늦으면 기존 `delta > 0.25` 조건이 강제로 정지했다.
- `touch-style empty focus does not pause but hidden page freezes and releases input`: 캔버스 포커스가 풀려 `relatedTarget=null`이면 게임 루트의 blur가 정지했다. 페이지를 떠나지 않아도 발생한다.

## 수정 계약

프레임 지연은 기존 순수 엔진의 100ms 상한과 1/120초 서브스텝으로 처리한다. 지연분 전체를 한꺼번에 진행시키거나 일시정지 창을 띄우지 않는다. 화면 내 포커스 해제는 키보드 눌림만 해제한다. 수동 정지, 메뉴, Escape/P, 실제 창 blur와 document.hidden은 여전히 경기를 멈추고 입력을 비운다. 숨김 전환에서는 프레임 기준 시각을 초기화한다. 자동 복귀 대신 계속 버튼으로 재개한다.

정지 카드에는 직접 정지/다른 창으로 이동/게임 화면 이탈 중 해당 이유를 표시한다. 경기 규칙·보상·성장 계산은 바꾸지 않는다. 이 로컬 시간 정책을 향후 경쟁 기록 검증용 서버 시계로 간주하지 않는다.

## 출시 안내 운영 계약

홈의 오늘 기록 영역 바로 아래 **배너 한 개**를 사용한다. 기록 버튼·안전 안내보다 앞에 놓지 않는다. 강제 팝업, 자동 캐러셀, 깜빡임, 반복 말풍선은 넣지 않는다.

- 첫 안내: `running-tour`, version `1`, “러닝 투어가 열렸어요”, CTA “게임하기”.
- 닫기 또는 게임 진입: 해당 id/version을 이 브라우저에서 확인한 것으로 저장한다. 더보기에서 먼저 들어가도 확인 처리한다.
- 재방문·새로고침: 같은 버전은 다시 보이지 않는다. 더보기 → 미니게임의 상시 진입은 유지한다.
- 홈 배너 → 게임 → 뒤로: 홈으로 돌아온다. 더보기 → 게임 → 뒤로: 더보기로 돌아온다.
- 저장 차단: 현재 페이지 세션 동안만 닫힘을 기억하며 게임 진입은 막지 않는다. 재시작 후에는 다시 보일 수 있다.
- 다른 기기/브라우저의 닫기 상태는 동기화하지 않는다. 개인 기록·계정·게임 메달에 쓰지 않고 원격 이벤트도 보내지 않는다.
- 다음 기능: `ProductAnnouncement`의 슬롯·표시/저장 동작을 재사용한다. 문구, id, version, enabled, 이동 callback을 제공한다. 중요한 새 출시에서만 버전을 올린다. 오탈자 변경으로 버전을 올리지 않는다. 종료는 `enabled:false`로 한다.
- 여러 캠페인을 동시에 쌓지 않는다. 홈에는 운영자가 선택한 하나만 연결한다. 기간별 자동 스케줄·관리 콘솔·노출 통계는 이번 범위에 없다.

구현 진입점: `app/src/domain/product-announcements.ts`, `app/src/components/ProductAnnouncement.tsx`, `Home.tsx`, `home/TrainingHome.tsx`, `AppShell.tsx`.

## 검증 경계

기존 배포본에서 자동 정지 회귀 두 건이 이름으로 실패한 것을 확인했다. 새 회귀는 900ms 지연 후 계속 진행, 과도한 시간 보정 없음, 화면 내 포커스 해제, 실제 숨김 시 정지, 입력 해제와 재개를 확인한다. 출시 안내는 최초 노출, 닫기/열기 후 재노출 억제, 버전 교체, 비활성화, 저장 차단, 다른 탭, 홈/더보기 복귀를 확인한다.

최종 검사 결과와 배포 SHA는 이 문서를 포함한 PR 및 작업 완료 보고에 남긴다. 브라우저 모바일 에뮬레이션을 실제 iPhone/Safari 검증으로 보고하지 않는다. 관련 없는 전체 서비스 테스트나 실제 계정 저장을 확인한 것으로 확대하지 않는다.

로컬 결과: 관련 단위/계약 검사 18/18, PC·모바일 게임 브라우저 검사 26/26, 앱·E2E TypeScript 검사, Vite 빌드 통과. 초기 forks 워커 두 개가 시작 시간 초과하여 동일 범위를 단일 threads 워커로 다시 실행했다. 안내가 항상 보이도록 고의 결함을 넣었을 때 `honors stored acknowledgement after a fresh load and disabled releases`가 이름으로 실패했고 원본을 복구했다. PC 900×900·모바일 360×800 화면에서 배너 위치·줄바꿈·기록 CTA·가로 넘침 없음을 확인했다. 실제 iPhone Safari는 미검증이다.
