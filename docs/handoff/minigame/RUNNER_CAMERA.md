# 러너 추적 카메라와 주행면 가림 개선

2026-10-14 · 기준 main `af61974e` · 담당 Codex.

요청은 러너를 느슨하게 따라가는 능동적인 시점, 빠른 이동감과 장애물 등장, 하단 안내/그래픽 가림과 옆 검은 빈 공간 제거다.

## 구현

- `camera.ts`: 러너를 약 33~48% 위치로 지연 추적한다. 달리기/회복/대시마다 목표 위치가 달라 캐릭터를 화면 한 점에 붙이지 않는다. 뒤쪽 한계에서는 러너가 화면 왼쪽으로 밀리는 것을 볼 수 있다.
- 주행 좌표를 화면 폭 1.4배로 투영하여 장애물이 화면을 더 빠르게 가로지른다. 러너·장애물·점프 가이드는 같은 투영을 사용한다. 엔진의 충돌, 반응 시간, 코스, 에너지, 점수와 저장 형식은 변경하지 않는다.
- 가까운 바닥과 소품은 빠르게, 먼 도시 건물은 느리게 흐른다. 배경 이동 목표 속도는 회복 105 / 달리기 220 / 대시 510 논리 px/s이며 부드럽게 가감속한다. 이 숫자는 가상 게임 연출 값이며 실제 러닝 속도가 아니다.
- 대시 잔상과 발 아래 짧은 속도선을 사용한다. 점프를 따라가는 작은 수직 이동을 추가한다. 낮은 가로 화면은 확대를 줄이고 수직 추적을 늘려 상단 HUD와 점프가 겹치지 않게 한다.
- 캔버스 바닥 위치를 높여 주행 공간을 확보한다. 도시 트랙은 좌우와 화면 아래까지 연결하고 검은 뒤쪽 구멍·받침 그래픽을 제거한다. 연습용 벨트도 양쪽으로 확장한다.
- 경고·웨이브·조작 안내는 모두 HUD로 옮긴다. 실제 장애물 위치에 글상자를 놓지 않는다. 화면 밖에 이미 생성된 장애물도 진입 예고에 포함한다.
- 일시정지 중 추적과 이동 거리를 동결한다. 새 판/구간 전환 시 초기화하며, 움직임 줄이기에서는 카메라 추적·배경 가속·속도선을 끈다.

## 검수

- 카메라 3, 기존 렌더러 2(모든 도시/캐릭터/구간 포함), 제스처 5, 엔진 22, 시각 토큰 계약 해당 1 = 33개 통과.
- 실제 소스에서 지연 추적을 `offset = target`으로 바꾸면 `retains visible runner movement during tracking and projects hazards at the same scale`이 실패한다. 원복 후 재통과. 미세 부동소수점 차이를 화면 이동으로 오인하지 않도록 실제 2px 이상 차이를 요구한다.
- PC/휴대폰 브라우저에서 카메라 지연, 대시 가속, 일시정지 동결, 상단 안내와 점프의 분리, 13초 서울 코스 재생, 제스처, 저장/복구, 움직임 줄이기를 검사한다. 세로와 가로 점프 화면을 이미지로 검수한다.
- 타입 검사, 최종 브라우저 수, 운영 빌드와 공개 배포 SHA/검수 결과는 연결 PR 완료 기록을 따른다. 실물 iPhone Safari 또는 실계정 서버 왕복을 검증한 것으로 설명하지 않는다.

게임 규칙/저장 키/에셋 파일/백엔드/훈련 도메인 변경 없음. 이전 생성 자산을 재사용하며 Tripo 비용은 추가하지 않았다. 검수용 `data-runner-x/y`, `data-camera-offset`, `data-scene-travel`은 실제 렌더 좌표를 읽기 위해 캔버스에 표시하며 게임 로직의 입력이 아니다.
