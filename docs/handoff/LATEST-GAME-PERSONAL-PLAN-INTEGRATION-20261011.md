## 통합 과정에서 고친 실제 결함

1. 계정 동기화가 진행되는 동안 새 도시 기록·메달·설정을 만들면 이전 응답이 작업 사본을 덮어썼다. 응답을 현재 사본에 병합하고, 화면 수명·계정·세션 세대로 늦은 응답과 콜백을 차단했다. 초기화는 이전 동기화가 끝난 뒤 계정 삭제와 기기 초기화 순서로 처리한다.
2. 월 합계만 남기던 메달 압축은 서로 다른 날의 오프라인 기록을 잃었다. 월별 압축에도 날짜별 run/ad 횟수를 남기고, 각 횟수의 최대값을 병합한다. 기존 숫자 월 합계는 같은 월의 보수적 하한으로 읽는다. 복원할 날짜 정보가 없는 과거 합계에서 일별 기록을 추정하지 않는다.
3. 서버의 전체 메달 합계 검사만으로는 같은 총량을 다른 날짜로 옮겨 일일 상한을 초기화할 수 있었다. 기존 일별 횟수·월 하한·보유 항목을 각각 보존하도록 검증했다. 실제 게이트웨이 회귀에서 수정 전 `200`, 수정 후 `422`를 확인했다.
4. 라이선스 생성 스크립트의 shebang이 Vitest의 모듈 가져오기에서 구문 오류를 일으켰다. `node scripts/generate-third-party-notices.mjs` 사용을 유지하면서 모듈 가져오기도 가능하게 했고, 라이선스 문장의 내용은 그대로 두고 줄 끝 공백을 정규화했다.

최신 본체의 리뷰 화면·문구에 맞춰 테스트 진입 경로와 선택자를 조정했다. 저장 전 확인, 메모 복구, 가져온 수치의 읽기 전용·출처 보존, 중단 안내와 뒤로 가기 보호 검사는 유지했다. 대기 중인 history 정리가 끝난 뒤 별도 reader의 POP을 확인하도록 fixture를 갱신했으며, 보호를 제거하는 결함이 해당 부정 검사를 실패시키는 것도 확인했다.

## CI 병목과 최종 커밋 검증

이전 성공 실행 `37736423120`은 UTC/KST 단위 검사를 직렬로 약 40분, 두 일반 브라우저 경로와 네 화면 조건을 직렬로 약 99분 실행했다. 전체 스키마·해시 검사와 브라우저 범위를 그대로 유지하면서 UTC/KST는 두 독립 작업, 일반 브라우저는 네 고정 화면 조건의 독립 작업으로 나눴다. 각 화면 작업은 기존 빌드·fixture 두 경로를 모두 worker 1로 실행한다. 기존 전용 브라우저 10개 명령과 배포 조건·권한·본문은 보존했다. 실제 단축 시간은 최종 hosted 실행에서 확인해야 한다.

`app-quality`는 두 시간대 모두 성공해야 진행하고, 기존 `app-browser`는 네 일반 화면 작업과 전용 브라우저 작업이 모두 성공해야 통과한다. 실패·취소·건너뜀·빈 결과·누락 결과를 실제 Bash 실행으로 거부하는 검사를 추가했다. 프로젝트 runner는 알려진 화면 조건 하나만 받고 파일·grep·경로 축소 인수를 허용하지 않으며, 전체 runner의 기존 8개 조합도 유지한다.

`11b2ffd1`의 hosted contract 검사는 통과했지만, 로컬에서 최신 화면 fixture의 추가 실패를 재현한 뒤 해당 전체 실행 `38124433639`를 취소했다. 그 실행은 전체 CI 성공 증거가 아니다. 수정과 병렬화를 포함한 최종 PR 커밋에서 전체 gate를 새로 실행하고 그 결과로 병합 여부를 판단한다.
