# 친구들의 밤: 구현과 인수인계

## 이번에 연결한 흐름

일지를 저장한 날에는 **잠자리 준비하기**와 **친구 방 보기** 중에서 고른다. 과거 날짜의 일지는 방 방문만 안내한다. 준비 화면에서 물건과 자리를 고르고, 실제 방에 보이는 친구 세 명과 잠자리를 준비한다. 불을 끄면 그날 결과가 저장된다. 다음 날 돌아오면 아침 그림을 보고, 마음에 드는 모습만 사진첩에 담는다. 그림이 있는 사진 12종은 같은 그림의 일지 스티커로도 획득한다.

아침의 **나도 일어났어 → 어떻게 잤는지 적기**는 그 아침 날짜의 일지로 이동한다. 수면 질을 직접 적었을 때만 그 값에 맞는 인사를 한다. 수면 시간만 입력했거나 입력하지 않았다면 좋고 나쁨을 추측하지 않는다. 원래 일지를 작성 중이라면 두 번째 편집기를 열지 않고 원래 입력으로 돌려보낸다. 같은 날짜에 일지가 여러 개 있으면 직접 선택하게 한다.

## 사용할 수 있는 내용

- 기존 48종의 방문·돌봄·입양·이야기·꾸미기를 유지한다.
- 물건은 작은 공, 종이 상자, 낮은 쿠션, 작은 인형, 큰 이불, 작은 천막 6종이다.
- 처음에는 자리 2개와 물건 3개를 쓴다. 함께 자기 3일에 인형, 7일에 큰 이불과 세 번째 자리, 14일에 천막이 열린다. 연속일을 요구하지 않는다.
- 한 번 놓은 배치를 기억한다. 다음 밤에는 **그대로 재우기**로 바로 이어갈 수 있다.
- 동물마다 물건과 자리 선호가 다르다. 놓은 물건을 쓰지 않는 결과도 있다. 사진첩의 **누가 뭘 썼을까?**에서 실제로 놓은 밤과 사용한 밤을 비교한다. 한 번 쓰지 않은 물건을 싫어한다고 단정하지 않는다.
- 첫 밤에는 선택한 친구의 평범한 상호작용 하나를 보장한다. 특별한 사진은 보장하지 않는다.
- 잠자는 방은 기존의 웅크린 2D 잠자는 그림을 사용한다. 약한 호흡 모션은 동작 줄이기 설정에서 꺼진다.
- 잘 못 잤다고 기록한 날에도 보상을 깎지 않는다. **같이 쉬기**는 타이머나 점수 없이 이용할 수 있다.

## 결과와 저장 규칙

- 결과는 불을 끌 때 한 번 정하고, 다음 날 공개한다. 새로고침·배치 변경·다시 쉬기로 뽑기를 반복하지 않는다.
- 기상 날짜당 한 번만 새 밤을 만든다. 밤을 건너뛴 만큼 결과를 자동 생성하지 않는다.
- 준비 화면의 기상 날짜는 오늘 또는 내일이다. 먼 미래 날짜를 잘못 골라 방이 오래 잠기는 것을 막는다.
- 실제 그 방에 있던 친구만 결과에 등장한다. 함께 쓰는 그림에는 두 친구가 모두 있어야 한다.
- 기본 사용 확률 65/35/10%, 좋아하는 자리 가산 10%p(최대80%)는 현재 게임 조정값이다. 사용자 조사로 검증된 최적값이라는 뜻이 아니다.
- 희귀 장면은 같은 물건을 서로 다른 두 밤에 쓴 뒤부터 조건부5%로 추첨한다. 실패 횟수에 따른 희귀 장면 보장은 없다.
- 수면 시간·수면 질·휴대전화 사용 여부는 등장 확률과 보상을 바꾸지 않는다. 기기 밖 사용이나 실제 수면을 측정하지 않는다.
- 기존 v2 펫 저장에 선택적인 observation 기본값을 추가했다. 기존 기록은 유지한다. 오래된 수면 기록에는 없는 결과를 만들어 붙이지 않는다.
- 사진은 사용자가 눌렀을 때만 저장한다. 실제 관찰하고 저장한 전용 그림만 스티커로 지급한다. 중복 지급하지 않으며, 다른 계정이나 오래된 저장 세대의 기록을 읽지 않는다.
- 펫 방의 진행은 기존처럼 이 브라우저에 저장한다. 이번 작업으로 기기 간 펫 동기화를 제공하지 않는다.

## 그림

실제 런타임 에셋은 `app/public/games/pet-room-v1/observations/`에 있다. 장면12종과 소품3종, 합계416,326bytes다.

장면은 공을 안은 수달, 수달과 물범의 공, 상자에 든 고양이, 상자에서 나온 발, 쿠션 위 물범, 납작하게 누운 물범, 꼬리를 덮은 레서판다, 천막 속 레서판다, 이불 속 토끼, 토끼와 고슴도치, 인형과 강아지, 인형을 껴안은 강아지다.

전용 그림이 없는 조합은 그 동물의 기존 그림과 실제 물건으로 표현한다. 전용 스티커가 있다고 안내하지 않는다.

- 원본·프롬프트·해시·레이어 계약: `docs/art/pet-observations/`
- 날짜/장면 ID/등장 동물 목록: `scene-manifest.json`
- 스티커와 출처: `app/public/collections/pet-observations-v1/`
- 제작한 원본을 사용하며 Neko Atsume 또는 Pokémon의 캐릭터·화면 이미지를 복사하지 않는다.

## 검증 범위

집중 단위 검사는 결과 고정, 실제 등장 친구, 날짜 중복, 예전 저장, 저장 실패, 계정 격리, 사진→스티커, 일지 선택/삭제/초안 복귀를 확인했다.

로컬 브라우저에서 합성 게스트 기록으로 다음을 직접 실행했다.

1. 375px: 아침 장면 → 사진 저장 → 새로고침 → 같은 결과와 사진 복원 → 사진첩.
2. 같은 아침 날짜의 일지에 수면5시간·수면 질 나쁨 입력 → 저장 → 해당 인사로 복귀. 이는 테스트 입력일 뿐 권장 수면 시간이 아니다.
3. 320px·동작 줄이기: 준비 화면 스크롤 → 재우기 → 자는 방. 문서와 준비 패널의 가로 넘침 없음.

재현: 로컬 Vite를4232포트에서 실행한 뒤 `node app/e2e/run-pet-observation-review.mjs`. URL은 `PET_PREVIEW_URL`로 바꿀 수 있다. 검수 화면은 `app/e2e/pet-observation-preview.html`이며 프로덕션 진입점에서 불러오지 않는다. 결과와 화면은 `reports/qa/pet-observation-20261026/`에 있다.

실제 사용자 만족도, 실제 휴대전화 수면 계측, 운영 계정 저장 왕복을 이 결과로 주장하지 않는다.

## 배포 시 구분

프런트엔드와 새 에셋 외에 계정 저장 검증기의 새 스티커 ID도 생성했다. `supabase/functions/_shared/account-state-validator.mjs`는 기존 생성 도구로 만든 파일이다. 데이터베이스 마이그레이션은 없다. 운영 계정에서 새 스티커를 저장할 수 있다고 발표하기 전에 계정 저장 함수의 해당 검증기 배포도 확인해야 한다.

코드 반영, 빌드, CI, Pages 공개, 운영 계정 저장 확인은 별도 단계로 기록한다. 이 문서나 로컬 브라우저 결과만으로 운영 배포가 끝났다고 표시하지 않는다.

## 추가 검수 중 발생한 로컬 실행 지연

- 구현 파일과 원본 에셋 작성은 끝났다. 마지막 변경은 기상 날짜를 오늘·내일로 제한하는 UI와 그 회귀 검사다. 해당 검사1개는 통과했다.
- 그 직전 상태에서 프로덕션 TypeScript 검사와 Vite 빌드가 성공했다. 아침/사진/일지 왕복의 로컬 브라우저 검사도 성공했다.
- 마지막 날짜 제한을 포함한 추가 타입 검사와 재빌드는 로컬 명령 지연으로 종료를 확인하지 못했다. 재시도한 Git 상태 조회도20초 제한에서 ETIMEDOUT이 발생했다. 이를 코드 오류 또는 최종 빌드 성공으로 기록하지 않는다.
- 멈춘 재빌드와 fetch/stage 묶음, 마지막 순차 타입 검사 세션98214는 취소되어 종료코드1을 확인했다.
- 이후 전체 파일 조회 대신 Git 참조와 커밋 차이만 읽는 방법으로 저장소 접근을 회복했다. 새 origin/main 60620af6의 훈련 설명 변경을 확인했다. 해당 변경과 이번 펫 기능은 함께 보존한다.
- 이 기록은 코드 반영 전 검수 이력이다. 최종 커밋과 CI 상태는 Git에서 확인한다. 마지막 날짜 제한을 포함한 최종 통합 타입 검사/빌드와 운영 공개 여부를 이전 빌드 성공과 구분한다.
- c86ff9ff까지 통합한 뒤 마지막 날짜 제한을 포함한 TypeScript 검사가 통과했다. 계정 저장 검증기 최신 여부도 다시 통과했다(check:true, 1,467,784bytes). 중복된 로컬 재빌드는 더 실행하지 않고 최종 커밋의 CI 결과와 운영 공개를 따로 확인한다.
