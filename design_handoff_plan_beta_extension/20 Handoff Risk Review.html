CRITICAL 전체 ✓ RESOLVED

AppShell 라우팅 구조를 완전히 무시함

실제 앱 AppShell.tsx는 단일 SPA. URL 아닌 useState 기반 뷰 전환. 5개 tab (home · journal · plan · log · trends) + utility 뷰 (more · guide · minji · content) 조합. DeferredMobileScreens로 lazy loading.

내 시안은 독립 화면인 것처럼 그려짐. Session Prep을 어느 tab 아래 두는지, Weekly Wrap은 tab === "journal"인지 "trends"인지, Coach Dashboard는 새 tab을 추가해야 하는지 명시 없음.

개발자가 "어디에 넣지?"에서 막힘.
각 시안에 AppShell integration 섹션 추가 필요:
1) 어느 tab에 속하는지 (tab: "plan" or 신규 tab)
2) DeferredMobileScreens에 어떻게 등록
3) viewForTab() · viewFor*Draft() 확장 필요 여부
4) screenKey 조합에 추가할 상태 키
5) URL query param 지원 (딥링크 필요 여부) 영향: 개발자 2-3일 blocked · 잘못 구현 시 기존 화면 라우팅 깨짐

HIGH 18 Wrap

Weekly Wrap · "자동 생성" 트리거의 실제 구현 어렵다

"매주 일요일 22:00 자동 생성" — 이 트리거를 어떻게 구현?

문제:
1) 브라우저는 백그라운드 실행 안 됨. 사용자가 앱을 안 열면 트리거 안 됨.
2) Service Worker + Push Notification로 알림 보내려면 서버 필요. 지금 앱은 로컬 우선 (loadEntries()는 localStorage).
3) 자동 생성 결과를 어디 저장? localStorage에 weekly-wrap-2026-W36? Supabase 테이블 추가?
4) 사용자가 일요일 밤에 앱 열면 그때 생성? 그럼 "22:00 자동"이 아님.

시안은 이 기술 부채를 안 다룸.
현실적 재정의:
· "매주 일요일 이후 처음 앱 열 때 lazy 생성" — 백그라운드 아님
· 클라이언트 계산 (weekly-wrap-generator.ts) — localStorage에 캐시
· 계정 사용자만 Supabase 저장 · 게스트는 localStorage
· UI: "이번 주 요약이 준비됐어요" 배너 홈 상단 (일요일 이후)
· Push 알림은 다음 단계로 분리 (PWA + Service Worker 별도 스프린트) 영향: 시안대로 구현 시 PWA 인프라 3주+ 지연
