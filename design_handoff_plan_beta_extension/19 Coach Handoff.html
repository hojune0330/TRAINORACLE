Coach Handoff · 실사용 가이드

실제 앱 조사 — CoachSupportPanel.tsx 3.5KB는 초대 코드 발급·수락만. 코치가 실제로 여러 선수를 관리하는 대시보드가 없음. 백엔드는 support_invitations 테이블 + list_shared_journal_entries() RPC 완비. 프론트엔드만 만들면 됨.

진입 경로 · 양방향

선수 관점: Account 화면 → 코치 초대 → 코드 발급 (기존 CoachSupportPanel 그대로)
코치 관점: Account 화면 → 코치 모드 진입 → 이 대시보드 (신규)

코치 모드 활성화 조건: support_connections 테이블에서 자신이 supporter로 1명 이상 연결된 경우. 기존 계정 시스템으로 자동 감지.

앱 백엔드 · 이미 준비됨

list_shared_journal_entries() RPC
코치가 볼 수 있는 선수 일지 조회. shared_fields 필터링 (TRAINING_RECORD, TRAINING_NOTE, PAIN, MOOD, BODY_STATE). 개인 메모 자동 제외. supabase/migrations/0013_shared_journal_projection.sql
support_connections 테이블
athlete_id · supporter_id · shared_fields · season_ends_on · revoked_at. 시즌 자동 만료 · 폐지 가능.
R-4 · R-7 판정 엔진
impl/src/plan-generator/ 규칙 엔진 재사용. 각 선수 최근 데이터에 판정 실행 → Priority Signal 생성.
Coach Note 저장소
신규 필요. coach_notes 테이블 (athlete_id · supporter_id · target_date · text · created_at). 선수 앱 LogDetail에 표시.

핵심 개선점

  • 자격 미확인 배너 — 페이지 헤더에 항상 표시. TrainOracle이 코치 자격 검증 안 함을 명시. 개인 메모는 안 보임.
  • Priority Signal Strip — 즉각 개입 필요 신호 상단 가로 스크롤. R-4 통증 / R-7 위반 / 감정 저하 3종.
  • Athlete Grid — 카드 1장에 Mode 배지 · PB · Cycle 진행 바 · 오늘 신호 · 통증 5도트. 한눈에 6명 상태.
  • Cycle 진행 바 — 10칸. 완료/오늘/미완료/미래 상태. 미완료가 있으면 주황.
  • 선수 상세 — sticky right panel. 지난 7일 세션 (에너지 색 stripe) · 현재 신호 상세 · 코치 노트 이력 · 새 노트 컴포저.
  • Plan Override — 코치가 강도 -10% 제안 원 탭. 선수 앱에서 승인/거부 필요. 강제 아님.
  • Coach Note Composer — 특정 날짜에 노트 남김. 선수가 앱에서 그날 LogDetail 볼 때 표시.
  • 팀 메시지 — 전체 선수에게 브로드캐스트. 대회 공지 · 훈련 안내.

권한 · 보안

  • 본인 메모 절대 안 보임 — memoPurpose !== 'ANALYZABLE_TRAINING_NOTE'는 RPC에서 필터링
  • 시즌 종료일 지나면 자동으로 접근 차단 (season_ends_on >= current_date)
  • 선수가 언제든 연결 해제 가능. revoked_at 설정 시 즉시 RLS 차단.
  • 코치 노트는 선수에게만 표시. 코치 본인은 남긴 이력으로만 확인.
  • 코치가 여러 명 있어도 서로 다른 코치의 노트는 못 봄.

AppShell 통합 · 라우팅

실제 앱은 useState 기반 SPA — 5탭 (홈·일지·계획·분석·더보기). 코치 대시보드는 Bottom tab bar에 6번째 탭 추가하지 않음. Bottom tab이 6개 되면 iOS Human Interface Guideline 위반 + 홈/일지 등 선수용 기능과 코치용 기능이 섞임.

Option A · 권장 · 더보기 서브뷰: 기존 tab='account' ("더보기" 탭) 내부에 "코치 모드" 항목 추가. 클릭 시 viewForAccount: {mode:'coach-dashboard'}.
이 방식은 코치가 먼저 자신의 계정 컨텍스트로 들어간 뒤 코치 대시보드로 진입 → 선수 앱과 코치 앱의 개념적 분리 유지.

Option B · 대체 · 프로필 스위처: 계정에 코치 모드 활성화되면 홈 상단에 "선수 앱 ↔ 코치 앱" 토글. 전체 앱 컨텍스트를 appMode: 'athlete'|'coach'로 스위칭. Coach 모드에서는 5탭이 대시보드·선수·메시지·분석·더보기로 바뀜.
단점: 구현 복잡 · 초기 릴리즈 부담. B는 Phase 2로.

결정: A. Phase 1 완성 이후 사용량 데이터로 B 판단.

선수 앱 반대편 UI: 코치 노트가 남으면 선수 앱 LogDetail 상단에 회색 배너 자동 표시. "코치가 오늘 노트를 남겼어요" · 배너 접기 가능. Plan Override 승인 요청은 LogDetail 상단에 주황 배너로 별도. 승인/거부/보류 3버튼.

DB 스키마 · coach_notes · plan_override_requests

파일: supabase/migrations/0020_coach_notes.sql · 0021_plan_override.sql 

CREATE TABLE coach_notes (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  athlete_id   UUID NOT NULL REFERENCES auth.users(id),
  supporter_id UUID NOT NULL REFERENCES auth.users(id),
  target_date  DATE NOT NULL,
  text         TEXT NOT NULL CHECK (char_length(text) <= 500),
  created_at   TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at   TIMESTAMPTZ,
  deleted_at   TIMESTAMPTZ,  -- soft delete
  seen_at      TIMESTAMPTZ,  -- 선수가 읽은 시각
  CONSTRAINT valid_connection
    FOREIGN KEY (athlete_id, supporter_id)
    REFERENCES support_connections (athlete_id, supporter_id)
);

-- RLS: 코치는 자신이 쓴 것만 · 선수는 자기 앞 노트만 (deleted_at IS NULL)
-- 코치가 삭제 요청 시 soft delete · 선수는 즉시 안 보임

CREATE TABLE plan_override_requests (
  id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  session_id     UUID NOT NULL,
  athlete_id     UUID NOT NULL,
  supporter_id   UUID NOT NULL,
  proposed_delta JSONB NOT NULL,  -- {"targetRepSeconds": -20} 등
  status         TEXT NOT NULL DEFAULT 'pending'
                 CHECK (status IN ('pending','approved','rejected','expired')),
  created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
  responded_at   TIMESTAMPTZ,
  expires_at     TIMESTAMPTZ NOT NULL  -- 세션 시각 + 30분
);
편집 정책: 코치는 자신이 남긴 노트를 30분 이내에만 편집/삭제 가능. 이후는 삭제 요청만 (soft delete). 선수는 본 이후 전에만 노트가 사라짐 (seen_at 확인).

Plan Override 만료: 세션 시각 + 30분 지나면 자동 expired. 크론 아닌 read time에 확인.
