## 1. 승인 범위

2026-10-01 오너 요청: 사주·토정비결처럼 자기 또는 친구의 최고기록만 넣어
흥미롭게 읽고 비교하는 오라클을 만든다. 이야기형 구성은 허용하지만 성격,
재능, 생리학적 능력, 미래 성과, 궁합 점수를 근거 없이 만들어내지 않는다.
이는 기존 개인 오라클·공개 친구 비교와 별도의 **일시적 직접 입력 풀이**다.
기존 문서 전체의 정본 승격이나 미수용 수식 채택이 아니다.

## 2. 입력·보관

- 800m, 1500m, 3000m, 5000m, 10km, 하프, 마라톤 중 종목과 실제 최고기록.
- 시:분:초 또는 분:초 표기, 소수 초 지원. 0·음수·비유한·잘못된 시간 형식 거부.
- 달성일은 선택. 없으면 날짜 미입력으로 표시하고 오늘 기록으로 간주하지 않는다.
- 친구 기록은 비교 동의를 사용자가 확인해야 결과 생성 가능. 공개 프로필이나
  친구 계정을 조회하지 않는다. 이 확인은 서버 공유 동의를 대신하지 않는다.
- 입력은 React 메모리에만 보관. 저장소, URL, 브라우저 history, 로그, 분석 이벤트,
  서버, 외부 AI로 기록 숫자를 전송하지 않는다. history에는 화면 단계만 넣는다.
- 풀이 종료·새로고침·계정 변경으로 입력이 초기화된다. 기존 경기 기록·계획·일지에
  자동 저장하거나 처방 기준으로 승격하지 않는다. 해당 특성을 화면에서 알린다.

## 3. 계산과 설명

- 평균 1km 시간 = 기록 초 × 1000 / 경기 거리.
- 같은 속도로 나눈 400m 시간 = 기록 초 × 400 / 경기 거리. 실제 랩 기록이나
  인터벌 목표가 아니다. 초는 내부 원값 보존, 표시에만 소수 둘째 자리 반올림.
- 400m 거리 환산은 거리 / 400. 실제 경기장이 트랙이었다고 추정하지 않는다.
- 같은 종목의 기록만 시간 차이와 평균 페이스 차이를 비교한다. 서로 다른
  종목의 평균 페이스를 우열·궁합이나 예상 기록으로 환산하지 않는다.
- 비교 비율을 표시할 경우 |기록 A - 기록 B| / max(A,B) × 100으로 정의한다.
  궁합 확률·현재 능력·훈련 강도 차이로 표시하지 않는다. V1은 초 차이를 우선한다.
- 달성일을 입력해도 현재 체력을 보증하지 않는다. 시기·코스·날씨·노력 차이가
  확인되지 않았음을 알리고, 능력 부족·젖산 역치·VO2max·부상 위험을 추론하지 않는다.
- 결과는 직접 입력한 기록과 단순 산술에 따른 고정 설명이다. 실시간 LLM 호출 없음.

## 4. 러닝 궁합

궁합은 함께 달리는 **방식**을 찾는 이야기형 이름이다. 점수나 승패가 아니다.
기존 FRIEND_COMPARISON_AND_TOGETHER_RUNNING_ORACLE_SPEC §5의 범위대로
함께 준비·정리하기, 본운동은 각자 기준, 회복 중 다시 만나기를 안내한다.
한 사람의 최고기록 페이스를 다른 사람에게 처방하지 않는다. 다른 종목이어도
두 기록은 나란히 읽을 수 있지만 정량 차이 판정은 하지 않는다.

## 5. UX

- 내 기록 / 친구 기록을 첫 화면에서 선택할 수 있다. 기본은 내 기록이며,
  친구만 단독으로 풀어볼 때도 동의를 확인한다. 상대 기록은 필요할 때 추가한다.
- 종목 한 번 선택 → 기록 입력 → 풀이. 입력 순서가 친구부터여도 비교 화면은
  나 / 친구의 소유 관계를 뒤집지 않는다.
- 첫 결과는 최고기록과 대표 숫자, 짧은 해석. 이어지는 해석은 탭 또는 다음 장.
- 데이터 비례 그림과 수치·단위·텍스트를 함께 제공한다. 가짜 능력치 레이더 금지.
- 실제 최고기록, 같은 속도로 나눈 수치, 훈련 처방을 명확히 구분한다.
- 브라우저 뒤로가기와 화면 뒤로가기는 직전 단계로 돌아가며 입력을 보존한다.
- 예시 데이터 자동 주입·자동 공유·일지 작성 요구·기록 입력 보상 없음.
- 기존 색·폰트·44px 터치 영역, 320px 및 글자 확대, 모션 감소 동등 기능 유지.

## 6. 검증

소수 초·시간 경계·0·오류 형식, 서로 다른 종목, 동의 미확인, 날짜 오류,
입력 변경 후 재계산, 반복 실행의 결정성, 저장소·history 원문 유출 없음,
모바일 결과·친구 비교·이전 단계 복귀를 검증한다. 검증 결과는 구현 보고서에
분리하며 문서 작성으로 완료를 주장하지 않는다.
