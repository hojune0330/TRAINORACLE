# 오라클 V2 구현 계약

```yaml
version: 2.1
status: OWNER_APPROVED_IMPLEMENTATION_SCOPE
approval: 2026-10-04 사용자 Implement the proposed plan
public_activation: false
production_verification: NOT_PERFORMED
```

## 1. 범위와 선행 계약

승인된 56개 전체 범위를 유지한다. 기존 제작 연결표의 W0~W6가 작업 번호 정본이다.
이 계약은 RUNNING_PROFILE_CONTRACT의 V1 설명을 삭제하지 않고 V2에만 적용한다.
PRODUCT_NORTH_STAR의 보관·안전·권한 경계는 유지한다.

- W0 정합성·계약: 문항, 계산, 저장, 삭제, 공유, 56개 완료 조건.
- W1 근거·원고: 모든 주제의 충분/부분/없음/변경/철회 원고와 근거.
- W2 문항·점수: 자체 응답 지수 및 캐릭터. V1 응답을 점수로 변환하지 않는다.
- W3 기록 계산: 기존 M01~M20의 적격 입력·단위·분모·과거 스냅샷 연결.
- W4 계정·공유: 기존 암호화 저장과 충돌 처리 확장, 구버전 보호·철회.
- W5 UX·자산: 짧은 질문, 결과·세부 읽기·비교·보관함, 독창적 캐릭터.
- W6 통합 검수·공개: 두 비공개 전체 여정 검수 뒤 모든 범위가 준비되면 공개.

## 2. 자체 응답 지수

문항 원본은 app/src/domain/oracle-profile-v2.ts의 ORACLE_AXES다. 이는 자체 한국어
문항이며 PRETIE-Q/MOMS의 공인 번역·축약판·검증 척도가 아니다. 출시 전 사람의
문항 이해도 점검은 별도이며, 코드 테스트가 타당성을 입증하지 않는다.

축은 CHALLENGE(기록 도전 선호), INTENSITY(높은 강도 선호), STRUCTURE(계획 선호),
SOCIAL(함께 달리기 선호), EXPLORE(새 경험 선호), REFRESH(기분 전환 동기)와
선택 SU(보조 운동 선호), WE(웨이트 선호)다. 축마다 같은 개념의 긍정형 문항 3개를 쓴다.
행동 빈도·능력·학습 의향·훈련 가능 여건은 점수 입력이 아니다.

답은 1~5 또는 UNKNOWN/VARIES/INEXPERIENCED/SKIPPED다. 미응답은 필드 부재다.
3개 숫자가 모두 있을 때만 raw=100*(sum-3)/12, display=5*floor(raw/5+0.5).
부분 응답, 오류, 삭제, 미수신은 0이 아니다. 배열·문자 숫자·추가 필드는 거절한다.
낮은 동의(1,2)와 높은 동의(4,5)가 함께 있으면 mixed=true와 해당 문항 근거를 남긴다.
이 mixed는 제품의 설명 규칙이지 심리학적 기준이 아니다.

결과는 문항·계산 버전과 원본 응답을 포함한다. 0~100은 자신의 답을 정리한 지수이며
인구 백분위, 체력, 고통 인내, 진단, 에너지 시스템 능력 또는 신뢰 확률이 아니다.

## 3. 캐릭터

핵심 6축 중 display>=75이고 mixed=false인 축만 후보가 된다. SU/WE는 캐릭터를
정하지 않는다. threshold는 제품 표시 규칙이다. 후보 순서는 고정 목록 순서이며
서열이 아니다. 여러 후보는 사용자가 대표를 선택한다. 유효한 기존 선택은 유지하고,
부적격해지면 새 인물을 몰래 선택하지 않는다. 후보가 없거나 여러 후보인데 선택 전이면
중립형을 대표로 둔다. 응답한 축 이름과 범위를 결과에 보존한다.
인터벌·대회 취향·통증 인내·선천적 재능은 이 지수로 추론하지 않는다.

## 4. 호환·삭제·공유

V2 코어 도입만으로 현재 V1 서버 스키마를 변경하거나 활성화하지 않는다. 서버 읽기
호환과 구버전 명시적 거절이 먼저이며 V1 오프라인 초안은 삭제하지 않는다. 서버 버전
확인 전 성공 안내 금지. 롤백은 노출/쓰기 중지이며 V2 읽기 기능과 원자료는 유지한다.
로그인 초안은 기존 암호화 경로를 사용하고 게스트 자료는 계정에 자동 귀속하지 않는다.

응답 수정은 새 결과 버전을 만든다. 당시 풀이와 현재 풀이를 구분한다. 삭제 요청은
현재 응답뿐 아니라 관련 파생물과 공유를 즉시 비활성화한다. 과거 수정본은 상위 정책의
보관 기한을 따르며 보관 중인 자료를 다시 개인화나 공유에 사용하지 않는다.
친구 비교 동의와 외부 공유 동의를 분리하고 조회/계산/공유 때 철회를 재확인한다.
이미 다운로드된 이미지를 회수한다고 약속하지 않는다. 원문 메모는 계산 입력 금지.

## 5. 공개 조건

56개 항목마다 개인/비교/교육, 입력 적격성, 5개 자료 상태, 버전 근거, 다음 행동,
실제 완료 증거를 남긴다. 정적 카탈로그나 교육 문장만으로 개인 풀이 완료 금지.
첫 비공개 경로: 응답→점수→캐릭터→계정 저장→재접속→수정.
두 번째 비공개 경로: 기록→풀이→친구 비교→공유→철회.
두 흐름 이후 병렬 확대하되 전체 완성 전에 새 기능을 공개하지 않는다.
30개 합성 페르소나는 실제 사용자 연구가 아니다. 320/375px, 200% 확대, 키보드,
화면낭독기, 줄인 모션, 저장 충돌·구버전·철회 결함 주입을 검수한다.

## 6. 통합 구현 세칙

### 6.1 공개 진입 게이트 (2026-10-05 구현 범위)

- `VITE_FEATURE_ORACLE_V2=true`이며 `VITE_KILL_ORACLE_V2`가 `true`가 아닐 때만
  기존 프로필 진입과 `?oracleV2=1` 직접 진입이 V2를 연다. 개발 모드·쿼리·초대만으로
  게이트를 우회하지 않는다. OFF/차단 상태의 기존 프로필 진입은 V1을 유지한다.
- 같은 게이트에서 유효한 `#oracle-compare-invite`는 V2 초대 화면으로 연결한다.
  계정 기능이 켜진 비로그인 사용자는 기존 계정 화면을 거치며, 현재 인증 확인 전
  기기에 남아 있는 계정 ID를 로그인 완료로 취급하지 않는다.
- 로그인 복귀 중에는 검증된 초대 코드 하나만 동일 탭의 `sessionStorage`에 임시 보존한다.
  기존 `account=1` 복귀에서만 재개하고, V2 전달·로그인 취소·기능 OFF 시 지운다.
  원문 해시/OAuth 토큰/응답/동의는 보관하지 않고 코드의 쿼리·history state·localStorage
  복사는 금지한다. 저장소가 막혀 있으면 영구 저장이나 URL 쿼리로 우회하지 않는다.
- 초대 진입·로그인 복귀는 초대 수락, 비교 동의, 외부 공유 동의가 아니다.
  해당 작업은 기존 V2의 명시적 사용자 행동과 서버 권한 확인을 그대로 따른다.
- 이 변경은 공개 가능한 진입 코드의 구현이며 실제 플래그 활성화·운영 배포가 아니다.
  §5의 전체 출시 조건 및 서버 비교 제어는 별도로 유지한다.

### 6.2 자료·화면 통합

- 작성 중 `EDITING` 초안은 자동 전송하지 않는다. 3문항을 마치거나 추가 여건의 반영을
  선택했을 때만 제출한다. 원격 충돌 해결은 초안과 화면을 함께 새 기준으로 맞춘다.
- 점수 초안과 추가 여건은 서로 다른 확정 작업이다. 추가 여건 저장이 미완성 점수를
  확정하지 못하며, 계정 풀이에는 서버가 확인한 응답만 사용한다.
- 첫 조회 중·실패·삭제는 빈 응답과 다르다. 각각 미확인·철회로 표시하고, 자료를
  확인한 뒤 실제로 항목이 없는 경우만 없음으로 표시한다.
- 월간 거리는 달력 월 범위, 주기 회고는 실제 계획의 세션 날짜 범위를 사용한다.
  주기 자료가 없으면 임의의 최근 56일을 현재 주기라고 대체하지 않는다.
- 파일 구간은 현재 계정의 확인된 목록에서 충돌을 제외한 관찰 자료만 사용한다.
  파일의 날짜가 경기 날짜와 같다는 이유로 같은 경기로 연결하지 않는다.
- 훈련법 풀이에는 사용자가 선택한 실제 세션의 검증된 카탈로그 바인딩을 전달한다.
  자료의 수정번호·계정·확인 상태가 달라지면 이전 선택을 무효화한다.
- 풀이의 출처·원자료 식별·버전·빠진 입력은 상세 영역에 보존한다. 기본 화면을 줄이기
  위해 근거 정보를 없애지 않는다. 메모 원문은 근거 영역에도 포함하지 않는다.
- 일지·달력·계획·훈련법·경기 기록·학습 자료는 원래 풀이 위의 Reader로 연결해
  닫기·뒤로가기 후 읽던 풀이가 유지되게 한다. 조회가 자동 저장/교정 적용이 되어서는 안 된다.
- 친구 초대는 인증된 한 수신자에 연결하되 초대 수락을 비교 동의로 간주하지 않는다.
  양측의 필드별 비교 동의와 별도 외부 공유 동의를 확인하고, 조회 시 문서 버전과
  만료·철회를 재검사한다. 수동 입력 체험은 이 서버 권한 경로의 대체 수단이 아니다.
- 장비 없음과 보유 장비의 동시 선택, 중복 대회·경기 조건·동일 시간대는 저장 전에
  거절한다. 모르는 비용·시간과 명시적인 0은 구별한다.

### 6.3 현재 로그인 보안의 계승

- 비교 초대·동의·조회·공유는 현재 지원되는 로그인 방식과 활성 서버 채널을 검사한다.
  세션 ID가 있다는 이유만으로 비밀번호·AMR 누락·갱신 단독 인증을 허용하지 않는다.
- 비교 상대 계정에 비밀번호가 추가되거나 세션이 제거·만료되면 이전 동의로 조회하지 않는다.
- 초대와 비교 동의에 당시 서버가 확인한 인증 채널을 연결한다. 비교 상대의 채널이 닫히면
  요청자가 다른 활성 채널로 로그인했더라도 그 상대의 이전 동의로 자료를 조회하지 않는다.
- 이미 인증된 소유자의 비교·외부 공유 철회는 기능 또는 로그인 채널이 닫혀도 유지한다.
  이는 새 동의·조회·공유 허용이 아니라 기존 권한을 줄이는 별도 경로다.
- DB 검수는 최신 인증 마이그레이션을 제외한 축약 환경이 아니라 실제 통합 체인에서 한다.
  로컬 전체 체인 검수는 운영에서 보류된 마이그레이션의 활성화 승인이 아니다.

운영 순서와 철회 기능을 보존하는 롤백은
[비교 운영 문서](../../reports/plans/ORACLE_V2_COMPARISON_OPERATIONS_2026-10-04.md)를 따른다.
본 세칙 추가는 운영 배포 완료나 과학적 타당성 입증을 의미하지 않는다.
