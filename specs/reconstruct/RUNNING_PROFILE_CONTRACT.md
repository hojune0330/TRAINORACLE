## 1. 목적과 지위

재미있게 자신을 알아보는 오라클을 만든다. MBTI 검사를 복제하거나 자체 질문을
검증된 심리척도로 표시하지 않는다. 능력·선호·행동·반응은 구분해서 설명하되
통계적으로 독립이라고 가정하지 않는다. 기존 기록 풀이·개인 오라클을 대체하지 않는다.
이 계약은 해당 화면의 추가 범위만 채택하며 기존 초안 전체를 정본으로 승격하지 않는다.

## 2. V1 구현 범위

| 영역 | 구현 | 허용하지 않는 해석 |
|---|---|---|
| 좋아하는 방식 | 직접 고른 동기·강도·동행·진행 방식·대회·종목·보조운동·웨이트·제약 | 성격 검사 점수, 통증 인내 점수, 생리학적 능력 |
| 경기 기록 | 기존 오라클의 실제 경기 기록 비교 | CS·ASR·재능·순위의 임의 계산 |
| 최근 훈련 | 기존 출처 관문의 훈련 목적별 횟수 | 에너지 공급 비율, 능력 부족, 적정 비율 |
| 관찰된 변화 | 기존 월별 RPE 중앙값 및 출처·기간 | 회복 완료·저반응자·훈련 효과·원인 확정 |

월별 RPE가 없을 때 거리 자료를 반응으로 대체하지 않는다. 실패·로딩·미수신은
빈 기록과 다르게 표시한다. 미응답·아직 모름·기록 없음은 점수 0이 아니다.
처방 엔진·안전 판단·훈련량·강도·빈도·포인트는 변경하지 않는다.
기본 보기와 선수 보기는 수행 정보를 차별하지 않으며 이번 프로필은 양쪽에 같다.

## 3. 질문과 표현

처음에는 동기(복수)·강도 선호(단일)·동행 선호(단일) 세 질문만 제시한다.
단일 선택은 다음으로 전환하고 복수 선택은 다음 버튼으로 확인한다. 필수 답변은 없다.
더 알아보기에서 진행 방식·대회 목표·선호 종목·보조운동·웨이트·실제 제약을 묻는다.
아직 모름과 건너뛰기를 구분한다. 모름은 다른 응답과 동시에 저장하지 않는다.
선택지는 독립된 개념으로 작성하고 강한 운동·무거운 중량·통증 무시를 보상하지 않는다.
V1 결과 이름은 선택한 응답의 짧은 조합이다. V1은 확률·백분위·검사 점수·고정 유형을 만들지 않는다.
설문 원문 번역·복제·축약판 점수화는 이번 범위가 아니다.

## 4. 보관과 개인정보

계정 응답은 기존 ACCOUNT_STATE 암호화 문서에 RUNNING_PROFILE 종류로 보관한다.
서버가 확인한 버전과 원자적 갱신 조건을 사용한다. 오래된 화면의 저장은 덮어쓰지 않는다.
클라이언트는 기존 암호화 초안/아웃박스로 미전송 응답을 보호한다. 서버 확인 전 성공 금지.
질문 중 아직 제출하지 않은 입력은 메모리에 있으며 이탈 확인으로 보호한다.
제출 후 대기 응답의 암호화 보관과 모든 탭의 실시간 자동 저장을 혼동하지 않는다.
다른 계정 응답·지연 응답은 즉시 분리하며 게스트 응답을 로그인 계정에 자동 이전하지 않는다.
게스트는 저장 없는 체험이며 닫기·새로고침 시 응답 초기화를 미리 알린다.
응답 삭제는 현재 응답을 빈 문서로 저장하며 기존 계정 수정본 보관 정책을 유지한다.
친구·공유 프로필에는 자동 포함하지 않는다. 원문 메모·이름·연락처·기기 토큰은 입력 금지.
history에는 단계만, 외부 분석 이벤트·LLM에는 응답을 보내지 않는다.

## 5. 화면과 이동

오라클 요약에서 러닝 프로필로 진입한다. 질문 한 화면·한 행동을 유지한다.
결과는 좋아하는 방식 / 경기 기록 / 최근 훈련 / 변화 네 화면으로 나눈다.
출처 종류는 짧게 항상 표시하고 계산 기준·한계·논문은 접힌 설명에서 제공한다.
뒤로가기 시 질문과 답변을 유지하고 결과의 탭 변경은 질문 이력을 늘리지 않는다.
모바일 320px·200% 글자 확대·키보드·줄인 모션을 지원한다. 확대 시 세로 스크롤 허용.
계정 저장 미지원·오프라인·충돌·실패는 명시하고 응답을 몰래 버리지 않는다.

## 6. 후속 연구 관문

CS/D'·ASR: 입력 프로토콜·측정 오차·대상 선수·모델 버전·허용 해석 검토 후 별도 채택.
PRETIE-Q/MOMS: 이용 조건·한국어 검증·연령 적용성·문항 이해도·재검사/구성 타당성 검토.
짧은 자체 질문은 선호 수집이지 척도 대체가 아니다. 합성 페르소나는 심리측정 검증이 아니다.
웨어러블: 원 측정과 기기 모델 추정의 출처를 분리하고 환경 보정의 미확인 영역을 남긴다.
처방 연결: 선호로 기존 훈련을 동등하다고 치환하지 않는다. 목적/부하/회복/안전 관문 별도.
친구 비교·공유: 선택 필드·동의·철회·청소년·삭제 계약을 갖춘 뒤 확대한다.

## 7. 검수 기준

- 미응답/모름/복수/제약을 분리하고 가짜 점수를 만들지 않는다.
- 응답 변경은 기록·훈련 집계·반응 값과 기존 계획을 변경하지 않는다.
- 메모를 바꿔도 결과가 같으며 응답 밖 속성을 저장할 수 없다.
- 서버 미지원·조회 실패를 EMPTY로 간주하지 않는다.
- 계정 전환·두 탭 저장·재시도·충돌·삭제·서버 확인 상태를 검증한다.
- 응답 편집과 이전/다음, 축약 흐름과 상세 흐름, 결과 탭, 좁은 화면을 검증한다.
- 결함 주입 결과·로컬 검사·배포·실 사용자 검증은 분리 보고한다.

## 8. 점수와 캐릭터 확장 준비

2026-10-04 후속 오너 요청에 따라 **점수와 캐릭터 제공을 준비한다.**
V1의 점수 미제공을 제품의 영구적 금지로 해석하지 않는다.
[점수와 캐릭터 설계안](../../reports/plans/ORACLE_RUNNING_PROFILE_SCORE_CHARACTER_PLAN_2026-10-04.md)은
자체 취향 지수, 실제 경기 기록 비교, 근거가 표시된 캐릭터를 구분해 정의한다.

이 추가는 설계 범위다. V1 범주형 응답을 0~100으로 자동 이전하거나,
새 문항을 검증된 심리척도로 표시하거나, 처방·부하·안전 규칙을 변경하지 않는다.
새 버전의 문항·계산·저장·공개 검토를 거쳐 적용한다. 공식 경기력 점수표는
권리와 적용 범위가 확인된 뒤 별도로 도입한다. `재미로 보기` 안내만으로
근거 없는 재능·건강·확률 해석을 허용하지 않는다.

변경 이력: 1.0의 구현·개인정보·검수 범위 유지. 1.1은 후속 점수 설계 링크와
준비/실행 구분만 추가하며, 정본 승격·런타임 활성화·배포 완료를 뜻하지 않는다.
