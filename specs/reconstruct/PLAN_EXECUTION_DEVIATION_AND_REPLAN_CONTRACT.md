## 1. 목적과 지위

**계획과 다르게 훈련했을 때 기록만 남기고 끝내지 않는다. 달라진 사실과 판단의 한계를 설명하고, 다음 훈련부터 남은 주기까지 필요한 범위의 교정안을 먼저 제시한다.**

오너는 의도적 변경과 뜻하지 않은 변경 모두를 설명·처방·이후 일정 교정으로 연결하도록 요청했다. 이 문서는 그 요구를 기존 계약과 대조한 신규 설계다. 요구의 존재가 아래 모든 세부 정책·훈련 수치의 채택, 코치의 독립 검수 또는 구현 완료를 뜻하지 않는다.

사용자에게는 `계획과 실제 훈련` / `다음 훈련 확인`으로 안내한다. `이탈`, `불이행`, `실패 점수`를 선수 평가나 보상 차감에 사용하지 않는다.

**강한 개입은 적극적인 확인·설명·교정안 제시다. 동의 없는 계획 덮어쓰기나 사소한 차이마다 전체 계획을 재생성하는 것이 아니다.**

## 2. 원본 계약과 충돌 해소

이 계약은 기존 적응 규칙을 지금 해제하지 않는다. 새 정책이 채택되고 저장·실행 경로가 구현되기 전까지 런타임은 기존 계약을 따른다. 설명·사실 비교, 생리학적 해석, 재설계안 생성, 실제 적용을 각각 별도 관문으로 구현한다. 비교가 가능하다고 후속 처방 권한까지 얻지는 않는다.

## 3. 반드시 구분할 것

1. **전체 목표:** 준비 중인 종목·경기·기간·사용자가 정한 목표. 다르게 수행했다는 이유만으로 바꾸지 않는다.
2. **계획한 자극:** 당시 선택하고 저장한 훈련 구성과 주기 내 역할.
3. **실제 수행 사실:** 확인 가능한 운동 종류·구간·반복·시간·회복·순서·자기보고.
4. **해석:** 실제 구성이 계획한 자극과 어느 부분에서 달라질 수 있는지. 검토된 규칙이 적용되는 범위만 설명한다.
5. **이후 판단:** 그대로 진행, 확인 후 진행, 일부 교체·재배치, 남은 주기 재설계 중 무엇이 필요한지.

더 짧게 했다는 사실만으로 `훈련 효과 없음`, 더 빨리 했다는 사실만으로 `더 좋은 훈련`, 횟수 부족만으로 `능력 부족`이라고 하지 않는다. 계획한 에너지 시스템 이름은 실제 측정된 대사 기여율이 아니다. 바뀐 훈련에도 유의미한 수행이 있을 수 있으며, 원래 목적과의 차이를 설명한다.

## 4. 입력과 근거 모델

### 4.1 비교 기준 고정

- 수락 당시의 전체 계획·세션·구간 원본, plan revision, content fingerprint, 날짜·슬롯, 선택된 configuration/rule/explanation 버전을 읽는다.
- 수행 전에 확정한 변경과 수행 후 기록한 차이를 구별한다. 미래 세션의 변경을 과거 수행의 비교 기준으로 소급하지 않는다.
- 동일 날짜라는 이유만으로 계획에 자동 연결하지 않는다. 기존 명시적 연결을 재사용하거나 사용자가 정확한 계획 세션을 선택한다.
- 복합 훈련, 둘로 나눈 수행, 워치 파일과 수동 기록은 별도 버전의 대응표가 필요하다. v1 단일 연결을 느슨하게 만들어 억지로 넣지 않는다.
- 과거 원본 누락·스코프 오류·저장 읽기 실패는 `SOURCE_UNAVAILABLE`이다. 빈 기록이나 미수행으로 대체하지 않는다.

### 4.2 실제값의 단위와 범위

| 항목 | 요구사항 |
|---|---|
| 거리 | 세션 전체 / 본운동 합계 / 구간 / 반복 1회의 범위와 단위를 보존 |
| 시간 | 전체 경과 / 실제 운동 / 준비·정리 / 반복 운동 / 회복 시간을 구별 |
| 반복·세트 | 계획 횟수와 직접 보고한 수행 횟수 구별. 총횟수와 세트별 횟수 이중 합산 금지 |
| 회복 | 반복 사이와 세트 사이, 걷기·조깅·정지, NONE·미기록·측정 실패를 구별 |
| 강도 | 계획 페이스, 실제 구간 기록, 세션 RPE를 서로 대체하지 않음. PACE_TARGET에 임의의 계획 RPE를 만들지 않음 |
| 다른 운동 | 근력의 부하·세트·반복, 점프의 접지 횟수, 자전거 등 고유 단위 보존. 러닝 km나 범용 피로 점수로 환산하지 않음 |
| 시각 | 실제 수행일·가능하면 시작 시각/시간대. 오전·오후만 있는 자료로 정확한 시간 간격을 주장하지 않음 |
| 출처 | 직접 입력, 유효한 기기 관측, 계산값, 자기보고, 미기록을 구분. 기기 자료는 기존 수용 정책을 통과한 필드만 사용 |

각 값에는 sourceId/sourceRevision, field/segment reference, evidenceKind, unit, scope, eligibilityReason을 둔다. 원문 메모·운동 이름에서 수치나 운동 종류를 추론하지 않는다. 숫자 차이는 동일 단위·범위에서만 계산한다.

원본 구조화 운동 기록을 그대로 보존하고, 계획 구간과의 대응은 별도 `ExecutionAlignment`로 둔다. 대응되지 않은 추가 운동은 사라지지 않지만, 특정 계획 구간을 수행한 것으로 세지 않는다. 한 실제 구간을 두 계획 세션에 중복 배정하지 않는다.

### 4.3 기존 진행값의 제한

`COMPLETED`, `PERFORMED`, `AS_PLANNED`는 기존 생성 방식과 출처를 확인해야 한다. 특히 완료+슬롯 일치로 파생한 `AS_PLANNED`는 반복·속도·회복의 일치를 증명하지 않는다. 새 비교기가 기존 enum을 조용히 다시 해석하지 않는다.

`NOT_PERFORMED`, `RESTED`, `SKIPPED`도 해당 계획의 진행 응답이지, 하루 동안 다른 운동을 전혀 하지 않았다는 증거가 아니다. `MISSING`과 늦은 워치 동기화는 미수행이 아니다.

## 5. 비교 결과: 사실과 판단 분리

신규 비교 결과는 하나의 준수율 점수 대신 다음 층을 가진다.

```text
ExecutionComparison
  basis: account/athlete scope + immutable plan/session refs + evidence revisions
  sourceState: COMPLETE | PARTIAL | UNAVAILABLE | CONFLICTING
  alignment: exact linked occurrence + explicit segment correspondence
  facts[]: dimension + planned + observed + unit/scope + source refs
  unknowns[]: missing/ambiguous/ineligible facts and their consequences
  interpretations[]: accepted rule/version + supporting facts + limits
  reviewDecision: status + action scope + reason codes + required inputs
  authority: DESCRIPTIVE_ONLY | REVIEWED_IMPACT_POLICY
```

- `COMPLETE`는 필요한 자료를 완전하게 읽었다는 의미이지, 모든 실제값이 있다는 뜻이 아니다.
- 원본 사실 차이는 표시할 수 있어도, 영향 크기의 `작음/큼`은 채택된 허용 범위·측정 오차 정책이 있을 때만 판정한다. 공통 ±10% 같은 임의의 기준을 만들지 않는다.
- 다른 종류 수행·추가 운동·명시적 건너뜀은 확인 작업의 근거가 될 수 있다. 특정 생리학적 결과의 증거는 아니다.
- RPE 상승, 수면 부족, 기기 심박 등 하나의 값만으로 회복 실패나 특정 시스템 부족을 확정하지 않는다.
- 한 항목이 불명확하다고 확인된 모든 사실을 숨기지 않는다. 무엇은 알며 무엇은 아직 모르는지 나눈다.

## 6. 개입 수준과 적용 범위

| 단계 | 사용자에게 제공할 것 | 시스템이 해서는 안 되는 것 |
|---|---|---|
| `OBSERVE` | 확인된 차이와 설명. 적용 가능한 정책이 있으면 유지 근거 | 규칙이 없는데 `영향 없음`이라고 판정 |
| `CLARIFY` | 판단을 바꾸는 누락 항목 하나만 질문, 또는 기기 자료 기다리기 | 미기록을 휴식으로 간주하거나 긴 설문 강제 |
| `REVIEW_NEXT` | 다음 훈련을 다시 확인할 이유와 검토 대상 일정 | 오늘 결과만 보고 다음 날의 부하 임의 계산 |
| `REPLAN_REMAINDER` | 현재 주기의 아직 하지 않은 훈련을 유지·교체·재배치한 안 | 못한 MAIN 몰아넣기, 한도 우회용 작은 변경 연쇄 |
| `REVIEW_BLOCK` | 중주기 목적·경기 준비에 미치는 영향과 더 넓은 재설계안 | 한 번의 차이로 24주 전체를 초기화하거나 목표 기록 변경 |
| `SAFETY_HOLD` | 기존 안전 상태와 필요한 확인 경로를 우선 노출 | 다른 운동 완료·좋은 기기 수치·사용자 동의로 D9 해제 |

이 단계는 난이도나 사용자 등급이 아니다. 안전 상태와 근거 준비 상태, 교정 범위는 서로 독립된 필드로 보존한다. 단순히 수정 횟수가 많다고 자동 승급하지 않는다.

계획 미수행도 무조건 일정 변경 사유는 아니다. 검토 결과 기존 계획을 유지하는 것이 맞다면 그것이 정식 교정 결론이며, 원래 일정을 보여주고 이유를 설명한다.

검토 중인 훈련은 달력에서 짧게 표시한다. 일반 변경 검토를 D9 차단처럼 다루지는 않지만, 아직 재검토하지 않은 일정을 `교정 완료` 또는 새로 추천된 훈련처럼 표시하지 않는다. 사용자가 검토를 미뤄도 이미 저장한 기록은 유지한다.

## 7. 재설계 원칙

### 7.1 최소 변경에서 필요한 전체 변경까지

검토 순서는 `해당 세션 → 다음 관련 세션 → 현재 주기 나머지 → 중주기/경기 앵커 → 대주기 연결`이다. 영향이 발견된 범위까지만 확장한다. 필요하면 여러 미래 세션을 함께 재설계하며, 단일 세션 수정으로 억지로 제한하지 않는다.

다음 조건을 동시에 지켜야 한다.

1. 이미 수행한 과거, 진행 중인 훈련, 원래 기록은 불변이다. 미래 일정은 새 revision으로 만든다.
2. 목표·경기일·시간 제약·본인이 고정한 일정은 기본 유지한다. 충돌하면 해당 조건 변경을 명시적으로 묻는다.
3. 누락된 MAIN은 빚이 아니다. 다음 날 추가하거나 쉬는 날을 없애서 자동 보충하지 않는다.
4. 검토된 템플릿·구성과 종목/경험/환경 적격성만 사용한다. 설명은 해당 새 구성·배치와 같은 버전을 읽는다.
5. 단순 주간 거리뿐 아니라 운동 종류, 회복, 강한 세션의 배치, 오전·오후, 시간 상한, 채택된 기계적/신경근 부담 규칙을 함께 점검한다. 비교할 규칙이 없으면 동등하다고 선언하지 않는다.
6. `48시간`, `72시간`, `주간 10%` 같은 새 간격·증감률을 이 문서에서 정하지 않는다. 실제 수용된 정책만 적용한다.
7. 기본은 목표 보존과 기존 약속한 범위 내 교정이다. 강도·양·빈도 자동 증가와 점수 기반 증량은 금지한다.
8. 한 세션을 줄여도 다른 날의 밀집도나 실제 총량이 늘 수 있다. 변경한 세션 하나가 아닌 전체안의 전후 차이를 검사한다.
9. 여러 일정·여러 차원이 바뀌는 재설계는 기존 단일 차원 successor를 반복 호출해 구현하지 않는다. 별도 전체안 정책·근거·명시적 수락이 필요하다.
10. 적격한 교정안을 만들 수 없으면 이유와 해결 가능한 조건을 제시한다. 빈 계획이나 원래 안을 교정된 새 안으로 위장하지 않는다.

실제 이미 많이 수행한 운동은 되돌릴 수 없다. 적게 하는 미래안을 제시한다고 그 부담이 상쇄되었다거나 회복이 끝났다고 표시하지 않는다.

### 7.2 재설계안의 필수 내용

`ExecutionReplanProposal`은 다음을 가진다.

- 원인인 비교 revision과 유효한 규칙·구성·출처 버전.
- 유지되는 목표와 변경 범위, 그대로인 세션, 바뀌는 세션과 이유.
- 이전/이후 전체 일정 스냅샷, 세션별 lineage crosswalk.
- 바뀐 거리·운동시간·회복·강도·빈도·슬롯/날짜의 벡터. 계산 불가 항목은 unknown.
- 유효성 검토 결과, 남은 불확실성, 사용자에게 필요한 확인.
- 예상 plan revision, evidence digest, safety epoch, 권한 scope, 멱등 키.
- 미리보기 만료 조건. 만료 시간을 임의로 정하는 대신 입력·버전 변경 시 즉시 무효화.

`MAINTAIN`도 근거 있는 결과이며, 새 버전을 불필요하게 저장하지 않는다. 장기 영향이 불확실하면 더 가까운 훈련만 교정하고 다음 재검토 지점을 설명할 수 있다. 이것을 미래 성과 보장으로 표현하지 않는다.

## 8. 사용자 흐름

### 8.1 일지에서 시작

```text
오늘 훈련 기록 저장
  → 계획과 다른 부분이 있나요? (필요할 때만)
     계획대로 / 일부만 했어요 / 다른 운동을 했어요 / 쉬었어요
  → 판단에 꼭 필요한 추가 선택 하나
  → 달라진 내용과 다음 훈련 확인
  → 현재 일정 / 교정안의 달력 비교
  → 이 일정으로 변경
```

- 변경 유형이 기록으로 명확하면 같은 질문을 또 하지 않는다. `추가 운동`은 원래 훈련 완료와 공존할 수 있으므로 네 선택 중 하나만 고르게 해서 정보를 잃지 않는다.
- `다른 운동도 했어요`, `자세히 적기`, `나중에 확인` 경로를 제공한다. 계획 밖에서 시작한 간단 기록도 정확한 연결을 고를 수 있다.
- 이유는 선택 사항이다. `시간 부족`, `장소·장비`, `일정 변경`, `몸 상태`, `다른 운동 선택`, `남기지 않음` 등 구조화 사유만 받는다. 의도 여부는 설명 맥락이지 벌점이나 생리학 판정 근거가 아니다.
- 몸 상태 확인은 기존 안전 입력으로 연결한다. 원문 메모를 읽어 사유·통증·동기를 추측하지 않는다.
- 저장 성공을 먼저 알려준다. 교정안 계산 실패 때문에 일지 저장 실패로 보이거나 재입력을 요구하지 않는다.

### 8.2 표시 방식

첫 화면은 최대 세 가지를 짧게 보여준다: **무엇이 달랐는지 / 다음 훈련을 확인할 이유 / 지금 할 일**. 입력한 정확한 값은 유지한다. 긴 기전·연구·처리 정보는 `왜 이렇게 제안하나요?` 뒤에 둔다.

메인 탭인 홈에 `훈련 코칭`을 상설 배치한다. 새 전역 하단 탭을 늘리는 대신, 기존 큰 분석 소개·6개 메뉴를 재배치하여 현재 확인할 코칭과 다음 행동 한 건을 먼저 보여준다. 일지의 `계획한 훈련과 비교하기`와 계획 달력에서도 동일한 검토 화면으로 진입한다. 화면 내부는 `차이 / 다음 일정 / 이유·근거`를 필요에 따라 펼친다.

홈 상단 요약과 상세 읽기 화면은 같은 결과/버전을 사용한다. 개인 코칭 이력과 일반 훈련 읽을거리는 구분하여 아래에 제공하고, 근거 없는 개인 설명을 콘텐츠 양을 위해 생성하지 않는다. [홈·코칭 UX 구현안](../../reports/plans/PLAN_EXECUTION_HOME_AND_COACHING_UX_2026-09-28.md)이 상태별 배치·버튼·모션·접근성·복귀·읽을거리 계약을 구체화한다.

기존안과 새 안을 달력에서 비교하고 바뀐 날짜·오전/오후만 강조한다. 색뿐 아니라 `유지/변경/삭제/새 배치` 라벨을 쓴다. 용어 설명을 다녀오면 원래 일지·날짜·선택·스크롤 위치로 복귀한다.

### 8.3 설명 예시의 경계

다음은 제품 문장 구조 예시이며 새 훈련 수치나 처방이 아니다.

- 사실: `계획한 반복 중 일부만 기록했어요. 쉬는 시간은 아직 확인되지 않았어요.`
- 영향: `원래 구성과 같은 자극을 받았는지는 아직 판단하기 어려워요. 남은 반복을 내일 자동으로 더하지는 않아요.`
- 행동: `실제로 한 훈련 확인` → 검토된 규칙을 적용할 수 있으면 `다음 일정 비교`.
- 다른 운동: `예정된 달리기 대신 근력 운동을 기록했어요. 같은 훈련을 한 것으로 계산하지 않고, 다음 일정에 필요한 확인을 할게요.`

모든 사용자에게 위 불확실성 문구만 반복하지 않는다. 적격 근거와 채택 정책이 있으면 무엇을 유지·변경할지, 그 이유를 구체적으로 제시한다.

### 8.4 홈 노출과 읽기 상태

- 홈 상단은 중요한 검토 한 건을 우선하지만 다른 미해결 항목을 삭제하지 않는다. 목록으로 갈 수 있는 경로와 개수를 보존한다.
- 글을 읽음, 검토를 마침, 새 계획이 서버에 적용됨은 독립 상태다. 읽기나 `나중에`가 적용 동의/안전 해제가 되지 않는다.
- 근거·정책·계획이 바뀌면 설명과 제안을 갱신한다. 읽는 도중 화면을 강제로 이동시키지 않되 오래된 제안 적용은 즉시 막는다.
- 예시/일반 글/내 기록 코칭은 표식과 적용 권한이 다르다. 현재 자료를 읽지 못한 상태를 새 방문자로 바꾸고 예시로 대신하지 않는다.
- 일반 분석 차트는 서술 범위를 유지한다. 신규 영향 해석·교정은 채택된 별도 정책이 있을 때만 코칭의 행동으로 노출한다.

## 9. 저장·동기화·계정 경계

- 로그인한 사용자의 적용 기준은 계정의 최신 온라인 원본이다. 기기 임시값만 바꾸고 `계획 변경 완료`라고 하지 않는다.
- 읽기 비교는 출처·버전을 표시한 캐시로 가능하다. 오프라인 교정안은 미리보기로 남고, 온라인 최신 근거·안전·revision 검증 후에만 수락한다.
- 실제 일지 저장과 후속 계획 적용은 별도 작업이다. 재설계 실패로 일지가 사라지지 않는다.
- 계획 변경, 새 버전 보존, 계보 연결, 적용 영수증은 기존 계정 저장 계층을 이용한 원자적 처리다. UI 여러 저장 호출로 흉내 내지 않는다.
- 두 기기에서 변경하거나 실제 기록을 편집·삭제·추가한 경우 기존 미리보기는 만료된다. 새 근거로 다시 비교하며 중복 적용하지 않는다.
- 계정 전환·권한 회수·안전 상태 변경 시 보이던 제안과 적용 버튼을 무효화한다. 이전 계정의 비교 수치가 남으면 결함이다.
- 기록 동기화·복원 실패를 0건으로 처리하지 않는다. 재시도는 멱등적이며 이미 성공한 적용을 다시 실행하지 않는다.
- 적용 취소는 아직 수행하지 않은 미래 부분의 새 제안이다. 과거 원본을 삭제하거나 이미 수행한 일정까지 되돌리지 않는다.

## 10. 프라이버시·안전·권한

- 개인 기록은 기존 허용된 구조화 필드만 사용한다. raw memo, symptom clause, 비밀 메모 내용·존재·길이·해시·embedding은 비교·추천·로그·외부 모델에 넣지 않는다.
- 비교·재설계는 프로그램된 규칙과 검토된 설명으로 구성한다. 실시간 LLM이 수치·효능·개인 근거를 만들지 않는다.
- 공개 공유에는 개인 수행/안전 근거를 자동 포함하지 않는다. 내부 provenance와 공개 요약의 저장·출력을 분리한다.
- `RULE_SPEC_D1_D9.D-9`의 ACTIVE/UNKNOWN, 유효하지 않은 안전 정보와 기존 hold는 우선한다. 의미를 이 문서에서 재정의하지 않는다.
- 청소년·혼자 훈련하는 사용자를 일괄 차단하지 않는다. 기존 SYSTEM self-selection과 처리 권한을 유지하고, 명시된 TENANT/COACH scope의 선택 권한만 그 경계대로 적용한다.
- 모든 일지에 교정 알림을 반복하지 않는다. 같은 근거의 동일 경고는 합치며, 새로운 중요한 사실이 있을 때만 다시 확인한다. 무시했다고 보상·연속 기록을 박탈하지 않는다.

## 11. 적용 정책 등록 요건

수치 변경·간격·허용 범위·재배치 정책은 각각 다음을 갖춘다.

```text
ruleId/version + status + exact scope + source refs/review version
required evidence + missing/conflict behavior
comparison dimension/unit/scope + accepted tolerance if any
permitted actions + prohibited actions + cross-session constraints
supported youth/self-use/coach authority conditions
explanation template + counterexamples + invalidation conditions
owner adoption reference + runtime registry identity
```

근거 검토 후 오너 최종 승인이라는 기존 채택 경로를 사용한다. 동일한 기능 승인 질문을 되풀이하지 않고, 새로운 수치/효과/권한 확대에만 정확한 채택 항목을 제시한다. 외부 전문가의 독립 승인으로 포장하지 않는다.

## 12. 필수 검수 시나리오

1. 완료 버튼만 누른 기록에서 실제 반복·거리·회복을 생성하지 않는다.
2. `AS_PLANNED` 파생값을 완전 준수 증거로 승격하지 않는다.
3. 부분 수행을 같은 처방의 RPE 추세에 섞지 않으면서 확인된 차이는 설명한다.
4. 세션 전체 40분과 본운동 20분을 같은 범위로 빼지 않는다.
5. 반복 회복 NONE·미기록·세트 회복을 구별한다.
6. 수동+워치 중복, 늦은 동기화, 상충한 편집을 이중 수행으로 세지 않는다.
7. 오전 달리기와 오후 근력, 추가 운동, 복합 구간을 단일 러닝 총량으로 환산하지 않는다.
8. 날짜만 같은 다른 훈련을 기존 계획에 자동 연결하지 않는다.
9. 수락 전 조절한 계획과 수행 후 교정한 계획의 비교 기준을 뒤섞지 않는다.
10. 놓친 MAIN을 다음 날 몰아넣거나 쉬는 날에 자동 보충하지 않는다.
11. 다음 일정 변경이 남은 주기에서 새로운 밀집·시간/경기 충돌을 만들면 거절한다.
12. 작은 단일 차원 변경의 연쇄로 다차원 재설계 권한을 우회하지 않는다.
13. D9/권한/계정/안전 epoch 변경 직후 오래된 제안을 적용할 수 없다.
14. 두 기기 동시 적용, 저장 응답 유실, 재시도에도 원본·계보·영수증은 일관된다.
15. 한 번 적용한 뒤 새 기록이 도착해도 자동으로 계획을 또 바꾸지 않는다.
16. 메모·비밀 메모를 바꾸어도 비교 결과·분석 로그·추천이 변하지 않는다.
17. 화면에서 유지/변경 근거를 읽고 뒤로 가면 동일한 일지·날짜·스크롤로 복귀한다.
18. 320/375px, 200% 글자 확대, 키보드, 줄인 모션에서 질문·적용·취소에 접근할 수 있다.
19. 청소년·초보·숙련자 모두 미기록을 실패로 취급하지 않고 기존 허용 범위를 유지한다.
20. 보고서나 mock 화면을 실제 비교·교정·계정 저장·배포 증거로 세지 않는다.

이는 전체 기능의 시험 목록이다. RT3의 대상 테스트 60건과 브라우저 4건은 사실 비교/화면 범위이며, 이 20개 전체 수용 시나리오를 완료했다는 뜻이 아니다. 특히 원자적 재설계 적용과 동시성 시험은 미실행이다.

## 15. RT3 실제 구현 범위 (2026-09-29)

- `descriptive-review-v1`: 정확한 계획 연결, 원본 검증 대기/누락, 겹친 기록, 부분 수행/휴식/건너뜀, 직접 입력한 수치, 구조화 운동 구성, 통증 확인을 구분한다.
- RT3에서는 `AS_PLANNED + COMPLETED + EXPLICIT RPE`로 수치 범위를 비교했다. RT4 정적 검토에서 AS_PLANNED가 완료·시간대로부터 파생됨을 확인했으므로, 아래 §16의 나란히 표시로 대체한다. MODIFIED/PARTIAL의 기존 동일 처방 분석 제외는 유지한다.
- 운동 구성의 자유 이름, 일지 제목, 메모 원문을 비교 입력으로 읽지 않는다. 실제 구간과 계획 구간의 대응은 아직 미구현이므로 임의 매칭하지 않는다.
- 홈 상설 코칭, 당시 처방/실제 기록/해석/다음 행동 읽기, 일반 안내 2편, 일지 원본 비교 안의 공통 설명을 구현했다.
- 현재 일정과 해당 일지로 이동할 수 있다. 이 기능은 계획을 저장/교체하지 않고, 읽기를 검토 완료 또는 교정 수락으로 저장하지 않는다.
- 전체 목표인 교정안 생성, 전후 달력, 원자적 계정 적용은 아직 구현하지 않았다. 4개 OPEN 항목은 유지한다.
- 자세한 실행 증거와 잔여 작업: [구현 보고서](../../reports/implementation/PLAN_EXECUTION_COACHING_IMPLEMENTATION_2026-09-29.md).

## 16. RT4 출처 정확성과 간결한 검토 화면

2026-09-29 오너는 상세 계획의 개선 실행을 승인하며 클릭 피로, 긴 글, 불필요한 스크롤을 줄이도록 요청했다. 이번 적용 범위는 기존 읽기 전용 코칭의 의미 수리와 표시 개선이다. 저장 스키마, 원문 소비, 신규 처방 정책, 계획 쓰기 권한은 개방하지 않는다.

- AS_PLANNED/MODIFIED 파생값을 `직접 표시`, `본인 확인`으로 표현하지 않는다. 완료·시간대는 구간별 수행 증거가 아니다.
- 직접 입력한 RPE와 원래 목표 RPE는 두 숫자로 나란히 표시한다. 구간 대응이 없는 현재 코칭에서는 범위 안/밖, 준수/미준수나 이를 근거로 한 CHANGED 판단을 하지 않는다.
- 첫 화면에는 짧은 결과, 직접 기록한 핵심 수치, 바로 할 수 있는 행동을 둔다. 긴 원래 처방이 먼저 나오지 않는다.
- 읽기 화면은 `요약 / 계획·기록 / 이유`로 바로 이동할 수 있다. 순서대로 통과해야 하는 마법사가 아니며 일지 저장에 새 질문을 추가하지 않는다.
- 같은 기능의 버튼·좌우 넘기기를 제공하되 큰 글자와 긴 실제 운동 구성에는 세로 스크롤을 허용한다. 내용 잘라내기나 글자 강제 축소로 화면을 맞추지 않는다.
- 안전·출처 누락·중복 같은 현재 확인이 필요한 상태는 모든 읽기 페이지에서 보인다. 긴 일반 한계·처리 정보는 선택해서 읽는다.
- 홈과 일지의 간단 비교도 같은 자료를 사용한다. 읽기·페이지 전환은 저장·보상·계획·안전 상태를 변경하지 않는다.
- 메모·자유 이름·제목은 입력으로 사용하지 않는다. 새 코드의 실제 시험 결과는 구현 보고서에서 따로 기록한다. 이전 64건은 RT3의 실행 이력이지 RT4 완료 증거가 아니다.

## 17. RT5 독립 검수 개선 (2026-09-29)

오너는 30개 페르소나 검수 보고서의 개선 및 수동 배포를 승인했다. 범위는 읽기 전용
코칭과 사용자 이동의 수정이다. 신규 수치 정책·자동 재처방·정본 승격은 포함하지 않는다.

- 같은 날짜의 검증된 계획 링크에서 실제 AM/PM만 달라지면 당시 계획은 보존하고
  계획 시간대와 실제 시간대를 구분해서 표시한다. 원본 세션 참조·지문 검증은 유지한다.
  다른 날짜·위조 링크·다른 계정은 계속 거부하며, 변경된 시간대를 AS_PLANNED로 승격하지 않는다.
- 일지의 비교 진입 한 번으로 당시 구성과 실제 기록을 함께 읽는다. 긴 이유만 추가로 펼친다.
- 워치 자료 대기와 계정 자료의 불완전 조회는 짧은 상태로 보인다. 미기록·완료로 대체하지 않는다.
- 탭 패널 ID와 펼침·읽기 위치를 유지한다. 다른 기록·계정에서는 읽기 상태를 공유하지 않는다.
- 읽던 기록이 사라지면 안전한 제목으로 포커스를 돌린다. 자정과 앱 복귀 시 날짜를 갱신한다.
- 중복 기록은 안정된 번호로 구별하고 해당 기록을 직접 연다. 원문 제목·메모를 식별 재료로 쓰지 않는다.
- 작은 화면의 요약은 핵심 지표 2개를 우선한다. 전체 지표는 계획·기록에 보존한다.
  큰 글자와 긴 구성에는 스크롤을 허용하고, 통증 안내·44px 터치 영역을 유지한다.

기존 실행 수치는 RT4 이력이다. RT5 결과와 배포 근거는 별도 구현 보고서에 기록하고,
네 OPEN 이슈는 유지한다.

## 18. RT6 오너 승인: 남은 일정 변경의 첫 공개 범위

2026-09-29 오너는 `근거가 있는 실제 기록과 짧은 확인 → 유지·줄이기·교체·뒤로 옮기기 → 선수가 선택 후 적용`을 승인했다. 이는 외부 전문가 독립 검수나 전체 재설계 계약의 정본 승격이 아니다. 기존 RT3~RT5의 읽기 전용 범위는 당시 이력이며, 이번 추가 범위만 아래와 같이 개방한다.

- 트리거는 `EXECUTION_REVIEW_CONFIRMED`다. 기존 NEXT_FRAME의 PB/SB·EXPLICIT_REQUEST와 섞지 않는다. 개인 메모·자유 운동명·제목을 읽거나 해시하지 않는다.
- 첫 적용 형식은 검증 가능한 V3 계획이다. V4~V6의 별도 조정 근거를 V3로 바꾸거나 버리지 않는다. 지원하지 않는 저장 형식은 이유를 표시하고 원본을 유지한다.
- 오늘과 과거, 결과가 기록된 슬롯은 변경하지 않는다. 미래 날짜로 연결된 일지도 보호한다. 시작일·종목·주기 길이·오전/오후 슬롯·주기 계보는 유지한다.
- 유지: 새 계획 버전을 만들지 않는다. 줄이기: 다음 변경 가능한 RPE 시간형 훈련을 기존 범위의 최소 시간으로 제시하며 강도는 올리지 않는다. 상세 반복의 수치를 임의로 깎지 않는다.
- 교체: 다음 주요 훈련 대신 원래 계획에 있는 회복/저강도 구성을 사용한다. 시간·강도 상한을 비교할 수 있고 늘어나지 않을 때만 가능하다. 비교 불가능한 상세 처방을 임의 시간으로 환산하지 않는다.
- 뒤로 옮기기: 미래 훈련을 같은 시간대의 기존 운동 슬롯으로 옮기고 원래 슬롯은 휴식으로 둔다. 휴식일에 새 운동을 추가하지 않는다. 주요 훈련 간격은 원래 계획의 최소 간격보다 좁히지 않으며 같은 날 주요 훈련을 두 번 배치하지 않는다. 고정 경기·약속이 없다는 확인이 있어야 한다. 이는 회복 완료 보장이 아니며 다음 주기는 변경된 마지막 훈련을 기준으로 확인해야 한다.
- 한번에 선택한 한 변경만 적용한다. 조건이 맞지 않는 행동에는 원인을 표시한다. 반복 적용도 항상 현재 계획을 기준으로 감소/보존 경계를 재검사한다. 빈 기록·워치 대기·파생 AS_PLANNED만으로 효과나 체력 부족을 진단하지 않는다.
- 변경안은 원래 계획 지문, 출처 일지, 구조화 근거 지문, 날짜, 변경 정책 버전, 계정 범위에 묶는다. 적용 직전 자료·계획·통증·템플릿 권한을 재검사한다.
- 온라인 적용은 계정 계획의 기존 CAS/영수증 경로를 사용하며 이전 계획과 진행 결과를 함께 보관한다. 서버는 동일 트랜잭션에서 일지 버전 집합도 대조해야 한다. 이 관문이 배포되기 전에는 계정 적용을 성공으로 표시하지 않는다. 응답 불명은 재확인 상태이지 저장 성공/원복 성공이 아니다.
- 변경된 계획에서 과거 링크를 덮어쓰지 않는다. 원본 보관함이 과거 일지의 비교 근거다. 변경 전 설명 영수증을 새 계획에 재사용하지 않는다.
- 화면은 `무엇을 바꿀까요? → 날짜별 전후 → 적용`이다. 통증은 별도 기존 확인으로 연결하고, 긴 한계와 정책 설명은 접는다. 적용 성공은 저장 확인 후에만 표시한다.

이 절은 구현 범위를 채택한다. 실행·배포 증거와 미완성 사항은 [RT6 구현 보고서](../../reports/implementation/EXECUTION_REMAINDER_REPLAN_IMPLEMENTATION_2026-09-29.md)에 따로 기록하며 기존 OPEN 이슈는 닫지 않는다. 상단 실행 시험 수치는 RT4의 이력이며 RT6 완료 수치가 아니다.

RT6 현재 구현은 V3의 변경안 생성, 전후 비교, 기기 원본 보관 후 적용과 계정용 서버 코드를 포함한다. SQL 0040의 로컬 실행 증거는 운영 DB 적용 증거가 아니다. 온라인 최초 저장, V4~V6 재설계, 다음 주기 자동 재생성은 완료하지 않았다.

## 19. 명시적 반복 기록과 당시 처방 비교 (2026-09-30)

§15~§17의 구간 대응 미구현은 당시 이력이다. 다음의 좁은 대응만 추가하며, 워치 랩 자동 매칭이나 생리학적 능력 진단을 개방하지 않는다.

- 대상은 원본 지문이 검증된 `PACE_TARGET` 거리 반복이다. `exerciseLog.plannedRepetitions`에 세트·반복 번호와 사용자가 직접 입력한 거리·초·회복 초·회복 방식을 저장한다. 모든 수치는 선택 사항이며 빈 칸에 계획값을 채우지 않는다.
- 계획 세션 ID 및 당시 내용 지문을 일지 링크와 일치시킨다. 현재 계획으로 바꿔 비교하지 않는다. 동일 번호 중복, 원문·추가 필드, 음수·무한대, 원본 범위를 벗어난 번호는 거부하거나 비교 불가로 남긴다. RESTED/SKIPPED는 수행 기록을 보유한 채 저장할 수 없다.
- 계획 거리와 같은 실제 거리를 기록한 구간에만 목표 초를 대조한다. 다른 거리·시간 누락·거리 누락을 개인 페이스로 자동 환산하지 않는다. 미기록 반복은 실패나 0으로 집계하지 않는다.
- 다음 운동 구간의 거리 기록이 있고 회복 시간과 방식이 모두 있을 때만 해당 회복을 비교한다. 반복 마지막과 세트 마지막을 구분한다. 세트 회복은 반복 회복에 더하지 않으며, 최종 반복 뒤를 다음 반복 회복으로 계산하지 않는다.
- 모든 반복의 거리·시간이 있을 때 앞뒤 같은 개수의 평균을 보여준다. 홀수 개에서는 가운데 한 회를 양쪽 평균에서 제외하되 전체 구간의 목표 비교에서는 유지한다. 숫자는 관찰값이지 정상/비정상 임계값이나 능력 점수가 아니다.
- 설명은 `관찰된 차이 / 함께 확인할 조건 / 아직 판단할 수 없는 것`을 구분한다. 빠른 출발 뒤 후반 시간이 늘었으면 다음에는 첫 반복의 목표 속도를 확인하도록 안내한다. 회복·날씨·코스·피로 등은 가능한 확인 항목이지 해당 세션에서 검출한 원인으로 표기하지 않는다.
- 한 번의 실패나 좋은 기록으로 ATP-PC·해당계·산화 능력 부족/우수, 효과, 향상의 원인을 단정하지 않는다. 통증·겹친 기록·원본 미확인 처리는 이 비교보다 우선한다.
- 기본 빠른 기록에 질문을 추가하지 않는다. 선택해서 `반복별 기록 남기기`를 열며, 세 구간씩 넘긴다. 실제 입력 및 원본 보존은 상세 폼과 빠른 폼이 동일하다.
- 남은 일정 교정 근거 지문에는 이 구조화된 실제 수치와 원본 참조를 포함한다. 수치 변경 후 이전 교정안을 적용할 수 없다. 메모·제목·자유 운동명은 계속 제외한다. 반복 비교는 자동 증가 또는 새 처방 채택의 권한이 아니다.
- 브라우저·온라인 저장 검증기를 같은 원본에서 생성한다. 로컬 검사 통과와 운영 서버 배포는 따로 보고한다. 전체 목표 및 기존 OPEN 이슈를 이 절만으로 종결하지 않는다.
