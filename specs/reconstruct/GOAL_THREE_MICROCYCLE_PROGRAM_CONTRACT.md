# 10km 한 달 기본 프로그램 — 마이크로사이클 묶음 계약

기준: 2026-10-11 오너의 구현 승인 및 단위 명확화. 로컬 구현 계약이며 배포 증거가 아니다.

## 훈련 단위

- 최소 훈련 단위는 **9.5일 마이크로사이클**이다.
- **마이크로사이클 3개 = 28.5일 = 한 달 기본 프로그램**이다. 한 마이크로사이클을 한 달이라고 부르지 않는다.
- 시작일 오전부터 57개 반일을 이어 붙이면 29개 민간력 날짜에 걸친다. `29일`은 달력상의 표시 범위이지 새로운 최소 단위가 아니다.
- 각 마이크로사이클은 19반일이며 시작 오프셋은 0·19·38이다. 두 번째는 공유 날짜의 오후부터 시작한다.
- 공유 날짜에는 앞 마이크로사이클의 훈련만 표시한다. 뒤 마이크로사이클의 첫 반일은 명시적인 휴식으로 유지한다. 훈련을 숨겨 충돌을 해결하지 않는다.
- 하루 실제 훈련 최대 1회, 누락 날짜를 임의의 휴식으로 채우지 않음, D-day가 가까워도 압축하지 않음을 지킨다.
- UI는 `한 달 기본 훈련 · 9.5일 × 3`, `1차 · 9.5일`처럼 월 단위와 하위 단위를 구분한다.
- 기존 단일 프레임의 열거형을 28.5나 29로 늘리지 않는다. 기존 저장 자료와 개인 기록 경로는 유지한다.

## 원본과 처방 권한

- 목표는 10km 60·50·45·40·30분이다. 목표 선택은 현재 실력, 현재 기록, 건강 확인의 근거가 아니다.
- 기본 처방은 기존 검토된 시간·RPE 카탈로그와 경험·훈련일 수로 구성한다. 목표 숫자만 달리 골랐다고 근거 없는 증량을 하지 않는다.
- 명시적인 `목표 속도로 연습` 선택은 기존 동일 종목 `GOAL / RACE_AVERAGE_V1` 원본만 사용한다. 실제 개인 기록을 만들지 않는다. `시간 기준으로 훈련`과 별개의 보이는 선택으로 제공하고 숨은 설정으로 두지 않는다.
- 카탈로그 전체 시간에 준비·본운동·반복 회복·정리를 포함한다. 기본 시간 범위를 넘는 완전한 원본은 미리볼 수 있지만 **전체 시간 확인과 몸 상태 확인을 각각 완료해야 적용**한다. 확인을 피하려고 시간을 잘라내지 않는다.
- 사용자 자료의 달력 구성·회복 배치 원칙을 참고했지만 특정 선수 수치, 개인 기록, 건강 문장, 이미지 자체를 앱 자산으로 복사하지 않는다.
- 이 제품 묶음을 creator 프로그램이나 별도 검수된 목표별 달성/증량/테이퍼 원본으로 표시하지 않는다. creator registry의 미채택 상태를 우회하지 않는다.
- 한 달 목표 달성 보장, 자동 테이퍼, 기록 없는 사람의 개인 능력 추정은 제공하지 않는다.

## UI·저장

- 목표 → 날짜 → 경험 → 속도 기준 → 추천 하나를 먼저 본다. 속도 기준은 목표 속도/시간 기준 두 가지이며, 훈련일 수·시간대는 필요할 때 연다.
- 달력/목록은 읽기 전용이다. 휴식은 간단히 표시하고 날짜를 눌러 상세 처방을 읽는다.
- 3개 원본 프레임을 version 1 프로그램으로 감싼다. 현재 적용한 마이크로사이클과 나머지 예정 프레임을 구분한다.
- 현재 9.5일의 수정·진행은 기존 검증된 편집 영수증으로만 연결한다. 날짜·종류·순서가 불명확한 수정은 원본으로 조용히 대체하지 않는다.
- 다음 마이크로사이클은 이전 것을 명시적으로 마친 뒤 따로 시작한다. 지난 훈련을 오늘로 옮기지 않는다.
- 새 프로그램으로 교체할 때 이전 전체 프로그램과 진행 상태를 보관한다. 보관 한도 초과 시 삭제 대신 저장을 거절한다.
- 전용 JSON 백업은 현재 프로그램과 프로그램 보관 내역을 포함한다. 복원은 현재 실행 중인 계획을 바꾸지 않는다. 소유 파일 확인·원본 재연산·revision 검사를 거친다.
- 로컬 저장 키는 `trainoracle.goal-training-program.v1` 및 `trainoracle.goal-training-program.history.v1`이며 기존 계정별 로컬 네임스페이스와 삭제 목록을 따른다.
- 현재 출시 정책의 계정 저장 보류는 유지한다. 새 프로그램을 계정 저장 성공으로 가장하거나 계정 모드 실패를 공용 로컬 저장으로 우회하지 않는다. 계정 모드의 시작은 지원 전까지 제한한다.
- 지원되는 계정에서는 원본 `GOAL_PROGRAM_BODY`, 진행 `GOAL_PROGRAM_PROGRESS`, 목록 `GOAL_PROGRAM_INDEX`를 기존 암호화 문서 v3로 분리한다. 기존 500KB 제한·소유자 검증·버전 비교·동의 및 삭제 경계를 유지한다. 서버 capability 확인 없이 새 문서를 쓰지 않는다.
- 계정 원본/진행을 확인한 뒤 목록을 확정한다. 동기화 대기·충돌을 저장 성공으로 표현하지 않는다. 충돌은 계정본과 기기 초안을 보존하고 명시 선택하며, 초안 파일은 해당 초안의 보관 이력까지 포함한다. 계정본 선택만으로 현재 실행 계획을 바꾸지 않는다.
- 새 계정 IndexedDB는 기기 전체 삭제 대상이다. 차단·실패하면 모두 삭제되었다고 알리지 않는다.
- 수정 계보 및 보관 수는 기존 18개 한도를 따른다. 증명할 수 없는 긴 계보는 원본 바이트를 보존한 채 사용을 제한한다.

## 2026-10-11 후속 오너 결정

오너는 `증량·회복안은 별도 검토표로 먼저 제안하고 내가 확인 후 적용`을 선택했다.
따라서 세 마이크로사이클의 새 증량·감량 수치와 역할 배치는 검토표로 분리한다.
검토표 작성, 합성 페르소나 검수, 계산 테스트는 해당 수치의 런타임 승인으로 사용하지 않는다.
확인 전 기존 승인 구성·분량을 유지한다. 목표 속도 구간과 시간 기준 구간을 분명히
표시하는 개선, 저장·복구 구현은 이 검토와 독립적으로 진행한다.
