## 적용 범위

빠른 기록의 답변과 최종 저장을 분리한다. 운동 결과, 시간대, 체감강도, 몸 상태를 고른 뒤
작은 요약에서 `운동 추가`, `글 추가`, `이대로 저장`을 제공한다. 휴식/건너뜀도 자동 저장하지
않는다. 세부 숫자는 선택이며, 단일 선택만 다음 단계로 이동한다. 글/숫자/복수 구성은
명시적 반영을 기다린다. 기존 일지 ID, 날짜, 계획 연결, 계정 소유권은 유지한다.

## 실제 운동 구성

PostSessionEntry.exerciseLog는 선택 필드다. 버전 1, 출처 SELF_REPORTED, 최대 24개 구성.
구성별 안정 ID, 운동 종류, 선택 이름, 순서 있는 실제 구간을 보존한다. 구간은 최대 64개이며
각 구간별 거리 m, 시간 초, 반복 수, 세트 수, 실제 중량 kg, 점프/접지 수, 좌우 구분,
반복/세트 회복을 선택적으로 남길 수 있다. 상한은 저장/화면 보호용이며 훈련 권고가 아니다.
서로 다른 반복/세트는 별도 구간으로 입력한다. 빈 숫자는 미기록, 명시적 0초 회복과
회복 없음은 별도 값이다. 잘못된 숫자는 조용히 버리지 않고 반영을 막는다.
거리/시간은 한 번의 운동, 반복 수는 세트당 횟수이며 세트 수와 분리한다. 예를 들어
400m, 10회, 2세트는 400m를 20회 수행한 구조다. 마지막 반복/세트 뒤 회복 포함 여부를
따로 받지 않는 현재 형식으로 총 소요 시간을 자동 계산하지 않는다.

같은 종류도 여러 구성으로 추가 가능하다. 수정은 ID 유지, 복제는 새 ID, 순서 변경과
삭제 취소를 제공한다. 작성 중 종류를 바꿔도 확정 전 값은 보존한다. `운동 추가`는 같은
세션의 구성이고 별도 오전/오후 훈련은 새 일지다. 휴식으로 바꿀 때 기록한 운동을 자동
삭제하지 않으며, 수행 사실이 남아 있으면 휴식 저장 전 사용자가 직접 정리하게 한다.

## 분석 경계

exerciseLog는 기록/본인 조회/계정 보관/백업용이다. 기존 intensityAssessment의 엄격한
필드 조건을 완화하지 않는다. 거리/시간 이중 합산, kg의 %1RM 환산, 점프 거리의 접지 수
환산, 운동 종류로 에너지 시스템 확정, 계획값을 실제값으로 복사하는 동작은 금지한다.
현재 분석 투영에는 exerciseLog를 포함하지 않는다. 기존 명시적 거리/RPE 및 기존에
적격한 intensityAssessment만 원래 계약대로 소비한다. 추후 변환 규칙은 별도 채택한다.

## 글과 저장

한 일지의 기존 메모를 저장 전에도 편집한다. 여러 독립 글 장수 저장은 이번 범위가 아니다.
운동 내용과 글 쓰기는 요약을 경유하지 않고 전환할 수 있으며 미반영 운동 입력도 유지한다.
기존 용도 선택, 비밀 글 암호화, 외부 LLM 금지, 안전 검토, 계정 전송 대기/충돌 조건을
그대로 적용한다. 원문은 로그/추적/분석에 추가하지 않는다. 안전 검토 안내와 일반 계정
저장 성공 안내는 별도 필드로 전달한다. 성공 문구 존재만으로 검토 경고를 만들지 않는다.

## 왕복 이동과 호환성

오라클에서 시작한 기록은 성공 후 원래 주제의 개인 결과로, 취소 시 원래 주제/모드로
돌아간다. 실제 안전 검토는 우선 표시한다. 주제 간 뒤로가기는 내 기록/예시와 스크롤
맥락을 보존한다. 계정 변경은 다른 계정의 입력 원점을 무효화한다.
기존 exerciseLog 없는 일지는 그대로 읽는다. 클라이언트, 계정 검증 번들, 백업/복원,
수정 화면이 같은 필드를 보존해야 한다. 운영 서버 배포 전 로컬 번들 통과를 온라인
지원 완료로 표시하지 않는다.
일지 요청은 supportsExerciseLogV1 기능 지원 여부를 전송한다. 지원하지 않는 구버전에서
exerciseLog가 있는 기록의 조회/수정/복원/삭제를 시도하면 서버는 UPGRADE_REQUIRED(426)로
중단한다. 목록에서 몰래 제외하거나 구버전 형식으로 덮어쓰지 않는다. 서버부터 배포한다.
